# Reverbs

<!-- summary -->
`#reverb` (`GraphNode::Reverb`, kernel `fast_reverb`) is the FDN reverb: `[l, r].reverb(:hall)` runs inputs through diffusion, a per-sample FDN, and energy-normalized output taps; presets `:room`, `:hall`, `:plate`, `:shimmer`, `:gated`, ...; the friendly form takes `room_size:`, `decay:`, `damping:`; options for modulation, in-loop filters, drive, shimmer, freeze, `duck:`, `gate:`; `mix:`/`wet:`/`dry:`/`level:`/`predelay:` take nodes read every sample.  One reverb serves all channels.  `sig.convolve('hall.wav')` (alias `ir`; `GraphNode::Convolver`, kernel `fast_convolve`) plays an impulse response with zero latency (wet -10 dB by default); `reverb_match('hall.wav')` fits the FDN to an impulse (`m.save :name`; presets `fit_room`, `fit_hall`, `fit_space`).
<!-- /summary -->

## Quick reference

- `[l, r].reverb(:hall)` (`:room`, `:stadium`, `:space`, `:plate`, `:shimmer`, `:gated`, `:drone`, ...), or `reverb(room_size:, decay:, damping:, mix:)`; one reverb serves every channel.
- Code `lib/mb/sound/graph_node/reverb.rb` (kernel `fast_reverb`, mirror `MB_SOUND_KERNELS=reverb_network=ruby`); spec `spec/lib/mb/sound/graph_node/reverb_spec.rb`; help `help :effects`.
- `sig.convolve(impulse, mix:, wet:, dry:, gain:, normalize: true, predelay:, length:/trim:, fade:, partition:)` (alias `sig.ir(...)`): wet -10 dB and no dry by default; impulse a Sample, a file path (file guard), or NArray channels (1, 2, or 4: true stereo assumed LL LR RL RR, unverified); code `lib/mb/sound/graph_node/convolver.rb`, `convolve_methods.rb`, `lib/mb/sound/convolution.rb`, `ext/mb/sound/fast_convolve/` (kernel `convolve_engine`, mirror `MB_SOUND_KERNELS=convolve_engine=ruby`); specs `spec/lib/mb/sound/graph_node/convolver_spec.rb`, `spec/ext/mb/sound/fast_convolve_spec.rb`.

`GraphNode::Reverb` / `#reverb` (`lib/mb/sound/graph_node/reverb.rb`, from the reverb video; `[l, r].reverb(:hall)` / `mix.reverb` take one input per channel) is the one reverb (`FdnReverb`/`#fdn_reverb` were removed 2026-10-10; their room_size/decay/damping contract is `#reverb`'s friendly form).  Its network (inputs → diffusion stages → feedback delay network → output taps) runs in C (`ext/mb/sound/fast_reverb`, `Reverb::Network` over `FastReverb::Network`, exact Ruby mirror `Reverb::Network::RubyKernel`: the `reverb_network` kernel, chosen when a network is built, `MB_SOUND_KERNELS=reverb_network=ruby`): diffusion stages a block at a time (no feedback), the FDN one sample at a time, so loops are exactly the line delays at every buffer size and any buffer runs without splitting.  `show_internals: true` makes graphviz drawings (`--graphviz`, `node.graphviz`) show the network inside the reverb as a cluster drawn from its `Network::Layout` (`Reverb#graphviz_internals`, hooked into `Traversable#graphviz`): inputs to lines with their gains, each diffusion stage (delays in ms, polarities, the Hadamard mix, the shuffle), the feedback lines (loop delays, loop gains, damping) with the Householder reflection, and the lines each output sums; the sound is the plain reverb's, any option allowed (omnibus18, 2026-10-30, the maintainer's "Draw from the network."; before, it built a third copy of the network out of delay and matrix nodes, without modulation or loop processing).
- Classic presets `:room`, `:hall`, `:stadium`, `:space`, `:default` keep the 2026-01 structure: `:stadium`, `:space`, `:default` sound as then (impulse responses null against the old code to -122..-143 dB; renders -126 dB), `:room` too but with its wet at -10 dB (was -16 dB, then 0 dB on 2026-10-10, -10 dB since 2026-10-11 (user: 0 dB too wet, -16 too low); nulls -140 dB scaled by the wet) and `:hall` with compact loops (`loop_extra: 0`: +0.9 dB energy, T30 7.03→7.17 s) (user's picks by ear, 2026-10-10); they keep the old loop timing with `loop_extra: CLASSIC_LOOP_EXTRA` (1024 samples at 48 kHz; each line is read at its tap for the output and 21.3 ms later for the loop, what the old `FEEDBACK_BLOCK` read did) and the old level through `level: Reverb.classic_level(n, stages)` for stereo in and out; other channel counts get `Reverb.channel_trim` = 2 / sqrt(inputs × outputs) (user's decision 2026-10-10: mono in or out +3 dB each, the old levels; the reverb answers the inputs' mean power and spreads one total wet energy over its outputs, so 6 outputs are -4.8 dB each and 8 voice inputs -6 dB each).  `loop_extra: 0` gives compact loops, gains retuned from `tuned_loop_extra` so each line keeps its decay per second (RT60 room 0.271→0.276 s, hall 7.03→7.17, stadium 5.66→5.66, space 26.7→28.7, default 0.79→0.84; +0.2 to +3.3 dB energy, denser early sound).  Room-size presets: `:plate`, `:shimmer`, `:grit`, `:lofi`, `:gated`, `:drone`.
- Friendly form: without a preset, `room_size:` (0..1), `decay:` (RT60, any Length), `damping:` (0..1) build a room-size layout (`Reverb.room_params`: FdnReverb's stratified log-random delays rejecting near-integer ratios, diffusion 1-15 ms and feedback 15-120 ms scaled by 0.3 + 0.7 room_size; 8 lines, 4 stages, `loop_extra: 0`, subtle modulation, wet -6 dB; `ROOM_DEFAULTS`).  `decay:` works with any preset too (line gains 10^(-3 loop/decay)); `mix:` (0..1) like the chorus's.  Every input, a single node too (since 2026-10-10; before, a mono reverb ended with its input), is padded with `extra_time` of silence so the tail rings out.  With several inputs, one that ends plays silence until they all have (`Reverb::PaddedInput`, as in Dynamics; a short buffer is an input's last), and the reverb ends on the exact sample where the last one did (2026-10-12: before, an input ending early, e.g. `stereo(saw * one_shot_env, saw).reverb`, raised a ShapeError).  Mixer, ChannelMixer, Dynamics sidechains, multitap, and chorus were checked the same way and were fine.
- Gains (energy-normalized, 2026-10-10; were hand-tuned per preset): inputs on their lines at 1/sqrt(lines per input), Hadamard stages × 1/sqrt(N), Householder feedback, each output's group of lines × sqrt(N / group size); with stereo in and out, wet 1 gives each output within ~1.5 dB of the input energy (other counts × channel_trim; no feedback; 4-line networks with 1-2 stages up to ±3 dB, coherent input copies), whatever the lines, stages, inputs, and outputs (the old structure moved by tens of dB; e.g. hall at 4 vs 16 lines 6.7 LU apart, now 0.8).
- Modulation (research 2026-10-10, below): `modulation:` (alias `mod:`) moves each feedback line ±depth, `diffusion_modulation:` (`diffusion_mod:`) each diffusion line by 0..2 depth: true/`:subtle` (feedback 0.25 ms at 0.5 Hz smooth random, ~1.4 cents; diffusion 0.05 ms at 0.7 Hz sine), `:lush`, `:chorus`, `:seasick` (`MODULATION`, `DIFFUSION_MODULATION`), a depth, a node, or `{ depth:, rate:, shape: :sine/:triangle/:random/:smooth, spread:, max_depth: }` (rate a number, Pitch (tempo pitches follow the tempo), or node).  Per-line rates spread over 1 ± spread (0.3) and start phases spread, from the seed; LFO targets every 16 samples of the stream (`FastReverb::LFO_STEP`), ramps between, each LFO its own splitmix64 stream; fractional reads Catmull-Rom.  Off for classic presets (sound kept), on (subtle, feedback only) for the room-size form.  Modulation shortens RT60 a little (cubic interpolation loses highs in the loop: hall 7.03→6.53 s with :subtle).
- Inside the feedback loop (per line; numbers or nodes): `damping:` (first-order absorption filters per line, RT60 at Nyquist exactly (1 - damping) × the reverb time; a number; `damping_design: :exact` default since 2026-10-10, `:jot` the old approximate design, which damps more (Jot 0.5 = exact 0.6) and kills the longer lines above ~0.7; the room-size presets and `ROOM_DEFAULTS` were retuned to keep their sound: default 0.5→0.6, plate 0.3→0.34, shimmer 0.5→0.6, grit 0.2→0.22, gated 0.3→0.34, drone 0.6→0.72, RT60s at 1k/8k Hz within 0.3%) or `lowpass:` (one-pole Hz/Pitch/node), `highpass:`, `drive:` with `drive_mode:` (`:soft` rational tanh, `:hard`, `:fold`; unity small-signal gain), `crush:` (bits, quantized toward zero so tails can't limit-cycle), `shimmer:` (0..1, two power-complementary 50 ms grains per line at `shimmer_pitch:`, default 12 st, mixed at equal power), `freeze:` (0..1: input muted, loop gains → 1, filters bypassed; lossless), `stretch:` (scales the feedback delays live; lines sized for `max_stretch:`).  After the network: `duck:` (how far the wet sound ducks while the input peak is above `threshold:`: `-12.db` and `12.db` both duck by 12 dB, never boosting (maintainer 2026-10-14); a bare number is a linear gain at most 1, a bare number above 1 raises with the `.db` hint (live mode: dB of ducking), and a node gives dB of reduction; until db-1 (2026-10-14) a positive number of dB of reduction, which old graph documents still load as; `threshold:` default -30.db; 10 ms fall, 300 ms rise) and `gate:` (seconds open after the input falls below the threshold, 20 ms close: gated reverb), from a 50 ms-release peak follower.  Not built: a general `reverb { |fb| ... }` insert block (the FDN is N lines through a matrix; the loop-program machinery has one loop variable and no matrix op yet), reverse reverb.

## Convolution (`#convolve`, conv-reverb-1, 2026-11-06)

The maintainer picked a convolution reverb from the options (SIR, a convolution VST, is his most-used plugin effect: 557 instances, in three of his four representative eras).  His questions: "Has the patent expired on using time domain convolution for the first partition to reduce latency?" (Lake DSP's US 5,502,747, filed 1993, has expired; Gardner published the scheme in 1995) and "an alternative to convolution for some of the projects would be color and decay matching on the existing reverb" (`reverb_match`, below).

- Scheme (`ext/mb/sound/fast_convolve/fast_convolve.c`, `MB::Sound::Convolution`; non-uniform since 2026-11-06, the maintainer's "Up to 8192, spike spread"): the impulse's first 128 samples (the head) run in the time domain, a 128-tap dot product per sample and path, so the output has no latency (an impulse of a single 1 returns the input from sample 0 exactly).  The rest runs in levels of overlap-save convolution, each with its own block size Q and frequency-domain delay line (`Convolution.plan`, Gardner's non-uniform partitioning): partitions of 128 samples to 1024, of 1024 to 16384, and of 8192 from 16384 to the end (`Plan#to_s`, e.g. `128 + 7 x 128 + 15 x 1024 + 34 x 8192 (spread)` for 6 s).  Uniform levels: every Q samples the last 2Q inputs are transformed (2Q-point complex FFT; two real channels share one transform as x0 + i x1, and the outputs come back from one transform of the conjugated, Hermitian-extended A0 + i A1), stored in the level's ring, multiplied by the partitions' spectra (scaled by 1/2Q), and the inverse's last Q samples are the level's output for its next block; partitions reading older spectra are summed across the block by its position, leaving the first partition and the two transforms for the boundary.  The 8192 level is spread: it starts one block later than its size requires (from 16384, so the 1024 level reaches one block further), its output for block m + 1 needs spectra only up to block m - 1, and all of its work for a block runs during the previous block as a task list done by the block position (`Engine#task`): the forward transform of the previous segment as 8 sub-FFTs of 2048 points of the decimated sequence combined by three radix-2 passes in chunks of 2048 butterflies, the ring store, every partition, the packed output spectrum, the inverse the same way, and the next block's tails (two tail buffers swap at the boundary).  No buffer carries a whole 16384-point transform.  `partition: P` gives a uniform plan (a P-tap head and P-sample blocks, the round-1 engine).
- FFTs: Pocketfft through `Numo::Pocketfft.fft` (public, one array per call), called from Ruby between engine calls (`Convolution::Runner#run`: the uniform levels' boundaries from `Engine#boundary_levels`, a bit mask, then `Engine#task`/`#task_result` for the spread level's sub-FFTs).  The C engine owns no FFT, so there is no second FFT implementation.  About 5 objects per 128-frame buffer.
- Same output at any buffer size, bit for bit: the blocks run on the node's own grid, and every sum and task computes the same values wherever a buffer cuts (spec'd at 1/128/800, 367 and 64 in the slow tier, and with odd chunkings through the spread level).  Against a direct double-precision convolution: -146 to -150 dB peak-relative (the float32 output's rounding) for impulses from 20 samples to 24577, including the plan's edges (128, 129, 1024, 1025, 16384, 16385, 24577) and every channel layout.  FFT rounding leaves values near 1e-16 where the exact convolution is 0 (a predelay's leading zeros) until the rings hold only silence; `quiet?` (the node's idle check) waits for the inputs to be silent for the impulse length plus two of the longest levels' reach, after which the output is exactly zero.
- Plans: `Convolution.plan(L)` (`HEAD`, `LEVELS`); impulses up to 128 samples are all head, up to 1024 head plus 128-sample partitions, up to 16384 plus 1024-sample partitions, longer ones add the spread 8192 level.  `partition:` makes a uniform plan.
- Channels (`Convolver::PATHS`): mono; one impulse on both channels of a stereo input; mono to stereo (2-channel impulse); parallel stereo (2 channels, left to left, right to right); true stereo (4 channels in the order left to left, left to right, right to left, right to right; a mono input feeds both sides).  The 4-channel order is an assumption, unverified against real files (maintainer, 2026-11-06: he has used only 2-channel impulses in SIR).  Inputs ending at different times pad with silence; the outputs ring for the impulse's length after the last input ends and end on the exact sample where the convolution does (input length + impulse length - 1).
- Impulse handling: `normalize: true` (default) scales the impulse to unit energy per output (the mean over outputs of the paths' summed energies), so broadband sound comes out at about the level it went in, as the FDN's energy-normalized wet does; `gain:` (dB or linear) after it; `predelay:` prepends zeros; `length:`/`trim:` truncates with a raised-cosine fade over `fade:` (default a quarter of the kept length); the end under -120 dB of the peak is dropped (`Convolver::TRIM_FLOOR`).  Other sample rates resample through `Analysis::DSP.resample`.
- Mix: `#delay`'s rules (`DelayMethods.mix_levels`): `mix:` is an equal-power crossfade (a number or node; wet 1 and dry 1 crossfaded), `wet:`/`dry:` levels; the default is the normalized convolution alone at -10 dB (`ConvolveMethods::DEFAULT_WET`; maintainer, 2026-11-06: "default probably should be wet -10dB normalized, dry 0"; until then wet 1).  `ir` is the short alias ("ir is good"; recipes print `convolve`).  The dry path is added outside the Convolver (`DelayMethods.ring_sum` / `StereoDelayMethods.wet_dry`).
- Files: a path goes through `Sample[]` (so `GraphIO::FileGuard`); `:convolve` is in `Registry::FILE_METHODS` and `KEEP_NAME`, so a document's `convolve('room.wav')` is checked at load, read beside the document, and prints as written.  Impulses made from NArrays print as FIXME (not representable), like the sampler's in-memory Samples; the graph sweep factory is listed so in the recipe and document round trips.  No relation fuzz step: the fuzz checks `to_ruby` and document round trips, which an in-memory impulse can't make.
- Node traits: `memory: :long`, `idle_check: :sleep_ready?` (the engine's zero run), `carry: :adopt` (`Engine#swap_state` exchanges inputs, spectra, sums, tails, and position with an engine of the same shape; spec'd: a rebuilt convolver continues the old one's samples bit for bit).
- Cost, Mac container (i9-9880H, 2026-11-06, under the heavy-run lock), stereo noise input (the noise included), 6 s of buffers per run, average best of 3, % of realtime at 128 / 800-frame buffers, uniform 1024 (round 1) -> non-uniform: 3 s stereo 5.5 / 5.0 -> 3.1 / 2.5; 3 s true stereo 10.6 / 9.8 -> 3.9 / 3.3; 6 s stereo 8.6 / 8.4 -> 3.4 / 2.8; 6 s true stereo 16.0 / 16.0 -> 5.3 / 4.4 (the FDN presets cost 1-3%; the model below had predicted 2.0-2.8%: the engine's per-block Ruby calls and the 8192 level's partition sums, memory-bound at about 2 ns per complex multiply-add, cost more than modeled).  Worst single buffers, non-uniform at 128 frames: 99.9th percentile 26-58% of the period, worst without a GC run 37-63%, worst 71-89%; at 800 frames 99.9th 23-25% (once 152%, a GC run), worst without GC 10-12%; the uniform plan's were alike (43-65% at 128 frames).  The worst buffers fall at scattered positions in the 8192-sample cycle, not at the spread level's boundary (OS scheduling and GC on the shared container).  Profile, 6 s stereo, 800 frames: head and per-sample work ~0.7%, the 128 level's 256-point transforms ~0.3-0.5%, the 1024 level's and the spread level's 2048-point transforms ~0.6%, the spread level's tasks ~1% (its partitions ~0.02% each).
- Non-uniform estimate, before building it (2026-11-06, the maintainer: "estimate perf gain"; a model from component timings on the Mac: head 0.25 ns per tap and path, complex multiply-adds 0.69-2.23 ns by partition size and spectra size, Pocketfft complex FFTs 3.7 us at 256 points to 277 us at 16384, boundaries 2 FFTs + 5 us + 20 ns per bin; the uniform model gives today's engine cost within the noise of the graph measurements): a 128-tap head, then levels of 128 to 1024, 1024 to 8192, and 8192 blocks to the end would cost 6 s stereo 2.1% (today 8.1-8.8%), 6 s true stereo 2.8% (17-19%), 3 s stereo 2.0% (4.8-6.0%), 3 s true stereo 2.6% (10-11%), at 128 and 800 frames alike; the catch is the 8192 level's boundary (two 16384-point FFTs, about 0.8 ms with the smaller levels' boundaries landing on the same sample, 30% of a 128-frame period once every 8192 samples).  Spreading it: start that level one block later (its partitions from 16384, the 1024 level covering one more block, about +0.2%) and build its transforms from sub-FFTs as each sub-block arrives (a radix-r first stage, a combine pass at the end; about 11 us per 128-frame buffer), or a GVL-free worker thread with its own FFT (pocketfft's C, already in numo-pocketfft's source).  A capped plan (levels to 4096) costs 3.2% / 5.0% for 6 s stereo / true stereo with a 0.25 ms boundary and no spreading.
- Next steps (not built): float32 spectra for the spread level (its partition sums are memory-bound; half the traffic, about -130 dB instead of -146), fewer Ruby calls per 128-sample block (the 128 level's boundary is eight calls and two Pocketfft plans every 128 samples).

## Fitting the FDN to an impulse (`reverb_match`, conv-reverb-1)

- Measurements (`Analysis::ImpulseResponse`): octave bands 125 Hz-8 kHz as FFT masks with raised-cosine edges 1/6 octave wide (brick-wall masks ring as 1/t: a floor near -38 dB under a synthetic 125 Hz decay, T60 3.68 s read for 3.0; 3.11 with the taper); per band the energy, a noise floor from the last tenth and the point where the 10 ms envelope meets it +5 dB (Lundeby, simplified), Schroeder's backward integral with the floor subtracted, T60 from T30 (else T20, T10), EDT; broadband onset (first sample within 20 dB of the peak), C50/C80 from the onset, the late-tail band levels (each band's fitted decay line 80 ms after the onset plus its energy), and the late L/R correlation.  Synthetic tails with known T60s read back within 5% per band (spec: 10%), under a -80 dB noise floor too.
- Fit (`ReverbMatch`): room_size by the closest C50 + C80 of 0.1/0.3/0.5/0.7/0.9; decay, damping, and the in-loop highpass by Nelder-Mead over renders of the reverb's impulse (least squares on log T60 ratios, 60 renders per search), with a second search using the in-loop lowpass instead of damping (the reverb takes one) when damping leaves over 10% RMS; predelay from the onsets; peaking EQ (1 octave wide) at the octave centers from the late-tail level differences, two passes; width from the correlation (decorrelated outputs through `width(w)` have correlation (1 - w^2)/(1 + w^2)); `level:` for unit wet energy per output.  The result prints as Ruby (`m.to_ruby`: `sig.reverb(room_size:, decay:, damping:, ..., level:).peq(...).width(...)`) and `m.apply(sig, mix:)` mixes it like `#convolve`.
- Accuracy (synthetic impulses): a 3 s tail with T60 2.1 to 0.6 s: within 5% per band, RMS 3-5%, tail 0.2 dB RMS, about 11 s on the Mac; a dark 1.5 s room (0.9 to 0.3 s): RMS 10.5%, worst +16% at 1 kHz (the damping filter's T60 curve doesn't bend over the mids that far), tail 0.9 dB; the :hall preset's own impulse: within 7% but 8 kHz -14% (the room-size form's subtle modulation loses highs) and C50 15 dB off (its slow build-up is beyond room_size 0.9).  The match has no direct sound or discrete early reflections; the report shows C50/C80 so the gap is visible.  Bench numbers per impulse are in `/app/tmp/listening/conv-reverb-1/info.json`.
- Saving fits (2026-11-06, the maintainer: "library yes"): `ReverbMatch.graph` builds the fitted graph from recorded DSL calls (`input.blend(mix, curve: :power) { |s| s.reverb(...).peq(...).width(...) }`, or the wet graph at `wet:` plus `dry:` without a mix), so `m.save(:name)` writes an ordinary effect document (`inputs input: :audio`, `param :mix` at 0.3, tags `fitted`) on the save shelf, and `#apply` defaults like `#convolve` (wet -10 dB, no dry).  The library ships three fits of the generic synthesized impulses as built-in presets, stored values generated by `bin/save_presets.rb` (`LIBRARY_PRESET_FITS`): `fit_room` (0.92-0.30 s, dark), `fit_hall` (3.0-1.0 s, warm; the lowpass search won), `fit_space` (5.6-2.6 s).
