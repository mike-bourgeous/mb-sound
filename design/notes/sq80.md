# SQ-80 voice, patches, and (designed) SysEx import

The Ensoniq SQ-80-flavored voice and its helpers.  CLAUDE.md keeps a summary and points here.  Update both when behavior changes.

## Panel units and envelopes

`lib/mb/sound/sq80.rb`: `SQ80.time` (the manual's time chart, 0..63 panel values to seconds, geometric between chart points), `SQ80.level` (-63..+63 to -1..1), `SQ80.env_options` (L1-L3/T1-T4, LV with `:linear` "L" or `:exp` "X" curves, T1V, TK, second release, CYC, `loop:`, `restart:`), `SQ80::TimeScale` (T1V/TK time nodes, `Op::TimeScale` in plans); `sq80_env` in the console (`EnvelopeMethods`) and in voices (`Notes#sq80_env`).  Research: `research/sq80/README.md` on branch `research-sq80`; values marked UNVERIFIED there (second release level and rate, velocity curves, TK scaling) are by ear.  More in `envelopes.md`.

## The voice (sq80-lib-1, 2026-10-17)

First built as `bin/synths/sq80_voice.rb` (2026-10-07); moved to the library so it can be loaded in a live `bin/sound.rb` session and found in `help /sq80/` (maintainer 2026-10-17: "I'd like a way to load an sq-80 patch in a live session in sound.rb, and have it show up in `help /sq80/`"; "Both, library first": our voice as a library patch now, real SQ-80 SysEx program import designed on top of it).

- `lib/mb/sound/sq80/waves.rb`: `SQ80::Waves` (was `MB::Sound::SQ80Waves` in the script): original tables built from the manual's descriptions, nothing from the ROM: `:formant` (a KeyMap of 11 tables, one per 8-semitone zone from note 24, a 1/h spectrum lifted around 750 Hz and 1.4 kHz at each zone's center, so the vowel stays put), `:synth3` (equal-level harmonics 1, 2, 3, 5, 7, 11, 13, 17, 19, 23), `:prime` (1, 3, 5, 7, 11).  `Waves[name]` also takes any library table (`Wavetable.names`), a Wavetable, or a KeyMap.
- `lib/mb/sound/sq80/voice.rb`: `SQ80::Voice.build(source, seed:, **settings)` over `Voice::DEFAULTS` (the script's sound).  Settings: `voices`, `cutoff` (Hz), `reso` (0..1 at CC 71's center), `drive_mode` (`:feedback` soft-clipped resonance, `:input`), `drive`, `chop` (octaves; a looping two-32nd envelope on the cutoff, 0 off), `flutter` (octaves per unit of poly pressure; a sample-and-hold LFO whose rate follows the key's poly pressure, 0 off; since omnibus9, 2026-10-18, its steps glide through a critically damped 12 Hz SVF lowpass, `Voice.flutter_lfo`/`FLUTTER_GLIDE_HZ`, after the maintainer's Bench note that :flutter_pad "seems like it's still not interpolating": poly pressure itself was smooth (largest step 0.001 per sample on poly_chord.mid), the zipper was the S&H's up-to-2.5-octave cutoff jumps), `second_release`, `osc1`..`osc3` (`{ wave:, semitones:, level:, vibrato:, env1: }`), `env1`/`env2`/`env4` (`SQ80.env_options` panel values; ENV1 sets the level of oscillators with `env1: true`, ENV2 the filter, ENV4 the VCA), `lfo1` (`{ rate:, depth:, delay:, wheel:, pressure: }`, Hz and semitones), `filter` (`{ env2:, key:, velocity:, aftertouch: }`, octaves), `transpose` (semitones added to every oscillator; the filter's key tracking still follows the keys; omnibus9), `level`.  Hash settings merge into the defaults key by key; unknown names raise with suggestions.  Numbers or nodes for `cutoff`, `reso`, `chop`, `flutter` (drive is a number: lp4 takes only numbers); a zero chop, flutter, oscillator level, or filter amount leaves its nodes out.
- The build keeps the script's node creation order and arithmetic (`osc1 * 0.45 + osc2 * 0.35 + osc3 * env1 * 0.4`, mods in the same order), so the defaults render the script's samples: f32 md5 of every sample (buffers 800/128/7 in turn) identical to the old script on five option sets and MIDI files, and the script's FLAC renders identical; named Constant cutoff/reso/chop/flutter also render bit for bit (2026-10-17).  `spec/lib/mb/sound/sq80_spec.rb` keeps a copy of the original voice as the reference.
- `lib/mb/sound/sq80/patches.rb`: `SQ80::Patch` (Data: `name`, `description`, `settings`, `#full_settings`) and `SQ80::PATCHES`: `:classic` (the defaults an octave down, `transpose: -12`, level 1.99: bench-fixes-1, the maintainer on the omnibus9 Bench, "Maybe one octave down?" after two; -20.30 LUFS on the chords), `:flutter_pad`, `:chop` (an octave down), `:vox_lead`, `:prime_bass` (an octave up), `:glass` (transposes from the maintainer's sq80-lib-1 Bench notes, omnibus9: classic "a couple octaves lower", chop "play it lower", prime "a little too low"; levels rematched: classic -20.32, chop -20.28 LUFS on the chords, prime_bass -20.19 on its line, against -20.30/-20.31/-20.12 before).  Levels match `:classic`'s loudness within 0.1 LU on a 3-bar phrase at 100 BPM (chords, a lead line for :vox_lead, a bass line for :prime_bass; about -20.3 LUFS through the default -10 dB master).
- Console (`SQ80Methods`, extended into MB::Sound): `sq80(source = nil, patch = nil, seed:, **settings)` (nil source: live `midi`; a Symbol in either position is the patch, so `sq80(:glass)` and `sq80(clip, :glass, cutoff: 900)` both work) and `sq80_patches` (prints names and descriptions, returns the names).  `sq80` is a recorded top-level DSL method (`Recipe::Surface::TOP`), so graphs print as `sq80(clip, :chop, cutoff: 400, seed: N)`; the voice's internals aren't recorded, which also makes the script's graph representable for the first time (it held built wavetables).
- Presets: `presets/sq80_<patch>.mbg.rb`, saved by `bin/save_presets.rb` from `bin/synths/sq80_voice.rb -p <patch>` with the patch's nonzero cutoff, reso, chop, and flutter as params: `sq80(midi, :chop, cutoff: cutoff, reso: reso, chop: chop, seed: drawn_seed(N))`.  The document calls the library patch, so it follows library changes to the patch (graph documents' rule); `--check` lists ones whose params went stale.
- Help: `help :sq80` (topic), `help :sq80` method pages from the doc comments, `help /sq80/` lists the topic (search pages now list matching topics first) and the methods.
- Script: `bin/synths/sq80_voice.rb` is a thin wrapper: `-p/--patch`, options default to the patch's (nil), `sq80_voice(midi, ...)` stays for snippets that load the file, `sq80_voice_patch` (Constants for --save) and `sq80_voice_description` serve `bin/save_presets.rb`.

## Wave voices: the 2026-10-06 prototype patches (protos-1, 2026-10-23)

The research prototype (branch research-sq80, `research/sq80/prototype/sq80_voice.rb`, a separate offline Numo engine) had three patches the maintainer kept liking on the Bench after the library voice's patches fell out of favor (guards-1's regression study, `workbench/research/sq80-regression/`): he picked "square bass grit" and wrote "These sounds should be in the library if they aren't", then "it's the overall patch that works, not necessarily the 8-bit or grit".  They are now `bin/synths/wave_voices.rb` (`wave_voice(midi, :digibrass | :organ_reso | :square_bass, grit:, cutoff:, reso:, voices:)`, settings in `WAVE_VOICES`) and six shipped presets with neutral names (the SQ-80 demo ban): `:digibrass`, `:organ_reso`, `:square_bass` and `_grit` versions, saved by `bin/save_presets.rb` with `cutoff` and `reso` params.

- Presets, not a library method: the zoom-out's "presets at every scale" (layer 2) and "presets instead of methods" (a smaller surface).  Each document holds the whole voice as plain DSL (`synth(midi) { |v| ... wavetable_of([...]) ... lp4(...) }`), so it reads and edits as a patch, prints through recipes, and needs no script at run time; `preset :square_bass, midi: clip` or `midi: midi` (live).
- Rebuilt from library nodes: the prototype's additive tables as `wavetable_of` (library :saw/:square, harmonic lists for the formant wave (40 harmonics), the drawbar organ, and SYNTH 3), its linear L/T envelopes as `v.env([[level, seconds], ...], release_at: 3, curve: 0)`, the noise-and-chirp attack (lowpassed noise and a falling 1.8 kHz sine), key tracking and envelope octaves as `cutoff * 2 ** (...)`, vibrato, levels (`mix * 0.35` into the filter).  Added for playing: amplitude velocity 0.5..1 (none in the prototype); levels set for -20.3 LUFS through the default master on a phrase in each role (bass line, organ chords, brass stabs; 4 bars at 100 BPM, default clip velocity), like the library's other synth presets.
- Filter: lp4 is the prototype's ladder (same TPT cascade, 0.375 compensation): `tuning: :hardware` is its cutoff mapping (the prototype predates `:musical`), the patches' k (2.2, 3.4, 2.8) are lp4 resonances 0.3717, 0.6401, 0.481 on the :db curve, linear output equal within -280 dB; driven, lp4's rational saturator stands in for the prototype's tanh (-38 dB residual at drive 1.5).
- The saw's phase matters through the drive: the prototype's saws were +1/n sine-phase harmonics (a falling ramp from its top), the library saw half a cycle on and upside down, so the voices play it `.with_phase(0.5)` at a negative level (spectral shape 0.6-1.2 dB and envelope 0.8-1.4 dB away from the prototype with the library saw's own phase, 0.1-0.5 dB with it).
- `grit:` (cheap: the tables read without interpolation, no mipmaps): 256-sample tables, `aquantize(1r/127)` (8-bit), `decimate(38461.5)` (held at the DOC rate) on the oscillator mix; the attack stays clean, as in the prototype.
- Match on the prototype's own phrase (C3 G3 C4, then Eb4 G4 C5; square bass an octave down) against its renders (`/app/tmp/listening/sq80/*.flac`), mel spectrum shape over active frames with the level removed / centroid / 10 ms envelope: digibrass 0.09 dB / +22 cents / 0.08 dB (grit 0.30 / +26 / 0.08), organ_reso 0.65 / +16 / 0.06 (grit 0.79 / +20 / 0.08; the differences are above 5 kHz, at low levels), square_bass 0.45 / +12 / 0.10 (grit 0.40 / +12 / 0.14).  Clean against grit: prototype 0.86 / 1.42 / 0.15 dB, ours 0.85 / 1.98 / 0.38.
- Specs: `spec/bin/synths/wave_voices_spec.rb` (the ladder against a copy of the prototype's, every patch clean and grit from streams, clips, and a Session's live MIDI input, presets equal to the script, recipes and documents), `spec/bin/save_presets_spec.rb` (every preset like the script).

## SysEx programs: parser built, import designed (sq80-lib-1)

Format research: `research/sq80-sysex/README.md` (header, nybbles, the 102-byte layout, mod sources, waves, what's unverified, local checks).  Built: `lib/mb/sound/sq80/sysex.rb`, `SQ80::SysEx.read(path | bytes)` (every one- and all-program message, other ESQ messages skipped, `FormatError` for malformed data), `.dump`/`.write` (an all-program message for 40 programs, else single-program messages), and `SQ80::Program` (Data in panel units: `name`, `envs`, `lfos`, `oscs`, `dca4`, `filter`, `flags`, `glide`, `pan`, `pan_mod`, `split`; `.decode(bytes)`, `#to_bytes`, `#wave_name(i)`, `#sq80_only?`, `.init`).  It decodes the maintainer's four local banks and writes each back byte for byte (keeping FINE's and LV's low bits as found).  Nothing maps a Program onto sound yet.

### Mapping onto the voice (design)

The library voice is one fixed SQ-80-shaped patch (ENV2 on the filter, ENV1 on OSC3, chop and flutter); a program needs the general form, so the importer would add a program voice: `SQ80::Voice` settings gain the program's shape (`oscs` with two pitch mods and two DCA mods each, three LFOs, four envelopes, a filter with two mods and keyboard tracking, DCA4, pan, flags), built by a second builder (`Voice.build_program`), and the classic voice stays as it is (bit-identical).  Mod sources become nodes per voice once each (`:lfo1` → that LFO, `:env2` → ENV2, `:vel` → `:velocity`, `:vel2` → `:vel_x`, `:kybd` → `:key` from the bottom, `:kybd2` → `:key` bipolar, `:wheel`, `:pedal`, `:xctrl` → a configurable CC (breath, CC 2, by default), `:press` → `v.aftertouch` (poly or channel, like the SQ-80's poly keyboard), `:off` → nothing) and feed `mod_sum`/`mod_scale` slots.

| SQ-80 | Ours | Fit |
|---|---|---|
| ENV1-4 L1-L3, T1-T4, T1V, TK, second release, CYC, ENV RESTART | `sq80_env` panel values as they are (`cycle:`, `restart:`) | exact to our sq80_env (its own UNVERIFIED items: second release level/rate, TK scaling) |
| LV | `lv:` + `lv_curve:` from the L/X bit | exact once the bit is known; until then `:linear` (decision) |
| OSC OCT/SEMI | `semitones:` | exact |
| FINE 0..31 | `semitones:` + fine / 32 | approximate (step size UNVERIFIED) |
| OSC pitch mods | `v.hz.transpose(mod_sum(src => amount × k))` | scale k UNVERIFIED (measure) |
| WAVE | an original table by family (below) | approximate by design |
| DCA level 0..63, on | osc `level:` on a dB curve, off when not on | curve UNVERIFIED |
| DCA mods | the level through `mod_sum` | scale UNVERIFIED |
| DCA4 level, ENV4 | output level × ENV4 | exact for ENV4; level curve as DCAs |
| FC 0..127, Q 0..31 | lp4 cutoff (Hz) and resonance (0..1) | mapping curves UNVERIFIED (the SQ-80 filter is a CEM3379 four-pole, like lp4) |
| filter KEYBD 0..63 | `:key` octaves per octave (63 = 1) | approximate |
| filter mods (s7) | `mod_scale` slots | scale UNVERIFIED |
| LFO FREQ, WAVE, L1, L2, DELAY, HUMAN, RESET, mod | `v.lfo(rate, shape:, from: L1, depth: L2, delay:, human:, sync: reset ? :key : :free)`, the mod source scaling the depth | shapes exact; rate table and delay time UNVERIFIED |
| SYNC | OSC2 `.sync(osc1)` | exact (minBLEP hard sync) |
| AM | OSC2 × OSC1 (ring) | approximate (the SQ-80 AM's offset unverified) |
| MONO, GLIDE, OSC RESTART, VOICE RESTART | `voices: 1` legato, `v.hz.glide(t)`, key-synced or `.free` oscillators, retrigger mode | approximate (glide time table UNVERIFIED) |
| PAN, pan mod | `.pan(mod_sum(...))` | exact shape, scale approximate |
| split/layer | not in the first importer (a layered program could sum two voices; splits the `split` MIDI transform) | unsupported (listed) |

Waves (never the ROM's samples): additive waves the manual describes by their harmonics are built exactly from those lists (SYNTH1-3, PRIME, 4 OCTS, OCTAVE, OCT+5, ORGAN, SQR 2, PULSE2, SAW 2, BASS 2, E PNO2 by harmonic count); classic shapes from the library (SAW, SQUARE, SINE, TRIANG, PULSE); noises from `noise` (NOISE1 filtered); fixed-formant waves as KeyMaps like `:formant` (FORMT1-5 at their formant centers, GLINT1-3 one high harmonic held in place, VOICE1-3/ALIEN as two-formant vowels); sampled instruments (PIANO, EL PNO, BASS, REED 1-3, CLAV, BRASS, STRING, BELL, DIGIT1-2, GRIT) as original additive or FM stand-ins of the same family, each a named table in `SQ80::Waves` with a one-line description of what it imitates; transients, loops, and drums (49-74) at first silent with a warning listing them (later: our drum voices and clicks, or user samples through `Sample`).  `sq80(..., waves: { 9 => Sample['my_piano.flac'] })` could let someone supply their own audio for a ROM wave.

### API sketch

- `SQ80::SysEx.read('bank.syx')` (built) → Programs; console `sq80_programs('bank.syx')` lists number, name, waves, and unsupported features.
- `sq80(midi, sysex: 'bank.syx', program: 3)` or `program: 'NAME  '` (by name, case- and padding-insensitive), and `sq80(midi, program: prog)` with a Program; settings on top change the result (`cutoff:` ...), as with patches.
- Saving: a graph from a program saves as `sq80(midi, program: SQ80::Program.new(...))` data (no file dependency), or with `sysex: "assets/bank.syx"` in a bundle (FileGuard reads only inside the document's directory; `Registry::FILE_METHODS` entry).
- Live: `sq80_request(:all)` sends `F0 0F 02 0n 0A F7` (all programs) or `09` (current program) and waits for the dump on live MIDI input (`MIDI::Event` already has `:sysex`; sending needs MIDI output, which mb-sound doesn't have yet).

### Test plan

- Synthetic programs only in the repository (`Program.init.with(...)`; the parser specs already do this).  Per parameter: a program differing from init in one field builds the expected settings (e.g. ENV values reach `sq80_env` unchanged, SYNC builds a synced tone, each mod source resolves to its node), and renders change in the expected direction (cutoff up: brighter by spectral centroid; second release: a tail).
- Every importer path builds and renders the four local banks' 160 programs without errors (opt-in `MB_SOUND_SQ80_SYX_DIR`, local only, never in CI), and prints a count of approximations and unsupported features per bank; no renders of factory or third-party programs leave the machine.
- Unit curves (FC, Q, LFO rate, pitch mod depth, DCA levels, FINE, glide): measured on hardware or a faithful emulation by rendering single-parameter test programs (synthetic, made with `SysEx.write` and sent to the instrument), then fitted; until then each conversion is a named constant marked UNVERIFIED, as in `sq80.rb`.
- Listening: A/B against the maintainer's SQ-80 (or recordings of it) for a handful of his own programs.
