# Oscillators and antialiasing

Detailed notes moved from CLAUDE.md (2026-10-10); CLAUDE.md keeps a summary and points here.  Update both when behavior changes.


Tone waveforms are antialiased by default (`lib/mb/sound/band_limit.rb`, kernels in the `fast_synth` extension); every shape has a naive (aliased) `a*` twin for lo-fi sounds and control signals.  Measure any expression with `bin/aliasing.rb 'p.saw' 'p.asaw'` (coherent-sampling aliasing table and cost; `--render DIR` writes 100 Hz-8 kHz sweeps with spectrograms).

- `ramp`/`saw`, `square`, `triangle` use PolyBLEP/PolyBLAMP (corrections on the samples either side of each edge, found on the phase plus phase modulation, so FM/PM and through-zero motion work); `asaw`/`asaw`, `asquare`, `atriangle` are naive (`Tone#band_limited?`).  `.lfo` fades band-limiting in from 15 to 30 Hz (`BandLimit::LFO_FADE`), so slow LFOs keep exact jumps (delay times, gates) and audio-rate "LFOs" are clean.  Free-running PolyBLEP shapes have exact means at every pitch (PolyBLEP's step correction sums to the ideal step's area, and PolyBLAMP's extra 1/12 per corner cancels over a cycle): measured 2026-10-08 at 2-12 kHz, means within 1e-5 at any start phase, and 50 ms window means over a 2-12 kHz sweep within 8e-5 of the ideal band-limited waveform's (low-frequency beats of aliases near 0 Hz, -70 dB at 4799.7 Hz); a band-limited tone's first sample is corrected as if it had always run (`state.blep[3]` 0 = never played, 2 = after a jump), so a square starting at phase 0 plays 0, the ideal, not +1 (fixed 2026-10-08).
- `pwm(width, pivot:)` (alias `skew`; width a number or node) warps the phase of any shape: `square` → pulse (`pulse(w)`/`apulse(w)`), `triangle.skew(w)` → a true skewed triangle rising for `w` of each cycle (0.9 near a rising saw, 0.1 near a falling one), `sine.pwm(w)` → CZ-style phase distortion; DC offset removed by default (`dc: true` keeps it); the warp's corners are band-limited too.  Pivots (osc-env-1, 2026-10-12; the maintainer's idea: "what if each wave shape had a predefined phase offset for pwm, and pwm could be phase shifted?"): the warp turns around a pivot o (cycles): rotate the phase by -o, warp, rotate back (`BandLimit.warp(p, w, o)`, C `bl_warp_pivot`), so the knees sit at o and o + w where the shape's phase is o and o + 0.5; the phase map is still two linear pieces, so the breakpoint candidates are the shape's own plus the two knees (`BandLimit.pivot_candidates`, exact rotated phases; breakpoints carry their rotated phase x and shape phase u, and the sync kernel and phase jumps evaluate breakpoint sides from them, since rounding the rotation could land on the wrong side of a jump) and PolyBLEP/PolyBLAMP, minBLEP sync, clean resets, and band-limited jumps all apply unchanged.  Defaults `BandLimit::PIVOTS`: triangle 0.75 (its low point, so its halves are the rising and falling slopes and `width` is the rising fraction, like `pulse`'s high fraction and `Notes#lfo(skew:)`; 0.25, the peak, would have made `width` the falling fraction), every other shape 0 (unchanged sounds).  `pivot:` (a number or node read per sample like the width, wrapped to 0...1) overrides it; `pivot: 0` is the old warp bit for bit (`triangle.skew(w, pivot: 0)`: the triangle split at its zero crossings into a slow positive hump and a quick negative dip, the sound before 2026-10-12, so existing `triangle.skew`/`pwm` uses changed sound: `bin/tone_gallery.rb` (plus `skew_triangle_pivot0`), `bin/songs/antialias_song.rb`, `bin/audio_load_check.rb`, `MB::Sound.warm_up`).  Width 0.5 ignores the pivot (the identity warp, bit for bit a plain shape).  DC: a warped shape's offset is H(o)·(2w - 1) with H(o) the mean of the shape over [o, o + 0.5) (`BandLimit.half_mean`, from closed-form integrals; `HALF_MEAN` at 0; 0 for a triangle at 0.75, so a skewed triangle needs no DC removal).  A moving pivot is handled like a moving width (breakpoints recomputed when it changes; a corner passing a resting phase isn't corrected, as for width).  Kernels: `FastSynth.oscillate_bl`'s optional 14th argument, `oscillate_sync`'s 23rd, `mb_bl_oscillate`'s pivot signal; Ruby mirrors exact.  Plans take constant pivots (scalar 15 of the tone op); a pivot node keeps the tone unplanned (`plan_unsupported_reason`).  Not for wavetables and complex shapes yet (their warp always pivots on 0; an explicit `pivot:` there goes through `live_error`; `complex_triangle.pwm` keeps the lobe warp): planned as part of a later vector phaseshaping project (maintainer, 2026-10-12: "Agreed", not now), which would extend `mb_wavetable.h`'s warp, the plan's wavetable path, and `Wavetable::KernelRuby`.  Triangle pivot 0.75 confirmed by the maintainer ("Keep").  `Notes#lfo(skew:)` stays its own phasor arithmetic (phase 0 mid-rise with the low point at 1 - skew/2, float32 node math): not bit-identical to `atriangle.skew`, whose low point is fixed at 0.75, so it wasn't switched.  Cost (ns/sample, min of 3 alternating runs against master-ai on the Mac's container, 800-sample buffers, `tmp/listening/osc-env-1/bench.txt`): constant-width `triangle.skew(0.3)` 23.8 -> 21.4 (unchanged within noise), width node every sample: square 29.2 -> 31.8, triangle (now on the 0.75 pivot) 50.5 -> 57.9, `pivot: 0` 48.0; width and pivot nodes 85.7 (worst case: breakpoints rebuilt every sample); at 128-sample buffers 59 -> 59 (square), 79 -> 85 (triangle), pivot node 137.  Pivot 0 keeps the inline breakpoint loop (the first version rebuilt pivot candidates on every width change: +20 ns).  Aliasing (`bin/aliasing.rb`, NHR below 20 kHz at 1/3/4 kHz): `triangle.skew(0.9)` -63/-56/-46 dB (old lobe warp -50/-35/-35; naive new -43/-30/-28): two corners instead of four kinks.
- `complex_saw`/`complex_square`/`complex_triangle` are closed-form band-limited impulse trains, integrated (`BandLimit.blit_ruby`): no aliasing or negative frequencies (-153 dB), top octave lifted ~2.6 dB.  With phase modulation, `pwm`, or sync (or resets and timelines with `clean`) they play from complex wavetables of the exact series (`Tone.complex_table`, `Tone#complex_table?`, kernel `:wavetable`; also `complex_sine` with a warp or sync; 2026-10-08, before: the naive `acomplex_*` with PM, `pwm` ignored, sync refused); without `clean`, resets of plain complex tones restart the impulse trains as before.  With `clean` (and no PM), warps, resets, and timeline jumps run through the synced table kernel without sync events (`Tone#clean_table?`: exact corners, resets as hard sync events with `FastWavetable.sync`'s `reset_phase`).  Measured two-sided (`bin/aliasing.rb -c`, harmonics on both sides): PM 0.5 rad (0.08 cycles) at 1 / 3 kHz -45 / -29 dB (naive -20 / -14; the rest are PM sidebands past Nyquist), `pwm(0.3)` -31 to -40 (naive -12 to -18; clean -113 to -118), sync 2.37 -101 to -112; clean resets against the ideal complex reset waveform -30 to -57 dB (restart -24 to -32; a minBLEP step on the table measured worse at edges, where the imaginary part has log peaks).  The impulse trains' phase leads the exact series by their integrators' leak (0.6 samples at 100 Hz, 0.006 at 1 kHz).
- `sync(ratio: r)` hard-syncs a tone to a hidden master at its own pitch (playing at pitch × r; r a number or node), `sync(master)` to a Pitch/Tone/phasor (its `wraps` port) or any trigger node; `softsync` reverses direction instead.  Synced tones use a causal minBLEP kernel whose output is exactly the naive waveform through the minBLEP's minimum-phase filter (`FastSynth.oscillate_sync`, `BandLimit.sync_tables`): polynomial segments are delayed by the filter's moments (about 2.78 samples) and events add residuals of their value, slope, and curvature jumps; sine segments use per-frequency residuals (`BandLimit.sync_sine_table`, 6 MB, built on first use).  So DC and harmonics match the ideal synced waveform (DC error < 1e-4; harmonics -56 to -106 dB; aliasing -88 to -135 dB); until 2026-10-07 every step left 2.78 samples times its height of DC behind (+0.82 on a ramp synced at 2.37x of 3 kHz) and soft-synced squares spiked on their edge at phase 0.  Synced sines cost 1.3-2.2% of realtime at 3-4 kHz masters; no phase modulation with sync.
- `fm_feedback(amount, gain: env, dc: false)` (aliases `fmfb`, `fm_fb`; amounts in cycles; sines only; renamed from `feedback`/`fb` 2026-10-09 so `feedback` is graph feedback, see Feedback loops) is FM operator self-feedback in the kernel (`FastSynth.feedback_sine`, mirror `Tone#feedback_ruby`, history `state.feedback` = [y1, y2, dc]): y = sin(2π(phase + pm + amount × avg(y[n-1], y[n-2]))) × gain, DX7-style two-sample average; `gain:` (an envelope) is inside the loop so brightness follows it, `at` is outside.  Measured at 55-440 Hz: 0.16-0.24 cycles (1-1.5 rad) saw-like, 0.32 (2 rad) the brightest clean setting; chaos starts ~0.35 but stays above 12 kHz (a hiss many playback chains drop) until ~0.56, audible broadband noise from ~0.64; `Tone::FEEDBACK_MAX` = 1 cycle (2π; DX7 FB 7 at full level) is the knob range (no clamping anywhere).  DC (mean -0.25 at 0.32 cycles) is removed from the output by default (`dc: true` keeps it) by a pitch-tracking one-pole at f/20 outside the loop.  Resets (key sync) clear the history so every note starts identically (`reset(t, keep_feedback: true)` / `.keep_feedback` keep it; timeline jumps keep it).  Aliases like FM at high notes (1 kHz, 0.24 cycles: worst alias -59 dB); ~28 ns/sample for any amount (sine 21).  Not with other shapes, pwm, sync, noise.  `Tone.dx7_feedback(0..7)` = 2^(fb-7) cycles (MSFA's arithmetic; the operator's level goes in `gain:`).  Demo: `bin/synths/fm_brass.rb` (`--feedback 0` to compare).
- `tone.gain(g)` (alias `amp`; number or node, e.g. an envelope) multiplies the output inside the Tone after `at` and jump steps, bit-identical to `tone * g` without a Multiplier (`FastArithmetic.scale`, Numo fallback/mirror); saves ~4 ns/sample at 128-sample buffers (~2 at 512) against `tone * env`.  On feedback sines it is the output gain; `fm_feedback(gain:)` is the in-loop one.
- Phase jumps (reset inputs, timeline jumps of tempo tones) are band-limited steps over the next 32 samples by default (minBLEP/minBLAMP from the old waveform to the new, queued in `state.jump_residual`; `Tone.jump_residual` adds a 4-tap raised cosine 1.5 samples after the jump so each step has the area of an ideal step on the sample, -dv/2 + ds/12: no DC drift at audio-rate resets; a reset on an edge in value starts from its left side; 2026-10-07; plain sines still jump naively).  Opt-in `clean` (`tone.clean`, `reset(trig, clean: true)`, `pwm(w, clean: true)`; user's choice 2026-10-08: the default keeps key-synced voices' cost predictable) plays a tone's jumps through the synced kernels: band-limited ramps, squares, triangles, and warped shapes without PM, noise, or an LFO fade (`Tone#reset_sync?`, kernel `:reset_sync`) make each jump a hard sync event on its sample to the target phase (`FastSynth.oscillate_sync`'s `reset_phase`), as clean as sync (harmonic error against the ideal reset waveform -72 to -86 dB instead of -19 to -38), at the cost of the naive waveform through the minimum-phase filter (about 2.8 samples of delay, minBLEP edge ringing with peaks up to ~1.4x PolyBLEP's) and about 2x the oscillator's CPU (bin/synths/fifth_pad.rb with `.clean` saws: 16% -> 19.5% of realtime at 512-sample buffers).  Resets happen on whole samples (sync pulses carry sub-sample times), so audio-rate resets jitter by up to a sample where sync doesn't.
- Reset inputs (top-down note flow): `tone.reset(trig, to: nil)` jumps the phase at every nonzero sample of `trig` (e.g. `clip.trigger`), at exactly that sample (step measured with that sample's FM/PM/width); `to:` is nil (the `with_phase` start), cycles, a node of cycles, or `:random`; `reset(nil)` removes it; not with `sync`.  The Tone splits the buffer at reset samples in Ruby around the kernels (a scan costs ~3 us per 128-sample buffer, each reset ~35 us; tones without a reset input skip it).  `.free` (`free?`) = never reset (no key sync in synth voices; reset+free and rnd+fixed `to:` conflicts: last call wins with a warning; reset+sync raises; `lfo` tones aren't `free?` but may take a reset input); `.random_phase`/`.rnd(seed:)` = random start, new random phase per reset.  Randomness: `MB::Sound.seed(n)` / `random_seed` / `next_seed` (`RandomMethods`, default seed 0 or `RANDOM_SEED`, restored before every spec example); random-phase tones draw a sub-seed when `rnd` is called (creation order), `Tone#seed=` for derived seeds.  `smooth(t, reset: trig)` jumps instead of gliding on resets.  Noise (`noise(seed:)`, `Tone#noise(blend, seed:)`) draws a sub-seed when `noise` is called too and keeps its own splitmix64 state (`Tone::State#noise`, read and written by the `fast_sound` kernels; exact Ruby mirror `Tone.noise_random`), so noise repeats from the seed and parts don't share a stream (it used C's process-wide `drand48` until 2026-10-06, so noise renders changed then); noise tones advance a running phase wrapped every sample (all four C kernels and both Ruby mirrors), so their output is the same in any block sizes (2026-10-10: before, ~1% of samples differed by an ulp, since increments reach ±freq/2 cycles and each block summed them from its start).
- `softclip`, `clip`, `abs`, numeric `quantize` use antiderivative antialiasing on the excess over the linear part plus a half-sample Thiran allpass on the dry signal (`MB::Sound::Shaper`, `GraphNode::Shaper`, the `fast_clip` extension): flat level, half a sample of delay, aliases below the fundamental 25-56 dB lower; `asoftclip`, `aclip`, `aabs`, `aquantize` are the plain shapers (exact, for control signals).
- Deliberate aliasing: `sig.decimate(rate, jitter: 0, seed:)` (aliases `crush_rate`, `srr`; `GraphNode::Decimator`, kernel `FastLofi.decimate` in `fast_lofi`, exact mirror `Decimator.process_ruby`; 2026-10-11, sound-design-1) is a sample-rate reducer: a phase accumulator advances by rate/fs after each sample and the input sample where it reaches 1 (within 1e-9, so 8000 Hz holds exactly every 6 samples) is held, with no filtering (zero-order hold at any fractional rate; the rate is a number, Pitch, or node moving per sample, e.g. `v.freq * 4` so every note folds onto its own harmonics; rates >= fs pass through, <= 0 freeze).  `jitter:` (0..0.95) scales each hold period by 1 ± jitter·u from a splitmix64 state seeded by `seed:` or a sub-seed drawn only when jitter is on.  `mix:` (number or node, default 1) blends the crushed signal with the input inside the node (crushed × mix + input × (1 − mix), float32, after the kernel; omnibus5, 2026-10-12); to be consolidated with a universal wet/dry mix for nodes and subgraphs when that exists (maintainer: "Yes, with a note to consolidate whenever we do universal wet/dry mix for nodes and subgraphs").  Same output at any buffer size; a plan boundary.  Cost ~2-6 ns/sample over its input (constant rate; 128/800-sample buffers), plus its rate node.  `interpolation: :linear` (textures-2, merged 06ca713f, 2026-10-15; the maintainer: "linear interpolation decimation to get some grunge with less ringing"; aliases `:foh`, `:lerp`; `:hold` default) is a first-order hold: the output runs in a straight line from the previous held sample to the newest over each hold period (position = the phase; state [phase, held, factor, previous held]), one hold period late.  A 1 kHz sine crushed at 7 kHz: images relative to the tone at 6/8/13 kHz -15.6/-18.0/-22.2 dB held, -31.1/-36.1/-44.6 dB linear; 12-24 kHz total -16.5 against -41.4 dB (sinc^2 instead of sinc, so less grunge too).  Bit depth stays `aquantize`.  The Bthelick vocal-lead trick: a resonant filter into a key-tracked decimator (demos `bin/synths/vocal_lead.rb`, `bin/songs/vocal_lead_song.rb`).  Omnibus5 listening picks (2026-10-11): the vocal lead's crusher tracks the note fully by default (`crush_track: 1`) and mixes with the uncrushed signal (`crush_mix:` → `decimate(mix:)`, patch 0.5, song 0.4; "Decimation wet/dry is too strong"); `drop:` octaves dive the pitch after each note-off over `drop_time:` (0.25 s; from A1 two octaves reach ~15 Hz, where each kick-wavetable cycle is nearly one kick).  The song plays `VOCAL_BASS_HOOK` (eighths at A1-E2 with rests for the dives) as a talking bass with a sine sub on the same clip, a 4-bar triangle skewed 0.9 (`Notes#lfo(skew:, phase:)`, rising 3.6 bars), `--first` the sound-design-1 version bit for bit.  `Tone#pwm` on a triangle warped the two lobes until osc-env-1 (2026-10-12); it is a true skewed triangle now (see pivots above).
- Ports (`GraphNode::Ports`): side outputs that aren't audio channels, made on first use: `tone.wraps` (sync pulses valued 1 - d, d the sub-sample position of the wrap; a wrap within 1e-9 of a sample gives 1 on it, so 2000 Hz pulses every 24 samples; `BandLimit.sync_pulses`) and `.increment`, `TempoNode#jumps`/`#jump_phase` (see Tempo sync); `node.ports`, `port_info`, `inputs`.  A node with ports computes frames; every reader (main output and ports) must read each buffer, as a Session does.

- Buffer-size invariance (2026-10-13): naive discontinuous shapes (`asquare`, `asaw`, `gauss`, naive pulses) snap a wrapped phase within 1e-9 cycles of a jump onto it, taking the value after the jump (`osc_snap_edge` in `mb_osc_shapes.h`, mirror `Tone.snap_edge_ruby`; like `bl_snap`), so jumps landing exactly on samples (800 Hz = 60 samples, 540 Hz every 800 samples: the 808 metal bank) land on the same sample at any block size; at 800-sample buffers this moved a few such edges (the 808 cymbal and open hat).  Tones whose frequency is a signal (e.g. `v.hz`, FM, vibrato) keep a running phase wrapped every sample (fixes-6, 2026-10-13; maintainer: "Yes if cpu cost in C is minimal"): `mb_wrap_phase` in `ext/mb/sound/include/mb_phase.h` (mirror `Tone.wrap_phase`; never returns 1.0, so a wrapped phase stored between blocks continues exactly; 0 for non-finite phases; compares instead of `floor()` for steps under a cycle, since the wrap is on the loop's dependency chain) in every kernel (naive/phasor in fast_sound, PolyBLEP `mb_bl_osc.h`, BLIT and feedback sines in fast_synth, cycle wavetables `mb_wavetable.h`, sample-mode position and phase in fast_wavetable, the plan's naive, vec-sine, and synth kernels) and Ruby mirror (`Tone#phases_ruby`, `BandLimit` mirrors and `.sync_pulses`, `Wavetable::KernelRuby`). - Unison: `pitch.unison(n, detune: 12.cents, layout: :random, phase: :random, spread: 0, normalize: :power, seed: nil) { |p, i| p.saw }` on any Pitch (`220.hz`, Notes, `v.hz`; `lib/mb/sound/unison.rb`): the block gets each copy's `pitch.transpose(offset)` (so `v.hz` keeps key sync, bend, glide, vibrato), and every oscillator made from it (or pitches derived from it) gets the phase through `Pitch#unison_phase` (`:random` = `rnd`, new random phases at each key-sync reset; cycles; `:reset` = leave alone).  `detune` is the outermost copies' distance either side (Interval or semitones, or an Array of fixed offsets, or a node of semitones: copies keep fixed layout fractions -1..1 scaled by it, computed for all copies at once by `Unison::Detune` in the `fast_unison` extension; copies are `Unison::CopyPitch`es making the base pitch's kind of tone; `detune_mode: :exact` (default since 2026-10-07; every copy exp per sample, ~0.15% of realtime more for 7 copies) or `:interp` ramps the exact outermost ratio every 16 samples of the stream (buffer-size independent) and spaces copies linearly in Hz, middle copy sharp by 1200·log2(cosh(d·ln2/12)) cents (0.18 at 25 cents, 2.9 at 100), ~half the detune math of `:exact`; fixed detunes keep the plain `transpose` path); `:random` layout jitters by up to 1/3 step, recenters, rescales (seeded from the root RNG or `seed:`; per-lane in synths; since 2026-10-10 copy i's block also runs in `MB::Sound.with_seed(seed + 1 + i)`, so random phases and noise made in the block repeat with the same `seed:`, and `swarm` draws one seed for its chord layout and copies; graph-io prints one `seed:`).  `GraphNode::ChannelMixer::Unison` mixes with 1/sqrt(n) (or `:peak` 1/n); `spread > 0` (or a node) returns stereo, equal-power pans × sqrt(2) with sides alternating by pair (`Unison.pan_slots`).  `mix:` (0..2 or a node, clamped; default 1 = bit-identical) sets the side copies' level to mix² (0.5 = -12 dB, 2 = +12 dB): center copies (`Unison.center_copies`: nearest the pitch for odd counts, two nearest for even; 2 copies are both centers) stay at 1, and the normalization follows the weights (power 1/sqrt(Σw²), so loudness stays put).  Per copy: the block gets `|p, i|`, `Pitch#unison_copy` (`Unison::Copy`: index, count, RNG from the unison's seed drawn after the layout), and pitch methods on copies take per-copy values: a Range (random), `spread(a..b)` (even, lowest copy first), `channels(...)` (cycled); Intervals → semitones, Lengths → seconds.  Node-detune copies of Notes pitches take `glide`/`bend_range`/`vibrato`/`transpose(node)` (`CopyPitch#notes_pitch`: a NotePitch transposed by the copy's offset node fraction × detune, so exact detune through `Notes::Frequency`; the `Detune` node is built lazily by `Unison::CopySet` only if plain copies use it).  Glides with the same settings share one `Notes::Glide` per Notes (memoized in `NotePitch#number_node`; before and inside the block alike).  `Pitch#transpose`/`NotePitch#transpose` take a node of semitones; a fixed transpose of a tempo pitch gives `TempoNode#scaled(ratio)` (exact ratio, freewheel follows the parent), so `1.beat.hz.unison(3)` stays timeline-locked.  `Notes::Glide` has `overshoot:` (0..1, smoothstep + k t³(1-t)²) and relative `from: -7.st`.  `pitch.swarm(12, chord:, detune:, glide: 0.08..0.9, overshoot:, scatter: 1.oct | from: G3..G4, drift: 10.cents, drift_rate:, spread: 1, ...)` (`lib/mb/sound/unison/swarm.rb`) is a unison of per-copy glides on Notes pitches, optional chord tones (`Unison.chord_offsets`), scattered or banded starts, and sine drift; cost ~0.8% of realtime per gliding copy at 512-sample buffers (Glide + Frequency + saw each; 24 copies ~20%, ~56% at 128), less once glides settle.  Demos: `bin/songs/unison_song.rb`, `bin/songs/swarm_song.rb`.
