# Tweening curves

<!-- summary -->
`MB::Sound::Curve` (`Curve[:elastic, overshoot:]`, many named easings with `_in`/`_out` variants, `Curve.db`/`Curve.s`, `bezier`, Procs; `#lookup` tables in C) maps progress 0..1 and is shared by glides (`v.hz.glide(t, shape:)`), tweens (`tween([300.hz, 3000.hz], 1.bar, curve:)`: the length is per step between keyframes, not the total), `smooth(t, curve:)`, and the antialiased shaper `sig.ease(curve, ...)` (`aease` exact).  `bounce_hits(2.bars, count:, elasticity:, decay:)` makes bouncing-ball rhythms.  Demos `bin/songs/tween_song.rb`, `bin/songs/bouncing_ball.rb`.

`MB::Sound::Curve` (`lib/mb/sound/curve.rb`, `curve/library.rb`) maps progress 0..1 to 0..1 (overshoot allowed), shared by glides, tweens, smoothing, shapers, and TimelineInterpolator blends: `Curve[:elastic, overshoot: 0.4, cycles: 4]`, names `linear smoothstep(:smooth,:s) smootherstep sine(_in/_out) quad..quint exp back anticipate elastic squiggle bounce steps ease(_in/_out/_in_out)`, any name with `_in/_out/_in_out/_out_in`, `Curve.db(d)`/`Curve.s(d)` (Envelope's signed-dB curve and :s shape, specs check they match), `Curve.power`, `Curve.bezier`, Procs; `reverse`, `in`/`out`/`in_out`, `>>`, `blend`, `steps`.  `#call` and `#map` (Numo) give identical values; `#lookup` evaluates a 2048-cell Hermite value table in C (`FastClip.curve_lookup`, ~4 us per 512 positions for any curve, within 1e-7 of `#map` except at bounce contacts (1e-4) and vertical end slopes), used by glides.  `bin/plot_curves.rb` plots or tabulates them.

- Glides: `v.hz.glide(t, shape: :squiggle, overshoot:, cycles:)` (`Notes::Glide`; no shape = the old smoothstep code, bit-identical, pinned by `spec/lib/mb/sound/tween_reference_spec.rb`); `swarm(..., shape:, cycles:)` takes per-copy values (`channels(:squiggle, :elastic)`, Ranges).  Shaped glides cost the same as plain ones.
- Tweens: `tween([300.hz, 3000.hz, 800.hz], 1.bar, curve: :elastic)` (`SequenceMethods#tween`, built on `Clip#tween`, a shaped Glide on a clip shifted to keyframes): the length is the time between keyframes, not the whole tween (maintainer, 2026-10-17: "I want tween length to mean interval still"; a filters-1 Bench render assumed the whole length and never swept back): N values take N steps per loop, so `tween([100.hz, 5000.hz, 100.hz], 2.bars)` is back at 100 Hz after 4 bars and loops every 6, and `tween([100.hz, 5000.hz], 2.bars)` goes up and down in 4; values are keyframes (each value at its step start, tweening to the next during the step; the last holds or loops back over the last step; repeat a value to hold it); Pitches tween in octaves and give Hz (overshoots stay above 0 Hz), plain numbers linearly, `log:` overrides, mixing raises.  `smooth(t, curve:)` curves every step change (an elastic knob).
- Tweens in Sessions (fixed 2026-10-11, branch arrange-form): a graph launch is a content jump onto the tween's first keyframe note; the source chased it and `Glide#chase` jumped there and dropped `from:`, so every tween in `bg`/`render`/scripts sat at its second keyframe from the first sample (a one-way tween stayed there; a looping one tweened only on later cycles).  `MIDI::Source::Chase#starts` now marks a chased note that starts right at the jump, and `Glide#chase_start` keeps a pending `from:` so the note-on that follows glides from it (`spec/lib/mb/sound/tween_spec.rb`).  Renders of tween demos made before the fix (e.g. `bin/songs/tween_song.rb`'s first cycles) sound different after it.
- Tweens launched partway through their loop (fixed 2026-10-11, branch omnibus4; found by arrange-3): a looping tween follows the timeline like any looping clip, so `tween([200, 1000], 1.bar)` launched at bar 2 is in its second step (1000 -> 200); the chase of that step's note glided into it from the pending `from:` (the first keyframe, 200 = the target), so it held 200 for the launch bar, and a launch mid-step jumped to the step's target and held it.  `Source::Chase` now also carries `previous` (the clip event before the chased one, around the loop) and `elapsed` (stream seconds since the chased note started), and a Glide made with `resume: true` (tweens) glides from the previous keyframe, already `elapsed` into the step, so a launch at any frame gives the same values as a tween that had played from the timeline's start (`tween_spec.rb`, buffers 800/367/128, mid-step with uneven steps and an elastic curve).  `tween(..., align: :launch)` counts cycles from the launch instead (starts at its first keyframe wherever it lands); `bin/songs/bouncing_ball.rb`'s pan rolls use it (they started at a timeline-dependent point before: held at the far side for the launch step).  Unchanged: tweens launched on their loop's start (tween_song's parts), non-looping tweens, knob follows (start at position 0).  Uneven steps (omnibus13; SessionFuzz seed 116): the glide time came from a second clip of step gaps read as a number, which switched to the next step's gap on the sample a launch chased the step before it from when the next step started between that sample and the next (174 BPM, `[1.beat, 3.beats]` launched on beat 2: the 1-beat step resumed as if it were 3 beats long, 1000 instead of 3000); the glide now reads each step's own length (`Glide` `time: :length`, the note-on's `MIDI::Event#length_hint`, and a chased note's hint is its length from the jump).
- Shaper: `sig.ease(curve, in:, out:, range:, edges: :clamp/:extend/:wrap/:mirror/:none, symmetric:)` (`GraphNode::CurveShaper`; "ease" since `curve`/`shape` are Envelope settings) is antialiased like softclip (ADAA on the excess over the in->out line plus the half-sample allpass; edge modes integrated too; closed forms for polynomial/cosine/exp curves, a Hermite antiderivative table otherwise; `FastClip.shape_curve`, mirror `CurveShaper.shape_ruby`); `aease` is exact for control signals.  Hot paths and custom Proc curves (maintainer 2026-10-25: note the table lookup option for any future curves that need it): `Curve#lookup` (the C value table glides use, `#value_table`; about a plain smoothstep's cost for any curve, within ~1e-7 of `#map` for smooth curves) is the route for a curve evaluated per sample where `#map` is too slow.  Plain `aease` maps every sample through `Curve#map_edges` (`CurveShaper#plain`), so a Proc curve costs a Ruby call per sample there (the ambient presets' `wear.aease(->(t) { ... })`: 373 us summed over the ambient song in plan_layer.md's measurements); it could send Proc (and other `#map`-only) curves through `#lookup` when one needs it, accepting the table's error, kept exact for now.  Demo: `bin/songs/tween_song.rb`; renders in /app/tmp/listening/tweening/.

- Bounce rhythms: `bounce_hits(2.bars, count: 16, elasticity: 0.75, note: C2, reverse:)` (`SequenceMethods`) is a Clip of hits at length × (1 - e^i), converging on the bar line; velocities fall by `decay:` separately from the timing (`:gentle` e^(i/2), default since 2026-10-08 (user's listening pick); `:speed` e^i, the impact speed, the old default; `:none`; a factor per hit; a Curve or Curve name over the hits; a Proc of (i, position fraction)), and `pitch: -1` (semitones or Interval per hit, or a Proc) moves later hits; demo `bin/songs/bouncing_ball.rb` (per-section decays: 0.9 per hit for the drop and settle, the user's picks; `--decay` overrides all; balls loop with `align: :launch` so they drop where launched).
- Dynamic cookbook cutoffs (`filter(:lowpass, cutoff: node)`) clamp to `Cookbook::DYNAMIC_MIN_CUTOFF` (1 Hz, like FourPole; negative and NaN included).  Fast moves into very low cutoffs still make a direct-form biquad's output jump (a DC bump that decays once the cutoff rises; measured in the commit 8323e7d1 message), so tween cutoffs as Pitches.  Since 2026-10-08 graph cookbook filters build `Filter::SVF` (`filters.md`), whose parameters may move every sample without DC bumps; the bump remains only with `structure: :biquad`.
