# Dynamics (compressor, compander, ducking, limiter, multiband)

Branch dynamics-1 (2026-10-11).  CLAUDE.md keeps a summary and points here.  Update both when behavior changes.

Maintainer's asks: a limiter for the master chain (oscillators are full scale, the master bus is -10 dB), lookahead brickwall and true-peak aware, plus a clipper-style option; a classic feed-forward compressor with a sidechain input as a node; tech house ducking ("bass needs to be louder"); multiband OTT-style upward + downward compression on Linkwitz-Riley crossovers; an arbitrary piecewise compander (2026-10-11), with monotone cubic segments.

## Survey (from memory; marked where unverified)

- Giannoulis, Massberg, Reiss, "Digital Dynamic Range Compressor Design: A Tutorial and Analysis" (JAES 60(6), 2012).  The recommended structure: level detection in dB (`x_L = 20 log10 |x|`), a static gain computer with a quadratic soft knee (below `T - W/2` unity, inside the knee `y = x + (1/R - 1)(x - T + W/2)^2 / (2W)`, above `T + W/2` `y = T + (x - T)/R`), then the gain (`y - x_L`) smoothed in the log domain with a branching one-pole (attack coefficient when the gain falls, release when it rises), then makeup.  They compare detector placements (smoothing the level before the gain computer vs the gain after it; the log-domain gain smoother avoids the release-dependent "attack lag" of linear-domain detectors and keeps the knee exact).  Their "smooth decoupled" peak detector adds a release stage inside the attack stage; I recalled but did not reverify its exact equations, so the branching smoother is what's built.  The quadratic knee formula above is verified by its own properties in the specs (continuous value and slope at both knee edges).
- True-peak limiting: BS.1770-4 Annex 2's 4x polyphase interpolator (12 taps per phase) estimates inter-sample peaks; `fast_loudness` and `Loudness::TruePeak::PHASES` already have it.  Commercial true-peak limiters oversample the gain detection (and sometimes the gain application); the latency of the interpolator (about 6 samples here) adds to the lookahead.
- Lookahead brickwall (common design, e.g. in open-source limiters such as Signalsmith's write-up; unverified details): required gain per sample `min(1, ceiling / |x|)`, a sliding minimum over the lookahead window, an instant-attack release smoother, then a moving average over the same window, with the audio delayed so the average has reached the peak's required gain when the peak arrives.  Because every value averaged is at most the peak's required gain, the output never exceeds the ceiling (up to float rounding; a final clamp catches that).
- Linkwitz-Riley crossovers: LR(2n) is a Butterworth-n lowpass squared and highpass squared; since `B_n(s) B_n(-s) = 1 + (-1)^n s^(2n)`, low + high is the allpass `B_n(-s)/B_n(s)` (LR2 needs the high band inverted).  Multi-band trees stay flat when each lower band also passes the higher crossovers' allpasses.  TPT SVFs keep these identities exactly in the digital domain (same bilinear mapping for every branch).
- OTT (Xfer, free; descended from Ableton's "OTT" multiband preset): three bands (crossovers about 88 Hz and 2.5 kHz, unverified), each with downward compression at a very high ratio (about 66:1, unverified) above a threshold and upward compression (about 4:1, unverified) below a lower one, per-band output gains, `depth` as a parallel mix, `time` scaling attack/release.  Built here from the same pieces, with values chosen by ear and measured, not copied.

## Design

One gain-computer core, several faces (`lib/mb/sound/graph_node/dynamics.rb`, kernel `ext/mb/sound/fast_dynamics`, exact mirror `Dynamics.process_ruby`):

1. **Detector**: `:peak` (|x| per sample) or `:rms` (one-pole mean square over `rms:` time, default 10 ms), in dB with a floor of -200 dB.  Linked (default): one detector for all channels, driven by the loudest channel each sample (max of |x| or of x^2); `link: false` gives each channel its own.  The detector reads the `sidechain:` (any node or bundle; one sidechain channel drives every channel) instead of the input when given.
2. **Gain computer**: a transfer curve, input level dB → output level dB, as segments `[x0, y0, b, c, d]` (`y = y0 + b dx + c dx^2 + d dx^3`, dx = x - x0) found by binary search; the first and last segments are linear, so the curve continues its end slopes.  Every face builds its segments in Ruby: the compressor's quadratic knee exactly, upward compression and expansion as extra linear segments, the compander's points linearly, as monotone cubics (Fritsch-Carlson / PCHIP slopes, never overshooting), or with a Curve shape per segment (sampled at 32 points and joined by monotone cubics), and a block form sampled every dB.  The gain is `y - x_L`, clamped to `range` (lowest, for gates and expanders) and `max_gain` (highest, for upward compression and the compander).
3. **Smoothing**: the gain in dB through a branching one-pole: `down` time while the gain falls, `up` time while it rises (compressors and ducks: attack = down, release = up; gates: attack = up, release = down), plus an optional `hold:` that delays the slow direction (restarting whenever the gain is steady or moves the other way).  While the gain is above 0 dB (an upward boost) it falls over its own `boost` time (`upward_attack:`; default 1 ms for `compress`, the attack for `compand`): with one attack for everything, a hit after a quiet stretch came through at up to +24 dB while the attack worked through the whole swing (measured on an 808 bus: peaks +6 dB over the dry peak; first fix targeting 0 dB at the boost speed still let it through, since an exponential approach to 0 never crosses it).  Per-sample recursion with state carried across buffers, so output is identical at any buffer size.  Times take seconds, Lengths, Durations (follow the tempo; `release: 1.n8` for a duck), or nodes; the kernel recomputes a coefficient only when its time changes.
4. **Lookahead**: the audio is delayed by `lookahead:` (whole samples) while the detector reads it undelayed (compressor: anticipates attacks; the limiter's own algorithm below).
5. **Makeup**: dB number, or `:auto` (half the curve's gain at 0 dBFS back, a heuristic).
6. **Mix**: `mix:` blends the processed and plain signal as gains (`gain = mix * gain + 1 - mix`), so parallel ("New York") compression stays phase-aligned even with lookahead.

**Units** (one rule, db-1, 2026-10-14): levels (`threshold:`, `upward_threshold:`, `ceiling:`, `amount:`, `range:`), gains (`makeup:`, `min_gain:`/`max_gain:`, squeeze `gain:`/`max_gain:`), and compander points are written `-12.db`: Numeric#db returns a `MB::Sound::Decibels` (`lib/mb/sound/decibels.rb`), a linear gain (0.251) that remembers its dB value, so dynamics read it as exactly -12 dB (`DynamicsMethods.level`, `.level_db`, `.gain_db`, on the shared `Decibels.gain_of`/`.db_of`; numbers_lengths_phases.md lists every dB-valued argument).  Bare numbers are linear gains, like gains everywhere else (`threshold: 0.25` is about -12 dB, `makeup: 2` +6 dB, `compand(0.01 => 0.001)`).  A negative bare number goes through `live_error` (`threshold: -20 is a linear gain, and gains can't be negative; for -20 dB write -20.db`; raises in scripts and specs; live mode reads it as dB with a warning once per call site, maintainer 2026-10-14 (db-1 round 2), replacing the absolute value the 2026-10-13 decision named), and so does a bare 0 where -inf dB means nothing (thresholds, ceilings, makeup, `max_gain`, compand points; live mode reads it as 1, 0 dB); a bare 0 `range:`/`amount:`/`min_gain:` is -inf dB (no limit on the cut).  `duck(amount:)` (and reverb `duck:`) reads a dB amount by its magnitude (`Decibels.reduction_db`, maintainer 2026-10-14: "Will duck ever be anti-duck? That's more of a follower"): `-12.db` and `12.db` both duck by 12 dB; a bare linear gain at most 1 ducks by its dB, a bare number above 1 raises with the `.db` hint (live mode: dB of ducking).  Linear levels above 1 (louder than full scale, e.g. `threshold: 6` = +15.6 dB) warn once per call site (graph documents load quietly, `quiet_levels`).  Defaults are Decibels (`threshold: -20.db`, `makeup: 0.db`, `max_gain: 24.db`; compand's `min_gain`/`max_gain` default to nil, unlimited).  Plain dB numbers remain where a value is a width or a position on the dB axis, not a level: `knee:`, compand's `over:`/`step:` and its block (dB in, dB out), and the classes under the DSL (`Dynamics.new`, `Dynamics::Transfer`).  Times as in numbers_lengths_phases.md.

Decision (maintainer, 2026-10-13, "Decibels: option b, with full migration after the genre experiment"; api-1 Q1, "one rule everywhere in the later migration (makeup, compander points and squeeze gain too)"): bare negative levels become linear gains treated by absolute value, like gains everywhere else (`live_error` for a negative linear level, a warning above 1), with every bare-number call site in bin/lib/spec moved to `.db` and graph documents loading the old meaning by format version.  api-1 (2026-10-13) added the tag, the exact dB reading, and warnings; db-1 (2026-10-14) finished it: bare numbers are linear everywhere above, the call sites (bin/lib/spec, the funk template's master compressor, presets/dnb_drums) write `.db`, the old export rewrite of bare levels is gone, and `GraphIO::FORMAT` 3 documents read bare numbers as linear while older ones load through `DynamicsMethods.from_old_document` (bare levels at 0 and below and every bare gain or compand point become the Decibels they meant; an infinite `min_gain`/`max_gain` is dropped, the unlimited default) with one warning per document (`format 2 document: bare dynamics levels and gains (like makeup: 9) are read as dB, ...; save it again`).  Every bin script renders bit-identically (101-render sweep).  Headerless text (plain `to_ruby`) is read with the current meaning.

**Limiter** (`limit`, its own kernel in the same extension, mirror `Dynamics::Limiter.process_ruby`): detector level per sample (with `true_peak: true`, the max of the sample and the Annex 2 interpolated values on both sides of it, which delays the detector by 6 samples), required gain `min(1, ceiling/level)`, a sliding minimum over `lookahead + 1` samples, an instant-attack release one-pole, a moving average over `lookahead + 1` samples, then the delayed audio times the gain, clamped to the ceiling.  Linked across channels by default.  Latency: `lookahead` samples, plus 6 with `true_peak`.

**Multiband**: `bands(f1, f2, ..., order: 4) { |low, mid, high| ... }` splits with an LR crossover tree (C kernel, mirror), yields one node (or bundle, for multichannel input) per band, and sums what the block returns (one-channel results are used for every channel; returning fewer nodes than bands drops bands).  Any node works per band.  Without a block it returns the bands as an Array.  Crossover frequencies are fixed numbers for now (nodes later: the SVF rows could take per-sample coefficients).

**Mono low end** (genre-1 round 2, maintainer 2026-10-13: "Mono bass should be an option; headphones and ambient would not want it unless pressing to vinyl"): `mono_below(frequency, order: 4)` was `bands(frequency) { |lo, hi| [lo.mono, hi] }` for multichannel nodes (one-channel nodes come back unchanged): the lows of every channel averaged into one shared channel, the highs untouched.  A 40 Hz all-side signal comes out more than 30 dB down in the side; a 2 kHz one within 0.1 dB.  Since decks-1 (2026-10-22), a stereo pair keeps its mid (L + R) / 2 untouched and highpasses only its side (L - R) / 2 with the high half of the Linkwitz-Riley crossover (`order` 2: one critically damped SVF section; 4, 8: each Butterworth section twice), then back to L/R: a mix whose lows are already mono passes sample for sample.  The crossover version put the whole mix through its allpass, rotating kick and sub against each other into taller peaks: panel round 2's N16 (Nev) measured 2.3 LU lost at :vinyl's -1 dBTP ceiling on a mix whose side was 77 dB under the mid (lap 1: -13.7 vs -11.4 LUFS with `mono: false`).  Three or more channels still use `bands`.  The same order's slopes: LR2's side highpass leaves the 40 Hz side about 15 dB higher than LR4's, LR8's 25 dB lower (spec'd).  Mastering reports print the side below the crossover in the mix before the chain too (`side below 120 Hz -35.8 dB in the mix, -32.4 dB mastered`), so a report says whether the lows were mono already.  Genre templates with club or vinyl targets put it first in their master chain (genres.md).

**Squeeze** (maintainer 2026-10-11: not "ott", which is Xfer's product name; "Squeeze it to eleven"): `squeeze(preset = :default, depth:, time:, upward:, downward:, split:, gain:, max_gain:, lookahead: 2.ms)`, three LR4 bands each through `compress` with downward and upward thresholds, `makeup: :auto`, `mix: depth`, and a 2 ms lookahead shared by every band (so the bands stay aligned and the sum flat).  `SQUEEZE_PRESETS`: `:default` (gentle glue: 120 Hz / 2.5 kHz, 3:1 down at -24/-26/-28 dB, 1.5:1 up below -42/-44/-46 dB, attacks 5/2.5/1.25 ms, releases 200/150/100 ms, depth 0.5) and `:eleven` (88 Hz / 2.5 kHz, 66:1 down at -28/-30/-32, 4:1 up below -46/-48/-50, attacks 3/1.5/0.75 ms, releases 150/100/60 ms, depth 1).  Measured on a 124 BPM 808 bus (dry peak -0.5 dB, RMS -15.7, crest 15.2 dB): default crest 17.7 (peak +1.7, RMS -16.1), `:eleven` crest 19.2 (peak +2.4, RMS -16.9); without the lookahead and with the first attack times (12/6/3 ms) `:eleven`'s crest was 32 dB (peaks +20 dB): fast attacks let through only the first fraction of a millisecond of each hit, but the auto makeup still raises those, so follow `:eleven` with `limit`.  Probes (crest vs attack scale and lookahead): 1 ms lookahead + attack x0.25 gave crest 20.1, 2 ms + x0.1 16.3).

**Channels**: every face takes a single node or a bundle and handles channels itself (excluded from ChannelDispatch, like `reverb`), returning a node for one channel, a bundle otherwise.

**Plan layer** (optimizer-2, 2026-10-12): one-channel companders (compress, expand, noise_gate, duck, compand) are `Plan::Op::Dynamics`, running FastDynamics.compand's kernel (moved to `include/mb_dynamics.h`) on the node's own state; sidechains are boundary inputs, node times fuse; a lookahead node's tail after its input ends runs unfused.  Since fuse-more-1 (2026-10-25) multichannel companders fuse too: one `Op::Dynamics` computes every channel in one kernel call (ops may compute several Values), the Dynamics rooting its region like a ChannelMixer (`Plan::MultiDescribable`); an input that ends replays the block unfused and leaves the node unfused (a channel ending first plays on as silence, a lookahead flushes).  Limiters and crossover bands stay boundaries with reasons (`Plan.explain`).  See plan_layer.md.

**CPU budget**: the master chain at 800-sample stereo buffers should stay well under 1% of realtime per compressor or limiter (one log10 and one pow per sample per detector; the limiter's window loops are O(lookahead) per sample, ~72 compares and adds at 1.5 ms), and an OTT under about 3%.  Measurements below.

## Measurements

CPU per 800-sample stereo buffer (2026-10-11, Linux container, no YJIT, best of 3 x 600 buffers, a noise source with a moving level so every gain changes each sample; the source's own 53 us subtracted; realtime is 16 667 us):

| node | us | % of realtime |
|---|---|---|
| compress (peak, linked) | 33 | 0.20 |
| compress (RMS, unlinked, 5 ms lookahead) | 47 | 0.28 |
| compand (5 points, cubic) | 31 | 0.18 |
| compand (block, 113 segments) | 32 | 0.19 |
| duck (sidechain node) | 35 | 0.21 |
| limit (true peak, 1.5 ms) | 69 | 0.42 |
| limit (no true peak) | 51 | 0.30 |
| limit (true peak, 5 ms) | 182 | 1.09 |
| bands LR4, 3 bands | 44 | 0.26 |
| bands LR8, 3 bands | 85 | 0.51 |
| squeeze (:default or :eleven) | 122 | 0.73 |

The limiter's sliding minimum and moving average loop over the window every sample (O(lookahead)); a monotonic deque and a running sum (recomputed periodically against drift) would make long lookaheads cheap if needed.

**Latency**: `compress(lookahead:)` delays by its lookahead; `limit` by `lookahead` samples plus 6 with `true_peak` (72 + 6 = 78 samples, 1.6 ms, at the defaults); `squeeze` by 2 ms.  Nothing compensates other paths: in a master chain the whole mix moves later together, which is harmless; a limiter on one player puts it 1.6 ms behind the others.  Dynamics nodes flush their delay line (silence in, `latency` samples out) when their input ends, so renders keep the last samples; in a master chain the MixSource never ends and the chain's tail tracking renders the delayed end as part of the tail (`render` adds the tail after the last player).  A new chain's spill-over feeds the old one silence, which flushes it the same way.

**Static accuracy**: steady levels follow the curves within 1e-4 dB (float32 output); slow tones through the RMS detector (symmetric attack/release, settled) within 0.1 dB at every point; asymmetric smoothing biases a rippling detector toward the faster direction (measured -0.15 dB at a point with attack 50 ms / release 500 ms), as expected.

**Listening set**: `/app/tmp/listening/dynamics-1/` (`render_bench.rb`, `bench_set.py`, `levels.json`): pumping bass/pad ducked by a kick, a drum bus (plain, compressed, parallel, compand glue), squeeze on the bus and on a mix (LUFS-matched), a hot mix through softclip vs the limiter, and an expander on a noisy pluck.

**Listening picks and duck defaults** (maintainer, bench notes 2026-10-11; applied in omnibus4): pumping: "deep pump -18 db, 1/8 + hold -- Faster release might help, but I like the deeper cut"; drum bus: parallel ("New York") compression; hot mix: softclip into the limiter.  So `duck` defaults to `amount: -18, attack: 1 ms, hold: 20 ms, release: 1.n16` (was -8, 2 ms, no hold, 0.15 s).  Gain of `1.constant.duck(kick)` behind the bench's 808 kick at 124 BPM (dB at the 16th / offbeat / 3rd 16th / next kick, time below -3 dB): old default -8.0 / -5.4 / -2.4 / -1.1, 331 ms; the bench's deep pump (1/8 release) -16.2 / -11.0 / -6.7 / -4.1, 484 ms (never recovers before the next kick); new default -14.8 / -7.2 / -2.7 / -1.0, 348 ms; 1/16 dotted -15.7 / -9.5 / -4.9 / -2.6; `hold: 1.n16, release: 1.n32` -18.0 / -6.4 / -0.9 / -0.1 (flat top).  The kick's own decay keeps the sidechain above -30 dB for most of a 16th, so the release starts late.  Parallel compression and softclip-into-limit are doc examples (DynamicsMethods, `#limit`), not new defaults; there's no master-chain helper to change.  A/B: `/app/tmp/listening/omnibus4/` (pump_old_default vs pump_new_default vs the bench's pump_deep).

## Trigger tracks: ducks keyed by a line nobody hears (duck-keys, 2026-10-18)

Maintainer: "Duck needs to key off the kick or a dedicated non-sounding line of closed hihats or impulses (gives more control when the kick envelope doesn't trigger the ducker in the desired way)."  Three forms, all read by the same readers (`duck(:x)`, `bus(:x)`, `compress(sidechain: :x)`; buses.md):

```ruby
sidechain :pump, grid(16, 'x...x...x...x.x.').loop          # a trigger track (alias trigger_track; `key` is the session key)
sidechain :pump, line, shape: :impulse                        # one sample per hit (pair with duck(..., attack: 0))
sidechain :pump, line, shape: env(0, 0.08)                    # an envelope per note (env/amp_env/fm_env/filter_env)
sidechain(:hats, hats) { |c| tr808(c) }                       # a sounding patch as the key, never heard
bass.duck(:pump); master { |mix| mix.duck(:pump, amount: -3.db) }
sidechains                                                    # name => "q:1 pump (trigger, playing) read by bass"
turn :"pump/level", 0                                         # the pump off (its level knob; scenes: "pump/level": 0)
kit { tr909; voice :trigger, silent: true }                       # a silent kit row: duck(:drums, only: :trigger)
genre(:dnb) { sidechain :pump, :pump }                        # a template trigger line (genres.md)
```

- **A trigger track is a track** (`track(:pump, trigger: true) { |clip| ... }` underneath): scenes, the clip matrix, `launch`, `swap`, `stop`, undo, takes, warm-up, and set documents treat it like any track, and it shares the namespace (`Session::Names`).  Its route is a trigger route (`Session::Buses#route(name, trigger: true)`, `Route#key`): the player renders like any other, but `#deliver_trigger` gives its buffer only to its readers' signal (after its fades, before its mute, like every sidechain source), never to the mix, buses, sends, stems (`render(stems:)` writes no file for it), CUE (`cue :pump` raises), or the bus meters.  `to:`, `send:`, and `feed` raise for trigger tracks; defining the name again without `key:` makes it an ordinary track.  Any trigger route turns on the routed render (`routed?`), so a key is exact at any buffer size like other sources.  A trigger track renders even while nothing reads it (its patch is cheap: ~17 us per 800-frame buffer for a gate key; a pad ducked by a gate trigger track measured 70 us vs 53 us with the same gate inline, a trigger track of 808 hats 127 us; Linux desktop, no YJIT, medians of 600 buffers, two rounds agreeing).  A trigger track never sleeps on silence (only mutes put players to sleep, and a read source keeps rendering while muted), so mute doesn't stop a pump: its level knob or `stop :pump` does (below).
- **Shapes.**  `:gate` (default): the note's velocity while it is held (`n.gate * n.velocity`), so accents key harder and longer notes hold the duck longer.  The brief asked for impulses by default, but a one-sample impulse barely moves the default duck (1 ms attack): -0.29 dB of a -12 dB amount; `:impulse` (`clip.trigger`) is there for `attack: 0` ducks (an instant cut on the exact sample).  Envelope shapes are rewired to the clip's notes through their recipe (`env(0, 0.08)` becomes `clip.env(0, 0.08)`; any other envelope raises with the block form as the hint).  A trigger track plays envelopes as they are: Session#add skips Playable's "envelope on a triangle and pink noise" for trigger track names.  Pad gain under a quarter-note key at 124 BPM (dB at the 16th / offbeat / 3rd 16th / next beat, time below -3 dB): gate -18.0 / -7.8 / -2.9 / -1.1, 358 ms; impulse with attack 0 -7.8 / -2.9 / -1.1 / -0.4 (hold, then the release), 237 ms; `env(0, 0.08)` -18.0 / -13.6 / -5.1 / -1.9, 426 ms; the default 808 kick through `only: :kick` -18.0 / -15.9 / -12.5 / -9.5, 484 ms (its decay keeps the sidechain above -30 dB: the reason for trigger lines).
- **Silent kit voices** (drums.md): `voice :trigger, silent: true` plays for its readers and is never mixed into the kit (nor its separate outputs); without a block a trigger pulse per hit (`Machine::TRIGGER_PULSE`, the hit's velocity falling linearly to 0 over 30 ms, so a 1 ms attack follows it).
- **Set documents** print `sidechain(:pump, q: 1) { |clip| n = clip.notes; n.gate * n.velocity }` (the patch block, built once like a track's) and load it back (`Loader::SET_COMMANDS`); a trigger track with options sidechain doesn't take prints as `track(..., trigger: true)`.
- **UI**: the tracks pane writes "trigger" before a trigger track's clip (`TrackInfo#trigger`).
- Specs: `spec/lib/mb/sound/sidechain_methods_spec.rb` (exact at 800, 7/128/333, 1, and 367/368-frame buffers), `take_spec` (replays bit for bit at 800, 367/368, 64), `genre_spec`.

- **Names** (maintainer via the coordinator, 2026-10-18: "key" became "trigger"; "pick whichever are most likely to be guessed as aliases"): `sidechain` is canonical, aliases `pump`, `trigger_track`, `trigger_line` (also the template builder's `pump`); listing `sidechains`, aliases `pumps`, `trigger_tracks`, `trigger_lines`.  Rejected: `impulse` (an existing generator, `GenerationMethods#impulse`), `click` (a Hit layer, `h.click`, and the word for a beater or metronome sound), `key_track`/`key_line` (`key` is the session key; no legacy names).
- **Level, not mute** (maintainer: "Use a knob or other existing feature to control it with code we already have"): each trigger route has a Session knob `:"pump/level"` (0..1, default 1; `Session#trigger_level_name`, made by `route(name, trigger: true)`), and `#deliver_trigger` multiplies the trigger by it on exact frames, like send levels.  So `turn :"pump/level", 0` stops the pump (journaled, undoable, exact in takes; `over:` ramps), scenes and sections take `"pump/level": 0`, `learn`/`cc:` map it to a controller, and set documents save it as a knob line.  Between 0 and 1 it lowers the trigger, which changes the duck only near its threshold (a gate at 0.75 stays over -30 dB down to a level of about 0.04): it is an on/off control for gates and a depth for shaped triggers.  Mute keeps the old rule (readers hear sources before their mute, so a soloed bass keeps pumping); `mute :pump` prints a one-line hint naming the knob and `stop`.
- **Impulse warning**: `duck(:pump)` warns once per call site (`Decibels.warn_once`) when `:pump` was defined with `shape: :impulse` and the duck's attack isn't 0 (checked when the duck is built, so a trigger defined later isn't caught).

Later: triggers as a plan input (`p.param`) rather than a boundary.

## Reverb ducking

The reverb's own `duck:` has fixed times (DUCK_FALL 10 ms, DUCK_RISE 300 ms after a 50 ms peak follower; the maintainer asked for a faster duck release).  Instead of new reverb parameters, a reverb can now be ducked by its input with any times: `wet = sig.reverb(:hall, dry: 0); sig + wet.duck(sig, amount: -12.db, release: 80.ms)` (sig used twice branches through a Tee).  Not yet a reverb option.
