# Filter banks (`GraphNode::FilterBank`)

<!-- summary -->
`sig.filter_bank(freqs, width:, gain:, pan:, normalize:)` (`GraphNode::FilterBank`, filterbank-1, 2026-11-13) runs N SVF sections in one node and one C kernel (`include/mb_filter_bank.h`, `FastFilter.filter_bank`, exact Ruby mirror `FilterBank.process_ruby`), each band with its own type, frequency, width, gain, and pan, summed into C output channels (stereo now, written for N) or chained (`serial: true`).  `bandpass_series`, `peq_series`, `peq`, and `formant` are built on it; widths are unit-typed (`30.cents` octaves, `40.hz` Hz, a number Q) and any per-band argument takes `per_harmonic(a..b, curve:)`, a bare Range, a list, or a Proc.  A plan op (`Plan::Op::FilterBank`) fuses it and lane-groups it across voices.
<!-- /summary -->

## Quick reference

- `sig.filter_bank([300, 900, 2400], width: 50.cents, gain: [1, 0.5, 0.25], pan: per_harmonic(-0.8..0.8), normalize: true)`; `sig.bandpass_series(f0, count: 32, width: 15.cents..90.cents, pan: -1..1)`; `sig.peq_series(f0, count: 8, gain: -6.db)`; `sig.peq(200.hz => -6.db)`; `sig.formant(:a, :o, morph:)`.
- Widths: an Interval is an octave bandwidth (`30.cents`, `0.25.oct`; the cookbook's digital bandwidth, so Q follows a moving band), a Pitch a bandwidth in Hz (`40.hz`: Q = f / 40 on every change), a number or node Q (`quality:` too; `peq`/`peq_series` keep plain numbers as octaves).
- Per band: `per_harmonic(a..b, curve: :exp)` (band i of N at a + (b - a) curve(i / (N - 1)); Intervals, Pitches, Decibels, numbers), `per_harmonic(v1, v2, ...)` (one per band, cycling), a bare Range (`per_harmonic` with the linear curve), an Array, or a Proc of the band index.
- Code `lib/mb/sound/graph_node/filter_bank.rb` (node, router, outputs), `lib/mb/sound/per_harmonic.rb`, kernel `ext/mb/sound/include/mb_filter_bank.h` (fast_filter, fast_plan's `plan_filter_bank.c`), plan op `lib/mb/sound/plan/filter_bank_op.rb`; spec `spec/lib/mb/sound/graph_node/filter_bank_spec.rb`; help `help :filters`.

## The node (filterbank-1, 2026-11-13)

Maintainer, choosing option 3 of the FilterSum review: "Do 3 now, with the future possibilities of multichannel/surround and a filter-to-graphnode refactor in mind.  Clean up old unused leftovers like filtersum."  Before it, `bandpass_series` was a `Filter::FilterSum` of N `Filter::SVF`s in a `SampleWrapper` (a plan boundary: "a Filter::FilterSum filter"), `peq` a `Filter::FilterChain` of SVFs, and `formant` its own five-section kernel (`FastFilter.formant`); three ways to run parallel or serial SVF sections.

**Bands.**  Each band is one SVF section (`mb_svf.h`'s design and step, the same as `filter(:bandpass, ...)`): a type (any `Filter::SVF` type, `:bandpass` by default; `:peak`, `:notch`, shelves, and passes for EQs), a frequency, a width, and a linear gain (Decibels read exactly), each a number or a node read every sample.  Frequencies have a harmonic layout, f = F (1 + R h): F a frequency, R a ratio (numbers or nodes, shared by every band or per band), h the band's harmonic offset (its index for `bandpass_series`/`peq_series`, 0 for explicit frequencies), so a moving fundamental is one signal read by every band rather than N multipliers.  Widths are kept as (mode, value): Q, octaves (Q = 0.5 / sinh(bw w0 ln 2 / (2 sin w0)), Cookbook's), or Hz (Q = f / bw).

**Outputs, written for N channels.**  The bank mixes every band into C output channels with a per-band gain vector.  C is 1 unless `pan:` or `channels:` says otherwise.  Stereo pans are positions -1..1 with a `ChannelMixer::PanLaws` law (`pan_law: :equal_power` default, `:linear`, `:minus_4_5db`): constant pans become the band's gain vector (PanLaws.gains), node pans are recomputed by the kernel with the same formulas whenever the pan moves.  For C > 2 the kernel already takes any constant gain vector per band; a surround `place:` computes them from `ChannelMixer::Position`'s laws later (moving surround pans then add a law id per channel count), so nothing in the kernel or the plan op assumes two channels.  With C > 1 the DSL returns a `Channels` bundle of `FilterBank::Output`s whose `FilterBank::Router` (a `MultiOutput`, `Plan::MultiDescribable`) computes every channel in one kernel call, as multichannel Dynamics does.

**Topology.**  `:parallel` (the default) sums the bands (in double, one float32 rounding per output sample).  `serial: true` chains them (`peq`, `peq_series`): each band's output is rounded to float32 and fed to the next, as `Filter::FilterChain` of SVFs did, so peq renders are bit-identical to before (null tests against master-ai).  Serial banks are mono and take no `normalize:`.

**Normalization.**  `normalize: true` scales the output so pink noise (equal power per octave) keeps its power over 100 Hz-10 kHz (Formant's reference band): scale² = ln(100) / Σ g² P(Q), with P(Q) = 2 atan(√(4Q² - 1)) / √(4Q² - 1) the power an analog bandpass of peak gain 1 passes from pink noise (2 at Q 0.5, the atanh form below; ~π/2Q for narrow bands), so the level holds when bands are added, widened, or narrowed (`:bandpass` and `:bandpass_skirt` bands only).  The kernel keeps each band's term and recomputes the scale only on samples where a width or gain moves.  Overlap between bands is ignored (a sum of powers): narrow bands hold within 0.3 dB (spec: 8 harmonics of 150 Hz at Q 40, analytic responses), fixed-Q bands that overlap up a harmonic series add between peaks, so the bank comes out louder than the reference (+0.9 dB at Q 10 over 8 harmonics of 150 Hz, +1.0 dB at Q 20 over 16, +1.7 dB at Q 3 over 4).

**Front ends.**  The band settings come from one of two front ends in the same kernel: the band list above, or morph tables (Formant): S snapshots of each band's (ln f, ln Q, ln g), a morph position (0..1 across the snapshots, clamped), a shift in semitones added to ln f, and a width scale subtracted from ln Q (with Formant's normalization, -ln(scale) / 2 added to ln g).  `Formant` is a `FilterBank` subclass that builds the tables from its vowels; its kernel is the old `FastFilter.formant` loop moved into the bank, so its output is bit-identical (null tests against master-ai and against the old kernel: one vowel, a five-vowel morph, morph, shift, and width moving, unnormalized).  Formant keeps its own normalization (each vowel's table normalized from its analytic response at construction, plus the width law); the bank's live rule is the general form of the same idea (a narrower band passes power in proportion to 1/Q) but it ignores the overlap Formant's table normalization measures, so switching would move Formant's levels (not measured yet): a Bench question, not a silent change.

**Kernel and rules.**  `include/mb_filter_bank.h` (`mb_fbank_run`) is shared by fast_filter (`FastFilter.filter_bank(outs, x, config, signals, state, rate)`) and fast_plan (`OP_FILTER_BANK`, `plan_filter_bank.c`).  The node keeps its settings in a DFloat (`@config`: a header, then each band's type, parameter slots, constants, and channel gains, then any morph tables) and its state in another (2 integrator states per band, then the flush grid count, `MB_FLUSH_GRID`), both read by the C op each block, so sample-rate changes and rebuilds need no recompile.  Node parameters are sampled once per block into a signal list (one entry per distinct node: a fundamental shared by 32 bands is read once) and bands refer to them by slot.  Coefficients are recomputed only on samples where a signal changes; the same output at any buffer size (state carried; flushes on its own 800-sample grid).  `node_traits memory: :short, carry: :snapshot` (the state; a snapshot of another band count starts fresh).  The bank ends when its input or any parameter node ends (as Formant did).

**Plan.**  `Plan::Op::FilterBank` (one dst per channel, `extra_dsts` for C > 1; the node is the op's object) fuses the bank with its input and parameter nodes and runs it inside lane groups (a voice per lane, one `run_lanes` call; each lane runs the kernel in turn: no lane-major kernel yet).  Mono banks are `Plan::Describable` nodes; multichannel banks plan through their router.  Before, `bandpass_series` and `formant` were plan boundaries.

## Measurements (filterbank-1, Mac container, against a master-ai 3314d3af worktree)

- 32-band `bandpass_series(f0, count: 32, quality: 14.14)` on 10 s of noise at 800-frame blocks, best of 3 (old / new): fixed f0 0.256 / 0.054 s unplanned, 0.217 / 0.054 s planned; f0 an LFO 0.480 / 0.274 s unplanned, 0.487 / 0.249 s planned.  The hand-built sum of 32 `filter(:bandpass)` nodes (the same in both trees): fixed 0.256 s unplanned, 0.120 s planned; moving 0.506 / 0.283-0.302 s.  A moving fundamental recomputes every band's coefficients each sample (a tan per band); fixed settings cost about 3.5 ns per band-sample.
- 8 synth voices of dense_modulated.mid, each `bandpass_series(v.hz, count: 24, quality: 30)`, 8 s at 128-frame blocks, best of 3 (old / new, % of realtime): plans off 173 / 69, planned without lane groups 156 / 36, lane groups 143 / 33.
- Allocations per 128-frame buffer in steady state (unplanned and planned alike): 32-band bandpass_series, fixed or moving, 257 objects / 0; peq and formant 0 / 0.
- jit_bench --quick (one repeat, each tree): render means within noise (tunnel_vision 47.6 / 47.3% at 128 frames YJIT on, night_bus_flow 9.7 / 9.9%, dense 33.9 / 32.7%); night_bus_flow's scene builds (its peq) in two more alternating rounds of 2 repeats, slowest block YJIT on at 128 frames 17.3, 15.4 ms (old) and 14.9, 15.7 ms (new).
- Null tests (96000 samples, blocks cycling 800/128/367): formant and peq/peq_series bit-identical; bandpass_series -138 to -141 dB re peak (band sums in double, node fundamentals multiplied in double).

## Toward filters as graph nodes

The coming refactor ("filter to graph node") makes filters native GraphNodes instead of `Filter` objects run by `Filter::SampleWrapper` (which samples inputs into Hashes, forwards unknown methods to the filter, and asks `Filter` classes for their state through `SampleWrapper.filter_state`).  FilterBank is the pattern: a node class owning its kernel's state and settings as DFloats, describing itself to the plan layer, carrying state by snapshot, with design math (coefficients, responses) in class methods.  Next steps, in order of payoff:
- `filter(:lowpass, cutoff:, quality:)` is a one-band bank: the SVF wrapper path (and `Op::FilterSvf`, whose lane-major kernel is worth keeping as the one-band fast path) can become a `FilterBank` with one band, so a filter and a bank of them share one node, one kernel, and one plan op.
- `GraphNode::FourPole` already is a node over `Filter::FourPole`'s math; its state can move onto the node the same way.
- `structure: :biquad` (Cookbook) stays as the direct form (its thumps on drums), as a node of its own.
- Filters used outside graphs (Butterworth, FIR, HilbertIIR, NoiseColor, FilterChain, the envelope followers) stay Array processors.

## What it replaced

- `Filter::FilterSum` (parallel SVFs for `bandpass_series`) and `Filter::FilterSet` (its base class with FilterChain; folded into `FilterChain`), removed.
- `Filter::FilterBank` (the maintainer's 2020 class for parallel filters over Arrays, not used in graphs; filters.md's "Later": "can be removed if we add a replacement"), removed.
- `FastFilter.formant` and `Formant.process_ruby` (Formant runs on the bank kernel), removed.
- `peq`'s `Filter::FilterChain` of SVFs in a SampleWrapper, and `structure: :biquad` on `peq`, `peq_series`, and `bandpass_series` (unused outside specs; chain `filter(:peak, ..., structure: :biquad)` for the direct form).
- `FilterChain` stays: Butterworth, HilbertIIR, and NoiseColor are chains of biquads outside the plan layer.
