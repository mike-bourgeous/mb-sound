# Generative music

<!-- summary -->
A generator is a looping Clip whose events per cycle are a pure function of (seed, cycle): every draw is counter-based (`Generative::Dice`, splitmix64 over the seed and a key path, C `fast_generative` with an exact Ruby mirror), so cycles come out the same cold or in order (seeks, takes, documents, any buffer size).  Probability scales (`Weights`, `Chord`, `Field`, `Harmony`) are printable values with operators; `generate`, `strikes`, `melody`, `motifs` (phrase memory), and `beats` (evolving drum rows) make generator clips, steerable by knobs read once per cycle at a decision point; `markov` and `lsystem` write long forms that `flow { generate ... }` plays and `Form::Plan` works out ahead.  Help `help :generative`, `help :long_form`.
<!-- /summary -->

## Quick reference

- Generators: `generate`, `strikes`, `melody`, `motifs`, `beats`; long forms `markov`, `lsystem` played by `flow { generate ... }`; scales `Weights`, `Chord`, `Field`, `Harmony`.
- Every draw is counter-based (`Generative::Dice`, `fast_generative`); seeds come from `MB::Sound.seed` / `next_seed`.
- Specs `spec/lib/mb/sound/generative/`; demo `bin/songs/generative_demo.rb`; help `help :generative`, `help :long_form`.

The generative layer, phase G1 (branch `gen-1`, 2026-10-15; follow-ups `gen-2`), G2, phrase memory (branch `gen-3`, 2026-10-16), G3, knob steering and evolving rhythms (branch `generative-g3`, 2026-10-28), and G4, long form (branch `generative-g4`, 2026-10-29), built to the proposal of the research spike `research-generative` (commit be0a9e79, `research/generative/README.md` and `proposal.md`; never merged).  The summary block above feeds the generated index (`design/notes/README.md`, `rake docs:index`).  Update it when behavior changes.

At a glance (compact forms; the sections below have the details):

- Values: `scale(:dorian, :d).weights.blur(0.1) + tones(D3, F3, A3) * 2` (or `chord(:min7, root: :d).weights`: `chord` with a quality and `root:` is a `Generative::Chord` value, anything else the MIDI transform), `.blend(other, t)`, `.over(A3..A5, around: E5)` (a `Field`), `harmony(0 => a, 12.bars => b, curve:, loop:)` (keys and loops are lengths, plain numbers raise; keyframes blended per moment; Weights `+ - * blend` with a Harmony give a Harmony); they print back as the expression that made them.
- Clips: `generate(1.bar, values:) { |cycle, dice| rows }` (`Clip.generate`; lengths, not Integer divisions), `strikes(field, every:, chance:, gap:)`, `melody(weights_or_harmony, ...)` (Scale melodies keep their notes; `vary: true` is a generator); `Clip#values` is what kits build voices for; `map_clip` transforms map generated events (`Generative::Producer`).
- Phrase memory: `motifs(h, 8, step: 1.n8, form: %i[a a b a], answer: { b: :a }, vary:, mutate:, evolve:, range:, around:)` (`Generative::Motifs`); every `evolve` passes each step mutates within 32 generations of the first form (a cold jump to cycle 10^6 costs one cycle, ~0.1-5 ms).
- Steering (`Generative::Steer`): `motifs(h, 8, density: knob(:busy), mutate: knob(:wander))`, `range: knob(:reg).choose(A2..A4, A3..A5)`, `strikes(chance:)`, `beats(energy:)`, `generate(1.bar, busy: knob(:busy)) { |cycle, dice, busy:| }`, read once per cycle at its decision point, `lead:` (one beat) before it.
- Rhythms: `beats(16, hold: 2, energy: knob(:energy)) { kick [1, 0, 0, 0] * 4, keep: [0, 4, 8, 12]; hat euclid(10, 16), mutate: 0.5; fill every: 8, snare: 0.7 }` (`Generative::Beats`); `rhythm(field, pattern)` one melodic row.
- Live, reading cycle N queues N+1 on the realtime scheduler thread (`Scheduler#background`, `Generative::Ahead`); renders compute where read.  Demos `bin/songs/generative_demo.rb`, `bin/songs/generative_steer.rb` (`--fixed`), `bin/songs/generative_blur.rb`; `help :generative`.
- Long form: `markov(still: { drift: 3, hush: 1 }, ..., seed:)` (pair keys `[a, b] =>` second order; `outro: {}` ends and the next draw starts over; weights may be knobs, read at commit points), `lsystem(%i[intro body outro], body: { %i[build drop body] => 2, ... }, generations: 3, seed:)` (nonterminals skipped; `vary: true` a new word per visit), both with `take`, `word`, `.flow(bars)`; `flow { generate chain, still: 6, drift: 4..8 }` plays one drawn section per pass (`goto :x` forces a state); `form.plan(seed:).at(pos)` (`Form::Plan`) works passes out ahead; genre templates' `generator` (`t.generative(seed:)`, `t.endless`); `bin/songs/endless.rb`; `help :long_form`.

## The shape

A generator is a **looping Clip whose events for each cycle are a pure function of (seed, cycle)**.  Every random choice is a counter-based draw (`dice.rand(:note, i)`: a hash of the seed and the keys), never a call on a stateful `Random`, so cycle 517 comes out the same computed cold (a seek, a take replayed from the middle, a render that starts at hour three) or after cycles 0..516.  Generator clips carry their per-cycle block as the clip's `Clip::Variation` (the hook `humanize(vary:)` and `permute(vary:)` already used), so they play wherever clips play: synths, `tr808`/`tr909`/kits, scenes, `swap`, `rec`, `bake`, MIDI export, takes, graph documents.

Maintainer, 2026-10-15: "Start G1 now"; on the proposal's four design choices, "Accept for now but discuss later after build":

1. Generators are Clips first (a stateful live MIDI source for call and response comes later, phase 5).
2. Generation runs one cycle ahead on the scheduler thread, with the dice in C.
3. Knobs are read at a decision point one beat before each cycle (per-generator `lead:`) — built in G3 (Steering, below).

Maintainer, 2026-10-16: "Start G2 now": phrase memory (motifs, a a b a forms, answers, mutation every few passes) on the G1 dice, a same-register melody A/B, and dense/granular blur demos (the proposal's G3 phrase memory moved up; knob steering stays G3, long form later).  Listening Bench verdicts that shaped it: the spike's "Phrase memory vs a fresh walk" went to "a2 phrases, no blur" (so the demo plays no blur by default); G1's "melody(scale) vs melody(harmony)" went to the old lead, with "New is higher so comparison isn't as easy" (so every demo lead now plays in one register); G1 blur: "much more audible with a much higher density or a granular sampler" (`bin/songs/generative_blur.rb`).
4. Forms allow the same section name with different lengths — built in G4 (generative-g4, 2026-10-29; arrangement.md, "Song forms").

## Pieces (`lib/mb/sound/generative.rb`, `generative/`, `generative_methods.rb`)

- **Dice** (`generative/dice.rb`, kernel `ext/mb/sound/fast_generative`): state = splitmix64's finalizer of the seed; each key folds in as `mix(state ^ key)`.  Keys: Integers (low 64 bits, two's complement), Symbols and Strings (FNV-1a; `Symbol#hash` changes per process), Rationals (`mix(key(num)) ^ key(den)`), nil; Floats raise (draws must not depend on rounding).  `Dice.new(seed, *keys)`, `dice[:kick]` (a sub-path: `dice[:a].rand(1) == dice.rand(:a, 1)`), `rand`, `rands(n)` (one C call), `chance(p, ...)`, `int(range, ...)`, `pick(Array | Hash | Field, ...)`, `smooth(t, ...)` (value noise), `shuffle`.  `Dice.index(weights, u)` is the weighted pick everything uses: Array#sum's Kahan-Babuska total, then the first running sum past u * total (the C version reproduces Array#sum exactly).  `MB_SOUND_KERNELS=fast_generative=ruby` (or `Kernels.set(fast_generative: :ruby)`; the `dice_*` kernels, kernels.md) runs the exact mirror; `spec/ext/mb/sound/fast_generative_spec.rb` compares them.
- **Weights** (`weights.rb`): 12 pitch-class weights, a value (frozen), not a signal node, so operators are value arithmetic: `+` layers (or adds a number), `*` scales or masks class by class, `-` (floored at 0), `/`, `**` (sharpen), `blur(amount, reach:)` (leaks to neighbors, keeping the total), `blend(other, t)` (each side normalized, so halfway between keys favors the common tones; with a Harmony, a Harmony, gen-3), `floor`, `normalize`, `over(range, around:, width:)` → Field.  With a Harmony operand, `+`, `-`, `*`, and `blend` (gen-3; maintainer's open item, "my call, do it") return a Harmony (`Harmony.of_weights`: the Weights combined with the harmony at each moment, printing back as written, repeating with the harmony's period; gen-2): `s.blur(0.2) + chords * 2` works like `chords * 2 + s.blur(0.2)`, bit for bit.  Made by `scale(:dorian, :d).weights` (`Scale#weights(*per_degree)`, a module included into Scale), `tones(D3, F3, A3)` (a chord layer), `chord(:min7, root: :d).weights` (a named chord layer, below), `weights(12 numbers)`.  `puts w` is a bar chart.
- **Chord** (`chord.rb`, gen-2; maintainer 2026-10-15: "Add named chords too"): `chord(:min7, root: :d)` is a chord value; `.weights` is the same layer as `tones(*chord.notes)`, `.weights(2, 1, 1.5, 1)` weighs each chord tone from the root up (cycled), `.notes` gives Notes lowest first after `inversion:` (0 up to size - 1).  `SequenceMethods#chord` dispatches: one quality Symbol/String plus `root:` (no `scale:`) is the value, every other call the MIDI transform as before; `Transform::Chord` now raises for a chord name with `root:`/`scale:` (it ignored them), so the two never overlap.  Qualities are the transform's `SHAPES`/`ALIASES` (one table; `:maj :min :dim :aug :sus2 :sus4 :'7'/:dom7 :maj7 :min7/:m7 :m7b5 :dim7 :'6' :min6/:m6 :'9' :maj9 :min9 :add9 :power ...`).  Roots: names (octave 4 without a number, like `scale`; `:d3`, `:bb2`), Notes, note numbers, Pitches (nearest note).  Prints back as `chord(:min7, root: :d).weights`; `GraphIO::Registry::VALUES` allows `Chord#weights` (`chord` is the recorded DSL method).  `Generative.weights` takes Chords, so harmony keyframes may be chords.
- **Field** (`field.rb`): weights over a contiguous range of note numbers (pitch class × a Gaussian bell around `around:` with `width:` semitones), plus `harmonic` (the class weights inside the bell's 5% register) for `tonal` (the scale notes in register), `home(near)`, `near(target, u)`.  `draw(u)`, `**`.
- **Harmony** (`harmony.rb`): keyframes at clip positions (Durations: `12.bars`, `3.beats`; 0 for the start) of Weights, Scales, Chords, or note Arrays, blended between (`curve: :linear`, `:step`, or any Curve), `loop:`; the blend's shape is Weights#blend's (each side normalized) and its total moves from one keyframe's total to the next's (gen-3: G1 dropped to a total of 1 between keyframes and jumped back to the keyframe as written on its exact position, so `key + chords * 1.5` weighed the scale notes at 1/11 of the chord tones between keyframes and 1/2.5 on them; found when motifs lost the scale notes between keyframes; changes what G1 melodies and strikes draw from layered harmonies, A/B `g2.hfix` on the Bench); `blur` and operators apply to the blend at each moment, and may take other Harmonies (`key.blur(0.15) + chords * 1.5`).  `at(position)` caches by position (512) and caches held keyframes with their operators applied; `over(...)` gives a **FieldTimeline** (`at(position)` → Field, its bell computed once, Fields cached by their weights).  `harmony(0 => a, 12.bars => b)` parses as keywords with non-Symbol keys (`**positions`).  Keys and `loop:` must be lengths (gen-2; maintainer 2026-10-15: "Require lengths"): any zero is the start, other plain numbers raise with a `write 12.bars` hint (G1 read them as bars; live mode still does, with a warning, like bare dB numbers), seconds lengths raise (they don't follow the tempo).
- Every value remembers the expression that made it (`Generative::Value`) and prints it back: `scale(:dorian, D4).weights.blur(0.1) + tones(D3, F3, A3, C4) * 1.2`, parenthesizing equal-precedence right operands so values rebuild with the same rounding.  The recipe writer prints them through the same code (`RubyWriter#leaf`).
- **Generator** (`generator.rb`, `producer.rb`): the Variation block of a generator clip: `events(cycle)` computes once per cycle (a Mutex-guarded cache of 32 cycles), normalizes rows (`[start, length, value, velocity, { marks }]`, starts in exact whole notes or Durations; Floats raise) and checks `reach` (latest end from the cycle's start, 2 cycles by default; it sets the clip's note-off lookback), and keeps `stats` (cycles, notes, thread CPU, worst cycle).  `Producer` marks variations that replace events: `Clip#map_clip` (transpose, legato, reverse, stretch, rotate, vel, ...) wraps them with its map (`Mapped`), so transforming a generator transforms what it generates (before G1, `melody(vary: true).transpose(12)` silently played untransposed variations).
- **Ahead** (`ahead.rb`): reading cycle N queues N+1 on a runner: `Session::Scheduler#background(&block)` on a realtime session (the scheduler thread, priority -3; the scheduler attaches itself when its thread starts and detaches on close).  Renders and specs have no runner: cycles are computed where they're read, with the same events.
- **Clip.generate** (`clip_generate.rb`, console `generate`): `generate(1.bar, values: notes, seed:, reach:) { |cycle, dice| rows }`.  Cycle lengths must be lengths (`2.bars`, `1/2r`): a plain Integer raises (it would be a note division, the spike's friction 2).  `dice` is `Dice.new(seed, cycle)`; `Dice.new(dice.seed)` for draws shared across cycles.  The clip's own events are cycle 0's (what it plays without looping, what listings and `first_note` see).
- **Clip#values**: the notes a clip may play (`values:` for generator clips, else its events' values); drum kits (`Drums::Machine`, `TR808`, `Kit#plays_clip?`) choose voices from it instead of base events (the spike's placeholder events are gone).
- **strikes** (`strikes.rb`, console): candidates on each step of `every:` with `chance:` (a number or a lambda of the cycle), keyed by the **global** step, so the cycle `length:` only sets caching; a candidate within `gap:` steps after another candidate is dropped (a look-back rule: any cycle needs only `gap - 1` steps before it); the note is drawn from the field at the strike's position, sharpened by `sharpen:`.
- **motifs** (`motifs.rb`, `GenerativeMethods#motifs`; G2, gen-3): a melody with phrase memory.  `motifs(source, steps = 8, step: 1.n8, form: %i[a a b a], answer: { b: :a }, density: 0.5, vary: 0.2, mutate: 0.15, evolve: 2, leap: 3, range:, around:, width:, velocity:, legato:, seed:)` is a generator clip of one phrase per cycle (`steps * step` long): cycle n plays letter `form[n % form.length]` (nil: a silent phrase) of pass `n / form.length`, motif generation `pass / evolve`.  Named `motifs`, not the proposal's `phrases`: `phrases 8, 16` is a Genre::Builder method (phrase lengths); no MB::Sound, Pry, Clip, or GraphNode name collides.
  - A motif (`Motifs::Motif`) is per grid step: whether a note starts there (step 0 always; others with `density`, strong (even) steps 1.2x, weak 0.8x), a contour in scale steps (moves of 0, ±1, ±2, ±3 weighted 1, 3, 1, 0.4, up to `leap`, turning back past ±6 from the first note, then centered so the notes average out at 0), a velocity, and a per-letter anchor offset of -1..1 steps.  Realized per note against the field where the note starts: the scale notes there (`Field#tonal`, cached per Field), the anchor the scale note nearest `around:` (the range's middle by default) plus the offset, the note `contour` steps from it.  So a motif comes back through chord and key changes, in the register `range:`/`around:` set (to match another line: the demo's leads average 62-63 at seed 7).
  - Rules: a phrase's first note is the strongest note nearest its target (`Field#home`: a chord tone when a chord layer is on top); answers (`answer: { b: :a }`) keep the call's rhythm and the first half of its contour, mirror the rest around the last kept note, land on the strongest note nearest the end (home), and hold it to the phrase's end; a call's last note moves a scale step off the strongest notes (an open ending) when the field has stronger and weaker notes; repeats of a letter within a pass vary (`vary`: a middle note moved a step or dropped, the note before holding through); blurred wrong notes (a semitone neighbor outside the scale notes, by its weight, the target counted 3 times) only in the middle of a phrase.  A Scale source gets its root weighted 1.5 so answers have a home; Weights and Harmonies weigh their own.  Answers answer motifs only (chains raise).
  - Mutation, bounded (so a cold jump costs one cycle and a motif keeps its face): each step of a motif mutates in a generation with probability `mutate`, and its state is set by its latest mutation within `Motifs::MEMORY` (32) generations, relative to the first form: restore (weight 3), neighbor (±1 step, 3), toggle (drop a note, or fill a rest with a passing note between its neighbors, 1.5), accent (×0.8 or ×1.15, 1).  A motif is never more than one change per step from where it began, and generation g costs one look back per step (draws come 64 generations per C call, cached), whatever g is.  The spike's `Phrases` mutated generation g from g - 1 (a memo chain: 20-45 ms cold at cycle 10,000, more further in); this definition is a pure function of (seed, letter, g), so sequential and cold are the same by construction.  (A motif can't drift arbitrarily far: question for the maintainer whether a slower "the tune grows" drift is wanted, e.g. re-basing every N generations, at the cost of chains.)
  - Recipes and documents: a recorded GenerativeMethods call; `form:` prints as an Array of Symbols, `answer:` as a Hash.  The loader counts `steps` like melody's; motifs itself caps steps at 256 and the form at 64 letters.
- **melody** (`SequenceMethods#melody`, `generative/melody.rb`): with a Scale, the same notes as before G1 (`vary: true` is now a generator clip; each cycle still draws from `Random.new(Clip.cycle_seed(seed, cycle))`, and the walk's pick goes through `Dice.index`, the same arithmetic: 0 mismatches over 1000 seeds × parameter sets; `bin/songs/midi_transforms_song.rb`, whose bass is a `melody(vary: true)`, renders byte-identical on master-ai and gen-1).  With Weights, a Harmony, a Field, or a FieldTimeline: a walk over the notes with weight (`leap:` of them at most), by weight / move size, from the strongest note nearest `start:`, reading the field where each note starts; counter-based dice.

## Steering (G3, `generative/steer.rb`; maintainer 2026-10-28: "Generative G3" tonight)

- **What steers**: any option given a moving param (MIDI::Param: `knob(:x)`, `cc(1)`, a tempo LFO, `knob(:x).choose(...)`, param arithmetic) makes the generator *steered*; plain numbers keep the unsteered code paths (renders without params are unchanged; `golden:check` untouched).  Options: `generate(1.bar, busy: knob(:busy)) { |cycle, dice, busy:| }` (extra keywords reach the block as keywords, checked against its parameters with did-you-mean, a typo of `seed:` too; plain values pass through every cycle), `motifs` `density:` / `vary:` / `mutate:` / `range:` (a choice of ranges), `melody` (probability scales, `vary: true`) `rest:` / `leap:` (rounded) / `range:`, `strikes` `chance:` (it read the cycle start before G3; now the decision point like the rest), `beats`/`rhythm` `energy:` / `swing:`.
- **The decision point** of cycle n is `n * length - lead` in clip positions (`lead:` a length, one beat by default, or the cycle if shorter; at most one cycle).  Values decided there are a frozen Hash; the cycle's events are a pure function of (seed, cycle, values), cached by `[cycle, values]`.
- **Where the read happens**: a steered clip (`Clip#steered?`, `#steer_lead`) doesn't read a cycle until a read window reaches its decision point (`Clip#edges` skips it; nothing of it may start earlier: steered events start at most `lead` before their cycle, checked); `Clip#edge_horizon` counts an undecided cycle's decision point as a possible edge, so a ClipSource's quiet reads end there and the full read happens in the span holding the decision point.  `MIDI::ClipSource` sets `Steer.origin` (the timeline position of clip position 0; `:clocked` for clips on their own clock, which read the timeline position at the read) around its reads and chases, so the knob is asked for the decision point's timeline position, which lies in the span being rendered: `Knob#value_at` answers the exact rendered value on that frame.  So renders are deterministic, at any buffer size (checked bit for bit at 367/368 and 1000/13 samples), a turn issued before a cycle's decision point steers it and a later one the next cycle, and takes replay the decisions (knob turns replay on their frames; decisions made for future positions, e.g. a cycle read early by a listing, are logged, Session::Decisions).
- **Remembered**: decisions per (Session epoch, cycle) per generator (256), so caches stay consistent within a pass and a seek (a new epoch) decides again; Clip's cycle caches are keyed by epoch too (`Steer.key`, an Integer: no allocation).  A cycle first read after its decision point (a launch mid-song reading earlier cycles for note-offs, a seek) reads the values as they are then.  Knobs are frame-based: after a seek, a ramp in progress keeps going in frames, it doesn't jump to the timeline (so "cold vs in order" holds for cycles decided on their decision points: a copy launched at bar 5 decides cycles 5-7 like the one playing from bar 1, under a gesture; `steer_spec.rb`).
- **Ahead of time**: when cycle n is decided, Ahead computes n + 1 on the scheduler thread with the values the params have *then* (`Steer#peek` under `MIDI::Param.peek`: knobs answer what they know without deciding or logging, choices keep their hysteresis state); if the decision point brings the same values, playback finds the cycle cached.  Under a three-keyframe gesture, 18 of 22 cycle computations ran ahead (the rest: the clip's own events, the cycles before the first read); a hand turn costs one cycle computed where it's read (render thread): 50-150 us for the demo's parts.
- **Documents and Sessions**: `Clip#param_nodes` → `MIDI::ClipSource#param_nodes` (the union over every clip it played, so a ring-out's silent clip doesn't change the node set; a swapped-in clip with new knobs announces `Plan.changed`, found by the session fuzz) → `MIDI::Stream#sources`, so graph documents get `knob` header lines (`energy: energy` in the call) and Sessions adopt the knobs.  Steered motifs and `tr909(beats(...))` render bit-identically after a round trip.
- Costs: a decision read is ~6 us (two knobs); a steered clip's 800-frame edge read ~12 us against ~8 us unsteered (cycle computes included, no Ahead runner).
- Not built: knob steering for `generate`'s `values:`/lengths (structure, not options), per-option leads, a stateful "the tune grows" drift (motifs' mutate stays bounded: steering `mutate:` moves how far from home the motifs are, not a drift).

## Evolving rhythms (G3, `generative/beats.rb`)

- `beats(steps = 16, step: 1.n16, hold: 1, over: 8, energy: 0.5, swing: 0.5, groove: [1.0, 0.55, 0.75, 0.6], humanize: 0.08, seed:, lead:) { rows }` (from the spike's `Beats` prototype, b_rhythm.rb): rows are methods named after drums (`Sequence::Grid::GM_DRUMS` and `ROW_ALIASES`; typos raise with did-you-mean) taking a probability Array or `euclid(hits, steps, rotate:)`, with `keep:` anchors (never drift; kept through energy unless it is 0), `drift:` (smooth value noise per step over `over:` hold blocks), `mutate:` (Euclidean rows: the hit count wanders by up to mutate × steps / 2 on smooth noise, the rotation changes with probability mutate per block), `level:`, `energy: false`, `length:` (steps).  `row :bass, pattern, note: C2` or `notes: field` for other names; rows with `notes:` walk the field's scale notes (mostly steps, turning back at the edges; the first hit of a cycle on the strongest note near the middle), drawn per hold block so a held bar repeats its line.  `fill every: 8, last: 1.beat, snare: 0.7, low_tom: 0.3` adds those amounts in the last cycle of every 8 (fills play at any energy; drums named only there get rows that play only in fills).  `fill every: 8, energy: true, ...` (gen-midi-2, maintainer 2026-10-30: "Option") makes the fill follow the energy: its amounts energized like the rows' (`Beats.energize`: as written at 0.5, toward 1 above, fading to nothing at 0) and its length scaled by 2^(2e - 1) (`Beats.fill_span`: the written `last:` at 0.5, doubled at 1, halved toward 0, within the cycle), so a build's last bars fill longer and denser and raising the energy still only adds hits; the default stays as built.
- Energy (`Beats.energize`): below 0.5 `p * 2e`, above `1 - (1 - p)^(2e)`; hit draws are fixed per hold block and step (`Dice.new(seed, :hit, row, block).rands(steps)`), so raising the energy only adds hits and `hold: 2` repeats each random bar (the issue's "looping one-shot random").  Groove: an Array (cycled) or a lambda of the step's 0...1 position; swing 0.5..0.75 delays odd steps by `(swing - 0.5) * 2` steps; humanize varies velocities per cycle.
- `rhythm(source, pattern, steps:, length:, drift: 0.15, keep: [0], level: 0.9, **beats_options)` is `beats` with one melodic row.  `Clip#values` lists the rows' notes, so `tr909`/`tr808`/kit-builder kits build their voices.
- Documents: the rows block loads as a build block on `Beats::Builder` (a plain class, so the loader's implicit self and Registry checks work: `Registry::VALUES`, `BUILD_BLOCKS`), and documents may write `[1, 0, 0, 0] * 4` (`Registry::ARRAY_VALUES` `*`/`+`; `LIMITS[:steps]` bounds repeats).
- Not built from the proposal: `beats(from: kit)` (an existing grid kit set drifting), row methods from a kit's own voice names (rows are GM names today), groove curves over N bars.

## Seeds, takes, documents

- Seeds default to `MB::Sound.next_seed` (recorded as drawn seeds, `seed: drawn_seed(N)` in documents).  Takes replay generator tracks bit for bit at other buffer sizes, through scene changes, transposed generators, and seeks (`generator_spec.rb` "takes").
- Graph documents: `tones`, `weights`, `harmony` are top-level values (`Registry::TOP_EXTRA`); `Scale#weights` and the Weights/Harmony/Field methods are in `Registry::VALUES`; `strikes`/`melody`/`generate` are recorded DSL calls.  `generate` blocks print as their source and load with `trust: :code` (or a `named_proc`).  Limits: `LIMITS[:steps]` (4096) for melody counts; strikes check 4096 steps per cycle; Fields 128 notes; blur reach 1..6.
- `Clip#event_at` (chases after seeks and launches) now takes the previous cycle's last note before a cycle's first note (it took the same cycle's last note, which differs for varying clips).

- Cost per cycle is bounded by the generator's shape (slots × leap, steps × gap, rows × steps), never by search or retries; there are no memo chains in G1, so a cold jump costs one cycle.  The worst single cycles (up to ~10 ms) are GC pauses and first calls; the worst steady cost is a harmony's first visit to a blend position (blend + operators + a Field, ~35-40 us), cached after that, so a looping harmony pays it once per loop position (harmonies combined with operators cache too when they all loop with the same length, `Harmony#period`).
- A dice draw is ~0.3-0.5 us from Ruby (the C hash is a few ns; the rest is the method call), against ~150 us per note with the spike's Ruby-only dice.
- Live, cycles are computed a cycle ahead on the scheduler thread, so the render thread reads cached cycles; the first cycle after a launch or a cold seek is computed where it's read (one cycle's cost, above).
- Renders: the 32-bar demo (92 s) renders in ~33 s wall (2.8x realtime, instruments and rooms included).

## Long form (G4, `generative/markov.rb`, `generative/lsystem.rb`, `form/walking.rb`, `form/plan.rb`; maintainer 2026-10-29: "Generative G4 long form")

Forms that write themselves, on the same rule as the clips: every choice a counter-based draw, so a piece is a pure function of its seeds (plus, when steered, the knob values read at its decision points), seeks cold, and replays from takes.

- **Per-occurrence section lengths** (the proposal's question 4): `chorus 16` ... `chorus 8` in any flow (arrangement.md, "Song forms").
- **`markov(still: { drift: 3, hush: 1 }, drift: { bloom: 3, still: 1 }, ..., start:, seed:)`** (`Generative::Markov`): states are section names, each with the states that may follow and weights; draw n is `Dice.new(seed, :markov).pick(weights, n)` from the state before it, so state n needs the walk before it, memoized (~4 us a state cold: 10,000 states 44 ms, 100,000 0.37 s, on the i9 while renders ran; cached reads ~5 us).  Pair keys `[before, state] => { ... }` (order 2) win over the state's own rule.  An empty rule (`outro: {}`) ends the chain; the next draw starts over at `start` (a flow that comes back to the chain plays a new song; ends take a draw).  Weights may be moving params (`knob(:motion)`, `cc(1)`, arithmetic), read at the flow's commit point (G3's decision points for sections: the section's fill start, else its end); a rule whose weights are all turned to zero ends the chain.  `take(n)`, `draws(n)` (`[state, draw number]`), `[](n)`, `terminal?`, `states`, `reseed(seed)`, `flow(bars, sections: nil, loop: false)` (sections: n writes the first n out as a linear Form; else one generate step deciding as it plays; `loop: true` wraps it in `label :top ... goto :top` so an ending chain starts over forever).  Prints back as `markov(...)` (moving weights through `MIDI::Param.label`: `knob(:motion)`); rules named like the options (`:start`, `:seed`) go in a leading Hash.  Checks: every reachable state has a rule (did-you-mean), weights >= 0 or params, not all zero (`{}` for an end).
- **`lsystem(%i[intro body outro], body: { %i[build drop body] => 2, %i[build drop] => 1 }, generations: 3, seed:, vary: false)`** (`Generative::LSystem`): the axiom rewritten `generations` times, every symbol at once; a rule is a word, a Symbol, or words with weights drawn with `Dice.new(seed, :lsystem, visit, generation).rand(position)`; words cached, at most 4096 symbols (`LIMIT`; 10 generations of a doubling system: 279 symbols in 0.6 ms).  Symbols with a rule are nonterminals: flows leave them out unless they have a length (so `body` vanishes and the song ends after its generations).  `vary: true` grows a new word for each visit of a generate step (visit k draws with its own keys), so `label :top; generate song; goto :top` never repeats; without it every visit plays the same word.  `word(generations, visit:)`, `symbols`, `nonterminal?`, `reseed`, `flow(bars)` (the word written out).  Prints back as `lsystem(...)`.
- **`generate source, still: 6, drift: 4..8, bloom: [8, 12], sections: n`** (a flow step, `Form::Generate`, instruction `[:generate, step]`): each pass plays one section drawn from the source, decided at the commit point before it (`Form::Walking#generate_step`; counters `[:gen, i] => [draws, tail]` and `[:visit, i]` ride in the walk's counters, so a re-decided commit draws the same), until the source ends (a chain's end, a word's last symbol) or `sections:` per visit, then the flow carries on; every visit continues the source where the last left it.  Lengths per occurrence: bars, Durations, Ranges of whole bars (`Dice#int`) or Arrays (`Dice#pick`) drawn with `Dice.new(source.seed, :length)` and the draw number, so occurrence n always gets the same length (`Markov#flow(sections:)` and `LSystem#flow` write out the same lengths a generate step draws).  The step declares the sections it gives lengths to (a length with options declares them with those: `breakdown: { length: [8, 16], fill: [:riser, 4] }`, printed back that way); sections it may play must be sections of the form (else an error naming them).  `goto :hush` during a generated flow plays hush next as if the source had drawn it (a chain carries on from there); `finish` in a flow with no plays ends it; `seek :hush` seeks to where an uninterrupted run next plays it.  `markov`, `lsystem`, and `knob` are callable inside flow blocks (the BasicObject builder forwards them), so a printed flow builds again; set documents load them (`Registry::TOP_EXTRA`).
- **`Form::Plan`** (`form.plan(seed:)`): the passes of an uninterrupted run worked out without a Session (the walk is `Form::Walking`, shared with Playback, so both decide the same: picks, weighted gotos, goto Procs, generate steps; steered sources read their params at the simulated commit points as peeks): `plan[k]`, `plan.at(pos)`, `plan.find(name, from:)`, Enumerable (lazy for endless forms).  ~25-30 us a pass (the ambient endless form: bar 900, an hour in, 6 ms; bar 9000, 10 hours, 21 ms; bar 90,000, 0.27 s).
- **Cold seeks**: a seek to a bar or another position while a form plays now plays the form on from the pass an uninterrupted run plays there (`Playback#seek_position`, arrangement.md "Seeks"; the pass's scene launches at the seek, its boundary where the run's is), decisions counting passes as that run did (`@decision_offset`), so what follows draws what it draws; the plan is kept per playback (`Playback#plan`, remade when the meter map changes) and worked out to the target when the seek is issued (`prepare_seek`, on the console's thread), so the landing on the render thread only adopts the pass.  `render(from: 901, preroll: false)` / a script's `--from 901 --seek` starts an endless piece an hour in, cold; the clips are timeline-pure, so the music there is what the run plays (spec: frame for frame against an uninterrupted render from the seek's bar).  Performer controls (loop!, goto, skip) aren't replayed by the plan; goto Procs see the history as played.
- **Takes**: generated flows replay bit for bit, with gotos and bar seeks (`long_form_spec.rb`).  Found on the way: a seek landing right away (inside the console line that issued it) restarts the form inside the line, and the take counted the form's scene launches as the line's own landings, so replays ran the line early (at the landing in the next epoch); seek actions now run outside the take line (and outside a replayed line's forced landings, `Seeks#without_command_or_line`).
- Genre templates' generators and `genre(:ambient).endless` (genres.md, "Generated forms"); `bin/songs/endless.rb`.
- Not built: Markov chains learned from a corpus (a reference form, a take's form; the Illiac/EMI note), steering lsystem weights (words grow at a visit's start, not at commit points), a plan that replays performer controls, `t.long`.
