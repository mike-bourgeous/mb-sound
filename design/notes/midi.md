# MIDI

<!-- summary -->
`lib/mb/sound/midi/` is pull-based (no callbacks; only live input reads a clock): Sources (`FileSource`, `ClipSource`, `LiveSource`) make `MIDI::Event`s, `MIDI::Stream`s share them among readers and make transform views (`echo`, `arp`, `chord`, `humanize`, `quantize`, `lock`, ...), `MB::Sound::Notes` (`v` in synth code) turns them into signal nodes, and `Synth` allocates voices through `MIDI::Allocator` lanes.
Moving parameters (`MIDI::Param`: `cc(...)`, knobs, tempo LFOs, clips) are read once per decision; the session key and `MIDI::Lock` styles map keys into scales; `midi_clip`/`midi_kit` import MIDI files as clips in exact whole notes.
Live MIDI uses JACK ports when a server answers, else bundled RtMidi; specs use synthetic MIDI files only (the maintainer's `tmp/music/` is private).

## Quick reference

- Notes (`v`): `gate`, `trigger`, `number`, `velocity`, `freq`, channel-wide controllers (`bend`, `pressure`, `cc(n)`, GM-named `mod`, ...; smoothed by default), envelopes with GM2 scaling, `v.hz` (`.glide`, `.vibrato`, `.bend_range`), `v.key_trigger`, `v.cutoff`, `v.reso`, `v.lfo`, `v.mod_sum`/`mod_scale`, `poly_pressure`, `aftertouch`.
- `Synth.new(source, voices:, spares:, retrigger:, skip_idle:, exact_lanes:) { |v, i| }` (more options below; `retrigger:` presets `:string` and `:ring`); `same_key: :restrike` for real-time input, `:count` for files and clips.
- Moving parameters: `cc(1, 0.5..0.7)`, knobs, `knob(:x).choose(...)`, tempo LFOs (`4.bars.lfo.at(0.5..0.66)`), clips (`transpose(seq(0, 5).n1.loop)`), arithmetic; examples in `bin/midi/moving_params.rb`.
- Session key and locks: `key :d, :dorian`, `mode :lydian`; streams `degrees(layout: :flow | :fit, black: :passing | :silent | :lower)`, `snap(:chord, from:, extend:, avoid:, bass:)`, `stream.lock(:play)`; styles `lock :mash | :play | :along | :chord | :off` (console `lock :play` locks the Session input); demo `bin/midi/key_lock.rb`; help topics `:key`, `:lock`, `:params`.
- Console: `midi` (a Notes on live input through the Session's `MidiInput`), `midi_file(path)`; MIDI files as clips: `midi_tracks(path)`, `midi_clip(path, track:, channel:, bars:, from:, loop: true, slides:, cc: :steps | :fit | false, timing: :score | :performed, sustain:)`, `midi_kit(path)` (help `:midi_files`); documents save them as `events(...)` / `grid(row: events(...))` rows, not the file.


`lib/mb/sound/midi/` is a pull-based event layer, loaded from `midi/streams.rb` after Sequence: Sources make Events, Streams share them among readers, Notes turns them into signal nodes, and Synth allocates voices.  Nothing is pushed through callbacks, and nothing reads a clock except live input.

- `MIDI::Event` (`midi/event.rb`): the only MIDI message type (`Note#to_midi`/`Pitch#to_midi`/`Tone#to_midi` return note-on Events whose `bytes` `MIDI::Output#<<` sends), a Data value (normalized velocity/CC/pressure 0..1, bend -1..1, raw kept, 0-based channel, time in Rational seconds since the stream start; allocator types `:choke`/`:glide` and `legato`).
- Sources (`midi/source.rb`: `read(from, to)`, `seek`, `restart`, `ended?`, `music_end`, `chase`; note-ons/offs kept balanced across jumps): `FileSource` (one tempo via a tempo-map object, `loop:`; `#notes`/`#note_stats` list notes with key and pedal release times as played, via `MIDI::NoteList` in `midi/note_list.rb`, used by `bin/midi/midi_roll.rb`), `ClipSource` (see Sequences), `LiveSource` (below).  `MIDIFile` (`midi/midi_file.rb`) only parses and analyzes files (`events`, `tracks`; no clock).
- Chases (`Source::Chase`, 2026-10-11): `starts` marks a chased note that starts exactly at the jump (its note-on follows); clip sources also give `previous` (the note before, around the loop) and `elapsed` (seconds since the chased note started), which `Glide`s made with `resume: true` (tweens) use to resume the glide in progress (omnibus4); Notes nodes apply chases through `chase_item`, which calls `#chase_start` for those (the same as `#chase` except `Glide`, which keeps a pending `from:` so tweens launched in a Session glide from their first keyframe; see `curves.md`).
- `MIDI::Stream` (`midi/stream.rb`) reads a source once for many `reader`s (cursors in seconds, so any sample rate; late readers start at the slowest), stamps bend ranges from RPN 0, and makes transform views (`midi/transform.rb`: `channel` 0-based, `transpose`, `sustain` (the only sustain handling), `velocity_curve`, `bend_range`).  Streams include `Nameable`/`Traversable` but aren't GraphNodes.  `Stream.for` takes a Stream, Source, Input, Clip, MIDIFile, filename, or anything with `#to_midi_stream` (a Notes).
- Per-buffer read costs (int-frames-1, 2026-10-23; the zoom-out's "integer frame counters on hot paths, Rationals for musical positions"): times stay exact Rational seconds (the API of every reader and event), but quiet reads do no Rational arithmetic.  `ClipSource` reads that no edge can reach compare integer frames: after each full read `#arm_quiet` stores the last frame a read may end on before the next possible edge (`floor(t * r)`, the frame the edge lands on, the rule Notes' offsets use) or the next loop cycle (`ceil(c * r) - 1`, so cycles are still made on the read that made them before: variations, generators, params), from `Clip#edge_horizon`, at a rate r on whose grid the read's end lies (48000 lcm its denominator); a read ending at or before it returns `NO_EVENTS` after `numerator * (r / den) <= q`, and the clip position catches up exactly when next needed (`#clip_position`, the next full read).  Any new tempo (the transport's cached wnps object), clip, jump, pending swap, flams, or clock takes the full read; `set_clip_position` disarms wherever the position is set (keep that when adding ClipSource state).  `MIDI::ClipSource.quiet_reads = false` is the full read, for `clip_source_quiet_spec.rb`, which compares both over random spans, rates, off-grid ends, tempo changes, hours-long positions, seeks, swaps, feel transforms, and reads ending one frame around every edge and cycle start.  Streams compare times by identity first (`Stream#advance` hands out each buffer's end once and readers pass it back: `read_for`'s checks, `fill`, `Allocator#advance`, `Source#read` with one `<=>`), and skip searches of empty logs and lane queues.  Night Bus audit (YJIT, 128 frames): ClipSource self time 78 -> 34 us per buffer (99.3% of reads quiet), the audit total 571 -> 520 objects per buffer.  Left: `Stream#advance` still makes one Rational per stream per buffer (27 per buffer in the audit; integer reader cursors would change the reader API).
- `MIDI::LiveSource` (`midi/live_source.rb`; `Stream.live(connect:, output:, timing:)`) reads `MIDI::Input#read_raw` (JACK frame times or RtMidi deltas).  `MIDI_TIMING=exact` (default) keeps timestamp spacing at a constant latency L (default: the output's queue limit + period + one buffer, ~63 ms with `:default`, ~18 ms with `:low`; `latency:` overrides); JACK input with a JACK `output:` is sample-exact through `DeviceOutput#jack_clock`, else the input clock is anchored at the first events and re-anchored when off by more than L (`#track_drift` is the hook for a DLL); `asap` puts events at the start of the read.  `MIDI::RealtimeReader` (`midi/realtime_reader.rb`) plays a file or live input against the wall clock for the bin/midi tools (no audio).
- `MB::Sound::Notes` (`lib/mb/sound/notes.rb`, `notes/`): the per-voice (or mono) signal DSL over a stream (`v` in synth code; `Notes.new(stream | source | clip | file, sustain: true)`).  Note nodes read `note_stream`, the input through the sustain pedal transform (lazy and held weakly, so a Notes used only for controllers or as a synth source never holds the input back), unless `sustain: false` (Synth lanes, already pedaled, and `Clip#notes`); `stream` stays the input (controllers, `to_midi_stream`, `.source`); `control_specs` adds the pedals while note nodes use them.  Every node has its own reader and puts events on exact samples at its own rate: `gate`, `trigger` (impulse = velocity), `number`, `velocity`, `lift`, `choke` (`:choke` events, CC 120), `freq` (Tuning + bend); last-note priority; held values chase `Source#chase` after jumps.  Channel-wide nodes (`bend`, `bend_semitones(range)`, `pressure`, `cc(n, range:)`, GM-named `mod`, `brightness`, `resonance`, `attack_time`, `vibrato_rate`, ... with `MIDI::ControlSpec`s, listed by `notes.controls`) are shared per control stream (`Notes.control_stream`).  `env`/`amp_env`/`fm_env`/`filt_env` are `NoteEnvelope`s wired to gate/trigger/velocity/choke (`lift: true` opt-in), GM2 time scaling (CC 73/75/72) unless `.gm(false)`, registered for `notes.idle?`/`notes.level`.  `v.hz` is a `NotePitch` whose tones key-sync (`Notes::KeyedTone`, `reset(v.key_trigger)`) unless `.free`/`.lfo`/`.sync`; `.bend_range(12.st)`, `.transpose`, `.vibrato`, `.glide(50.ms | :gm, legato:)`.  `v.key_trigger` (`Notes::KeyTrigger`, alias `key_sync_trigger`) is `v.trigger` without note-ons that add energy to a sounding voice (user rule, 2026-10-05: adding energy to an existing envelope doesn't reset oscillators), i.e. note-ons while a `retrigger: :add` envelope of the Notes is sounding, decided per buffer from the envelopes' state at the buffer start (`Notes#adding_at?`, `NoteEnvelope#sounding_at?`, so graph order doesn't matter); `v.trigger` fires at every note-on.  `v.cutoff(base, env:, keytrack: 0.5)` and `v.quality(q)` feed `filter(...)`; `v.reso(amount)` (CC 71 around the base) feeds `lp4(resonance:)`.  `v.poly_pressure` (alias `key_pressure`; per-key 0xA0 pressure of the newest held note, 0 at each note-on, held after release; the Allocator routes each key's pressure to its lane), `v.aftertouch` = max(poly, channel pressure) (it was an alias of `pressure`; `channel_pressure` is the new alias); ControlSpec type `:poly_pressure`, listed but left out of ACID XML.  Controller smoothing (2026-10-08; `Notes::Smoother`, kernel `FastControl.smooth`, mirror `Smoother.smooth_ruby`): CCs, GM-named controls, channel/poly pressure, aftertouch, and bend (so `v.hz`/`v.freq`) glide between MIDI steps through a triangle FIR (two moving averages; each step an S-shaped transition that lands exactly after the time, delay half of it): `Notes::CONTROL_SMOOTHING` 10 ms, `BEND_SMOOTHING` 5 ms (`Notes.control_smoothing`/`.bend_smoothing` apply live: nodes made with the default keep a smoother, a pass-through one while the default is false, and `Smoother#length=` re-plans it from the current output on its next buffer, also in plans (the plan op reads the smoother's arrays each block); nodes given `smooth:` keep theirs; spec_helper restores them); adaptive smoothing `smooth: :adaptive` (`Notes::ADAPTIVE_SMOOTHING` 5..200 ms) or a Range of times (also as the global defaults): each step glides linearly from the current output over the time since the previous step, clamped (the user's scroll-bar idea; a slow 7-bit wheel becomes a line, lag one step interval; kernel `FastControl.adaptive`/`mb_adaptive_run`, mirror `Smoother.adaptive_ruby`, plan `Op::Smooth` picks the kernel by the state's length, 8 = adaptive); per node `smooth:` (`v.cc(1, smooth: 20.ms)`, `v.mod(smooth: false)`, `v.bend(smooth: 0)`, `p.midi_cc(..., smooth:)`); switch CCs (curve `:switch`) step unless given a time; gate/trigger/number/velocity/lift/choke never smooth; poly pressure jumps at note-ons and content jumps.  Measured on 7-bit pressure steps every 4 ms: energy above 200 Hz / 2 kHz -54 / -65 dB stepped, -86 / -136 at 10 ms (one-pole and linear ramps measured worse above 2 kHz); ~1 us per moving 128-sample buffer, settled buffers pass the frozen constant through (`spec/lib/mb/sound/notes_smoothing_spec.rb`).  Specs that check values on event samples set the defaults to false.  `v.lfo(rate, shape: :tri/:saw/:square/:sine/:noise, depth:, delay:, from:, sync: :key/:free/:random, wheel:, pressure:, unipolar:, human:, seed:, skew:, phase:)` (a Multiplier of a `Tone#lfo`, depth, and FadeIn; `skew:` makes the triangle rise for that fraction of each cycle (0.5 plain, toward 1 a ramp; built from the phasor with one exact `aclip`, because `Tone#pwm` on a triangle warps its lobes, not its slopes; omnibus5, 2026-10-11, for the vocal lead song's wobble), `phase:` the starting phase (key resets go there; `1 - skew / 2` starts a skewed LFO from its low point); Duration rates follow the tempo; `:noise` is `GraphNode#sample_hold` (alias `sah`) on a naive square; `vibrato` is built on it).  Mod sums (`ModMethods`, also `MB::Sound.mod_sum`): `v.mod_sum(base, src => amount)` (Intervals in semitones) and `v.mod_scale(base, src => amount)` (base × 2 ** octaves); Symbol sources in voices: `:velocity`, `:vel_x`, `:key` (octaves from C4), `:wheel`, `:pedal`, `:breath`, `:bend`, `:pressure`, `:poly_pressure`, `:aftertouch`, `:lift`, `:gate`.  Demo: `bin/synths/sq80_voice.rb` (~50% of realtime at 128-sample buffers and ~16% at 512 for 8 voices without its chop/flutter oddities, ~80%/26% with them, normalized to the fm_bass reference below, 2026-10-07).  Gate/trigger/choke and envelopes return nil once the stream ended and the envelopes are idle; nodes report `ended?` for script ringdowns.  Nodes are cached per instance through WeakRefs.  Fast paths (the `notes_fast` path of MB::Sound::Kernels: `Kernels.notes_fast?`, off with `MB_SOUND_KERNELS=notes_fast=ruby`, kernels.md; null-tested in `spec/lib/mb/sound/notes_fast_paths_spec.rb`): constant frozen buffers while nothing changes (consumers cache by identity), one `Notes::EnvelopeInputs` reader per envelope, idle envelope kernel skips, shared Stream events and Frequency nodes.
- Ending on a grid (fixes-12, 2026-10-14): a Notes' gate, trigger, and choke nodes end the graph once the stream is over and the Notes is idle (`Notes::Node#finished?`).  That check ran at buffer starts, so a graph ended up to a buffer after the stream's last event, and a filter ringing on a gate or trigger was cut at a buffer-size-dependent sample (measured on master-ai 94c421d7, clip ending at 24000: ends at 24800 at 800-sample buffers, 24255 at 367/368, 24744 at 1031, 24001 at 1; `gate.filter(:lowpass, cutoff: 50)` lost its whole decay at full level).  For Notes without envelopes or a quiet check (`Notes#grid_end?`) these nodes now end on their `END_GRID` (800 samples of their own output) at or after the sample after the stream's last event (a gate with a note still held waits `TAIL_SECONDS` more), returning a short last buffer, so they end on the same sample at any buffer size, where 800-sample buffers ended them before (renders at 800 unchanged); a seek or restart before then (a new reader generation) cancels the end.  `Resonator` now treats a short input buffer as the input's last and rings out after it in the same buffer (like nil).  Envelopes and Synths (fixes-13, 2026-10-14): Notes with envelopes ended at the first buffer start where every envelope was idle, and Synths at the first buffer start after their lanes ended, so a resonant filter after them was cut 0..799 samples off (measured on master-ai b6b06139 against 800-sample buffers: `(saw * amp_env).filter(:lowpass, quality: 8)` -77 to -99 dB, a Synth into it -52 to -98 dB, ending up to 800 samples earlier or 1031 later).   - Envelopes end on the `END_GRID` of their own output (counted from their first sample, like the note nodes').  `NoteEnvelope#sample` renders a buffer crossing a grid point after the stream's last event in pieces split there and records its idle state on the point (`Notes#grid_idle`); the graph ends at the first point where every envelope of the Notes that has rendered is idle and the Notes is quiet: the last envelope to reach it in a buffer decides and returns a short buffer (arithmetic cuts the others' full buffers at it), the others return nil from their next buffer, and the Notes' gate/trigger/choke nodes end there too (`Notes#grid_end_frame`; a seek or restart cancels it).  800-sample buffers from the first sample ended there before, so those renders don't change, except where the old check at a buffer start saw another envelope's state from after that start (an envelope rendered earlier in the same buffer): `(saw * amp_env).filter(cutoff: 200 + 2000 * filter_env)` ended at 38400 at 800 because the amp envelope, sampled first, was already idle at the buffer's end; it now ends at 39200, the first point where both were idle (the filter rings 800 samples longer). - `MIDI::Allocator` (`midi/allocator.rb`) splits a stream's notes into `lanes` (`Lane < Stream`, `voices + spares`; one in mono mode), each with at most one note plus every channel-wide event, reading its input once so lanes read in any order with identical results.  When full, the `steal:` chain (`:same_note`, `:oldest_released`, `:oldest`, optional `:quietest`; `protect: :lowest/:highest`) chokes a victim while the new note goes to a spare.  `lane.idle_check` frees released lanes.  `retrigger:` (when every voice is busy and the chain has `:same_note`): `:reuse` (default: restart the newest lane playing the note), `:louder` (reuse it only if no envelope would attack downward, via `Lane#louder_check`/`level_check`; else as `:new_voice`), `:new_voice` (a spare takes it, so the old note rings on), `:quietest` (the quietest lane playing the note), `:per_key` (one lane per key, always restarted, even with voices free).  Mono (`voices: 1`, `priority: :last/:low/:high`) sends legato note-ons; polyphonic `glide_mode: :last` (default) sends `:glide` events, `:voice` none.  Allocator unison (several lanes per note) isn't built; oscillator unison is `pitch.unison` (oscillators.md).
- `MB::Sound::Synth` (`lib/mb/sound/synth.rb`; `MB::Sound.synth(source = nil, voices: 8, **opts) { |v, i| }`, nil meaning live `midi`; `notes.synth`, `clip.synth`): `Synth.new(source, voices: 8, spares: 2, steal:, protect:, mono:, priority:, glide_mode:, retrigger:, controls: [], bend_range: nil, sustain: true, seed: nil, tail: 11, skip_idle: true) { |v, i| graph }` reads the source through `.sustain`, splits it with an Allocator, calls the block per lane with a Notes on it, and sums the lanes (`sample_individual(count)`; bundles give one `Synth::Output` per channel).  Lane blocks run in `MB::Sound.with_seed(seed + i)` and `Synth.with_lane(i, lanes)`: inside them `per_voice(list | range)` (2026-10-10, `MidiMethods#per_voice`, the voice-level sibling of `per_channel`; `channels`/`per_channel` keep their multichannel meaning there) returns the lane's value right away: a list cycles over the lanes (voices plus spares), a Range spreads evenly over them (`ChannelSpread#value`), outside a lane block it raises (`Synth.current_lane` is nil); the graph-io writer prints lanes that differ only in values with it.  `controls: [:volume, :expression, :pan]` (CC 7/11/10) are opt-in.  `retrigger:` takes the Allocator modes plus `:add` (reuse, every lane envelope `retrigger: :add`) and the presets (`Synth::RETRIGGER_PRESETS`): `:string` (`:per_key` lanes + `:add` envelopes, never doubling a key; user-approved for pianos/e-pianos; key-synced oscillators keep their phase on these re-strikes, `.free` ones never reset; see `bin/synths/fm_epiano.rb`) and `:ring` (alias `:bell`; user's choice for bells, fm_bell's default with `-r` to compare): a free voice if any, else the quietest lane ringing the note with `:add` envelopes, else steal the quietest (`RING_STEAL` unless `steal:` given).  Renders: /app/tmp/listening/retrigger/.  `ended?` = finite source over and every lane idle: Notes idle and the lane's output under -90 dB (`Synth::QUIET`, `Notes#quiet_check`, `Synth#quiet_lanes`), measured after each buffer by default; with `exact_lanes: true` (`Synth.new(..., exact_lanes: true)`, `Synth#exact_lanes=` before the first sample, `Session#exact_lanes = true` for the Synths of players it starts, `render(exact_lanes: true)`, and always in take replays) measured over whole cells of the `SKIP_GRID` (800 samples) and recorded at the grid points, where every buffer crossing one is split (`Synth#sample_lanes`, `#record_cells`), and the allocator frees a released lane by that record, counting only notes sent to it before the record (`Lane#idle_position`), so allocation is the same at any buffer size (fixes-7, 2026-10-13: measured after each buffer, a released lane was free at 367/368 and not at 800 when a note came, which then played on another lane with another free-running phase, +1.2 dB in a persona take).  Maintainer decision (fixes-7 round 2): exactness only when asked for, so the default costs nothing extra at any buffer size and renders as before; exact lanes cost a pass over the lanes per grid crossing: standalone (graph_profile, dense_modulated.mid, against master-ai d86d4454) fm_epiano 11.5 -> 12.6% of realtime at 128, 6.0 -> 7.8% at 367/368, 4.2% at 800 either way; pluck 49 -> 55%, 24 -> 34.6%, 16.6 -> 17% (default: the same as master-ai at every size).  In a Session the measuring grid is aligned with the Session's frames when the player starts (`Synth#align_grid`), so 800-sample Session buffers never split even for synths launched off the 800-frame grid (idle skipping keeps its grid of the synth's own time: moving it moves where free-running oscillators pause, night_bus_flow's mono hooks by up to +6 dB).  With exact lanes, a lane's Notes count it quiet only if the part of the current cell it has played is quiet too (`Synth#cell_quiet?`), and ends come at the grid point after the last loud cell, so envelope-less voices (filter pings) and resonant tails ring out and aren't reused while ringing (the peak is also `Notes#level` for `steal: :quietest`); the runner's ringdown keeps a Synth and ignores the nodes inside it; then `tail:` seconds of silence and nil.  `skip_idle: true` skips idle lanes (Notes idle, output under -120 dB, no delays/reverbs/FIR/feedback loops/tempo nodes inside the lane, and some node plans can't fuse (`Synth#lane_fusable?`, from the node types and settings alone, `Plan.fusable_type?`, planned or not: lanes plans could fuse whole run in lane groups, computed every buffer, see Plan layer, and skipping them only when unplanned or ungrouped made the plans change the samples, omnibus12: a key-synced `v.hz.saw * v.gate` reset from a running phase planned and a paused one unplanned, -3 dB for ~27 samples at note-ons); MIDI transforms and clip sources upstream only make events, which wake lanes, so clip synths skip too since 2026-10-10; not sample-exact, since free-running oscillators and noise pause while skipped, but the same at any buffer size since 2026-10-13: lanes fall asleep only on a grid of `Synth::SKIP_GRID` = 800 samples of the synth's own time (an idle lane whose last grid cell was silent; buffers are split there when needed, unless a held note with no event in the buffer keeps the lane awake) and wake on the exact sample of their next event (`Lane#first_pending_time`, events from the readers' cursor only; a mid-block wake reads shared plan inputs through `Plan::SharedInputs#window`); 800-sample runs sleep where they did before, but wakes moved from the buffer start to the event sample, so lanes that wake mid-buffer render noise and free-running phases differently from before).  Cost (2026-10-04, YJIT, 8 voices, saw × amp_env → lowpass): ~6% of realtime at 128-sample buffers, ~2.3% at 512.
- Sub-lanes (synth-sublanes-1, 2026-10-16; `GraphNode::SubLane`, `lib/mb/sound/graph_node/sub_lane.rb`): skippable parts of a lane's graph (one or more channels) that sleep while they have nothing to play, so a lane only computes the parts that sound; `Sampler::Instrument#play` makes one per narrow layer of a layered instrument in synth voices (SoundFont zones that overlap; layers covering at most half the keyboard, `Instrument::SUB_LANE_COVERAGE`; see `sampler.md`).  A sub-lane falls asleep at a `SKIP_GRID` point of the synth's own time after a cell of exactly zero output (not just under -120 dB, so filter states have flushed) with its envelopes and sampler voices idle, and wakes on the exact sample of the next lane event its `wake:` Proc accepts (`Lane#first_pending_time(from, to) { |e| ... }`; the instrument's: note-ons with a region for the key and velocity) or at a content jump.  While asleep it outputs frozen zeros and pauses the nodes only it reads (found from the lane graph: every reader exclusive, Tees by all branches), keeping in step its branches of Tees read elsewhere in the lane (read and dropped; shared controllers are left to `Plan::SharedInputs`), its Notes nodes and knob readers (advanced), and its own reader of the lane (its clock); idle Notes envelopes catch up on their stream time at the wake (`NoteEnvelope#advance`).  The Synth tells sub-lanes which lane piece is being read (`Synth#lane_piece`: lane, synth sample, count, serial; set in `#sample_lane`/`#sample_skippable_lane`), windows shared inputs for mid-piece wakes (`#sub_lane_window`), and advances their clocks while the whole lane sleeps (`SubLane#lane_skipped`).  Output is the same at any buffer size and, for instrument layers (envelopes, sampler voices, filters, zone values), bit-identical to rendering them every buffer (GeneralUser GS piano, Tine EP, Full Orchestra, Standard kit at 800, 128, 367/368, 1/7/333/801/64; `spec/lib/mb/sound/sub_lane_spec.rb`, also under plan check mode); free-running oscillators of a sub-lane's own would pause, as in skipped lanes.  A sub-lane stays awake with a `#reason` if a node inside reads a lane node without a Tee, has long memory, or shares a `ZoneValue::Index` with nodes outside (the Synth gives them their own while building each lane: `SubLane.prepare`, `ZoneValue.separate`).  Synths with sub-lanes form no plan lane groups; outputs of sub-lanes that can't sleep are plan pass-throughs.  `Synth#sub_lanes` lists them per lane (`skipped_samples`, `wakes`, `asleep?`); `Synth.sub_lanes = false` / `MB_SOUND_SUB_LANES=0` turn them off, `skip_idle: false` too.
- Same-key notes (omnibus8 `fixes-prepanel-1`, maintainer 2026-10-17): jack-keyboard drops note-offs when its window loses focus with a key or the pedal down, and "pressing the same note again stops the note in most synths", but the Allocator counted overlapping notes on one key (on 60, on 60, off 60 left a voice on at any voice count and retrigger mode).  `same_key: :count | :restrike` on `MIDI::Allocator`, `Synth` (and `Notes`, for readers without an Allocator); nil (the default) picks `:restrike` when the source is real-time input (`MIDI::Source#realtime_input?`: `LiveSource` (hardware and the UI keyboard's `VirtualInput`), `Session::MidiInput` taps (console `midi`, `LiveClip` monitors, and take replays, which read the same taps, so replays allocate the same way), transforms and merges of them; Allocator lanes answer false), else `:count` (files, clips, transforms of them; unchanged).  Allocator `:restrike`: a note-on for a key whose lane is *sounding* (held) on that channel restarts that same lane (note-offs for the notes it held, then the note-on, at the note-on's time, so lanes stay balanced), before `retrigger:` and the steal chain and after choke groups; the key's older note-ons are forgotten, also stolen/choked ones when the key starts on a new lane, so the next note-off releases it.  Released (ringing) keys get a lane as usual.  Pedal: `Stream#sustain` already sends a pedal-held key's note-off just before its re-press, so it takes a new lane (piano-like; the old one rings in its release); a dropped note-off under the pedal ends at pedal up after one re-press.  Mono: the key leaves the note stack (older entries dropped) and is pushed again; if it was sounding it restarts with a plain note-off/note-on (not legato: no glide, envelopes retrigger); a re-press under another held note stays legato as usual.  Poly pressure follows the restruck lane's one slot.  `Notes` (no Allocator) reads `Stream#restrike` (`Transform::Restrike`: off before a re-pressed held key's on, the older note-off dropped, CC 123+ forgets the channel) before the pedals; `Notes#synth` passes its mode on.  A merge of live and clip streams restrikes clip notes a live key repeats (documented edge).  MIDI going out: `MIDI::Output` (`same_key: :restrike` default, `:raw`) writes through `Output::NoteBalancer` (raw bytes: a note-on for a held key sends a note-off first, the extra note-off is dropped, CC 123+ forgets the channel), so receivers aren't left guessing.  MIDI file export (export-1, on hold) must do the same: end the earlier note before the next note-on of a key in each track/channel.  Specs: `allocator_spec.rb` ('same_key', a randomized invariant with dropped note-offs), `same_key_spec.rb` (Notes, Synth at 480/7/128/800, Stream#restrike, NoteBalancer).

## Parameters that move (`value_at`; midi-consol-2, 2026-10-17, built from the midi-consol-1 proposal)

Transforms work in event time, so a moving parameter answers "what is your value at this moment?" at each decision point rather than being sampled per buffer.  One protocol (`MIDI::Param`, `lib/mb/sound/midi/param.rb`), shared with generators and the planned G3 knob steering:

- `value_at(pos, frame: nil, transport: nil, stream: nil)` (knobs-1: the one signature of every value that moves, knobs and clips too; params.md "Values that move"): the value at timeline position `pos` (Rational whole notes); `frame:` the Session frame when the reader knows it (clocks and tempos), `stream:` the transform's `Param::Reading` (controllers seen on its input).  Plain values answer themselves through `ValueSource.value_at` (no allocation); `Param.wrap(x, what)` checks and wraps clips (`ClipValue`, `Clip#value_at`: the value sounding there) and graph trees (`Param::Graph`: knobs, readers, constants, tempo LFOs, sums and products of them; anything else raises `NotAParam` with the follow-a-knob hint).  `Param.param?` decides; plain arguments take the old code paths, so renders without params are bit-identical (checked by md5 over bin/songs and bin/synths).
- Kinds: `cc(n, range, curve:, default:, channel:)` (`Param::CC`, a ControlSpec: the last value of controller n on the transform's own input stream, else the Session's default MIDI input at or before the position (`MidiInput#cc_at`, history plus values trimmed from it), else the default; maintainer decision 2026-10-17, examples in `bin/midi/moving_params.rb` to judge it; Bench verdicts 2026-10-18: controllers rest at 64 there, and the script plays `knob_arp` by default); knobs (`knob(:x)`, `Knob#value_at`, below); tempo LFOs (`2.bars.lfo.triangle.at(0.5..0.7)`: `Tone.shape_ruby` at pos / cycle + phase through the #at range; FM/PM/other shapes refused); clips; `knob(:x).choose(a, b, ...)` (`Param::Choice`: equal zones of the knob's own scale, a quarter-zone hysteresis so a knob on a border doesn't flutter; any param can drive one; a `cc` drives it by its controller position along its curve, `ControlSpec#position`, the inverse of `#value` with centers too, so `cc(1, 100..8000, curve: :exp).choose(...)` and a knob learned on CC 1 pick alike (omnibus18; before, cc positions were linear in the value)); `modes(...)` (a Choice of mode names).
- Arithmetic: params combine with numbers and each other (`0.5 + cc(1) * 0.2`, `Param::Expr`; graph nodes times params too, `knob(:a) * cc(1)`) and print back through `Generative::Value`'s recipe printer (`to_ruby`, recipes, graph documents; `GraphIO::Registry` lets documents call `cc`, `modes`, `Knob#choose`, and param arithmetic).  Transforms list the graph nodes their params read as sources (`Transform#param_nodes`), so documents get knob headers and Sessions adopt the knobs.  Streams list the controllers their params read (`Stream#param_control_specs`, into `Notes#control_specs` and ControlMap/ACID XML).
- Read points (once per decision): stream NoteMaps at the played note-on, at the note's timeline position (`Scheduled#param_at`): humanize time and velocity, quantize amount, swing amount (the note-off warps by its note-on's amount), chance p, transpose step (`Transform::MovingTranspose`, a NoteMap so note-offs follow), every n (at the bar's start), legato fraction (`Transform::Legato` reads it at the note-on and keeps it for the note-off; below 1/64 it is 1/64; omnibus15); arp rate at each step (`Arp#rate_at`; numbers of 1 or more are note divisions); ratchet count at the note-on and rate at each hit.  Clip operations with a param (`Clip::ParamOperations`, prepended to Clip and Seq, arguments passed through as given) add a Variation that reads at each event's clip position (every: the cycle start; legato: `bass.loop.legato(5.bars.lfo.at(0.25..1))`, slides keep their overlap); strikes' `chance:` at the cycle start.
- `Knob#value_at(pos)` (`Knob::ValueAt`, the Mac's G3 requirements): a position in the span being rendered gives exactly the rendered value; a future position gives the value as known at the call (ramps in progress, pending segments, turns waiting in the Session's change queue rebuilt from their journal data, which now includes `smooth:`), never extrapolating a follow (the latest value while following; the value before a follow that hasn't started).  Side-effect free for the sound, no render lock (the knob's own short lock; the change queue copied).  Future answers are decisions: the knob remembers each (up to 4096), and `Session::Decisions` logs them; takes save them (`r.decisions [...]`) and replays answer from them, so ahead-of-time reads replay exactly whatever the thread timing.
- Decision lead: a reader deciding ahead sees only turns issued before it decided.  Generators (G3, generative.md "Steering") decide each cycle at its decision point, `lead:` (one beat) before it, inside the span holding that point, so a knob answers its exact rendered value there and a turn issued before the decision point steers the cycle; the next cycle computed ahead on the scheduler thread uses `MIDI::Param.peek` (no decision remembered or logged, choices' hysteresis state untouched) and is used only if the decision agrees.
- Not built: per-sample audio nodes as params (a transform has no sample clock: have a knob follow the node; a Hz LFO under 20 Hz gets the tempo LFO of about its period in the error: `0.1.hz.lfo` -> `write 5.bars.lfo.at(...)` at 120 BPM, `Param::Graph.tempo_lfo_for`), probabilistic scale blends for keyboards and per-degree staggered morphs between scales (proposals below).

- Pitch marks in voices (midi-consol-2b, maintainer 2026-10-18): `Notes#freq` and `v.hz` (NotePitch, glides too) add each note's pitch mark to its number (`Notes::Number` with `marks: true`, memo `:marked_number`; `NoteStack::Entry#pitch` so an uncovered mono note keeps its mark), so marked notes (cents locks, chop hits, `MIDI::Event#pitch` from bends) sound in tune in plain voices as in samplers. ## Clips from MIDI files (midi-import-1, 2026-10-28)

The maintainer (2026-10-28), about his dnb song "One Eighty": "load a midi file as a clip ... and use its rhythm as a rhythm template", decided as both meanings, rhythm first (Sequences: rhythm and feel templates).  His files in `tmp/music/` are private: specs build synthetic files with `spec/support/midi_writer.rb` (midilib), which reproduces the features of his set (surveyed on both machines): legato overlaps, dense CC lanes, files without a tempo event, tempo maps, 960 and 24576 ppqn, 5/4, 7/4, 6/8 with a 9/8 bar, GM drums on channel 10, RPN bend ranges, controller-only files.

- `MIDI::Import` (`midi/import.rb`; console `midi_tracks`, `midi_clip`, `midi_kit` in MidiMethods, help `:midi_files`).  `midi_tracks(path)` lists tracks (`TrackList`, one line each: index, name without NULs, channels, notes and range, mono / poly N / drums, slide count, controller lanes with counts).  Track picks by index or name (case-insensitive, or a unique part); nil picks the only track with notes (or the only track with events in a controller-only file); ambiguous names (two "Unnamed" tracks are common), unknown names (did you mean), and several note channels in one track (format 0) raise with the choices.
- Score time: positions are ticks / (4 ppqn) whole notes, exact Rationals, never through seconds, so files without tempo events import exactly and clips play at the session tempo.  Bars come from the time signatures (4/4 without one; a meter change starts a bar).  `from:` is a bar offset, `bars:` a length; without `bars:` the clip ends on the first bar line at or after the last note's end less a 32nd (`END_GRACE`, so a legato tail doesn't add a bar).  Notes start inside the window; notes still sounding at its end are cut.  Velocities as played; the clips are `performed?`.  The sustain pedal holds notes (`sustain: true`, like `Capture`), else it is kept as a CC 64 lane.  A key struck again before its note-off ends the earlier note there, and that note's note-off is skipped (pairing note-offs first-in-first-out instead cut the second note short).
- Slides (`slides: :auto`) are decided per pair of notes in start order: the next note starts at least `LEGATO_GAP` (a 32nd) later, before this one ends, overlapping by less than `LEGATO_MAX_OVERLAP` (an eighth) and less than half of this note, with no third note sounding during the overlap.  Measured on his files: the legato halves of his legato/staccato pairs get every overlap (15/15, 31/31), the staccato halves none, his sustained arpeggios none (the half-note rule and the third note), the live acid take 23 of 46 notes, and One Eighty's reese 216 of its 484 overlaps (the rest: 69 start together like chords, 118 overlap more than half of a short note, some have a third note during the overlap).  A whole-track rule (polyphony at most 2) found none there: the line has a few long drones.  `slides: true` marks every overlap, `false` none.
- Controllers become Sequence::ControlLanes (Sequences: controller lanes): every CC except bank select, data entry and (N)RPN selection (6, 38, 96-101), and channel mode messages; bend, carrying the RPN 0 bend range the file set (`ControlLane#range`, sent as RPN 0 when the clip launches, seeks, or swaps in); channel and poly pressure.  Each lane's value before the window is chased to a point at 0.  `cc: :steps` (default), `:fit` (`Clip#fit_controls`), `false`, or an Array of CC numbers and `:bend`/`:pressure`/`:poly_pressure`.
- `timing: :performed`: event positions are the tempo map's seconds times the session tempo's whole notes per second (rubato kept, bars no longer aligned), the loop rounded up to whole bars of the session meter.
- `midi_kit(path, track:, bars:, from:, loop:, timing:)`: channel-10 tracks and drum-named tracks (kick, snare, hat, ...) as a `Sequence::Kit` with rows named by `Grid::GM_DRUMS` (else the TR-808 voice), so tr808/tr909 play it like a grid.  Drum note lengths are ignored (his drum notes are 2-3 16ths long, overlapping the next hit): hits are `DRUM_HIT` (a 32nd) or up to the next hit of the same drum.  Notes without a drum name are left out with a warning.
- Recipes print `midi_clip("riff.mid", track: 1, bars: 2)` as called; graph documents keep the data, not the file (`RubyWriter::FILE_DATA`): clips as `events(..., controls: {...})`, kits as `grid(kick: events(...), ...)` (grid rows may be clips).  Documents and library files calling `midi_clip`/`midi_kit` go through the file rules (`Registry::FILE_METHODS`, FileGuard: paths relative to the document).
- Tempo maps: `MIDI::TempoMap` (`midi/tempo_map.rb`) reads every tempo event of every track (the last on a pulse wins, 120 BPM before the first), converting pulses to exact seconds span by span; FileSource and MIDIFile use it by default (before, the first tempo of the first track held for the whole file), so his rubato piano pieces (106 and 191 tempo events) play at their recorded times.  `FileSource::ConstantTempo` keeps one tempo on purpose.
- Notes controllers keep Float values between 7-bit steps (`Notes::Control#update`: a value that isn't a raw step keeps its fraction), so fitted lanes play at full precision; byte-parsed events and out-of-range values read as before.
- Not built: program changes and bank selects are dropped (a patch per clip could come from them); controller-only clips become knob gestures by hand (`turn :vol, lane.keyframes(0.0..1.0), curve: lane.gesture_curve`: Duration keys, values mapped onto the knob's range), not by a command; the One Eighty smoothing study is below.

### One Eighty smoothing study (midi-import-1 item 7, local only)

His "One Eighty 2006.mid" track 1 (the microKORG reese, 739 notes over 179 bars at 180 BPM) carries a 3296-step CC1 lane exported from ACID ("the original ACID file has far fewer control points"): ACID wrote steps on a 32nd-note grid when the value changed (spacing 120-1320 ticks, 1-4 7-bit steps a point, one jump of 75).  Scripts and renders stay out of git (`/claude/jobs/e84fa5c8/tmp/midi-import-1/scripts/study*.rb`; Bench set `tmp/listening/midi-import-1/`, unpublished).
- Gesture.fit of the lane (`cc: :fit`): within half a 7-bit step 1051 keys (linear, 8.7 s), one step 393 (cubic, 2.7 s, the default), two 204, four 137 (1.0 s): 12% of the steps at the default.  The maintainer will compare the count with a screenshot of the ACID envelope.
- Zipper energy of the control signal `v.mod` over the whole lane (above 200 Hz / 2 kHz, the `notes_smoothing_spec` measure): raw steps without smoothing -63.7 / -73.7 dB, the default 10 ms triangle -97.4 / -144.7, `smooth: :adaptive` -94.6 / -125.0, fitted keys without smoothing -71.5 / -81.2 (the 1/512 grid's own steps), fitted with the default smoothing -107.1 / -151.2.  The resolution barely matters once smoothed (1/128: -101.9 / -148.3, 1/256: -104.6 / -147.6, 1/512: -107.1 / -151.2) and costs little (a dense cubic lane is 0.5% of realtime in ClipSource, 0.9% through a Notes controller at 1/512 vs 0.65% at 1/128), so 1/512 stays the default (`fit_controls(resolution:)` changes it).
