# MIDI

Detailed notes moved from CLAUDE.md (2026-10-10); CLAUDE.md keeps a summary and points here.  Update both when behavior changes.


`lib/mb/sound/midi/` is a pull-based event layer, loaded from `midi/streams.rb` after Sequence: Sources make Events, Streams share them among readers, Notes turns them into signal nodes, and Synth allocates voices.  Nothing is pushed through callbacks, and nothing reads a clock except live input.

- `MIDI::Event` (`midi/event.rb`): the only MIDI message type (`Note#to_midi`/`Pitch#to_midi`/`Tone#to_midi` return note-on Events whose `bytes` `MIDI::Output#<<` sends), a Data value (normalized velocity/CC/pressure 0..1, bend -1..1, raw kept, 0-based channel, time in Rational seconds since the stream start; allocator types `:choke`/`:glide` and `legato`).
- Sources (`midi/source.rb`: `read(from, to)`, `seek`, `restart`, `ended?`, `music_end`, `chase`; note-ons/offs kept balanced across jumps): `FileSource` (one tempo via a tempo-map object, `loop:`; `#notes`/`#note_stats` list notes with key and pedal release times as played, via `MIDI::NoteList` in `midi/note_list.rb`, used by `bin/midi/midi_roll.rb`), `ClipSource` (see Sequences), `LiveSource` (below).  `MIDIFile` (`midi/midi_file.rb`) only parses and analyzes files (`events`, `tracks`; no clock).
- Chases (`Source::Chase`, 2026-10-11): `starts` marks a chased note that starts exactly at the jump (its note-on follows); clip sources also give `previous` (the note before, around the loop) and `elapsed` (seconds since the chased note started), which `Glide`s made with `resume: true` (tweens) use to resume the glide in progress (omnibus4); Notes nodes apply chases through `chase_item`, which calls `#chase_start` for those (the same as `#chase` except `Glide`, which keeps a pending `from:` so tweens launched in a Session glide from their first keyframe; see `curves.md`).
- `MIDI::Stream` (`midi/stream.rb`) reads a source once for many `reader`s (cursors in seconds, so any sample rate; late readers start at the slowest), stamps bend ranges from RPN 0, and makes transform views (`midi/transform.rb`: `channel` 0-based, `transpose`, `sustain` (the only sustain handling), `velocity_curve`, `bend_range`).  Streams include `Nameable`/`Traversable` but aren't GraphNodes.  `Stream.for` takes a Stream, Source, Input, Clip, MIDIFile, filename, or anything with `#to_midi_stream` (a Notes).
- `MIDI::LiveSource` (`midi/live_source.rb`; `Stream.live(connect:, output:, timing:)`) reads `MIDI::Input#read_raw` (JACK frame times or RtMidi deltas).  `MIDI_TIMING=exact` (default) keeps timestamp spacing at a constant latency L (default: the output's queue limit + period + one buffer, ~63 ms with `:default`, ~18 ms with `:low`; `latency:` overrides); JACK input with a JACK `output:` is sample-exact through `DeviceOutput#jack_clock`, else the input clock is anchored at the first events and re-anchored when off by more than L (`#track_drift` is the hook for a DLL); `asap` puts events at the start of the read.  `MIDI::RealtimeReader` (`midi/realtime_reader.rb`) plays a file or live input against the wall clock for the bin/midi tools (no audio).
- `MB::Sound::Notes` (`lib/mb/sound/notes.rb`, `notes/`): the per-voice (or mono) signal DSL over a stream (`v` in synth code; `Notes.new(stream | source | clip | file, sustain: true)`).  Note nodes read `note_stream`, the input through the sustain pedal transform (lazy and held weakly, so a Notes used only for controllers or as a synth source never holds the input back), unless `sustain: false` (Synth lanes, already pedaled, and `Clip#notes`); `stream` stays the input (controllers, `to_midi_stream`, `.source`); `control_specs` adds the pedals while note nodes use them.  Every node has its own reader and puts events on exact samples at its own rate: `gate`, `trigger` (impulse = velocity), `number`, `velocity`, `lift`, `choke` (`:choke` events, CC 120), `freq` (Tuning + bend); last-note priority; held values chase `Source#chase` after jumps.  Channel-wide nodes (`bend`, `bend_semitones(range)`, `pressure`, `cc(n, range:)`, GM-named `mod`, `brightness`, `resonance`, `attack_time`, `vibrato_rate`, ... with `MIDI::ControlSpec`s, listed by `notes.controls`) are shared per control stream (`Notes.control_stream`).  `env`/`amp_env`/`fm_env`/`filt_env` are `NoteEnvelope`s wired to gate/trigger/velocity/choke (`lift: true` opt-in), GM2 time scaling (CC 73/75/72) unless `.gm(false)`, registered for `notes.idle?`/`notes.level`.  `v.hz` is a `NotePitch` whose tones key-sync (`Notes::KeyedTone`, `reset(v.key_trigger)`) unless `.free`/`.lfo`/`.sync`; `.bend_range(12.st)`, `.transpose`, `.vibrato`, `.glide(50.ms | :gm, legato:)`.  `v.key_trigger` (`Notes::KeyTrigger`, alias `key_sync_trigger`) is `v.trigger` without note-ons that add energy to a sounding voice (user rule, 2026-10-05: adding energy to an existing envelope doesn't reset oscillators), i.e. note-ons while a `retrigger: :add` envelope of the Notes is sounding, decided per buffer from the envelopes' state at the buffer start (`Notes#adding_at?`, `NoteEnvelope#sounding_at?`, so graph order doesn't matter); `v.trigger` fires at every note-on.  `v.cutoff(base, env:, keytrack: 0.5)` and `v.quality(q)` feed `filter(...)`; `v.reso(amount)` (CC 71 around the base) feeds `lp4(resonance:)`.  `v.poly_pressure` (alias `key_pressure`; per-key 0xA0 pressure of the newest held note, 0 at each note-on, held after release; the Allocator routes each key's pressure to its lane), `v.aftertouch` = max(poly, channel pressure) (it was an alias of `pressure`; `channel_pressure` is the new alias); ControlSpec type `:poly_pressure`, listed but left out of ACID XML.  Controller smoothing (2026-10-08; `Notes::Smoother`, kernel `FastControl.smooth`, mirror `Smoother.smooth_ruby`): CCs, GM-named controls, channel/poly pressure, aftertouch, and bend (so `v.hz`/`v.freq`) glide between MIDI steps through a triangle FIR (two moving averages; each step an S-shaped transition that lands exactly after the time, delay half of it): `Notes::CONTROL_SMOOTHING` 10 ms, `BEND_SMOOTHING` 5 ms (`Notes.control_smoothing`/`.bend_smoothing` apply live: nodes made with the default keep a smoother, a pass-through one while the default is false, and `Smoother#length=` re-plans it from the current output on its next buffer, also in plans (the plan op reads the smoother's arrays each block); nodes given `smooth:` keep theirs; spec_helper restores them); adaptive smoothing `smooth: :adaptive` (`Notes::ADAPTIVE_SMOOTHING` 5..200 ms) or a Range of times (also as the global defaults): each step glides linearly from the current output over the time since the previous step, clamped (the user's scroll-bar idea; a slow 7-bit wheel becomes a line, lag one step interval; kernel `FastControl.adaptive`/`mb_adaptive_run`, mirror `Smoother.adaptive_ruby`, plan `Op::Smooth` picks the kernel by the state's length, 8 = adaptive); per node `smooth:` (`v.cc(1, smooth: 20.ms)`, `v.mod(smooth: false)`, `v.bend(smooth: 0)`, `p.midi_cc(..., smooth:)`); switch CCs (curve `:switch`) step unless given a time; gate/trigger/number/velocity/lift/choke never smooth; poly pressure jumps at note-ons and content jumps.  Measured on 7-bit pressure steps every 4 ms: energy above 200 Hz / 2 kHz -54 / -65 dB stepped, -86 / -136 at 10 ms (one-pole and linear ramps measured worse above 2 kHz); ~1 us per moving 128-sample buffer, settled buffers pass the frozen constant through (`spec/lib/mb/sound/notes_smoothing_spec.rb`).  Specs that check values on event samples set the defaults to false.  `v.lfo(rate, shape: :tri/:saw/:square/:sine/:noise, depth:, delay:, from:, sync: :key/:free/:random, wheel:, pressure:, unipolar:, human:, seed:, skew:, phase:)` (a Multiplier of a `Tone#lfo`, depth, and FadeIn; `skew:` makes the triangle rise for that fraction of each cycle (0.5 plain, toward 1 a ramp; built from the phasor with one exact `aclip`, because `Tone#pwm` on a triangle warps its lobes, not its slopes; omnibus5, 2026-10-11, for the vocal lead song's wobble), `phase:` the starting phase (key resets go there; `1 - skew / 2` starts a skewed LFO from its low point); Duration rates follow the tempo; `:noise` is `GraphNode#sample_hold` (alias `sah`) on a naive square; `vibrato` is built on it).  Mod sums (`ModMethods`, also `MB::Sound.mod_sum`): `v.mod_sum(base, src => amount)` (Intervals in semitones) and `v.mod_scale(base, src => amount)` (base × 2 ** octaves); Symbol sources in voices: `:velocity`, `:vel_x`, `:key` (octaves from C4), `:wheel`, `:pedal`, `:breath`, `:bend`, `:pressure`, `:poly_pressure`, `:aftertouch`, `:lift`, `:gate`.  Demo: `bin/synths/sq80_voice.rb` (~50% of realtime at 128-sample buffers and ~16% at 512 for 8 voices without its chop/flutter oddities, ~80%/26% with them, normalized to the fm_bass reference below, 2026-10-07).  Gate/trigger/choke and envelopes return nil once the stream ended and the envelopes are idle; nodes report `ended?` for script ringdowns.  Nodes are cached per instance through WeakRefs.  Fast paths (`Notes.fast_paths`, `MB_SOUND_NOTES_FAST=0` off; null-tested in `spec/lib/mb/sound/notes_fast_paths_spec.rb`): constant frozen buffers while nothing changes (consumers cache by identity), one `Notes::EnvelopeInputs` reader per envelope, idle envelope kernel skips, shared Stream events and Frequency nodes.
- Ending on a grid (fixes-12, 2026-10-14): a Notes' gate, trigger, and choke nodes end the graph once the stream is over and the Notes is idle (`Notes::Node#finished?`).  That check ran at buffer starts, so a graph ended up to a buffer after the stream's last event, and a filter ringing on a gate or trigger was cut at a buffer-size-dependent sample (measured on master-ai 94c421d7, clip ending at 24000: ends at 24800 at 800-sample buffers, 24255 at 367/368, 24744 at 1031, 24001 at 1; `gate.filter(:lowpass, cutoff: 50)` lost its whole decay at full level).  For Notes without envelopes or a quiet check (`Notes#grid_end?`) these nodes now end on their `END_GRID` (800 samples of their own output) at or after the sample after the stream's last event (a gate with a note still held waits `TAIL_SECONDS` more), returning a short last buffer, so they end on the same sample at any buffer size, where 800-sample buffers ended them before (renders at 800 unchanged); a seek or restart before then (a new reader generation) cancels the end.  `Resonator` now treats a short input buffer as the input's last and rings out after it in the same buffer (like nil).  Envelopes and Synths (fixes-13, 2026-10-14): Notes with envelopes ended at the first buffer start where every envelope was idle, and Synths at the first buffer start after their lanes ended, so a resonant filter after them was cut 0..799 samples off (measured on master-ai b6b06139 against 800-sample buffers: `(saw * amp_env).filter(:lowpass, quality: 8)` -77 to -99 dB, a Synth into it -52 to -98 dB, ending up to 800 samples earlier or 1031 later).  Now:
  - Envelopes end on the `END_GRID` of their own output (counted from their first sample, like the note nodes').  `NoteEnvelope#sample` renders a buffer crossing a grid point after the stream's last event in pieces split there and records its idle state on the point (`Notes#grid_idle`); the graph ends at the first point where every envelope of the Notes that has rendered is idle and the Notes is quiet: the last envelope to reach it in a buffer decides and returns a short buffer (arithmetic cuts the others' full buffers at it), the others return nil from their next buffer, and the Notes' gate/trigger/choke nodes end there too (`Notes#grid_end_frame`; a seek or restart cancels it).  800-sample buffers from the first sample ended there before, so those renders don't change, except where the old check at a buffer start saw another envelope's state from after that start (an envelope rendered earlier in the same buffer): `(saw * amp_env).filter(cutoff: 200 + 2000 * filter_env)` ended at 38400 at 800 because the amp envelope, sampled first, was already idle at the buffer's end; it now ends at 39200, the first point where both were idle (the filter rings 800 samples longer).  Bin renders at 800 (acid, dnb, electric_pianos, filter_ping, fm_bass, fm_epiano, acid_song, night_bus_flow, sequence_demo) kept their lengths and samples (within -125 dB).  A Notes whose envelopes never rendered ends as before; a hanging note still ends after `TAIL_SECONDS` at a buffer start.
  - Synth lanes (Notes with a quiet check) keep ending at buffer starts (so filters inside a lane ring out below -90 dB first); the Synth itself ends on its measuring grid (`SKIP_GRID`, aligned like `#align_grid`): from the buffer reaching past its stream's last event (`Synth#tail_mode?`) it splits blocks at grid points, measures lanes over grid cells (`#cells?`, as with `exact_lanes`; per piece, short pieces looked quiet), and ends (`#check_end`, `#end_frame`) at the first grid point after the last event where every lane is idle and nothing has been louder than -90 dB for a whole cell, plus its `tail:`, returning silence after its lanes up to there and a short last buffer (`#fallback_end` if every lane ended before a grid check).  Again where 800-sample buffers ended it.

- `MIDI::Allocator` (`midi/allocator.rb`) splits a stream's notes into `lanes` (`Lane < Stream`, `voices + spares`; one in mono mode), each with at most one note plus every channel-wide event, reading its input once so lanes read in any order with identical results.  When full, the `steal:` chain (`:same_note`, `:oldest_released`, `:oldest`, optional `:quietest`; `protect: :lowest/:highest`) chokes a victim while the new note goes to a spare.  `lane.idle_check` frees released lanes.  `retrigger:` (when every voice is busy and the chain has `:same_note`): `:reuse` (default: restart the newest lane playing the note), `:louder` (reuse it only if no envelope would attack downward, via `Lane#louder_check`/`level_check`; else as `:new_voice`), `:new_voice` (a spare takes it, so the old note rings on), `:quietest` (the quietest lane playing the note), `:per_key` (one lane per key, always restarted, even with voices free).  Mono (`voices: 1`, `priority: :last/:low/:high`) sends legato note-ons; polyphonic `glide_mode: :last` (default) sends `:glide` events, `:voice` none.  Allocator unison (several lanes per note) isn't built; oscillator unison is `pitch.unison` (oscillators.md).
- `MB::Sound::Synth` (`lib/mb/sound/synth.rb`; `MB::Sound.synth(source = nil, voices: 8, **opts) { |v, i| }`, nil meaning live `midi`; `notes.synth`, `clip.synth`): `Synth.new(source, voices: 8, spares: 2, steal:, protect:, mono:, priority:, glide_mode:, retrigger:, controls: [], bend_range: nil, sustain: true, seed: nil, tail: 11, skip_idle: true) { |v, i| graph }` reads the source through `.sustain`, splits it with an Allocator, calls the block per lane with a Notes on it, and sums the lanes (`sample_individual(count)`; bundles give one `Synth::Output` per channel).  Lane blocks run in `MB::Sound.with_seed(seed + i)` and `Synth.with_lane(i, lanes)`: inside them `per_voice(list | range)` (2026-10-10, `MidiMethods#per_voice`, the voice-level sibling of `per_channel`; `channels`/`per_channel` keep their multichannel meaning there) returns the lane's value right away: a list cycles over the lanes (voices plus spares), a Range spreads evenly over them (`ChannelSpread#value`), outside a lane block it raises (`Synth.current_lane` is nil); the graph-io writer prints lanes that differ only in values with it.  `controls: [:volume, :expression, :pan]` (CC 7/11/10) are opt-in.  `retrigger:` takes the Allocator modes plus `:add` (reuse, every lane envelope `retrigger: :add`) and the presets (`Synth::RETRIGGER_PRESETS`): `:string` (`:per_key` lanes + `:add` envelopes, never doubling a key; user-approved for pianos/e-pianos; key-synced oscillators keep their phase on these re-strikes, `.free` ones never reset; see `bin/synths/fm_epiano.rb`) and `:ring` (alias `:bell`; user's choice for bells, fm_bell's default with `-r` to compare): a free voice if any, else the quietest lane ringing the note with `:add` envelopes, else steal the quietest (`RING_STEAL` unless `steal:` given).  Renders: /app/tmp/listening/retrigger/.  `ended?` = finite source over and every lane idle: Notes idle and the lane's output under -90 dB (`Synth::QUIET`, `Notes#quiet_check`, `Synth#quiet_lanes`), measured after each buffer by default; with `exact_lanes: true` (`Synth.new(..., exact_lanes: true)`, `Synth#exact_lanes=` before the first sample, `Session#exact_lanes = true` for the Synths of players it starts, `render(exact_lanes: true)`, and always in take replays) measured over whole cells of the `SKIP_GRID` (800 samples) and recorded at the grid points, where every buffer crossing one is split (`Synth#sample_lanes`, `#record_cells`), and the allocator frees a released lane by that record, counting only notes sent to it before the record (`Lane#idle_position`), so allocation is the same at any buffer size (fixes-7, 2026-10-13: measured after each buffer, a released lane was free at 367/368 and not at 800 when a note came, which then played on another lane with another free-running phase, +1.2 dB in a persona take).  Maintainer decision (fixes-7 round 2): exactness only when asked for, so the default costs nothing extra at any buffer size and renders as before; exact lanes cost a pass over the lanes per grid crossing: standalone (graph_profile, dense_modulated.mid, against master-ai d86d4454) fm_epiano 11.5 -> 12.6% of realtime at 128, 6.0 -> 7.8% at 367/368, 4.2% at 800 either way; pluck 49 -> 55%, 24 -> 34.6%, 16.6 -> 17% (default: the same as master-ai at every size).  In a Session the measuring grid is aligned with the Session's frames when the player starts (`Synth#align_grid`), so 800-sample Session buffers never split even for synths launched off the 800-frame grid (idle skipping keeps its grid of the synth's own time: moving it moves where free-running oscillators pause, night_bus_flow's mono hooks by up to +6 dB).  With exact lanes, a lane's Notes count it quiet only if the part of the current cell it has played is quiet too (`Synth#cell_quiet?`), and ends come at the grid point after the last loud cell, so envelope-less voices (filter pings) and resonant tails ring out and aren't reused while ringing (the peak is also `Notes#level` for `steal: :quietest`); the runner's ringdown keeps a Synth and ignores the nodes inside it; then `tail:` seconds of silence and nil.  `skip_idle: true` skips idle lanes (Notes idle, output under -120 dB, no delays/reverbs/FIR/feedback loops/tempo nodes inside the lane, and no plan lane groups: grouped lanes are computed every buffer, see Plan layer; MIDI transforms and clip sources upstream only make events, which wake lanes, so clip synths skip too since 2026-10-10; not sample-exact, since free-running oscillators and noise pause while skipped, but the same at any buffer size since 2026-10-13: lanes fall asleep only on a grid of `Synth::SKIP_GRID` = 800 samples of the synth's own time (an idle lane whose last grid cell was silent; buffers are split there when needed, unless a held note with no event in the buffer keeps the lane awake) and wake on the exact sample of their next event (`Lane#first_pending_time`, events from the readers' cursor only; a mid-block wake reads shared plan inputs through `Plan::SharedInputs#window`); 800-sample runs sleep where they did before, but wakes moved from the buffer start to the event sample, so lanes that wake mid-buffer render noise and free-running phases differently from before).  Cost (2026-10-04, YJIT, 8 voices, saw × amp_env → lowpass): ~6% of realtime at 128-sample buffers, ~2.3% at 512.
- Sub-lanes (synth-sublanes-1, 2026-10-16; `GraphNode::SubLane`, `lib/mb/sound/graph_node/sub_lane.rb`): skippable parts of a lane's graph (one or more channels) that sleep while they have nothing to play, so a lane only computes the parts that sound; `Sampler::Instrument#play` makes one per narrow layer of a layered instrument in synth voices (SoundFont zones that overlap; layers covering at most half the keyboard, `Instrument::SUB_LANE_COVERAGE`; see `sampler.md`).  A sub-lane falls asleep at a `SKIP_GRID` point of the synth's own time after a cell of exactly zero output (not just under -120 dB, so filter states have flushed) with its envelopes and sampler voices idle, and wakes on the exact sample of the next lane event its `wake:` Proc accepts (`Lane#first_pending_time(from, to) { |e| ... }`; the instrument's: note-ons with a region for the key and velocity) or at a content jump.  While asleep it outputs frozen zeros and pauses the nodes only it reads (found from the lane graph: every reader exclusive, Tees by all branches), keeping in step its branches of Tees read elsewhere in the lane (read and dropped; shared controllers are left to `Plan::SharedInputs`), its Notes nodes and knob readers (advanced), and its own reader of the lane (its clock); idle Notes envelopes catch up on their stream time at the wake (`NoteEnvelope#advance`).  The Synth tells sub-lanes which lane piece is being read (`Synth#lane_piece`: lane, synth sample, count, serial; set in `#sample_lane`/`#sample_skippable_lane`), windows shared inputs for mid-piece wakes (`#sub_lane_window`), and advances their clocks while the whole lane sleeps (`SubLane#lane_skipped`).  Output is the same at any buffer size and, for instrument layers (envelopes, sampler voices, filters, zone values), bit-identical to rendering them every buffer (GeneralUser GS piano, Tine EP, Full Orchestra, Standard kit at 800, 128, 367/368, 1/7/333/801/64; `spec/lib/mb/sound/sub_lane_spec.rb`, also under plan check mode); free-running oscillators of a sub-lane's own would pause, as in skipped lanes.  A sub-lane stays awake with a `#reason` if a node inside reads a lane node without a Tee, has long memory, or shares a `ZoneValue::Index` with nodes outside (the Synth gives them their own while building each lane: `SubLane.prepare`, `ZoneValue.separate`).  Synths with sub-lanes form no plan lane groups; outputs of sub-lanes that can't sleep are plan pass-throughs.  `Synth#sub_lanes` lists them per lane (`skipped_samples`, `wakes`, `asleep?`); `Synth.sub_lanes = false` / `MB_SOUND_SUB_LANES=0` turn them off, `skip_idle: false` too.
- Same-key notes (omnibus8 `fixes-prepanel-1`, maintainer 2026-10-17): jack-keyboard drops note-offs when its window loses focus with a key or the pedal down, and "pressing the same note again stops the note in most synths", but the Allocator counted overlapping notes on one key (on 60, on 60, off 60 left a voice on at any voice count and retrigger mode).  `same_key: :count | :restrike` on `MIDI::Allocator`, `Synth` (and `Notes`, for readers without an Allocator); nil (the default) picks `:restrike` when the source is real-time input (`MIDI::Source#realtime_input?`: `LiveSource` (hardware and the UI keyboard's `VirtualInput`), `Session::MidiInput` taps (console `midi`, `LiveClip` monitors, and take replays, which read the same taps, so replays allocate the same way), transforms and merges of them; Allocator lanes answer false), else `:count` (files, clips, transforms of them; unchanged).  Allocator `:restrike`: a note-on for a key whose lane is *sounding* (held) on that channel restarts that same lane (note-offs for the notes it held, then the note-on, at the note-on's time, so lanes stay balanced), before `retrigger:` and the steal chain and after choke groups; the key's older note-ons are forgotten, also stolen/choked ones when the key starts on a new lane, so the next note-off releases it.  Released (ringing) keys get a lane as usual.  Pedal: `Stream#sustain` already sends a pedal-held key's note-off just before its re-press, so it takes a new lane (piano-like; the old one rings in its release); a dropped note-off under the pedal ends at pedal up after one re-press.  Mono: the key leaves the note stack (older entries dropped) and is pushed again; if it was sounding it restarts with a plain note-off/note-on (not legato: no glide, envelopes retrigger); a re-press under another held note stays legato as usual.  Poly pressure follows the restruck lane's one slot.  `Notes` (no Allocator) reads `Stream#restrike` (`Transform::Restrike`: off before a re-pressed held key's on, the older note-off dropped, CC 123+ forgets the channel) before the pedals; `Notes#synth` passes its mode on.  A merge of live and clip streams restrikes clip notes a live key repeats (documented edge).  MIDI going out: `MIDI::Output` (`same_key: :restrike` default, `:raw`) writes through `Output::NoteBalancer` (raw bytes: a note-on for a held key sends a note-off first, the extra note-off is dropped, CC 123+ forgets the channel), so receivers aren't left guessing.  MIDI file export (export-1, on hold) must do the same: end the earlier note before the next note-on of a key in each track/channel.  Specs: `allocator_spec.rb` ('same_key', a randomized invariant with dropped note-offs), `same_key_spec.rb` (Notes, Synth at 480/7/128/800, Stream#restrike, NoteBalancer).
- Zone value indices and skipping (synth-sublanes-1): a `ZoneValue::Index` serves its readers in lockstep, and a skipped lane advanced its FadeIn (an SF2 LFO's delay) whose delay `ZoneValue` shared the voice's Index with paused values: GeneralUser GS "Full Orchestra" in a 6-voice synth raised "ZoneValue::Index: buffer 2 was asked for after buffer 15 (readers out of step)" on master-ai.  `Synth#prepare_skipping` (while building each lane) gives values read through advanced Notes nodes an Index on private Notes number/velocity nodes (`ZoneValue.separate`; with branches of the shared number node instead, its other branches overflowed).
- MIDI transforms (`midi/stream_transforms.rb`, `midi/transform/*.rb`; user decisions 2026-10-09 in the memory's ideas-midi): Stream methods mirrored on Notes (a Notes with the same pedal setting; pedals hold transformed notes) and, for `echo`/`arp`/`strum`/`chord`/`snap`/`through`, on Clips (returning Streams).  Future-event transforms are `Transform::Scheduled` (a time-sorted queue sent as it comes due, so any read size gives the same events; a ledger of note ids keeps output balanced through jumps, swaps, and stream ends: `overlap: :retrigger` (default; newest note owns the key) or `:stack`, `jump: :ring` (default; queued echoes ring on) or `:cut`) and `Transform::Timeline` TimelineNodes (Stream#sources lists them, so Sessions hand them the transport and timeline).  `echo(delay, count, pitch: degrees/Interval/Array cycled, velocity:, gate: (nil = played length), dry:, scale:, root:) { |e, i| }`; `arp(mode, rate = 16, octaves:, step:, gate: 0.5, velocity: nil/number/accents, swing:, latch:, start: :grid (timeline-locked, waits for the next step) / :key (Juno), steps: [offsets], scale:, seed:)` (modes up down updown downup up_down down_up played random converge diverge pinky thumb chord); `chord(:min7 | degrees, scale:)`, `strum(spread, :down/:up/:alternate/:random/:played, window:)` (live chords need a window, added as latency), `humanize(time = 4 ms, velocity:, seed:)` (4 ms since midi-consol-1, decision 7; 10 ms before) and `quantize(grid, amount:, window:, ends:)` (later only), the stream versions of the clip operations (midi-consol-1: `swing`, `chance`/`maybe`, `every` (timeline bars), `legato` (below 1 by `Event#length_hint`), `ratchet(count, rate:)`, `ghost_chords` (live input too), `rotate` = `shift`; shared cores in `Sequence::Feel`, see sequences.md), `snap(scale, root)`, `transpose(step, scale:)`, `select`/`reject`/`velocities(range)`/`map_notes { |e| }` (note-offs follow; `Transform::NoteMap`), `rechannel`, `split(note)`, `merge(*streams)`, `vel`, `velocity_curve(Range)`, `note_length`/`len`, `shift`.  `Event#transpose(step, scale:)`, `#with_channel`.  Random ones seed from `MB::Sound.next_seed` (or `seed:`), one Random per decision from seed + counter. Live MIDI goes through JACK MIDI ports on the shared JACK client when a JACK server answers (see Audio I/O; `connections` are the port's live JACK connections), else the bundled RtMidi 6.0.0 (`ext/mb/sound/fast_midi/`, `MB::Sound::FastMIDI`; CoreMIDI on macOS, ALSA sequencer on Linux): `MB::Sound::MIDI::Input` (`lib/mb/sound/midi/input.rb`) polls the queue in `#read_raw` (once per buffer, from LiveSource).  By default it opens a port named after the script (`DeviceOutput.client_name`); `connect:`/`MIDI_DEVICE` connect to a source by part of its name, searching the other compiled API too when `MIDI_API` isn't set (`Input.find_port`; no match warns with the source list and leaves the port unconnected); `Input.open_live` prints where to connect (bin/midi tools).  `MIDI_API` picks `core`/`alsa`/`jack` (JACK by default when a JACK server answers, jackd or PipeWire's: `DeviceOutput.jack_running?` is `FastAudio.jack_server?`, which dlopens libjack and opens and closes a client without starting a server, ~5 ms).  `MB::Sound::MIDI::Output` (`lib/mb/sound/midi/output.rb`) is a minimal output (`write`/`<<` of bytes, `connect:`), used by `bin/midi/midi_events.rb --forward` and the specs; scheduled MIDI output isn't built.  RtMidi's C API leaves `msg` dangling after errors, so `fast_midi.c` never reads it.  `bin/midi_check.rb` shows the MIDI APIs, why one is chosen, the loaded libjack, audio backends, all ports, and `--listen`/`--loopback` tests (`spec/bin/midi_check_spec.rb`).  RtMidi is vendored unmodified (built with `HAVE_SEMAPHORE` on Linux, as RtMidi's own build does; without it closing a JACK output raced its process callback and crashed libjack under load), and compiled inside `rtmidi_build.cpp`, whose `mb_rtmidi_jack_release` deactivates a JACK client before its port goes (unregistering on an active client races libjack's notification thread; 2026-10-12, see Audio I/O); `ext/mb/sound/fast_midi/README.md` has the update steps.

Specs send real messages through a private JACK dummy server (`spec/support/jack_dummy.rb`; they skip without `jackd`) with `MIDI::Output`/`FastMIDI::Output`.  Every JACK2 server maps ~38-40 MB of `/dev/shm`, so Docker's 64 MB holds one (dock.sh creates the container with `--shm-size=512m` since fixes-14): spec processes take turns through a lock file (`/dev/shm/mbspec-jackd-UID.lock`; a server started outside it that leaves too little room makes the specs skip after `LOCK_TIMEOUT` rather than crash both); `JackDummy.start` also cleans up after crashed or dead spec servers (registry slots, metadata DB, orphans), and servers run under `setpriv --pdeathsig TERM`.  A spec process from an older checkout (no lock) running at the same time can still crash both servers (SIGBUS; `JackDummy.stop` warns).  Spec servers run with `--sync`: an asynchronous server skips or repeats cycles for a client that is late (lost or doubled messages under load); the JACK input drops repeated cycles in C and `read_raw` warns once, but lost events can't be recovered, so live users with an async jackd should use `--sync` or a lighter load (details in Audio I/O, "Late clients").

`MIDI::ControlMap` (`midi/control_map.rb`) lists the controllers something responds to and writes controller maps for the ACID DAW (user: ACID remote control of synths matters).  It collects `ControlSpec`s from specs, Arrays, other maps, anything with `#control_specs` (`Notes`: the controller nodes in use on its control stream; `Synth`: its lanes' shared controllers, output controls, and the sustain pedals' CC 64/66/67 (`Transform::Sustain::CONTROL_SPECS`) unless `sustain: false`; `Notes::Control` nodes; knobs with a controller, `GraphNode::Knob#control_specs`), and graph nodes/bundles (every upstream node with `#control_specs`); equal specs once, specs sharing a CC number grouped.  `ControlSpec#type` is `:cc`, `:bend` (`ControlSpec.bend(range:)`, raw 0..16383 centered at 8192), or `:pressure` (`ControlSpec.pressure`); `Notes#bend`/`bend_semitones` (so every `v.hz`/`v.freq`) and `#pressure` carry them, sorted after the CCs (`ControlSpec#key`; `map[:bend]`, `map.types`).  Enumerable over specs, `numbers`, `[]`, `groups`, `to_s` (also `pretty_print`, for Pry), `to_acid_xml(name: script)`, `write_acid_xml(path)`.  Console: `midi.controls`, `synth.controls` (`Synth#output_controls` is the `controls:` list).  The XML matches the old Manager's byte for byte (`spec/test_data/acid_xml_reference.xml`, `spec/test_data/acid_xml_bend_reference.xml`), except that entries are sorted by CC number and `params=` counts entries.  Effect and synth scripts list their controls (`p.midi_cc` specs, even when constants, the script's MIDI controllers, and the graph's) after the parameters when MIDI is in use, hidden by `-q`, and take `--acid-xml FILE` (`-` prints it; written even with `-q`).

Knobs and MIDI (arrange-3, 2026-10-11; `arrangement.md` Knobs): `GraphNode::Knob#listen(stream)` reads controller Events once per Session span (a `Stream` reader; moves on the exact frames of their event times, `Rational` stream time), follows its `cc` or `#learn`s the next controller moved, with `:pickup` (wait until the controller passes the knob) or `:jump` takeover.  Console `learn :cut`, `knob :cut, ..., cc: 74` use `Session#knob_midi`, the session's default MIDI input (live input attached on first use); arrange-4 journals controller gestures (`:cc`) and takes replay the moves.

## Proposal: parameters that move (`value_at`), for transforms and knob steering (midi-consol-1, 2026-10-16; decision 4: next, not built)

Transforms work in event time, so a moving parameter must answer "what is your value at this moment?" rather than be sampled per buffer.  One small protocol, shared with the planned G3 knob steering of generators (`Knob#value_at`):

- `value_at(pos, transport:, stream: nil)`: the value at timeline position `pos` (Rational whole notes); `stream:` is the transform's input, for parameters that listen to it.  Plain values (Numerics, Durations, Intervals, Decibels) answer themselves (a refinement or a `Param.wrap` that leaves them as they are, so nothing is allocated for constants).
- Implementations: `cc(1, 0.3..0.95, curve:)` (a `MIDI::ControlSpec`-backed param that keeps the last value of that CC seen on its input stream, exact at event time; ControlMap and ACID XML list it), clips as params (`seq(0, -4, 3, -2).n1.loop` read with `Clip#event_at(pos)`: transpose by sequence), tempo shapes (`2.bars.lfo` evaluated from position: TempoNode sine/ramp/square as pure functions), Session knobs (`knob(:x)`: `Knob#value_at(frame or pos)` from the knob's ramp, the same call generators use at decision points).
- Read points: once per decision, recorded so takes replay exactly: at the played note-on for NoteMap transforms (humanize amount, quantize amount, swing, chance p, transpose step), at each step for arp/ratchet, per cycle start for clip-side generators and `every`.  Clips read params at the event's position (they know the future), streams at the event's timeline position.
- Arithmetic: params compose with operators into param expressions (`0.6 + 0.3 * 2.bars.lfo`), each printing itself back as Ruby for recipes and graph documents; a Spec stores params as given.
- Not proposed: per-sample audio nodes as params (a transform has no sample clock); use a knob following a node instead.
