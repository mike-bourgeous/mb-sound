# Sampler

Sampler and audio capture, stage 1 of "Sampler + second drum machine" (maintainer, 2026-10-13; the persona panel's second request after exact takes: Nev Ashdown (jungle) and Tiko (looper) wanted it most, Kez (DnB) for resampling).  Branch `sampler-1`.  Stage 2 (`drums-2`: kit builder + TR-909) builds on the `Sample` type.

The panel's asks, in their words (`research-persona-panel` 0c08a17d, jungle friction F1-F6): "`rec = bounce(drums, 2.bars, bpm: 138.75)` for the record, `rec.slices(16)` to cut it, slice and pitch kept as separate things, `rec.at(7.n16)` for tracker 9xx offsets, and reverse per hit"; "`node.bounce(1.bar, root: F1)`, then reverse and slices on top"; "build the sampler like a tracker, with slices you can see, offsets you can type, and pitch kept separate from slice, because in jungle the chop is the instrument"; S950-style lofi and a cyclic timestretch as the first effects; `help :sampler` and a chop lesson.

## API sketch

```ruby
# Samples: immutable values (MB::Sound::Sample), mono or multichannel float32 at 48 kHz
kick = Sample['sounds/kick.flac']                     # files (GraphIO FileGuard rules), a root of C4
pno  = Sample['piano_c4.flac', root: C4, loop: 0.5.seconds..1.2.seconds]
s    = Sample[narray]                                 # Numo arrays (one per channel, or 1D)
rec  = bounce(2.bars, bpm: 138.75) { tr808(grid(16, kick: 'X...', ...)) }   # any graph, offline, private tempo
rec  = bounce(drums, 2.bars, bpm: 138.75)             # a graph built elsewhere
bass = reese.bounce(1.bar, root: F1)                  # GraphNode#bounce
cap  = capture_audio(4.bars, on: :bar)                # live: the master bus (or from: mic) from a launch point; cap.sample once done

# Sample edits return Samples
s.reverse (rev)  s.trim(0.1..0.4)  s[1000...9000]  s.fade(in: 1.ms, out: 5.ms)  s.gain(-3.db)  s.normalize
s.bits(12)  s.lofi(:s950)  s.stretch(1.25, cycle: 25.ms)  s.looped(0.5..1.0, mode: :ping_pong)  s.at(7.n16)  s.mono

# Slices: regions of one sample (no copies)
brk = rec.slices(16)                 # equal parts (a Slices: brk[3], brk[4..7] joins, brk.length)
brk = rec.slices(at: [0, 2.n16, 7.n16])  /  rec.slices(:onsets)   # times or detected transients
brk = brk.name(k: 0..1, h: 2..3, s: 4..5, sk: 4..7, g: 7)          # names for ranges of slices; brk[:sk]
brk[:s].rev  brk[3].at(0.25)         # a slice is a Sample too

# Instruments: regions mapped to keys, velocities, round robins
inst = brk.keymap(from: C2)                            # one key per slice, played at its own pitch
inst = Sampler::Instrument.new { |i| i.region pp, keys: C1..B3, vel: 1..63, root: C3; i.region ff, ..., seq: 2 }
inst = sfz('piano/piano.sfz')                          # SFZ import

# Playing: a GraphNode::Sampler voice
synth(midi) { |v| pno.play(v) * v.env(0.002, 0.3, 0.8, 0.4) }
synth(midi, voices: 1) { |v| inst.play(v, transpose: 3) }
clip.sampler(inst, voices: 1) { |v, s| s * v.env(0.0005, 0.01, 1, 0.006) }
amen = brk.chop(:k, T, :h, :g, [:s, 2], brk[:s].rev, R, ...)   # a Clip of keys with pitch marks
inst = brk.keymap(from: C1, split: C4)                         # slices below C4, the last one chromatically above
bg :breaks, amen.sampler(brk)
```

## Decisions

- **One value type, `Sample`**, separate from `Wavetable` (the persona's workaround was sample-mode Wavetables in a KeyMap).  A Sample holds the sound (one SFloat per channel), `root` (a Note; C4 by default), `loop` (a Range of source samples, a mode), `start`/`stop` (its region of the data: slices and `at` are views on the parent's data and its band-limited levels, so slicing a break costs nothing), `reversed?`, `fade` lengths, and a lineage (parent, method, arguments) for printing.  Playback quality reuses the sample-mode Wavetable levels (half-octave mipmaps, 4x oversampled, `:optimal` interpolation; see oscillators.md): built once per Sample data on first play (`Sample#table(channel)`), shared by every slice and voice.  Measured: a 3 s mono sample builds in 0.28 s into 7.9 MB of levels (13.7x the data); `mips: :octave` is about 8x, the default for `sfz()` (maintainer, round 2), which takes `mips:`.
- **Kernel `fast_sampler`** (new purpose-specific extension; exact Ruby mirror `Sampler::KernelRuby`, `-ffp-contract=off`) reads those levels through `mb_wavetable.h` (`wt_read_table`, `wt_select`, `wt_value_sel`) without the Wavetable's own loop levels: the sampler does its own position, direction, and loop logic per sample (one-shot, forward, ping-pong, release loop) and jumps at loop points like a hardware sampler.  Positions are doubles in source samples; level selection follows |speed|.
- **Note-ons inside the kernel**: at each nonzero trigger sample it picks a region from the note number and velocity (first match; lokey..hikey, lovel..hivel, round robins), so starts are sample-exact and the output is the same at any buffer size.  One region per note (SFZ layering would multiply the per-note cost; layer by adding a second sampler).  A voice re-struck while sounding keeps the old note as a tail faded out linearly over `declick:` (64 samples, 1.3 ms by default), so truncating mono voices (the jungle chop) don't click.  Worst case per sample per channel: two interpolated reads of two levels each (the tail and the new note); otherwise one.
- **Pitch**: speed = 2^((key - root) * keytrack / 12 + tune / 12) * source rate / output rate * freq / note_hz(key), where `freq` is the voice's frequency node (`v.freq`: bend; or a NotePitch with glide/vibrato) relative to the note's own frequency, so modulation is relative and keytrack 0 (drums, slices) still bends.  `transpose:` adds semitones.
- **Slice and pitch separate (chop hits)**, the maintainer's "C + D" (2026-10-13, round 2; the first version encoded hits as note numbers above 127, removed): a chop hit is an ordinary key of the slices' keymap (from C2: every slice, then every named run that isn't a single slice, then all of those reversed) carrying a pitch mark, a per-note pitch like the accent and slide marks (`Seq::Step#pitch`, `Note#pitch(n)`, `Sequence::Event#pitch`, `MIDI::Event#pitch` from `ClipSource`, `Notes#pitch_mark`, read by SamplerVoice at the note-on).  `Clip#transpose`/`Seq#transpose` move the marks of marked notes instead of their keys (a chop clip knows it is a chop through its events' marks).  Live keyboards play the same keys (the slices), with pitch from bend or a knob through the frequency input.  MIDI 1.0 bytes: a marked note-on is a pitch bend at `MIDI::Event::PITCH_MARK_BEND_RANGE` (24 semitones; set the receiver's bend range to match) followed by the note-on: per-note pitch would need MPE or MIDI 2.0, which our outputs don't speak, and a mono chop voice is where marks matter, so a channel bend says the same thing.  Plain synths ignore marks unless they use `v.pitch_mark` (Notes#freq doesn't include it, which keeps planned voices unchanged).  Split keyboards ("D"): `brk.keymap(from: C1, split: C4)` (Instrument `split:`): keys from the split up play the region the voice last played below it, chromatically from the split key (per voice, like round robins).
- **Round robins** are per voice (lane): sequential counters per key (SFZ seq_length/seq_position) and random draws (lorand/hirand) from a splitmix64 seeded per voice with `MB::Sound.next_seed` (recipes print one seed).  A shared counter across lanes would depend on lane order inside a buffer, so not buffer-size invariant.  For polyphonic round robins prefer random.
- **Velocity**: the trigger's value (Notes#trigger is valued at the velocity), scaled per region by `veltrack` (0 by default for `play`; SFZ's amp_veltrack 100 = (vel/127)²).  Velocity layers pick regions.
- **Envelopes stay in the graph** (`* v.env(...)`), as for every other voice; SFZ ampeg_* becomes the envelope `Instrument#play` multiplies in.  One-shot voices register with the Notes (`Notes#register`) so a Synth doesn't reuse the lane until the sample ends.
- **Bounce** renders offline through `render`'s private Transport and Session (`bounce(graph, 2.bars, bpm:)`, master gain 0 dB, no master chain, exact length from the transport), so the session tempo never changes (F7).  `capture_audio` uses the Session's audio recorder with an in-memory output (master bus from an exact frame) or a silent player tapping a node.
- **Lofi and stretch are offline edits** (`bits`, `lofi(:s950 | :sp1200 | :mpc60)`, `stretch`), baked into a new Sample, so they cost nothing per voice; the voice's `interpolation: :none` / `mips: false` gives the classic aliasing read.
- **SFZ**: `sfz(path)` parses the text format (a load format, not a mini-language) into an `Instrument`: `<global>`/`<group>`/`<region>` inheritance, sample=, lokey/hikey/key, lovel/hivel, pitch_keycenter, pitch_keytrack, tune, transpose, volume, offset, end, loop_mode, loop_start/loop_end, seq_length/seq_position, lorand/hirand, amp_veltrack, ampeg_attack/decay/sustain/release; sample paths go through FileGuard (relative, inside the file's directory) and `Registry::FILE_METHODS`.
- **Graph documents**: samples save as bundle assets (FLAC with their tags: root, loop, slices) with SHA-256; slices and edits print as chains on the asset (`Sample["assets/rec.flac"].slices(16)[4..7].rev`).
- **Plan layer**: the Sampler is a plan boundary for now (`plan_unsupported_reason`).

## As built (sampler-1, 2026-10-13)

- Files: `lib/mb/sound/sample.rb` (+ `sample/slices.rb`, `onsets.rb`, `lofi.rb`), `lib/mb/sound/sampler.rb` (+ `sampler/instrument.rb`, `kernel_ruby.rb`, `sfz.rb`, `capture.rb`), `lib/mb/sound/sampler_methods.rb` (bounce, capture_audio, sfz, chop, sampler), `lib/mb/sound/graph_node/sampler_voice.rb`, `graph_node/sampling_methods.rb` (GraphNode#bounce), `ext/mb/sound/fast_sampler/`.
- Stereo samples play as a `Channels` bundle of one SamplerVoice per channel (same seed, so the same regions); mono samples in a stereo instrument feed every channel.
- Round robins: sequential counters count every note-on of a key in a voice (SFZ-like), random draws one splitmix64 number per note-on.  Velocity is the trigger's value (Notes#trigger), MIDI-rounded for velocity layers.
- One-shot instruments register their voices with the Notes (`Notes#register`), so a Synth lane stays busy until the sample ends.
- Chop hits are keys with pitch marks (see above); the frequency input (bends) applies to them too.
- Onsets (`Sample::Onsets`): energy of the first difference in 256-sample windows every 64 samples, rises of 9 dB over a window, placed on the first sample whose change reaches a quarter of the attack's largest; tr808 hits land within about 10 samples of the grid.
- Capture: `Session#capture_audio(frames, output:, at:)` records the master bus from an exact frame for exactly `frames` (not listed in `recordings`); node sources play through a silent `GraphNode::CaptureTap` player.
- Graph documents: `Sample`, `Sample::Slices`, `Sampler::Instrument` record `play`/`sampler`/`node`/`chop`; values print through `lineage` (views and `with` changes); origins print as `Sample["assets/x.flac"]` in bundles (`GraphIO::Assets#sample`, the audio and tags), `Sample["/path"]` for files outside bundles; slices' keymaps print as `.keymap(...)`, SFZ instruments as `sfz(path)`.  Not yet: instruments built region by region (FIXME), SFZ folders copied into bundles, bounces printed as `bounce(...)` recipes (they save as audio).
- Measured per voice (one channel, 4 s of a 4 s noise sample, frequency input, Ruby input nodes included; AMD 7950X, alternating not needed for a new feature): optimal interpolation 59 / 29 ns per sample at 128 / 800-sample buffers (0.28% / 0.14% of realtime); worst case, a retrigger every 64 samples so the declick tail always plays, 83 / 49 ns (0.40% / 0.24%); with `:sinc` 250 / 218 ns (1.2% / 1.05%).  A 3 s mono sample's levels: 0.28 s to build, 7.9 MB (built once per audio and level spacing, shared by slices and voices).
- Demo conversions: `bin/synths/jungle.rb`'s breaks (the persona's KeyMap sampler) is a bounced Sample, `.jungle_slices_of` (12 bits, 32 sixteenths on the record's tempo grid, named) and a `Sampler::Instrument` of the same zones (residual against the old patch -42 to -60 dB: declick tails, fade shape, band-limiting across slice edges); `presets/jungle_breaks.mbg` holds one 12-bit record asset.  Bundles save edits that make new audio (`Sample::EDITS`) as assets, views through their lineage; block-built instruments print as `Sampler::Instrument.new { |i| i.region(...) }`.

## Follow-ups (sampler-2, 2026-10-13)

From the maintainer's Bench verdicts on sampler-1:
- **Lofi reads** ("drop-sample, no levels" for dirty lofi): `lofi` presets return Samples read with interpolation `:none` and no band-limited levels (`Sample#interpolation`/`#mips`, nil = the voice's own); `lofi(:x, read: :clean)` and `Sample#read_as(:clean | :drop, interpolation:, mips:)` (a view) say otherwise; custom `lofi(rate:, bits:)` and `bits` keep the sample's read.  Views and later edits keep it; FLAC tags save it (bundle assets keep it).  Voices' `interpolation:`/`mips:` default to nil: each region reads as its sample says (else `:optimal` and the instrument's mips); given explicitly they apply to every region.  `fast_sampler` has a `REGION_INTERP` column (a code, or -1 for config's), so one instrument mixes drop-sample and clean regions; a sinc region needs config's sinc kernel.  The clean default stays for plain playback.
- **Converters** (verdict "mpc60"; the song "no converter"): the help topic says which suits what (mpc60 cleanest, s950 darker, sp1200 dirtiest; a whole song often wants none).
- **Stretch fit** (question "does autocorrelation guide the cycle time or cycle fudging?"): sampler-1's `stretch` used neither: output cycle k (exactly `cycle` samples) played the input from round(k × cycle / ratio), cut wherever that fell (hard cuts unless `crossfade:`).  `fit: :auto` (`Sample::Lofi.fit_plan`, offline in Ruby + Pocketfft) plans the cycles from the channels' mix: each cycle's length is the lag near `cycle` (±25%) with the highest normalized autocorrelation when it reaches 0.7 (a whole number of local periods), its end moved to the nearest rising zero crossing within 0.5 ms; the next cycle starts where the input best matches (normalized cross-correlation over half a cycle, ≥ 0.3) what would have followed that end, within ±25% of a cycle of output time / ratio (so the output keeps time; the last cycles stay inside the input), then at the nearest rising zero crossing.  Measured on the Bench sources (2× at 30 ms): seam error (RMS over 8 samples of continuing vs spliced, / signal RMS) fixed → auto: pad 0.77 → 0.44, Reese 0.97 → 0.08, formant voice 0.91 → 0.09, break 0.51 → 0.39; planning 0.03-0.08 s per 1.4-2.9 s of audio.

## Follow-ups (sampler-3, 2026-10-13)

From the maintainer's Bench verdicts on sampler-2:
- **Per-preset reads** (verdict "mpc60, clean read"; the earlier "drop-sample, no levels" was for dirty lofi): `Lofi::PRESET_READS` says how each preset reads unless `read:` says otherwise: `:mpc60` (the cleanest converter) reads clean, `:s950` and `:sp1200` keep the drop-sample read.  Saved bundles keep their reads (lofi audio saves as an asset with its read in the FLAC tags); a document that recorded `lofi(:mpc60)` without an asset would now read clean.
- **Stretch `fit: :auto` is the default** (3 of 4 verdicts; the fourth, bass, preferred sampler-1's fixed cycles but noted "the fixed version tunes lower").  `fit: :fixed` is the plain cyclic stretch (`nil`/`false` mean :fixed, as `nil` did before).  Measured on the Bench renders (YIN median over 100 ms frames of the steady middle, and the peaks of averaged 0.5 s Hann spectra; the scratch script is with the sampler-3 Bench renders, `tmp/listening/sampler-3/pitch.rb`): the Reese bass (A1, 55.0 Hz) stretched 2x with 30 ms fixed cycles has its strongest partials at 60.8, 121.7, 182.5 Hz (a 60.8 Hz series, +1.76 semitones) interleaved with 27.5, 88.3, 149.2, 210 Hz (that series minus 33.3 Hz) only 6-12 dB down; YIN finds a periodicity of 30.2 Hz, about an octave below.  `fit: :auto` and auto-hard measured 55.0 Hz with no partials below 45 Hz.  Why: cycle k plays the input from k × cycle / ratio, so each cycle starts the input's harmonic h × f0 at a phase h × f0 × cycle / ratio further on; the output's partials sit at h × f0 / ratio + m / cycle (a 33.3 Hz comb offset by 27.5 Hz here), the strongest within 1 / (2 cycle) = 16.7 Hz of h × f0.  For a bass that is up to 5 semitones away and the companion partials make a residue pitch near f0 / ratio and 1 / cycle: the bass sounds lower.  Higher notes keep their pitch on average (the vocal at 165 Hz split into 148.3 and 181.7 Hz partials of equal strength: rough, not lower).  Fitted cycles are whole periods, so the comb lines land on the harmonics.  So :auto stays the default for basses too; :fixed remains for the stutter on breaks and the metallic buzz.

## SoundFont 2 (sf2-1, 2026-10-16)

Maintainer, 2026-10-16: "Start sf2 import" (SFZ import existed; an SF2 exporter is planned in the on-hold export-1 brief, so the mapping below is meant to be its mirror).

API: `font = sf2('GM.sf2')` is a `Sampler::SF2::Font` (`font.presets` lists `bank:program name`, `font[0]`, `font['Pad']`, `font[128, 0]`, `font.play(v)` plays the first preset); `sf2(path, 0)` / `sf2(path, preset: [128, 0] | 'Strings', name:, mips: :octave, attenuation: 0.4, wheel: true)` is the `Sampler::Instrument` (alias `soundfont`).  Instruments print as `sf2(path, preset: ...)`; documents read fonts relative to themselves (`Registry::FILE_METHODS`, `KEEP_NAME`), and bundles copy `.sf2` files as assets (`Assets::EXTENSIONS`).

Reading (`lib/mb/sound/sampler/sf2.rb`, pure Ruby): the RIFF `sfbk` form's INFO texts and the `pdta` hydra when opened (GeneralUser GS 2.0.3, 30 MB, 287 presets: 0.03 s); `smpl` (and `sm24`, one byte per sample, else ignored) only for the samples a chosen preset plays, with `pread`.  Fonts are cached by file (WeakRef) and so are their samples and built instruments, so presets sharing samples share playback tables.  Robust to missing terminal records (EOP/EOI/EOS detected by name or shape, so a file without them keeps its last record), truncated files and odd chunk sizes (lengths clamped to the file), ROM and SF3 (compressed) samples (skipped and listed).  Samples keep their own rate (the kernel resamples); `Sample#save` now tags rates other than 48 kHz and `Sample[]` reads such files back at that rate, so bundle assets keep their positions.

Zones (`Font#zones`): the instrument's global zone (a first zone without sampleID) under each local zone, preset generators (global, then local) added to the instrument's, except key and velocity ranges (intersected) and the instrument-only generators (offsets, sampleModes, exclusiveClass, overridingRootKey, keynum, velocity: ignored at the preset level), as the specification says (sections 8.5, 9.4).

| keyRange, velRange | region keys:, vel: |
| overridingRootKey, else the sample's original pitch (255: C4) | root: |

Per-zone settings: values that differ from zone to zone (or key to key, with keynum scaling) are `Sampler::ZoneMap`s (first zone holding the key and velocity; prints as `Sampler::ZoneMap.new([[keys, vels, value], ...])`), and `Instrument#play` makes a `GraphNode::ZoneValue` of each for the voice, reading the Notes' number and velocity rounded like the kernel's region choice, so each note gets its own zone's envelope, filter, and modulation with one voice per layer.  ZoneValue looks the value up once when the number and velocity hold for the buffer (first/last plus `ptp`: 1.2 µs per 128 samples, `minmax` was 3.2).  Uniform values stay plain numbers, so the envelope kernel keeps its constant runs.  Layers share modulation sources and sums with the same settings (one vibrato LFO per note).

`Instrument` grew for this, generically: region `pan:`, envelope Hashes (Notes#env options), `filter:`, `modulation:` (named env/LFO sources summed into pitch and cutoff cents and volume centibels), and `Instrument.layered`; the RubyWriter prints all of them region by region, so an SF2 instrument without its recipe still round trips through a bundle (spec: within 1e-4 with 24-bit assets).

## Choke groups and SF2 exclusive classes (sf2-chokes, 2026-10-16)

The SoundFont 2.04 specification (section 8.1.2, generator 57 exclusiveClass): when a note starts in a zone with a nonzero class, every other sounding note of the same preset with that class ends "as fast as possible" (FluidSynth kills them with a very short release, per channel).  GM kits use it for the hats (GeneralUser GS Standard: closed F#2, pedal G#2, open A#2 in class 1), so before this the open hat rang under the next closed hats.

- **Generic, in Instrument regions**: `i.region(s, choke: :hat)` (a Symbol or Integer; 0/nil none) is the SF2 class: the region's note-ons belong to the group and the group's note-ons cut it.  `group:` and `off_by:` set the two halves separately (SFZ's `group=`/`off_by=`, which `sfz()` now reads; 0 is none, `off_mode` is always fast).  An SF2 zone's class becomes `choke: class` (pairs take the left zone's).  The RubyWriter prints them, so bundles round trip.
- **Where the choke happens: the allocator.**  A choke is a cross-voice event (one lane's note-on ends another lane's note), and Synth lanes only see their own notes, so the decision belongs in `MIDI::Allocator`, which already sends `:choke` events when it steals a voice.  `Instrument#play`, given a Synth lane's Notes and an instrument with groups, registers its `Sampler::ChokeMap` with the lane's allocator (`Allocator#add_chokes`; equal maps once, so 14 lanes register one).  On each note-on, before allocating it, every active lane (sounding or released) on the same channel whose note is cut by a group the note-on starts gets a `:choke` at the note-on's time.  The ChokeMap looks up groups from every region holding the key and velocity (all layers; round robins too), rounded like the kernel's region choice; keys mixing groups across round robins or split-keyboard notes aren't distinguished.  Mono allocators ignore groups.  Without an allocator (a Notes from a clip, `trigger:`/`number:`) nothing chokes.
- **Release: Envelope::CHOKE_TIME (3 ms, 144 samples at 48 kHz), from the exact note-on sample**, the same as drum kit chokes (`Drums::ChokeGate`, Envelope's choke): the lane's envelopes (volume and modulation) release through Notes#choke as for a stolen voice, the choked lane is free again after the choke time (the new note usually takes a free lane; with every voice busy the usual steal chain applies), and it's exact at any buffer size because the events are.
- **SamplerVoice choke input** (`fast_sampler`, mirror `KernelRuby`): voices of instruments with groups read Notes#choke; at a choke sample without a note-on the voice stops CHOKE_TIME later, silently under an envelope (so one-shot lanes, kept busy by `Notes#register`, fall idle instead of playing the rest of a 2 s open hat at zero gain), and with a ChokeGate-identical linear fade for instruments without an envelope.  A note-on cancels a pending choke (a note-on on a choke's sample wins); a choke while choking changes nothing.  Instruments without groups don't read the input (no cost; behavior on voice steals is unchanged for them).
- Note that closed hats in one class also cut each other (16th-note closed hats get shorter tails), as in FluidSynth.

Measured (i9-9880H container, 12-voice synth, 8 s, alternating runs; "before" stubs `Instrument#choke_map` to nil, master-ai's behavior): GeneralUser GS Standard kit with disco hats (open hat on every off-beat, cut by the next closed hat) 8433/8351 → 4559/4538 ns per sample at 800-sample buffers and 40757/41710 → 23563/23658 at 128: chokes save ~45%, since a choked one-shot lane stops and sleeps instead of playing out a long open hat at zero gain.  A preset without classes (the GM piano) runs the same code either way (no choke map, no choke input; the allocator checks one nil per note-on): 4635-4647 vs 4678-4697 at 800 (within 1%, not attributable), 21298/21322 vs 21249/21445 at 128.  Renders: `/app/tmp/listening/sf2-chokes/` (Bench set `sf2-chokes-2026-10-16`).

Open: whether `choke:` should also take an Array (a region in several groups), and an `off_mode: :normal` equivalent (release through the envelope's own release instead of 3 ms).

## Sleeping layers: Synth sub-lanes (synth-sublanes-1, 2026-10-16)

Open item (A) of sf2-1: a layer with no region for the note should sleep and wake on the exact note-on sample.  Built as `GraphNode::SubLane` (generic, Synth-owned; mechanism in `midi.md`, Sub-lanes): `Instrument#play` in a Synth lane wraps each narrow layer of a layered instrument in a sub-lane that sleeps after a silent grid cell with its envelopes and sampler voices idle and wakes on the exact sample of a note it plays (`Instrument#wake_check`: note-ons with a region for the key and velocity, velocities one step wider for the trigger's float rounding; every note-on of keys with sequential round robins, which count every note of their key; every note-on with random round robins (one draw per note-on) or a split; note-offs too in mono lanes, where releasing a note can return the lane to an older held one).  The same samples as rendering every layer (bit for bit, at any buffer size; the sampler voice is idle and its draws and counters unchanged by the notes it sleeps through, the masked envelope idle, the filter flushed to zero before the cell counts as silent).

- Narrow layers only (`Instrument::SUB_LANE_COVERAGE`, 0.5 of keys 21..108 by velocities 1..127, `Instrument#coverage_share`): a sub-lane splits the voice's plan regions (its outputs are a boundary), which at 128-sample buffers cost more than layers that seldom sleep save.  GeneralUser GS: piano layers 1.0 / 0.05, Tine EP 1.0 / 0.03, Full Orchestra 0.90 / 0.97 / 0.79 / 0.16 / 0.11, Standard kit 0.69 / 0.11 / 0.0; strings, choir, brass 1.0 / 1.0.
- Layer envelopes (masked by coverage) read the voice's shared gate/trigger/velocity/choke nodes instead of an EnvelopeInputs of their own (same samples), and layers in sub-lanes read zone values through a per-layer `ZoneValue::Index`, so a sleeping layer only reads Tee branches (its trigger, number, pitch, pitch mark, GM time controllers, number/velocity for its index: about 2.6 us per 128-sample buffer per voice, plus its wake check 1.5 us and clock 0.5 us).
- Found on the way (master-ai bugs): Full Orchestra in a 6-voice synth raised "ZoneValue::Index ... readers out of step" once an idle lane was skipped (its LFO's FadeIn read its delay ZoneValue while the Index's other values paused; `ZoneValue.separate`); plan lane groups over 64 members raised in `FastPlan.run_lanes` (`plan_layer.md`).

What an awake sub-lane costs: its output is a plan boundary, so the layer's filter chain is a region of its own instead of part of the voice's mix region (~15 us per 128-sample buffer per voice for a stereo layer), plus the sub-lane's bookkeeping (~5 us).  Fixed on the way: the first version split every buffer crossing a grid point while a looping sample played a stretch of exact zeros (a sleep candidate), which took the voice's Tees out of lockstep: +31% at 128 (`SamplerVoice#sustaining?` now skips those splits).  Measured and dropped: a sub-lane around the sampler voices only (no region split; worst +2-10%, typical gains 0-5%), and around voices and envelope with the filter outside (its region still split; worst +30%).  A plan rebuild per state change is out (5.5 ms per lane).  Parity would need the plan layer to skip a sleeping layer's ops inside a fused region (a C and feed change), or cheaper region boundaries.  A sleeping layer costs ~4.6 us per 128-sample buffer per voice (Tee branch reads, wake check, clock).

## Steal fade (synth-sublanes-1, 2026-10-16; on by default since defaults-1)

Maintainer 2026-10-16: "Make an A/B first."  When a synth runs out of voices the allocator chokes the oldest lane and gives the new note a spare; enveloped voices fade through their envelope's choke (3 ms), but a sampler voice without an envelope (slices, plain samples, `.sampler(sample)`) rang on under the new notes until its sample ended (only voices of instruments with choke groups read the choke).  `inst.play(v, steal_fade: true)` (and `.sampler(..., steal_fade: true)`, `Sample#play`, `Slices#play`/`#sampler`) reads `Notes#choke` and fades the voice linearly over `Envelope::CHOKE_TIME` from the exact choke sample (the group-choke fade); `steal_fade: 10.ms` sets the time (for that voice's group chokes too; `SamplerVoice` `choke_time:`).  With an envelope the steal itself sounds the same (the envelope fades the voice either way), but the voice also stops, so a later note on that lane starts without the old note's 64-sample declick tail under its attack (GM piano riff on 3 voices: max difference 0.074 at a peak of 0.55; the GM Standard kit: none) and stolen voices cost no CPU (that piano render took 1.3 s instead of 2.4).  Existing uses don't steal envelope-less voices: chop clips play on one mono voice (`clip.sampler(brk)`; a new hit truncates the last through the 64-sample declick), and the demo songs' sampler voices have envelopes; the A/B renders (`/app/tmp/listening/steal-fade/`, Bench set `steal-fade-2026-10-16`) use a break in quarter-note slices hit every 16th on 2 voices (59 steals in 4 bars), a bounced one-shot saw stab as triads on 3 voices (12), the help topic's looped bass as 3-note chords on 2 voices (16), and the GM piano riff above (31).

Verdict (Listening Bench, 2026-10-16): "after" on the chopped break, the one-shot stab chords, and the looped bass, "same" on the enveloped GM piano, so defaults-1 made `steal_fade` on by default (`Instrument#play`, and through it `Sample#play`, `Slices#play`/`#sampler`, `Instrument#sampler`, `clip.sampler`, SFZ/SF2 instruments); `steal_fade: false` is the old behavior (stolen envelope-less voices ring on), and a length still sets the fade time.  Recipes print only what was given, so documents of graphs using the default don't mention it and `steal_fade: false` round-trips (`sampler_graph_io_spec.rb`).  One-voice chops (`clip.sampler(brk)`) are unchanged (a new hit retriggers the one lane, through the 64-sample declick, rather than stealing), and so is any synth whose notes end before it runs out of lanes (released lanes are reused, not stolen); checked with 8 overlapping held hits: 1 voice identical, 2 and 3 voices different.
