# Sound-design screen (`ui :sound`)

<!-- summary -->
`ui :sound` (or `design :bass`) is the tiled screen for designing a track's sound: the patch inspector (`Panes::Inspector`: the voice in SOURCE FILTER AMP MOD FX sections, knobs turned with arrows, Enter types a value), the node's preview (`Plot::Panels`), the graph's code, and the RENDER pane (`UI::PatchRender`: a second copy of one voice, reset to its post-build snapshot and played one note in windows after the live render thread's buffers, showing a settled cycle, spectrum, and envelope), and the library picker (`Panes::Picker`, NAV l: find as you type, a auditions, Enter loads an entry into the inspected track at its launch point).  A new track starts from the init voice (`preset :init`, `bin/synths/init_voice.rb`); live literals (`bind`) and build knobs rebuild a track's patch at its launch point.
<!-- /summary -->

The tiled screen for designing sounds (sound-design-ui-1, 2026-10-26): the maintainer's first priority for the sound-design UI, "Do 4 and 1" of the options offered: (4) a design pass first, a mock-up of the screen as static captures to react to, then (1) a patch inspector pane: pick a track or node, see its parameters as knobs (live values, ranges, units, curves from Param records), with the filter/shaper preview, turned with arrow keys or MIDI (journaled, undoable), the code updating beside it.  First version turns only what is already a knob; live rebuilds of literals come later.  The library index and its picker are being built in parallel (library-core-1): this screen shows where the picker goes, and the inspector doesn't need it.

Design inputs: the library design draft (workbench `research/library-design/design-draft.md` and STATE.md: picker with find-as-you-type, Enter doing the likely action named on the status line, a shortcut per action, auditions on CUE only, a side panel, save key flow, A/B, dirty state, favourites; morph/randomize later), terminal_ui.md (tiles, panes as Ruby kinds, layouts as data, pane modes, the command bus), params.md (the Param record), racks.md (the inspection protocol: `param_info`, `param_snapshot`, `Plot::Panels.preview`).

Mock-up captures (with a real patch: `preset :dnb_reese` on a track with its cutoff on a knob, and a pad reading the same knob) at 120x40 and 236x80, with a value prompt and a second track: `/app/tmp/sound_design_mockup/` (made by its `make_captures.rb`, which also lists the open questions in its README).

## Using it

```ruby
knob :cut, 2400.hz, range: 150.hz..8000.hz
track(:bass) { |clip| preset :dnb_reese, midi: clip, cutoff: :cut }
bg :bass, riff
ui :sound            # then NAV d (or Ctrl-W d): into the inspector
```

In the inspector (since sound-design-nav-1 in sections: Sections below): s f a o x jump to SOURCE FILTER AMP MOD FX, Up/Down pick a param of the picked row (or a knob no row shows), Left/Right turn it (Shift or H/L fine; a held key is a live sweep you hear and one `turn :cut, 0 => ..., 1.n8 => ...` line when you let go), Enter types a value (`turn :cut, ` on the prompt line: `3000.hz`, `0.3`) or, on a param no knob drives, offers its `bind` line (Live literals below), 0 the default, m learns a MIDI controller (`learn :cut`: turn one), t/T the next/previous track, n/N (or ] [) the next/previous row (its preview and params), p every node as chips, P the panel, v V a kit's voices.  Every change is a console line through `UI.run_line`, printed in the REPL pane: journaled, undoable, in the take.  NAV c goes into the code pane (arrows scroll, y copies).

## How it works

- **Data** (`UI::Inspect`, `lib/mb/sound/ui/inspect.rb`): `Poll#call(needs)` gathers an `InspectInfo` into `Slow#inspector` only while a visible pane needs `:inspect` (`Follow` passes the feed's needs).  Graphs come from `Session#ui_graphs` (each current player's GraphNodeInput, under the players' mutex only, never the render lock); roots climb through Tees and from a multi-output node's outputs to the node with the recipe (a Synth's outputs to the Synth, whose `to_ruby` prints the whole synth).  Nodes are read with `Traversable#param_info`/`#param_snapshot` (settings only, never sampling; nodes with their own parameter API, like ChannelMixer's Unison, get a Params from `param_info`).  The node list, the knob names the graph reads (Knob readers in its graph, in order), and the code are cached per graph (by the roots' identity); each poll takes only the selected node's snapshot again, so its preview follows turns.  A node's knobs include those read through a few nodes of arithmetic (`lp4(knob(:cut) * lfo)` reads :cut).  Plumbing (Constants, Knobs and readers, Tees, Multipliers, Mixers, ProcNodes, note frequencies, synth outputs) is never listed.  `Inspect.target` (`{ track:, node: }`, set by the inspector's keys) is what the panes ask for; without one the inspector follows the clip matrix's track (`Clips.selected`), else the first player.  Measured on the Mac container (dnb_reese, 173 nodes): the first gather of a graph ~6-12 ms, cached polls ~0.4 ms.
- **Knob values** are the snapshot's (`Snapshot#knobs`, per buffer), so meters move with turns, follows, and MIDI.
- **Turning**: `UI::KnobTurns` (`ui/knob_turns.rb`), the racks pane's turning moved into a module both panes include: PaneKeys::Preview steps through `Session#preview_turn` while a key is held, one PaneKeys::Commit (`Session#gesture_line`) when it stops (TurnGesture), PaneKeys::Run `turn` lines for set values; a turn moves by 2% (0.2% fine) of the knob's position along its curve (`Spec#position`/`#value`: a cutoff moves evenly in pitch), stepped knobs (Integer ranges) by one step.
- **Typed values**: a key may return `PaneKeys::Ask[prompt, text, answer]`: the tiles open a prompt line (the palette's line editor, Router `:line`, returning to the pane's mode), and Enter hands the text to the pane's `key_<answer>(state, text)`, whose result is handled like a key's (the inspector's is a `turn :cut, <text>` line); Esc cancels.

## The render pane (sound-design-ui-2)

The maintainer, after the mock-up captures (2026-10-26): "a one-shot render of the processed waveform updated periodically when parameters change".  Three rounds:

- Round 1 rendered 3 s of the track's clip through its whole patch (Synth, clip, sandbox Session) on a worker thread; held: the live render thread's lag went from p99 0.7 ms to ~10 ms in a held sweep (builds were ~100 ms of Ruby holding the GVL).
- Round 2 rendered one note for 0.5 s in forked processes (one render server per patch, a forked copy per render); the lag came back to the no-render numbers.
- Round 3 (2026-10-27), his redesign: "I'm expecting that I will build up a patch from nodes. I had no problem with realtime rendering a waveform+filter for one cycle in the fft_experiment by just keeping two copies and calling sample one time on the second copy"; "one can reset every oscillator and filter in the copy, grab a bunch of cycles, and find the Nth cycle where N is long enough for the filter to be at steady state.  Maybe show a few cycles and/or adjust to zero crossings when using unison"; "The second copy can also run at a much lower sample rate for display, as long as it's not too close to filter frequency response warping territory".  What is built now, replacing the forks and the sandbox render:

`Panes::Render` (`render`, jump w; the right column between the code and the keys, weight 2, at least 8 rows):

- **The copy** (`UI::PatchRender::Copy`): one voice of the inspected graph's Synth, built by calling the live `Synth#voice_block` again (lane 0's index and seed, `Synth.with_lane`, so `per_voice` values and seeds match lane 0) with a `Notes` reading a `NoteFeed` (a MIDI::Source the render plays notes into).  Not a Synth, no clip, never in a Session's render.  `knob(:x)` inside the block resolves through a scope Session that is never rendered: it only holds copies of the session's knobs (at the copy's rate) and the tempo, meter, key, and tuning for build-time lengths; readers of live knobs that the block captured (a document param bound to a knob is resolved when the preset loads) are rebound to the copy's knob of that name, and a copy that still shares any node with the live graph is refused.  Plans are installed on it.  It is rebuilt only when the voice block, the note, or the session settings change (Job#copy_key); a knob turn sets the copy's knobs (exact jumps) and renders again.  The copy is built on the worker under `Internal.with_private_rng` (the voice block draws seeds; the shared generator would race scene builds) and `Internal.strictly`.
- **Reset**: one block of silence after the build (so every oscillator has made its state), then a snapshot of every node's `plan_snapshot` and of the note streams' state; each render puts them back (`plan_restore`, the feed and streams rewound to that stream time), so every render starts from the same state: the same knobs give the same samples.  Knobs and their readers keep counting forward (the values set before a render land on the next frame they read).
- **The cycle view** (`PatchRender.cycle`): the note held, sampled a few periods at a time; a period has settled once it differs from the one before by less than -40 dB after both are scaled to the same RMS (the next period read a fractional period later, linearly interpolated; slow envelopes don't count as change).  The view is that period from the first rising zero crossing of the channels' mix after it, plus a period's worth of samples to stop.  A note whose periods never repeat within 0.4 s (detuned unison copies, a moving LFO) shows 4 periods from a rising zero crossing at 0.4 s.  The settled sound's second half gives the spectrum.
- **The envelope view**: the copy reset again and the note played for `PatchRender.seconds` (0.5 s), held for the clip note's length or the role's share; min/max over 1024 columns; LUFS (measured a tenth of a second at a time), peak, RMS.
- **Input** (`PatchRender.input`): the clip's first note (number, velocity, length), else a guess from `ROLES` matched on the track's name and its graph's code: kick C2, drums D2, bass A1, pad C3 (the maintainer, 2026-10-27: "pad C3 to start probably"), pluck/keys C4, lead G4, else C3.
- **Rate** (`PatchRender.rate_for`): the lowest of 24, 32, 48 kHz at least 8 times every lowpass cutoff in the copy (four-pole, diode, lowpass SVFs; a cutoff that moves, an LFO or envelope on it, keeps 48 kHz, as does a voice with no lowpass or one that can't change rate).  Measured against the same copy at 48 kHz (a saw through lp4, and 16 detuned saws through lp4), drawn as the pane draws (each column's min and max): at 88 columns the cycle differs only by an edge landing one column over (0.0-0.9% of the peak once a column's shift is allowed; 6-24% without); at 472 columns 0.0-4.7% (a Braille dot of 8 rows is 6.2%).  12 and 16 kHz rounded the saw's edge visibly at 472 columns (12-23% beyond a column's shift), so the lowest rate is 24 kHz.  RMS within 0.03 dB, peak within 0.16 dB.  dnb_reese stays at 48 kHz (its cutoff has an LFO).
- **Views**: s cycles all that fit (the cycle above the spectrum above the envelope, 5 rows each at least; the cycle beside the spectrum in a wide, short pane; the cycle alone in a small one), the cycle, the envelope, the spectrum.  The first row: track, LUFS, peak, RMS, what played, "settled 18 ms" or "4 cycles", the copy's rate, the render's time.
- **When** (`PatchRender::Debounce`, a state machine with a transition table: idle, waiting, busy, dirty): 0.1 s after the last change (the track, the voice block, the input, the length, the values of the knobs the voice reads), at most every 0.2 s while changes keep coming, at once when nothing is shown for the track.  A render of a track no longer inspected is dropped; the overlay is only ever the same track's.
- **Where**: in this process, `PatchRender::Worker` (one thread per pane placement, priority -3, ending after 10 s idle and dropping its copies), in 256-frame blocks and short analysis steps, each followed by `.rest`.  Round 4 (below): the worker works only in windows right after the live render thread finishes a buffer.  `PatchRender.inline` (UI specs, captures) renders on the drawing thread.

### Round 4: trim (2026-10-27)

The maintainer: merge once the live render thread's lag in a held sweep is at the no-preview numbers ("Trim first"); post-synth effects needn't be in the plot ("only per-voice effects"), so the one-voice copy is the right scope.

- **Work windows** (`.slack`, `.rest`): `Session#frames_rendered` (new, a lock-free reader) reaches the copy through `Source#frames`.  The worker waits for it to change (the render thread just finished a buffer and is about to wait on its output), then works for `WINDOW_SHARE` (0.35) of the time between buffers (measured from two buffer ends seen one after the other; 0.4-4 ms), then waits for the next buffer: one sleep most of the way, then 0.5 ms looks.  Every render starts with a wait, so nothing it does lands on the render thread's turn.  This was the change that mattered: the time the render thread spent late was in waking from its pacing sleep, not in rendering, and only while a render's first steps (before any pause) or its windows ran into the render thread's wake.  Neither window size (0.1 against 0.35) nor GC timing changed the lag once every step was in a window.
- **Builds**: in steps with a window between them (the scope, the voice block's call, rebinding and checks, the rate change, `Plan.install`, the prime and snapshots).  The voice block's call is still one stretch (6-9 ms for dnb_reese when warm), started at a window's beginning.  The scope Session is kept by the Worker for the next copy while the settings and knob specs stay (a Session took 5-30 ms to make), the rate comes from the live voice's lane graph (no 48 kHz build to read cutoffs from), and the last `COPIES` (4) copies are kept: switching back to a track or note just previewed doesn't build again, and drops no copy into the old generation.  A rate band change (a knob moving a lowpass cutoff across 3/4 kHz) makes a new copy.
- **One render a note**: the note plays once, held for the clip note's length or the role's share; the cycle comes from its held part, the envelope view and figures from the first `seconds`, the spectrum from the held part after the cycle.  (Round 3 played it twice.)
- **Allocations** (objects per update, dnb_reese / a lp4 saw / 16 detuned saws): 16.7k / 6.1k / 15.0k before, 2.8k / 1.5k / 3.1k after.  Buffers kept per copy (`Copy#work`) and copied into without views (`FastArithmetic.copy_range`); `NoteFeed#read_events` returns one frozen empty Array between notes; the settle scan compares every period at once in matrices, 64 points a period, in 4096-sample pieces; the spectrum keeps its window, band index matrix (one `max(axis: 1)` for 256 bands), and buffers, averaging the last 3 windows of 2048; loudness is BS.1770 on kept K-weighting filters working in place, block energies from slices (the same LUFS as `Loudness::Analyzer` to 1e-3, which made a few hundred objects a call).  The graph itself makes ~1 object a block.  With malloc churn down, the major collections (`:oldmalloc`) during a sweep went away.
- **Cost per update** (YJIT): dnb_reese 44 → 12 ms, the lp4 saw 4.6 → 2.6 ms, 16 detuned saws 18.5 → 6.5 ms.

## The envelope preview (envelope-view-1, 2026-10-27)

The maintainer (2026-10-26): "I think we will need a visual envelope display and possibly editor as well"; picked "Display + live literals" (the editor later).  Display ideas from his private visualizers (workbench `research/library-design/STATE.md`; ideas only, never their code): a copy rendered at a low rate, the sustain a fixed share of the plot, a playhead while a note plays, breakpoint labels in real units, a velocity-scaled trace, an adaptive time grid with its step.

- **Data** (`Envelope::Preview`, `lib/mb/sound/envelope_preview.rb`): `#param_info` lists every segment time in seconds (`unit: 's'`; a knob's value and name; a Notes envelope's time before GM2 scaling, so `v.amp_env(knob(:att), ...)` shows `attack → knob att`) and the levels that aren't fixed (`:sustain`, or `:t1_level`, ... for multi-segment envelopes), then the node inputs; `#preview_data` the settings as plain values (times, levels, curves, shapes, release and loop nodes, gated or the hold, velocity range, octave depth, hold_last; nil where a node gives a value whose current value isn't known); `#playhead_state` where a note is, from the state the render thread writes (plans keep it in the node, fused or not).
- **Drawing** (`Plot::Panels::EnvelopeView`, registered for `MB::Sound::Envelope`): a copy (`Envelope.new(segments: ...)` from the data, velocity off, gated by `Envelope::PreviewGate`) renders one note at a rate chosen for 2048 points (at most 48 kHz); gated envelopes hold the sustain for 35% of the plot (`SUSTAIN_SHARE` of attack + decay + sustain + release), gateless ones release after their hold; 4% of room after the release.  Dashed rules at the breakpoints; the title names them (`A 20ms D 300ms S -4.4dB R 500ms`; `t1 10ms→1 t2 200ms→0.3 | t3 500ms→0 loop t1`; `~` for node times and levels, drawn as 0.1 s and 0.5; `×2^(2.0 oct)` for filter envelopes, whose level is drawn); the time axis (`Scale::Time` `divisions: 5`: ticks every nice step for about 5 divisions at any size) says its span and step (`1.19s 200ms/div`, shown when it fits a third of the width: from about 48 columns).  Traces are kept for the last 8 preview data, so a moving playhead rebuilds only the chart.  Matches the envelope at 48 kHz within 0.05 at every copy sample (spec).
- **Live** (`Panels.preview(..., live:)`, passed to registered blocks taking a third argument): `Inspect::Gatherer` gives the selected node's `NodeInfo#live`, the newest sounding note of the envelope's copies (synth lanes: smallest samples since the note started) as `{ stage:, segment:, position: (seconds), peak:, at: (monotonic) }`, and keeps the last note's peak after it ends (`{ stage: :idle, peak: }`).  The playhead is the segment's start plus its position, held at the sustain point while the key is down and at the release's end after it; the preview pane adds the seconds since the poll while a segment runs (`Preview.clock`), in 1/240 s steps (`PLAYHEAD_STEP`), and is a live pane (`Preview#priority` :live: `ui.target_fps`, slowing under load like the meters) while the node has a playhead, else a list pane at 8/s (omnibus15; the maintainer: "can it reach 60+ like other parts of the UI?"; measured per frame with YJIT: chart 0.18 ms, `Plot::Live#draw` 0.27 ms at 48x10 and 0.34 ms at 100x20, so the chart is rebuilt rather than cached with only the playhead moving).  A peak other than 1 (velocity) adds a second trace, the levels times the peak, and `pk -3.1dB` in the title.
- Copies of one envelope group by preview data too (an amp and a filter envelope whose times are GM nodes had the same param values: nil); `Notes::NoteEnvelope::GmTime` is plumbing.
- Captures: `spec/lib/mb/sound/ui/golden/tiles_sound_envelope_{80x24,120x40,236x80}.txt` (the fake bass's amp envelope with a note in its decay at peak 0.7).

## Live literals (envelope-view-1)

Mock-up question 3: turning a number that no knob drives.  `bind :bass, lp4: :resonance` (console `ArrangementMethods#bind`, `Arrangement#bind_literal`, `Arrangement::LiteralBinding`):

- **Naming a literal**: tracks build their patches inside `Recipe.counting` (`Arrangement.counted` wraps the block, keeping its arity, parameters, and source location), so every recorded call has an ordinal in its scope (`Call#ordinal`: build block invocations count their own calls, the counting block the top level), and `Recipe.key_of(call)` names it by where it was made, `[:top, :synth, 0, :lp4, 0]`, the same in every synth lane and when the patch builds again.  The line names the call by method and `nth:` (which of the patch's calls of that method, ordered by `Call#seq`, so any root gives the same order), so takes replay it.
- **The argument**: a keyword of the param's name, else the positional parameter of that name in the DSL method (`Notes#amp_env(attack, decay, sustain, release)`), past the recorders.  Literals are numbers, pitches (`1200.hz`, bound in Hz), and fixed lengths; Durations (tempo lengths) and nodes are refused with the reason.  A graph document's param (a Constant named after a param of the root's `GraphIO::Document`, e.g. `preset :dnb_reese`'s `cutoff`) is `bind :bass, :cutoff`, given to the preset as `cutoff: :"bass/cutoff"` (`LiteralBinding.with_documents`, read by `preset`).
- **The knob**: `:"bass/reso"` (`as:` names it; the Param names table's short alias: resonance → reso, frequency → freq, quality → q), `(lo..hi).at(value)` from the names table (typed: seconds for times, Hz for pitches) widened to hold the value, else 0..4× the value; `range:` overrides.  An existing knob of that name is reused only at the literal's value.
- **The rebuild**: a test build first, with a stand-in knob (a Constant for document params, since `preset` would adopt a Knob into the session): the patch must build and read it (a setting read once while building can't follow a knob), else nothing changes.  Count-like Integer literals (`LiteralBinding::COUNT_NAMES`: voices, copies, taps, ...; names-table entries with Integer ranges) are shown read-only, with the reason on the status line and no bind offered (the maintainer, 2026-10-27: "Show read-only").  Then the track's patch becomes a wrapper (`LiteralBinding.wrap`: `Recipe.substituting` gives the call `knob(:"bass/reso")`, read through `Session.current`, so rehearsal sandboxes read their copies; `#literal_bindings`, `#unbound_patch`; a second bind wraps the same base patch with both) and the track starts again at its launch point (`start_track`: the same player name, so routes and sends stay), in one `Session#command`: journaled, one undo step (`Arrangement#undo_state` keeps the tracks' patches; the old graph comes back from undo's retired graphs).  Since sound-design-2 the new graph takes the old one's running state on the swap frame (State across a rebuild, below).
- **Exactness**: at the knob's starting value the rebuilt graph gives the same samples as the same rebuild without binding, bit for bit, for lp4's resonance and cutoff (a Pitch), amp_env's attack, sustain, and release (GM-scaled times become `knob * factor` Multipliers), and dnb_reese's cutoff param (spec, 200 buffers after the swap); a take with bind, a turn, and undo replays bit for bit.
- **Inspector**: `Inspect.snapshot` adds the literal arguments of a node's recorded call that `#param_info` doesn't list (lp4 keeps numbers as Floats, so `resonance: 0.25` had no row; detail `"literal"`), so a node's params show what the code wrote.  Down past the knobs picks the selected node's params (a knob-driven one turns its knob); on a literal the status line names Enter's action (`make resonance knob :"bass/reso": rebuilds bass at its launch point (notes play on; delays and reverbs start fresh; Left/Right bind it now and turn)`, or why it can't be bound), and Enter puts the `bind` line on the prompt (`PaneKeys::Ask`), editable, which Enter runs.  `NodeInfo#binds` (`Inspect::Bind`: line and knob, or reason) for the selected node, kept per graph.
- Since library-instruments-1 (2026-10-28) a track's preset params are its knobs already (`:"bass/cutoff"`, Arrangement::TrackKnobs), so they show as knob rows without a bind; `bind :bass, :cutoff` names that knob, and `bind :bass, cutoff: :cut` makes the param follow another knob (one rebuild).  Struck instruments' decay shows the same way (`:"bells/decay"`).
- Not built: graphs played with `bg` (no patch to rebuild).  Carrying state, literals inside lists, and chained setters came with sound-design-2 (State across a rebuild, The envelope editor, below).

## Sections (sound-design-nav-1, 2026-10-29)

The maintainer (2026-10-28): "For sound design the focus is on the oscillators, filters, and envelopes.  Found it kind of awkward to try to get there."  The research spike `research-sound-design-nav` (2a7c329b: classifier, coverage of every shipped instrument, five directions as captures) and his decisions (2026-10-29): sections "Fewer, envelopes inside" (the Minimoog way), the view "By screen size" (sections from 120x40 up, the front panel at 80x24, a key flips), `design :bass` as "ui :sound with density rules", auditions "MAIN always".

- **Classifier** (`UI::Inspect::Classify`, `ui/inspect/classify.rb`, from the spike's `sections.rb`): walks a played graph (roots' `#graph` plus `#sources` and `#feedback_sources`, Tee branches resolved), marks the **audio path** from the roots back through main, side, and feedback ports (never into control nodes: envelopes, controllers, LFOs, note plumbing, glides, knobs, and arithmetic made only of those, `2 ** lfo`, a velocity-scaled envelope), then sorts every node by class, recipe call, and place into **SOURCE** (oscillators, unison, sampler voices, grains, struck resonators, dust on the path, glide as pitch, FM operators), **FILTER** (lp4, diode, cookbook/SVF filters, formants, resonators fed audio), **AMP** (shapers before the voice's amp as drive, choke gates, drum bursts), **MOD** (LFOs, drift, sample-and-hold off the path, oscillators read as LFOs), **FX** (reverb, chorus, delays, loops, dynamics, bands, decimators, post-amp filters and shapers, pans and other channel mixers).  The **voice's amp** is the enveloped Multiplier nearest the output; others are a layer's level (digibrass's noise burst).  **Envelopes go where they shape** (`env_section`): amp env and level env to AMP, filter env to FILTER, pitch and layer envelopes to SOURCE, any other to the section of the node it reaches (a drum's resonator pitch sweep sits in FILTER beside its `ping`), else MOD.  Plumbing (tees, constants, knobs, arithmetic, note and synth wiring, MIDI, tempo nodes, controllers, smoothing, LFO internals, drum voice wrappers) is hidden and counted by reason.  Copies with the same settings are one row; counts are per voice and channel (divided by synth lanes, and by 2 after a stereo mixer: `lp4 stereo`, not `lp4×2`); drum nodes carry their voice's name.
- **Knobs on their params**: `NodeInfo#param_knobs` (a param that reads exactly one knob through arithmetic, `knob(:cut) * lfo`, turns that knob), and knobs read only through hidden arithmetic join the row their signal reaches (`Classify.attach_knobs`: through a param port that row; through a shaper's main input the shaper, a drive gain; through another node's main input the SOURCE row feeding it, an oscillator mix).  Knobs no row shows (`InspectInfo#loose`) are knob rows above the sections.  A param row with a knob shows its meter, value with unit (a plain-number preset knob's unit from the Param names table: `Panes.unit_of`), what else moves it (`← lfo`, `← filter env`, from the modulators' destinations), and the knob's name; a literal shows dim with `·`, and its Enter offers the `bind` line.
- **Data**: `NodeInfo` gained `section`, `what` ("amp env", "post-amp EQ"), `dest` (["lp4 cutoff"]), `voice`, `channels`, `param_knobs`; `InspectInfo` gained `loose`, `hidden`, `voices`, `voice`, `unfit`.  The nodes are the section rows in section order, then up to `MAX_PLUMBING` (40) groups of hidden nodes with settings (section `:plumbing`, `what` the reason).  The default row is the first filter whose params read a knob, else the first filter, else the first SOURCE row (`Inspect.default_node`); a kit's voice opens on its body instead (sound-design-2, the obvious answer to sound-design-nav-1's question 2): its resonator (`ping`, `resonate`), else its first SOURCE row, else a shared body upstream of its rows (`Inspect.upstream_body`), so a 909 kick opens on its ping, not its click's highpass (guard: every tr909/tr808 voice in `inspect_presets_spec.rb`).  Nodes in several drum voices' graphs (the 808's metal bank under its hats and cymbal) belong to no voice (`Classify.drum_voices`), so they show with each of them.
- **The pane** (`Panes::Inspector`, title SOUND): the track line, a kit's voice strip (v V), loose knobs, then the sections: the picked row open with its params (every row open when they all fit; else sections collapse to one line each, farthest from the picked one first, and the farthest lines go when even that is too tall); the last line counts the hidden plumbing.  Keys: **s f a o x** jump to SOURCE FILTER AMP MOD FX (again: the next row there; MOD is `o` because `m` learns), n/N ] [ Tab step rows in section order, Up/Down pick params, Left/Right turn, Enter types or binds, **p** the plumbing view (every node as chips: the old list), **P** the panel, **v V** a kit's voices, t T tracks.  Note plumbing params (gate, trigger, velocity, choke, frequency, phase, reset, ...) aren't listed while a node feeds them.
- **Guard** (`inspect_presets_spec.rb`): every shipped instrument preset and the tr909/tr808 kits classify with no node unfit, amp/filter/pitch envelopes in AMP/FILTER/SOURCE, every row's voice among the kit's voices, and a default row.  Coverage on 2026-10-29: 41 instrument graphs + 2 kits, 0 unfit (the spike's table in its README; jungle_breaks' `PitchMark` was the one gap, now note plumbing).
- **Binding through bundles** (the spike's finding): a unison's call is recorded on the bundle it returns, and a call run per channel on a stereo bundle (`saws.lp4(...)` after a stereo unison) on the bundle it returns, so the mixer and the per-channel nodes had no call and `bind` couldn't reach `detune:` or a stereo lp4's `resonance:`.  `ChannelMixer::Unison#recipe_bundle` and `ChannelDispatch::ChannelGroup#bundle` link them, `LiteralBinding.call_of` follows the link (calls reached that way inside a graph document stay fixed: documents bind their params), and `positional_names` reads a bundle call's names from the node method it runs.  A bound stereo lp4 resonance gives the same samples; a bound detune runs the unison's moving-detune path (within -70 dB, not bit for bit; spec).
- **FILTER's view**: lp4 and diode rows have a response preview (Plot::Panels, design/notes/racks.md: Previews), so the inspector opening on a bass's filter shows its curve, titled with cutoff, resonance, and tuning (`lp4 ~2580 Hz reso 0.25` while an LFO moves it; dashed octave either side).
- **The front panel** (P; the default at 80x24, the maintainer's "By screen size"): each section's knobs and bindable literals as cells side by side (`Panes::Inspector#draw_panel`: name, a meter or dim dots, the value; cells named after their knob, `bass/glide` is glide, the param's row title before a name two rows share), the picked section open and the others one line each when short; Up/Down step cells (the cell's row becomes the picked row, so the preview follows and a literal's bind line is ready), Left/Right turn, Enter types or binds. ## The init voice (sound-design-2, 2026-10-29)

The maintainer (2026-10-29): "Init, based on 2osc morph with optional am/fm/sync, like sq80+mini dx7": a library instrument to copy and edit, not a blank mode.  `bin/synths/init_voice.rb` (`MB::Sound.init_voice(midi, voices:, **knobs)`, `INIT_KNOBS`), saved by `bin/save_presets.rb` as `presets/init.mbg.rb`; `design :lead` on a new track starts from it, and `track :lead, :init` / `L.inst.init` play it.

- **OSC1, OSC2**: each a wavetable tone on the library's `:basic_norm` scan (sine 0, triangle 1/3, square 2/3, saw 1; every frame as loud as the saw), so the wave knob is one band-limited oscillator (mipmapped levels by pitch, clean under FM as far as the levels allow) and the level holds while it moves.  Why not the others: a crossfade of four PolyBLEP tones costs four oscillators; `pwm`/`skew` morphs only one pair (triangle to saw).  Named `osc1`/`osc2` (`.named`), so the sections, panel, and chain strip say OSC words.
- **tune2** (semitones from OSC1, 7 cents by default), **mix**, **am** (OSC2 × (1 − am + am × OSC1) through `Tone#gain`; 1 is ring modulation), **fm** (linear through-zero FM of OSC2's frequency by OSC1 × the note frequency × fm: a DX7-style index, the same sidebands at every note; frequency rather than phase modulation because synced tones take no PM), **sync** (0/1: OSC2 hard-synced to OSC1).  All three off by default: two detuned saws.
- **sync is a build knob** (below): `Tone#sync(master, enabled:)` reads `enabled:` once while the graph builds (`GraphNode.build_value`), so sync off builds no synced kernel (the synced wavetable kernel costs 190-520 ns a sample even with no pulses, 5-10x the plain table, measured on the Mac container at 55/220/880 Hz).  OSC2's `param_info` shows the switch as its `sync` param.
- lp4 (cutoff at C4, keytracked half; reso; `filter_env(0.002, fdecay, 0, release, depth: fenv)`), `amp_env(attack, decay, sustain, release)`, `glide`.  Level 1.8: -20.3 LUFS on the library phrase (`seq(C4, E4, G4, A4.n4, G4, E4, D4.n4, C4.n2, R.n2).n8` twice, 100 BPM, default master), peak -7.2 dBFS; AM on -23.6, FM 1.5 on sines -21.6, sync with tune2 14 -20.4, a morph sweep -19.9.
- Every knob shows: the panel at 80x24 is `SOURCE wave1 mix wave2 am sync tune2 fm glide`, `FILTER cutoff reso fdecay release fenv`, `AMP attack decay sustain release`.  Two inspector changes made that true for any graph: knobs a row reads that no shown param names (a pitch offset through note plumbing, an FM depth inside a frequency param the sections hide as note plumbing) join the first row reading them as knob params (`Inspect.unshown_knobs`, in `walk`); and build knobs (`InspectInfo#build_knobs`) are turned a step a key, each one `turn` line, never a held sweep (`Inspector#key_turn`), with Enter's hint saying each turn rebuilds.

### Build knobs (`Arrangement::BuildKnobs`)

A track knob its patch reads while building (`GraphNode.build_value` inside `TrackKnobs.building` notes it: `Arrangement#note_build_knob`) can't be followed by the graph.  `turn :"lead/sync", 1` then rebuilds the tracks that read it at their launch points (`Arrangement#turn_build_knob`: the knob's `build_value` is the new value while the patches build, the turn lands with the rebuilt graphs, one `Session#command`: one undo step, journaled, replayed from takes); a turn to the value it has rebuilds nothing.  Ramps, follows, gestures, and keyframes of a build knob go through `live_error` ("read when lead builds, so it takes plain values").  Not handled: scenes, snapshots, and MIDI controllers setting a build knob change its value without a rebuild (the next build reads it).

### State across a rebuild (`Session::Carry`, sound-design-2)

The maintainer (2026-10-29): when `bind` rebuilds a patch, "carry the running state (oscillator phases, envelope stages/levels, filter states, held notes) into the new graph so a bind mid-note doesn't restart or click; where state can't map (structure changed), fall back to a short crossfade; say what carries".  `Session#add(..., carry: true)` (from `Arrangement#start_track(..., carry: true)`, which `bind_literal` and `turn_build_knob` pass):

- **Matching** (`Carry.plan`, on the building thread): from the graphs' outputs, nodes of the same class through the same source names (Tees climbed); then, for nodes whose `#sources` don't lead to their inputs (a multiband compander's bands), the k-th node of a class with the old graph's k-th when both have as many (Synths first); then a voice's Notes nodes the old graph lacked (a unison whose detune became a knob reads note numbers of its own) take an old node of their kind in the same voice (class and label: a controller only of its number).  `Plan` counts `stateful` new nodes, `matched`, and `uncarried` (running state without a snapshot: delay lines, reverbs, feedback loops, choruses, formants, sampler voices, grains, loop players, filters other than SVFs, biquads and chains of them, drum kit voices' idle sleeping; any graph node kind not in `Carry::STATELESS`, so an unknown kind crossfades rather than cuts).
- **The swap** (`add_now`, render thread): the change splits the buffer on its frame (`Change#split`, like seeks: `Seeks#carry_change?`), so the old graph has played exactly up to it; `Carry.apply` copies every pair's `plan_snapshot` into its partner (`plan_restore`; note envelopes their kernel state only, Notes nodes everything but their own stream's cursor, generation, and frame counts, and they skip the chase of the new stream's notes in progress, `Notes::Node#skip_start_chase!`) and each Synth's allocator (lane states, held keys, the mono stack, times moved to the new graph's stream time, which every graph counts from its own start) and idle bookkeeping (`SYNTH_STATE`: asleep lanes stay asleep on the same grid).  The carried notes' note-offs come from the old source read ahead from the swap with a reader of its own (up to 32 s; `Allocator#inject`), since the new source never started them; live input's arrive live.  With `full?` (every stateful node matched, nothing uncarried) the swap is a cut and the new graph plays the old one's samples; else the 5 ms declick crossfade (`Session#last_carry` says which).
- **Seeds**: `Arrangement#build_patch` remembers the random generator state each track build started from, and a carrying rebuild builds from it outside the root stream, so unison layouts, random phases, and noise seeds are the replaced graph's (before, a rebuild redrew them: a stereo unison patch differed by 0.16).
- **Snapshots added** for it: Dust and Drift (their random streams and positions), FilterChain (`peq` bands) through `SampleWrapper.filter_state`, and `Tone#plan_restore` making the State of a tone that hasn't played.
- **Measured** (`spec/lib/mb/sound/session/carry_sweep_spec.rb`, every shipped instrument preset rebuilt mid-note at bar 2:1 against no rebuild): 22 of the 41 instrument presets bit for bit (init, dnb_reese, dnb_sub, square_bass, digibrass, organ_reso, the tine and reed pianos, funk bass/keys/clav, jungle reese/sub, every sq80_*, ambient_drone with drift, the rainstick with dust); the other 19 crossfade (reverbs, delays, formants, crossovers, `and_then` tails, the kits' voices): their voices play on and their effects' tails start fresh.  A bound unison detune (the moving-detune path) is within -60 dB of the fixed one over 3 s (was -70 dB from fresh oscillators).  Undo's restore and `swap` don't carry (they bring a kept graph back, or keep the graph).
- Guards: `carry_spec.rb` (a bind mid-note bit for bit; exact at 367-frame buffers; a mono glide; the init voice's sync turned on mid-note keeps the note sounding, no gap or click; a reverb crossfades), and the sweep above (3 presets in the everyday run, the rest under SLOW=1).

### The envelope editor (sound-design-2)

The maintainer's earlier "display done; editor later.  It needs literals inside lists (multi-segment env points) and chained setters", now built through live literals:

- **Literals inside lists**: `LiteralBinding.slot_of` names a segment list's numbers (`env([[level, time, curve, shape], ...])`, the first argument when it's an Array of Arrays): `:t2` the second segment's time, `:t2_level` its level, `:t2_curve` its curve; a slot ends in a path (`[:arg, 0, [1, 1]]`), the value is dug out (`slot_value`) and the substitution copies the lists along the path (`replace_path`).  `bind :lead, env: :t2` makes `:"lead/t2"`.
- **Chained setters**: a node's config calls (`.curve(release: 30)`, recorded on the node it returns) are bindable calls too (`LiteralBinding.calls_of`, `keys_of` counts them): `bind :lead, curve: :release` makes `:"lead/release_curve"` (Target#arg is the call's argument, #param the inspector's and the knob's name).  `.sensitivity(0.5..1.0)` takes a Range: not a number, so not bound.  Two literals of one call stack their substitutions.
- **Ranges** (`LiteralBinding.envelope_entry`): times like an attack's (0.0001..10 s, exp), levels 0..1 (widened to hold the value), curves -60..60 dB.
- **The inspector**: the literals a node's code wrote that `#param_info` doesn't name (`LiteralBinding.literals`: call arguments, segment-list curves, chained setters' arguments as `:release_curve`) are its params, dim with a dot.  Left/Right on a bindable literal (any, not only envelopes) binds it at once and turns it (`Inspector#literal_turn`: `bind :lead, env: :t2, on: :now; turn :"lead/t2", 0.378`; the rebuild lands on the next buffer, its state carried, so notes play on); later presses turn the knob it made until the inspector shows it.  Up/Down puts the picked param in `Inspect.target[:param]`, and the preview marks it (`EnvelopeView.focus_of`: a solid rule at a segment's end for its time or curve, a level rule for :sustain and `:t2_level`, `▸t2` in the title), beside the playhead.
- Guards: `literal_binding_spec.rb` (each list point and the chained curve bound at their values within 1e-6 of the carried rebuild, ranges, the inspector's first press binding on :now, its second a turn, the preview's mark).
