# Feedback loops

<!-- summary -->
`sig.feedback { |fb, input| input + fb.delay(5.ms) * 0.8 }` (alias `fb`; `GraphNode::FeedbackLoop`) runs a loop's nodes one sample at a time as plan ops in C (`fast_loop`, exact Ruby mirror), the same output at any block size; `sig.delay(t, feedback: g) { |d| d.fb { ... }; d.wet { ... } }` is the tape-echo insert form.  Loop ops: arithmetic, shapers, delays, SVFs, biquads, lp4/diode ladders; other nodes on the loop go through `MB::Sound.live_error`.  Latency compensation (`compensate:` `:pitch` default, `:echo`, `:dc`, `false`) keeps periods and echo times exact; a hidden high shelf sustains loops with gentle lowpasses.

`sig.feedback { |fb, input| input + fb.delay(5.ms) * 0.8 }` (alias `fb`; `GraphNode::FeedbackMethods`, `GraphNode::FeedbackLoop` in `lib/mb/sound/graph_node/feedback_loop.rb`) builds a loop: the block gets the loop variable (`fb`, the loop's own output) and the input (`input`; `in` is a Ruby keyword) and returns the body; `sig.delay(t, feedback: g, dry:, wet:) { |fb| insert }` is the tape-echo form (the loop output is `insert(delay(input + g * output))`, so the insert runs on every repeat, the first included; without a block `#delay` is unchanged); insert pipelines (user decision 2026-10-09; `{ |d| d.fb { ... }; d.wet { ... } }` processes only the recirculated or only the output signal) `sig.delay(t, feedback: g) { |d| d.fb { |fb| fb.filter(3000.hz.lowpass).softclip }; d.wet { |wet| wet.filter(5000.hz.lowpass) } }`: a block that calls the builders on its argument (`GraphNode::DelayMethods::InsertPipeline`; else the block's return value is the tape insert) is a pipeline, `d.fb` processes only the recirculated signal in the loop (first echo clean, each later repeat processed once more, on time) and `d.wet` every echo on its way out, outside the loop and not fed back (its latency not compensated); either may be left out; with `d.fb` the echoes come from a second delay line outside the loop (`(input + g * loop).delay(t)`, since loop taps don't exist yet), about one delay's extra cost.  The loop's nodes (those depending on `fb`) run one sample at a time as plan ops in C (`ext/mb/sound/fast_loop`, `FastLoop.run`; exact Ruby mirror `Plan::Loop::Program#run_ruby`, `MB_SOUND_PLAN=ruby`; `MB_SOUND_PLAN_CHECK=1` runs both and compares bit for bit), so the output is the same at every block size and loops may be as short as one sample; everything else (input, delay times, gains, cutoffs, LFOs, envelopes, MIDI) is computed by the graph per block and read per sample (`FeedbackLoop#plan_sources` shows the plan layer only these inputs, so regions upstream still fuse).  Ops on the loop: arithmetic (Mixer, Multiplier, Constant, `/`, `**`), shapers (antialiased or not), delays (`fb.delay(t)`: Filter::Delay through `SampleWrapper#loop_describe`, its own DelayLine buffer and time handling, any interpolation; no `feedback:`/`wet:`/`dry:` of its own inside a loop), SVF filters (any type; cutoff/Q/gain may move).  `fb` is the current output when every path from it to the output has a delay, else the output one sample earlier (`Op::LoopHistory`, gen~-style); delays read from the sample being computed (at least one sample back).  Latency compensation (default; `compensate: false`; user decision 2026-10-09): the longest delay on the loop reads earlier by the rest of the loop's latency, so loop periods and echo times are exact.  Default mode `:pitch` (`compensate: true`; user decision 2026-10-09, `Program#pitch_latency`): the latency is the rest of the loop's phase delay at the fundamental 1/T (T the delay's time), from each op's complex response (delays, gains, antialiased shapers' half sample, SVFs' exact response; the DC estimate unwraps the phase and gives the loop gain's sign, linear-phase loops keep the exact DC value), evaluated at every 16th sample of the stream (in C since 2026-10-10: `FastLoop.pitch_track`, `ext/mb/sound/fast_loop/loop_pitch.c`, bit for bit with the Ruby version `Program#pitch_track_ruby`, which `MB_SOUND_PLAN=ruby` runs and check mode compares; Ruby checks whether anything moved before calling it; `#sustain_stretch` takes the phase at w with the shelf once (until 2026-10-10 its lambda assigned the method's locals, so the phase came from w - h with the shelf applied twice; fixed in both by the user's decision): lowpass at the pitch T60 110 Hz 20.83 → 21.20 s, 440 Hz 4.70 → 4.78 (unfiltered 20.74 / 4.67), lowpass at 2x within 0.3%) and ramped linearly between points while inputs move (same output at any block size), held exactly while nothing moves; no fixed-point iteration is needed since the target pitch 1/T is known.  `compensate: :dc` is the earlier mode: group delay at DC from per-op moments (the history's sample, an antialiased shaper's half sample, a lowpass SVF's 1/(2gQ), an allpass's twice that, other delays; gains weight parallel paths; per block in Ruby, per sample when a gain or cutoff moves; `FeedbackLoop#latency`).  `compensate: :echo` (omnibus16, 2026-10-29; what `#delay`'s insert loops use): `:pitch` with highpass, bandpass, and bandpass_skirt SVFs (biquads too) counted as wires (`Plan::Loop::Program::ECHO_WIRES`, left out of `#response_program`, so the C tracker needs no change): at an echo's 1/T (a few Hz) a low cut leads by up to 180 degrees, so `:pitch` put repeats up to half an echo off (tape insert hp200+lp3000+softclip at 0.1 s: echo energy centers +2327/-2342/-145/+2184 samples from k*T), while the repeats' energy sits in the passband where that phase is small.  Echo centers with `:echo` equal `:dc`'s on every insert measured (one-sample impulse, feedback 0.5, energy centers in samples off k*T at echoes 1-4, 0.1 s; the spec "#delay echo arrivals" keeps a table of them): tape insert 3.5/8.1/12.6/17.1, hp200 0.4-0.8, hp80 0.5-1.3, hp500+lp2000 5.4-28.4, bandpass 1 kHz 8.2-53.7 (uncompensated: no moments), lp3000 -1.2, lp800 0-5.2, softclip 0.8-3.0; over echo times 10-100 ms and low cuts 40-400 Hz with lp3000, 1.2-6.0 samples a pass (`:pitch` 6-438).  Unlike `:dc`, a short comb through a lowpass keeps `:pitch`'s tuning (bit for bit: lowpass at 2x the pitch -0.2 cents vs `:dc` -13.5); both detune a comb whose highpass is under its pitch (a DC blocker at 0.1x: +38 cents, at 0.4x +143; `:pitch` exact): tune those with `feedback { }`.  A phase fade (the highpass's phase scaled by how much of the pitch it passes) was tried and dropped: in between (1/T near the cut) it put echoes 20-127 samples a pass off where `:echo` is within 6.  Measured (KS, two-sample average plus an SVF lowpass at 8x/4x/2x the pitch, 110-1760 Hz, fundamental error in cents): `:pitch` within 0.02/0.02/0.18 (`:dc` -0.25/-2.0/-13.5, uncompensated -40 or worse); higher partials keep the filter's dispersion (2nd/3rd partials -0.7/-1.8 cents at 8x in both modes, -4.8/-9.3 at 4x), and without a filter every partial is within 0.01 cents (the user's "440 compensated sounds a tiny flat" is a perception check, renders below); tape echo centers of mass within 0.01 samples.  Cost of `:pitch` (YJIT, % of realtime, KS at 440 Hz with a lowpass, 512/128-sample blocks): constant parameters 0.50/0.76 (= `:dc`), cutoff LFO 3.2/5.8 (`:dc` 1.5/3.0, none 0.64/0.88), gliding delay time 2.4-2.6/3.9-4.1 (`:dc` 1.06/1.65): ~4 us of Ruby per 16-sample point before the C kernel (pluck on dense_modulated.mid 116.5 → 39.2% / 65.7 → 20.0% of realtime at 128/512, feedback_song 109.7 → 41.8 / 61.3 → 17.3, flanger 20.1 → 16.7 / 16.1 → 13.5, tape_delay unchanged).  Sustain (`sustain: true`/`:pitch`, default; `false` off; user's request 2026-10-09 after the round-2 KS renders, default by playability): a loop with SVFs gets a hidden shelf on its pitch delay's input (gain x + rest lowpass(x), params set per block by `Program#pitch_track`, which now returns [latency, gain, rest] from the same 16-sample points) so the loop's gain at the pitch is what it would be with every SVF a wire, aimed at the unfiltered gain to the power group delay / period (`Program#sustain_stretch`, every 4th point) since a mode's envelope decays once per group delay; KS fundamental T60 (s, 110/440/1760 Hz, lowpass Q 0.707 at 8x/4x/2x/1x the pitch, none = 20.7/4.70/0.43): off 20.0/12.7/1.91/0.18, 4.55/2.99/0.47/0.045, 0.43/0.37/0.11/0.011; on 20.9/20.4/20.8/21.2, 4.70/4.69/4.69/4.78, 0.43/0.43/0.44/0.45 (none 20.74/4.67/0.43; the sustain spec's fit over 1 s, 2026-10-10).  A flat boost would make the loop's DC mode grow (a lowpass passes DC; simulated: +105 dB/s at 440 Hz), so boosts are a high shelf (lowpass at `SUSTAIN_SHELF` 0.85 x the pitch, Q 0.5, gain solved exactly at the pitch, phase in the latency), capped at `SUSTAIN_MAX` 2 (shelf transitions ring on their own above ~2.3-2.6), and only for gentle lowpasses (every SVF a lowpass with Q <= 1/sqrt(2), joining paths filtered alike; highpasses, bandpasses, notches, peak cuts, and half-filtered mixes blew up when boosted); filters with gain above 1 at the pitch get a flat cut (`SUSTAIN_MIN` 1/64).  Scan (`/app/tmp/listening/feedback_loops/round3/stability.rb`, 12 filter shapes x 3 pitches x 8 cutoffs): no loop unstable with sustain that is stable without; 21 resonant-lowpass loops that blow up without it are stable with it.  `#delay` echo loops pass `sustain: false`; loops without SVFs are bit-identical; `FeedbackLoop#sustain_ratio`. Input ends (2026-10-13): when a boundary input ends, the loop reads it as silence and rings out until its output has been below -90 dB for its longest delay plus the sinc reach, ending on that exact sample (see the delays note, Ringing out).

Biquad and four-pole loop ops (delay-fx-1, 2026-10-28): `fb.filter(type, ..., structure: :biquad)` (OP_BIQUAD: `Filter::Cookbook`, coefficients per sample as its dynamic kernel through `mb_biquad.h`, state in the Cookbook's ivars as fast_plan's `plan_biquad.c`; mirror: `Cookbook#dynamic_process` per sample) and `fb.lp4(...)` / `fb.diode(...)` in every mode and drive mode (OP_FOUR_POLE: `mb_four_pole.h`'s coefficient caches and `mb_fp_step`/`mb_dl_step` with the flush grid, settings as fast_plan's OP_FOUR_POLE; mirror: `Filter::FourPole#dynamic_process_ruby` per sample) run inside loops, C and mirror bit for bit.  `Plan::Loop::Op::Biquad < Op::Svf` with `#filter` a `Filter::SVF.from_cookbook` copy (the same cookbook response), so latency compensation, the C pitch tracker, and the sustain shelf treat a biquad as that SVF (a biquad lowpass tape echo is the SVF one within 4e-18, the same echo times).  Four-poles and diode ladders are in the latency estimate since omnibus16 (2026-10-29; until then wires: a 1000-sample echo through `lp4(2000)` landed 9.8 samples later per repeat, `lp4(500)` 39, a string through lp4(2000) at a 1000-sample period 15 cents flat, lp4(500) 65): `#response_program` entries `:four_pole` (`RK_FOUR_POLE` in `loop_pitch.c`, words cutoff, resonance, 8 scalars (rate, k_max, compensation, mix), flags (curve, normalize, diode, tuning)) evaluate the kernels' small-signal linear response at the pitch from their own coefficients (`Filter::FourPole#kernel_coefficients` = `mb_fp_coef_update`/`mb_dl_coef_update`, Padé tan included; `Program#four_pole_point` = `pc_fp_point`: a TPT stage 1/(1 + j s), s = tan(w/2)/g, the cascade in_gain mix(h)/(1 + k h^4), the diode in_gain/(D(js) + k) with D(s) = s^4 + 7s^3 + 15s^2 + 10s + 1; the same at any drive, whose saturators have unit small-signal gain), and the DC moments their group delay (`#four_pole_dc_delay`: lp taps sum(n m_n)/(2 g sum m) - 2k/(g(1 + k)), lp4 2/(g(1 + k)), the diode 5/(g(1 + k)); hp/bp taps none).  The compensation equals the filter's exact phase delay at 1/T (lp4/lp2/diode at 500-2000 Hz, resonance 0-0.9, within 0.01 samples); echoes through lp4(500) in `feedback { }` keep their spacing within 0.2 samples; strings through lp4/diode at 8x the pitch within 0.3 cents (1 cent at 4x: a steep lowpass moves a decaying mode off the whole-phase frequency).  A four-pole on the loop counts as a harmonic risk for sustain (its resonant peak: no boosts, flat cuts still), and its response is in both of sustain's passes (sustain makes up for SVFs only, as before).  In `:echo` loops, hp2/hp4/bp2/bp4 taps are wires (`ECHO_WIRE_MODES`).  In `:pitch` loops a highpass tap now has its phase at the pitch like an SVF highpass (a string through `lp4(200, mode: :hp2)` at 48 Hz: 456 -> 28 cents; an echo-length loop through it is then off like an SVF highpass's: use `#delay`'s `:echo`).  A FourPole's `keep_last` param memory is skipped in loops (an ended boundary input reads as 0 there, like every loop input).  Not yet: multitap taps and loop taps inside loops, oscillators, envelopes.
