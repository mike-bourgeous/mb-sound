# Feedback loops

Detailed notes moved from CLAUDE.md (2026-10-10); CLAUDE.md keeps a summary and points here.  Update both when behavior changes.


`sig.feedback { |fb, input| input + fb.delay(5.ms) * 0.8 }` (alias `fb`; `GraphNode::FeedbackMethods`, `GraphNode::FeedbackLoop` in `lib/mb/sound/graph_node/feedback_loop.rb`) builds a loop: the block gets the loop variable (`fb`, the loop's own output) and the input (`input`; `in` is a Ruby keyword) and returns the body; `sig.delay(t, feedback: g, dry:, wet:) { |fb| insert }` is the tape-echo form (the loop output is `insert(delay(input + g * output))`, so the insert runs on every repeat, the first included; without a block `#delay` is unchanged); insert pipelines (user decision 2026-10-09) `sig.delay(t, feedback: g) { |d| d.fb { |fb| fb.filter(3000.hz.lowpass).softclip }; d.wet { |wet| wet.filter(5000.hz.lowpass) } }`: a block that calls the builders on its argument (`GraphNode::DelayMethods::InsertPipeline`; else the block's return value is the tape insert) is a pipeline, `d.fb` processes only the recirculated signal in the loop (first echo clean, each later repeat processed once more, on time) and `d.wet` every echo on its way out, outside the loop and not fed back (its latency not compensated); either may be left out; with `d.fb` the echoes come from a second delay line outside the loop (`(input + g * loop).delay(t)`, since loop taps don't exist yet), about one delay's extra cost.  The loop's nodes (those depending on `fb`) run one sample at a time as plan ops in C (`ext/mb/sound/fast_loop`, `FastLoop.run`; exact Ruby mirror `Plan::Loop::Program#run_ruby`, `MB_SOUND_PLAN=ruby`; `MB_SOUND_PLAN_CHECK=1` runs both and compares bit for bit), so the output is the same at every block size and loops may be as short as one sample; everything else (input, delay times, gains, cutoffs, LFOs, envelopes, MIDI) is computed by the graph per block and read per sample (`FeedbackLoop#plan_sources` shows the plan layer only these inputs, so regions upstream still fuse).  Ops on the loop: arithmetic (Mixer, Multiplier, Constant, `/`, `**`), shapers (antialiased or not), delays (`fb.delay(t)`: Filter::Delay through `SampleWrapper#loop_describe`, its own DelayLine buffer and time handling, any interpolation; no `feedback:`/`wet:`/`dry:` of its own inside a loop), SVF filters (any type; cutoff/Q/gain may move).  `fb` is the current output when every path from it to the output has a delay, else the output one sample earlier (`Op::LoopHistory`, gen~-style); delays read from the sample being computed (at least one sample back).  Latency compensation (default; `compensate: false`; user decision 2026-10-09): the longest delay on the loop reads earlier by the rest of the loop's latency, so loop periods and echo times are exact.  Default mode `:pitch` (`compensate: true`; user decision 2026-10-09, `Program#pitch_latency`): the latency is the rest of the loop's phase delay at the fundamental 1/T (T the delay's time), from each op's complex response (delays, gains, antialiased shapers' half sample, SVFs' exact response; the DC estimate unwraps the phase and gives the loop gain's sign, linear-phase loops keep the exact DC value), evaluated at every 16th sample of the stream (in C since 2026-10-10: `FastLoop.pitch_track`, `ext/mb/sound/fast_loop/loop_pitch.c`, bit for bit with the Ruby version `Program#pitch_track_ruby`, which `MB_SOUND_PLAN=ruby` runs and check mode compares; Ruby checks whether anything moved before calling it; `#sustain_stretch` takes the phase at w with the shelf once (until 2026-10-10 its lambda assigned the method's locals, so the phase came from w - h with the shelf applied twice; fixed in both by the user's decision): lowpass at the pitch T60 110 Hz 20.83 → 21.20 s, 440 Hz 4.70 → 4.78 (unfiltered 20.74 / 4.67), lowpass at 2x within 0.3%) and ramped linearly between points while inputs move (same output at any block size), held exactly while nothing moves; no fixed-point iteration is needed since the target pitch 1/T is known.  `compensate: :dc` is the earlier mode: group delay at DC from per-op moments (the history's sample, an antialiased shaper's half sample, a lowpass SVF's 1/(2gQ), an allpass's twice that, other delays; gains weight parallel paths; per block in Ruby, per sample when a gain or cutoff moves; `FeedbackLoop#latency`).  Measured (KS, two-sample average plus an SVF lowpass at 8x/4x/2x the pitch, 110-1760 Hz, fundamental error in cents): `:pitch` within 0.02/0.02/0.18 (`:dc` -0.25/-2.0/-13.5, uncompensated -40 or worse); higher partials keep the filter's dispersion (2nd/3rd partials -0.7/-1.8 cents at 8x in both modes, -4.8/-9.3 at 4x), and without a filter every partial is within 0.01 cents (the user's "440 compensated sounds a tiny flat" is a perception check, renders below); tape echo centers of mass within 0.01 samples.  Cost of `:pitch` (YJIT, % of realtime, KS at 440 Hz with a lowpass, 512/128-sample blocks): constant parameters 0.50/0.76 (= `:dc`), cutoff LFO 3.2/5.8 (`:dc` 1.5/3.0, none 0.64/0.88), gliding delay time 2.4-2.6/3.9-4.1 (`:dc` 1.06/1.65): ~4 us of Ruby per 16-sample point before the C kernel (pluck on dense_modulated.mid 116.5 → 39.2% / 65.7 → 20.0% of realtime at 128/512, feedback_song 109.7 → 41.8 / 61.3 → 17.3, flanger 20.1 → 16.7 / 16.1 → 13.5, tape_delay unchanged).  Sustain (`sustain: true`/`:pitch`, default; `false` off; user's request 2026-10-09 after the round-2 KS renders, default by playability): a loop with SVFs gets a hidden shelf on its pitch delay's input (gain x + rest lowpass(x), params set per block by `Program#pitch_track`, which now returns [latency, gain, rest] from the same 16-sample points) so the loop's gain at the pitch is what it would be with every SVF a wire, aimed at the unfiltered gain to the power group delay / period (`Program#sustain_stretch`, every 4th point) since a mode's envelope decays once per group delay; KS fundamental T60 (s, 110/440/1760 Hz, lowpass Q 0.707 at 8x/4x/2x/1x the pitch, none = 20.7/4.70/0.43): off 20.0/12.7/1.91/0.18, 4.55/2.99/0.47/0.045, 0.43/0.37/0.11/0.011; on 20.9/20.4/20.8/21.2, 4.70/4.69/4.69/4.78, 0.43/0.43/0.44/0.45 (none 20.74/4.67/0.43; the sustain spec's fit over 1 s, 2026-10-10).  A flat boost would make the loop's DC mode grow (a lowpass passes DC; simulated: +105 dB/s at 440 Hz), so boosts are a high shelf (lowpass at `SUSTAIN_SHELF` 0.85 x the pitch, Q 0.5, gain solved exactly at the pitch, phase in the latency), capped at `SUSTAIN_MAX` 2 (shelf transitions ring on their own above ~2.3-2.6), and only for gentle lowpasses (every SVF a lowpass with Q <= 1/sqrt(2), joining paths filtered alike; highpasses, bandpasses, notches, peak cuts, and half-filtered mixes blew up when boosted); filters with gain above 1 at the pitch get a flat cut (`SUSTAIN_MIN` 1/64).  Scan (`/app/tmp/listening/feedback_loops/round3/stability.rb`, 12 filter shapes x 3 pitches x 8 cutoffs): no loop unstable with sustain that is stable without; 21 resonant-lowpass loops that blow up without it are stable with it.  `#delay` echo loops pass `sustain: false`; loops without SVFs are bit-identical; `FeedbackLoop#sustain_ratio`.  Cost: +1 SVF and a multiply-add per sample (KS 440 Hz constant: 0.62/1.02% of realtime at 512/128 vs 0.52/0.76), and the Ruby points roughly double while parameters move (cutoff LFO 7.0/10.6 vs 3.8/6.9; gliding delay 6.3/8.6 vs 3.4/5.4).  Round-2 KS items (user: "the excitation pulse comes through way too loud and the resonance is quiet"): the patch added the raw noise burst after the loop filter (`input + lowpass(loop)`, burst 36-41 dB above the ring) and a lowpass at 2x costs the fundamental 0.26 dB per period (library correct); write `(input + loop).filter(...)` to filter the burst with the string (renders `/app/tmp/listening/feedback_loops/round3/`).  Excitation (user's round-3 note "the excitation still seems too prominent"; 2026-10-09): classic Karplus-Strong writes one period of noise into the delay line and outputs the loop after its damping, so the burst is never heard raw and the string is periodic from its first period: `exc = (noise.at(0.5) * adsr(0, 0, 1, 0, hold: 440.hz.period)).and_then(0.constant)` (`and_then` keeps the input alive, or the loop ends with it), `exc.feedback { |fb, input| d = (fb + input).delay(440.hz.period, smoothing: false); ((d + d.delay(1.samples)) * 0.4985).filter(:lowpass, cutoff: 880, quality: 0.5**0.5) }`; `bin/synths/pluck.rb` does the same per voice (`--pick` periods of noise, velocity opens a lowpass on it up to `--brightness` times the pitch).  Burst peak (first 20 ms) over ring RMS (0.1-0.3 s), sustain on, lowpass at 2x, 110/440/1760 Hz: round-3 patch 12.9/11.1/25.2 dB, classic 11.7/9.7/18.5; pluck.rb at velocity 0.9 36.2/23.3/20.2 before, 12.9/14.7/19.7 after (high notes stay ~19 dB because the two-sample average shortens the ring itself: T60 0.43 s at 1760 Hz whatever `--sustain` says; renders `/app/tmp/listening/feedback_loops/round4/`).  The latency estimate now counts every SVF type's parameters as dependencies (a highpass cutoff that changed after holding still kept the old latency).  Short delays (decision 2026-10-09): sinc reads closer than the kernel's reach blend into cubic over 4 samples (cubic below about 9 samples at 1x, sinc from about 13), constant whole-sample delays read directly; the C sinc read caches its weights while the delay holds (exact).  Dispatch: computed goto (switch with `-DMB_LOOP_SWITCH`) and multiply-add superinstructions (`Program.superinstructions`); an exact decode-time rewriter (2026-10-10) drops x * 1, 0 + x (a -0 may stay -0 where the mirror gives +0: equal values, which the user accepted for sound, 2026-10-10), and copies, reads constant whole-sample sinc delays directly (`OP_DREAD_INT`, an internal opcode), and indexes cubic/linear taps without a modulo when they don't wrap (real loops within noise, feedback_song about -7%); C loop alone, ns/sample: Karplus-Strong 54 (switch 61), tape insert 73 (77).  Cost (YJIT, 512-sample blocks, mono, % of realtime): comb 0.22, one-pole 0.17, Karplus-Strong 0.41, tape echo with two SVFs and a softclip 0.70 (0.44 uncompensated: compensation makes a constant delay fractional), flanger 0.88.  Fallback (decision 2026-10-09): a node without loop ops on the loop (an oscillator modulated by `fb`, a four-pole, a reverb, a proc) goes through `MB::Sound.live_error` (`Plan::Unsupported` in scripts and specs; in live mode a warning, then the body runs as a graph in blocks of the longest delay, max 256, or 1 without a delay; `fb` a block late and that delay a block shorter via `Filter::Delay#loop_offset`; op latencies not compensated).  Not yet: oscillators, envelopes, four-pole/biquad filters, multitap and matrix feedback inside loops (the reverb has its own kernel, see Reverbs), cross-voice (lane-major) loops, loop taps (a node on the loop read outside it raises).
