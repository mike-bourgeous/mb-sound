# Genre templates (`lib/mb/sound/genre.rb`, `genre/`, console `GenreMethods`)

<!-- summary -->
`genre :dnb` (`GenreMethods`, `lib/mb/sound/genre.rb` + `genre/`) is a frozen `Genre::Template` of what the persona panel learned about a genre: tempo and range, meter, phrases, key, a `Form`, drum `Kit`s with fills, material clips, roles (patches with levels, params, filters, ducks, bus routes), scenes, knobs, `Mix` targets, and tips, for `:dnb`, `:jungle`, `:ambient`, `:funk`, `:house`, `:techno`.  Templates compose (`genre(:dnb, tempo: 170)`, a builder block, `like`, `Genre.define`), set up and play a Session (`t.setup`, `t.play`, `t.short(60)`), print back (`t.to_ruby`), and grow generated forms (`t.generative(seed:)`, `t.endless`).  Demo `bin/songs/genre_demo.rb -G dnb`; help `help :genres`.
<!-- /summary -->

I'd like to capture the genre information as flow structures or something, and potentially repeat the experiment when there are more features." ## What a template is

`genre :dnb` returns a `Genre::Template`: a frozen `Data` value holding what the panel's research said a genre is, as the library's own objects:

| field | type | example (`:dnb`) |
|---|---|---|
| `name`, `title` | Symbol, String | `:dnb`, `"Drum & bass (modern UK)"` |
| `tempo`, `tempo_range` | Numeric, Range | `174`, `170..176` |
| `meter` | `[beats, unit]` | `[4, 4]` |
| `phrases` | Array of bars | `[8, 16, 32]` |
| `key` | `[mode, root]` (`#scale` makes the Scale) | `[:minor, :f]` |
| `form` | `Form` (a `flow` block) | intro 32, build 8, drop 32 (at bar 41: the classic "drop at 33" plus a build), breakdown 16, pullup 1, drop2 32, outro 32 |
| `kits` | `{name => Sequence::Kit}` (grids, fills) | `:intro`, `:build`, `:drop` (two-step, ghosts, a `:roll` fill), ... |
| `clips` | `{name => Sequence::Clip}` | `:riff`, `:chords`, `:hook`, `:hit` |
| `roles` | `{name => Genre::Role}` | `drums: Role(:dnb_drums)`, `bass: Role(:dnb_reese, params: { cutoff: :cut }, duck: -8.db)` |
| `scenes` | `{name => {track => kit/clip name, knob => value}}` | `drop: { drums: :drop, bass: :riff, sub: :riff, cut: 2400 }` |
| `knobs` | `{name => [default, options]}` | `cut: [2400, { range: 150..8000, curve: :exp }]` |
| `buses` | `{name => Genre::Bus(steps, to)}` | `hall: Bus([[:filter, [:highpass], {...}], [:reverb, [:hall], { mix: 1 }], [:at, [12.db], {}], [:duck, [:drums], { only: :kick, ... }]])` |
| `sidechain` | `[track, node]` that roles' `duck:` reads | `[:drums, :kick]` (`duck(:drums, only: :kick)`) |
| `mix` | `Genre::Mix` | `loudness: -10..-8, true_peak: -0.5.db, mono_below: 120, master: [[:dnb_master, [], { air: :air, drive: 8 }]], gain: 0.db` (master: steps run in order, each a preset with an `:input` or a GraphNode method with arguments: jungle's `master :compress, ...; master :at, 5.db; master :limit, ceiling: -1.db`) |
| `tips` | Array of Strings | "Drop on a 32-bar boundary for DJs ...", "Keep the sub mono ..." |

Roles name a **patch**: a preset (`presets/*.mbg.rb`, shipped with mb-sound: the genre patch scripts saved by `bin/save_presets.rb`), else a `Genre::Patches` method (a noise `riser`, from Tunnel Vision), else an `MB::Sound` method taking a MIDI source (`:tr808`, or a voice method such as `:dnb_reese_voice` once its script is loaded).  So a template plays without requiring any bin/ script, and stays data: no Procs, nothing that can't print.  Role options: `level:` (a gain, written in dB), `params:` (preset params: numbers, or Symbols naming template knobs, which the preset's param then reads: `params: { cutoff: :cut }`; round 2, after graph documents' params learned to take nodes and knob names), `filter:` (a knob name: a lowpass on the role's output that the knob drives, for patches without a fitting param, like the house stub's tine piano), `duck:` (an amount: sidechain ducking keyed by the template's `sidechain`, the drums track's own kick voice; see "Buses and the sidechain" below), `q:`, `fade:`, `about:`, `to:` (a template bus the role's main out feeds), `send:` (`{ bus => gain or knob name }`).

## Building, composing, printing

```ruby
genre :dnb                          # the registered template
genres                              # lists them (name, title, tempo)
t = genre(:dnb, tempo: 172)         # Data#with: any field
t = genre(:dnb) { tempo 170; role :bass, :jungle_reese, level: -2.db }   # the builder, on top
t.form; t.kits[:drop]; t.scene(:drop); t.scale; t.tips
t.short                             # the form scaled to about a minute (sections, fills, phrase fills, and role bars: params / 2^n, at least 1 bar)
t.setup                             # tempo, meter, quant, knobs, master, tracks, scenes on the current Session
t.play                              # setup + play_form(t.form)
puts t.to_ruby                      # Genre.template :dnb, "..." do ... end (evaluates to an equal template)
Genre.define(:my_dnb, 'Mine') { like :dnb; tempo 168 }   # register a new one (lazy: built on first use)
```

- The builder (`Genre::Builder`, `instance_exec`) has one method per field (`tempo 174, range: 170..176`, `meter 7, 8`, `phrases 8, 16`, `key :minor, :f`, `flow do ... end`, `kit :drop, grid(...)`, `clip :riff, seq(...)`, `role :bass, :dnb_reese, level: -1.db`, `scene :drop, drums: :drop, bass: :riff`, `knob :cut, 2400, range: ..`, `sidechain :drums, only: :kick` (the `pulse` kit and its ghost kicks are gone since genre-fixes, below), `loudness`, `true_peak`, `mono_below`, `master`, `master_gain`, `tip`, `about`) plus `like :other` (start from another template) and `layers beat: :beat, bass: :bass_a, ...` (a looper's build-by-layering: one cumulative scene per layer, each named after the track it adds).  Other calls (`grid`, `seq`, `chord`, `events`, `scale`) go to `MB::Sound`, so kits and clips are written with the usual DSL; note names resolve because the template files are inside `module MB::Sound`.  Unknown builder methods raise with did_you_mean suggestions.
- Short forms in one line each: `genre(:dnb, tempo: 170)` (Data#with), `genre(:dnb) { role :bass, :jungle_reese }` (the builder on top), `Genre.define(:mine) { like :dnb }` (lazy registry), `t.short(60)` (the form / 2^n to about 60 seconds), `t.mix.report(loudness(...))`; console help `help :genres`.
- Re-declaring a role, kit, clip, scene, or knob replaces it (so `genre(:dnb) { ... }` overrides parts); the form is replaced whole; `without roles: [...], scenes: [...]` removes parts (removed roles leave the scenes too); `master nil` clears the chain.
- `to_ruby` prints the builder: kits and clips through their graph-io recipes (`grid(16, kick: "X...").loop(align: :launch).fill(:roll, ...)`), the form through `Form#to_ruby`, levels as `-1.db`.  `Template#==` compares the printed code (like `Form`).
- Registered templates are built lazily (the first `genre(:x)`): building clips and forms needs `MB::Sound` loaded and a Session for form knob options, which templates don't use (section knob values live in scenes, which a template's knobs exist for).
- Scenes name kits and clips by Symbol; `Template#scene(name)` resolves them (a role-named key whose value isn't a kit or clip name is passed on: `:on`, `:off`, `nil`, `:keep`), and knob keys pass through (`cut: [2500, { from: 250, over: 8 }]`).  The builder validates when it builds the template (`Builder#__check__`, raising ArgumentError with suggestions): every scene track is a role, every kit/clip name exists, every form section has a scene, knob keys are knobs, the tempo is in its range.

## Generated forms (G4, generative-g4, 2026-10-29)

The brief: "a generative variant per genre template ... a template's form generated by markov/lsystem from its phrase vocabulary", and "`genre(:ambient).endless` plays forever".

- `generator source, bars: { ... }, sections:, use:, scenes:` (in short `generator markov(...)|lsystem(...), bars:, use:`; every shipped template has one; builder; `Genre::Generator`, a template field printed by `to_ruby`; `generator nil` removes it): a `markov` or `lsystem` over the template's section names, lengths per occurrence (bars, Ranges, Arrays; sections of the written form left out keep their length), `sections:` (how many `#generative` plays when the source doesn't end), `use:` (material swapped in every scene for the generated form: `{ drone: :drone_walk }`), `scenes:` (values added to scenes).  Checked: every section the source may play has a scene and a length, swaps name kits or clips, scene values name scenes.
- `t.generative(seed:, sections:)` (usually just `t.generative(seed:)`): a copy whose form is `flow { <the written form's phrase fills>; generate source, bars: { ... } }`, the written sections' options (fills) carried in the lengths (`build: { length: 8, fill: [:riser, 4] }`), the swaps applied; `seed:` reseeds the source (another song from the same grammar).  `t.endless(seed:)`: the same in `label :top ... goto :top`, forever.  Generated songs play full length (genre_demo's `-E` skips `short`); `#bars`/`#seconds`/`#short` count a generated form's first 64 planned passes; the summary prints the first passes.
- The generators (40 seeds each, 2026-10-29: distinct section orders, song lengths): `:dnb` L-system (one to three build-drop cycles turning through breakdown + pull-up into drop2 or another drop; breakdowns of 7 or 15 plus the pull-up keep 8/16-bar phrases): 10 orders, 2.0-5.7 min (median 4.0); `:jungle` L-system (rolls into drops, breakdowns into drop2): 11, 1.9-5.8 (3.1); `:house` L-system (breakdown-drop-pickup cycles, a breakdown2-drop2, 16-bar phrases): 9, 2.3-5.9 (3.4); `:techno` Markov (peaks trading with their b-sides, breakdowns to peak2 or another build, the outro chain when it comes): 25, 3.4-26 (7.0; a long tail: the chain may ride the peaks for a while); `:funk` Markov (the layers in order, then groove/bridge/peak/strip until the outro): 17, 1.3-6.6 (2.4); `:ambient` Markov (moods; no end: `sections: 12` for `#generative`).  Lengths vary per occurrence on top of the orders.
- `:ambient`'s endless form (`bin/songs/endless.rb`): moods `emerge -> drift`, drift to bloom/hush/tide/itself, bloom to tide/hush/drift, hush to drift/tide/emerge, tide to hush/drift/dissolve, dissolve to emerge (the arch restarting); emerge and dissolve 8 bars, drift/bloom/tide 8 or 16, hush 4 or 8.  The key walks (`keys = markov(d: { g: 2, a: 2, e: 0.5 }, ...).take(24)`: a key every 16 bars, held 12 and blended over 4, a 384-bar loop, 25.6 min at 60 BPM) the yo scale on D, G, A, E, keys that all hold D, E, and A, so the bowls (D4, A3), rin (E5), gong (D2), and stick (D5) stay in key on their clocks in seconds while `:drone_walk` (`strikes` of the root, one 8-bar note per 8 bars: D2, G1, A1, E2; measured: the drone stem's peaks move from 73.4/110 Hz to 55/82.7 Hz at bar 17), `:motif_walk` (the koto: `motifs` of 32 quarters, about four notes per 8 bars, a b a c), and `:harp_walk` (`motifs` of sixteenths, swung 0.6) follow it.  The written form and its scenes are unchanged (golden `ambient` passes).

## Buses and the sidechain (genre-fixes, 2026-10-18)

Kez Volta (round 2 sheet): "Every ducked part building its own ghost kick?  That's not sidechain, that's cosplay."  Until genre-fixes, `duck:` keyed from a ghost 808 kick (`Genre::PULSE_KICK`) playing the `pulse` kit's kick row under every scene; buses-1's `duck(:drums, only: :kick)` replaces it:

- `sidechain :drums, only: :kick` (builder) names the track and the node inside its graph that ducks read; `Template#patch` makes `node.duck(:drums, only: :kick, amount: r.duck, release: 1.n16)`, read on the exact sample by the Session's buses, so only kicks that play duck (a hats-only breakdown ducks nothing; drop2's extra kicks duck).  `pulse`, `Template#pulse_kick`, and `PULSE_KICK` are gone (no legacy alias; maintainer rule 2026-10-17).  Ducks outside a Session read silence.
- The drums track must always hold the node: `Template#scene` gives the sidechain track's kits a silent row for it when they lack one (`keyed_kit`: a hats-only breakdown kit keeps a sleeping kick voice; otherwise the buses warn "no node named :kick" whenever such a kit plays).  The added `Kit.new` is recorded explicitly (library calls aren't recorded), so set documents print it.
- `bus :hall, [:filter, :highpass, { cutoff: 250 }], [:reverb, :hall, { mix: 1 }], to: :other` declares a template bus: steps like the master's (`[name, *args, params]`: a mastering preset, an effect preset with an input such as `:ambient_tape`, or a GraphNode method), none for a plain group.  `Template#setup` defines the buses (each after the bus it feeds, `Genre.bus_order`) before the tracks, and tracks get the roles' `to:`/`send:`.  Symbol params of steps and patch methods become knobs only when they name template knobs (`only: :kick` stays a name).
- Checks: bus names unlike roles and knobs (one namespace), routes and `to:` name buses, no bus loops, send knob names exist, the sidechain is a role.
- Trigger lines (duck-keys, 2026-10-18; maintainer: "dedicated non-sounding line of closed hihats or impulses"): `sidechain :pump, :pump` (a template clip) or `sidechain :pump, grid(...)` (the clip joins the clips under the track's name), `shape: :gate | :impulse`: `#setup` makes the trigger track (dynamics.md, "Trigger tracks") after the buses, `#scene` plays the line under every scene that doesn't name it (`pump: :off` rests it, another clip replaces it; `others: :keep` scenes leave it), roles' `duck:` read `duck(:pump)`, `#trigger_track` names it, `to_ruby` prints `sidechain :pump, :pump[, shape: :impulse]`.  The plain form stays `[track, only]`; a trigger line is `[track, nil, line, shape]`.  Checks: the trigger track is named unlike roles, knobs, and buses, and the line is a clip or kit.  `:dnb` keeps its kick-keyed ducks by default (renders bit-identically to master-ai f6dd8c0d) and offers the old ghost kick's line as `clip :pump` (the two-step) with a tip: `genre(:dnb) { sidechain :pump, :pump }`, or `bin/songs/genre_demo.rb -G dnb -K` (-9.3 LUFS both; bass stem -18.2 vs -18.6 LUFS, sub -19.4 vs -19.8; residual -24.4 dB; Bench `/app/tmp/listening/duck-keys/`).  The template bus ducks (`[:duck, :drums, { only: :kick }]`) still name their own source.
- Padded sidechain rows (`#keyed_kit`) were already generic over `sidechain[1]`: a template whose drums patch is a Machine kit with `voice :trigger, silent: true` can say `sidechain :drums, only: :trigger`, and kits lacking the row get an empty one, as for :kick.  tr808/tr909 presets have no silent voices, so the shipped templates keep padding a real (resting) kick voice.
- Templates using them: `:dnb` (a `:hall` bus, highpassed 250 Hz, wet +12 dB, ducked -6 dB by the kick; sends from drums -24 dB, bass, neuro, impact -20, riser -18; the sub dry), `:techno` (`:rumble`: the drums' lows through a dark hall, ducked -18 dB by the kick, Munro's rumble bus; `:echo`: dotted eighths for the stab, the send following the `:space` knob), `:ambient` (`:weather`: rain and wind `to:` it, through `Genre::Patches.hiss`, pink hiss above 2.5 kHz gated by `input.sounding`, so it stops with the weather; bus steps may name Patches methods taking the input; the `ambient_tape` preset would add wow and wear but costs 27% of realtime per stereo 800-frame buffer, the hiss 1%), `:house` (ducks only).
- The master (fixes-1030, `Template#setup_master`): a template's last mastering preset (`master :club`, `:quiet`) is the `master` call's own preset, the steps before it the block (`master(:quiet) { |m| ... }`, not a block ending in `m.master(:quiet)`; renders md5-identical), so an override (script `--master streaming`, `--reference FILE` (`:match`), `render(master:)`, `Session#mastering_override`) replaces it: one loudness target, a chain ending with its preset, exact targeting (listen-1 found `-G ambient --master streaming` running `:quiet` then `:streaming`, warning of two targets, and `--reference` reporting a level the file didn't have); `--master none` drops it.  `genre_spec` checks every template, with and without an override.  Templates whose preset isn't the last step keep it in the block.
- Set documents save it all (graph_io.md, Set documents): `t.setup; save :x, set` round-trips the buses and routes (`genre_spec`).

## Mono low end (round 2)

Maintainer, 2026-10-13: "Mono bass should be an option; headphones and ambient would not want it unless pressing to vinyl."  `mono_below 120` in a template makes `GraphNode#mono_below(120)` (`DynamicsMethods`: an LR4 crossover per channel, the lows averaged into one channel, the highs untouched; the sum is an allpass) the first stage of its master chain; without it the low end stays as mixed.  Decisions per genre: `:dnb` 120 Hz (club systems; the sub is mono anyway), `:jungle` 150 Hz (cut for vinyl and dubplates, from Nev's research), `:house`/`:techno` 120 Hz (club stubs); `:ambient` and `:funk` never (headphone listening, wide rooms and pads).  `Mix#report(result, data)` adds `side below 120 Hz -38.3 dB re mid (mono_below 120: mono)` (side vs mid power in the FFT bins below the template's frequency, or 120 Hz; "mono" under -30 dB; the crossover's slope leaves side content just above the frequency leaking into the bins below it, so a mono_below master measures about -35 to -40 dB, not -inf).

Techno's bass is `Genre::Patches.roller` (patches-4, 2026-10-13; maintainer: "Roller sub maybe needs filtered noise and/or reverb, clashes with 808 kick"): a short sub sine with a bandpassed-noise tick on every note (24 times the note, 0.34% of the power above 1 kHz), the part above 250 Hz in a small room, ducked -9 dB under the `:peak` kick (`pulse :peak`).

## Levels and the limiter (patches-5)

Maintainer on genre :dnb (2026-10-13): "Mix needs a bit of rebalancing especially in second drop; limiter is controlling everything so relative levels seem to change when neuro stops".  Measured on the short form's stems (`/app/tmp/listening/patches-5/gr.rb`: the stems summed, run through `mono_below` and `dnb_master` offline, matching the render's loudness within 0.1 LU; peaks per 100 ms window before the clipper vs after the limiter): the clipper and limiter together held the drop 8.0 dB down (median), drop2 7.1, the outro 3.9 (so the drums and sub came up ~3 dB when the neuro stopped); the limiter alone 2.1 dB median through drop2, up to 5.5 dB on peaks.  Rebalanced (drums -1 dB, Reese -2, sub -9 (was -6), neuro -5.5 (was -1.5); `dnb_master`'s new `drive` param 8 dB, was 11): clip + limit medians drop 4.1, drop2 2.7, outro 0.8; the limiter alone 0.0-0.3 dB median and 2.6-2.9 dB at the 90th percentile of 100 ms peaks (3.3 in the 2-bar build), 4.0-4.7 dB on the single highest; -9.9 LUFS (was -7.5), so the loudness target became -10..-8.  Drive 10 measured -8.5 LUFS with the limiter's 90th percentile at 3.3-4.1 dB.  Found on the way: scene changes on a playing kit track left rows the new kit lacks playing (the hats-only breakdown kept the drop's kick and snares, the limiter taking up to 14 dB off it); Arrangement now silences them (design/notes/arrangement.md).

## Demo

`bin/songs/genre_demo.rb --genre dnb` (`-G`; `-g` is the script runner's graphviz flag) (generated forms: `-E song|endless -S seed`) builds and plays (or renders) a template's short form, nothing else: `genre(p.genre).short(p.seconds).play`.  `--full` plays the whole form, `-s` sets the length, `--show` prints the template, `--bpm` scales the tempo; `--help` lists the genres.  Renders: `/app/tmp/listening/genre-1/`.
