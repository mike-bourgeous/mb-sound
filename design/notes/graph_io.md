# Graph I/O (recipes and Ruby export)

<!-- summary -->
Every graph remembers the DSL calls that built it (`GraphNode::Recipe`, `lib/mb/sound/graph_node/recipe.rb`), so `node.to_ruby` prints it back as Ruby, and graph documents (`.mbg.rb`, `lib/mb/sound/graph_io.rb` + `graph_io/`: `save`, `preset`, `GraphIO.load`/`.dump`) save graphs, clips, bundles with assets, racks, and whole sets.  Documents load by walking the Prism tree through `GraphIO::Registry`, never eval; file reads go through `GraphIO::FileGuard`.  Every plain value prints through one printer, `MB::Sound::RubyValue` (Rationals as `3/4r` and `3r`; graph document format 7).  A new DSL method taking a build block goes in `BUILD_BLOCKS`; one that reads files or allocates by an argument goes in `Registry::FILE_METHODS` or `Loader#check_limits`.

## Quick reference (from CLAUDE.md, 2026-10-30)

- Printing: `node.to_ruby(inputs: { midi: notes }, seeds: true)` (seeds off by default), console `ruby node`; lanes that differ in values print `per_voice(...)`, anything unrepresentable `nil # FIXME(graph-io): ...`; no flow control.  Round trips: 210/220 graph sweep factories and 31/34 bin synth/effect scripts bit-identical (`spec/bin/recipe_script_sweep_spec.rb` runs under `--tag smoke`).
- Call keys: `Recipe.key_of`, `Recipe.substituting { }` (below, "Call keys and substitutions").
- Document header and lines: `graph 7, name:, kind:, saved:, mb_sound:, from:, description:, options:` (the number is `GraphIO::FORMAT`, 7 since printers-1, 6 since parity-1; `GraphIO::FORMATS` names each version's change), `inputs :midi`, `param :drive, 1.0, range:, description:, cc:`, `knob :cut, 800.0, range:, curve:, cc:` (GraphNode::Knobs, saved at their current value; format 5 writes them typed, `knob :cut, (150.hz..8000.hz).at(2400.hz)`, params.md).  Runtime blocks: the safe subset, else `&named_proc(:x)`, else `trust: :code`.
- API: `GraphIO.load(path_or_text, inputs:, params:, trust:)`, `.parse` (header), `.dump(graph, name:, inputs:, params:, options:)`, `.save`, `.document_of(graph)` (`doc[:drive] = 2` sets every Constant of the param); console `save :dark_hall, g` (never replaces: `save!`, `bump: true`; library.md), `preset :dark_hall, input: mic, mix: 0.6`, `presets`.
- Clips without a recipe save as `events([start, length, value, velocity, { marks }], ..., length:, loop:)` rows; graphs reading files save as bundles (`save(..., bundle: true/false)`); set documents print buses as `bus(:hall, to:) { |sig| ... }`.


## What it does

Every graph remembers the DSL calls that built it ("recipes"), so it can print itself back as Ruby: `node.to_ruby` (alias `to_rb`; also bundles, Synths, Notes, clips), `node.to_ruby(inputs: { midi: notes }, seeds: true)` (seeds are left out by default for reading, maintainer 2026-10-10; phase 2 documents will always include them), console `ruby node` (also `ruby [l, r]`).  fm_bass prints as its own source (lane locals, operators, `13.db`, `100.ms`) and the printed code renders bit-identically.

```ruby
ruby 220.hz.saw.filter(:lowpass, cutoff: 800).delay(1.n16.dotted).softclip
# 220.hz.saw.filter(:lowpass, cutoff: 800).delay(1.n16.dotted).softclip
```

## Recording (`lib/mb/sound/graph_node/recipe.rb`, `recipe/surface.rb`)

- Generated recorder modules are prepended to the DSL surface by `Recipe.install!` (end of `lib/mb/sound.rb`; `Recipe.refresh!` when GraphNode includes a new module): the GraphNode `*Methods` modules plus `#named` (on GraphNode and on every node class that defines a DSL name itself, e.g. `Pitch#tone`, `FourPole#filter`), Tone, Pitch, NotePitch, Notes (plus ModMethods), Channels, Clip/Seq, Note's length methods (`C4.n8`), MB::Sound's top-level graph modules (`Surface::TOP`, plus `file_input`), `Numeric#constant`, `Array#channels`/`#reverb`, `KeyMap.zones`, and `.new` of node classes, filters, Notes, KeyMaps, and drum Kits when called from outside `lib/mb/sound` (`NewRecording` checks the caller; e.g. `GraphNode::Mixer.new(taps)` in a script).
- `Surface::EXEMPT` (per class) and `Recipe::EXEMPT` (GraphNode) list the public methods left out, with reasons (readers, plumbing, things the library calls while sampling); predicates, setters, and `plan_*` are always out.  The guard in `spec/lib/mb/sound/graph_node/recipe_spec.rb` checks that the first method in every node class's ancestry for each DSL name is a recorder, and that every public method of the surface classes and top-level modules is recorded or exempt.
- Outermost calls only: a thread-local depth (`Recipe.state`) means DSL methods calling DSL methods inside the library leave no records.  A call returning a new object stores a `Recipe::Call` (receiver, name, args, kwargs, block, block kind, invocations, scope, seq, seeds, lane, statements) in the object's `@graph_recipe` `Record`; a call returning its receiver appends to the record's configuration list (`Tone#sine`, `#at`, `#named`; not for Pitches, which are values).  An object returned again in another block scope (a channel-wide `v.cc(1)` shared by every lane, a delay pipeline's wet node returned by the delay) gets that scope's call in `Record#scoped`.  The record's owner check ignores records copied by `dup`; `Record#marshal_dump` is nil, so filter objects Marshal-copied per channel carry an empty record.
- Aliases share one recorder (so `instance_method(:additive) == instance_method(:harmonics)` stays true); aliases are recorded under their official name, the method they alias (`Recipe.official_name`: the end of the method's super chain, past recorders and generated dispatchers), with the spelling the code used kept as `Call#written` (block sources are found by it): `.for(2)` prints and saves as `.until(2)`, `.fb { }` as `.feedback { }`, `.saw` as `.saw`, `filt_env` as `filter_env`, `clip.tone` as `clip.hz` (omnibus9, 2026-10-18: the maintainer's rule that saved files use the official name, applied to every alias at the merge review).  `Recipe::KEEP_SPELLING` lists the exceptions with reasons (`*`, note marks `a!`/`s!`, the setter alias `at_rate`, `Channels#channels`); `recipe_alias_spec.rb` fails for an alias whose official name isn't a recorded public method unless it is listed there.  Forwarding methods must be real aliases to be found (Pitch's wave shapes and `amp`/`skew` became `alias`es).  Old documents written with aliases still load (they are public methods).  `#coerce` only raises the depth (`0.5 * node` records the Constant's `*` and prints as `0.5 * node`).
- Build blocks (`BUILD_BLOCKS`: `synth`, `feedback`/`fb`, `delay`/`feedback_delay` inserts, `unison`, `swarm`, `oversample`, `.new`; since added: `map_notes`, `bands`/`multiband`, Kit `fill`, `sampler`, and the rack constructors `rack`/`mrack`/`irack`/... (racks.md)) are wrapped: each call of the block runs at depth 0 as user code and becomes an `Invocation` (args, result, the block's locals, read after it returns from the Binding of its frame, taken through the VM's debug inspector (`FastRecipe.frame_binding`) at the block's first recorded call (scene-build, 2026-10-12: the old `TracePoint(:b_return)` targeted at the block made YJIT discard all compiled code each time it was enabled, so every graph built during playback, e.g. at a scene change, cost the render thread 50-120 ms of recompiling; it also leaked nested blocks' locals into the build block's, e.g. a feedback block's `input` naming the oscillator; `Recipe.locals_mode = :trace` / `MB_SOUND_RECIPE_LOCALS=trace` keeps it for comparison), whether anything drew a seed, statements).  The wrapper proc answers `arity`, `parameters`, `lambda?`, and `source_location` like the block.  Delay insert pipelines record `d.fb { }`/`d.wet { }` as statements of the delay's block (`PipelineRecording` on `InsertPipeline#set_fb`/`set_wet`).  Runtime blocks (`proc`, `spy`, schedules) are never wrapped.
- Bundle channel access (`bundle[i]`, `left`, `right`, `l, r = bundle`, `map`, `each`, `outputs`, `channels`, ...; `ELEMENT_ACCESS`) notes the channels of a recorded bundle as `bundle[i]` and runs at the caller's depth, so `map` blocks stay user code.
- Seeds: `MB::Sound.next_seed` (`SeedRecording`) adds each seed drawn during a recorded call to the call, and marks the build block invocation it ran in.  Seeds drawn inside `MB::Sound.with_seed` derive from its seed (`SeedRecording#with_seed` counts the nesting), so they aren't added to the call, and calls made inside (`Call#lane`: a synth lane or `:seeded`) don't print seeds.  Synth lanes (seed + lane), unison copies (seed + 1 + copy), swarms (one seed for the chord layout and the copies), chorus hiss (seed, seed + 1), and tr808 voices (seed + 1 + voice index) all derive per-copy randomness from one seed of their own (maintainer 2026-10-10: changing which random phases and noise they get needed no A/B), so each prints a single `seed:`; the synth prints its `seed:` when a lane drew one.
- `Recipe.enabled = false` / `MB_SOUND_RECIPES=0` turns recording off (for measurements).

## Printing (`recipe/ruby_writer.rb`, `RubyWriter`)

- Objects used more than once, named by a block local, captured by a block from an outer scope, or (two or more in a scope) drawing random seeds become variables, in the order of their last recorded touch (seeded objects in creation order); everything else stays a chain.  Variable names (maintainer 2026-10-10) come from block locals, else the node's `.named` name (`.named('Bass Osc')` -> `bass_osc`), else a role: `voice` (Synth), `osc` / `lfo` (Tones), `env` (envelopes), `notes`, `clip`, `fx` (results of filters, delays, reverbs, choruses, shapers, feedback loops, resampling; `RubyWriter::FX`), `out` (the final output), `sig` otherwise; never the last method name; numeric suffixes on collisions (`fx2`), `_` after Ruby keywords.  A bare zero-argument call whose name a variable already uses prints with `()` (`noise = noise().named("noise")`; the name is chosen before the right side prints).
- Operators print with precedence-based parentheses; unary minus literals are parenthesized as receivers.  Unrecorded Constants print as numbers in arithmetic (`0.5 * x`) and as `N.constant` elsewhere, with live values (queued `constant=` changes, Multiplier/Mixer `constant=`) winning over recorded ones.
- Values print through `MB::Sound::RubyValue` (`lib/mb/sound/ruby_value.rb`, printers-1, 2026-10-30), the one value printer, which the writer calls with `gains: true` and its own block for nested values (graph objects, template slots); the writer keeps only what needs its state (assets, lengths read from graph objects, steps, blocks, samples, wavetables).  Rationals print as `3/4r`, whole ones `3r`, negative `-3/4r` (the maintainer's decision D6, 2026-10-30: one spelling everywhere, so whole Rationals reload as Rationals; before, the writer printed `3r/4`, Decibels `(3r/4).db`, forms, genre values, and tempo maps whole Rationals as Integers); a quotient Rational binds like `/` (`RubyValue.precedence`: `(3/4r).seconds`, `x * (3/4r)`, `(3/4r).constant`; `3r/4.constant` used to read as `3r / 4.constant`).  Guard: `ruby_value_spec.rb` round-trips its cases in the console and through the Loader and fails Rational formatting anywhere else in lib/ and bin/; recipe_spec's graph sweep round-trips every plain value in each factory's recorded calls (equal, same class).
- Values in their units: `100.ms`, `96.samples`, `lfo.samples`, `1.oct`/`7.st`/`50.cents` (the Interval's own unit, checked to rebuild exactly), Durations (`1.n16.dotted`, `1.n8.triplet`, `3.n16`, `2.bars`; else `k.nN`), Phases, Notes (`A3`) and Pitches (`440.hz`; tempo-synced ones as their Duration, `1.bar.hz`, `3.n16.hz`, patches-1 2026-10-13: they printed their frequency at the current tempo before, so a loaded LFO stopped following the tempo; documents may call Duration#hz and #lfo; other node frequencies get a FIXME), floats exactly k/10 dB as `k.db`, `per_channel(...)` for ChannelValues/ChannelSpread, `Wavetable[:name]` for library tables, `Klass.new(field: ...)` for Data values (`MIDI::ControlSpec`), class names relative to MB::Sound.
- Build blocks print with their parameter names.  Several invocations (synth lanes, unison copies) print once: each lane is printed with its literal values as numbered slots, and if the skeletons match, slots that differ become `per_voice(a..b)` (when the values spread evenly; synths only) or `per_voice(x, y)` (the shortest repeating list); lanes that differ in structure print lane 0 with a warning (decision 10's "lane 0 + warning"; unrolled per-lane blocks were not built).
- Runtime blocks print as their source text, found with Prism from `source_location` (a call name picks among several blocks on one line); a block that reads local variables of the code around it gets a FIXME naming them (`reverse_delay`'s `a`).
- With `seeds: true`, seeds print as `seed: N` where the method takes one (or passes keywords on).  When a call drew a seed that can't be printed (a method without `seed:`, or several seeds outside `with_seed`; rare since the derived seeds above), no seeds print at all and a warning says rebuilds match only in the same order after the same `MB::Sound.seed` (mixing printed and drawn seeds would shift the draw order).  Without `seeds: true` nothing about seeds prints; objects that drew seeds still print in creation order, so a rebuild after the same `MB::Sound.seed` matches.
- Free inputs (unrecorded objects that aren't values) are named from `inputs:` or automatically (`midi` for Notes, `clip`, `input`), listed in a `# inputs:` header; their channels print as `input.outputs[i]`, a recorded bundle's as `bundle[i]`.  Inputs of classes defined outside `lib/` get a FIXME.
- Anything unrepresentable prints as `nil` with `# FIXME(graph-io): ...` at the end of its line and in the header (NArray data, sample-made wavetables, procs without source).
- No flow control: the output is literals, unit methods, recorded DSL calls, local variables, and build blocks, the subset phase 2 will read with Prism (no eval).

## Cost

Measured 2026-10-10 (container, alternating on/off runs in one process, `Recipe.enabled`; noisy, other work running):
- Graph build, best of 9: fm_bass on c_major.mid (oversample 4, 225 recorded calls) 72.6 vs 72.1 ms (+0.7%; medians +3.5%); sq80_voice on dense_modulated.mid (8 voices, 323 calls) 132.7 vs 130.5 ms (+1.6%); a 16-voice synth of 40-node lanes (2594 calls) 349 vs 329 ms (+6.2%; medians -1%).  The prototype measured ~8% on fm_bass.
- Worst case, a loop of cheap DSL calls on one node (`x.softclip`, `x.aclip(-1, 1)`): +3.6 to +4.9 us per call (+21 to +24%), about half of it GC (with GC off +2.5 us, +19%).  Recording a call allocates a Call (160 B), a Record (80 B), and its args/kwargs (~200 B): ~0.4-1.5 KB per call by `memsize_of_all` deltas (fm_bass +224 KB, sq80_voice +476 KB, the 16-voice synth +1.8 MB), mostly kept alive by the graph anyway.
- Sampling is unchanged (nothing records at sample time): 200 x 512-sample buffers of a 100-node chain built with and without recording, 64.5 vs 63.5 ms (best of 5).  Inner DSL calls made inside the library pay only the recorder's argument splat and a thread-local depth check.
- Rerun by toggling `MB::Sound::GraphNode::Recipe.enabled` around graph builds in one process (alternating), e.g. `MB::Sound.fm_bass(MB::Sound::Notes.new('spec/test_data/c_major.mid'))` after loading `bin/synths/fm_bass.rb`.

## Graph documents (phase 2, branch `graph-io-2`, 2026-10-11)

Saved graphs are `.mbg.rb` files: the Ruby `to_ruby` prints (with seeds) after a header, read back without running them as Ruby.  `lib/mb/sound/graph_io.rb` (API, limits, presets, console), `graph_io/loader.rb` (Prism walker), `graph_io/registry.rb` (what may be called), `graph_io/document.rb` (Document, Writer), `graph_io/trusted_code.rb` (the opt-in eval).

```ruby
# mb-sound graph document: a Ruby subset that MB::Sound.preset and
# MB::Sound::GraphIO.load read without running it (no eval).
graph 3,
  name: "tape",
  kind: :effect,
  saved: "2026-10-11T03:59:05Z",
  mb_sound: "0.12.0.usegit (8d22e350)",
  from: "bin/effects/tape_delay.rb",
  options: { pitch: false, delay: 0.1, feedback: 0.75, smoothing: 2.0, oversample: 2.0 }
inputs :input
param :dry, 1.0, description: "Dry (input) level"
param :wet, 1.0, description: "Wet (echo) level"
param :drive, 1.0, description: "Input gain into the tape"

input2 = input[0].resample(mode: :libsamplerate_fastest).named("input")
...
[(dry * input2 + wet * (input2 * drive).delay(0.1, feedback: 0.75, smooth: 2.0) { |fb| ... }, ...].channels
```

- Format 4 (racks-r2, 2026-10-17): typed inputs (`inputs sig: :audio, side: :audio, depth: [:control, 0.5]`; untyped `inputs :midi`/`:input` still load, as notes/audio; `Document#input_types`, `#input_defaults`), optional `outputs :audio` (`Document#outputs`), rack documents (`graph 4, kind: :effect, rack: :arack`, `Document#rack?`; knob lines are the rack's knobs and may take `share:`/`follow:`; `GraphIO::RackWriter`, `Loader#load_rack`; loading gives a Rack, or the applied instance with inputs), and graph documents carrying definitions of the named racks they apply (`arack(:dub, ...) { ... }` before the graph; a session's own definition wins; a bare `rack(:x)` falls back to a rack document among the presets).  Details in racks.md.  Sums ring since format 4 too; older documents build their sums (also set documents' graph tracks, and patches and other blocks built later, through `Loader#build_proc`; omnibus9, 2026-10-18) inside `Mixer.with_ring(:first)`, and those sums print as `.ring(:first)`, so saving again as format 4 keeps the ending (spec: graph_io_sets_spec's format 3 fixture).
- Header: `graph N, **meta` first (N is `GraphIO::FORMAT`, 7 since printers-1 (2026-10-30, values through RubyValue), 6 since parity-1 (2026-10-30, clip `shift` no longer wraps), 5 since param-1 (2026-10-24, typed `param`/`knob` lines; params.md), 4 since racks-r2, 3 since db-1, 2026-10-14: format 3 reads bare dynamics levels, gains, and compand points as linear gains, older documents as dB with one warning (dynamics.md, Units); format 2 (omnibus7, 2026-10-13) marks drawn seeds, below; newer versions refuse to load; meta is informational: name, kind, saved, mb_sound version and commit, from, `description:` (what the graph is and where it came from; `Document#description`; scripts give it with `synth_script(description: ->(p) { ... })` / `effect_script(description:)` for `--save`, `GraphIO.dump(meta: { description: })` otherwise, and a re-save of a loaded document keeps it; patches-2, 2026-10-13: the library presets' descriptions credit the persona panel), and `options:`, the script parameters baked into the graph), then `inputs :a, :b`, one `param :name, value, range:, description:, cc:, curve:, unit:` per param (ControlSpec-shaped), and one `knob :name, value, range:, curve:, unit:, cc:, takeover:, smooth:, description:` per `GraphNode::Knob` in the graph (omnibus4, 2026-10-11: the console's `knob` syntax; loads as one Knob per line, read by every use, overridable like a param, `Document#knob?`, `Document#set` turns it at the knob's next frame with its declick glide; knobs join a Session when it plays the graph or the console's `preset` loads it (omnibus6; see arrangement.md, Knobs, graph-io); a moving knob saves its last rendered value after a `# :cut was ramping to 3000 when saved; ...` comment; two different knobs with one name, or a knob named like a param or input, raise DumpError).  Headerless text (plain `to_ruby` output) loads too, with inputs from its `# inputs:` comment.
- Inputs bind by name (`inputs: { midi: notes }`); missing ones raise, extra ones warn.  Params: each use of a param's name is a new `value.constant.named(name)` (as scripts make them: one Constant shared by tape_delay's two channels changed the right channel, since oversample set the rate of everything upstream and a node shared between an oversampled and a plain branch read at two rates; between two oversample regions after a resample the output differed by up to 0.92; fixed in the library by omnibus4, see graph_nodes.md, and the per-use Constants stay so documents render like their scripts).  `GraphIO.document_of(graph)[:dry] = 0.5` sets every Constant of a param; overrides on load (`params: { drive: 2 }`) are numbers, or (genre-1 round 2, maintainer 2026-10-13: "template knobs can drive presets' own params") a graph node or a Symbol naming a knob of the Session (`preset :dnb_reese, midi: riff, cutoff: :cut`, `params: { depth: 0.3.hz.lfo.at(0..1) }`); overriding a baked option raises with a "change it in the script" hint.
  - Bound params (`Loader#bound_param`): every use of the param reads that one node (consumers branch it with `get_sampler`: a Tee, or a new reader per use for a Knob), a `knob` line bound this way makes no Knob of its own, and the document's default stays its value (`param_values`); `Document#set` raises for a bound param ("turn :cut instead"), and `preset` turns joined knobs only for numeric overrides.  A re-save prints a bound knob as a `knob` header line of the Session's knob, not as the param.
  - Safety rules unchanged: bindings come only from the caller's Ruby (the `params:`/`preset` keywords), never from document text (`param :x, :cut` and `param :x, 1.constant` still raise "needs a number"); knob names resolve only through the Session's knob table (`Session#knobs`: the loader's session, else `Session.existing`; never created, never `const_get`), and an unknown name is a `LoadError` with did_you_mean suggestions and the session's knob names; nodes are taken as given (no Registry check, since they are the caller's objects).  Found on the way: a call in a header value (`param :x, 1.constant`) raised a NoMethodError before the call limits were set; the loader now sets them before the header.
- Loader (`GraphIO::Loader`): size, syntax-node count, and nesting depth are checked iteratively before anything runs, and so is forbidden syntax anywhere in the file (if/unless/case/ternaries, loops, def/class/module, backticks, globals, ivars, cvars, interpolation, regexps, `&.`, `&&`/`||`, begin/rescue, splats, multiple and operator assignment, implicit block parameters, `self`, `__FILE__`, BEGIN/END) and forbidden names (`Registry::FORBIDDEN`: eval family, send/public_send/__send__, method/define_method, const_get, ivar access, binding, system/exec/spawn/fork/backticks/popen, require/load, exit/abort/at_exit/trap; `Registry::KERNEL` without a receiver: proc, lambda, loop, sleep, puts, rand, ...).  Then the walker evaluates literals (numbers, Rationals, Complex(), strings without interpolation, symbols, ranges, arrays, hashes), locals (Prism depth picks the scope), constants (`Registry::CONSTANTS`, built from loaded classes: classes whose `.new` is recorded, library Data values, `Wavetable`, `KeyMap`, `Sequence::Duration`, seq markers, Note names, `Float::INFINITY`; never `const_get` with document text), and calls checked against `Registry.allowed?` (the `Recipe.wrapped` names of the receiver's ancestors, numeric unit mixins, `Registry::VALUES`, class methods; bundle iteration with blocks is out) and made with `public_send`.  Errors are `GraphIO::LoadError` with `path`, `line`, and did_you_mean hints; exceptions raised by DSL calls are wrapped with the line.
- Blocks: build blocks (`Registry::BUILD_BLOCKS` = `Recipe::BUILD_BLOCKS` + `wet`) become procs that walk their bodies per call in a new Scope, answer `arity`/`parameters`/`lambda?` like the literal block, and hand their locals to the recorder (`graph_io_locals`, used by `Recipe.trace_locals` instead of a TracePoint), so a loaded graph re-dumps to the same text (193/193 sweep factories).  Runtime blocks (`proc { |buf| ... }`, lambda values) are checked against the safe subset at load (`Loader#runtime_problem`: arithmetic and `Registry::RUNTIME` math methods, `Math`/`Numo::NMath`, their own parameters and locals; no outer reads, no blocks) and interpreted on each call; they keep their text (`graph_io_source`) for printing.  Outside the subset: `&named_proc(:fold)` from `MB::Sound.named_proc(:fold) { |buf| ... }` (the writer prints registered procs that way), else `trust: :code`, which evals the block's saved source in `TrustedCode` after a warning (off by default).
- Limits (`GraphIO::LIMITS`, `limits:` per load): 1 MB, 250k syntax nodes, depth 400, 100k DSL calls, 30 s build time, delays (positional, `seconds:`, `max_delay:`, multitap taps; Durations at the slowest tempo) 60 s, `silence`/`until` 600 s, `with_buffer` 2^20 samples, oversample 16, resample 768 kHz, synth voices 64, unison/swarm copies 64, clip repeat-like counts 4096, integers 64 bits (and `n ** k` with k > 64).  Files (`file_input`, `midi_file`) only relative to the document's directory (no absolute paths or `..`), and only for documents loaded from files or with `base_dir:`.  The library's own checks (envelope segments, harmonics) cover the rest; a new DSL method that allocates by an argument needs a line in `Loader#check_limits`.
- Writer (`GraphIO.dump` / `Writer`): the RubyWriter with `seeds: true`, `knobs:` (Constants named after a param with its value print as the bare name; the writer's `knobs_used` picks which params get `param` lines, the rest go to `options:`) and `knob_nodes:` (a loaded graph's own Constants, and its Knobs, which print as their bare names after the `knob` header lines); plain `to_ruby` prints a Knob or Knob reader as `knob(:cut)` (inline, since each reads the Session's knob on its own; 2026-10-12: before, as a free input); FIXMEs raise `GraphIO::DumpError` (problems, code). ## Decisions (maintainer, 2026-10-10)

1. Basis: recorded outermost DSL calls with introspection as fallback, now; long term "both, split at the library boundary" (declared-parameter library nodes plus recorded project builders), a later project.
2. Text format (phase 2): "Ruby for now, with the hope of a declarative diffable graph long term": saved files will be a Prism-parsed Ruby subset (no eval), which `to_ruby` already prints.
3. Saved patches follow library changes.  4. Recording always on.
5. Runtime blocks: safe-subset blocks, a named registry, and opt-in `trust: :code` later (phase 2); phase 1 prints Prism source with FIXMEs.
6. Names: console `ruby node`, `node.to_ruby`; `.mbg.rb` files and save/preset/presets are phase 2.
7. No flow control in printed code; optional repeat/spread syntaxes instead (`per_voice`, `per_channel`).
8. Script params become `params:` in phase 2 (phase 1 prints them as `1.0.constant.named("drive")`).
10. Lanes that differ: `per_voice(list | range)` (built, see MIDI notes) and `per_channel(list | range)`.

Phase 2 decisions (maintainer, 2026-10-10/11): files are a Prism-walked Ruby subset against the recorded registry, never eval/instance_eval/Marshal/YAML.load (JSON a machine twin if cheap); saved patches follow library changes (a `rails new`-style project generator later; Gemfile.lock pins the sound per project); new node types should replace proc nodes where possible, runtime blocks load from the safe subset, then named procs, then opt-in `trust: :code`; names `.mbg.rb`, `save`, `preset` (not `load`, Kernel#load), `presets`, `ruby`; presets in a project's `presets/` or the user data dir, path printed; no flow control, optional repeat/spread syntaxes; script params become `params:` with overrides on load; state snapshots deferred (P4; maybe a .zip or MessagePack container instead of sidecars).

## Params (param-1, 2026-10-24)

`param` and `knob` header lines build `MB::Sound::Param`s at load (`design/notes/params.md`): a line whose default is outside its range, whose range ends mix types, or whose curve is unknown is a LoadError at its line; `spec[:param]` and `Document#declarations` hold them.  Lines also accept the canonical ranged spelling (`param :depth, (0.0..1.0).at(0.5)`, `knob :cut, 800.0.in(100.0..8000.0)`; Registry allows `Range#at` and `#in`), but documents still write format 4's `param :x, v, range: lo..hi` (`Param#document_line`, the same text), so the format didn't change.  Param overrides outside their range go through `Param#check` (raise in scripts and specs, limit with a warning live; was a warning).  A range saved high to low declares low to high and is kept as written.

Format 5 (param-1 round 2, 2026-10-24, the maintainer's "typed docs + bump"): `param` and `knob` lines are written in the canonical spelling with typed values (`param :cutoff, (20.0..10000.0).at(500.0), description: "..."`, `knob :cut, (150.hz..8000.hz).at(2400.hz)`, `clamp: false`); `spec[:value]` holds the base-unit number (params bind as Constants), typed overrides (`cutoff: 3000.hz`) and `Document#set` take unit values.  Older documents keep loading.  The shipped presets were rewritten and render the same.

Format 6 (parity-1, 2026-10-30, maintainer's D5': "rotate wraps and shift shifts"): `Clip#shift` (and Seq's) moves notes without wrapping, dropping those that leave the clip; it was an alias of `#rotate`.  The loader reads `.shift(` on a clip in documents before format 6 as `.rotate(` (`Loader` `@old_shift`, from `GraphIO.since?(version, :clip_shift)`; resaved, they print `rotate`).  Recipes printed the alias's calls as `rotate` already, so only hand-written documents carried `shift`.  None of the shipped presets uses clip shift; `bin/save_presets.rb --check` compares bodies without the format number, so a bump alone doesn't mark every preset out of date.

Format 7 (printers-1, 2026-10-30, the maintainer's D6: `3/4r` and `3r` everywhere through one helper, though saved text changes): every value prints through `MB::Sound::RubyValue`, so Rationals read `3/4r` and whole ones `3r` (events rows, forms, scene `q:`/`fade:`, tempo maps, genre values), Decibels `(13/2r).db`, and rack `using(...)` knob values print exactly (they were rounded to 6 significant figures, `Knob.number`).  No loader rule changes: `3r/4` and `3/4r` are the same Rational, and older documents' Integers load as Integers, as before.  Format numbers live in `GraphIO::FORMATS` (version => the change's name; loaders ask `GraphIO.since?(version, :linear_gains)`), so branches adding versions touch only that table.  The shipped presets were saved again (`bin/save_presets.rb`).

## Call keys and substitutions (envelope-view-1, 2026-10-27)

`Call#ordinal` counts each scope's recorded calls by name (a build block invocation's own counter; at the top level only inside `Recipe.counting`, which Arrangement tracks wrap their patches in), `Recipe.key_of(call)` names a call by its chain of enclosing build calls and ordinals (`[:top, :synth, 0, :lp4, 0]`, the same for every invocation, so every synth lane), and `Recipe.substituting({ key => ->(args, kwargs) { [args, kwargs] } }) { build }` runs the same code with those calls' arguments replaced; the calls record what they were given, so the graph prints `lp4(1200.hz, resonance: knob(:"bass/reso"))`.  The recorders pass the arguments through the block (`{ |b, a = args, kw = kwargs| super(*a, **kw, &b) }`), keeping what the method gets apart from what is recorded (a drawn seed given back by a loader reaches the method but isn't recorded as given).  Used by live literals (sound_design_ui.md).

## Params as track knobs (library-instruments-1, 2026-10-28)
