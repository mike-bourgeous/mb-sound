# Multichannel

<!-- summary -->
Every node has `outputs`/`channel_count`; `GraphNode::Channels` is the bundle (`stereo(l, r)`, `channels(a, b, c)`; Array-like but deliberately not Enumerable: `.to_a` for `shuffle` etc.).  DSL calls on bundles run per channel with NumPy-style broadcasting (per-channel arguments via bundles or `per_channel(list | a..b)`; `per_voice` in synth voices); `reverb` is the exception (one reverb for all channels).  Conversions are `GraphNode::ChannelMixer` nodes (`pan`/`balance`, `width`, `mono`, `swap`, `mid_side`, `matrix`, `place`, `left`/`right`); sample all outputs of a mixer in turn.  Pan laws (`ChannelMixer::PanLaws`): mono `:equal_power` (default), `:minus_4_5db`, `:linear`; stereo `balance(x, law:)`/`pan(x, law:)` take `:balance` (default) or ACID's `:constant_power`, `:balance_0db`/`_3db`/`_6db`, `:add_channels` (provisional), all planned bit for bit.

## Quick reference

- Bundles: `stereo(l, r)`, `channels(a, b, c)`, `[l, r].channels`, `per_channel(list | a..b)`, `per_voice` in voices; `.to_a` for Enumerable methods.
- Mixers (`GraphNode::ChannelMixer`): `pan`, `balance`, `width`, `mono`, `swap`, `mid_side`, `matrix`, `place`, `left`/`right`.
- Pan laws: `PanLaws.gains(law, x)` (mono, [l, r]), `PanLaws.stereo(law, x)` (stereo, a 2x2 matrix), `PanLaws::LAWS`/`STEREO_LAWS`; `stereo.balance(4.bars.lfo, law: :add_channels)`; spec `spec/lib/mb/sound/graph_node/channel_mixer/pan_laws_spec.rb`, plan cases in `spec/lib/mb/sound/plan/channel_mixer_ops_spec.rb`.
- Code `lib/mb/sound/graph_node/channels.rb`, `lib/mb/sound/graph_node/channel_mixer/`; spec `spec/lib/mb/sound/graph_node/channels_spec.rb`; demo `bin/songs/stereo_song.rb`; help `help :stereo`.

Detailed notes moved from CLAUDE.md (2026-10-10); the summary block above feeds the generated index (`design/notes/README.md`, `rake docs:index`).  Update it when behavior changes.


Every GraphNode has `outputs` (`[self]` for one channel) and `channel_count`; nodes with several outputs (stereo file inputs, multi-output reverbs, `MultiOutput`s) act as bundles.  `GraphNode::Channels` (`lib/mb/sound/graph_node/channels.rb`) is the bundle class: `stereo(l, r)`, `channels(a, b, c)`, `[l, r].channels`, `node.stereo`; it is Array-like (`[]`, `each`, `map`, `l, r = bundle`) but deliberately not Enumerable (`Enumerable#filter` is `select`).  `GraphNode::ChannelDispatch` (loaded last in `graph_node.rb`) generates a per-channel version of every `*Methods` module method, so DSL calls on a bundle run per channel and return a bundle.  Channel counts combine like NumPy broadcasting (1 is reused, N-N per channel, other mismatches raise); per-channel arguments are bundles, `channels(0.010, 0.013)` of plain values, or lazy `spread(a..b)`; `per_channel(list | range | nodes)` (written `per_channel(list | a..b)` for values; 2026-10-10, naming direction with `per_voice`, see MIDI: in synth voice blocks `per_voice(list | a..b)` gives per-lane values) is the one spelling for all three (values -> `ChannelValues`, a Range -> `ChannelSpread`, nodes -> a bundle), with `channels`/`spread` kept as aliases; filter objects are Marshal-copied per channel.  `reverb` is the deliberate exception: a bundle's channels all feed one reverb.

Conversions are `GraphNode::ChannelMixer` nodes (`lib/mb/sound/graph_node/channel_mixer/`): one N-in/M-out gain-matrix node per call, a subclass per mixing law declaring its channel counts, `param`s (numbers or nodes read every sample; numeric gains are computed once) and `option`s, with `#params`/`#gains`/class-level `.params` for introspection.  `pan(pos, law:)` (`ChannelMixer::Pan`; laws `:equal_power` default, `:minus_4_5db`, `:linear`; stereo bundles balance, the common DAW default, also `balance`), `width(w)`, `mono`/`mixdown`, `swap`, `mid_side`/`from_mid_side`, `matrix(rows)` (any N->M, entries numbers, complex, or nodes; replaced `MatrixMixer`), `place(x:, y:)` (alias `position`; phase-amplitude Lt/Rt positioning, replaced `ComplexPan`), plus `left`/`right`.  Complex gains send every input through the same Hilbert stage (`ChannelMixer::Analytic`) and output real parts unless an input was complex.  Mixer outputs advance to a new frame when an output is sampled again, so sample all outputs of a mixer in turn (as a Session does).  Mixers with real number gains are planned (channelmixer-1, 2026-10-23; `plan_layer.md`): the mixer roots a fused region computing every output, so a unison's oscillators fuse with their pitch and the mix.  `master { |mix| ... }` gets the whole mix as a bundle.  `graphviz` collapses each per-channel call into one box listing per-channel arguments (`expand_channels: true` shows every node).  Deferred (local idea notes): surround layouts/matrix presets and encoder-aware `place` laws (with the user's private surround work), dual/stereo pan modes, `.widen`/`.haas`/ping-pong, `Mixer` accepting bundles, mixer fusion (graph optimizer), vectorized N-channel nodes.  See `bin/songs/stereo_song.rb`.

## Stereo pan laws (pan-laws-1, 2026-11-04)

The maintainer, about the ACID pan laws the Linux session measured: "These would be good pan laws to include in the standard channelmixer node."  `ChannelMixer::Balance` has `option :law` (one of `PanLaws::STEREO_LAWS`, default `:balance`, unchanged); `Channels#balance(x, law:)` picks one, and `Channels#pan(x, law:)` on a stereo bundle passes the stereo names through (the mono names, the default `:equal_power` included, still give the default `:balance`, as before).  A stereo law on a mono `pan` raises with the mono choices; mixer options are `MB::Sound::Param`s, so a misspelled law suggests the nearest.  `PanLaws.stereo(law, x)` gives `[[L to L, R to L], [L to R, R to R]]` (x in -1..1, + right):

| law | ACID name | center | x >= 0 (mirrored for x < 0) |
|---|---|---|---|
| `:balance` | (mb-sound's DAW balance) | 1 | L' = min(1, sqrt(2) cos((x + 1)pi/4)) L, R' = R |
| `:constant_power` | Constant Power, Film (same in stereo) | -3 dB | L' = cos((x + 1)pi/4) L, R' = sin((x + 1)pi/4) R |
| `:balance_0db` | Balance 0 dB | 1 | L' = (1 - x) L, R' = R |
| `:balance_3db` | Balance -3 dB | g = 0.7071 | L' = g(1 - x) L, R' = (g + (1 - g)x) R |
| `:balance_6db` | Balance -6 dB | 0.5 | L' = (1 - x)/2 L, R' = (1 + x)/2 R (the mono `:linear` law per channel) |
| `:add_channels` | Add Channels (ACID's default) | 1 | L' = (1 - x) L, R' = R + x L |

"Applied to each stereo channel" (constant power) means a diagonal matrix: each input channel keeps its own side's gain of the mono `:equal_power` law, nothing crosses (the study's `pan_matrix` is `[cos a, 0, 0, sin a]`); likewise `:balance_6db` is the mono `:linear` law per channel.  Only `:add_channels` crosses channels: the far channel moves into the near one, so a hard pan is the mono sum L + R on one side, and L + R is unchanged at every position (the maintainer: it "gradually mixes a stereo input to mono at extreme left/right pan so no sound disappears except by possible phase cancellation").

Source of truth: branch `research-acd-format-linux` df0870d6, `research/acd-format/acd/audio_render.rb` `pan_matrix`/`pan_matrices`; the balance and constant-power laws null against ACID's render of a pan-law reference project to that study's -12.7 dB floor.  **`:add_channels` is provisional**: modeled from ACID's description, not yet measured against a render (whether ACID scales the sum); a reference project with the default law panned hard left, hard right, and half way would settle it.  `pan_laws_spec.rb` checks every law against formulas written out independently and a copy of `pan_matrix` (equal for numbers; within 2e-7 for SFloat positions).

Plan layer: fixed positions plan as `Op::Mix` weights, like every numeric mixer.  Moving positions: `:balance` and `:constant_power` use `Op::PanGain` (`:balance`, `:equal_power`); the straight-line laws are written once in `PanLaws.linear_stereo` over anything with `*`, `+`, and a clip block, so the unplanned mixer (numbers, NArrays) and `Balance#plan_describe_moving` (plan Values: clips, products, sums) run the same float32 steps, bit for bit without a new op or C change (for `:balance_3db`, 3 clips and 11 products and sums before the two output products).  Swept by the graph sweep ("balance laws") and the relation fuzz (half its pan steps balance a stereo input by a random stereo law; 43 such graphs among seeds 1..1200 held every relation, 2026-11-04).
