# Scripts

<!-- summary -->
Every bin/ script except the console `bin/sound.rb` uses a `ScriptingMethods` helper backed by `ScriptRunner`: `effect_script { |input, p| }`, `synth_script { |midi, p| }`, `song_script(bars:) { |p| }`, or `script(args:) { |args, p| }`, sharing `-o`, `-f`, `-g`, `-P`, `-q`, `-L`, `--ui [LAYOUT]`.
Parameters are options only (`name: [default, 'description', '-x', Type, range]`); graph-building code goes inside the block, loadable scripts are guarded with `if main_script?(__FILE__)`, and every script starts with the `RUBY_THREAD_TIMESLICE=10 MB_SOUND_YJIT=1` shebang (`spec/bin/shebang_spec.rb`), never `RUBY_YJIT_ENABLE=1`/`--yjit`.
Plain song files start with `require 'mb/sound/dsl'` (`MB::Sound::DSL`): the console's commands and note names at the program's top level, waiting for background playback at its end.
<!-- /summary -->

## Quick reference

- Helpers: `effect_script { |input, p| }`, `synth_script { |midi, p| }`, `song_script(bars:) { |p| }`, `script(args:) { |args, p| }`; options only (`name: [default, 'description', '-x', Type, range]`), graph code inside the block.
- Shebang `#!/usr/bin/env -S RUBY_THREAD_TIMESLICE=10 MB_SOUND_YJIT=1 ruby` (`spec/bin/shebang_spec.rb`); plain song files `require 'mb/sound/dsl'`.
- New scripts go in the smoke tables (`spec/bin/script_smoke_spec.rb`, `bundle exec rspec --tag smoke`); code `lib/mb/sound/script_runner.rb`.

Detailed notes moved from CLAUDE.md (2026-10-10); the summary block above feeds the generated index (`design/notes/README.md`, `rake docs:index`).  Update it when behavior changes.


Every bin/ script except `bin/sound.rb` is built on one of four helpers in `ScriptingMethods`, backed by `ScriptRunner` (`lib/mb/sound/script_runner.rb`, OptionParser):

- `effect_script(input_channels:, live_channels:, **params) { |input, p| graph }` - the input is an audio file (first audio argument or `-i`, rung out with a `Ringdown` node until 1 s of quiet, 10 s cap) or live input (`-c/--input-channels`); `--repeat [COUNT]` loops the file.  `-m/--midi SOURCE` takes `p.midi_cc` controls from a MIDI port (part of its name) or a `.mid` file (played with the graph, also in `-o` renders; `p.midi` is that Notes); only the input's `Ringdown` decides when a file effect ends (live MIDI control nodes never end).
- `synth_script(**params) { |midi, p| graph }` - `midi` is a `MB::Sound::Notes` on the MIDI file or live port given (`-i` or a non-audio argument; by default the script's own port), like the console's `midi`: a mono voice applying the sustain pedals (`midi.hz.saw * midi.amp_env`; `Notes.new(midi.stream, sustain: false)` ignores them) and a source for synths (`midi.synth(voices: 6) { |v| ... }`, `Synth.new(midi)`, `MB::Sound.synth(midi, ...)`).  A MIDI file rings out: once it has ended and every voice is idle (`Synth#ended?` or the Notes nodes' `#ended?`), the runner stops after a second of quiet (10 s tail limit), like effect file inputs (`Ringdown#ended?`); a Synth itself returns nil only `tail:` (`MIDIFile::TAIL_SECONDS`) later, for players without tail detection.  Converting old patches (all of `bin/synths/` and `bin/wavetable_pr_example.rb` use Notes/Synth): `midi.env(...).db(N)` became `fm_env`/`amp_env` with curve -N rising, (1 - s) × N for the decay and s × N for the release (N with sustain 0), the sustain and the old 0.5..1 velocity range mapped through the same curve (see fm_bass.rb, fm_bell.rb); plain `midi.env` amplitude envelopes keep -6..0 dB velocity; fixed-ratio operators are `v.hz.transpose(Math.log2(r).oct)` (key-synced), node ratios `(v.freq * node).tone.reset(v.key_trigger)` (fm_bell.rb), `reset(v.trigger)` for tones and per-voice LFOs that restart at every note-on (drums); `named('portamento')` filters became `v.hz.glide(t)`.  `bin/synths/fm_chain.rb` (the 2021 chained fm_synth: each held note FM-modulates the previous one) is a script-local GraphNode reading `midi.note_stream` per buffer and splitting buffers at event samples.
- `song_script(bars:, **params) { |p| ... }` - the block arranges the song on the current session (`bg`, `at_bar`, `master`); `-b/--bars N` plays or renders N bars (live too), `--stems DIR` (renders only) also writes each track to DIR (see `render(stems:)`, method_modules.md), `--bpm` sets the starting tempo and scales the song's tempo changes (`Transport#override_bpm`), `--graphviz` draws the session at the start (`Session#graph_view`).  Render windows (omnibus8 `fixes-prepanel-1`, 2026-10-17; panel Kez #8): `--from WHERE` (a section, label, or marker name, or a bar number) and `--to WHERE` (instead of `--bars`) render one part of the song through `render(from:, to:, preroll:)`; `--bars` counts from `--from`, and `--from` alone ends at the song's own `bars:` (`to: bars + 1`); `--seek` renders with `preroll: false`.  Live, `--from` seeks there (`MB::Sound.seek`, waiting for it to land; fresh state) and `--bars`/`--to` stop after it.  `--take [FILE]` records the run (render or live) as a take and saves its replay script (see arrangement.md, Takes).  `--reference FILE` (listen-1) masters like a reference track (`--master match`, implied; master_effects.md, Reference mastering), `--tilt auto|off|DB` sets its tilt EQ (measured in renders, none, or a fixed dB/octave); `--master match` without a reference, `--reference` with another preset, or `--tilt` without `--reference` is an input error.
- `script(args:, **params) { |args, p| ... }` - general scripts (utilities, plots, file processors, benchmarks, MIDI tools): only `-h/--help` is common, positional arguments go to the block (`args:` Integer/Range checks their count; negative numbers stay positional).

In short: `effect_script { |input, p| }` (file or live input, rung out with `Ringdown`; `-m` MIDI controls), `synth_script { |midi, p| }` (`midi` is a `Notes`; file renders ring out), `song_script(bars:) { |p| }` (`-b`, `--bpm`), `script(args:) { |args, p| }`.

Effects, synths, and songs share `-o/--output` (or a positional audio file) to render instead of playing, `-f/--force`, `-g/--graphviz`, `-P/--plot`, `-q/--quiet`, `-L` (a latency profile, audio_io.md), `--ui [LAYOUT]` (below), and play through the background `Session`.  Parameters are options only (no positional numbers): `name: default` or `name: [default, 'description', '-x', Type, allowed_range_or_array, :required]` in any order after the default (`name: [default, 'description', '-x', Type, range]` in the common case); bad values print the option help.  `p.midi_cc(1, :hz, range: 0.0..6.0)` (`p.midi_cc(1, :hz, range:)`) gives a Notes controller node (range relative to the value; its `MIDI::ControlSpec` has the parameter's name and description, listed by `p.midi.controls` and the script's control listing) when MIDI is open (live unless rendering, or `-m FILE`), else a constant; a value inside the range is the knob's center (raw 64, each half linear), else the nearest end, so it starts at the value.  Graph-building code belongs inside the block (`--graphviz` runs song blocks twice).  Guard scripts that can also be `load`ed with `if main_script?(__FILE__)`.  Every script starts with `#!/usr/bin/env -S RUBY_THREAD_TIMESLICE=10 MB_SOUND_YJIT=1 ruby` (checked by `spec/bin/shebang_spec.rb`; see Audio I/O for the time slice).  `MB_SOUND_YJIT=1` makes `lib/mb/sound/jit.rb`, the first file `lib/mb/sound.rb` loads, call `RubyVM::YJIT.enable(call_threshold: MB::Sound::JIT::CALL_THRESHOLD)` (yjit-threshold-1, 2026-10-25): Ruby fixes YJIT's call threshold when YJIT starts (measured on 4.0.9: once `RUBY_YJIT_ENABLE=1` or `--yjit` started it, `enable(call_threshold:)` returns false and methods still compile after 30 calls), so the shebangs no longer start YJIT at boot.  `MB_SOUND_YJIT_CALL_THRESHOLD=n` overrides the threshold (A/B runs: `MB_SOUND_YJIT_CALL_THRESHOLD=30 bin/scene_profile.rb ...`); YJIT already on when mb-sound loads keeps Ruby's threshold; benchmarks comparing YJIT on and off in children pass `MB_SOUND_YJIT` and unset `RUBY_YJIT_ENABLE` (`osc_state_benchmark.rb`, `plot_benchmark.rb`).  YJIT roughly halves graph cost (fm_bass at 128-sample buffers under the profiler: ~190% of realtime without, ~85% with; +8 MB RSS) but compiles methods only after many calls, so live paths (`ScriptRunner` live play, `bin/sound.rb` startup) call `MB::Sound.warm_up` (`lib/mb/sound/warm_up_methods.rb`; nil without YJIT) before the first output write: a throwaway graph of common nodes (~0.2 s; first-buffer stall ~55 ms to ~14 ms), plus MIDI voices in synth scripts (`warm_up(midi: true)`; ~0.35 s; ~50 ms to ~14 ms).  `ruby bin/x.rb` and specs run without YJIT.

Persona panel patches (patches-1, 2026-10-13; named for their genres in patches-2 (Tiko's rig as `funk`, the jungle Rhodes as `jungle_keys`, by the maintainer), maintainer: "there's no context for someone else", with the file comments and preset descriptions giving the provenance): `bin/synths/dnb.rb` (Kez Volta's), `jungle.rb` (Nev Ashdown's), `ambient.rb` (Kaede Rowntree's), and `funk.rb` (Tiko Marvell's) hold the four persona agents' instruments (research branches `research-persona-*`), one self-contained method per patch taking a MIDI source with its knobs as keywords (`dnb_reese_voice(midi, cutoff:)`; maintainer: kept so a later instrument/library project can convert them mechanically), selected by `-p` through `<script>_patch(midi, patch, **params)`, which makes the script's numeric options named Constants so `--save` turns them into preset params; `bin/songs/tunnel_vision.rb`, `memory_card.rb`, `tin_roof.rb`, and `loop_church.rb` build their tracks from those methods.  `bin/save_presets.rb` saves them (and four effect methods) into the library's `presets/` (see graph_io.md), each with a `description:` from the script's `<script>_description(patch)` (passed as `synth_script(description:)`).  `bin/synths/electric_pianos.rb` (patches-2, 2026-10-13; the maintainer asked for an FM piano closer to a physical Rhodes or Wurlitzer than the jungle keys, `jungle_keys_voice`) has `tine_piano_voice` (1:1 FM bark growing with velocity squared, a 14:1 bell ping, a tonebar octave, an asymmetric pickup) and `reed_piano_voice` (2:1 FM: odd harmonics, a velocity-driven symmetric pickup clipper, a 1 kHz honk), presets `:tine_piano`/`:reed_piano`.  Since patches-4 (2026-10-13; the maintainer preferred the tine piano on the Listening Bench) `jungle_keys_voice` plays `tine_piano_voice` in its hall (`piano: :fm` for Nev's own keys), so `jungle.rb` requires `electric_pianos.rb`; the tine's `amp:` (preset param `amp`) pushes its amp clipper at a constant clean level.

## The console (`bin/sound.rb`)

`bin/sound.rb` is the console, not a script helper: it shows `Help.welcome`, runs `Help.install_pry!` (Pry's help, play, reset, hist and other colliding commands become `pry-*`; help.md), installs the take hooks (arrangement.md, Takes), and carries a did_you_mean workaround in its exception handler until mb-util prints `detailed_message`.

## Plain song files: `require 'mb/sound/dsl'` (omnibus18, 2026-10-30)

Every persona in both panel rounds wanted a plain Ruby file that starts with one require and then writes console code at its top level.  `require 'mb/sound/dsl'` (also `require 'mb-sound/dsl'`, the guess next to the gem's `require 'mb-sound'`; `lib/mb/sound/dsl.rb`, `MB::Sound::DSL`) loads mb-sound and gives the requiring program's top level what bin/sound.rb's console has (it evaluates in `MB::Sound`):

```ruby
require 'mb/sound/dsl'

bpm 124
bass = seq(A1, R, A1, C2, R, E2, D2, R).n8.repeat(4)
bg :bass, bass.synth(voices: 1) { |v| v.hz.saw.lp4(v.cutoff(900), resonance: 0.4) * v.amp_env }.at(-6.db)
bg :hat, grid(16, 'x.x.x.x.x.x.x.xx').repeat(4)
```

`ruby song.rb` plays its four bars and ends when everything has rung out (looping clips play until Ctrl-C, as with `wait`).

- Methods: `main` (Ruby's top-level object) is extended with `MB::Sound::DSL`, generated forwarders `def play(...) = ::MB::Sound.play(...)` for every public command of MB::Sound's own modules (no setters, no Module/Object methods; none of them shadow a Kernel method, checked when it was written).  State stays on MB::Sound, so the console, scripts, and DSL files share one model.  Commands added later (HelpMethods on first `help`) are forwarded by `method_missing`, which defines their forwarders.  Nothing else changes: other objects, classes, and modules see no new methods.
- Constants: `MB::Sound::DSL::Constants` is prepended to Object's singleton class; a constant missing at lexical top level (`self.equal?(Object)`, blocks included) resolves to the Note (`C4`, `Ab3`) or the MB::Sound constant (`R`, `T`, `Session`).  Lookups inside other classes and modules raise as before; `Object.const_get(:C4)` resolves too (Ruby can't tell it from a top-level lookup).
- The end: `DSL::ExitWait` is registered with `ExitClose.register(..., first: true)` (closed before the Sessions, which ExitClose closes latest first): when the program ends normally while the background Session plays or has something queued, it calls `MB::Sound.wait` (tails included).  An explicit `wait` at the end leaves nothing to wait for; an exception, `exit`, or Ctrl-C ends the program right away; `MB::Sound::DSL.wait_at_exit = false` turns it off.
- Script rules stay: `MB::Sound.live` is false (errors raise), and the helpers work at the top level (`song_script(bars: 4) { |p| ... }` with `-o out.flac`, `main_script?(__FILE__)`).  bin/ scripts keep `require 'mb-sound'` and `module MB::Sound` blocks (constants in their bodies, `MB::Sound` methods there).
- Spec: `spec/lib/mb/sound/dsl_spec.rb` runs song files as real processes (never in the spec process: specs' top-level blocks would then resolve note names).

## Input checks and errors (ux-fix-1, 2026-10-18)

`ScriptRunner#check_inputs` runs first in `run_effect`/`run_synth`, before anything is built: a missing input file, `-o` without an effect input (unless INPUT_TYPE is set), a missing `.mid`, or a synth argument naming neither a file nor a MIDI port raise `ScriptRunner::InputError`; `ScriptingMethods#script_errors` prints those, `DeviceOutput::Unavailable` (no sound card), `DeviceOutput::NoSuchDevice` (a mistyped OUTPUT_DEVICE), and `RenderWindow::TargetError` as `script.rb: message` and exits 2; every helper, plain `script` too (ux-fix-2), runs through it (the list is `ScriptingMethods.script_errors`; `scripting_methods_spec.rb` checks every `*_script` helper against every listed error).  Song `--from`/`--to`: flag combinations and bar numbers are checked before the param dump, names as the song's form starts (`Arrangement#before_form`, before play_form's warm-up) and against the markers after the song block, with one message live and in renders (`--from no section, label, or marker :drp (sections and labels: ...) (did you mean :drop?)`; markers a song sets after its form starts can't be `--from` targets).  A render that fails before its first frame deletes its file.  Script output drops color codes when it isn't a terminal (ColorPolicy, help.md).  Renders print a one-line progress in a terminal (RenderProgress; a targeted render's passes say `(pass 1/2, measuring)` and `(pass 2/2, mastered)`), say once when a pre-roll plays a song unheard (`--seek` is faster), print a targeted render's song log once (its second pass runs with $stdout muted), and on Ctrl-C keep the partial file and say so.

## Screens and keys for live scripts (ux-1, 2026-10-17)

- `--ui [LAYOUT]` (effects, synths, songs; live only): the script plays in a terminal screen without a console (`ScriptRunner#live_ui`: `UI::Tiles` with `repl: :none`).  Songs default to `:show` (transport and form, tracks, queue, knobs, a big scope over the spectrum, meters, cpu, messages), synths and effects to `:play` (scope, spectrum, the keyboard, meters, knobs, cpu, messages; synths start in KEYS mode, the keyboard playing the script's MIDI input, and with no MIDI device the keyboard alone plays).  q quits (Ctrl-C too; in KEYS Ctrl-C first leaves the keyboard), Space pauses the whole Session (`Session#paused=`: the render thread writes silence and renders nothing), Right skips to the next section, Left back to the start of this one, Esc all notes off, Ctrl-] NAV, F2 the keyboard.  An ended song keeps its final meters up ("ended: q quits").  What the script prints goes to the messages pane (`UI::Messages::Writer` as `$stdout`).  Spec: `spec/bin/script_ui_spec.rb`.
- Live synth and effect scripts on a terminal (not `--plot`, not `--ui`) read keys (`ScriptRunner::LiveKeys`): Esc sends sustain off and all notes off on every channel into the session's MIDI input (a `MIDI::VirtualInput`), Esc twice within a second all sound off (CC 120); q or Ctrl-C quits; l prints the last 20 MIDI events.  `MIDI_LOG=1` prints every MIDI event as it arrives, `MIDI_STUCK=seconds` warns once per note held longer.  Spec: `spec/lib/mb/sound/script_runner/live_keys_spec.rb`.

## Song screen keys (ux-r3 items 42, 43, 2026-10-17)

The keys are ux-r3-input's `UI::Keys::SONG_SCREEN` and `SYNTH_SCREEN` keymaps (one table for dispatch, the hints, and the `?` overlay), passed to `Tiles.new(play_keys:, on_action:)`; `ScriptRunner#live_ui` acts on their actions (`SCREEN_ACTIONS`; a spec checks the tables bind no others).  Song screens: q or Esc quit, Space pause, Left/Right a bar, Up/Down or [ ] a section, PgUp/PgDn a scene.  Synth and effect screens: q quit, Space pause, Esc all notes off (twice: all sound off; Tiles hands a screen's :panic to its on_action instead of running the console's `panic`).  Held keys and kitty repeats step.  `ScriptRunner::Scrub` (states idle/back/forward, `TABLE` over every (state, key)): Left goes to the start of the bar playing (the bar before at a bar line), then a bar back per press; Right a bar forward; a press within `GRACE` (0.6 s, wall clock) of the last steps from the previous target, so a fast tempo never traps Left in the bar a seek landed in; held, 2 bars per press after 1 s and 4 after 2 s.  Everything goes through `seek` (journaled, exact frames).  Up/[ goes to the start of the section playing, or the one before it within the grace window (the form's history); Down/] is `skip`; PgUp/PgDn `go` the previous/next scene.

## Params (param-1, 2026-10-24)

`ScriptRunner::Param` carries the `MB::Sound::Param` of its declaration (`design/notes/params.md`).  Option help and checks read its range, so an option named like a common control takes the names table's range when it gives none (`mix: 0..1`, `depth: 0..1`, `feedback: -1..1`, `pan`, `width`, `quality`, `sustain`, `voices`; typed entries like `cutoff` only for typed defaults such as `2400.hz`, which parse from the command line).  `--save` still writes only declared ranges.  `ScriptRunner.declarations_of(path)` reads a script's declarations without running it (the guard spec, in forks).
