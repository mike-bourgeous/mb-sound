# Method Modules

<!-- summary -->
`MB::Sound` extends topic modules that make the console API of `bin/sound.rb`: `IOMethods`, `PlaybackMethods` (`play`, `bg`, the background `Session`, `render`), `ScheduleMethods`, `ArrangementMethods`, `TransportMethods`, `PlotMethods`, `AnalysisMethods`, and about 20 more (Generation, Envelope, Midi, Sequence, Knob, Rack, ...).  `play`/`bg`/`render`/`write` share one conversion, `MB::Sound::Playable.graph`, which turns graphs, files, samples, clips, instruments, wavetables, and presets into a graph or a friendly `Playable::Unplayable`.  Plumbing that isn't a console command goes in `MB::Sound::Internal` (not extended, so it stays out of tab completion).
<!-- /summary -->

## Quick reference

- Console API: `MB::Sound` extends the topic `*Methods` modules (`PlaybackMethods`: `play`, `bg`, `render`; `ScheduleMethods`, `ArrangementMethods`, ...); `MB::Sound::Playable.graph` converts anything playable.
- Plumbing that isn't a command goes in `MB::Sound::Internal`; before adding a command, check collisions with `MB::Sound` methods and Pry commands.
- Specs `spec/lib/mb/sound/playable_spec.rb`, `spec/lib/mb/sound/help_spec.rb` (every command in a topic).

`MB::Sound` extends several method modules that provide the top-level API available in `bin/sound.rb`.  Library plumbing that isn't a console command lives in `MB::Sound::Internal` (module_function, not extended; 2026-10-13, research-api-surface P8): `is_numeric_array?`, `convert_sound_to_narray`, `any_sound_to_array`/`any_sound_to_hash`, `detect_input`/`detect_output`, `generate_negative_freqs`, the root random generator (`root_rng`, `default_seed`, `reseed`, `restore_rng`), and the shared plotters (`plotter`, `close_plotter`); Pry completes bare words from private methods too, so private alone wouldn't keep them out of tab completion.  `reset_plotter` and its SIGWINCH handler are gone (plotters read the terminal size on every plot).
The same surface reaches a plain Ruby file's top level through `require 'mb/sound/dsl'` (`MB::Sound::DSL`: forwarders on `main` to MB::Sound, top-level note and MB::Sound constants, a wait for background playback at the end; omnibus18, scripts.md).

- `IOMethods` - File read/write via ffmpeg
- `PlaybackMethods` - `play`, `input`, real-time audio, plus the background session:
  - `play` (play-1, 2026-10-17; maintainer: "play should be fully modernized; playing a sample should do _something_ useful"): the foreground version of `bg`.  It starts the sound now (or at a launch point) as the player `:play` in the background Session, so it mixes with what plays there and goes through the master chain, master gain, and monitor trim, then waits until the player ends (`Session#playing_after_queue?(:play)` turns false) while plotting the mix with `visualize(stop:, header:)` (unless `plot: false`, `quiet:`, or PLOT=0); Ctrl-C stops it with a declick (`STOP_FADE` bars) and leaves it in `stopped` (`resume :play`).  Options: `gain:`, `fade:`, `at:`/`on:`/`in:`, `plot:`, `graphical:`, `spectrum:`, `quiet:`.  Inside a scheduled block or a `render` block (a non-realtime `Session.current`), it starts the sound like an unnamed `bg` and returns its entry without waiting (so help examples using `play` run in the guard spec).  A genre template (`play genre(:dnb)`, or `play :dnb` when no preset has that name) runs `Template#play` (its `short(60)` when the form is over 90 s) and waits until the form and its tails end; Ctrl-C is `panic`.  Removed with the old buffer loop (standing rule: superseded APIs aren't kept): `output:` (use `render(output, sound)` or `use_output`), `sample_rate:`, `device:` (`use_output`/`OUTPUT_DEVICE`), `clear:` (the plot clears the screen), the private `play_file`/`play_input`/`graph_playback?`/`graph_description` (now `Playable.describe`).
  - `Playable` (`lib/mb/sound/playable.rb`, not extended) is the one conversion `play`, `bg` (once, before knobs are adopted, so knobs and the player share one graph), `Session#add`/`#to_nodes` (so `render`), and `write` (non-audio data, rendered without master gain) use: `Playable.graph(x)` returns `Graph(nodes, description, ends, note)`.  Graphs/bundles/inputs as before (an Envelope alone plays as the level of a 220 Hz triangle plus pink noise at 0.5, since omnibus9: the maintainer's Bench note, 2026-10-17, "something with some noise mixed in will make the envelope clearer"); NArrays and number Arrays through `ArrayInput` (exact samples); Arrays one sound per element; Strings: sound files, `.mid` (default patch), `.sfz`/`.sf2` (demo phrase), a missing file is an error with suggestions; `Sample` via `#node` (once, stereo kept); `Slices` one by one with `SLICE_GAP` (0.15 s) silences, at most 64 (choice: the point of slices is hearing the cuts; `brk.sample` plays the whole); `Instrument`/SF2 fonts a demo phrase (`demo_phrase`: a C major arpeggio and chord when keytracking regions cover C3..C5, else each region's first key in turn: drum kits, slice keymaps); Clips on their `instrument` (`Sequence::PlayedBy`, see `sequences.md`), else `PATCH` (the keyboard pane's soft saw, 8 voices); grids on their instrument else `tr909` (omnibus9, the maintainer's Bench pick 2026-10-17), or `tr808` when a row names a voice only the 808 has (`Playable.tr909_rows?`: cowbell, congas, claves, maracas, cymbal); Notes/Streams on `PATCH`; `Drums::Machine` designs each voice once; Wavetables one C4 note; Symbols a preset (synth presets with `inputs :midi` get the demo phrase; sets and audio-input presets explain) or a genre (both: ambiguous, explained); anything with `#to_playable`; else `Playable::Unplayable` (an ArgumentError) naming the type and up to three ways it offers (`x.node`, `x.synth { ... }`, `clip.sampler(x)`, ...).
  - `bg` / `stop` / `outro` (alias `fadeout`) / `panic` / `players` / `resume` / `stopped` / `forget` (each returning journal entries; `stop`/`outro` take launch points; `panic` also resets the scheduler) play sounds in the background through one shared `Session` (`lib/mb/sound/session.rb`) that mixes every player in a single render loop locked to the sequence timeline
  - `swap` changes the clips a player plays without rebuilding its graph; `master` (alias `master_fx`) sets master effects on the mix (see Sequences and Master effects below)
  - Every change goes through the Session's change queue and journal (see `design/notes/arrangement.md`): `bg`, `swap`, `resume`, `master` return the change's journal entry (`bg :b lands 2:1 (queued)`; `entry.name` is the player name, accepted by `stop`/`swap`/`resume`), `stop`/`panic` return names; each command is one undo step
  - `monitor_gain` (alias `monitor`) sets the live-only monitor trim after the master chain (never in renders, recordings, or takes; set by `help.level`; see `help.md`)
  - `visualize` (alias `vis`) plots the mix live (Plot text, ~140 fps at 120x45; `graphical: true` for inline images) (until Ctrl-C, or until its `stop:` callable returns true: script `--plot` stops when `wait` returns); `render` runs a `Session` into a file (`report: :tracks` prints `MixReport`: per track (its stem path, also without `stems:`; `MixReport::Meter` is the Session's stem sink, passing parts on to a `Stems::Writer` when stems are written) and the mix (a tap): integrated LUFS, short-term max, true peak (`Loudness::Analyzer`), PLR (true peak minus integrated loudness, LU; chosen 2026-10-17 over a crest factor: the maintainer wanted the industry standard, and loudness meters report PLR as EBU R 128 s2 defines it (programme loudness vs maximum true peak), some also PSR against short-term loudness (Ian Shepherd's Dynamic Range meter, iZotope); because BS.1770's integrated loudness is gated (-70 LUFS absolute, -10 LU relative), silence and quiet stretches don't count, the "active time" the maintainer leaned toward, without our own definition of activity; a plain peak/RMS crest over the whole render would count silence); with a song form, each section pass from the frame it starts on (form passes seen half a bar ahead, placed like launches) with each track's and the mix's integrated LUFS and the mix's sample peak; `MixReport.last`, `#to_h`; measured before `loudness:` normalization; script `--report`; omnibus8, panel Nev F16 / Kaede 12) (or any output object; `bars:` renders always reach the end bar and tail, renders without `bars:`/`seconds:` stop at `MAX_RENDER_SECONDS`, `max_seconds:` caps any render; render windows `from:` (a section/label/marker Symbol or a bar number) and `to:`, `bars:` counting from `from:`: by default a pre-roll plays the song from its start in whole buffers without writing (`RenderWindow::Gate`; the same buffers as the whole render, so the file is bit-identical to the whole render's samples from the frame holding `from:`'s position, where launches land; measured on night_bus_flow's drop: 0.0 difference over 4 bars, while cutting the pre-roll's last buffer at the window, as first built, shifted the buffer grid and differed by up to 0.19, since synth lane freeing and idle skipping aren't buffer-size invariant without `exact_lanes`), stems start there too (`Stems::Writer#origin`); `preroll: false` seeks there (`Session#seek`, fresh state, faster); errors name the target with did_you_mean, a song that ends first, or 10 minutes (`max_seconds:`) without getting there); `wait` blocks until everything has ended, including master effects tails (use it at the end of scripts); `use_output` sets the background session's output (see Audio I/O below)
  - Stems (demo-song-2, 2026-10-12; maintainer: "rendering each individual track to a separate mp3 in the bench so it's easy to listen to just one track and understand its contribution"): `render('song.flac', bars:, stems: 'dir')` (`stem_format:`, default the mix file's extension) and song scripts' `--stems DIR` write one file per player name (`Session::Stems`, `lib/mb/sound/session/stems.rb`): the player's part of the mix entering the master chain (fades, mutes, ring-outs included), times the master gain, from frame 0 and padded to the render's length.  Pre-master by choice: a compressor/limiter acts on the sum, so a stem through the master alone wouldn't sound like its part of the mix; without master effects the stems sum to the mix (float rounding), with them to the mix before the chain.  Players are rendered into their own buffers and then added in the usual order, so the mix is bit-identical with or without stems (spec).  Same-named players (replacements, ring-outs) share a stem; unnamed `bg` players are `player_<n>`.  `loudness:` normalizes only the mix.  Pre-master parts can peak over full scale when the master gain is 0 dB and a limiter follows (Small Talk's drums: +5.5 dB), which integer formats clip: the writer tracks each stem's peak and warns with a `stem_gain:` (`--stem-gain DB`) that gives headroom.  The mix file does the same since filters-1 (2026-10-17; `MB::Sound::RenderPeak` around the file output, inside the window Gate, so only written frames count): a mix over full scale warns with the `gain:` that gives headroom, also under `loudness:`, whose second pass can't undo the clipping (a Bench render of lp4 at resonance 0.9 peaked at +10 dBFS and was normalized with flat tops).
  - `render` options at a glance: `stems: dir` writes each track's pre-master part, aligned; `from: :drop, bars: 8` / `to: :breakdown` render one part of a song, by default after a pre-roll that keeps the whole render's samples exactly (script `--from`/`--to`/`--seek`; arrangement.md); script `--take FILE` records the run as a replay script (arrangement.md, Takes); `report: :tracks` (script `--report`) prints LUFS, short-term max, true peak, and PLR per track, the mix, and each section pass (`MixReport.last`); `render(loudness: :spotify)` normalizes in a second pass (`AnalysisMethods` below).  `wait` ends scripts (waits for the background Session); `use_output` picks the output.  Every one of these goes through `MB::Sound::Playable.graph` (the `Playable` bullet above).
- `TransportMethods` (ui-api-1): `start` (also `play`/`go` with no arguments: resume, else play the loaded flow) and `pause` (a toggle); `flow` with no block shows the flow; `outro`/`stop :all` end a playing flow, and a console `go :scene` seeks it to the section playing that scene; `seek` takes any position spelling.  Details in arrangement.md (Transport).
- `MultichannelMethods` - `channels`, `stereo`, `spread` build multichannel signals and per-channel arguments (see Multichannel below)
- `ScheduleMethods` - `at_bar` (alias `on_bar`) / `after` / `every` / `scheduled` / `cancel` / `reset_scheduler` run blocks (they take launch points too and return printable handles with `#cancel`; see `arrangement.md`), and `bar(n, beat:)` is an absolute position for `at:` at bars on the `Session` timeline; `bg`/`stop`/`resume`/`bpm` inside them take effect exactly at the scheduled time, and launch points (`on: :beat`, `in: 1.beat`; see `LaunchPoint` in `arrangement.md`) count from the block's time (fixed 2026-10-10; they counted from the scheduler's run time, up to half a bar early); each block's commands are one undo step (see `bin/songs/scheduled_song.rb`)
- `ArrangementMethods` - the Set layer and performance tools (see `design/notes/arrangement.md`): `track` (alias `define_track`), `tracks`, `scene` (`define_scene`), `scenes`, `go` (`launch_scene`), `quant`, `mute`/`unmute`/`solo`/`unsolo`, `mutes` (`mute_group`), `undo` (`undo_change`), `redo!` (`redo_change`), `changes`, `take`
- `PlotMethods` - plots through `MB::Sound::Plot` (pure Ruby; terminal text, SVG, PNG, inline images; see `design/notes/plotting.md`): `plot`, `spectrum`, `time_freq`, `mag_phase`, `hist`, `spectrogram`, `chart { ... }` / `figure { ... }` builders, `plotter` (an MB::M::Plot-compatible `Plot::Plotter`); `hist(data, density: true)` or `pdf:` plots estimated densities with a theory over them, via `density` and `overlay`; `bin/plot_noise.rb` shows every noise shape's distribution
- `FFTMethods` - Spectral analysis
- `ScriptingMethods` - `effect_script` / `synth_script` / `song_script` / `script` for standalone scripts in bin/ (see Scripts below)
- `GainMethods`, `WindowMethods`
- `AnalysisMethods` - correlation, `freq_estimate`, and `loudness(file_or_channels, sample_rate:, weights:, true_peak:)`: ITU-R BS.1770-4 / EBU R 128 (`lib/mb/sound/loudness.rb`) returning a `Loudness::Result` with `integrated` (alias `lufs`; gated -70 LUFS / -10 LU over complete 400 ms blocks), `momentary`/`short_term` series every 100 ms from 0.1 s and their maxima (10 ms grid), `range` (alias `lra`), `true_peak`/`true_peaks` (dBTP; `true_peak: :annex2` default = BS.1770-4 Annex 2's 4x filter, `:accurate` = 32-tap Kaiser, `false`; kernel in `fast_loudness`; max with the sample peak), `gain_to(target)`, `to_h`.  Windows before the start count as silence (user rule: short audio gets values, as in ffmpeg; under 400 ms, integrated is one block padded to 400 ms).  LRA follows Tech 3342's MATLAB literally (>= gates, `sorted(round((n-1)*p+1))`, no interpolation, plus its 1.5 s of silence after the end; no leading padding, which the text doesn't state).  Files are read at their own rate in 10 s chunks; K-weighting is two Biquads from the analog prototype (exact 48 kHz table; other rates within ~0.03 dB).  Channel weights by count in ffmpeg/SMPTE order (L R C LFE Ls Rs; LFE 0, surrounds 1.41; mono 1.0, i.e. 3 LU under the same signal in stereo); `weights:` for other layouts.  Targets: `Loudness::TARGETS` (`ebu_r128`, `atsc_a85`, `spotify`/`_loud`/`_quiet` verified 2026-10-07 with sources; `apple_music`, `youtube`, `amazon_music`, `soundcloud` marked reported, unverified), `Loudness.target(name | lufs)`, `Loudness.normalize_file(path, target, peak: :warn | :reduce)`, `render(..., loudness: :spotify | -16, peak:)` (second pass over the written file).  `Loudness::Analyzer` streams any buffer sizes (~1% of realtime per 512-sample stereo buffer; 180 s of stereo in ~1 s); `node.loudness_meter` (alias `lufs_meter`; `GraphNode::LoudnessMeter`) is a pass-through bundle measuring all its channels live (`m.momentary`, `short_term`, `integrated`, `true_peak`, `to_s`, `reset`).  `bin/loudness.rb` prints a table (`-t spotify,ebu` gain columns, `--json`, `--markdown`, `-n spotify|-14` writes gain-only copies, `--targets`, `--accurate`); `bin/ab_listen.rb -m` matches by LUFS (`--match-by rms`, `M` key).  Validated against EBU Tech 3341 cases 1-6/9 and burst maxima, Tech 3342 cases 1-4, and ffmpeg's `ebur128` (`spec/lib/mb/sound/loudness_spec.rb`; differences in `/app/tmp/listening/loudness_report.md`)
- `StructureMethods` - `analyze_form(source, **options)` (alias `analyze_structure`): tempo, beats, bars, and meter of a file, audio data, or a graph or block rendered in memory (exact render grid by default); see `structure.md`.
- `HelpMethods` (loaded by bin/sound.rb with `lib/mb/sound/help.rb`, not by `require 'mb/sound'`; elsewhere `HelpAutoload`, extended into MB::Sound, loads it on the first `help`/`now`/`lesson` call, so plain scripts have them too, 2026-10-13) - `help`, `now`, `lesson`; see `help.md`.  bin/sound.rb also renames colliding Pry/pry-byebug commands to `pry-<name>` (`Help.rename_pry_collisions!`, help.md), autosaves the take every minute, and writes a `debug_dump` when an exception ends it (arrangement.md, Takes).
- `LiveMethods` - `MB::Sound.live?`/`live=` (`bin/sound.rb` turns it on) and `live_error(exception)`: raise in scripts and specs, warn and return nil in live mode so a live set keeps playing (the caller skips the change; used by Tone's build-time-only settings)

Name clashes between the modules (test-infra-1, 2026-10-30): when two modules extended into `MB::Sound` define one name, the later `extend` silently wins (2026-10-29: midi-import-1's `SequenceMethods#rhythm` and generative-g3's `GenerativeMethods#rhythm` merged without a conflict; the merge renamed one `rhythm_template`).  `spec/lib/mb/sound/name_clash_guard_spec.rb` (in `QuickSelection::ALWAYS`) compares the named MB:: modules mixed into `MB::Sound` (with `HelpMethods` loaded), Integer, Float, Rational, `Clip`, and `Notes`, public and private methods alike: a shared name must be in its `ALLOWED` with a reason, and the module Ruby calls must call `super` (checked with Prism) unless the entry says `super: false`.  Allowed today: `launch` (CueMethods over ArrangementMethods), `next_seed`/`with_seed` (Recipe::SeedRecording), `help`/`now`/`lesson` (HelpAutoload's stubs), and NumericSoundMixins' `radians`/`degrees` over mb-math's.  A new console command that collides fails there: rename it, or chain with `super` and list it.
