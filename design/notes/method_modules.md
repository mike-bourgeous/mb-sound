# Method Modules

Detailed notes moved from CLAUDE.md (2026-10-10); CLAUDE.md keeps a summary and points here.  Update both when behavior changes.


`MB::Sound` extends several method modules that provide the top-level API available in `bin/sound.rb`:
- `IOMethods` - File read/write via ffmpeg
- `PlaybackMethods` - `play`, `input`, real-time audio, plus the background session:
  - `bg` / `stop` / `outro` (alias `fadeout`) / `panic` / `players` / `resume` / `stopped` / `forget` play sounds in the background through one shared `Session` (`lib/mb/sound/session.rb`) that mixes every player in a single render loop locked to the sequence timeline
  - `swap` changes the clips a player plays without rebuilding its graph; `master` (alias `master_fx`) sets master effects on the mix (see Sequences and Master effects below)
  - Every change goes through the Session's change queue and journal (see `design/notes/arrangement.md`): `bg`, `swap`, `resume`, `master` return the change's journal entry (`bg :b lands 2:1 (queued)`; `entry.name` is the player name, accepted by `stop`/`swap`/`resume`), `stop`/`panic` return names; each command is one undo step
  - `visualize` (alias `vis`) plots the mix live (Plot text, ~140 fps at 120x45; `graphical: true` for inline images) (until Ctrl-C, or until its `stop:` callable returns true: script `--plot` stops when `wait` returns); `render` runs a `Session` into a file (or any output object); `wait` blocks until everything has ended, including master effects tails (use it at the end of scripts); `use_output` sets the background session's output (see Audio I/O below)
  - Stems (demo-song-2, 2026-10-12; maintainer: "rendering each individual track to a separate mp3 in the bench so it's easy to listen to just one track and understand its contribution"): `render('song.flac', bars:, stems: 'dir')` (`stem_format:`, default the mix file's extension) and song scripts' `--stems DIR` write one file per player name (`Session::Stems`, `lib/mb/sound/session/stems.rb`): the player's part of the mix entering the master chain (fades, mutes, ring-outs included), times the master gain, from frame 0 and padded to the render's length.  Pre-master by choice: a compressor/limiter acts on the sum, so a stem through the master alone wouldn't sound like its part of the mix; without master effects the stems sum to the mix (float rounding), with them to the mix before the chain.  Players are rendered into their own buffers and then added in the usual order, so the mix is bit-identical with or without stems (spec).  Same-named players (replacements, ring-outs) share a stem; unnamed `bg` players are `player_<n>`.  `loudness:` normalizes only the mix.
- `MultichannelMethods` - `channels`, `stereo`, `spread` build multichannel signals and per-channel arguments (see Multichannel below)
- `ScheduleMethods` - `at_bar` (alias `on_bar`) / `after` / `every` / `scheduled` / `cancel` run blocks, and `bar(n, beat:)` is an absolute position for `at:` at bars on the `Session` timeline; `bg`/`stop`/`resume`/`bpm` inside them take effect exactly at the scheduled time, and launch points (`on: :beat`, `in: 1.beat`; see `LaunchPoint` in `arrangement.md`) count from the block's time (fixed 2026-10-10; they counted from the scheduler's run time, up to half a bar early); each block's commands are one undo step (see `bin/songs/scheduled_song.rb`)
- `ArrangementMethods` - the Set layer and performance tools (see `design/notes/arrangement.md`): `track` (alias `define_track`), `tracks`, `scene` (`define_scene`), `scenes`, `go` (`launch_scene`), `quant`, `mute`/`unmute`/`solo`/`unsolo`, `mutes` (`mute_group`), `undo` (`undo_change`), `redo!` (`redo_change`), `changes`, `take`
- `PlotMethods` - plots through `MB::Sound::Plot` (pure Ruby; terminal text, SVG, PNG, inline images; see `design/notes/plotting.md`): `plot`, `spectrum`, `time_freq`, `mag_phase`, `hist`, `spectrogram`, `chart { ... }` / `figure { ... }` builders, `plotter` (an MB::M::Plot-compatible `Plot::Plotter`); `hist(data, density: true)` or `pdf:` plots estimated densities with a theory over them, via `density` and `overlay`; `bin/plot_noise.rb` shows every noise shape's distribution
- `FFTMethods` - Spectral analysis
- `ScriptingMethods` - `effect_script` / `synth_script` / `song_script` / `script` for standalone scripts in bin/ (see Scripts below)
- `GainMethods`, `WindowMethods`
- `AnalysisMethods` - correlation, `freq_estimate`, and `loudness(file_or_channels, sample_rate:, weights:, true_peak:)`: ITU-R BS.1770-4 / EBU R 128 (`lib/mb/sound/loudness.rb`) returning a `Loudness::Result` with `integrated` (alias `lufs`; gated -70 LUFS / -10 LU over complete 400 ms blocks), `momentary`/`short_term` series every 100 ms from 0.1 s and their maxima (10 ms grid), `range` (alias `lra`), `true_peak`/`true_peaks` (dBTP; `true_peak: :annex2` default = BS.1770-4 Annex 2's 4x filter, `:accurate` = 32-tap Kaiser, `false`; kernel in `fast_loudness`; max with the sample peak), `gain_to(target)`, `to_h`.  Windows before the start count as silence (user rule: short audio gets values, as in ffmpeg; under 400 ms, integrated is one block padded to 400 ms).  LRA follows Tech 3342's MATLAB literally (>= gates, `sorted(round((n-1)*p+1))`, no interpolation, plus its 1.5 s of silence after the end; no leading padding, which the text doesn't state).  Files are read at their own rate in 10 s chunks; K-weighting is two Biquads from the analog prototype (exact 48 kHz table; other rates within ~0.03 dB).  Channel weights by count in ffmpeg/SMPTE order (L R C LFE Ls Rs; LFE 0, surrounds 1.41; mono 1.0, i.e. 3 LU under the same signal in stereo); `weights:` for other layouts.  Targets: `Loudness::TARGETS` (`ebu_r128`, `atsc_a85`, `spotify`/`_loud`/`_quiet` verified 2026-10-07 with sources; `apple_music`, `youtube`, `amazon_music`, `soundcloud` marked reported, unverified), `Loudness.target(name | lufs)`, `Loudness.normalize_file(path, target, peak: :warn | :reduce)`, `render(..., loudness: :spotify | -16, peak:)` (second pass over the written file).  `Loudness::Analyzer` streams any buffer sizes (~1% of realtime per 512-sample stereo buffer; 180 s of stereo in ~1 s); `node.loudness_meter` (alias `lufs_meter`; `GraphNode::LoudnessMeter`) is a pass-through bundle measuring all its channels live (`m.momentary`, `short_term`, `integrated`, `true_peak`, `to_s`, `reset`).  `bin/loudness.rb` prints a table (`-t spotify,ebu` gain columns, `--json`, `--markdown`, `-n spotify|-14` writes gain-only copies, `--targets`, `--accurate`); `bin/ab_listen.rb -m` matches by LUFS (`--match-by rms`, `M` key).  Validated against EBU Tech 3341 cases 1-6/9 and burst maxima, Tech 3342 cases 1-4, and ffmpeg's `ebur128` (`spec/lib/mb/sound/loudness_spec.rb`; differences in `/app/tmp/listening/loudness_report.md`)
- `LiveMethods` - `MB::Sound.live?`/`live=` (`bin/sound.rb` turns it on) and `live_error(exception)`: raise in scripts and specs, warn and return nil in live mode so a live set keeps playing (the caller skips the change; used by Tone's build-time-only settings)
