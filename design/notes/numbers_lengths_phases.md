# Numeric Mixins

Detailed notes moved from CLAUDE.md (2026-10-10); CLAUDE.md keeps a summary and points here.  Update both when behavior changes.


`lib/mb/sound/numeric_sound_mixins.rb` adds methods like `.hz`, `.db`, `.meters`, `.bits` to Numeric (e.g. `440.hz.sine`, `-20.db`).  `-20.db` is a `MB::Sound::Decibels` (2026-10-13): a Numeric that acts as its linear gain (0.1) in arithmetic, comparisons, Numo (registered in Numo's UPCAST tables like Float; untyped `Numo::NArray[-6.db]` and `Numo::NMath` on a bare Decibels still see an object), and C extensions (`to_f`), returns plain Floats from arithmetic, keeps its dB value (`#decibels`, `#db_value`) for dB-taking parameters (dynamics levels, gains, and compand points, where bare numbers are linear gains since db-1, 2026-10-14; dynamics.md, Units), and prints as `-20.db` (`inspect`, `to_ruby`; `to_s` is the gain).  `440.hz` is a `Pitch` (`lib/mb/sound/pitch.rb`): a light frequency source whose oscillator methods (`sine`, `ramp`, `at`, `fm`, `pm`, `lfo`, `tone`/`hz`, `phasor`) make a new `Tone` each call; it plays as a full-scale sine when used directly as a signal, and sequences can hold it as a fixed frequency (`seq(C4, 440.hz)`).  `Note < Pitch` (C4 = 60) gets its frequency from the session `Tuning` (`tuning b4: 480`, live; in a scheduled block it changes on the block's time, `Session#at_time`).

**dB-valued arguments** (one rule, maintainer 2026-10-13/14, "everything dB-valued"; db-1): a Decibels value is read as exactly its dB, a bare number is a linear gain, a bare negative number raises `ArgumentError` in scripts and specs ("for -20 dB write -20.db") and is read as dB with a warning once per call site in live mode, and a bare 0 is -inf dB where that means a full cut, else goes through `live_error` (live: 0 dB) (`Decibels.gain_of`, `.db_of`; above-full-scale warnings with `above_one:`).  Graph documents before format 3 load with their old meaning, converted to Decibels with one warning (`GraphIO::OldDecibels`).  Inventory (2026-10-14):
- The rule: dynamics levels, gains, and compand points (dynamics.md); drum `accent:` (kit-wide and per voice; a gain, `6.db`, so a bare 2 is about 6 dB) and tr808 `more_cowbell:` (`true` or a gain); reverb `duck:` and dynamics `duck(amount:)` (`Decibels.reduction_db`: any dB amount ducks by its magnitude, `-12.db` and `12.db` alike, never boosting; a bare linear gain at most 1 by its dB, a bare number above 1 raises with the `.db` hint (live mode: dB of ducking); a reverb duck node still gives dB of reduction); chorus `hiss:` (a level, default `-72.db`); custom formant vowels' level column (`[[500, 0.db, 50], ...]`); onset detection `threshold:` (9.db rise) and `floor:` (-45.db below the loudest frame); `filter(..., gain:)`, `peq`, `peq_series`, `bandpass_series`, `Pitch#peak`/`Tone#peak` gains (already linear; Decibels now exact instead of measured with `to_db`, which every bin script renders identically); `help.level(-20.db)`; genre `true_peak` (read exactly).
- Decibels accepted, bare numbers keep their meaning (a linear reading makes no sense or the name says dB): envelope curves and every curve shape (signed dB: `curve: 60.db`, bare 60 as before; `Envelope.curve_values`, `Curve.db`, `Curve.s`, so glides, tweens, `ease`, `smooth`, drum hit curves too); `db_gain:` of `Filter::Cookbook`/`SVF` (their linear twin is `gain:`) and `SimpleEnvelopeFollower` `decay_db:`; `Noise.spectral_power_noise` slope (dB/octave).
- Not gains, left as numbers: LUFS targets (`loudness`, `render(loudness:)`, genre `loudness`), Loudness `Target` dBTP, plot floors and dB-axis ranges, compand `over:`/`step:`/blocks and knee widths, fm_chain's `velocity_range` width, script options typed in dB (converted with `.db` where used: `-a`, `-c`, `-C`, `--hiss`, ...).

`Tone` (`lib/mb/sound/tone.rb`) is the one oscillator node (no separate Oscillator or Phasor classes; `pitch.phasor` is a Tone with wave type `:phasor` that outputs its phase in cycles, no `at`).  Its DSL methods configure it before it plays (afterwards they raise `FrozenError`, or warn and change nothing in live mode; values that change come from input nodes; `sample_rate=` works any time), and everything that changes per sample (phase in cycles, band-limiting history, queued jump step, random-phase seed and draws) is one `Tone::State` (`lib/mb/sound/tone/state.rb`; plain-value `to_h`, chosen with `bin/osc_state_benchmark.rb`).  The class comment maps each buffer's steps to plan-layer ops (inputs, SPLIT at resets/timeline jumps, PHASE, SHAPE, GAIN, JUMP, PORTS).

Phases are in cycles everywhere (user decision 2026-10-10, branch phase-cycles): plain numbers and nodes given as phases count cycles (0.25 = 90°) in `with_phase` (`Tone.new(phase:)`, `Tone#phase`, `#phi`), `pm` and its index (an un-`at` Tone modulator plays at 1 cycle), `fm_feedback` amounts, `reset(to:)`, unison `phase:`, `ping(phase:)`, `harmonics(phases:)`, `Wavetable.from_harmonics` phases, `Tone.value_at` (the old `pm_cycles`/`pm_cyc`, `with_phase_cycles`, `fm_feedback_cycles` aliases were removed 2026-10-11, omnibus3).  `MB::Sound::Phase` (`lib/mb/sound/phase.rb`) states a unit: `0.25.cycles` (`.cyc`, `.cycle`), `1.5.radians` (`.rad`, `.radian`, `Phase.radians(x)`; replaces mb-math's identity `Numeric#radians`; keeps its radians exactly, so `to_radians` round-trips), `90.degrees` (`.degree`, `Phase.degrees(90)`; mb-sound overrides mb-math's `Numeric#degrees`, which returned radians, for real numbers (Complex keeps mb-math's); `#to_radians`/`#to_f` give mb-math's radians, `Phase#rotation` and a prepended `MB::M.parse_complex` patch keep mb-math's callers working; TODO: move the override into mb-math), `node.cycles` / `node.radians` (a node of radians: × 1/2π, one Multiplier); `to_cycles`/`to_radians`/`to_degrees`, arithmetic like Interval; `Phase.cycles(x)` converts any phase input to cycles, `Phase.to_radians(x)` to radians.  For trigonometry write `30.degrees.to_f` (radians).  Kernels take phase modulation and feedback amounts in cycles (band-limited and wavetable kernels add pm to the phase directly; shape and feedback kernels add pm × 2π to their radians, exact for 0).  bin/ FM scripts were retuned from radians to round cycle indices within 0.6% (e.g. fm_bass depth 0.16..0.32, was 1..2 rad); non-PM renders null-tested exact against 391c5cce.

Lengths: `Sequence::NumericDurations` adds musical lengths (`2.bars`, `3.beats`, `3.n16`, `3.sixteenths`, `1.n8.dotted`) returning `Sequence::Duration`s (see Tempo sync).  `MB::Sound::Length` (`lib/mb/sound/length.rb`) adds `Length::Seconds` (`4.seconds`, `250.ms`) and `Length::Samples` (`5.samples`, counted at the sample rate where used, so inside `oversample` too), sharing one protocol with Duration (`to_seconds`/`to_samples`/`to_whole_notes`); `node.samples` / `node.seconds` mark a node's unit.  `0.5.attack` (`Numeric#attack`, `Length::Attack`, omnibus5 2026-10-11) is a length in a patch's attack times, resolved where the patch is known (a track's `lead:`); it has no time of its own, so it is not a Length and other length-taking methods reject it.  Every method that takes a length accepts all of them plus plain numbers in its usual unit (seconds for delays, envelopes, `until`, `silence`, `render(seconds:)`; bars for fades and schedules; samples for `with_buffer`), via `Length.seconds`/`Length.samples` or `Duration.bars`/`Duration.whole_notes`.  Changing lengths (delay times) go through `Length::Source`, which keeps the unit and converts per buffer at the current rate.  `MB::Sound::Interval` (`lib/mb/sound/interval.rb`) is the pitch interval: `4.octaves` (`.oct`), `7.semitones` (`.st`, `.semi`), `50.cents` (whole cents exact; `1200.cents == 1.oct`), with `#to_semitones`/`#to_octaves`/`#to_cents`/`#ratio` and arithmetic; methods taking an interval also accept plain numbers in their usual unit via `Interval.semitones`/`Interval.octaves` (semitones for `transpose` on Notes, Pitches, clips, and seqs).  `MB::Sound::Scale` (`lib/mb/sound/scale.rb`; `scale(:minor, :a)`, `Scale[name, root]`, `Scale.new([0, 204.cents, 7.st], period:)`, `Scale.steps([2, 2, 1, ...])`) maps degrees to note numbers (`#note`, `#[]` → Notes, so Tuning applies; degree 0 is the root note, `:a` = A4, `root: A3` = A3), `#transpose(note, degrees)` (off-scale notes keep their distance above the scale note below), `#snap`, `#degree`, `#chord`, `#notes(range)`, `#mode(n)`; `Scale::CHROMATIC` is every transform's default, so degrees are semitones unless a scale is given (user decision 2026-10-09: `pitch:` is always in scale degrees).

Old-API cleanup (omnibus3, 2026-10-11; survey in the maintainer's idea notes): `Pitch#period` and `Tone#period` return a `Length::Seconds` (`220.hz.period`, for Karplus-Strong delays and `adsr(hold:)`; `.to_f` for the number), `#period_samples` a `Length::Samples` at the pitch's rate; both remember their origin (`Length::Quantity#origin`, [object, method]) so graph export prints `220.hz.period` / `A4.period` / `osc.period_samples` as the code wrote it (maintainer 2026-10-11: provenance, not Rational seconds; Float values) (was a Float, and `period * rate` would have made a Seconds holding samples); `Notes#period` and `Clip#period` stay seconds-valued nodes (pluck multiplies them, and node-valued Lengths don't do arithmetic).  Octave marks (`Pitch#up`/`dn`/`oct`, Step and Seq marks) and `peak(octaves:)` take Intervals (`A4.up(1.oct)`, `up(7.st)`; `12 * 1.oct` used to make 12 octaves) through `Interval.octave_semitones`.  Removed: `MB::Sound.apply_filter` (the DSL replaced it), the `*_cycles` aliases, and `Duration#seconds(transport)` (use `to_seconds(transport:)`; `x.seconds` means a Length on numbers and nodes).  Still open: `Phase#to_f` radians, delay `seconds:` keyword, `Filter#weighted_process`/`double_process`, Smoothstep/HaasPan length pairs, Transport methods taking Durations, `freq_estimate` returning a Pitch.
