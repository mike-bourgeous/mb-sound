# Plan layer (fused regions)

<!-- summary -->
`lib/mb/sound/plan.rb` + `plan/` (executor `ext/mb/sound/fast_plan`) runs connected regions of a graph as one op list per block in C, installed automatically by `Synth` and `Session#add`: an as-if transformation (the same samples bit for bit, the user's graph untouched, node state kept in the nodes), with lane groups across same-shape regions and rebuilds off the render thread.  Nodes join through `Plan::Describable` (`plan_describe`, `plan_inputs`, snapshots); call `Plan.changed(node)` after structural edits, and `Plan.explain(graph)` says why nodes stay unfused.  `MB_SOUND_PLAN=0|ruby`, `MB_SOUND_PLAN_CHECK=1`; specs use `plan_compare`, `rake plan:changed` decides on the 21-size sweep.

`lib/mb/sound/plan.rb` (+ `plan/`; executor `ext/mb/sound/fast_plan`) runs connected regions of a graph as one op list per block in C (optimizer stage 4, P1, 2026-10-08), an as-if transformation: the same samples (every op bit-exact with its node at either precision, since fast-sine-1 also the default fast sines, see below; Numo's own FMA caveat for complex×complex products as in fast_arithmetic), the user's graph untouched (plans reference nodes; graphviz, `sources`, names unchanged), and node state in the nodes (Tone::State's Arrays), so a plan can drop at any block boundary.
- Automatic: `Synth` installs a plan per lane and `Session#add` per player (`Plan.install`, which also precompiles).  `MB_SOUND_PLAN=0` turns plans off, `=ruby` runs the Ruby mirror; `MB_SOUND_PLAN_CHECK=1` (or `warn`) runs every planned block both planned and unfused on the same inputs and states and compares samples and node states (`Plan.check`: raise in scripts and specs; `:warn` disables that region).
- Node protocol (`Plan::Describable`, which prepends the `Plan::Planned` hook): `plan_describe(p)` returns the node's output Value, built with the DSL (`Plan::Builder`): `p[handle]` (described in the same plan if the region owns that node, else a boundary input), `p.const`, Value operators (`* + / ** real imag`), `p.tone(...)`, `p.param(constant)` (any node with `plan_param(count)` returning a number or the block's buffer and `plan_complex?`: Constant, TempoNode, knob readers), `p.boundary(h, optional:)`; plus `plan_inputs`, `plan_boundary_inputs`, `plan_unsupported_reason`, `plan_snapshot`/`plan_restore`, `plan_output_type`.  Multiplier's: `@multiplicands.keys.reduce(p.const(@constant, complex: plan_complex_buffer?)) { |product, m| product * p[m] }`.
- Covered: Constant (live params: steady values filled, changing ones' own buffers), Multiplier, Mixer, ComplexNode `:real`/`:imag`, `GraphNode#/` and `#**` and `Tuning#freq` (`ProcNode#plan_operator`; the tuning is read as each block runs), Shaper on real inputs (`include/mb_clip_shape.h`, shared with FastClip.shape), and Tone on the `:naive` and `:synth` kernels (every naive shape and noise, PolyBLEP shapes, pwm, LFO fades) with frequency, phase modulation, width, gain, and reset inputs (targets, `rnd`) as `Op::Tone`: split at reset samples, kernels shared with fast_sound/fast_synth through `include/mb_osc_shapes.h` and `include/mb_bl_osc.h`, each jump through the Tone's own Ruby (`Tone#plan_reset`; key sync costs what it costs unplanned, no fallback).
- Covered since P2 (2026-10-09): Notes event nodes (Gate, Number, Velocity, Lift, Trigger, KeyTrigger, Choke, EnvelopeInputs and its Ports, Glide, FadeIn with a numeric delay, PolyPressure, and the smoothed controllers Control/Bend/Pressure), Aftertouch (`Op::Max`), Notes::Frequency (Adds, NoteFreq on `Plan::CURRENT_TUNING`, `Op::Keep` of `#value`), NoteEnvelope::GmTime, and Envelope/NoteEnvelope (`Op::Envelope`: FastEnvelope's kernel moved into `include/mb_envelope.h`, on the envelope's state NArray, with its idle skip).  Boundaries for now: curve shapers, delays, tones with sync, ports, timelines, feedback, BLIT, or clean resets (SampleHold, TempoNode values, and cycle wavetables are ops since P3b; feedback loops got their own per-sample programs the same day, `feedback_loops.md`; the current list is under Boundaries below).
- Covered since P3a (2026-10-10, branch plan-p3a): filters (`Filter::SampleWrapper` with an SVF → `Op::FilterSvf`, with a `structure: :biquad` Cookbook → `Op::FilterBiquad`; `GraphNode::FourPole` in every mode, drive mode, clip, curve, self-oscillation, and the diode ladder → `Op::FourPole`; `lib/mb/sound/plan/filter_ops.rb`, C in `fast_plan/plan_filters.c` and `plan_biquad.c` sharing `include/mb_svf.h`, `mb_four_pole.h`, `mb_biquad.h` with fast_filter and fast_sound; the filter's own state and settings read each block, its remembered parameters written back; four-pole node parameters that end replay the block unfused, as envelope inputs), Notes::Cutoff/Quality/Resonance (`Op::Exp`, `Op::Clip`, Numo's float semantics), SQ80::TimeScale (`Op::TimeScale`).  `0 * x` folds to 0 (`Plan::Fold`, `Op::ZeroFold`; user decision 2026-10-09): a product with a zero constant of the patch (a Const, a fill, or a folded product; never a Constant node's live value) fills 0, x's ops still run every block (state, Tees, and envelopes stay in step), a non-finite x gives 0 where unfused gives NaN; warned once per kind (`Plan.fold_warnings`, `MB_SOUND_PLAN_FOLD_WARN=0`) and listed by `Plan.explain`.  Vectorized 2^x under `:fast` (user decision 2026-10-09; `include/mb_vec_exp2.h`, mirror `Plan::VecExp2`): NoteFreq and Pow with a Constant base (`OP_POWF`), 4.6/5.1 ns per sample against libm's 16, counted within `VecExp2::TOLERANCE` (2.4e-7 of the level; no float differing from libm was found), out-of-range and NaN samples recomputed with libm.  Envelope parameters filled with a constant go to the kernel as numbers, so its runs apply (see Envelopes).  Measured (graph_profile, YJIT, best of 3 alternating with master-ai b7fd18e5 while a Valgrind run used one core; % of realtime at 128/512, master → P3a; c_major.mid / dense_modulated.mid): fm_bass 14.5→13.5 / 10.2→8.8 and 23.6→22.2 / 19.7→18.0; fm_epiano 7.3→7.0 / 3.3→3.0 and 15.0→14.1 / 9.3→8.7; sq80_voice 72.3→59.7 / 28.0→25.6 and 87.1→76.3 / 42.4→38.1; stereo_drone 29.8→25.4 / 27.3→23.7; pluck 93.0→30.2 / 53.4→12.5 and 117.4→35.4 / 66.8→18.2; feedback_song 110.4→35.9 / 60.5→14.6; flanger 19.4→16.2 / 16.2→13.3; tape_delay 7.8→7.9 / 6.7→6.7.  Since P3b each sq80_voice lane is one 128-op region whose only boundary inputs are the shared controllers.
- Shared inputs (`Plan::SharedInputs`, 2026-10-09): a Synth samples each controller read by the regions of several lanes (every branch of the node's Tee a region boundary input; lanes without resamplers; a lane's own nodes stay with the lane, which advances them itself while skipped) once per block in `#sample_lanes` and hands the buffer to every region (`Region#gather`), skipping ~100 Tee branch reads per fm_bass buffer; regions running unfused replay it, and a mid-block rebuild or disabled region puts it on every branch (`#guard!`) so no source advances twice.  Measured (alternating with master-ai, best of 3, % of realtime at 128/512): fm_bass c_major 14.7→14.7 / 10.0→10.0, dense 23.6→22.9 / 19.2→19.2; fm_epiano c_major 7.4→7.4 / 3.5→3.5, dense 15.4→14.9 / 9.4→9.3 (a branch read cost ~0.1-0.25 us).
- Covered since P3b (2026-10-10, branch plan-p3b): real cycle-mode `#wavetable` tones and `Wavetable::KeyMap`s (`Op::Tone` kernel `:wavetable`: FM, PM, scan with `scan_wrap`, warps with band-limited corners, noise, gain, key-sync resets; FastWavetable.oscillate's loop moved into `include/mb_wavetable.h` (`mb_wt_oscillate`), run by `fast_plan/plan_wavetable.c`; the tone gives its table at the block's start and after each reset, `Tone#plan_wavetable`, which picks key zones as `#sample_c` does; `Tone#plan_snapshot` carries the picked zone, `@zone_table`, for check mode; sample-mode, complex, and clean tables stay boundaries), `GraphNode::SampleHold` (`Op::SampleHold`, `OP_SAMPLE_HOLD`; random draws through the node's Ruby generator, `SampleHold#plan_draw`, once per edge; mirror `SampleHold#process`), and `Sequence::TempoNode` values without ports in use as params (`TempoNode#plan_param`); since arrange-3 (2026-10-11) knobs (`GraphNode::Knob::Reader#plan_param`: a Float while the knob holds still over the block, else its frozen block buffer, the same cached block in check mode; `arrangement.md`).
- Lane groups (P3b; `Plan::LaneGroup`/`LaneGroups`, `lib/mb/sound/plan/lane_group.rb`): regions whose programs lower to the same words (`Program#signature`; scalars and objects may differ) run together: the first member sampled in a block runs every member's `Region#prepare` (rebuilds, fallbacks, boundary inputs, feeds), one `FastPlan.run_lanes` call (words shared; scalars, objects, inputs, params, outs per lane), then each member's `Region#finish` (check mode per lane).  A Synth groups every region of a shape across its lanes (voices + spares, and each voice's channels); `Plan.install(lanes:)` groups only the regions computing an installation's outputs (a stereo patch's same-shape channels; inside a graph a node may push buffers to its subgraph, as `Drums::Voice` fills its `Tap`s, or skip it, so a region can't be computed before its owner asks; the smoke suite's drums_808 found that); installations with resamplers group only the n-th region of a shape of each installation (regions inside and outside an oversampler run at different counts); members that can't run together (fallbacks, short inputs, another shape after a recompile) run alone, a member read while the group gathers runs at once, members a rebuild replaced mid-run are skipped, and groups regroup after rebuilds (a group formed by a rebuild in the middle of a block leaves out members whose replaced regions were already delivered in that block: `LaneGroup#hand_off` marks them, `#take_handoff` answers `SKIP_BLOCK` to the new group's run, `Region#prepare(in_group: true)` returns `:skip`; fuzz-fixes-1, the relation fuzzer's pan-over-a-sum-with-an-ending-input find: the new group computed the delivered left channel's next block early, reading the pan's left output a frame ahead, so the right channel got every frame a block early); a group writes a member's next block before the member's readers ask, so members alternate between two output buffers (`Region#swap_out!`; a Tee's frozen frame stays intact, as feedback_song's shared-buffer check required); `Plan.lanes`, `MB_SOUND_PLAN_LANES=0`.  Compute all voices (user decision 2026-10-10): grouped lanes are never skipped while idle (`Synth#update_skippable`; the idle-skipping specs run with lane groups off), and a Synth groups its lanes only if none may be skipped.  Since omnibus12 (2026-10-23) whether a lane may be skipped never depends on the plans: lanes whose nodes plans could all fuse (`Synth#lane_fusable?`: every node other than Tees and nodes shared with other lanes passes `Plan.fusable_type?`, a Describing node, or a multi-output node's output, without a `plan_unsupported_reason`, decided once at setup from the node types and settings) are never skipped, planned or not, and the others (long memory aside) may be, and don't group.  Before, `Synth#lane_planned?` read the installed regions, so a lane skipped unplanned (or with lane groups off, or ungrouped) ran every buffer in a lane group, and skipping changes the samples: protos-1 found a key-synced `v.hz.saw * v.gate` voice planned -42.9 dB from unplanned for 27 samples at note-ons (up to -3 dB on a clip whose later notes start idle lanes), the reset step starting from a running phase in one and a paused one in the other; fixes-9's unread-branch bug (below) was the same class.  Costs: unplanned (`MB_SOUND_PLAN=0`) and `MB_SOUND_PLAN_LANES=0` runs of fusable voices no longer skip idle lanes; planned grouped runs are unchanged.  Specs that test skipping end their patches in a Ruby block (`.proc { |x| x }`).  `run_lanes` runs `OP_SVF`, `OP_FOUR_POLE` (four-poles and diode ladders, each among their kind), and `OP_BIQUAD` lane-major (every lane's sample k before any lane's k + 1; per 64-sample pass a lane whose parameters hold for the pass, `pf_param_steady`, gets one coefficient set, as the single kernel's cache would, else per-sample coefficients; bit-exact through shared step functions: `mb_svf_step_with`, `mb_fp_coef_update`/`mb_fp_step`, `mb_dl_coef_update`/`mb_dl_step`, the cookbook and `biquad_filter`), reads a shared tuning once for `OP_NOTE_FREQ`, and runs other ops lane by lane.  In C (10 lanes, 512-sample blocks, the filter's ns/sample/lane, lanes vs alone): SVF constant 4.8 vs 6.1, moving cutoff 20 vs 20; lp4 13.5 vs 21.7, moving 31 vs 32; diode 12.4 vs 26.5, moving 41 vs 51 (moving parameters are coefficient math).  The first lane-major SVF, coefficients stored per sample, was slower than ten scalar runs (the scalar SVF is barely latency-bound).  Envelopes stay per lane: their general path (signal parameters, ~20-35 ns/sample, 45-75 while times move) is state-machine logic, not a latency-bound recursion, and a cheaper inner loop for parameters that equal the plan would be the steady-input specialization ruled out for envelopes.  Measured (graph_profile, YJIT, best of 3 alternating with master-ai a3e2c8e2 while a Valgrind run used one core; % of realtime at 128/512, master → P3b; c_major.mid / dense_modulated.mid): fm_bass 15.7→17.6 / 9.0→13.7 and 25.0→23.8 / 19.3→18.6; fm_epiano 7.0→9.6 / 3.6→5.1 and 15.2→13.6 / 10.0→8.8; sq80_voice 68.5→31.5 / 26.7→17.6 and 83.8→34.3 / 42.9→24.4; pluck 58.4→51.0 / 25.2→21.8 and 61.6→55.6 / 30.0→26.2; stereo_drone 26.7→27.2 / 24.5→24.8 (no groups: its right channel's inverted noise, `noise * -1`, is one op the left lacks); unison_song 17.8→16.5 / 6.2→6.0; swarm_song 59.4→57.5 / 20.6→21.4; peak RSS within ±6 MB.  Compute-all against idle skipping on this branch (lanes on vs `MB_SOUND_PLAN_LANES=0`, best of 3): fm_bass c_major 17.5 vs 15.2 / 14.5 vs 9.0, dense 22.8 vs 24.0 / 19.4 vs 17.8; fm_epiano c_major 10.6 vs 8.2 / 4.8 vs 3.3, dense 14.2 vs 15.9 / 8.0 vs 9.4; sq80_voice c_major 30.4 vs 32.5 / 18.0 vs 19.6, dense 34.3 vs 38.3 / 23.5 vs 25.5; pluck (never skipped) c_major 51.3 vs 57.9 / 20.0 vs 23.2, dense 53.5 vs 61.6 / 26.8 vs 30.4.  So steady costs move toward the worst case (fm_bass 17.6 vs 23.8 at 128) and the worst cases drop.  Feeds stay in Ruby: about half of their ~20 us per lane per block is reading the MIDI streams (allocator lanes, the sustain transform, Rational times), so a C port of the feed logic alone wouldn't pay.
- Lane group size (synth-sublanes-1, 2026-10-16): `LaneGroups#refresh` splits buckets of same-shape regions into groups of at most `LaneGroup::MAX_LANES` (64, `MB_PLAN_MAX_LANES` in `fast_plan.c`); before, a 70-voice synth raised "Plan lanes must number 1 to 64".  Synth sub-lanes (`midi.md`): `SubLane::Output#plan_sources` shows plans the channel's input (the SubLane itself isn't a node the region finder walks), and the output is a describable pass-through while its sub-lane can't sleep (so regions are the same as without it), a boundary while it can.
- Unread branches (fixes-9, 2026-10-13): `Plan.install(..., unread:)` takes a predicate for Tee branches nothing reads, and `Installation#live_branches` leaves them out wherever the plans ask who reads a Tee (the region finder's consumers, `Region#direct_source`, `SharedInputs#refresh`).  A Synth passes `Synth#unread_branch?` (made while building the lanes, `Tee.collect_branches`, and in no lane's graph), so an unused `band * 0.5` or `v.mod * 2` in a voice block changes neither fusing nor lane grouping (and so idle skipping) nor controller sharing; before, with a spy on one lane's band (a bus tap's `only:`), it regrouped every lane and changed the output (max difference 0.81 at a peak of 0.54).
- Event-driven nodes (`Plan::EventList`, `lib/mb/sound/plan/events.rb`): each block the Region runs the node's *feed* in Ruby (`#plan_feed`, after the boundary inputs are read): its own event handling (reader, NoteStack, chases, `#render` with the exact-sample edge rules, through `Plan::Recorder` standing in for the buffer) records an EventList (held values from an offset, impulses, Glide smoothstep ramps, FadeIn ramps, or rendered curve samples), and `Op::Events` renders it in C.  Node state stays in the node, so plans still drop at any block boundary.  `Notes::FeedGroup` reads a region's nodes on one stream once per block; `#plan_relevant?` skips events that can't change a node (not for Glide/FadeIn: events split their ramps).  Smoothed controllers add `Op::Smooth` (`include/mb_smooth.h`, shared with FastControl; the feed copies the block's jumps).  Feeders whose stream is over or ends within the block (`#plan_finished?(count)`) run that block unfused and become boundaries (check mode can't replay a stream's end); when the stream's content jumps back (restart, seek, rewind: `#plan_generation` changes), the first such node to be sampled re-includes every one of them at once, plus nodes found unsupported meanwhile (`Plan::RestartWatch`, `Installation#reinclude`; user: "do what makes most sense live", 2026-10-09).  Planning is opt-in per class (`plan_events!`); `Describable` prepends `Planned` to subclasses too (NoteEnvelope's own `#sample` must not run before a region it roots).  Envelope inputs outside the region are optional boundaries: an ending one replays the block unfused (`#plan_input_ended` returns `:replay`) and is a constant afterwards; Synth's skipped lanes advance fused nodes with `Notes::Node#advance`.
- Ops are Ruby objects (`Plan::Op::*`: a dst Value, operands, the describing node, `#run_ruby` mirror; every op bit-exact with its node, so check mode compares samples and states with no tolerance: the inexact-op machinery (`Op#exact?`/`#tolerance`, `Program#exact?`, `Region::STATE_TOLERANCE`, `Resonator#plan_state_tolerance`, `Plan.states_close?`, plan_helpers' `INEXACT_TOLERANCE`) went in omnibus14, unused since fast-sine-1); `Plan::Program` lists them (`to_s`), allocates registers (linear scan; a dst never shares its operands' slots; params own theirs), and lowers them to Int32 words for `FastPlan.run`.  `Plan.explain(graph)` lists regions, ops, and why other nodes stay unfused.
- Region finder (`Plan::Installation`): consumers first; a describable node joins its readers' region only if all of its readers, through every Tee branch, are fusable inputs of that one region, else it roots its own region (regions under `Plan.min_nodes`, 2, are dropped).  Regions read boundary inputs through their nodes' own Tee branches (lockstep kept); optional inputs (reset triggers) may end; a buffer of another type replays the block unfused (`Tee::Branch#replay`) and recompiles.  `Plan.changed(node)` after structural edits (Multiplier#add, a new Mixer summand, Tee branches, Tone configuration, spies) rebuilds the installation before its next block; `structure: false` (sample rates, constants, existing gains) recompiles the region.  Session::Strip's node-set caches (ux-fix-2) also refresh only through it (`GraphNode.structure_changes`); the structure check (`Session::Strip.structure_check`, on in specs via spec_helper, `MB_SOUND_CHECK_STRUCTURE=1` elsewhere; omnibus10/bench-fixes-1) walks every cached graph every 16 spans (`Strip::STRUCTURE_CHECK_SPANS`; every span tripled Session-heavy specs' time) and when the Session closes, and raises `Strip::UnannouncedStructureChange` (nodes added/removed) when one changed while the count stayed, so a structural edit that skips `Plan.changed` fails the spec that makes it.  Introspection never misses a buffer: `Plan.observe(node)` keeps a node a boundary, spied nodes are tapped (below), and a fused node read from outside its plan replans (`Region#foreign_read`).
- Precision (fast-sine-1, 2026-10-25; maintainer: "I want to do more FM in the future, so don't want to pay the performance penalty to use double precision to match Ruby.  Have unplanned Ruby use the C fast sine by default with an option for double precision."): `MB::Sound.precision` (`lib/mb/sound/precision.rb`; `Plan.precision` is the same setting) is `:fast` by default and `:exact` with `MB_SOUND_PRECISION=exact` (`MB_SOUND_PLAN_PRECISION` is gone), and it now applies to planned and unplanned graphs together, so planned == unplanned bit for bit at both (every op is exact; check mode, `plan_compare`, the relation fuzzer's `:plan_fast`, and the session fuzzer's `:plan` compare with no tolerance).  At `:fast` naive real sines without noise run a vectorized float polynomial (`include/mb_vec_sine.h`: the naive kernel's exact double phases, then a branch-free shape pass GCC vectorizes at baseline flags) through one function, `mb_vec_sine_oscillate` (`include/mb_vec_sine_osc.h`), called by the plan's tone op and by `FastSound.oscillate` (C global `FastSound.fast_math=`, set by `Precision.precision=`); `Tone#kernel_ruby` uses the mirror `Plan::VecSine` (bit-identical); note frequencies (`FastSound.number_to_freq`, `Op::NoteFreq`) and powers of a Constant or Knob base (`GraphNode#**` → `FastArithmetic.power_fast`, `Op::Pow` reading `ProcNode#fast_power_base`, so plan and node decide alike) use `mb_vec_exp2.h`.  Drift against exact math (the old planned-vs-unplanned numbers, now :fast vs :exact; fuzz-fixes-1, max per second relative to the peak, at 1/10/30/60 s): `220.hz.fm(330.hz.fm(5.hz.lfo.at(30)).at(800))` -110/-92/-82/-76 dB, a 3-op chain -118/-103/-95/-89 dB, 2-op FM -129/-112 dB at 1/10 s, PM and ring modulation flat at -116 and -134 dB; thresholds after fast sines (decimate's hold instants, sample-hold clocks) flip against libm (the float sine is exactly 0 at half periods where libm gives 1.2e-16); the fast sine's peak is 1 - 1.2e-7.  Renders that ran unfused sines (plan boundaries, unplanned scripts) moved by these amounts when unfused went fast (golden results in the fast-sine-1 report).  Cost (fast-sine-1, graph_profile, best of 2 rounds alternating with master-ai 24a27fd1, % of realtime at 128/800 frames, Mac container; synths on dense_modulated.mid): planned at :fast unchanged against master-ai (-4..+8%, noise); unplanned (`--plan off`) at :fast faster than master-ai's libm sines: fm_bass 59.5/33.1 → 49.5/23.3 (-17/-30%), fm_epiano -8/-21%, fm_bell -4/-11%, stereo_drone -22/-27%, unison_song -4/-1%; :exact unplanned equals master-ai's unplanned (within ±4%), :exact planned costs +46/+60% (fm_bass), +29/+42% (fm_epiano), +44/+68% (swarm_song, its 2^x glides), +35/+34% (stereo_drone), +23/+37% (unison_song), +12/+19% (generative_blur), +4/+14% (fm_bell), +4/+10% (fm_brass) over :fast.  Complex sines, BL `:synth` sines, `fm_feedback`, and wavetables are exact at both (other kernels).  `mb_wrap` floors without libm (`mb_floor` in `mb_ext_helpers.h`, bit-exact; naive sines ~10% and ramps ~27% cheaper).  History: from 2026-10-09 to fast-sine-1, :fast applied to plans only (unfused was libm), with tolerances (`Op::Tone::FAST_TOLERANCE` 4e-6, `VecExp2::TOLERANCE`) and drift between the paths; research on branch `research-fast-sines` (68e0f46a) measured the options (a double polynomial `fast64` in both, exact modulators, this float polynomial in both).
- Specs: `spec/lib/mb/sound/plan/` (`plan_compare` in `spec/support/plan_helpers.rb` runs a graph unplanned, in C, and with the mirror block by block with events, bit for bit for exact programs; mirror tones within 1e-6, as the Tone's own Ruby kernels; `notes_ops_spec.rb` also runs every example in check mode, which compares node states after each block) and `spec/ext/mb/sound/fast_plan_spec.rb`; in memcheck with `notes_fast_paths_spec.rb`.  Block sizes (user decision 2026-10-10: the full sweep is "overkill" before every merge): the default suite uses `QUICK_SIZES` = 1, 7, 128, 800, and `RANDOM_SIZE` (2..799, from RSpec's seed, so `rspec --seed N` repeats it); `MB_SOUND_PLAN_FULL=1` (`rake plan:full`, ~35 s) uses the 21-size `FULL_SIZES` (1-800 with the edges 1, 2, 127/128/129, 511/512, 800).  `plan_compare`'s default sizes repeat until they reach every `before_block` index and every `Source`'s last impulse or end, plus another pass (explicit sizes that miss an event raise); `PlanSpecHelpers.sizes_for(samples:, blocks:)` gives such lists (notes_ops keeps 4 × 5166 samples of its MIDI files).  Run `rake plan:changed` (`PLAN_DRY=1` reports only; `PLAN_FULL_LINES`, default 50) before merging branches that change `lib/mb/sound/plan*`, `ext/mb/sound/fast_plan`, `ext/mb/sound/fast_loop`, or `spec/support/plan_helpers.rb`.  Measured 2026-10-10: the default plan specs take ~31 s against ~34.5 s for the full sweep, since their cost is per sample (the Ruby mirror and check mode), not per block: notes_ops (4 file passes) and loop_spec (12000 samples per loop) are most of it.  The Tone null-test references set `MB::Sound.precision = :exact` (libm in both paths, the renders they were recorded from).
- Block counts (2026-10-10, branch plan-unfused-count): `Region#planned_blocks`/`#unfused_blocks` count from when the region's root was first planned: `Installation#rebuild` carries a replaced region's counts to the new region on the same root, and keeps those of regions without a successor (`Installation#dropped_blocks`); `Installation#planned_blocks`/`#unfused_blocks` are totals (graph_profile's stats include them).  Before this, a rebuild reset the counts, hiding the blocks that ran unfused just before it.  `plan_compare` checks every region plus the dropped ones (`fallbacks:` an Integer max per region, `true` any), and `Result#unfused_blocks(engine)` lets specs assert exact counts.  Expected unfused blocks, by design (one-off events, not per-block costs): an envelope or four-pole parameter input that ends runs 2 blocks unfused (the short-buffer block, which the node pads with its last value, unless the end falls on a block edge, and the first nil block, after which the plan is rebuilt with the value as a constant); a feeder whose stream is over (a one-shot envelope's end, a MIDI file's end) runs 1. ## Rebuild storms when event streams end (omnibus13, 2026-10-25)

alloc-2 found the Synth's plan installations rebuilding on the render thread when a Mixer summand ends (0.25-1.1 M objects in one buffer; fm_bass on dense_modulated.mid). The cause was mostly not the Mixer: when a lane's `Notes::EnvelopeInputs` feeder finished ("its event stream is over"), it left the plans, and its three Ports, which read it directly rather than through a Tee, were then found unsupported ("an input that isn't a Tee branch") one region compile at a time, each a rebuild of the whole lane installation (~15k objects).  Now:

- `Region#compile` collects every consumer of a non-Tee input in one pass and marks them all unsupported before failing, so one rebuild covers them.
- A feeder excluded at its stream's end takes its `plan_direct_readers` (EnvelopeInputs' Ports) with it, in the same rebuild.

After: 49 rebuilds, worst buffers 151k / 144k / 66k objects (102 / 101 / 64 ms); mean objects per buffer 279 -> 194.  Still open: several lanes' feeders ending in one buffer are each found by their own region, and each stale mark rebuilds the whole installation at the next region's prepare (up to 11 rebuilds per buffer here).  Options, not built: rebuild at most once per installation per block (regions that found a problem run unfused for the rest of the block, others keep their program; needs the stale checks in LaneGroup and SharedInputs to agree), incremental rebuilds of only the regions holding excluded nodes, or building the new installation off the render thread and swapping it in at a block boundary (the plan is an as-if transformation, so running unfused meanwhile keeps the samples).

Two causes made most of them:

- Every finished feeder of a region leaves at once (`Region#prepare`): fm_bass's four envelopes per lane, on one stream, were found one block at a time, each block unfused and each a rebuild of the lane.
- A node one installation left out is never claimed by another (`Installation#exclude`/`#unsupported!` set `@plan_excluded`; another installation's `#candidate_reason` says "left out by another installation" while the marking one still leaves it out): the Session player's installation reaches every lane's nodes through the Synth, took over the 32 nodes the lanes had left out when the stream ended, then rebuilt its whole graph for each one as it ended in turn (18 rebuilds, 8-10 in one buffer).

That gave 55 -> 27 rebuilds (max 11 -> 7 per buffer), worst buffer 120 -> 41 ms.  Then the three options:

- **Kept regions (option 2)**: `Installation#find_layout` (traverse + assign) keeps a current region whose new counterpart has the same root and nodes when none of them changed since it was built (`#note_change` tracks changed nodes, numbered) and it is installed, compiled, not disabled, with no recompile pending; nothing is kept after a structural change (Tee branches and readers may differ anywhere).  `#commit` removes and installs only the regions that changed and updates `Plan.watch` for the nodes that came or went.  `Plan.changed(node, structure: :ended)` (Mixer#sample_ended, Envelope/FourPole#plan_input_ended): the node only stopped reading ended inputs, so only its region rebuilds, and an installation that merely reaches it through another installation's nodes (the Session player's, seeing a lane's sum) doesn't rebuild at all.
- **Rebuilds elsewhere (option 3)**: `Plan::Rebuild`, `Deferral`, `Worker` (`plan/rebuild.rb`).  While a realtime Session's render thread renders a span, `Plan.deferral` is the Session's Deferral; `Installation#stale?` then starts a Rebuild instead of answering true.  The regions holding changed nodes run unfused until it lands (`Installation#held?`, checked in `Region#prepare`; the as-if contract makes those blocks sound the same), every other region keeps its program, and lane groups and shared inputs carry on.  The process-wide worker thread (priority -3) finds the layout in a dry-run shadow Installation (`#shadow_of`, from a `#snapshot` taken on the render thread) and compiles its new regions, also their signatures and ScaleMatch cores (`Program#scale_core`, cached), in slices of at most 0.5 ms (`Worker::SLICE`) holding the Session's render lock, so it never reads a graph a buffer is rendering (and never races a structural edit, which takes the lock too).  The next span's start installs it (`Deferral#apply` -> `Installation#adopt` -> `#commit`).  A structural change after the build started drops it; other changes hold their regions in the new layout and start the next build; an error drops it and the next block rebuilds in place.  Structural changes and foreign reads still rebuild before the next block wherever the plans render: either can give a fused node a reader outside its region, which reads it whether or not the region runs (the full suite under `:background` found it: master_spec's muted player, its LFO kept in step by `Strip#read_while_asleep` while the old layout fused it).  The render thread's side is warmed up in `MB::Sound.warm_up` (held regions, adopts).
- **Once per block (option 1)**: deferral gives it: a deferred installation lands once per span.  `Plan.rebuilds :next_span` builds at the next span's start on the rendering thread (deterministic; specs and the session fuzzer's :plan relation use it).  It isn't the offline default: after the two fixes above no installation rebuilt twice in a block in the measured songs, and holding regions unfused costs more than rebuilding in place where nothing waits.
- `Plan.rebuilds` (`MB_SOUND_PLAN_REBUILDS`): `:auto` (default: deferred on a realtime Session's render thread only), `:inline`, `:background` (every Session render, the worker thread; offline renders hold their regions until the worker gets the lock, which an offline loop gives up only between buffers), `:next_span`.
