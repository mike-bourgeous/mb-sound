# Plan layer (fused regions)

Detailed notes moved from CLAUDE.md (2026-10-10); CLAUDE.md keeps a summary and points here.  Update both when behavior changes.


`lib/mb/sound/plan.rb` (+ `plan/`; executor `ext/mb/sound/fast_plan`) runs connected regions of a graph as one op list per block in C (optimizer stage 4, P1, 2026-10-08), an as-if transformation: the same samples (every op bit-exact with its node, except the default fast sines within -124 dB, see below; Numo's own FMA caveat for complex×complex products as in fast_arithmetic), the user's graph untouched (plans reference nodes; graphviz, `sources`, names unchanged), and node state in the nodes (Tone::State's Arrays), so a plan can drop at any block boundary.
- Automatic: `Synth` installs a plan per lane and `Session#add` per player (`Plan.install`, which also precompiles).  `MB_SOUND_PLAN=0` turns plans off, `=ruby` runs the Ruby mirror; `MB_SOUND_PLAN_CHECK=1` (or `warn`) runs every planned block both planned and unfused on the same inputs and states and compares samples and node states (`Plan.check`: raise in scripts and specs; `:warn` disables that region).
- Node protocol (`Plan::Describable`, which prepends the `Plan::Planned` hook): `plan_describe(p)` returns the node's output Value, built with the DSL (`Plan::Builder`): `p[handle]` (described in the same plan if the region owns that node, else a boundary input), `p.const`, Value operators (`* + / ** real imag`), `p.tone(...)`, `p.param(constant)` (any node with `plan_param(count)` returning a number or the block's buffer and `plan_complex?`: Constant, TempoNode, knob readers), `p.boundary(h, optional:)`; plus `plan_inputs`, `plan_boundary_inputs`, `plan_unsupported_reason`, `plan_snapshot`/`plan_restore`, `plan_output_type`.  Multiplier's: `@multiplicands.keys.reduce(p.const(@constant, complex: plan_complex_buffer?)) { |product, m| product * p[m] }`.
- Covered: Constant (live params: steady values filled, changing ones' own buffers), Multiplier, Mixer, ComplexNode `:real`/`:imag`, `GraphNode#/` and `#**` and `Tuning#freq` (`ProcNode#plan_operator`; the tuning is read as each block runs), Shaper on real inputs (`include/mb_clip_shape.h`, shared with FastClip.shape), and Tone on the `:naive` and `:synth` kernels (every naive shape and noise, PolyBLEP shapes, pwm, LFO fades) with frequency, phase modulation, width, gain, and reset inputs (targets, `rnd`) as `Op::Tone`: split at reset samples, kernels shared with fast_sound/fast_synth through `include/mb_osc_shapes.h` and `include/mb_bl_osc.h`, each jump through the Tone's own Ruby (`Tone#plan_reset`; key sync costs what it costs unplanned, no fallback).
- Covered since P2 (2026-10-09): Notes event nodes (Gate, Number, Velocity, Lift, Trigger, KeyTrigger, Choke, EnvelopeInputs and its Ports, Glide, FadeIn with a numeric delay, PolyPressure, and the smoothed controllers Control/Bend/Pressure), Aftertouch (`Op::Max`), Notes::Frequency (Adds, NoteFreq on `Plan::CURRENT_TUNING`, `Op::Keep` of `#value`), NoteEnvelope::GmTime, and Envelope/NoteEnvelope (`Op::Envelope`: FastEnvelope's kernel moved into `include/mb_envelope.h`, on the envelope's state NArray, with its idle skip).  Boundaries for now: curve shapers, delays, tones with sync, ports, timelines, feedback, BLIT, or clean resets (SampleHold, TempoNode values, and cycle wavetables are ops since P3b).
- Covered since P3a (2026-10-10, branch plan-p3a): filters (`Filter::SampleWrapper` with an SVF → `Op::FilterSvf`, with a `structure: :biquad` Cookbook → `Op::FilterBiquad`; `GraphNode::FourPole` in every mode, drive mode, clip, curve, self-oscillation, and the diode ladder → `Op::FourPole`; `lib/mb/sound/plan/filter_ops.rb`, C in `fast_plan/plan_filters.c` and `plan_biquad.c` sharing `include/mb_svf.h`, `mb_four_pole.h`, `mb_biquad.h` with fast_filter and fast_sound; the filter's own state and settings read each block, its remembered parameters written back; four-pole node parameters that end replay the block unfused, as envelope inputs), Notes::Cutoff/Quality/Resonance (`Op::Exp`, `Op::Clip`, Numo's float semantics), SQ80::TimeScale (`Op::TimeScale`).  `0 * x` folds to 0 (`Plan::Fold`, `Op::ZeroFold`; user decision 2026-10-09): a product with a zero constant of the patch (a Const, a fill, or a folded product; never a Constant node's live value) fills 0, x's ops still run every block (state, Tees, and envelopes stay in step), a non-finite x gives 0 where unfused gives NaN; warned once per kind (`Plan.fold_warnings`, `MB_SOUND_PLAN_FOLD_WARN=0`) and listed by `Plan.explain`.  Vectorized 2^x under `:fast` (user decision 2026-10-09; `include/mb_vec_exp2.h`, mirror `Plan::VecExp2`): NoteFreq and Pow with a Constant base (`OP_POWF`), 4.6/5.1 ns per sample against libm's 16, counted within `VecExp2::TOLERANCE` (2.4e-7 of the level; no float differing from libm was found), out-of-range and NaN samples recomputed with libm.  Envelope parameters filled with a constant go to the kernel as numbers, so its runs apply (see Envelopes). - Shared inputs (`Plan::SharedInputs`, 2026-10-09): a Synth samples each controller read by the regions of several lanes (every branch of the node's Tee a region boundary input; lanes without resamplers; a lane's own nodes stay with the lane, which advances them itself while skipped) once per block in `#sample_lanes` and hands the buffer to every region (`Region#gather`), skipping ~100 Tee branch reads per fm_bass buffer; regions running unfused replay it, and a mid-block rebuild or disabled region puts it on every branch (`#guard!`) so no source advances twice. - Covered since P3b (2026-10-10, branch plan-p3b): real cycle-mode `#wavetable` tones and `Wavetable::KeyMap`s (`Op::Tone` kernel `:wavetable`: FM, PM, scan with `scan_wrap`, warps with band-limited corners, noise, gain, key-sync resets; FastWavetable.oscillate's loop moved into `include/mb_wavetable.h` (`mb_wt_oscillate`), run by `fast_plan/plan_wavetable.c`; the tone gives its table at the block's start and after each reset, `Tone#plan_wavetable`, which picks key zones as `#sample_c` does; `Tone#plan_snapshot` carries the picked zone, `@zone_table`, for check mode; sample-mode, complex, and clean tables stay boundaries), `GraphNode::SampleHold` (`Op::SampleHold`, `OP_SAMPLE_HOLD`; random draws through the node's Ruby generator, `SampleHold#plan_draw`, once per edge; mirror `SampleHold#process`), and `Sequence::TempoNode` values without ports in use as params (`TempoNode#plan_param`); since arrange-3 (2026-10-11) knobs (`GraphNode::Knob::Reader#plan_param`: a Float while the knob holds still over the block, else its frozen block buffer, the same cached block in check mode; `arrangement.md`).
- Lane groups (P3b; `Plan::LaneGroup`/`LaneGroups`, `lib/mb/sound/plan/lane_group.rb`): regions whose programs lower to the same words (`Program#signature`; scalars and objects may differ) run together: the first member sampled in a block runs every member's `Region#prepare` (rebuilds, fallbacks, boundary inputs, feeds), one `FastPlan.run_lanes` call (words shared; scalars, objects, inputs, params, outs per lane), then each member's `Region#finish` (check mode per lane).  A Synth groups every region of a shape across its lanes (voices + spares, and each voice's channels); `Plan.install(lanes:)` groups only the regions computing an installation's outputs (a stereo patch's same-shape channels; inside a graph a node may push buffers to its subgraph, as `Drums::Voice` fills its `Tap`s, or skip it, so a region can't be computed before its owner asks; the smoke suite's drums_808 found that); installations with resamplers group only the n-th region of a shape of each installation (regions inside and outside an oversampler run at different counts); members that can't run together (fallbacks, short inputs, another shape after a recompile) run alone, a member read while the group gathers runs at once, members a rebuild replaced mid-run are skipped, and groups regroup after rebuilds; a group writes a member's next block before the member's readers ask, so members alternate between two output buffers (`Region#swap_out!`; a Tee's frozen frame stays intact, as feedback_song's shared-buffer check required); `Plan.lanes`, `MB_SOUND_PLAN_LANES=0`.  Compute all voices (user decision 2026-10-10): grouped lanes are never skipped while idle (`Synth#update_skippable`; the idle-skipping specs run with lane groups off), and a Synth groups its lanes only if that gives up no skipping of unfused work: each lane is never skipped anyway (long memory) or runs all of its own nodes in regions (`Synth#lane_planned?`; unison_song's synth doesn't group).  `run_lanes` runs `OP_SVF`, `OP_FOUR_POLE` (four-poles and diode ladders, each among their kind), and `OP_BIQUAD` lane-major (every lane's sample k before any lane's k + 1; per 64-sample pass a lane whose parameters hold for the pass, `pf_param_steady`, gets one coefficient set, as the single kernel's cache would, else per-sample coefficients; bit-exact through shared step functions: `mb_svf_step_with`, `mb_fp_coef_update`/`mb_fp_step`, `mb_dl_coef_update`/`mb_dl_step`, the cookbook and `biquad_filter`), reads a shared tuning once for `OP_NOTE_FREQ`, and runs other ops lane by lane.  In C (10 lanes, 512-sample blocks, the filter's ns/sample/lane, lanes vs alone): SVF constant 4.8 vs 6.1, moving cutoff 20 vs 20; lp4 13.5 vs 21.7, moving 31 vs 32; diode 12.4 vs 26.5, moving 41 vs 51 (moving parameters are coefficient math).  The first lane-major SVF, coefficients stored per sample, was slower than ten scalar runs (the scalar SVF is barely latency-bound).  Envelopes stay per lane: their general path (signal parameters, ~20-35 ns/sample, 45-75 while times move) is state-machine logic, not a latency-bound recursion, and a cheaper inner loop for parameters that equal the plan would be the steady-input specialization ruled out for envelopes. Compute-all against idle skipping on this branch (lanes on vs `MB_SOUND_PLAN_LANES=0`, best of 3): fm_bass c_major 17.5 vs 15.2 / 14.5 vs 9.0, dense 22.8 vs 24.0 / 19.4 vs 17.8; fm_epiano c_major 10.6 vs 8.2 / 4.8 vs 3.3, dense 14.2 vs 15.9 / 8.0 vs 9.4; sq80_voice c_major 30.4 vs 32.5 / 18.0 vs 19.6, dense 34.3 vs 38.3 / 23.5 vs 25.5; pluck (never skipped) c_major 51.3 vs 57.9 / 20.0 vs 23.2, dense 53.5 vs 61.6 / 26.8 vs 30.4.  So steady costs move toward the worst case (fm_bass 17.6 vs 23.8 at 128) and the worst cases drop.  Feeds stay in Ruby: about half of their ~20 us per lane per block is reading the MIDI streams (allocator lanes, the sustain transform, Rational times), so a C port of the feed logic alone wouldn't pay.
- Event-driven nodes (`Plan::EventList`, `lib/mb/sound/plan/events.rb`): each block the Region runs the node's *feed* in Ruby (`#plan_feed`, after the boundary inputs are read): its own event handling (reader, NoteStack, chases, `#render` with the exact-sample edge rules, through `Plan::Recorder` standing in for the buffer) records an EventList (held values from an offset, impulses, Glide smoothstep ramps, FadeIn ramps, or rendered curve samples), and `Op::Events` renders it in C.  Node state stays in the node, so plans still drop at any block boundary.  `Notes::FeedGroup` reads a region's nodes on one stream once per block; `#plan_relevant?` skips events that can't change a node (not for Glide/FadeIn: events split their ramps).  Smoothed controllers add `Op::Smooth` (`include/mb_smooth.h`, shared with FastControl; the feed copies the block's jumps).  Feeders whose stream is over or ends within the block (`#plan_finished?(count)`) run that block unfused and become boundaries (check mode can't replay a stream's end); when the stream's content jumps back (restart, seek, rewind: `#plan_generation` changes), the first such node to be sampled re-includes every one of them at once, plus nodes found unsupported meanwhile (`Plan::RestartWatch`, `Installation#reinclude`; user: "do what makes most sense live", 2026-10-09).  Planning is opt-in per class (`plan_events!`); `Describable` prepends `Planned` to subclasses too (NoteEnvelope's own `#sample` must not run before a region it roots).  Envelope inputs outside the region are optional boundaries: an ending one replays the block unfused (`#plan_input_ended` returns `:replay`) and is a constant afterwards; Synth's skipped lanes advance fused nodes with `Notes::Node#advance`.
- Ops are Ruby objects (`Plan::Op::*`: a dst Value, operands, the describing node, `#run_ruby` mirror, `#exact?`); `Plan::Program` lists them (`to_s`), allocates registers (linear scan; a dst never shares its operands' slots; params own theirs), and lowers them to Int32 words for `FastPlan.run`.  `Plan.explain(graph)` lists regions, ops, and why other nodes stay unfused.
- Region finder (`Plan::Installation`): consumers first; a describable node joins its readers' region only if all of its readers, through every Tee branch, are fusable inputs of that one region, else it roots its own region (regions under `Plan.min_nodes`, 2, are dropped).  Regions read boundary inputs through their nodes' own Tee branches (lockstep kept); optional inputs (reset triggers) may end; a buffer of another type replays the block unfused (`Tee::Branch#replay`) and recompiles.  `Plan.changed(node)` after structural edits (Multiplier#add, a new Mixer summand, Tee branches, Tone configuration, spies) rebuilds the installation before its next block; `structure: false` (sample rates, constants, existing gains) recompiles the region.  Introspection never misses a buffer: `Plan.observe(node)` keeps a node a boundary, spied nodes are tapped (below), and a fused node read from outside its plan replans (`Region#foreign_read`).
- `Plan.precision` is `:fast` by default (user decision 2026-10-09; `MB_SOUND_PLAN_PRECISION=exact` or `:exact` for bit-exact plans): naive real sines without noise run a vectorized float polynomial (`include/mb_vec_sine.h`: the naive kernel's exact phases, then a branch-free shape pass GCC vectorizes at baseline flags; Ruby mirror `Plan::VecSine`, bit-identical), within 6e-7 of libm (-124 dB); `Op::Tone::FAST_TOLERANCE` 4e-6 per block in check mode (a fast modulator's error moves the phases it modulates), node states compared within `Region::STATE_TOLERANCE` (1e-5, `Plan.states_close?`) for inexact programs, `plan_compare` within -100 dB of the peak.  Complex sines are exact (the old scalar fast path, `mb_fast_math.h`/`FastMath`, is gone).  `mb_wrap` floors without libm (`mb_floor` in `mb_ext_helpers.h`, bit-exact; naive sines ~10% and ramps ~27% cheaper).
- Specs: `spec/lib/mb/sound/plan/` (`plan_compare` in `spec/support/plan_helpers.rb` runs a graph unplanned, in C, and with the mirror block by block with events, bit for bit for exact programs; mirror tones within 1e-6, as the Tone's own Ruby kernels; `notes_ops_spec.rb` also runs every example in check mode, which compares node states after each block) and `spec/ext/mb/sound/fast_plan_spec.rb`; in memcheck with `notes_fast_paths_spec.rb`.  Block sizes (user decision 2026-10-10: the full sweep is "overkill" before every merge): the default suite uses `QUICK_SIZES` = 1, 7, 128, 800, and `RANDOM_SIZE` (2..799, from RSpec's seed, so `rspec --seed N` repeats it); `MB_SOUND_PLAN_FULL=1` (`rake plan:full`, ~35 s) uses the 21-size `FULL_SIZES` (1-800 with the edges 1, 2, 127/128/129, 511/512, 800).  `plan_compare`'s default sizes repeat until they reach every `before_block` index and every `Source`'s last impulse or end, plus another pass (explicit sizes that miss an event raise); `PlanSpecHelpers.sizes_for(samples:, blocks:)` gives such lists (notes_ops keeps 4 × 5166 samples of its MIDI files).  Run `rake plan:changed` (`PLAN_DRY=1` reports only; `PLAN_FULL_LINES`, default 50) before merging branches that change `lib/mb/sound/plan*`, `ext/mb/sound/fast_plan`, `ext/mb/sound/fast_loop`, or `spec/support/plan_helpers.rb`.  Measured 2026-10-10: the default plan specs take ~31 s against ~34.5 s for the full sweep, since their cost is per sample (the Ruby mirror and check mode), not per block: notes_ops (4 file passes) and loop_spec (12000 samples per loop) are most of it.  Bit-exact wiring specs (and the Tone null-test references) set `Plan.precision = :exact`.
- Block counts (2026-10-10, branch plan-unfused-count): `Region#planned_blocks`/`#unfused_blocks` count from when the region's root was first planned: `Installation#rebuild` carries a replaced region's counts to the new region on the same root, and keeps those of regions without a successor (`Installation#dropped_blocks`); `Installation#planned_blocks`/`#unfused_blocks` are totals (graph_profile's stats include them).  Before this, a rebuild reset the counts, hiding the blocks that ran unfused just before it.  `plan_compare` checks every region plus the dropped ones (`fallbacks:` an Integer max per region, `true` any), and `Result#unfused_blocks(engine)` lets specs assert exact counts.  Expected unfused blocks, by design (one-off events, not per-block costs): an envelope or four-pole parameter input that ends runs 2 blocks unfused (the short-buffer block, which the node pads with its last value, unless the end falls on a block edge, and the first nil block, after which the plan is rebuilt with the value as a constant); a feeder whose stream is over (a one-shot envelope's end, a MIDI file's end) runs 1.

- Optimizer round 2 (2026-10-12, branch optimizer-2):
  - `GraphNode::UnaryFunction` (`lib/mb/sound/graph_node/unary_function.rb`; maintainer's queue 2026-10-11): ComplexNode and MathFunction are thin subclasses (FUNCTIONS, `#apply`, `#plan_function`); the base holds the input, function, sources, descriptions, and the plan description.  `Op::Unary` (`OP_UNARY`): floor/ceil/round as Numo computes them on floats (double floor/ceil/round), `logf`/`log2f`/`log10f` as FastSound, ComplexNode `:abs` (complex: `(float)hypot`; real: `fabs`) and `:arg` (complex: `(float)atan2`; real: sign bit times `(float)pi`); mirror = the node's `#apply`; MathFunction of a complex signal stays unfused.  NaNs from different log functions carry different signs (glibc `log10f` gives +NaN for some negative inputs, `logf` -NaN) and x86 sums keep the first operand's NaN, so a Mixer of NaNs from several functions can differ in the NaN's sign between plan and unfused summing order (NaN either way; check mode compares NaN positions).
  - `Op::Tap` (maintainer 2026-10-11: "Op::Tap would be useful"): a spied member of a region (`Plan.tapped?`) stays fused; the region copies its Value into the tap's buffer (`OP_TAP`; a holder Array so lowered objects stay valid as it grows) and `Region#finish` calls its `:pre` spies (count) and `:post` spies (a view of the samples) after the block; an ended region gives them nil; check mode leaves the calls to the unfused reference.  Spies run after the region's whole block rather than right after their node, so a side channel read by another node of the same block sees it a block later (`Plan.observe` keeps the old boundary).  `Plan.observed?` is now only `Plan.observe`.
  - Dynamics (`Op::Dynamics`, `OP_DYNAMICS`, `fast_plan/plan_dynamics.c`; kernel moved to `include/mb_dynamics.h`, shared with FastDynamics.compand; mirror `Dynamics.process_ruby`): one-channel compress/expand/noise_gate/duck/compand fuse; sidechains are optional boundary inputs; fixed times are Consts, node times (LFOs, knobs, Durations' TempoNodes) are described and scaled to samples by a Mul; short sidechain/time inputs run the block unfused (`plan_pads_inputs?`), an ended one runs that block unfused and leaves the node unfused.  Lookahead tails: when a required input ends, members with `#plan_tail?` make that block replay unfused and are excluded while they flush (`Tee::Branch::ENDED` replays a nil read).  Multichannel dynamics, limiters, and crossover bands stay boundaries with reasons.  Knobs fuse as params into them (knob_spec).
  - Lane groups (`Plan::ScaleMatch`, maintainer's P3b note): a gain is an `Op::Mul` of a real Value by a real Const whose operand nothing else reads; `LaneGroups#refresh` buckets regions by their core (ops without gains), pads the members lacking a gain with `x * 1` (`Region#pad!`, reapplied after each compile; exact for real floats; complex never padded), and groups by the real signature (pads come off if signatures still differ).  stereo_drone's two channels now group.
