# Core Abstraction: GraphNode DSL

Detailed notes moved from CLAUDE.md (2026-10-10); CLAUDE.md keeps a summary and points here.  Update both when behavior changes.


The central pattern is `GraphNode` (`lib/mb/sound/graph_node.rb`), a module mixed into any class that implements `#sample`. It enables fluent chaining to build signal processing graphs:

```ruby
play 123.hz.triangle.at(-20.db)   # oscillators play until Ctrl-C
play 123.hz.fm(369.hz.at(1000)).softclip.filter(150.hz.highpass(quality: 4))
```

The DSL methods (`#filter`, `#delay`, `#softclip`, arithmetic operators, etc.) live in topic modules included by `GraphNode`, in `lib/mb/sound/graph_node/*_methods.rb`; `graph_node.rb` keeps naming, graph traversal, and shared private helpers.  Graph nodes support traversal via the `Traversable` mixin (`#graph` lists the node, then every upstream node after all the nodes that read it: by longest path, ties in breadth-first order; linear time since fixes-12, 2026-10-14, when the old walk over every path, exponential in stacked diamonds, printed hundreds of "Possible infinite loop on MIDI sustain" warnings for the jungle pad and left those nodes out of order; `sources` that loop fall back to that walk, `GraphNode.graph_by_paths`); key node types live in `lib/mb/sound/graph_node/`, MIDI nodes in `lib/mb/sound/notes/`.

`#at` on any node (node-at, 2026-10-12; `ArithmeticMethods#at`): a number or a node multiplies (`self * amplitude`, a Multiplier), and a Range `a..b` maps -1..1 onto it (`self * (b - a) / 2 + (a + b) / 2`, a Multiplier plus a Mixer, or only the Multiplier for ranges centered on 0), the meaning Tone#at has for full-scale signals, so `node.lp4(800).at(-20.db)`, `adsr(...).at(0.5)`, and `3.hz.lfo.lp4(10).at(400..2000)` work.  Tones keep their own #at (scale and offset inside the oscillator, Ranges of Durations for musical times); a node given to Tone#at multiplies after the tone (it raised NoMethodError before); since omnibus7 (maintainer 2026-10-13: "Why not alias to gain on nodes that have it?") it becomes the tone's #gain (inside the oscillator after the scale and offset, fused into the plan's tone op, bit for bit with `tone * node`) and returns the tone.  Round 2 (maintainer 2026-10-13: "I prefer the merge if it can handle biased ranges, and there's not already a node on it. If gain is a node, at should live_error and add a multiplier"): a numeric gain already set merges into one gain input (`node * g`; `(wave * amp + offset) * g * node` is kept for biased ranges; within one float32 ulp of `tone.gain(g) * node`, measured relative max 1.2e-7, about -138 dB), a gain that is already a node goes through `MB::Sound.live_error` and then a Multiplier after the tone, and phasors and tones already playing get the Multiplier (so `.at(node)` never fails live).  Since the tone itself is configured, a tone also used elsewhere carries the gain there too (as `.at(number)` always did).  The same round fixed Tone#gain's Numo path for gain inputs of a wider type (a DFloat ArrayInput on a float32 tone): `buf.inplace * dfloat` returned a new array and left the output unscaled; `Tone#scale_output` multiplies in the wider type and rounds once.  Outside Tone, Ranges of Durations, non-numeric or endless Ranges, and other values go through `MB::Sound.live_error` (live mode returns the node unchanged).  Per channel on bundles (ChannelDispatch), recorded and printed as `.at(...)`, loaded by graph documents, and planned as the ordinary Mul/Add ops.  No GraphNode class had an `at` with another meaning (checked by reflection; `DelayLine#at`, `MIDI::Event#at`, `Fades::Ramp#at`, `LaunchPoint#at` are not nodes); `Array#at` stays the index (the Array mixin forwards only `reverb`/`channels`/`as_input`), and `Channels` had no `at`.

Sums that ring (`ring: :all`; omnibus8 `fixes-prepanel-1`, 2026-10-17; panel Kaede #4: a gong rendered 7 s instead of 30 because `pings + noise * env` ended with the noise burst, and `sig + sig.reverb` cut the tail when the dry part ended).  Since the maintainer's answer (2026-10-17, "make ring: :all the default, with an opt-out") a `Mixer` made without `stop_early:` rings: it ends when every summand has ended, and a summand that gives a short buffer or nil has ended (zeros pad it, it isn't sampled again, `Mixer#sample_ended`; a node's last short read is its end, and some nodes, e.g. a planned Multiplier, raise when read after it).  The old default is the opt-out, at three scopes: one sum, `(a + b).ring(:first)` (or `false`; `ArithmeticMethods#ring`: this Mixer and the Mixers directly inside it, so `a + b + c`; `.ring`/`.ring(:all)`/`true` puts ringing back; other nodes go through `live_error`; recorded, prints `.ring(:first)`); a block, `GraphNode::Mixer.with_ring(:first) { ... }` (sums made inside without `stop_early:`); a Session, `Session#ring = :first` / `render(ring: :first)` (sums made in its context: the render block, scheduled blocks, and track patches, which `Arrangement#start_track` and recording monitors build inside `Mixer.with_ring(session.ring || Mixer.ring_mode)`).  Products (`Multiplier`) still end with their first input, so `osc * env` ends with its envelope and `osc * env + osc2 * env2` ends with the later envelope.  Behavior changes: a sum of something that ends and something that never ends (`drone + hit`, `noise.at(0.1) + one_shot`) no longer ends (play runs until Ctrl-C, renders without `bars:` stop at `MAX_RENDER_SECONDS` with the warning; since omnibus9, 2026-10-18, `bg`/`play` print a one-line hint once per process naming `.ring(:first)` and Ctrl-C when `GraphNode::RingHint` finds such a sum in a graph that would otherwise end, and the render cap warning adds the same line: a static build-time check, conservative (Tones with endless inputs, constants, knobs never end; ringing sums never end if one live input doesn't; products only if none of their inputs ends; other nodes only through main inputs that never end; spec_helper turns the notice off per example)); sums of two ending parts end with the later one (tails no longer cut); repo callers and specs that relied on the old end were migrated (listed in the merge report).  Plan layer: ringing Mixers are fused (they were boundaries): `plan_describe`/`plan_inputs` use only the summands still playing (`Mixer#live_gains`), and a region holding a ringing Mixer (`Region#@ringing`) runs a block unfused when a required boundary input ends or gives a short buffer (`gather` returns `:short`), where the Mixer drops the ended summand and calls `Plan.changed` so the region rebuilds without it.  That fallback block runs unfused at a place that depends on the buffer size; since fast-sine-1 the unfused sines are the fused program's (`MB::Sound.precision`), so ringing sums of planned sines agree across buffer sizes bit for bit (before, within 1.2e-7: the fallback used libm's sine).  Recorded since omnibus9 (2026-10-18): a sum made under `with_ring(:first)`, `Session#ring = :first`, or a graph document before format 4 prints as `(a + b).ring(:first)` when it has two or more inputs that can end (`Mixer#ring_implied?`, `Recipe.note_implied_ring`; sums directly inside drop theirs, an explicit `#ring` replaces it), so a re-save keeps the ending (before, only the explicit call printed).  Specs: `spec/lib/mb/sound/graph_node/ring_spec.rb` (also planned against unplanned with `plan_compare`).

Every consumer of GraphNodes must call `get_sampler` on the node(s) it stores in its constructor (e.g. `Tone#fixup_source`, `ProcNode`, `Filter::Delay` for delay-time nodes).  That branches a node used in several places through a `Tee`, so each use gets the same samples instead of advancing it twice (the user is open to an alternate design later).

When a Tee's branches read in lockstep (each reads every buffer once with the same count, as in a Session), they all get one frozen view of the source's buffer; otherwise the Tee copies through a CircularBuffer until they catch up (`lib/mb/sound/graph_node/tee.rb`); `Branch#catch_up` (fixes-11, 2026-10-13) moves a lagging branch forward to the furthest-ahead other branch, discarding exactly the frames it skipped (an overflowed branch gets a new reader there), for graphs waiting to start in a Session (see `arrangement.md`); the CircularBuffer and the branches' one-second readers are made only when a Tee first leaves lockstep (`Tee#buffers!`, `Tee::IdleReader` before; 2026-10-10: no script ever left it, and sq80_voice's 719 Tees held 324 MB: graph_profile peak RSS 406 → 96 MB, fm_bass 226 → 75).  So a node that processes its input in place copies it first only if `buf.frozen?` (user rule, so unshared chains keep passing one buffer through; e.g. Reverb's dry path, `SampleWrapper(in_place: true)`, Delay smoothing; `GraphNode::FrozenCopy` reuses one copy buffer).  Constants, TempoNodes, and Notes nodes return one frozen buffer while their value holds (generation 0; a Tee's reused view gets a new generation each buffer: `GraphNode::FrozenView`, below).  Numo blocks most writes to frozen views but not in-place arithmetic (`buf.inplace * 2`), so `Tee.shared_check` (env `MB_SOUND_CHECK_SHARED=1`) verifies shared buffers: raising in scripts and specs (the `:check_shared` tag; on in the smoke suite), warning and copying in `bin/sound.rb` (off by default there).  `MB_SOUND_SHARED_TEE=0` turns sharing off.  Multi-output nodes that compute every channel when one output is sampled again (Synth with multichannel lanes, ChannelMixer: the matrix mix and Pan's C path) alternate two sets of output buffers, so a channel's last buffer stays valid while its Tee still shares it after another output started the next frame (patches-1, 2026-10-13: a stereo synth or pan used twice raised SharedBufferModified; the samples were right in the orders tried).  Multiplier and Mixer have allocation-free fast paths for full buffers that don't promote their type (`ArithmeticNodeHelper#arithmetic_fast?`, C kernels in `fast_arithmetic`), bit-identical to the general path; so does `ChannelMixer::Pan` with a node position (`FastArithmetic.pan`, Numo's float steps, cos and sin in separate loops so no compiler merges them into sincos).

Sample rates and oversample (2026-10-11, omnibus4; found by graph-io-2): `node.oversample(m)` used to set the rate of everything upstream at once, so a node shared between an oversampled region and a plain branch was read at two rates (wrong pitch, then `BranchBufferOverflow` after a second), and a node built later on a shared node took the raised rate (tape_delay with one Constant shared by both channels: the right channel's region ran at 4x and gave 2x-rate output, up to 0.92 off).  Now `oversample` returns a `Resample` with a pending multiplier (`#oversample_pending`) applied at its first `#sample`, or by the plan layer before it reads the graph (`Installation#traverse`), when every consumer exists.  `Resample.apply_pending` applies it together with every other pending region (`Resample::PENDING`, a WeakMap) that reaches a Tee it reaches, outermost regions first (nested regions multiply: `(x.oversample(3) + y).oversample(2)` runs x at 6x; it ran at 3x before, the outer region setting the inner Resample's output rate), and regions of the same target rate together (a node read only by them, e.g. a Constant or oscillator shared by a stereo bundle's per-channel regions, moves to their rate).  `Tee.pin_rates` walks the regions from their inputs through `#sources` (stopping at Resamples): a Tee whose every branch is reached is inside and its source moves to the region's rate as before; branches of Tees also read outside the region are pinned to the region's rate (`Branch#resampled?`), reading the source through their own resampler (libsamplerate best sinc; `libsamplerate_zoh` for Constants, exact), so a shared node runs once at its own rate (order-independent) and each consumer reads it at its rate.  Resampled branches are plan boundaries (`fusable_edge?`) and count as resamplers for shared plan inputs.  Outside oversample, `at_rate`/`sample_rate=` on a branch still moves the source and every unpinned branch.  A node shared by the region and the outside therefore isn't oversampled (oversample a copy, or a node only the region reads, to get the higher rate).  Measured: a 220 Hz ramp shared by `(x * 0.5).oversample(2)` and `x * 0.5`, difference of the two 0.0097 peak in either build order (was 0.81); planned = unplanned.  graph-io's one-Constant-per-param-use stays (bit-identical round trips with scripts).

Measure graph cost with `bin/graph_profile.rb [-n 32,128,800] [--profile] [--plan on|off|ruby|both] script.rb` (captures a bin script's graph; reports GC runs and time, objects per buffer, and buffer CPU times with and without a GC; `--profile` adds self time and allocations per node class, inflated ~3 us per call, a fused region as one "Plan region"; `-a N` lists the top N allocation sites; `--plan both` alternates unplanned and planned runs, best of `-r`; synth worst case: `spec/test_data/dense_modulated.mid`); compare branches in alternating runs against a master-ai worktree.  Cost on 2026-10-06 (best of 5, % of realtime at 128/512-sample buffers): fm_bass 32.8/19.4, fm_epiano 16.9/6.2, stereo_drone 58.0/39.8, tempo_song 13.1/4.4, antialias_song 15.0/5.4.  Objects per 128-sample buffer on 2026-10-07: fm_epiano 44 (was 94; most of the rest are MIDI stream Rationals), stereo_drone 21 (40), fm_bass 76 (80).


## Allocation on the render path (alloc-1 2026-10-21, alloc-2 2026-10-25)

Every object a buffer allocates is GC work on the render thread: at a few hundred objects per buffer a minor collection runs every second or two, and allocation is what eventually starts a major one, which stops every thread (45-80 ms in the Mac container, ~15 ms of it YJIT's code roots).  research-gvl-render (86ecf51c) found allocation storms and majors, not the GVL, are what break the Ruby render, so render paths keep to these rules:

- Reuse buffers (zero them with `BufferHelper.zero`, not Numo's `#fill`, which allocates three objects a call); reuse result Arrays; plan regroupings once and refill (Reverb's output groups); no per-buffer Hashes, Procs, Strings, Enumerators (`each_with_index.map`), sort keys, or Numo temporaries for slicing and adding (`FastArithmetic.add_at`/`.accumulate`/`.copy_range`/`.fill_range`/`.last_at_least`).
- Share equal Rationals (`MIDI::Stream.shared_advance`: a Session's 11-27 streams advance from one time); compare with Floats, not Decibels constants (`Synth::QUIET_GAIN`: a Float compared with a Decibels goes through `#coerce`, an Array each time); `FastArithmetic.min_max` keeps a Float already in its result when the bits match (-0.0 isn't a flonum).
- Work a graph needs once goes where the graph is built, not in its first buffer: `Session#add` calls `GraphNodeInput#prime` (one walk: the Synths for `align_grids`, nodes' `#prime_render` such as `Drums::Voice` skipping, and the node set `Session::Strip#graph_node_set` would otherwise list on the render thread while the change waits to land).
- Frozen views carry generations (omnibus14, maintainer 2026-10-26: "The implicit mismatch in behavior is risky"): a Tee (and the plan layer's shared inputs and unfused replays) reuses one frozen view of its source's reused buffer (`GraphNode::FrozenView#of`, two slots for multi-output nodes that alternate buffer sets) and bumps the view's generation every buffer, so "unchanged" is explicit instead of implied by a new object's identity.  Steady-input caches (CurveShaper, `Length` scaling, SQ80 time scales, Envelope gate/trigger and parameter fits, Tone reset/jump scans, Notes frequency and GM times, loop latency/pitch checks) key on the buffer and its generation (`FrozenView::Key#match?`/`#set`, `FrozenView.generation`; 0 for frozen buffers never reused, such as Constants' and Notes nodes' steady buffers, which are replaced when their value changes), never on identity alone; `frozen_view_spec.rb`'s guard scans lib/ for methods comparing identity next to `frozen?` or steady caches.  Before this, the contract cost one view object per Tee per buffer (alloc-2 question).

Measure with `spec/lib/mb/sound/render_allocations_spec.rb` (per-buffer budgets for four graphs, failing with the top allocating sites; `ALLOC_REPORT=1` prints them; helper `spec/support/allocation_budget.rb`), `bin/alloc_audit.rb` (Night Bus plus the live keyboard), `bin/graph_profile.rb -a N`, and `bin/scene_profile.rb` (objects per render buffer and per second, GC per buffer, majors by reason).  All of them measure one pass, never a mastered render's loudness targeting (`Mastering::Targeting`'s pass 1 keeps four SFloats per buffer, ~180 MB on Tunnel Vision, which shows as old objects and `oldmalloc` majors that aren't the render's own; maintainer 2026-10-26: leave that memory "unless it interferes with optimization passes"): scene_profile renders with `loudness: false`, graph_profile measures captured graphs without a Session, and alloc_audit and render_allocations_spec run `#process_buffer`; their headers say so (omnibus14).  alloc-2's per-buffer numbers (128 frames, no YJIT): small song 87.9 -> 42.7 objects, routed mix 475 -> 126, dense_modulated synth 172.5 -> 138.5, synced lead 558 -> 107.

## Tee creation traces, and Tees long term (omnibus13, 2026-10-25)

The maintainer (A5): "important debugging/tracing info; can the object count be reduced instead by converting to a string or keeping only the first few relevant caller layers? Or can we somehow remove the need for tees long term?"  Each `Tee::Branch` kept `caller_locations(1, 24)` for the graph's life (24 Locations, the Array, the Backtrace: 25 old objects), `ProcNode` the same (`caller_locations(5, 24)`); a tunnel_vision run's scene builds left ~50k of them in the old generation (scene-jit-1's retention probe).  Now both keep `Internal.creation_trace`: one interned frozen String of `path:line` lines from the same 24 frames, the first 4 in lib/mb/sound (the node and DSL method; plumbing such as tee.rb, graph_node.rb's get_sampler, IvarPreset, and the recipe recorders left out), then `...` and the first 5 outside it (the script or console line); rebuilds of a patch share one String.  `Branch#creation_trace` reads it; SharedBufferModified and BranchBufferOverflow print it indented (they printed the first 6 and all 24 Locations before; messages still name the user's line, checked in `tee_spec.rb`).

Measured (tunnel_vision, `-n 512`, offline with the form warm-up, YJIT, the scene-jit-1 probe `sp_ret.rb`, two alternating rounds against master-ai 24a27fd1; Mac container):

| | master-ai | omnibus13 |
|---|---|---|
| objects allocated in buffers 4000-24000 surviving full GCs | 364,077 | 320,193 (-12%; trace objects 52.7k -> 1,505 Strings) |
| old objects at the end | 688,314 / 688,317 | 626,038 / 624,097 (-9%) |
| objects allocated in the run | 24.33 M | 24.54 M (+0.9%: about 4 more per branch) |
| GC: minor / major / ms | 116 / 32 / 4402, 111 / 32 / 4395 | 122 / 34 / 4474, 115 / 36 / 5119 |
| majors during render buffers (nofree + oldmalloc) | 8, 4 | 6, 6 |

So the old generation is smaller, but major GC time didn't fall: the extra majors are outside render buffers (warm-up and scene builds), within this VM's noise, and in the same window the run kept four SFloats per buffer from `Mastering::Targeting`'s pass-1 recording (21,486 x 4, ~180 MB malloc'd; `targeting.rb:69/70/295`), which is what grows `oldmalloc`.  A first version that walked frames with `Thread.each_caller_location` (up to 96) allocated a Location per frame visited: +1.27 M objects and 40% more minor GCs, so it reads the same 24 frames as before.

Removing Tees long term (options, not built; costs are estimates):

1. Plan-level fan-out.  Inside a fused region a node read twice is already one register; extend the plan layer so a region whose Tee branches all lie inside it skips the Tee (the Tee becomes a boundary only where Ruby nodes read it).  Cheap where plans reach (most synth lanes), no API change; Ruby-only consumers (samplers, reverbs, delays, drum triggers) still need Tees, so this shrinks them rather than removing them.
2. Pull-once frame caches per node.  Every node remembers the frame number of its last `sample(count)` and returns the same buffer to a second reader of that frame (the Session's span id, or a thread-local epoch set by whoever drives the graph).  Removes Tees and most `get_sampler` calls (143 call sites in 74 files) for lockstep readers; readers that aren't in lockstep (different counts, offline loops in specs and benchmarks, a branch read later) still need a buffer, so a fallback CircularBuffer stays.  Costs: an epoch check per `sample` call, an ivar per node, and the frozen-identity contract moves to the node (its buffer is shared by every reader).  Medium: touches every consumer's constructor, but mechanically.
3. Push-style evaluation.  The Session (or a Graph object) orders each player's nodes topologically once and calls them in order every buffer, each writing its output buffer, consumers reading their inputs' buffers by reference: no recursion, no Tees, one place for sleeping/skipping and for plans (an ordered op list in Ruby is what the plan layer already is in C).  Biggest change (every node's `sample` reads inputs through the schedule; variable-count reads such as resamplers and oversample regions need sub-schedules), but it is the design that removes the class of fan-out bugs (BranchBufferOverflow, unread branches, double advance) rather than managing it.
4. Keep Tees, slimmer.  Flyweight branches (an index into the Tee instead of an object with its own reader Hash), creation traces as above, and IdleReader/CircularBuffer only when needed (done since 2026-10-10).  Smallest, keeps every contract; leaves ~5 objects per Tee and per branch.

A reasonable path: 4 now (done for traces), 1 with the next plan round, 2 if allocation or GC still points at fan-out, 3 only as part of a bigger render-engine redesign.

## Inspecting nodes (ux-fix-1, 2026-10-18)

`GraphNode::Inspect` (`graph_node/inspect.rb`, included by Traversable and MultiOutput, so every node, bundle, Tee, and ChannelMixer; also Notes) makes `#inspect` and `#pretty_print` one line, `#<Type code>`, from the node's recipe (to_ruby joined onto one line, at most 200 characters), else `#<Type/name>`; `#inspect_full` is Ruby's old dump (2,000,000 characters for one delay: Pry opened a pager).  `inspect_spec.rb` inspects every node of every graph sweep graph, and checks that no node's `to_s`/`inspect` or Playable description holds a source location (ux-fix-2: ProcNodes were named after their block's location, and names show as values, so `play C4.saw` printed `freq=/.../tuning.rb:87`; the location is now `ProcNode#source_location`, in graphviz only, and Tuning#freq nodes display their note, `freq=C4`, through `ProcNode#display_label`).  Session prints `#<Session realtime, 3 players, 120 bpm>`.

## DSL names are reserved on node classes (2026-10-13)

A node class's own reader with a DSL method's name hides the DSL method on that node, so chains raise: `lp4(800).filter(:highpass, cutoff: 100)` hit `FourPole#filter` (the Filter::FourPole object), `outputs[0].reverb(:plate)` hit `ReverbOutput#reverb`, `sine.width(0.5)` hit the pwm width reader (research-api-surface d8aac01f, P1).  Maintainer rule: "Rename the readers, or get rid of them and use @references internally if no external users."  Removed: `ReverbOutput#reverb`, `Formant#width`, `Resonator#freq`, `MultitapDelay::DelayTap#delay`, `Silence#seconds`.  Renamed: `FourPole#filter` → `#kernel_filter` (`four_pole` is itself a DSL alias), `Tone#width` → `#pwm_width`, `Tone#soft_sync` → `#soft_sync?`, `Tee::Branch#tee` → `#owner_tee`, `Envelope#seconds` (private) → `#segment_seconds`, `SQ80::TimeScale#seconds` → `#time_seconds`.  `spec/lib/mb/sound/graph_node/dsl_shadowing_spec.rb` checks every GraphNode class by reflection: own public or private methods named like a DSL method must call super (seen as `invokesuper` in the instruction sequence) or be listed in its ALLOWED table with a reason (Knob#get_sampler, NodeSequence#and_then, the Pitch/Note/NotePitch frequency and tone shortcuts, Tone#wavetable).  The direction the maintainer prefers over ad hoc readers is a generic parameter API (`node.params`, `node[:width]`), not built yet.

## One instance variable layout per class (warnings-2, 2026-10-15)

Ruby gives each class at most 8 branches in its object-shape tree (the order instance variables were first set); past that it warns (`:performance`, "reached 8 shape variations") and stores that class's variables in a hash, slower to read.  32 classes had reached it, mostly because GraphNode's modules and the plan layer set their state lazily (name, recipe, internal Tee, feedback sources, spies, plan region/member/bypass, ...) in whatever order each node was named, recorded, branched, or planned, and the rest because classes set their own state lazily or only in some configurations.  Maintainer decision (2026-10-14): fix them all, then make the warning fail specs.

- `GraphNode::IvarPreset` (`lib/mb/sound/graph_node/ivar_preset.rb`): modules declare the variables they set lazily (`IvarPreset.declare(self, :@x, ...)`: GraphNode, Ports, ArithmeticNodeHelper), and every class that includes GraphNode, directly or through a module, gets `IvarPreset::Init` prepended, which sets the declared variables of its modules to nil before the class's own `initialize` (leaving variables a subclass set before `super` alone).  It loads first in `graph_node.rb`, so no class misses it.
- Classes set their own lazy variables to nil in their constructors (before anything that might set them, or after everything that does).  nil reads like an unset variable; only `defined?(@x)` differs (BufferHelper's check now tests nil).  Notes plan snapshots skip the mixin variables like the ones they already skipped.
- Spec guard: the warning guard fails the example that triggers a `:performance` warning (`MB_SOUND_WARNINGS_PERFORMANCE=report` only lists them), with a hint pointing here; Ruby emits each once per process, so the failing example may only be the first to trigger it.  `spec/lib/mb/sound/graph_node/ivar_preset_spec.rb` checks the mechanism.
- Finding the culprit: compare `obj.instance_variables` orders of live instances of the class (a scratch after-each hook walking `ObjectSpace` found the 32 classes' divergence points).

## blend: mixing an effect in (ux-1 round 2, 2026-10-17)

`sig.blend(mix = 0.5, curve: :linear, compensate: true) { |s| fx }` (`GraphNode::BlendMethods`, `lib/mb/sound/graph_node/blend_methods.rb`; maintainer: build it now, pick the law): dry * (1 - mix) + wet * mix, the same linear law as the effects' own `mix:` options (reverb, chorus, dynamics, decimate), so the names agree; `curve: :power` is equal power (sqrt gains) for uncorrelated wet signals.  `mix` is a number in 0..1, a knob's name (a Symbol, read through `knob(name)`, like racks' Symbol ports), or any node (gains built from it per sample; `:power` clips it to 0..1 first).  With `compensate:` the dry path is delayed by the latency the effect's own nodes report (`#latency`: Dynamics lookahead, the limiter's lookahead + 6), summed as for a chain (parallel branches inside the effect would be over-counted; nothing else reports latency yet, and racks have no latency of their own).  On a Channels bundle the block gets the whole bundle (excluded from per-channel dispatch, like reverb and chorus).  Recorded with its block as a build block (`Recipe::BUILD_BLOCKS`), so it prints and loads back as `sig.blend(0.3) { |s| ... }`.  Spec `spec/lib/mb/sound/graph_node/blend_spec.rb`.
