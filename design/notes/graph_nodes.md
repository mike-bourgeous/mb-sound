# Core Abstraction: GraphNode DSL

Detailed notes moved from CLAUDE.md (2026-10-10); CLAUDE.md keeps a summary and points here.  Update both when behavior changes.


The central pattern is `GraphNode` (`lib/mb/sound/graph_node.rb`), a module mixed into any class that implements `#sample`. It enables fluent chaining to build signal processing graphs:

```ruby
play 123.hz.triangle.at(-20.db)   # oscillators play until Ctrl-C
play 123.hz.fm(369.hz.at(1000)).softclip.filter(150.hz.highpass(quality: 4))
```

The DSL methods (`#filter`, `#delay`, `#softclip`, arithmetic operators, etc.) live in topic modules included by `GraphNode`, in `lib/mb/sound/graph_node/*_methods.rb`; `graph_node.rb` keeps naming, graph traversal, and shared private helpers.  Graph nodes support traversal via the `Traversable` mixin (`#graph` lists the node, then every upstream node after all the nodes that read it: by longest path, ties in breadth-first order; linear time since fixes-12, 2026-10-14, when the old walk over every path, exponential in stacked diamonds, printed hundreds of "Possible infinite loop on MIDI sustain" warnings for the jungle pad and left those nodes out of order; `sources` that loop fall back to that walk, `GraphNode.graph_by_paths`); key node types live in `lib/mb/sound/graph_node/`, MIDI nodes in `lib/mb/sound/notes/`.

`#at` on any node (node-at, 2026-10-12; `ArithmeticMethods#at`): a number or a node multiplies (`self * amplitude`, a Multiplier), and a Range `a..b` maps -1..1 onto it (`self * (b - a) / 2 + (a + b) / 2`, a Multiplier plus a Mixer, or only the Multiplier for ranges centered on 0), the meaning Tone#at has for full-scale signals, so `node.lp4(800).at(-20.db)`, `adsr(...).at(0.5)`, and `3.hz.lfo.lp4(10).at(400..2000)` work.  Tones keep their own #at (scale and offset inside the oscillator, Ranges of Durations for musical times); a node given to Tone#at multiplies after the tone (it raised NoMethodError before); since omnibus7 (maintainer 2026-10-13: "Why not alias to gain on nodes that have it?") it becomes the tone's #gain (inside the oscillator after the scale and offset, fused into the plan's tone op, bit for bit with `tone * node`) and returns the tone.  Round 2 (maintainer 2026-10-13: "I prefer the merge if it can handle biased ranges, and there's not already a node on it. If gain is a node, at should live_error and add a multiplier"): a numeric gain already set merges into one gain input (`node * g`; `(wave * amp + offset) * g * node` is kept for biased ranges; within one float32 ulp of `tone.gain(g) * node`, measured relative max 1.2e-7, about -138 dB), a gain that is already a node goes through `MB::Sound.live_error` and then a Multiplier after the tone, and phasors and tones already playing get the Multiplier (so `.at(node)` never fails live).  Since the tone itself is configured, a tone also used elsewhere carries the gain there too (as `.at(number)` always did).  The same round fixed Tone#gain's Numo path for gain inputs of a wider type (a DFloat ArrayInput on a float32 tone): `buf.inplace * dfloat` returned a new array and left the output unscaled; `Tone#scale_output` multiplies in the wider type and rounds once.  Outside Tone, Ranges of Durations, non-numeric or endless Ranges, and other values go through `MB::Sound.live_error` (live mode returns the node unchanged).  Per channel on bundles (ChannelDispatch), recorded and printed as `.at(...)`, loaded by graph documents, and planned as the ordinary Mul/Add ops.  No GraphNode class had an `at` with another meaning (checked by reflection; `DelayLine#at`, `MIDI::Event#at`, `Fades::Ramp#at`, `LaunchPoint#at` are not nodes); `Array#at` stays the index (the Array mixin forwards only `reverb`/`channels`/`as_input`), and `Channels` had no `at`.

Every consumer of GraphNodes must call `get_sampler` on the node(s) it stores in its constructor (e.g. `Tone#fixup_source`, `ProcNode`, `Filter::Delay` for delay-time nodes).  That branches a node used in several places through a `Tee`, so each use gets the same samples instead of advancing it twice (the user is open to an alternate design later).

When a Tee's branches read in lockstep (each reads every buffer once with the same count, as in a Session), they all get one frozen view of the source's buffer; otherwise the Tee copies through a CircularBuffer until they catch up (`lib/mb/sound/graph_node/tee.rb`); `Branch#catch_up` (fixes-11, 2026-10-13) moves a lagging branch forward to the furthest-ahead other branch, discarding exactly the frames it skipped (an overflowed branch gets a new reader there), for graphs waiting to start in a Session (see `arrangement.md`); the CircularBuffer and the branches' one-second readers are made only when a Tee first leaves lockstep (`Tee#buffers!`, `Tee::IdleReader` before; 2026-10-10: no script ever left it, and sq80_voice's 719 Tees held 324 MB: graph_profile peak RSS 406 → 96 MB, fm_bass 226 → 75).  So a node that processes its input in place copies it first only if `buf.frozen?` (user rule, so unshared chains keep passing one buffer through; e.g. Reverb's dry path, `SampleWrapper(in_place: true)`, Delay smoothing; `GraphNode::FrozenCopy` reuses one copy buffer).  Constants, TempoNodes, and Notes nodes return one frozen buffer while their value holds.  Numo blocks most writes to frozen views but not in-place arithmetic (`buf.inplace * 2`), so `Tee.shared_check` (env `MB_SOUND_CHECK_SHARED=1`) verifies shared buffers: raising in scripts and specs (the `:check_shared` tag; on in the smoke suite), warning and copying in `bin/sound.rb` (off by default there).  `MB_SOUND_SHARED_TEE=0` turns sharing off.  Multi-output nodes that compute every channel when one output is sampled again (Synth with multichannel lanes, ChannelMixer: the matrix mix and Pan's C path) alternate two sets of output buffers, so a channel's last buffer stays valid while its Tee still shares it after another output started the next frame (patches-1, 2026-10-13: a stereo synth or pan used twice raised SharedBufferModified; the samples were right in the orders tried).  Multiplier and Mixer have allocation-free fast paths for full buffers that don't promote their type (`ArithmeticNodeHelper#arithmetic_fast?`, C kernels in `fast_arithmetic`), bit-identical to the general path; so does `ChannelMixer::Pan` with a node position (`FastArithmetic.pan`, Numo's float steps, cos and sin in separate loops so no compiler merges them into sincos).

Sample rates and oversample (2026-10-11, omnibus4; found by graph-io-2): `node.oversample(m)` used to set the rate of everything upstream at once, so a node shared between an oversampled region and a plain branch was read at two rates (wrong pitch, then `BranchBufferOverflow` after a second), and a node built later on a shared node took the raised rate (tape_delay with one Constant shared by both channels: the right channel's region ran at 4x and gave 2x-rate output, up to 0.92 off).  Now `oversample` returns a `Resample` with a pending multiplier (`#oversample_pending`) applied at its first `#sample`, or by the plan layer before it reads the graph (`Installation#traverse`), when every consumer exists.  `Resample.apply_pending` applies it together with every other pending region (`Resample::PENDING`, a WeakMap) that reaches a Tee it reaches, outermost regions first (nested regions multiply: `(x.oversample(3) + y).oversample(2)` runs x at 6x; it ran at 3x before, the outer region setting the inner Resample's output rate), and regions of the same target rate together (a node read only by them, e.g. a Constant or oscillator shared by a stereo bundle's per-channel regions, moves to their rate).  `Tee.pin_rates` walks the regions from their inputs through `#sources` (stopping at Resamples): a Tee whose every branch is reached is inside and its source moves to the region's rate as before; branches of Tees also read outside the region are pinned to the region's rate (`Branch#resampled?`), reading the source through their own resampler (libsamplerate best sinc; `libsamplerate_zoh` for Constants, exact), so a shared node runs once at its own rate (order-independent) and each consumer reads it at its rate.  Resampled branches are plan boundaries (`fusable_edge?`) and count as resamplers for shared plan inputs.  Outside oversample, `at_rate`/`sample_rate=` on a branch still moves the source and every unpinned branch.  A node shared by the region and the outside therefore isn't oversampled (oversample a copy, or a node only the region reads, to get the higher rate).  Measured: a 220 Hz ramp shared by `(x * 0.5).oversample(2)` and `x * 0.5`, difference of the two 0.0097 peak in either build order (was 0.81); planned = unplanned.  graph-io's one-Constant-per-param-use stays (bit-identical round trips with scripts).

Measure graph cost with `bin/graph_profile.rb [-n 32,128,800] [--profile] [--plan on|off|ruby|both] script.rb` (captures a bin script's graph; reports GC runs and time, objects per buffer, and buffer CPU times with and without a GC; `--profile` adds self time and allocations per node class, inflated ~3 us per call, a fused region as one "Plan region"; `-a N` lists the top N allocation sites; `--plan both` alternates unplanned and planned runs, best of `-r`; synth worst case: `spec/test_data/dense_modulated.mid`); compare branches in alternating runs against a master-ai worktree.  Cost on 2026-10-06 (best of 5, % of realtime at 128/512-sample buffers): fm_bass 32.8/19.4, fm_epiano 16.9/6.2, stereo_drone 58.0/39.8, tempo_song 13.1/4.4, antialias_song 15.0/5.4.  Objects per 128-sample buffer on 2026-10-07: fm_epiano 44 (was 94; most of the rest are MIDI stream Rationals), stereo_drone 21 (40), fm_bass 76 (80).

## ProcNode uses and dedicated nodes (omnibus3, 2026-10-11)

Maintainer (2026-10-10): "we should build new node types to remove the need for proc nodes as much as possible", so graphs stay printable (`to_ruby`) without code blocks.  `floor`, `ceil`, `round`, `log`, `log2`, `log10` build `GraphNode::MathFunction` (since optimizer-2 a thin subclass of `GraphNode::UnaryFunction`, as is ComplexNode; both are plan ops) (`lib/mb/sound/graph_node/math_function.rb`; was a ProcNode each; same samples), and `bin/effects/grain_repeater.rb`'s stepped ramp uses `.floor` (renders bit-identically; it now round-trips through `to_ruby`).  ProcNodes left (survey 2026-10-11): `/` and `**` (`arithmetic_proc`; plan-described via `plan_operator`, recorded as operators so they print; candidates for Divider/Power nodes), `Tuning` "Number to frequency" (plan op `:note_freq`), `FourPole` "Q to resonance" for node qualities, `Reverb` `show_internals` feedback taps (debug view), `warm_up` identity, `bin/effects/reverse_delay.rb` (block-delayed feedback through a spy and a proc; needs multitap in feedback loops), `bin/synths/ep2_syn.rb` `--impulse` (filter impulse response, a debug output).


## DSL names are reserved on node classes (2026-10-13)

A node class's own reader with a DSL method's name hides the DSL method on that node, so chains raise: `lp4(800).filter(:highpass, cutoff: 100)` hit `FourPole#filter` (the Filter::FourPole object), `outputs[0].reverb(:plate)` hit `ReverbOutput#reverb`, `sine.width(0.5)` hit the pwm width reader (research-api-surface d8aac01f, P1).  Maintainer rule: "Rename the readers, or get rid of them and use @references internally if no external users."  Removed: `ReverbOutput#reverb`, `Formant#width`, `Resonator#freq`, `MultitapDelay::DelayTap#delay`, `Silence#seconds`.  Renamed: `FourPole#filter` → `#kernel_filter` (`four_pole` is itself a DSL alias), `Tone#width` → `#pwm_width`, `Tone#soft_sync` → `#soft_sync?`, `Tee::Branch#tee` → `#owner_tee`, `Envelope#seconds` (private) → `#segment_seconds`, `SQ80::TimeScale#seconds` → `#time_seconds`.  `spec/lib/mb/sound/graph_node/dsl_shadowing_spec.rb` checks every GraphNode class by reflection: own public or private methods named like a DSL method must call super (seen as `invokesuper` in the instruction sequence) or be listed in its ALLOWED table with a reason (Knob#get_sampler, NodeSequence#and_then, the Pitch/Note/NotePitch frequency and tone shortcuts, Tone#wavetable).  The direction the maintainer prefers over ad hoc readers is a generic parameter API (`node.params`, `node[:width]`), not built yet.
