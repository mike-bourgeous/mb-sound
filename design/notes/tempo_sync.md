# Tempo sync

Detailed notes moved from CLAUDE.md (2026-10-10); CLAUDE.md keeps a summary and points here.  Update both when behavior changes.


`Sequence::Duration` (`lib/mb/sound/sequence/duration.rb`) is an exact musical length in whole notes (comparable, `+`/`-`, scaled by numbers, friendly `to_s` like "3 × n16"), accepted wherever lengths are (`on:`/`in:`/`at:`, `fade:`, `every`, `after`, `render(bars:)`, `.len`, `until`).  `1.beat.hz` is a Pitch whose frequency comes from a `Sequence::TempoNode` following the tempo, and `4.bars.lfo` a Tone from it.  Tones made from the pitch lock their phase to the timeline on jumps (start, seeks, resume) plus `with_phase`, top-down through two TempoNode ports that are inputs of each tone (`Tone#follow_timeline`; `jumps` is 1 on the first sample after a jump, `jump_phase` the timeline position in cycles there, shared frozen zeros otherwise), split and band-limited like resets; they freeze while the timeline is paused unless `.freewheel` (per TempoNode; `Tone#timeline` is the TempoNode).  `sig.delay(1.n8.dotted)` (or `sig.filter(3.n16.delay(...))`, `multitap(1.n8.d, ...)`) follows the tempo; `2.bars.lfo.square.at(3.n16..5.n16)` gives an alternating delay time (`Tone#musical_time?`).  Tempo-following nodes include `Sequence::TimelineNode` (shared with `MIDI::ClipSource`, found through the Notes nodes' streams), which `Session` finds in every graph (`timeline_nodes`).  `Tone#lfo` means full range plus no MIDI retrigger.  `render(bars:)` counts bars on the timeline, so tempo changes during a render are followed; `tail: true` adds the master effects tail after the limit.  See `bin/songs/tempo_song.rb`.

Meter map (2026-10-10, branch `arrange-form`; `arrangement.md`): `Transport#meters` (`Meter(pos, bar_length, bar)`), `#meter(bar_length, at:)` (on a bar line; later entries dropped), `#meter_at`, `#bar_at(pos)` (Rational bar position from 1), `#bar_position(bar)`, `#next_bar_line(pos, every = 1)`, `#bars_length(pos, bars)`, `#bar_length(pos = position)`; console `meter 7, 8` (alias `time_signature`).  Bar numbers count through the map (`bar(n)`, `at_bar`, `after`, `every`, `seek(n)`, `:bar`/N-bar alignments, `in: N`, stamps, `render(bars:)`, form sections given in plain bars, takes).  `bar_length=` sets one meter for the whole timeline.  `Numeric#bars` Durations stay whole notes at the current transport's bar length when created (`Sequence.current_transport`, below).

Build-time tempo (2026-10-15, branch `fixes-14`): conversions that read a tempo when a graph is built (Lengths and Durations to seconds or samples by default, `Numeric#bars`, `bounce`'s default `bpm:`, `render`'s default tempo, `Clip#bake`, `ghost_chords`' default span, `Sample#transport`) read `Sequence.current_transport`: the current Session context's transport (a `render` block, a scheduled block, a scene build), else the default `Sequence.transport`.  Before, they read the default transport, so a song's `bpm 72` in a render (which sets only the render's own transport) left them at 120: granular_song bounced its sources and read its spray's `density: 1.n16` at 120 BPM, and wind_chimes' section envelopes got their default hold (twice the time before the release, in seconds at build) at 120, which happened to equal the intended release at 60 BPM (the song now passes `hold:`; renders unchanged).  Inside a scheduled block, `bpm n` queues the change for the block's time; the rest of the block now reads it (`bpm` returns it; `current_transport` is a Transport at the pending tempo, kept in the context), so a bounce or a length built after it counts at the tempo it will play at.  Audit: every `bin/songs` script rendered on master-ai and the branch with a hook reporting default-transport reads under a render session at another tempo (314 sites before, only `TimelineNode#transport`'s fallback after, which Sessions replace on start); only granular_song (spray) and wind_chimes changed, both kept bit-identical to the Bench picks.  Spec: `spec/lib/mb/sound/sampler_spec.rb` ("bounces at the tempo...").
