# Racks, typed ports, and the inspection protocol

<!-- summary -->
A `MB::Sound::Rack` (`lib/mb/sound/rack.rb`, console `RackMethods`) is a frozen, Proc-like reusable graph with typed ports (`:notes`, `:audio`, `:control`): `mrack`, `irack`, `arack`, `lrack`, `modrack`, `rack(name, in:, out:, **ports)`; apply with `src.then(&r)`, `r.(src)`, `stream.through(r)`.
Named racks join `Session::Names`; `knob :space, 0.3` in a rack block is a rack knob (`:"dub/space"`, per player once two instances play).
Slots (R3): `sig.slot(:color) { }` / `midi.slot(:keys) { }` are swappable holes; `swap :"dub/color", arack { }, fade:` hands over on an exact frame like master chains (`Session::Handover`; instruments keep sounding notes); re-defined named racks swap their instances.
Rack documents (`save :dub, rack(:dub)`) and graph documents reload bit for bit; every Traversable answers `port_info`, `params`, and frozen `param_info`/`param_snapshot`.
<!-- /summary -->

## API

```ruby
wobble = mrack { it.arp(:up, 16).echo(3.n16, 2, pitch: 7) }   # anonymous: a value, like a Proc
bg :keys, midi.then(&wobble).synth { |v| v.hz.saw * v.amp_env }
wobble.(clip); clip.stream.through(wobble)                     # other ways to apply: r.(src), stream.through(r)

arack :dub, side: :audio do |sig, side:|                      # named, with a sidechain port
  sig.duck(side).delay(3.n16, feedback: 0.4, wet: 0.3)
end
bg :bass, bass_line.then(&rack(:dub).with(side: :drums))      # a bus or track name as a value
rack(:dub).(bass_line, side: kick)                            # or bound at the call

irack(:keys) { |stream| stream.synth { |v| v.hz.triangle * v.amp_env } }   # notes in, audio out
lrack(:level) { |sig| sig.abs.filter(:lowpass, cutoff: 10) }  # audio in, notes or control out (alias amrack)
modrack(:wobble) { |ctl| ctl * 0.5 + 0.5 }                    # control in
rack(:sc, in: :auto) { |sig, keys:| ... }                      # types from parameter names (prints them)

dreamy = wobble >> mrack { it.humanize(1.n64) }               # Proc#>> order
lead.stream + pad.stream                                       # note streams merge with +
racks                                                          # name => "effect audio(sig) + audio(side) -> audio, 1 use (in :bass)"
rack(:dub).to_ruby                                             # its definition
```

Full-word aliases: `note_rack`, `audio_rack`, `instrument_rack`, `listener_rack` (and `amrack`), `mod_rack`.

## Model

- **`MB::Sound::Rack`** (`lib/mb/sound/rack.rb`) is a frozen value: name (or nil), main input port, extra ports, declared output type, bound port values, the block, and the constructor name (for printing).  It answers `call`/`.()`/`[]`, `to_proc`, `>>`/`<<` (composed racks keep their parts and apply them in order), and `with` (a new Rack with ports bound).
- **Kinds** come from the main input and the output: `:note_fx` (notes -> notes), `:instrument` (notes -> audio), `:effect` (audio -> audio), `:listener` (audio -> notes/control; `lrack` always), `:modulator` (control -> anything).  Extra ports never change the kind.  When `out:` isn't declared, a rack's kind is its input's default (`mrack` :note_fx) until a named rack's listing has seen an application's output.
- **Constructors** (`MB::Sound::RackMethods`) fix the main input's type: `mrack` notes, `irack` notes with `out: :audio`, `arack` audio, `lrack` audio as a listener, `modrack` control, `rack(name, in:, out:)` the general form (`rack(name, in:, out:, **ports)` with extra ports).  Apply with `src.then(&r)`, `r.(src)`, or `stream.through(r)`.

## Ports

- Three types (`GraphNode::Traversable::PORT_TYPES`): `:notes`, `:audio`, `:control`.  Port declarations are `Rack::Port::Notes`/`Audio`/`Control`; each coerces values given to it and explains wrong-domain method calls.
- **Extra ports** are keywords of the constructor call naming their type (`keys: :notes`) and keywords of the block (`|sig, keys:|`).  A keyword on one side and not the other raises when the rack is defined, with did_you_mean (`|sig, key:|` against `keys: :notes`).  A block keyword with a default makes the port optional (`|sig, depth: 0.5|`; listed as `control(depth)?`).
- **Binding**: `with(keys: midi)` returns a new rack; ports passed at the call merge over it.  An unbound required port goes through `MB::Sound.live_error` (scripts and specs raise naming the port; live, the input passes through unchanged).
- **Coercion** (decision of this branch): notes ports take Streams and Notes as they are, Clips as `clip.notes` (so every stream transform and every voice signal works inside; the recipe prints `clip.notes.then(&r)`), and Sources as Streams; audio ports take nodes and bundles, Arrays of nodes as bundles, and Symbols as `bus(:name)` (a bus or track); control ports take nodes, numbers as constants, and Symbols as `knob(:name)`.  A Notes input to a note rack gives a Notes back (a Stream result is wrapped), so console `midi` stays usable as one voice.
- **Stand-ins**: the proposal's typed stand-ins are the bound values themselves, after coercion.  Building happens at each application, when the values are known, so no pass-through node sits at a port: plans fuse across rack edges (proposal 2.9), and `arack { it }.(x)` returns `x`.  The typing shows up where it helps: a NoMethodError on a port's value is re-raised with the port's type (`stream is a notes port: streams carry notes; .synth makes audio, .notes gives one voice's signals`; `sig is an audio port: audio carries samples; arp is a note transform (it needs a notes port)`), with Ruby's own did_you_mean suggestions kept.  Wrong-type values raise TypeError naming the port and the crossing (`notes become audio through .synth`).
- **Output check**: `out:` (given, or implied by `irack`/`lrack`) is checked against the block's result: notes vs. sample streams (audio and control are both sample streams, so an `arack` may return a control-like node).  Failures go through `live_error`.
- **`in: :auto`** (decision 7, opt-in) reads the types from parameter names (`stream`/`midi`/`keys`/`notes`/... notes; `sig`/`audio`/`input`/`side`/... audio; `ctl`/`control`/`mod`/`depth`/... control; `AUTO_TYPES`), prints `# rack :sc inferred audio(sig, keys: notes) -> ?`, and raises for names it doesn't know and for `it`/`_1` blocks (nameless parameters).

## Named racks

- `Session::Racks` (`session/racks.rb`): a name claims the Session namespace as kind `:rack` (`Session::Names`; a collision with a track, bus, or knob goes through `live_error`).  `rack(:x)` looks one up (KeyError with did_you_mean).  Defining a name again replaces the rack for later applications, and (R3) instances playing swap to it at the next launch point (Slots and live swaps, below).
- `racks` lists name => "kind signature, uses (in :player, ...)": each application is remembered weakly, and "in" names the current players whose graphs hold an instance (a Notes instance is found through its stream).

## Recipes and graph documents

- A rack's constructor isn't recorded (a Rack prints itself: `Rack#to_ruby` gives its constructor call and block source; console `rack(:x).to_ruby`).  An application is (printed as `src.then(&rack)`): `Rack#call` records a Call `src.then` with the rack as its argument and the rack's block as a build block (`Recipe.call(..., kind: :build)`; build block wrappers now pass keyword arguments, recorded after the positional ones).  `RubyWriter#rack_text` prints it as `src.then(&rack(:dub))` for named racks and `src.then(&arack { |sig| ... })` for anonymous ones, the block printed from the application's recorded body with parameters named after the ports (so `it` blocks print with names), bound ports as `.with(side: ...)`.
- The constructor names are in `Recipe::BUILD_BLOCKS` (so the graph document loader builds their blocks as document code) and in `GraphIO::Registry::TOP_EXTRA`; the registry allows `then` on graph values, Notes, Clips, and Streams, and `with`/`>>`/`<<` on racks; `Loader#call_block` takes a Rack as a block argument (`to_proc`); build blocks in documents may take keywords (required, or with defaults evaluated in the block's scope).
- Anonymous racks round-trip through `GraphIO.dump`/`load` bit for bit (spec: an effect, a sidechain-port rack bound with `with`, an optional port, an instrument rack on a clip).  A graph using a named rack prints `rack(:name)`; since R2 graph documents also carry the rack's definition, and rack documents save racks themselves (below).

## Note streams merge with `+`

`MIDI::Stream#+` and `Notes#+` are `merge` (decision 4: `&` stays free for a later meaning; `Clip#&` already layers clips, so Clip has no `+`).  `Notes#+` is recorded and prints as `a + b`.

## Typed ports on every Traversable (the inspection protocol, proposal 5.3)

- `port_info` => `{ in: [{ name:, type:, role:, source:, active: }], out: [{ name:, type: }] }` on every Traversable (`{ in: [{ name:, type:, role: :main/:side/:param/:feedback, source:, active: }], out: [{ name:, type: }] }` with the roles below).  `port_type` is the output type: `:audio` for graph nodes, `:notes` for MIDI streams, sources, transforms, allocators and their lanes, `:control` for constants, knobs, knob readers, and Notes nodes (gate, number, velocity, ...).  `Traversable.port_type_of` covers numbers (control), Clips, Seqs, and Notes (notes), which aren't Traversable.
- Roles: `:main` (inputs named input, channel_N, voice_N, stream, ..., `MAIN_INPUT`; and every edge from a multi-output node to its own output), `:side` (`side`, `sidechain_N`), `:param` (everything else), `:feedback` (`feedback_sources`).  A parameter edge is `:control` whatever feeds it (an audio node read as a parameter); a notes source makes a `:notes` edge.  Drum kits read every voice as a main input.  `port_role(name)` and `port_active?(name)` are the hooks classes override.
- Multi-output nodes list `:out_1`, `:out_2`, ...; nodes with side outputs (`GraphNode::Ports`: Tone `wraps`/`increment`, TempoNode `jumps`) add them after the main output as `:control` ports with descriptions and `in_use` (Ports#port_info used to return only these, as an Array).
- `#sources` and `#inputs` keep their return values.  `port_info_spec` checks every node of every graph sweep factory.
- `params` (generic, for graph code on the build thread): a node's `:param` inputs by name, constants as numbers, other nodes as given (through Tees to the node itself).  ChannelMixer keeps its own `params` and adds declared ranges.  Dynamics' and Limiter's kernel setting vectors were also called `params`; they are `kernel_params` now, so `params` means one thing.
- For painters and other threads (the Mac UI owner's contract, `/app/tmp/briefs/ui-rack-contract.md`, 2026-10-17): `param_info` is a frozen Hash `{ name => ParamValue }` and `param_snapshot` one deep-frozen (Ractor-shareable) `Params`; both read settings only (no sampling, no render lock), so UI::Poll can take them about 4 times a second.  Shapes:

  ```ruby
  GraphNode::Traversable::ParamValue = Data.define(:value, :type, :unit, :range, :label, :detail)
  #   value:  Numeric for constants and knobs (the knob's current value); nil when another node drives it
  #   type:   :control (or :notes for a notes edge)
  #   unit:   frozen String or nil ("Hz", " Q"); range: frozen Range or nil
  #   label:  a knob's name (Symbol) or a named node's name (String), else nil
  #   detail: frozen String describing the driving node or knob, or nil
  GraphNode::Traversable::Params = Data.define(:node_class, :name, :values, :preview)
  #   node_class: the node's Class; name: frozen String or nil (unnamed)
  #   values: frozen { Symbol => ParamValue }; params[:cutoff] is values[:cutoff]&.value
  #   preview: frozen Hash of what a preview needs (#preview_data) or nil
  ```
- Previews: `Plot::Panels.preview(klass, params, chart)` is a pure function of a `Params` snapshot (`Plot::Panels.register('Class::Name') { |params, chart| ... }`, inherited by subclasses), drawing through the chart layer (ChartBuilder marks and scales; every renderer, text cells included; never preformatted ANSI).  `node.plot_preview(chart)` is the convenience that takes the snapshot and calls it; `Plot.preview(node)` returns a Chart or nil.  Registered: filter nodes (`Filter::SampleWrapper` over an SVF or cookbook biquad; `preview_data` gives structure, type, sample rate, and cutoff/quality/gain with constant and knob inputs at their current values; the dB response on a log frequency axis) and shapers (mode and parameters; the transfer curve over -2..2); since sound-design-nav-1 four-pole filters and diode ladders (`GraphNode::FourPole#preview_data`: mode, cutoff, resonance, tuning, curve, normalization, drive; knobs and constants at their values, other inputs at the last value read and listed in `:moving`; `Filter::FourPole#response`, the kernel's linear response, checked against an impulse through the filter; titled `lp4 2400 Hz reso 0.25`, `~` on a moving value, the tuning when :hardware, dashed responses an octave either side of a moving cutoff).
- `spy(snapshot: true)`: `:post` spies get `buf.dup.freeze` of each buffer (the NArray class the node returns, usually Numo::SFloat; one buffer long; one copy shared by the node's snapshot spies; nil when the node ends), for planned nodes too (`Plan::Op::Tap` calls the same spies).  No frame number rides along (a spy inside a Session render can read `Session.span`).
- `MIDI::Stream#spy { |event, stamp| }` (with `handle:`, `clear_spies`): every event the stream reads, once however many readers it has.  `event` is the `MIDI::Event` the readers share (frozen Data: `type, channel, note, value, velocity, raw, bytes` (frozen String), `time` (Rational stream seconds), `bend_range, legato, pitch, flam, length_hint` (a Duration or nil); not `Ractor.shareable?` only because Durations aren't frozen); `stamp` is a `Session::Stamp` (frozen Data: `frame` Integer, `pos` Rational whole notes, `bar_length, meter_pos, meter_bar`; `#bar`, `#beat`, `#to_s` "bar:beat") of the frame it lands on while a Session renders, nil outside one.  Sessions publish the span being rendered on the render thread (`Session.span`, a reused `Session::Span` with `frame`, `pos`, `per_sample`, `moving`, `sample_rate`, and `#stamp(offset)`); a stream counts offsets from the first stream time it reads in each span (readers read whole spans).  Taps stamp with the Session clock, never with draw time (proposal 5.4).

## Agreed follow-ups for phase V (the UI owner's contract)

- Taps as data: `Session#tap(node_or_stream, kind: :audio|:control|:notes, window: frames)` returning a handle with `#close`; the render thread fills bounded per-tap rings inside the render lock, and UI::Feed copies them into the frozen Snapshot only when the painter took the last one (records: id, type, first_frame, a frozen SFloat or frozen Events with exact frames and positions).
- Static vs. dynamic: `Plot.graph` and the lanes Figure split into a layout built once (ranks, boxes, wire paths, scale domains, time window) and per-frame updates from snapshot data; a `structure_version` counter (Session/graph/rack epoch) bumps on graph and rack changes.
- Rack pane data: a frozen `RackInfo` per instance through UI::Poll (name, ports from `port_info`, latency, rack knobs, slots); pane actions only through public commands.
- `Mark::Notes` and every panel draw through Plot's cell layer; changes to `Plot::Live`, `UI::Feed`, or `UI::Snapshot` go to the UI branch owner as a struct/API or a patch.

## Rack knobs (R2)

```ruby
arack :dub do |sig|
  space = knob :space, 0.35, description: 'Echo level and feedback'
  tone = knob :tone, 2400, range: 600..8000, curve: :exp, unit: 'Hz'
  sig + sig.delay(3.n16, feedback: space * 0.7, wet: space, dry: 0).filter(:lowpass, cutoff: tone.mod(0.13.hz.lfo, depth: 0.15))
end
turn :"dub/space", 0.7, over: 2.bars
rack(:dub).snap :wide; recall :"dub/wide", over: 1.bar, only: [:space]   # or recall :"dub/wide", only: [:space]
```

- `knob(name, default, range:, curve:, unit:, cc:, takeover:, smooth:, share:, follow:, description:)` (`KnobMethods#knob` inside a rack block, through `RackMethods#rack_knob`; ux-r4b 2026-10-18: called knobs, not macros, by the maintainer's decision "to not copy Ableton": `macro` is gone, `knob` with a default (or `share:`/`follow:`/`description:`) inside a rack's block makes the rack's knob, without one it reads the rack's knob of that name, else the Session knob; outside a rack `knob` is the console's, and `share:`/`follow:`/`description:` raise there): it makes a `GraphNode::Knob` carrying a `Rack::KnobInfo` (rack, rack knob name, the `Rack::Application` of this `Rack#call`, share, follow, description).  `Rack#call` runs the block inside a thread-local Application (`Rack.applying`/`Rack.application`), so rack knobs know their instance.  Asking again by name (`knob(:space)`) or with the same definition returns the same knob (printed racks repeat `knob(...)` at each use); a different definition raises.
- Being knobs, rack knobs get `turn`/`over:`/`learn`/`cc:`/snapshots/takes/undo/plan params (`p.param`)/ACID XML unchanged.  `Knob#mod(source, depth:)` (any knob: `knob.mod(lfo, depth:)`) is baseline plus modulation in the knob's scale (octaves for exp knobs; depth in fractions of the range), limited to the range, built from graph arithmetic and `aclip`, so plans fuse it; recorded and allowed in documents.
- Names (maintainer decision 8): rack knobs are standalone knobs until a graph using them is adopted (`Session::Knobs#adopt_knobs(sound, player:)`; `bg` and `Session#add` pass the player name).  `Session::Racks#instance_knob_names` keys each instance `[player, ordinal]` (ordinal among applications of that rack in one graph): `:"dub/space"` while one key uses the rack; from the second key on, every instance is per player (`:"bass/dub/space"`, `:"bass/dub.2/space"`; without a player `:"dub.1/space"`), and the first key's knobs are renamed (`Knobs#rename_knob`: value, readers, and snapshot entries kept; live mode prints the rename).  The same player playing the rack again joins its own knobs (keeping the value; the rack's current range and curve).  Anonymous racks' rack knobs belong to the player (`:"bass/space"`, without a player `:"rack/space"`).  Once per instance, the short name (`:"dub/space"`) is a group (`Session::Names` kind `:knob_group`, `Racks#knob_group?`/`#group_members`): `turn :"dub/space", 0.6` turns every instance's knob (one journaled turn each, one undo step; round 2, maintainer 2026-10-17).  Instances of players that are gone (forgotten: not playing, not stopped for `resume`, not queued to start, not an arrangement track) are dropped when graphs join and on `forget` (`Knobs#prune_rack_knobs`, `Racks#prune_knob_instances`): their knobs leave the session and its names; a rack left with no instances goes back to plain names and its groups are released.  Stopped players keep theirs (resume, scene relaunches).
- `share: true` makes the rack knob `:space` itself, joined to (or becoming) the Session knob through the usual adopt rules (another range or curve: `live_error`).  `follow: :space` starts `Knob#follow` of that Session knob when the rack knob joins, mapped position to position (`Spec#positions`, clipped to 0..1) into the rack knob's range and curve; a missing knob is a `live_error`.  Turning the rack knob ends the follow, like any knob.
- Snapshots: `rack(:dub).snap :wide` is `snap :"dub/wide", knobs: <the rack's rack knobs, every instance>` (`Session#snap(knobs:)`, `KnobMethods#snap(knobs:)`); `recall` takes `only:`/`except:` with knob names or rack knob names (`:space` matches any knob whose last path part is `space`; a name in `only:` matching nothing raises); `Rack#recall`, `Rack#knobs`.
- Printing: a rack knob prints as `knob(:space, 0.35, ...)` (its held value) wherever it is used (`RubyWriter#rack_knob_text`, `RubyWriter.knob_args`), never as a document knob line, so graphs with anonymous racks round-trip bit for bit.

## Rack documents and format 4 (R2)

- `save :dub_echo, rack(:dub)` (`save :dub, rack(:dub)`) / `GraphIO.dump(rack)` (`GraphIO::RackWriter`) builds the rack once on stand-ins for its ports (`Rack#build_on_stand_ins`: a zero Constant for audio and control ports, an empty-clip Notes for notes ports; the block's calls are recorded as top-level calls, not as an application) and prints:

  ```ruby
  graph 4, name: "dub_echo", kind: :effect, rack: :arack, saved: ..., description: ...
  inputs sig: :audio                  # main port first; optional ports [type, default]
  outputs :audio
  knob :space, 0.35, description: "Echo level and feedback 0..1"   # the rack knobs (share:/follow: allowed here only)
  knob :tone, 2400.0, range: 600.0..8000.0, curve: :exp, unit: "Hz", description: "Echo lowpass"

  sig + sig.delay(3.n16, feedback: space * 0.7, wet: space, dry: 0).filter(:lowpass, cutoff: tone.mod(0.13.hz.lfo, depth: 0.15))
  ```
  Optional ports' defaults come from the block's source (`Rack#port_defaults`, Prism; R1 printed them as nil).  Composed racks aren't saved (DumpError).
- `GraphIO.load` of a rack document (`Loader#load_rack`) returns a Rack named after the document, whose block walks the body per application with the ports and the knob lines' rack knobs (made with `rack_knob`, so named and shared like any rack's) bound through `Scope#bindings`; given inputs, the Rack applied to them.  It re-saves to the same text and applies bit-identically to the original.  The Document is remembered per Rack (`GraphIO.rack_document`).
- `preset :dub_echo` returns the Rack, defined in the Session under its name; `preset :dub_echo, sig: mic, side: :drums` the applied instance (its rack knobs join the session).  `presets` lists racks with typed inputs and rack knobs.
- Graph documents carry the definitions of the named racks they apply (`RubyWriter` option `define_racks:`, used by `GraphIO::Writer` and `RackWriter`; `RubyWriter.rack_definition` prints a rack from a stand-in build: every port a parameter (optional ones with their defaults), rack knobs as `knob(...)` at their defaults, seeds left out so each application draws its own (round 2: definitions used to print from the first application's body, which baked in unbound optional ports' defaults); nested racks first, before the graph): `arack(:dub, side: :audio) { |sig, side:| ... }`.  The same rack always prints the same definition, which is how loading compares (`GraphIO.place_rack`, round 2, maintainer 2026-10-17; no subgraph namespaces): no rack of that name in the session defines it; the same printed definition uses the session's silently; a different one is a `Rack::Conflict` (name, both racks, source, `rename_to`, `options` `[:session, :saved, :rename]`) settled by `racks:` (`racks: :session | :saved | :rename`; `GraphIO.load`, `preset`), else by the choice a replaying take recorded (`Take.note_choice`/`.replay_choice`; take lines save `choices: [[:rack, :dub, :rename]]`), else in live mode by `GraphIO.rack_conflict_handler` (default: `Conflict#ask`, a one-line console prompt when stdin is a terminal; the tiled UI's picker can replace it), else `live_error` (scripts, specs, renders raise; live without an answer keeps the session's).  `:session` keeps the session's rack, `:saved` replaces it (`Session::Racks#replace`, one undo step through `note_undo_extra`; later applications everywhere use it, and instances playing swap to it at the next bar since R3), `:rename` defines the saved copy as the next free name (`:dub_2`, `Racks#free_name`) and points only this document's `rack(:dub)` at it (printing the name).  A bare `rack(:name)` with no definition in the document resolves to the session's rack, else a rack document of that name among the presets (`Loader#rack_reference`), else a LoadError.  `preset :dub` of a rack document settles the same way.  Bundles hold the definition the same way (inline only; maintainer 2026-10-17).
- Format 4 for every document: typed inputs (`inputs midi: :notes`; old `inputs :midi`/`:input` load unchanged as notes/audio, `Document#input_types`), optional `outputs`.  The library presets were saved again (only the graph and inputs lines changed).

- Exact reloads (round 3, maintainer 2026-10-17): each application builds under its own seed (`Rack#call` draws one from the root generator, bypassing the recorder, unless `Rack#using(seed:)` gives it, and runs the block in `MB::Sound.with_seed`), and graph documents print each named rack's use as `rack(:dub).using(seed: drawn_seed(N), space: 0.7)`: the seed (drawn ones as `drawn_seed`, so `seeds: :fresh` redraws them; left out in synth lanes, whose seeds derive from the lane's, and without seeds) and the instance's rack knobs' current values where they differ from the definition's defaults (`RubyWriter#using_args`; a rack knob that joined a session knob reads it through `Knob#joined`; shared and following rack knobs belong to their session knobs and aren't saved).  `using` rack knob values start the instance's knobs there (`Knob.new(initial:)`, the Spec's default unchanged).  The definition itself keeps defaults and no seeds.  A turned, randomized rack (noise, drift, unison) saved and loaded into a fresh session renders bit for bit (`rack_documents_spec.rb`).  Instances without a player (`preset :dub, sig: mic`, graphs loaded or built outside `bg`) are never pruned: their knobs live and die with their graph (maintainer: fine as is).

## Inspection data (R2)

- `Rack::RackInfo` (deep-frozen Data, Ractor-shareable): `name, path, kind, signature, ports` (frozen `{ name:, type:, role: :main/:side, required: }`), `latency` (samples: the longest path through nodes reporting `#latency`, e.g. dynamics lookahead and limiters, summed with `GraphNode.longest_path` (the edges `GraphNode.graph` takes, through Tees and node outputs; a guard spec checks it reaches every node of every graph sweep factory), from a stand-in build, remembered per Rack in `Rack::LATENCIES`), `knobs` (the instance's knob names), `knob_specs`, `slots` (R3: frozen `{ name:, path:, type: :audio, content: }` with the content playing; `Rack#slot_specs` from a stand-in build for a rack not playing).  `Rack#info`, `Session::Racks#rack_info` (`{ name => [RackInfo per instance with rack knobs] }`, no render lock), `#uses`, `#output_of`.
- `help rack(:dub)` (`help rack(:x)`, `Help::RackPage`): kind and signature, ports, knobs with ranges and their Session knobs, latency, uses, source.  `racks` lists rack knobs (`knobs space 0.35 (0..1), tone 2400 Hz (600..8000 exp)`).

## Slots and live swaps (R3, branch racks-r3, 2026-11-13)

Phase R3 of the proposal (2.7: slots and the four handovers; decision 10: no `keep: :state`).  Brief `workbench/briefs/racks-r3.md`.

```ruby
arack :dub do |sig|
  sig.slot(:color) { |s| s.softclip(0.3, 0.6) }.delay(3.n16, feedback: 0.4) * knob(:space, 0.5)
end
bg :keys, keys_part.then(&rack(:dub))
swap :"dub/color", arack { |s| s.diode(700, resonance: 0.5) }          # next bar, the old content spills over
swap :"dub/color", ->(s) { s.lp4(1500) }, fade: 1.n8, on: :beat         # a crossfade
swap(:"dub/color", on: :now, fade: 0) { |s| s.lp1(900) * 2 }            # a cut, block form
arack(:dub) { |sig| sig.lp4(2000).delay(3.n16, feedback: 0.3) }         # defined again: instances swap at the next bar
swap :dub, arack { |sig| sig.softclip }, at: bar(9), fade: 0            # the same with a launch point and a handover
racks; help rack(:dub); rack(:dub).info.slots                           # slots with the content playing
```

- **The node.**  `GraphNode::Slot` (`graph_node/slot.rb`; DSL `SlotMethods#slot`, in GraphNode and Channels, excluded from ChannelDispatch so a bundle's content gets the whole bundle) reads its input and pushes it to each content's `Slot::Feed` (one per channel; a content may read a buffer in pieces, never ahead of it; an input ending inside a buffer gives its last frames, then nil, as the content would read the input itself).  The graph reads `Slot::Output` nodes (a bundle for several channels; the default content's channel count is the slot's, and a later mono content plays on every channel).  `Output#sources` lists the contents (`input`, `input_2`, ... while older ones spill over) and the slot's input (`source`); Feeds have no sources, so walks of a content's graph (its timeline nodes, knobs, slots, a warm-up's node set) stay inside it (racks-r3's session fuzz: the feed listed the input once, and a swap restarted the player's own clip as the content's timeline node).  With one content at full level the slot passes buffers through untouched, bit for bit like the content alone; it is a plan boundary (contents plan on their own; `Plan.changed` on the outputs whenever contents come or go).
- **The handover.**  Contents are `Session::Master::Chain`s, and `Session::Handover` (`session/handover.rb`; extracted from `Session::Master`, which delegates) does what master and bus chains do: `:spill` (default: the old content fed silence from the switch frame, dropped on the exact frame its tail has been quiet for a second, faded from the frame it has rung 10 s), `:fade` (`fade:` bars: both fed, gains ramped), `:cut` (`fade: 0`).  A slot counts frames from `Session#player_frame` (like knob readers), so a content starts on its landing frame; one starting inside a buffer is sampled from there (`Chain#skip`); `Session#slot_started` reads the frames before it on its shared branches.  The slot ends when its current content ends (tails still spilling are cut then).  Measured: spill-overs and cuts bit-identical at 800 vs 367-frame buffers, crossfades within 6e-8 (the ramp steps per buffer, as master crossfades do).
- **Names.**  `Session::Slots#adopt_slots` (from `Session#add`, after `adopt_knobs`): a rack's slots share their instance's key with its knobs (`Racks#instance_member_names`, which `instance_knob_names` now calls; keys remembered per `Rack::Application`): `:"dub/color"`, per instance `:"bass/dub/color"` once two players use the rack, with `:"dub/color"` a group (`Names` kind `:slot_group`) that swaps every instance; anonymous racks' slots and slots outside racks are the player's (`:"bass/color"`; `:color` without a player).  Kind `:slot`; forgotten players' slots leave with their rack knobs (`Knobs#prune_rack_knobs`).  Slots inside a content (or a new definition) are adopted when it is built, taking the old names.
- **Swaps.**  `Session#swap_slot(name, content, on:/in:/at:, fade:, start_time:)` (console `swap :"dub/color", rack_or_block, fade:`, dispatched by name kind; `fade:` elsewhere in `swap` raises) builds each target slot's content at once (a Rack taking audio, a block or callable; its rack knobs join the Session as the player's), warms the swap in a sandbox (`Warming`: the slot's content playing on a noise stand-in swaps to a copy of the new one, so the handover runs), and lands through `Session#change` (kind `:slot`: journaled, one undo step, `Slots::SlotSubject` restoring by rebuilding the old content with the same handover; takes replay the console line).  Contents waiting in the queue, or landed and not started, keep in step with shared nodes (`SlotGraph` as the change's graph; `Slots#slot_waiting_graphs` in `Strip#catch_up_waiting`).
- **Re-defining a named rack** (`arack :dub do ... end` again, `swap :dub, rack_or_block, on:, fade:`, a document loaded with `racks: :saved`): `Racks#redefine` defines it and, in the same undo step (`note_undo_extra` for the definition, kind `:rack` change with `Slots::RackSubject` for the instances), `Session#swap_rack_instances` swaps every instance in a playing player: each named audio rack's application is wrapped in an instance slot (`Rack#instance_slot?`: a name, audio in, not a listener, `out:` not notes/control; `Rack.instance_slots = false` turns it off; an `arack` returning notes is built again without one), which remembers the applied rack and its coerced port values; the new instance builds on the same input with those values under a new seed, as a `Rack::Application` keeping the old one's instance key (`Racks#inherit_key`), so its knobs join the old names with their values; its recorded `then` call takes the new rack, so documents print the new definition once it plays.  Stopped players keep theirs (questions).
- **Instrument slots** (notes in, audio out; proposal 2.7's "patch persist"): `midi.slot(:keys) { |n| n.synth { |v| ... } }` (`Notes#slot`, `MIDI::Stream#slot`) and named instrument racks (`irack`, or `out: :audio` on a notes rack: wrapped in instance slots too).  Each content reads the input stream through a `MIDI::Transform::SlotGate` (`midi/transform/slot_gate.rb`): the old content keeps the notes it started (their note-offs and poly pressure) and drops note-ons from the swap on, the new one takes notes starting at the swap; controllers, bend, and the pedal reach both.  A content built ahead of its swap reads the input shifted to start on its first frame (`SlotGate#start`, from the slot's own reader on the input, its clock); the swap time is that clock plus the frame offset, so a note on the swap frame goes to the new content at any buffer size (spec at 800 and 367 frames).  The audio handover is the same Handover (the old content rings out its voices and is dropped once quiet, 10 s at most; `fade:` crossfades, `fade: 0` cuts the old voices).  Gates have no sources, so content graphs end at them; the slot lists the input stream.  Seeks while a shifted content plays: chases pass through unshifted (a question).  Note -> note slots (proposal row 1: the ledger ending the old chain's notes, `jump: :ring`/`:cut`) are not built.  A named instrument rack's application returns its slot's output now, not the Synth (graph walks still find the Synth; library_spec).
- **Documents.**  A slot outside racks or in an anonymous rack prints from its re-recorded `slot` call (`Recipe.call` at swap time, kept in the original call's scope and order, installed when the content starts): `sig.slot(:color) { |c| c.lp4(500) }`.  A named rack's instance prints `rack(:dub).using(seed: ..., color: arack { |c| c.lp4(500) })`: `Rack#using` takes slot contents by slot name (Racks or blocks) beside knob values, `RubyWriter#slot_content_text` prints `rack(:x)` (with its definition), an anonymous rack's own Ruby, or a block as an `arack`; the definition keeps its default.  A slot swapping when saved gets a comment line, as a moving knob does.  Rack documents print slots inline in the body (no `slot` header line yet: a question).
- **Listings.**  `racks` (`slots color (softclip)`), `RackInfo#slots`, `help rack(:dub)` (a slots section), `help :racks` (text and an example).
- **Measured** (Mac container, YJIT; scripts in the branch report): steady-state objects per 128-frame buffer unchanged by slots (a graph with a named effect rack 33.9 unwrapped, 33.8 in its instance slot; an instrument 22.0 -> 23.9 in a slot: the slot's clock read on the input); CPU of a small named effect rack in its instance slot 109 -> 115 us per 128-frame buffer (the copy into the feed, a plan boundary).  Realtime Session on a virtual-clock NullOutput at 800 frames (16.7 ms): the first swap landing in a fresh process took 66-233 ms (YJIT compiling the activation, handover, and plan rebuild), later ones 2-16 ms; `warm_up` (bin/sound.rb's startup warm-up) now swaps slots in a sandbox (`WarmUpMethods#warm_up_slots`, ~0.1 s), after which every landing window measured 6-15 ms.  Slot warm-ups set `Session#plan_rebuilds = :next_span` on their sandbox, so the new content runs unfused there as it does live until its plan lands.  Not solved: the buffers rendered while the console builds and warms a swap (the prompt side) stalled 84-162 ms on new kinds of content in the same run, as the first `bg` did (82 ms) without slots: GVL contention with building and compiling on the console thread, a general Warming finding (questions).
- **Control signals** go through audio slots: `fade:` crossfades two contents' values, which is the glide (`over:` like knobs isn't a separate option yet).
- **Coverage.**  `spec/lib/mb/sound/rack_slots_spec.rb`; graph sweep factories (a slot; one spilling over and one crossfading by their own frame counts; `GraphSweep::PERFORMANCE_STATE`); `SessionFuzz::COMMANDS` gained a slot command (a slot of a part or of a named rack swapped a beat or two later by spill-over, crossfade, or cut, or the rack defined again), which found three bugs on its first soak (the feed's sources, reading past an ending input, a swap landing after the input ended).

## Racks as library entries (library-core-1, 2026-10-26)

Instruments and effect chains are racks (maintainer, 2026-10-24): a library file's `instrument :x do |midi| ... end` is an irack, `chain :x do |sig| ... end` an arack (`note_fx` an mrack), each an Entry of family :preset whose builder places the rack in the Session (`GraphIO.place_rack`) and applies it; `preset :x` gives the Rack like a rack document; the Session's named racks are entries of the :session shelf (for find and the heads).  See library.md.

## Params (param-1, 2026-10-24)

Rack knobs (`knob :space, 0.3, range:, curve:, cc:, description:` in a rack block) build their `MB::Sound::Param` through `Knob::Spec` (`design/notes/params.md`), description included, so they take typed values (`knob :tone, 2400.hz, range: 600.hz..8000.hz`), ranged defaults, and names-table ranges (`knob :mix, 0.3` is 0..1) like any knob.
