# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

mb-sound is a Ruby library for sound processing with a fluent DSL for building signal processing chains. It is a companion to an educational YouTube video series about sound. It uses Numo::NArray (via the `numo-narray-alt` fork) for numeric operations and includes C extensions for performance-critical paths.

### Folders

- `bin/` - user-facing scripts and experiments (`bin/effects/`, `bin/synths/`, `bin/midi/`, `bin/songs/`, plus general utilities at the top level); all but `bin/sound.rb` use the script helpers (see Scripts below)
- `ext/` - C extensions for performance-critical functions
- `lib/` - Ruby code (most functionality lives here)
- `spec/` - Test suite

## Build & Development Commands

```bash
bundle install                    # Install dependencies
bundle exec rake compile          # Compile C extensions (required before running)
bundle exec rspec                 # Run full test suite
bundle exec rspec spec/some_spec.rb        # Run a single test file
bundle exec rspec spec/some_spec.rb:42     # Run a specific test line
bundle exec rake                  # Default task (runs spec)
bin/sound.rb                      # Launch interactive Pry console with MB::Sound context
bundle exec rake memcheck         # C extension specs under Valgrind (~6 min; options in Rakefile)
```

Testing: run affected specs while working, and the full suite (about 2 minutes) before and after each merge, or more often for good reason.  Save suite output to a file and grep it instead of rerunning.  Concurrent spec processes work (per-process temp dirs and coverage files); parallelizing the suite is deliberately postponed, since slow or leaky specs are better fixed than hidden.

Spec conventions (`spec/support/`):
- Temp files: `tmp_path('name.flac')` gives a path in an empty directory per example, inside a random per-process `Dir.mktmpdir` removed at exit (`KEEP_SPEC_TMP=1` keeps it); never write fixed names under `tmp/`.
- Coverage is opt-in: `SIMPLECOV=1 bundle exec rspec` (CI sets it) reports to `coverage/` (+~20% suite time, +~30% smoke); bin/ scripts run by specs get `spec/subprocess_coverage_helper.rb` (via RUBYOPT), merged into the report after the suite.  If script specs are slow, check `coverage/.resultset.json` isn't huge; `rm -rf coverage` is safe.
- `fork_script(script, *args)` runs a bin/ script in a fork of the spec process (skips ~0.7 s of startup); a spec using it must also run its script once as a real process doing real work, so load-order problems still show.
- Before each example spec_helper calls `MB::Sound.close_outputs`, so cached outputs (and NullOutput pacing) don't leak between examples.  Specs that run a Session on the shared transport must `MB::Sound.rewind` afterwards.
- For limits like `Session::MAX_TAIL_SECONDS`, `stub_const` the constant where it's defined (`Session::Master::MAX_TAIL_SECONDS`) instead of rendering 10 s of tail.
- Load-sensitive specs: a few realtime timing examples can fail under heavy load (concurrent renders, other suites) or Valgrind and pass on a rerun: `spec/lib/mb/sound/device_output_spec.rb:244`, and `live_source_spec.rb`'s JACK "frame plus the latency" example under `rake memcheck` (first note one 256-sample period early).  Rerun once before investigating; under memcheck, Valgrind errors (not timing failures) are what count.
- Short inputs: `spec/test_data/arp_a7.flac` is a 0.4 s stereo Am7/Amaj7 triangle arp (made by `spec/test_data/make_arp_a7.rb`) for effect and script specs; test MIDI files start within 0.2 s.

The bin/ script smoke tests (`spec/bin/script_smoke_spec.rb`, tagged `:smoke`, about 1.5 minutes; plain `rspec` skips them, CI runs them as a separate job) run every script with `--help` (in forks for scripts that also render) and a short render (real processes), with shared-buffer checks raising (see Core Abstraction).  Run them with `bundle exec rspec --tag smoke` before merging changes to bin/ scripts, the script runner, or nodes that touch input buffers, and add new scripts to their tables.

System dependencies (apt): `ffmpeg gnuplot-qt libsamplerate0-dev libasound2-dev libjack-jackd2-dev jackd2 graphviz` (ALSA headers build RtMidi's ALSA sequencer backend; the shared JACK client loads libjack at run time, so `libjack-jackd2-dev` only builds RtMidi's JACK API, which specs use as an outside JACK client; `jackd2` runs a dummy JACK server for the JACK specs, which skip without it).  In the container, the Dockerfile sets `OUTPUT_TYPE=null` so playback uses `NullOutput`.

## Architecture

### Core Abstraction: GraphNode DSL

The central pattern is `GraphNode` (`lib/mb/sound/graph_node.rb`), a module mixed into any class that implements `#sample`. It enables fluent chaining to build signal processing graphs:

```ruby
play 123.hz.triangle.at(-20.db)   # oscillators play until Ctrl-C
play 123.hz.fm(369.hz.at(1000)).softclip.filter(150.hz.highpass(quality: 4))
```

The DSL methods (`#filter`, `#delay`, `#softclip`, arithmetic operators, etc.) live in topic modules included by `GraphNode`, in `lib/mb/sound/graph_node/*_methods.rb`; `graph_node.rb` keeps naming, graph traversal, and shared private helpers.  Graph nodes support traversal via the `Traversable` mixin; key node types live in `lib/mb/sound/graph_node/`, MIDI nodes in `lib/mb/sound/notes/`.

Every consumer of GraphNodes must call `get_sampler` on the node(s) it stores in its constructor (e.g. `Tone#fixup_source`, `ProcNode`, `Filter::Delay` for delay-time nodes).  That branches a node used in several places through a `Tee`, so each use gets the same samples instead of advancing it twice (the user is open to an alternate design later).

When a Tee's branches read in lockstep (each reads every buffer once with the same count, as in a Session), they all get one frozen view of the source's buffer; otherwise the Tee copies through a CircularBuffer until they catch up (`lib/mb/sound/graph_node/tee.rb`).  So a node that processes its input in place copies it first only if `buf.frozen?` (user rule, so unshared chains keep passing one buffer through; e.g. Reverb's dry path, `SampleWrapper(in_place: true)`, Delay smoothing; `GraphNode::FrozenCopy` reuses one copy buffer).  Constants, TempoNodes, and Notes nodes return one frozen buffer while their value holds.  Numo blocks most writes to frozen views but not in-place arithmetic (`buf.inplace * 2`), so `Tee.shared_check` (env `MB_SOUND_CHECK_SHARED=1`) verifies shared buffers: raising in scripts and specs (the `:check_shared` tag; on in the smoke suite), warning and copying in `bin/sound.rb` (off by default there).  `MB_SOUND_SHARED_TEE=0` turns sharing off.  Multiplier and Mixer have allocation-free fast paths for full buffers that don't promote their type (`ArithmeticNodeHelper#arithmetic_fast?`, C kernels in `fast_arithmetic`), bit-identical to the general path; so does `ChannelMixer::Pan` with a node position (`FastArithmetic.pan`, Numo's float steps, cos and sin in separate loops so no compiler merges them into sincos).

Measure graph cost with `bin/graph_profile.rb [-n 32,128,800] [--profile] script.rb` (captures a bin script's graph; reports GC runs and time, objects per buffer, and buffer CPU times with and without a GC; `--profile` adds self time and allocations per node class, inflated ~3 us per call; `-a N` lists the top N allocation sites); compare branches in alternating runs against a master-ai worktree.  Cost on 2026-10-06 (best of 5, % of realtime at 128/512-sample buffers): fm_bass 32.8/19.4, fm_epiano 16.9/6.2, stereo_drone 58.0/39.8, tempo_song 13.1/4.4, antialias_song 15.0/5.4.  Objects per 128-sample buffer on 2026-10-07: fm_epiano 44 (was 94; most of the rest are MIDI stream Rationals), stereo_drone 21 (40), fm_bass 76 (80).

### Numeric Mixins

`lib/mb/sound/numeric_sound_mixins.rb` adds methods like `.hz`, `.db`, `.meters`, `.bits` to Numeric (e.g. `440.hz.sine`, `-20.db`).  `440.hz` is a `Pitch` (`lib/mb/sound/pitch.rb`): a light frequency source whose oscillator methods (`sine`, `ramp`, `at`, `fm`, `pm`, `lfo`, `tone`/`hz`, `phasor`) make a new `Tone` each call; it plays as a full-scale sine when used directly as a signal, and sequences can hold it as a fixed frequency (`seq(C4, 440.hz)`).  `Note < Pitch` (C4 = 60) gets its frequency from the session `Tuning` (`tuning b4: 480`, live; in a scheduled block it changes on the block's time, `Session#at_time`).

`Tone` (`lib/mb/sound/tone.rb`) is the one oscillator node (no separate Oscillator or Phasor classes; `pitch.phasor` is a Tone with wave type `:phasor` that outputs its phase in cycles, no `at`).  Its DSL methods configure it before it plays (afterwards they raise `FrozenError`, or warn and change nothing in live mode; values that change come from input nodes; `sample_rate=` works any time), and everything that changes per sample (phase in cycles, band-limiting history, queued jump step, random-phase seed and draws) is one `Tone::State` (`lib/mb/sound/tone/state.rb`; plain-value `to_h`, chosen with `bin/osc_state_benchmark.rb`).  The class comment maps each buffer's steps to plan-layer ops (inputs, SPLIT at resets/timeline jumps, PHASE, SHAPE, GAIN, JUMP, PORTS).

Lengths: `Sequence::NumericDurations` adds musical lengths (`2.bars`, `3.beats`, `3.n16`, `3.sixteenths`, `1.n8.dotted`) returning `Sequence::Duration`s (see Tempo sync).  `MB::Sound::Length` (`lib/mb/sound/length.rb`) adds `Length::Seconds` (`4.seconds`, `250.ms`) and `Length::Samples` (`5.samples`, counted at the sample rate where used, so inside `oversample` too), sharing one protocol with Duration (`to_seconds`/`to_samples`/`to_whole_notes`); `node.samples` / `node.seconds` mark a node's unit.  Every method that takes a length accepts all of them plus plain numbers in its usual unit (seconds for delays, envelopes, `until`, `silence`, `render(seconds:)`; bars for fades and schedules; samples for `with_buffer`), via `Length.seconds`/`Length.samples` or `Duration.bars`/`Duration.whole_notes`.  Changing lengths (delay times) go through `Length::Source`, which keeps the unit and converts per buffer at the current rate.  `MB::Sound::Interval` (`lib/mb/sound/interval.rb`) is the pitch interval: `4.octaves` (`.oct`), `7.semitones` (`.st`, `.semi`), `50.cents` (whole cents exact; `1200.cents == 1.oct`), with `#to_semitones`/`#to_octaves`/`#to_cents`/`#ratio` and arithmetic; methods taking an interval also accept plain numbers in their usual unit via `Interval.semitones`/`Interval.octaves` (semitones for `transpose` on Notes, Pitches, clips, and seqs).

### Oscillators and antialiasing

Tone waveforms are antialiased by default (`lib/mb/sound/band_limit.rb`, kernels in the `fast_synth` extension); every shape has a naive (aliased) `a*` twin for lo-fi sounds and control signals.  Measure any expression with `bin/aliasing.rb 'p.ramp' 'p.aramp'` (coherent-sampling aliasing table and cost; `--render DIR` writes 100 Hz-8 kHz sweeps with spectrograms).

- `ramp`/`saw`, `square`, `triangle` use PolyBLEP/PolyBLAMP (corrections on the samples either side of each edge, found on the phase plus phase modulation, so FM/PM and through-zero motion work); `aramp`/`asaw`, `asquare`, `atriangle` are naive (`Tone#band_limited?`).  `.lfo` fades band-limiting in from 15 to 30 Hz (`BandLimit::LFO_FADE`), so slow LFOs keep exact jumps (delay times, gates) and audio-rate "LFOs" are clean.
- `pwm(width)` (alias `skew`; width a number or node) warps the phase of any shape: `square` → pulse (`pulse(w)`/`apulse(w)`), `triangle.skew(0.1)` → near-saw, `sine.pwm(w)` → CZ-style phase distortion; DC offset removed by default (`dc: true` keeps it); the warp's corners are band-limited too.
- `complex_ramp`/`complex_square`/`complex_triangle` are closed-form band-limited impulse trains, integrated (`BandLimit.blit_ruby`): no aliasing or negative frequencies (-153 dB), top octave lifted ~2.6 dB; with phase modulation they fall back to the naive `acomplex_*`.
- `sync(ratio: r)` hard-syncs a tone to a hidden master at its own pitch (playing at pitch × r; r a number or node), `sync(master)` to a Pitch/Tone/phasor (its `wraps` port) or any trigger node; `softsync` reverses direction instead.  Synced tones use a causal minBLEP kernel whose output is exactly the naive waveform through the minBLEP's minimum-phase filter (`FastSynth.oscillate_sync`, `BandLimit.sync_tables`): polynomial segments are delayed by the filter's moments (about 2.78 samples) and events add residuals of their value, slope, and curvature jumps; sine segments use per-frequency residuals (`BandLimit.sync_sine_table`, 6 MB, built on first use).  So DC and harmonics match the ideal synced waveform (DC error < 1e-4; harmonics -56 to -106 dB; aliasing -88 to -135 dB); until 2026-10-07 every step left 2.78 samples times its height of DC behind (+0.82 on a ramp synced at 2.37x of 3 kHz) and soft-synced squares spiked on their edge at phase 0.  Synced sines cost 1.3-2.2% of realtime at 3-4 kHz masters; no phase modulation with sync.
- Phase jumps (reset inputs, timeline jumps of tempo tones) are band-limited steps over the next 32 samples (minBLEP/minBLAMP from the old waveform to the new, queued in `state.jump_residual`).  Nothing sets the phase from outside (no `phi=`/`sync_cycles`); jumps arrive through inputs.
- Reset inputs (top-down note flow): `tone.reset(trig, to: nil)` jumps the phase at every nonzero sample of `trig` (e.g. `clip.trigger`), at exactly that sample (step measured with that sample's FM/PM/width); `to:` is nil (the `with_phase` start), radians, a node, or `:random`; `reset(nil)` removes it; not with `sync`.  The Tone splits the buffer at reset samples in Ruby around the kernels (a scan costs ~3 us per 128-sample buffer, each reset ~35 us; tones without a reset input skip it).  `.free` (`free?`) = never reset (no key sync in synth voices; reset+free and rnd+fixed `to:` conflicts: last call wins with a warning; reset+sync raises; `lfo` tones aren't `free?` but may take a reset input); `.random_phase`/`.rnd(seed:)` = random start, new random phase per reset.  Randomness: `MB::Sound.seed(n)` / `random_seed` / `next_seed` (`RandomMethods`, default seed 0 or `RANDOM_SEED`, restored before every spec example); random-phase tones draw a sub-seed when `rnd` is called (creation order), `Tone#seed=` for derived seeds.  `smooth(t, reset: trig)` jumps instead of gliding on resets.  Noise (`noise(seed:)`, `Tone#noise(blend, seed:)`) draws a sub-seed when `noise` is called too and keeps its own splitmix64 state (`Tone::State#noise`, read and written by the `fast_sound` kernels; exact Ruby mirror `Tone.noise_random`), so noise repeats from the seed and parts don't share a stream (it used C's process-wide `drand48` until 2026-10-06, so noise renders changed then).
- `softclip`, `clip`, `abs`, numeric `quantize` use antiderivative antialiasing on the excess over the linear part plus a half-sample Thiran allpass on the dry signal (`MB::Sound::Shaper`, `GraphNode::Shaper`, the `fast_clip` extension): flat level, half a sample of delay, aliases below the fundamental 25-56 dB lower; `asoftclip`, `aclip`, `aabs`, `aquantize` are the plain shapers (exact, for control signals).
- Ports (`GraphNode::Ports`): side outputs that aren't audio channels, made on first use: `tone.wraps` (sync pulses valued 1 - d, d the sub-sample position of the wrap; a wrap within 1e-9 of a sample gives 1 on it, so 2000 Hz pulses every 24 samples; `BandLimit.sync_pulses`) and `.increment`, `TempoNode#jumps`/`#jump_phase` (see Tempo sync); `node.ports`, `port_info`, `inputs`.  A node with ports computes frames; every reader (main output and ports) must read each buffer, as a Session does.
- Wavetables (`lib/mb/sound/wavetable.rb`, `wavetable/`; kernels in `fast_wavetable`, exact mirrors in `Wavetable::KernelRuby`): `Wavetable` is one value class for cycle tables (frames, `scan:` 0..1 morphs linearly, frames aligned in time by default) and samples (`mode: :sample`, `root:`, `loop:` Range of samples or Lengths, one-shots end unless reset); constructors `.from_harmonics` (exact Fourier amplitudes; the library's classic shapes are exact series too, with natural Gibbs peaks of about 1.18 on the saw and square, at the PolyBLEP tones' RMS and harmonic levels but with different peaks (user's choice); opt-in `taper: :sigma` applies Lanczos sigma factors per level for peaks near 1), `.from_samples`, `.from_function`, `.from_file`, `Wavetable[:saw | 'file' | array]` (library: `.register`, `.names`); `#save` writes everything derived (`#metadata`: mode, period, frames, aligned, spacing, taper, harmonics, root, loop, slicing details in `#source_info`) and `.from_file` uses it (no re-alignment); the frame helpers are `Wavetable.load_frames`/`save_frames`/`slice_frames`/`normalize`/`sort`/`blur`.  Stored as levels (mipmaps, `mips:` `:octave` default, `:half_octave`, a ratio, harmonic counts, or false) 4x oversampled; a tone picks levels by its motion per sample (increment, PM, warp slope) under the alias ceiling (harmonics may pass Nyquist if they fold above 20 kHz), crossfading over the last 1/5 octave (`LEVEL_FADE`).  Interpolation `:optimal` (Niemitalo 4-point 4th-order for 4x, default; its passband droop is undone by emphasized levels, `Wavetable::Emphasis`), `:cubic` (default without levels), `:linear`, `:none`, `:sinc` (Kaiser beta 12).  `440.hz.wavetable(t, scan:)` is a Tone wave type: FM, PM, `pwm` (PolyBLAMP corners), `sync`/`softsync` (real or complex cycle tables: an exact minimum-phase residual per harmonic at each sync event, `Wavetable.sync_residuals`, on `#sync_levels`: every harmonic count to 8 then quarter octaves, all below 20 kHz, always crossfading, so brightness doesn't step; truncated Taylor residuals overshot to several times full scale near 3 kHz), `noise`, resets, ports, `Wavetable::KeyMap` key zones picked at resets.  `node.phase_table(t, scan:, wrap:, increment:)` (also `#wavetable` on non-Tones) reads at a phase in cycles and `sig.waveshape(t, scan:)` maps -1..1 across the table (clamped); both pick levels from an `increment:` node, a phasor's `increment` port, or else the input's own change per sample (held peak; `increment: false` = brightest level).  `Pitch#harmonics(spectrum, update: 512)` (`GraphNode::HarmonicTable`) is an additive oscillator whose spectrum (numbers, nodes, or a callable of time) changes while it plays (32 harmonics: ~100 us per rebuild, 1.4% of realtime at 512-sample buffers, 1.8% at 128, plus its amplitude sources; spectra and half means in C, `FastWavetable.harmonic_spectra`/`.half_means`).  Synced tables don't band-limit `pwm` corners (-26 to -44 dB): correcting them per harmonic works for aliasing (-88 to -104 dB) but exposes the table sync's zero-delay residuals' DC error (2026-10-07 study and the reverted patch on the never-merged branch `research-sync` (2f595c60, `research/sync/`)).  Measured: saw table -104 to -110 dB of aliasing (NHR<20k) vs -33 to -38 for PolyBLEP `ramp`; synced saw table -104 / -100 dB at 1 / 3 kHz (synced ramp -99 / -95; sync kernel 60-75 ns per sample, 140 with the slave below the master); kernel 17-25 ns per sample; ~0.15-0.24% of realtime per tone.  Demo and snippets: `bin/songs/wavetable_song.rb`.
- Still aliasing: FM/PM sidebands (use `oversample`), `gauss`, naive `a*` shapes, unmipped (`mips: false`) tables.  Demo and A/B snippets: `bin/songs/antialias_song.rb`.
- Unison: `pitch.unison(n, detune: 12.cents, layout: :random, phase: :random, spread: 0, normalize: :power, seed: nil) { |p, i| p.saw }` on any Pitch (`220.hz`, Notes, `v.hz`; `lib/mb/sound/unison.rb`): the block gets each copy's `pitch.transpose(offset)` (so `v.hz` keeps key sync, bend, glide, vibrato), and every oscillator made from it (or pitches derived from it) gets the phase through `Pitch#unison_phase` (`:random` = `rnd`, new random phases at each key-sync reset; radians; `:reset` = leave alone).  `detune` is the outermost copies' distance either side (Interval or semitones, or an Array of fixed offsets, or a node of semitones: copies keep fixed layout fractions -1..1 scaled by it, computed for all copies at once by `Unison::Detune` in the `fast_unison` extension; copies are `Unison::CopyPitch`es making the base pitch's kind of tone; `detune_mode: :interp` (default) ramps the exact outermost ratio every 16 samples of the stream (buffer-size independent) and spaces copies linearly in Hz, middle copy sharp by 1200·log2(cosh(d·ln2/12)) cents (0.18 at 25 cents, 2.9 at 100), ~half the cost of `:exact` (exp per copy per sample); fixed detunes keep the plain `transpose` path); `:random` layout jitters by up to 1/3 step, recenters, rescales (seeded from the root RNG, or `seed:` for the layout only; per-lane in synths).  `GraphNode::ChannelMixer::Unison` mixes with 1/sqrt(n) (or `:peak` 1/n); `spread > 0` (or a node) returns stereo, equal-power pans × sqrt(2) with sides alternating by pair (`Unison.pan_slots`).  `mix:` (0..1 or a node, default 1 = bit-identical) is the side copies' level: center copies (`Unison.center_copies`: nearest the pitch for odd counts, two nearest for even; 2 copies are both centers) stay at 1, and the normalization follows the weights (power 1/sqrt(Σw²), so loudness stays put).  Per copy: the block gets `|p, i|`, `Pitch#unison_copy` (`Unison::Copy`: index, count, RNG from the unison's seed drawn after the layout), and pitch methods on copies take per-copy values: a Range (random), `spread(a..b)` (even, lowest copy first), `channels(...)` (cycled); Intervals → semitones, Lengths → seconds.  Node-detune copies of Notes pitches take `glide`/`bend_range`/`vibrato`/`transpose(node)` (`CopyPitch#notes_pitch`: a NotePitch transposed by the copy's offset node fraction × detune, so exact detune through `Notes::Frequency`; the `Detune` node is built lazily by `Unison::CopySet` only if plain copies use it).  Glides with the same settings share one `Notes::Glide` per Notes (memoized in `NotePitch#number_node`; before and inside the block alike).  `Pitch#transpose`/`NotePitch#transpose` take a node of semitones; a fixed transpose of a tempo pitch gives `TempoNode#scaled(ratio)` (exact ratio, freewheel follows the parent), so `1.beat.hz.unison(3)` stays timeline-locked.  `Notes::Glide` has `overshoot:` (0..1, smoothstep + k t³(1-t)²) and relative `from: -7.st`.  `pitch.swarm(12, chord:, detune:, glide: 0.08..0.9, overshoot:, scatter: 1.oct | from: G3..G4, drift: 10.cents, drift_rate:, spread: 1, ...)` (`lib/mb/sound/unison/swarm.rb`) is a unison of per-copy glides on Notes pitches, optional chord tones (`Unison.chord_offsets`), scattered or banded starts, and sine drift; cost ~0.8% of realtime per gliding copy at 512-sample buffers (Glide + Frequency + saw each; 24 copies ~20%, ~56% at 128), less once glides settle.  Demos: `bin/songs/unison_song.rb`, `bin/songs/swarm_song.rb`.

### Method Modules

`MB::Sound` extends several method modules that provide the top-level API available in `bin/sound.rb`:
- `IOMethods` - File read/write via ffmpeg
- `PlaybackMethods` - `play`, `input`, real-time audio, plus the background session:
  - `bg` / `stop` / `outro` (alias `fadeout`) / `panic` / `players` / `resume` / `stopped` / `forget` play sounds in the background through one shared `Session` (`lib/mb/sound/session.rb`) that mixes every player in a single render loop locked to the sequence timeline
  - `swap` changes the clips a player plays without rebuilding its graph; `master` (alias `master_fx`) sets master effects on the mix (see Sequences and Master effects below)
  - `visualize` (alias `vis`) plots the mix live; `render` runs a `Session` into a file (or any output object); `wait` blocks until everything has ended, including master effects tails (use it at the end of scripts); `use_output` sets the background session's output (see Audio I/O below)
- `MultichannelMethods` - `channels`, `stereo`, `spread` build multichannel signals and per-channel arguments (see Multichannel below)
- `ScheduleMethods` - `at_bar` (alias `on_bar`) / `after` / `every` / `scheduled` / `cancel` run blocks at bars on the `Session` timeline; `bg`/`stop`/`resume`/`bpm` inside them take effect exactly at the scheduled time (see `bin/songs/scheduled_song.rb`)
- `PlotMethods` - Terminal/gnuplot visualization
- `FFTMethods` - Spectral analysis
- `ScriptingMethods` - `effect_script` / `synth_script` / `song_script` / `script` for standalone scripts in bin/ (see Scripts below)
- `GainMethods`, `WindowMethods`, `AnalysisMethods`
- `LiveMethods` - `MB::Sound.live?`/`live=` (`bin/sound.rb` turns it on) and `live_error(exception)`: raise in scripts and specs, warn and return nil in live mode so a live set keeps playing (the caller skips the change; used by Tone's build-time-only settings)

- `ext/mb/sound/fast_envelope/` - Envelope state machine (`FastEnvelope.process`; built with `-ffp-contract=off` for its exact mirror) → `lib/mb/sound/fast_envelope.so`
- `ext/mb/sound/fast_audio/` - Sound card I/O through bundled miniaudio, plus the JACK backend (see Audio I/O) → `lib/mb/sound/fast_audio.so`
- `ext/mb/sound/fast_midi/` - Bundled RtMidi (see MIDI) → `lib/mb/sound/fast_midi.so`

New C code goes in purpose-specific extensions (the user's preference) rather than growing `fast_sound`; helpers shared between them (`mb_wrap`, `mb_ensure_inplace_sfloat`, `mb_read_signal_input`, ...) are `static inline` in `ext/mb/sound/include/mb_ext_helpers.h`, added to the include path by each `extconf.rb`.  Each kernel has an exact Ruby mirror that specs compare sample for sample (keep the operations identical, including float32 reads of signal inputs).  `depend` files list an extension's headers (rake doesn't rebuild on header changes otherwise); after changing `depend` or removing a source file, `rm -rf tmp/<platform>/<extension>` so the Makefile is regenerated.

### Envelopes

`MB::Sound::Envelope` (`lib/mb/sound/envelope.rb`; kernel in `fast_envelope`, exact Ruby mirror `Envelope.process_ruby`) is a state machine (idle, attack, decay, sustain, release, choke, ended) over curved segments (a segment list with a release node, ready for multi-segment envelopes) that land exactly on their targets at their times (whole samples).  Curves are signed dB, SuperCollider's curvature (`c = -d ln 10 / 20`): +60 falls like a 60 dB exponential, 0 is linear, negative swells; presets `:linear`, `:analog` [12, 60, 60] (default), `:snappy`, `:gentle`, `:swell`, `:dx`; `curve: 60`, `{ release: 30 }`, `[a, d, r]`, or `.curve(...)`; +30 is about the old `adsr(...).db(30)` (`GraphNode#db` is gone: write `10 ** (node / 20)` to turn dB into gain; `Numeric#db` stays).

Segment shapes (`shape:` `:exp` default or `:s`, per stage `{ attack: :s }`/`[a, d, r]`, or `.shape(...)`): `:s` is smoothstep of the dB-warped phase (zero slope at both ends; 0 dB = the old smoothstep ADSREnvelope); a time change re-rates the phase so it still lands on time, target/curve changes re-anchor at the current level and phase, and after a re-plan, release, or retrigger a short Hermite slope carry (≤ 2 ms, `S_SLOPE_TIME`; ≤ 1% of the step, `S_OVERSHOOT`) avoids corners.  Presets `:smooth` (S, [0, 0, 0]: the old ADSREnvelope exactly) and `:pad` (S, [0, 12, 12]); a curve preset name also sets the shapes (`CURVE_SHAPES`), `shape:` applies after `curve:`.  S code is out of line in the kernel (`env_plan_s`/`env_sample_s`) so the exp loop stays fast (ns/sample: exp 17.5, S 22.5).

Times, sustain, and curves take numbers, Lengths (Durations follow the tempo), or nodes; a change mid-segment re-plans the rest from the current level.  Inputs are signals: `gate:` (edges), `trigger:` (rising edges to > 0; negative values reserved), `velocity:` (read at the note start, mapped by a `sensitivity:` Range, `velocity_scale: :linear`/`:db`), `choke:` (3 ms, linear), `lift:` (release velocity at the release start: release time × 2 ** ((0.5 - lift) × 2), off by default); `.legato`.  `retrigger: :add` (or `.retrigger(:add)`) makes a note that starts while sounding attack to the energy sum sqrt(level² + peak²) (capped by `ADD_LIMIT`, so rolls level off within +3 dB of one strike; never below the current level) instead of its own peak (`:restart`, default), so soft re-strikes of ringing notes don't drop (`#velocity_peak`/`#retrigger_peak` predict peaks).  Without a gate, notes release `hold:` seconds after they start (default 2 × (attack + decay), at least 0.1; `false` forever); without gate or trigger it's a one-shot (then `#sample` returns nil); gated and triggered ones never end (`#idle?`).  Constructors (`EnvelopeMethods`, defaults 5 ms / 0.2 s / 0.7 / 0.3 s): `adsr` (generic, sensitivity 0..1; `node.adsr` multiplies; old `auto_release:`/`log:` are `hold:`/`curve:`), `env` (0.5..1), `amp_env` (release +40, -18..0 dB velocity), `fm_env` (`:dx`, sustain 0), `filter_env`/`filt_env` (outputs the cutoff multiplier 2 ** (env × `depth:` octaves; a number, `#to_octaves`, or a node), default 2).  Plot with `bin/plot_envelope.rb` (`--compare`, `--print`, `--shape s,exp,exp`).

### Tweening curves

`MB::Sound::Curve` (`lib/mb/sound/curve.rb`, `curve/library.rb`) maps progress 0..1 to 0..1 (overshoot allowed), shared by glides, tweens, smoothing, shapers, and TimelineInterpolator blends: `Curve[:elastic, overshoot: 0.4, cycles: 4]`, names `linear smoothstep(:smooth,:s) smootherstep sine(_in/_out) quad..quint exp back anticipate elastic squiggle bounce steps ease(_in/_out/_in_out)`, any name with `_in/_out/_in_out/_out_in`, `Curve.db(d)`/`Curve.s(d)` (Envelope's signed-dB curve and :s shape, specs check they match), `Curve.power`, `Curve.bezier`, Procs; `reverse`, `in`/`out`/`in_out`, `>>`, `blend`, `steps`.  `#call` and `#map` (Numo) give identical values; `#lookup` evaluates a 2048-cell Hermite value table in C (`FastClip.curve_lookup`, ~4 us per 512 positions for any curve, within 1e-7 of `#map` except at bounce contacts (1e-4) and vertical end slopes), used by glides.  `bin/plot_curves.rb` plots or tabulates them.

- Glides: `v.hz.glide(t, shape: :squiggle, overshoot:, cycles:)` (`Notes::Glide`; no shape = the old smoothstep code, bit-identical, pinned by `spec/lib/mb/sound/tween_reference_spec.rb`); `swarm(..., shape:, cycles:)` takes per-copy values (`channels(:squiggle, :elastic)`, Ranges).  Shaped glides cost the same as plain ones.
- Tweens: `tween([300.hz, 3000.hz, 800.hz], 1.bar, curve: :elastic)` (`SequenceMethods#tween`, built on `Clip#tween`, a shaped Glide on a clip shifted to keyframes): values are keyframes (each value at its step start, tweening to the next during the step; the last holds or loops back over the last step; repeat a value to hold it); Pitches tween in octaves and give Hz (overshoots stay above 0 Hz), plain numbers linearly, `log:` overrides, mixing raises.  `smooth(t, curve:)` curves every step change (an elastic knob).
- Shaper: `sig.ease(curve, in:, out:, range:, edges: :clamp/:extend/:wrap/:mirror/:none, symmetric:)` (`GraphNode::CurveShaper`; "ease" since `curve`/`shape` are Envelope settings) is antialiased like softclip (ADAA on the excess over the in->out line plus the half-sample allpass; edge modes integrated too; closed forms for polynomial/cosine/exp curves, a Hermite antiderivative table otherwise; `FastClip.shape_curve`, mirror `CurveShaper.shape_ruby`); `aease` is exact for control signals.  Demo: `bin/songs/tween_song.rb`; renders in /app/tmp/listening/tweening/.

- Bounce rhythms: `bounce_hits(2.bars, count: 16, elasticity: 0.75, note: C2, reverse:)` (`SequenceMethods`) is a Clip of hits at length × (1 - e^i) with velocity e^i, converging on the bar line; demo `bin/songs/bouncing_ball.rb` (looping clips play in phase with the timeline, so it rotates balls to drop on their launch bar).
- Dynamic cookbook cutoffs (`filter(:lowpass, cutoff: node)`) clamp to `Cookbook::DYNAMIC_MIN_CUTOFF` (1 Hz, like FourPole; negative and NaN included).  Fast moves into very low cutoffs still make a direct-form biquad's output jump (a DC bump that decays once the cutoff rises; measured in the commit 8323e7d1 message), so tween cutoffs as Pitches.

### Filter System

`lib/mb/sound/filter/` contains 16+ filter types (Biquad, FIR, Butterworth, Hilbert, Delay, etc.). Filters implement `#process` / `#reset`. `Filter::Cookbook` provides standard designs (lowpass, highpass, bandpass, etc.).

`sig.lp4(cutoff, resonance: 0..1)` (aliases `four_pole`, `lowpass4`; also `filter(:lp4, cutoff:, resonance:)`) is a CEM3379-style 4-pole lowpass (`GraphNode::FourPole` over `Filter::FourPole`; zero-delay-feedback OTA cascade in the `fast_filter` extension, exact Ruby mirror `FourPole.process_ruby`, own tan/tanh/2^x approximations): cutoff (Hz, a Pitch, or a node such as `v.cutoff(...)`) and resonance read per sample; -12 dB at the cutoff, 24 dB/octave; like the SQ-80 it never self-oscillates by default (resonance 1 = k 3.9, +37 dB peak) and keeps its bass (-6 dB at full resonance, `compensation: 0.375`; 0 gives -14 dB); `self_oscillate: true` (k 4.3, oscillates above ~0.74, starts from silence), `mode:` :lp2/:bp2/:bp4/:hp2/:hp4 taps.  `resonance_curve: :db` (default since 2026-10-07; `:linear` is the round-1 k = r × k_max) makes the gain at the cutoff linear in dB (-12 to +33.8 dB, closed form `FourPole.resonance_curve`; peak +14.5 dB at 0.5 vs +7.5 linear; user-approved 2026-10-07).  Retune values written for the linear curve with `FourPole.db_resonance(linear)` (same loop gain; 0.3 -> 0.21, 0.5 -> 0.33, 0.7 -> 0.47, 0.75 -> 0.51, 0.9 -> 0.68, 0.95 -> 0.79; inverse `linear_resonance`).  Resonant sweeps of a low saw step through single harmonics while the cutoff is low (the narrow peak, not a glitch; detuned pairs make it irregular).  `drive:` (level; saturates above ~1/drive) with `drive_mode:` `:input` (default, tanh on the cascade input), `:stages` (every OTA stage's current plus the input, Zavalishin's one-step secant method), or `:feedback` (`clip: :soft`/`:hard`; only the resonance feedback y4 - c x clips, the MS-20's diode-clipper idea on our 4-pole, passband clean); the last two default to drive 1.  `quality:` instead of `resonance:` (a number or node, e.g. `v.quality(4)`) maps a 2-pole Q to the same gain at the cutoff; in voices `v.reso(0.6)` (alias `resonance_amount`) follows CC 71 (base at 64, 0 at 0, 1 at 127; `v.resonance` is the raw CC 71 Q multiplier).  ns/sample: linear 20, :input 28, :feedback 34-37, :stages 61 (+22 with a per-sample resonance node on the dB curve); ~0.16% of realtime per mono filter at 128-sample buffers.  Renders and measurements: `/app/tmp/listening/four_pole/` (README rounds 1 and 2).

### Delays

`Filter::Delay` (`#delay`) and `GraphNode::MultitapDelay` (`#multitap`) are front ends for one `MB::Sound::DelayLine` (`lib/mb/sound/delay_line.rb`): a circular buffer that grows without losing stored audio, read in C (`MB::Sound::FastDelay.read` / `.feedback`) with Ruby mirrors (`#read_ruby` / `#feedback_ruby`) that specs check for exactly equal values.  Interpolation (`interpolation:`) defaults to `:sinc` (`DelayLine::DEFAULT_INTERPOLATION`; Kaiser-windowed, cutoff lowered by the read speed when a moving delay raises the pitch, so no aliasing up to 4x); `:cubic` and `:linear` (the old lo-fi sound) are options.  Constant whole-sample delays read directly in every mode; a moving or fractional `:sinc` delay costs ~1.5-2% of realtime per mono delay.  No mode reads samples newer than the current input.  Delay times are any length (`0.01`, `250.ms`, `96.samples`, `3.n16`, nodes, `node.samples`) held as `Length::Source`, so they keep their unit when the sample rate changes and rate changes rebuild nothing; fractional constant delays are kept (snapped within 1e-9 of whole samples).  `feedback:`, `wet:`, and `dry:` may be numbers or graph nodes; `#delay` smooths delay changes by default (`smoothing:`), `#multitap` only with `smoothing:`.  Tools: `bin/delay_gallery.rb` (null-test cases), `bin/delay_benchmark.rb` (`--interpolation`), `bin/delay_quality.rb` (error and aliasing against an exact sine answer).

### Reverbs

Two reverb implementations coexist; use `#reverb` in most cases:

- `GraphNode::Reverb` / `#reverb` (`lib/mb/sound/graph_node/reverb.rb`) - the original from the reverb video; presets (`:room`, `:hall`, `:space`, ...).  `[l, r].reverb(:hall)` takes one input per Array element.  Its diffusion and feedback network runs as one fused stage (`Reverb::FusedStage`; `show_internals: true` builds the old node graph, which specs check gives identical samples) with C matrix mixing (`MB::FastSound.matrix_mix`, also used by `ChannelMixer` for real numeric gains).  Stereo cost (2026-10-03): `:hall` ~4% of realtime, `:space` ~6.5%.  Its feedback loops are the line delays plus `Reverb::FEEDBACK_BLOCK` (1024 samples at 48 kHz, the block size the presets were tuned at), read from the lines' inputs with `DelayLine#past`, so it sounds the same at every buffer size (it used to feed back the previous buffer, so loops grew with the buffer size; fixed 2026-10-06, a preliminary fix until per-sample feedback in a kernel); buffers longer than the shortest loop run in pieces.
- `GraphNode::FdnReverb` / `#fdn_reverb` - an experiment (clean-room, by Claude Code) with `room_size`/`decay`/`damping`; still feeds back the previous buffer, so its sound depends on the buffer size (left as is: it will likely be replaced by a factory signature on `#reverb`); ~7% of realtime in stereo (2026-10-03); may be removed once `#reverb` gets similar parameters.

### Sequences

`lib/mb/sound/sequence/` (`MB::Sound::Sequence`) holds musical sequences: immutable `Clip`s of `Event`s timed in exact Rational whole notes, built with `seq` (e.g. `seq(C4, E4, G4.n4).n8`), `grid` (drum step strings like `'x...x...'`), and note length methods on `Note` (`n1`-`n8`, `n12`-`n128`, `.d`, `.t`, long names).  A clip is just a MIDI source: `clip.stream` is a `MIDI::Stream` of a new `MIDI::ClipSource` (a `TimelineNode`; a new source per call, since each follows its own graph's timeline), and its node methods are the mono (last-note) `Notes` nodes of `clip.notes`: `clip.env`/`amp_env`/`fm_env`/`filt_env` (NoteEnvelopes: `:analog` curves, default 5 ms/0.2/0.7/0.3, Envelope keywords such as `curve:`/`sensitivity:` (velocity range; `velocity:` is the input), GM2 time scaling off unless `gm: true`), `clip.tone`/`hz` (a key-synced NotePitch: `clip.tone.ramp`, `.transpose(7)`), `clip.freq` (Hz node), `clip.period`, `clip.gate`, `clip.trigger`, `clip.number`, `clip.velocity(range:)`; each call makes its own Notes, so share one with `n = clip.notes`.  Edges land on exact samples at the tempo of a shared `Transport` (`bpm 120`); `spec/test_data/clip_node_reference.json` (outputs of the removed `ClipNode` renderers) is the edge reference.  `clip.synth(voices: 2, **synth_options) { |v, i| }` is `Synth.new(clip, voices:, tail: 0)` (`v` is a lane's Notes; returns Channels for multichannel voices).  Non-looping clips end one buffer after their last note-off; NoteEnvelopes end once their stream ended and they are idle; an ended reset input (key sync trigger) only stops resets, so tones ring through releases.  `legato(0.85)` shortens notes without changing the rhythm.  `reverse` (alias `retrograde`) mirrors a clip or reverses a Seq's steps; `permute([2, 0, 1])` / `permute(seed: 3)` (alias `shuffle`) moves notes among the same rhythm, repeatably from the clip's seed.  In a `Session`, looping clips play in phase with the transport timeline (`seek`, `rewind`), so graphs started at different times stay in sync.  See `bin/songs/sequence_demo.rb`.  Launches, replacements, swaps, and master chain switches land on the sample whose window holds their time (floor, like Notes edges), so a clip launched on a bar line between samples (e.g. 112 BPM) keeps its first note. See `bin/songs/sequence_demo.rb`.

`swap :bass, bass2` (`Session#swap`, `lib/mb/sound/session/clip_swaps.rb`) changes a player's clips on the next bar via `ClipSource#swap_clip` on every ClipSource in the graph (exact time; graph and effect state kept; sounding notes get note-offs, held values chase the new clip).  Transformed clips remember their `source` and transform (`Clip#lineage` / `#rederive`), so clips derived from the old one (`bass.transpose(12)`) are rebuilt from the new one, and a `clip.synth` follows through its one source; pass `old => new` pairs (or `kit => kit2` for `grid` rows) when a player has unrelated clips.  See `bin/songs/swap_song.rb`.

### Tempo sync

`Sequence::Duration` (`lib/mb/sound/sequence/duration.rb`) is an exact musical length in whole notes (comparable, `+`/`-`, scaled by numbers, friendly `to_s` like "3 × n16"), accepted wherever lengths are (`at:`, `fade:`, `every`, `after`, `render(bars:)`, `.len`, `until`).  `1.beat.hz` is a Pitch whose frequency comes from a `Sequence::TempoNode` following the tempo, and `4.bars.lfo` a Tone from it.  Tones made from the pitch lock their phase to the timeline on jumps (start, seeks, resume) plus `with_phase`, top-down through two TempoNode ports that are inputs of each tone (`Tone#follow_timeline`; `jumps` is 1 on the first sample after a jump, `jump_phase` the timeline position in cycles there, shared frozen zeros otherwise), split and band-limited like resets; they freeze while the timeline is paused unless `.freewheel` (per TempoNode; `Tone#timeline` is the TempoNode).  `sig.delay(1.n8.dotted)` (or `sig.filter(3.n16.delay(...))`, `multitap(1.n8.d, ...)`) follows the tempo; `2.bars.lfo.square.at(3.n16..5.n16)` gives an alternating delay time (`Tone#musical_time?`).  Tempo-following nodes include `Sequence::TimelineNode` (shared with `MIDI::ClipSource`, found through the Notes nodes' streams), which `Session` finds in every graph (`timeline_nodes`).  `Tone#lfo` means full range plus no MIDI retrigger.  `render(bars:)` counts bars on the timeline, so tempo changes during a render are followed; `tail: true` adds the master effects tail after the limit.  See `bin/songs/tempo_song.rb`.

### Multichannel

Every GraphNode has `outputs` (`[self]` for one channel) and `channel_count`; nodes with several outputs (stereo file inputs, multi-output reverbs, `MultiOutput`s) act as bundles.  `GraphNode::Channels` (`lib/mb/sound/graph_node/channels.rb`) is the bundle class: `stereo(l, r)`, `channels(a, b, c)`, `[l, r].channels`, `node.stereo`; it is Array-like (`[]`, `each`, `map`, `l, r = bundle`) but deliberately not Enumerable (`Enumerable#filter` is `select`).  `GraphNode::ChannelDispatch` (loaded last in `graph_node.rb`) generates a per-channel version of every `*Methods` module method, so DSL calls on a bundle run per channel and return a bundle.  Channel counts combine like NumPy broadcasting (1 is reused, N-N per channel, other mismatches raise); per-channel arguments are bundles, `channels(0.010, 0.013)` of plain values, or lazy `spread(a..b)`; filter objects are Marshal-copied per channel.  `reverb` is the deliberate exception: a bundle's channels all feed one reverb.

Conversions are `GraphNode::ChannelMixer` nodes (`lib/mb/sound/graph_node/channel_mixer/`): one N-in/M-out gain-matrix node per call, a subclass per mixing law declaring its channel counts, `param`s (numbers or nodes read every sample; numeric gains are computed once) and `option`s, with `#params`/`#gains`/class-level `.params` for introspection.  `pan(pos, law:)` (`ChannelMixer::Pan`; laws `:equal_power` default, `:minus_4_5db`, `:linear`; stereo bundles balance, the common DAW default, also `balance`), `width(w)`, `mono`/`mixdown`, `swap`, `mid_side`/`from_mid_side`, `matrix(rows)` (any N->M, entries numbers, complex, or nodes; replaced `MatrixMixer`), `place(x:, y:)` (alias `position`; phase-amplitude Lt/Rt positioning, replaced `ComplexPan`), plus `left`/`right`.  Complex gains send every input through the same Hilbert stage (`ChannelMixer::Analytic`) and output real parts unless an input was complex.  Mixer outputs advance to a new frame when an output is sampled again, so sample all outputs of a mixer in turn (as a Session does).  `master { |mix| ... }` gets the whole mix as a bundle.  `graphviz` collapses each per-channel call into one box listing per-channel arguments (`expand_channels: true` shows every node).  Deferred (local idea notes): surround layouts/matrix presets and encoder-aware `place` laws (with the user's private surround work), dual/stereo pan modes, `.widen`/`.haas`/ping-pong, `Mixer` accepting bundles, mixer fusion (graph optimizer), vectorized N-channel nodes.  See `bin/songs/stereo_song.rb`.

### Master effects

`Session#master` (`lib/mb/sound/session/master.rb`, console `master { |mix| mix.softclip }`) runs the whole mix through a chain built on `GraphNode::MixSource` channels (one param = the mix as a stereo bundle, N params = one per channel; `master nil` bypasses).  New chains start at `bg`-style launch points; by default the old chain "spills over" (fed silence from the switch sample so tails ring out, dropped after 1 s below -90 dB or 10 s), `fade:` crossfades, `fade: 0` cuts (also used when the render load is over 60%).  Chains keep processing while idle, `panic` rebuilds the chain to clear tails, and `render` adds the tail after the last player (10 s cap).  Nodes that change the sample count (`resample`, `oversample`) can't be used in a master chain yet.  See Reverbs for which reverbs are light enough for a live master chain.

### Audio I/O

Device I/O goes through miniaudio (the old JackFFI, Jack/Alsa outputs and inputs, and the mb-sound-jackffi gem are gone; ffmpeg stays for files and ffmpeg outputs).  `OUTPUT_TYPE`/`INPUT_TYPE` are `device` (default), `ffmpeg` (output only), or `null`; unknown types raise.  `MB::Sound::DeviceOutput` (`lib/mb/sound/device_output.rb`) writes into a lock-free ring that a C callback on miniaudio's device thread drains (`FastAudio::Playback`); Ruby never runs on the audio thread.  `#write` keeps at most `AUDIO_LATENCY` seconds queued: a write that doesn't fit queues what fits and waits without the GVL until the rest fits, so the sound card's clock paces the Session one buffer at a time, with evenly spaced writes (and live MIDI reads) and the queue within about a period of full (2026-10-04, JACK dummy, period 128: `:default` write spacing 10.67 ms, sd 0.3 ms).  `MB::Sound::DeviceInput` (`lib/mb/sound/device_input.rb`, `INPUT_DEVICE`) records through `FastAudio::Capture`: `#read` waits without the GVL, skips the oldest audio beyond the queue limit so live input stays near real time, and resamples from the card's rate; `test_pattern: true` records a frame counter on the null device for specs.

Latency profiles (`DeviceOutput::PROFILES`, `AUDIO_PROFILE` or `profile:`; chosen with `bin/audio_load_check.rb` on the user's old Mac; rerun it after big performance changes): `:default` write 512 / period 128 / queue 50 ms (45-56 ms, clean with fm_bass and stereo_drone together), `:low` 256 / 128 / two writes (16-19 ms, light patches only), `:video` 400 / 128 / 50 ms (120 fps frames; 8-10 points more load, so 512 stays the default per the user), `:safe` 800 / 480 / 85 ms (about 110 ms; 60 fps frames).  `AUDIO_BUFFER`, `AUDIO_PERIOD`, and `AUDIO_LATENCY` override a profile; offline renders take `render(buffer_size:)`.  The queue is adaptive: it grows by half after dropouts, up to the `:safe` queue, and shrinks by a third back to the profile's after `DeviceOutput::SHRINK_AFTER` (10) seconds without dropouts (notes on stderr; `AUDIO_ADAPTIVE=0` disables).  `latency :low` (alias `lag`) restarts the background session on a device output with that profile.  Effect/synth/song scripts take `-L/--latency-profile` and a `profile:` keyword (`-L` wins, then `AUDIO_PROFILE`, then the script's default) and call `MB::Sound.warm_up` before live playback (synths: `warm_up(midi: true)`).  Live MIDI switches to `:low` (user decision, 2026-10-04): opening it (console `midi`, synth scripts, effect MIDI controls) calls `live_midi_latency`, which restarts the idle background session on a `:low` device output unless `AUDIO_PROFILE` is set or the user gave `latency`/`use_output` an output (`Session.output_chosen?`); not for ffmpeg/null outputs; with players or master effects it prints a `latency :low` hint instead.  Exact MIDI timing's latency follows the adaptive queue (console live sources follow output switches through `LiveSource#output=`).

Environment: `AUDIO_BACKEND` (e.g. `jack,pulseaudio`; on Linux JACK first only if a JACK server answers (including PipeWire's), then PulseAudio/PipeWire, then ALSA; CoreAudio on macOS; `null` is miniaudio's timer-driven fake sound card, used by the specs), `OUTPUT_DEVICE`/`DEVICE` (index or part of a name), `AUDIO_SAMPLE_RATE` (the rate written, 48000 by default), `JACK_CLIENT_NAME` (default: the script's name; also the PulseAudio/PipeWire application name).  Mono outputs open two channels.  Sample rates (user's choice): graphs and Sessions stay at 48 kHz, and when the card runs at another rate (e.g. 44.1 kHz on the Mac after jackd changed it) the writer resamples the mix with libsamplerate (`AUDIO_RESAMPLE`/`resample:` fastest sinc by default, ~0.8% CPU for stereo; medium, best, linear, zoh, or off to run at the card's rate); `#sample_rate` is the written rate, `#device_rate` the card's; `AUDIO_DEVICE_RATE` forces a card rate (specs use it with the null device); `AUDIO_SET_DEVICE_RATE=1` lets CoreAudio switch the card's system-wide rate.  `Session#sample_rate` is the output's; `Session#add` sets graphs at another rate to it, or resamples nodes that can't change rate (file inputs, raw Biquads); filenames open at it.  Most filters have `sample_rate=` (FirstOrder, Butterworth, HilbertIIR, FIR from a gain Hash, Gain, FilterBank, envelope followers; `spec/lib/mb/sound/filter/sample_rate_setters_spec.rb`), and DSL methods use the node's rate.

JACK has its own small backend instead of miniaudio's and RtMidi's (user requirement, 2026-10-04: every port of a script on one JACK/PipeWire node, added at any time, for their qpwgraph arrangement feature): `ext/mb/sound/fast_audio/mb_jack.c` loads libjack at run time and keeps one client per process; units (a port set plus a realtime process function) attach and detach at any time through an atomically swapped list, detaching after every cycle that might hold the old list has finished.  `Playback.new`/`Capture.new` take optional JACK port names (14th/11th argument) and reuse their rings, resampler, and adaptive queue on JACK's thread; `FastAudio::JackMIDIInput`/`JackMIDIOutput` are byte rings of [JACK frame time, bytes] records.  Ruby side: `MB::Sound::Jack` (`lib/mb/sound/jack.rb`; port names `out_N`, `in_N`, `midi_in`/`midi_in_2`, numbered after those in use; the user's old JackFFI is a reference for structure, not a spec); `DeviceOutput`/`DeviceInput`/`MIDI::Input`/`MIDI::Output` use it whenever JACK leads the backends and fall back to the next backend if it can't open.  JACK servers are never started; new audio ports are connected once (to the physical ports, to ports whose names contain `OUTPUT_DEVICE`/`INPUT_DEVICE`, or nowhere with `none`), and later rewiring by qjackctl/qpwgraph/session managers is left alone.  `FastAudio.jack_connect`/`jack_disconnect` wait (up to 200 ms) until JACK's graph shows the change (otherwise connections are listed late and first messages lost).  Specs: `spec/ext/mb/sound/fast_audio_jack_spec.rb`, `spec/lib/mb/sound/jack_spec.rb` (one-node acceptance test, sample-exact loopbacks).

Tools and threads: `bin/audio_check.rb` lists devices and measures latency, underruns, clock drift, write spacing, and queue range (`--busy` adds GVL contention).  A busy Ruby thread can starve the writer for a whole time slice (100 ms by default, longer than the queue; 131 underruns in 10 s on the user's Mac), so bin/ scripts set `RUBY_THREAD_TIMESLICE=10` in their shebang (user's choice; 0 underruns measured; read only when Ruby starts, so `ruby bin/x.rb`, irb, and `fork_script` don't get it); a priority of -3 on the busy thread also works.  The Session render thread calls `FastAudio.boost_thread_priority` (user-interactive QoS on macOS via `pthread_set_qos_class_self_np`, no privileges; a no-op elsewhere).  `vis` shows each buffer when it reaches the speakers (now + `output.latency`).  `use_output(obj_or_type)` gives the background session another output (refuses while players run); `render` accepts an output object; `OUTPUT_TYPE=ffmpeg` is any live ffmpeg output (`OUTPUT_FORMAT`, default audiotoolbox on macOS and pulse elsewhere; `OUTPUT_CODEC`; `OUTPUT_DEVICE` as the name or URL; about 0.4 s latency), wrapped in `BackgroundOutput` (feeds paced silence so ffmpeg never runs dry; kept separate from FFMPEGOutput by choice).

### Scripts

Every bin/ script except `bin/sound.rb` is built on one of four helpers in `ScriptingMethods`, backed by `ScriptRunner` (`lib/mb/sound/script_runner.rb`, OptionParser):

- `effect_script(input_channels:, live_channels:, **params) { |input, p| graph }` - the input is an audio file (first audio argument or `-i`, rung out with a `Ringdown` node until 1 s of quiet, 10 s cap) or live input (`-c/--input-channels`); `--repeat [COUNT]` loops the file.  `-m/--midi SOURCE` takes `p.midi_cc` controls from a MIDI port (part of its name) or a `.mid` file (played with the graph, also in `-o` renders; `p.midi` is that Notes); only the input's `Ringdown` decides when a file effect ends (live MIDI control nodes never end).
- `synth_script(**params) { |midi, p| graph }` - `midi` is a `MB::Sound::Notes` on the MIDI file or live port given (`-i` or a non-audio argument; by default the script's own port), like the console's `midi`: a mono voice applying the sustain pedals (`midi.hz.saw * midi.amp_env`; `Notes.new(midi.stream, sustain: false)` ignores them) and a source for synths (`midi.synth(voices: 6) { |v| ... }`, `Synth.new(midi)`, `MB::Sound.synth(midi, ...)`).  A MIDI file rings out: once it has ended and every voice is idle (`Synth#ended?` or the Notes nodes' `#ended?`), the runner stops after a second of quiet (10 s tail limit), like effect file inputs (`Ringdown#ended?`); a Synth itself returns nil only `tail:` (`MIDIFile::TAIL_SECONDS`) later, for players without tail detection.  Converting old patches (all of `bin/synths/` and `bin/wavetable_pr_example.rb` use Notes/Synth): `midi.env(...).db(N)` became `fm_env`/`amp_env` with curve -N rising, (1 - s) × N for the decay and s × N for the release (N with sustain 0), the sustain and the old 0.5..1 velocity range mapped through the same curve (see fm_bass.rb, fm_bell.rb); plain `midi.env` amplitude envelopes keep -6..0 dB velocity; fixed-ratio operators are `v.hz.transpose(Math.log2(r).oct)` (key-synced), node ratios `(v.freq * node).tone.reset(v.key_trigger)` (fm_bell.rb), `reset(v.trigger)` for tones and per-voice LFOs that restart at every note-on (drums); `named('portamento')` filters became `v.hz.glide(t)`.  `bin/synths/fm_chain.rb` (the 2021 chained fm_synth: each held note FM-modulates the previous one) is a script-local GraphNode reading `midi.note_stream` per buffer and splitting buffers at event samples.
- `song_script(bars:, **params) { |p| ... }` - the block arranges the song on the current session (`bg`, `at_bar`, `master`); `-b/--bars N` plays or renders N bars (live too), `--bpm` sets the starting tempo and scales the song's tempo changes (`Transport#override_bpm`), `--graphviz` draws the session at the start (`Session#graph_view`).
- `script(args:, **params) { |args, p| ... }` - general scripts (utilities, plots, file processors, benchmarks, MIDI tools): only `-h/--help` is common, positional arguments go to the block (`args:` Integer/Range checks their count; negative numbers stay positional).

Effects, synths, and songs share `-o/--output` (or a positional audio file) to render instead of playing, `-f/--force`, `-g/--graphviz`, `-P/--plot`, `-q/--quiet`, and play through the background `Session`.  Parameters are options only (no positional numbers): `name: default` or `name: [default, 'description', '-x', Type, allowed_range_or_array, :required]` in any order after the default; bad values print the option help.  `p.midi_cc(1, :hz, range: 0.0..6.0)` gives a Notes controller node (range relative to the value; its `MIDI::ControlSpec` has the parameter's name and description, listed by `p.midi.controls` and the script's control listing) when MIDI is open (live unless rendering, or `-m FILE`), else a constant; a value inside the range is the knob's center (raw 64, each half linear), else the nearest end, so it starts at the value.  Graph-building code belongs inside the block (`--graphviz` runs song blocks twice).  Guard scripts that can also be `load`ed with `if main_script?(__FILE__)`.  Every script starts with `#!/usr/bin/env -S RUBY_THREAD_TIMESLICE=10 RUBY_YJIT_ENABLE=1 ruby` (checked by `spec/bin/shebang_spec.rb`; see Audio I/O for the time slice).  YJIT roughly halves graph cost (fm_bass at 128-sample buffers under the profiler: ~190% of realtime without, ~85% with; +8 MB RSS) but compiles methods only after many calls, so live paths (`ScriptRunner` live play, `bin/sound.rb` startup) call `MB::Sound.warm_up` (`lib/mb/sound/warm_up_methods.rb`; nil without YJIT) before the first output write: a throwaway graph of common nodes (~0.2 s; first-buffer stall ~55 ms to ~14 ms), plus MIDI voices in synth scripts (`warm_up(midi: true)`; ~0.35 s; ~50 ms to ~14 ms).  `ruby bin/x.rb` and specs run without YJIT.

### MIDI

`lib/mb/sound/midi/` is a pull-based event layer, loaded from `midi/streams.rb` after Sequence: Sources make Events, Streams share them among readers, Notes turns them into signal nodes, and Synth allocates voices.  Nothing is pushed through callbacks, and nothing reads a clock except live input.

- `MIDI::Event` (`midi/event.rb`): the only MIDI message type (`Note#to_midi`/`Pitch#to_midi`/`Tone#to_midi` return note-on Events whose `bytes` `MIDI::Output#<<` sends), a Data value (normalized velocity/CC/pressure 0..1, bend -1..1, raw kept, 0-based channel, time in Rational seconds since the stream start; allocator types `:choke`/`:glide` and `legato`).
- Sources (`midi/source.rb`: `read(from, to)`, `seek`, `restart`, `ended?`, `music_end`, `chase`; note-ons/offs kept balanced across jumps): `FileSource` (one tempo via a tempo-map object, `loop:`; `#notes`/`#note_stats` list notes with key and pedal release times as played, via `MIDI::NoteList` in `midi/note_list.rb`, used by `bin/midi/midi_roll.rb`), `ClipSource` (see Sequences), `LiveSource` (below).  `MIDIFile` (`midi/midi_file.rb`) only parses and analyzes files (`events`, `tracks`; no clock).
- `MIDI::Stream` (`midi/stream.rb`) reads a source once for many `reader`s (cursors in seconds, so any sample rate; late readers start at the slowest), stamps bend ranges from RPN 0, and makes transform views (`midi/transform.rb`: `channel` 0-based, `transpose`, `sustain` (the only sustain handling), `velocity_curve`, `bend_range`).  Streams include `Nameable`/`Traversable` but aren't GraphNodes.  `Stream.for` takes a Stream, Source, Input, Clip, MIDIFile, filename, or anything with `#to_midi_stream` (a Notes).
- `MIDI::LiveSource` (`midi/live_source.rb`; `Stream.live(connect:, output:, timing:)`) reads `MIDI::Input#read_raw` (JACK frame times or RtMidi deltas).  `MIDI_TIMING=exact` (default) keeps timestamp spacing at a constant latency L (default: the output's queue limit + period + one buffer, ~63 ms with `:default`, ~18 ms with `:low`; `latency:` overrides); JACK input with a JACK `output:` is sample-exact through `DeviceOutput#jack_clock`, else the input clock is anchored at the first events and re-anchored when off by more than L (`#track_drift` is the hook for a DLL); `asap` puts events at the start of the read.  `MIDI::RealtimeReader` (`midi/realtime_reader.rb`) plays a file or live input against the wall clock for the bin/midi tools (no audio).
- `MB::Sound::Notes` (`lib/mb/sound/notes.rb`, `notes/`): the per-voice (or mono) signal DSL over a stream (`v` in synth code; `Notes.new(stream | source | clip | file, sustain: true)`).  Note nodes read `note_stream`, the input through the sustain pedal transform (lazy and held weakly, so a Notes used only for controllers or as a synth source never holds the input back), unless `sustain: false` (Synth lanes, already pedaled, and `Clip#notes`); `stream` stays the input (controllers, `to_midi_stream`, `.source`); `control_specs` adds the pedals while note nodes use them.  Every node has its own reader and puts events on exact samples at its own rate: `gate`, `trigger` (impulse = velocity), `number`, `velocity`, `lift`, `choke` (`:choke` events, CC 120), `freq` (Tuning + bend); last-note priority; held values chase `Source#chase` after jumps.  Channel-wide nodes (`bend`, `bend_semitones(range)`, `pressure`, `cc(n, range:)`, GM-named `mod`, `brightness`, `resonance`, `attack_time`, `vibrato_rate`, ... with `MIDI::ControlSpec`s, listed by `notes.controls`) are shared per control stream (`Notes.control_stream`).  `env`/`amp_env`/`fm_env`/`filt_env` are `NoteEnvelope`s wired to gate/trigger/velocity/choke (`lift: true` opt-in), GM2 time scaling (CC 73/75/72) unless `.gm(false)`, registered for `notes.idle?`/`notes.level`.  `v.hz` is a `NotePitch` whose tones key-sync (`Notes::KeyedTone`, `reset(v.key_trigger)`) unless `.free`/`.lfo`/`.sync`; `.bend_range(12.st)`, `.transpose`, `.vibrato`, `.glide(50.ms | :gm, legato:)`.  `v.key_trigger` (`Notes::KeyTrigger`, alias `key_sync_trigger`) is `v.trigger` without note-ons that add energy to a sounding voice (user rule, 2026-10-05: adding energy to an existing envelope doesn't reset oscillators), i.e. note-ons while a `retrigger: :add` envelope of the Notes is sounding, decided per buffer from the envelopes' state at the buffer start (`Notes#adding_at?`, `NoteEnvelope#sounding_at?`, so graph order doesn't matter); `v.trigger` fires at every note-on.  `v.cutoff(base, env:, keytrack: 0.5)` and `v.quality(q)` feed `filter(...)`; `v.reso(amount)` (CC 71 around the base) feeds `lp4(resonance:)`.  Gate/trigger/choke and envelopes return nil once the stream ended and the envelopes are idle; nodes report `ended?` for script ringdowns.  Nodes are cached per instance through WeakRefs.  Fast paths (`Notes.fast_paths`, `MB_SOUND_NOTES_FAST=0` off; null-tested in `spec/lib/mb/sound/notes_fast_paths_spec.rb`): constant frozen buffers while nothing changes (consumers cache by identity), one `Notes::EnvelopeInputs` reader per envelope, idle envelope kernel skips, shared Stream events and Frequency nodes.
- `MIDI::Allocator` (`midi/allocator.rb`) splits a stream's notes into `lanes` (`Lane < Stream`, `voices + spares`; one in mono mode), each with at most one note plus every channel-wide event, reading its input once so lanes read in any order with identical results.  When full, the `steal:` chain (`:same_note`, `:oldest_released`, `:oldest`, optional `:quietest`; `protect: :lowest/:highest`) chokes a victim while the new note goes to a spare.  `lane.idle_check` frees released lanes.  `retrigger:` (when every voice is busy and the chain has `:same_note`): `:reuse` (default: restart the newest lane playing the note), `:louder` (reuse it only if no envelope would attack downward, via `Lane#louder_check`/`level_check`; else as `:new_voice`), `:new_voice` (a spare takes it, so the old note rings on), `:quietest` (the quietest lane playing the note), `:per_key` (one lane per key, always restarted, even with voices free).  Mono (`voices: 1`, `priority: :last/:low/:high`) sends legato note-ons; polyphonic `glide_mode: :last` (default) sends `:glide` events, `:voice` none.  Unison isn't built.
- `MB::Sound::Synth` (`lib/mb/sound/synth.rb`; `MB::Sound.synth(source = nil, voices: 8, **opts) { |v, i| }`, nil meaning live `midi`; `notes.synth`, `clip.synth`): `Synth.new(source, voices: 8, spares: 2, steal:, protect:, mono:, priority:, glide_mode:, retrigger:, controls: [], bend_range: nil, sustain: true, seed: nil, tail: 11, skip_idle: true) { |v, i| graph }` reads the source through `.sustain`, splits it with an Allocator, calls the block per lane with a Notes on it, and sums the lanes (`sample_individual(count)`; bundles give one `Synth::Output` per channel).  Lane blocks run in `MB::Sound.with_seed(seed + i)`.  `controls: [:volume, :expression, :pan]` (CC 7/11/10) are opt-in.  `retrigger:` takes the Allocator modes plus `:add` (reuse, every lane envelope `retrigger: :add`) and the presets (`Synth::RETRIGGER_PRESETS`): `:string` (`:per_key` lanes + `:add` envelopes, never doubling a key; user-approved for pianos/e-pianos; key-synced oscillators keep their phase on these re-strikes, `.free` ones never reset; see `bin/synths/fm_epiano.rb`) and `:ring` (alias `:bell`; user's choice for bells, fm_bell's default with `-r` to compare): a free voice if any, else the quietest lane ringing the note with `:add` envelopes, else steal the quietest (`RING_STEAL` unless `steal:` given).  Renders: /app/tmp/listening/retrigger/.  `ended?` = finite source over and every lane idle: Notes idle and the lane's output, measured after each buffer, under -90 dB (`Synth::QUIET`, `Notes#quiet_check`, `Synth#quiet_lanes`), so envelope-less voices (filter pings) and resonant tails ring out and aren't reused while ringing (the peak is also `Notes#level` for `steal: :quietest`); the runner's ringdown keeps a Synth and ignores the nodes inside it; then `tail:` seconds of silence and nil.  `skip_idle: true` skips idle lanes (Notes idle, output under -120 dB, no delays/reverbs/FIR/tempo nodes; not sample-exact).  Cost (2026-10-04, YJIT, 8 voices, saw × amp_env → lowpass): ~6% of realtime at 128-sample buffers, ~2.3% at 512.
- Console: `midi(connect = nil, sustain: true)` is a `Notes` (pedals applied; `sustain: false` gives another Notes on the same input) on a cached `Stream.live` following the background session's output (`midi_stream` gives the Stream, `close_midi` closes them; opening it may switch to the `:low` profile, see Audio I/O); `midi_file(path, loop: false, sustain: true) { |midi| }` is a Notes on a FileSource.

Live MIDI goes through JACK MIDI ports on the shared JACK client when a JACK server answers (see Audio I/O; `connections` are the port's live JACK connections), else the bundled RtMidi 6.0.0 (`ext/mb/sound/fast_midi/`, `MB::Sound::FastMIDI`; CoreMIDI on macOS, ALSA sequencer on Linux): `MB::Sound::MIDI::Input` (`lib/mb/sound/midi/input.rb`) polls the queue in `#read_raw` (once per buffer, from LiveSource).  By default it opens a port named after the script (`DeviceOutput.client_name`); `connect:`/`MIDI_DEVICE` connect to a source by part of its name, searching the other compiled API too when `MIDI_API` isn't set (`Input.find_port`; no match warns with the source list and leaves the port unconnected); `Input.open_live` prints where to connect (bin/midi tools).  `MIDI_API` picks `core`/`alsa`/`jack` (JACK by default when a JACK server answers, jackd or PipeWire's: `DeviceOutput.jack_running?` is `FastAudio.jack_server?`, which dlopens libjack and opens and closes a client without starting a server, ~5 ms).  `MB::Sound::MIDI::Output` (`lib/mb/sound/midi/output.rb`) is a minimal output (`write`/`<<` of bytes, `connect:`), used by `bin/midi/midi_events.rb --forward` and the specs; scheduled MIDI output isn't built.  RtMidi's C API leaves `msg` dangling after errors, so `fast_midi.c` never reads it.  `bin/midi_check.rb` shows the MIDI APIs, why one is chosen, the loaded libjack, audio backends, all ports, and `--listen`/`--loopback` tests (`spec/bin/midi_check_spec.rb`).  RtMidi is vendored unmodified (built with `HAVE_SEMAPHORE` on Linux, as RtMidi's own build does; without it closing a JACK output raced its process callback and crashed libjack under load); `ext/mb/sound/fast_midi/README.md` has the update steps.

Specs send real messages through a private JACK dummy server (`spec/support/jack_dummy.rb`; they skip without `jackd`) with `MIDI::Output`/`FastMIDI::Output`.  Every JACK2 server maps ~38-40 MB of `/dev/shm`, so Docker's 64 MB holds one: spec processes take turns through a lock file (`/dev/shm/mbspec-jackd-UID.lock`); `JackDummy.start` also cleans up after crashed or dead spec servers (registry slots, metadata DB, orphans), and servers run under `setpriv --pdeathsig TERM`.  A spec process from an older checkout (no lock) running at the same time can still crash both servers (SIGBUS; `JackDummy.stop` warns).

`MIDI::ControlMap` (`midi/control_map.rb`) lists the controllers something responds to and writes controller maps for the ACID DAW (user: ACID remote control of synths matters).  It collects `ControlSpec`s from specs, Arrays, other maps, anything with `#control_specs` (`Notes`: the controller nodes in use on its control stream; `Synth`: its lanes' shared controllers, output controls, and the sustain pedals' CC 64/66/67 (`Transform::Sustain::CONTROL_SPECS`) unless `sustain: false`; `Notes::Control` nodes), and graph nodes/bundles (every upstream node with `#control_specs`); equal specs once, specs sharing a CC number grouped.  `ControlSpec#type` is `:cc`, `:bend` (`ControlSpec.bend(range:)`, raw 0..16383 centered at 8192), or `:pressure` (`ControlSpec.pressure`); `Notes#bend`/`bend_semitones` (so every `v.hz`/`v.freq`) and `#pressure` carry them, sorted after the CCs (`ControlSpec#key`; `map[:bend]`, `map.types`).  Enumerable over specs, `numbers`, `[]`, `groups`, `to_s` (also `pretty_print`, for Pry), `to_acid_xml(name: script)`, `write_acid_xml(path)`.  Console: `midi.controls`, `synth.controls` (`Synth#output_controls` is the `controls:` list).  The XML matches the old Manager's byte for byte (`spec/test_data/acid_xml_reference.xml`, `spec/test_data/acid_xml_bend_reference.xml`), except that entries are sorted by CC number and `params=` counts entries.  Effect and synth scripts list their controls (`p.midi_cc` specs, even when constants, the script's MIDI controllers, and the graph's) after the parameters when MIDI is in use, hidden by `-q`, and take `--acid-xml FILE` (`-` prints it; written even with `-q`).

## Working Notes (lessons learned)

### Verifying audio without speakers

The container has no audio device, so check sound-producing code by rendering it: `MB::Sound.render('file.flac', graph, bars: 4)` or loops of `node.sample(800)`, then look at peak levels, silent stretches, and exact sample offsets of note edges.  Use `NullOutput.new(..., sleep: false)` and `Session.new(realtime: false)` with `#process_buffer` for fast, deterministic tests.  To check that events happened (e.g. a swap landed on its bar), trace internal state from a scheduled block; spectral checks of the mix are easily fooled by other parts.  Leave listening to the user (on a Mac) with copy-pasteable snippets and expected results, and keep good snippets in demo script header comments.

### Gotchas

- `#sample` usually returns a reused buffer; `.dup` each buffer before collecting several of them (several false "bugs" came from forgetting this).  It may also be frozen (a Tee's shared buffer): copy before modifying a buffer you didn't create.
- A Tee branch that is never read keeps its Tee copying until the branch falls a whole CircularBuffer (1 s) behind, and raises `BranchBufferOverflow` if read later; benchmarks that reuse one node in two graphs sampled separately hit this.
- Oscillators (`Tone`, `noise`) are full scale (-1..1) by default, and the master bus (`Session#master_gain`, `master_gain -6.db`, `render(gain:)`) is -10 dB by default, live and in renders, so mixes of full-scale parts have headroom; effect scripts set it to 0 dB, since they process recordings with their own levels.  Check levels by rendering.
- Oscillators and constants play forever (there is no `.for`/`.forever`); sounds end through envelopes (one-shots without gate or trigger; gated or triggered ones, as in voices and clips, never end by themselves), clips, files, `x.until(seconds)` or `x.until(2.bars)` (`GraphNode::TimeLimit`, a hard cut; musical lengths follow the tempo, counted from the node's first sample), `and_then`, or `MB::Sound.silence(s)` (zeros, then the end; e.g. tails via `and_then(silence(s))`).  `play` of a graph says to press Ctrl-C, `write` caps graphs at `MAX_RENDER_SECONDS`, and `fft`/`plot`/`write` given a bare Tone or Pitch take one second of it.
- `40.hz` is a Pitch that plays as a sine when used as a signal, not a constant; use `40.constant` for fixed values in arithmetic, and `pitch.transpose(n)` or `(f * 2).hz` to change frequencies (`440.hz * 2` doubles the sine's amplitude).
- `Numeric#samples` is a `Length::Samples` (it used to return seconds at 48 kHz), and `#delay`/`#multitap` have no `samples:`/`sample_rate:` options: write `delay(96.samples)` or `delay(lfo.samples)` (counted at the running rate).  A plain node or number is seconds; `smooth(0.1)` and `smooth(4800.samples)` replace `smooth(seconds:/samples:)`.
- Use the `a*` names (`aramp`, `aclip`, ...) or `.lfo` for control signals that must keep exact edges (delay times, gates, phases), and remember that `softclip`/`clip`/`abs`/`quantize` add half a sample of delay (null tests against older renders show a -20 to -30 dB residual; align by half a sample to compare).  An edge landing exactly on a sample is a classic rounding trap in these kernels (phases snap within 1e-9 of an edge).
- The container compiles with GCC, which never warns about unused `static inline` functions; the user's Mac uses clang, which does for functions defined in a `.c` file (not in headers), and `-Werror` makes that a build failure.  After C changes, check that every static function in a `.c` file is still called.
- `Numo::Pocketfft.rfft` (and `ifft` of a complex view) read an NArray view like `x[100..]` from its parent's start; `MB::Sound.fft`/`ifft`/`real_fft`/`real_ifft` copy their input, but `.dup` views before calling Pocketfft directly.
- `node.filter(cookbook_filter)` re-applies the filter's original cutoff and quality every buffer, so changing `center_frequency` from outside (e.g. a MIDI callback) does nothing; pass `cutoff:` a node and change the node.
- `multitap` and other multi-output results are `Channels` bundles, which are deliberately not Enumerable (`.to_a` for `shuffle`, `reverse`, etc.).
- C4 = 60 (C3 = 48).  Derive expected values in specs from note constants or a quick script; hand-computed notes and offsets caused several wrong assertions.
- A realtime Session's render thread runs until `close`; close sessions in spec `after` blocks.  `kill -QUIT <pid>` prints every thread's backtrace (`MB::U.sigquit_backtrace`, set up in spec_helper).
- Before adding `bin/sound.rb` commands, check for collisions with `MB::Sound` methods and Pry commands (`Pry::Commands`; e.g. `reset` and `watch` are taken).

### Process

- In multi-step shell scripts, use `set -euo pipefail`, don't pipe away exit codes, and put commands on separate lines (a failure inside `a && b` doesn't stop the script; a batch loop that kept going after a failure once produced broken commits).
- Use the Edit tool for multi-line code changes; ad hoc Python/sed replacements often failed on indentation or escaping.  Never `sed -i` the Rakefile: on the Mac's case-insensitive `/app` mount it once left a stale lowercase `rakefile` entry that rake loads first (`LoadError ... rakefile`; `rake -f Rakefile` works around it).
- After merging (or rebasing onto) changes that touch `ext/`, run `bundle exec rake -f Rakefile clean compile` and check that it succeeds before trusting specs: a stale `.so` from before the merge loads fine and lets the suite pass while the merged C doesn't build (2026-10-06: gc-fixes changed `mb_read_signal_input`'s signature, and the four-pole and wavetable kernels from parallel branches still used the old one; git merged them cleanly).  When changing a helper in `mb_ext_helpers.h`, search the other active branches for callers.
- Kill only processes you started, by PID (never `pkill -f`): parallel sessions and agents run their own Valgrind, JACK, and spec processes.  Write commit messages to a file for `git commit -F` (a shell slip once left a title-only commit).
- Benchmarks are noisy when another session is compiling or running specs: alternate runs of the old and new code (e.g. a temporary master-ai worktree) instead of comparing against remembered numbers.
- Keep command output small (grep/head/tail, Read with offsets); large tool output fills the context quickly.
- Measure before explaining a failure; the first theory for the macOS latency problem was wrong, and a small experiment found the real cause.
- The user often says "note for later": record those in local memory (themed idea files), not GitHub, and implement them only after an explicit go-ahead.
- Preserve research side quests (prototypes, measurements, studies by research agents) before their worktree is removed; a gitignored `tmp/` is lost with it.  One study per branch `research-<topic>` off master-ai, never merged (`git branch --list 'research-*'` finds them), with everything in `research/<topic>/`: a `README.md` (the question in the user's words, date, method, result, what was decided, where any proposal lives), the prototypes and measurement scripts, and small results (tables, plots under about 1 MB each).  Leave out large regenerable data and renders, with a line saying how to regenerate them.  Commit once with a detailed message (the usual attribution lines), and point to the branch and commit from the proposal or notes that discuss the study.  Example: `research-scurve`.
