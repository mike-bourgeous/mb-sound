# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

mb-sound is a Ruby library for sound processing with a fluent DSL for building signal processing chains. It is a companion to an educational YouTube video series about sound. It uses Numo::NArray (via the `numo-narray-alt` fork) for numeric operations and includes C extensions for performance-critical paths.

### Folders

- `bin/` - user-facing scripts and experiments (`bin/effects/`, `bin/synths/`, `bin/midi/`, `bin/songs/`, plus general utilities at the top level); all but `bin/sound.rb` use the script helpers (see Scripts below)
- `ext/` - C extensions for performance-critical functions
- `lib/` - Ruby code (most functionality lives here)
- `spec/` - Test suite

## Build & Development Commands

```bash
bundle install                    # Install dependencies
bundle exec rake compile          # Compile C extensions (required before running)
bundle exec rspec                 # Run full test suite
bundle exec rspec spec/some_spec.rb        # Run a single test file
bundle exec rspec spec/some_spec.rb:42     # Run a specific test line
bundle exec rake                  # Default task (runs spec)
bin/sound.rb                      # Launch interactive Pry console with MB::Sound context
bundle exec rake memcheck         # C extension specs under Valgrind (full: ~30-45 min, up to 1.3 GB; options in Rakefile)
bundle exec rake memcheck:changed # only the memcheck specs for extensions changed since master-ai (MEMCHECK_DRY=1, FULL=auto)
bundle exec rake memcheck:status  # last full memcheck and whether one is due
bundle exec rake depend:check     # ext depend files against the headers the sources include
```

Testing: run affected specs while working, and the full suite (about 2 minutes) before and after each merge, or more often for good reason.  Save suite output to a file and grep it instead of rerunning.  Concurrent spec processes work (per-process temp dirs and coverage files); parallelizing the suite is deliberately postponed, since slow or leaky specs are better fixed than hidden.

Spec conventions (`spec/support/`):
- Temp files: `tmp_path('name.flac')` gives a path in an empty directory per example, inside a random per-process `Dir.mktmpdir` removed at exit (`KEEP_SPEC_TMP=1` keeps it); never write fixed names under `tmp/`.
- Coverage is opt-in: `SIMPLECOV=1 bundle exec rspec` (CI sets it) reports to `coverage/` (+~20% suite time, +~30% smoke); bin/ scripts run by specs get `spec/subprocess_coverage_helper.rb` (via RUBYOPT), merged into the report after the suite.  If script specs are slow, check `coverage/.resultset.json` isn't huge; `rm -rf coverage` is safe.
- `fork_script(script, *args)` runs a bin/ script in a fork of the spec process (skips ~0.7 s of startup); a spec using it must also run its script once as a real process doing real work, so load-order problems still show.
- Before each example spec_helper calls `MB::Sound.close_outputs`, so cached outputs (and NullOutput pacing) don't leak between examples.  Specs that run a Session on the shared transport must `MB::Sound.rewind` afterwards.
- For limits like `Session::MAX_TAIL_SECONDS`, `stub_const` the constant where it's defined (`Session::Master::MAX_TAIL_SECONDS`) instead of rendering 10 s of tail.
- Load-sensitive specs: a few realtime timing examples can fail under heavy load (concurrent renders, other suites) or Valgrind and pass on a rerun: `spec/lib/mb/sound/device_output_spec.rb:244`, and `live_source_spec.rb`'s JACK "frame plus the latency" example under `rake memcheck` (first note one 256-sample period early).  Rerun once before investigating; under memcheck, Valgrind errors (not timing failures) are what count.
- Short inputs: `spec/test_data/arp_a7.flac` is a 0.4 s stereo Am7/Amaj7 triangle arp (made by `spec/test_data/make_arp_a7.rb`) for effect and script specs; test MIDI files start within 0.2 s.

The bin/ script smoke tests (`spec/bin/script_smoke_spec.rb`, tagged `:smoke`, about 1.5 minutes; plain `rspec` skips them, CI runs them as a separate job) run every script with `--help` (in forks for scripts that also render) and a short render (real processes), with shared-buffer checks raising (see Core Abstraction).  Run them with `bundle exec rspec --tag smoke` before merging changes to bin/ scripts, the script runner, or nodes that touch input buffers, and add new scripts to their tables.

System dependencies (apt): `ffmpeg gnuplot-qt libsamplerate0-dev libasound2-dev libjack-jackd2-dev jackd2 graphviz` (ALSA headers build RtMidi's ALSA sequencer backend; the shared JACK client loads libjack at run time, so `libjack-jackd2-dev` only builds RtMidi's JACK API, which specs use as an outside JACK client; `jackd2` runs a dummy JACK server for the JACK specs, which skip without it).  In the container, the Dockerfile sets `OUTPUT_TYPE=null` so playback uses `NullOutput`.

## Architecture

### Core Abstraction: GraphNode DSL

The central pattern is `GraphNode` (`lib/mb/sound/graph_node.rb`), a module mixed into any class that implements `#sample`. It enables fluent chaining to build signal processing graphs:

```ruby
play 123.hz.triangle.at(-20.db)   # oscillators play until Ctrl-C
play 123.hz.fm(369.hz.at(1000)).softclip.filter(150.hz.highpass(quality: 4))
```

The DSL methods (`#filter`, `#delay`, `#softclip`, arithmetic operators, etc.) live in topic modules included by `GraphNode`, in `lib/mb/sound/graph_node/*_methods.rb`; `graph_node.rb` keeps naming, graph traversal, and shared private helpers.  Graph nodes support traversal via the `Traversable` mixin; key node types live in `lib/mb/sound/graph_node/`, MIDI nodes in `lib/mb/sound/notes/`.

Every consumer of GraphNodes must call `get_sampler` on the node(s) it stores in its constructor (e.g. `Tone#fixup_source`, `ProcNode`, `Filter::Delay` for delay-time nodes).  That branches a node used in several places through a `Tee`, so each use gets the same samples instead of advancing it twice (the user is open to an alternate design later).

When a Tee's branches read in lockstep (each reads every buffer once with the same count, as in a Session), they all get one frozen view of the source's buffer; otherwise the Tee copies through a CircularBuffer until they catch up (`lib/mb/sound/graph_node/tee.rb`); the CircularBuffer and the branches' one-second readers are made only when a Tee first leaves lockstep (`Tee#buffers!`, `Tee::IdleReader` before; 2026-10-10: no script ever left it, and sq80_voice's 719 Tees held 324 MB: graph_profile peak RSS 406 → 96 MB, fm_bass 226 → 75).  So a node that processes its input in place copies it first only if `buf.frozen?` (user rule, so unshared chains keep passing one buffer through; e.g. Reverb's dry path, `SampleWrapper(in_place: true)`, Delay smoothing; `GraphNode::FrozenCopy` reuses one copy buffer).  Constants, TempoNodes, and Notes nodes return one frozen buffer while their value holds.  Numo blocks most writes to frozen views but not in-place arithmetic (`buf.inplace * 2`), so `Tee.shared_check` (env `MB_SOUND_CHECK_SHARED=1`) verifies shared buffers: raising in scripts and specs (the `:check_shared` tag; on in the smoke suite), warning and copying in `bin/sound.rb` (off by default there).  `MB_SOUND_SHARED_TEE=0` turns sharing off.  Multiplier and Mixer have allocation-free fast paths for full buffers that don't promote their type (`ArithmeticNodeHelper#arithmetic_fast?`, C kernels in `fast_arithmetic`), bit-identical to the general path; so does `ChannelMixer::Pan` with a node position (`FastArithmetic.pan`, Numo's float steps, cos and sin in separate loops so no compiler merges them into sincos).

Measure graph cost with `bin/graph_profile.rb [-n 32,128,800] [--profile] [--plan on|off|ruby|both] script.rb` (captures a bin script's graph; reports GC runs and time, objects per buffer, and buffer CPU times with and without a GC; `--profile` adds self time and allocations per node class, inflated ~3 us per call, a fused region as one "Plan region"; `-a N` lists the top N allocation sites; `--plan both` alternates unplanned and planned runs, best of `-r`; synth worst case: `spec/test_data/dense_modulated.mid`); compare branches in alternating runs against a master-ai worktree.  Cost on 2026-10-06 (best of 5, % of realtime at 128/512-sample buffers): fm_bass 32.8/19.4, fm_epiano 16.9/6.2, stereo_drone 58.0/39.8, tempo_song 13.1/4.4, antialias_song 15.0/5.4.  Objects per 128-sample buffer on 2026-10-07: fm_epiano 44 (was 94; most of the rest are MIDI stream Rationals), stereo_drone 21 (40), fm_bass 76 (80).

### Plan layer (fused regions)

`lib/mb/sound/plan.rb` (+ `plan/`; executor `ext/mb/sound/fast_plan`) runs connected regions of a graph as one op list per block in C (optimizer stage 4, P1, 2026-10-08), an as-if transformation: the same samples (every op bit-exact with its node, except the default fast sines within -124 dB, see below; Numo's own FMA caveat for complex×complex products as in fast_arithmetic), the user's graph untouched (plans reference nodes; graphviz, `sources`, names unchanged), and node state in the nodes (Tone::State's Arrays), so a plan can drop at any block boundary.
- Automatic: `Synth` installs a plan per lane and `Session#add` per player (`Plan.install`, which also precompiles).  `MB_SOUND_PLAN=0` turns plans off, `=ruby` runs the Ruby mirror; `MB_SOUND_PLAN_CHECK=1` (or `warn`) runs every planned block both planned and unfused on the same inputs and states and compares samples and node states (`Plan.check`: raise in scripts and specs; `:warn` disables that region).
- Node protocol (`Plan::Describable`, which prepends the `Plan::Planned` hook): `plan_describe(p)` returns the node's output Value, built with the DSL (`Plan::Builder`): `p[handle]` (described in the same plan if the region owns that node, else a boundary input), `p.const`, Value operators (`* + / ** real imag`), `p.tone(...)`, `p.param(constant)`, `p.boundary(h, optional:)`; plus `plan_inputs`, `plan_boundary_inputs`, `plan_unsupported_reason`, `plan_snapshot`/`plan_restore`, `plan_output_type`.  Multiplier's: `@multiplicands.keys.reduce(p.const(@constant, complex: plan_complex_buffer?)) { |product, m| product * p[m] }`.
- Covered: Constant (live params: steady values filled, changing ones' own buffers), Multiplier, Mixer, ComplexNode `:real`/`:imag`, `GraphNode#/` and `#**` and `Tuning#freq` (`ProcNode#plan_operator`; the tuning is read as each block runs), Shaper on real inputs (`include/mb_clip_shape.h`, shared with FastClip.shape), and Tone on the `:naive` and `:synth` kernels (every naive shape and noise, PolyBLEP shapes, pwm, LFO fades) with frequency, phase modulation, width, gain, and reset inputs (targets, `rnd`) as `Op::Tone`: split at reset samples, kernels shared with fast_sound/fast_synth through `include/mb_osc_shapes.h` and `include/mb_bl_osc.h`, each jump through the Tone's own Ruby (`Tone#plan_reset`; key sync costs what it costs unplanned, no fallback).
- Covered since P2 (2026-10-09): Notes event nodes (Gate, Number, Velocity, Lift, Trigger, KeyTrigger, Choke, EnvelopeInputs and its Ports, Glide, FadeIn with a numeric delay, PolyPressure, and the smoothed controllers Control/Bend/Pressure), Aftertouch (`Op::Max`), Notes::Frequency (Adds, NoteFreq on `Plan::CURRENT_TUNING`, `Op::Keep` of `#value`), NoteEnvelope::GmTime, and Envelope/NoteEnvelope (`Op::Envelope`: FastEnvelope's kernel moved into `include/mb_envelope.h`, on the envelope's state NArray, with its idle skip).  Boundaries for now: curve shapers, delays, SampleHold, TempoNodes, tones with sync, ports, timelines, feedback, BLIT, clean resets, or wavetables.
- Covered since P3a (2026-10-10, branch plan-p3a): filters (`Filter::SampleWrapper` with an SVF → `Op::FilterSvf`, with a `structure: :biquad` Cookbook → `Op::FilterBiquad`; `GraphNode::FourPole` in every mode, drive mode, clip, curve, self-oscillation, and the diode ladder → `Op::FourPole`; `lib/mb/sound/plan/filter_ops.rb`, C in `fast_plan/plan_filters.c` and `plan_biquad.c` sharing `include/mb_svf.h`, `mb_four_pole.h`, `mb_biquad.h` with fast_filter and fast_sound; the filter's own state and settings read each block, its remembered parameters written back; four-pole node parameters that end replay the block unfused, as envelope inputs), Notes::Cutoff/Quality/Resonance (`Op::Exp`, `Op::Clip`, Numo's float semantics), SQ80::TimeScale (`Op::TimeScale`).  `0 * x` folds to 0 (`Plan::Fold`, `Op::ZeroFold`; user decision 2026-10-09): a product with a zero constant of the patch (a Const, a fill, or a folded product; never a Constant node's live value) fills 0, x's ops still run every block (state, Tees, and envelopes stay in step), a non-finite x gives 0 where unfused gives NaN; warned once per kind (`Plan.fold_warnings`, `MB_SOUND_PLAN_FOLD_WARN=0`) and listed by `Plan.explain`.  Vectorized 2^x under `:fast` (user decision 2026-10-09; `include/mb_vec_exp2.h`, mirror `Plan::VecExp2`): NoteFreq and Pow with a Constant base (`OP_POWF`), 4.6/5.1 ns per sample against libm's 16, counted within `VecExp2::TOLERANCE` (2.4e-7 of the level; no float differing from libm was found), out-of-range and NaN samples recomputed with libm.  Envelope parameters filled with a constant go to the kernel as numbers, so its runs apply (see Envelopes).  Measured (graph_profile, YJIT, best of 3 alternating with master-ai b7fd18e5 while a Valgrind run used one core; % of realtime at 128/512, master → P3a; c_major.mid / dense_modulated.mid): fm_bass 14.5→13.5 / 10.2→8.8 and 23.6→22.2 / 19.7→18.0; fm_epiano 7.3→7.0 / 3.3→3.0 and 15.0→14.1 / 9.3→8.7; sq80_voice 72.3→59.7 / 28.0→25.6 and 87.1→76.3 / 42.4→38.1; stereo_drone 29.8→25.4 / 27.3→23.7; pluck 93.0→30.2 / 53.4→12.5 and 117.4→35.4 / 66.8→18.2; feedback_song 110.4→35.9 / 60.5→14.6; flanger 19.4→16.2 / 16.2→13.3; tape_delay 7.8→7.9 / 6.7→6.7. - Shared inputs (`Plan::SharedInputs`, 2026-10-09): a Synth samples each controller read by the regions of several lanes (every branch of the node's Tee a region boundary input; lanes without resamplers; a lane's own nodes stay with the lane, which advances them itself while skipped) once per block in `#sample_lanes` and hands the buffer to every region (`Region#gather`), skipping ~100 Tee branch reads per fm_bass buffer; regions running unfused replay it, and a mid-block rebuild or disabled region puts it on every branch (`#guard!`) so no source advances twice.  Measured (alternating with master-ai, best of 3, % of realtime at 128/512): fm_bass c_major 14.7→14.7 / 10.0→10.0, dense 23.6→22.9 / 19.2→19.2; fm_epiano c_major 7.4→7.4 / 3.5→3.5, dense 15.4→14.9 / 9.4→9.3 (a branch read cost ~0.1-0.25 us).
- Event-driven nodes (`Plan::EventList`, `lib/mb/sound/plan/events.rb`): each block the Region runs the node's *feed* in Ruby (`#plan_feed`, after the boundary inputs are read): its own event handling (reader, NoteStack, chases, `#render` with the exact-sample edge rules, through `Plan::Recorder` standing in for the buffer) records an EventList (held values from an offset, impulses, Glide smoothstep ramps, FadeIn ramps, or rendered curve samples), and `Op::Events` renders it in C.  Node state stays in the node, so plans still drop at any block boundary.  `Notes::FeedGroup` reads a region's nodes on one stream once per block; `#plan_relevant?` skips events that can't change a node (not for Glide/FadeIn: events split their ramps).  Smoothed controllers add `Op::Smooth` (`include/mb_smooth.h`, shared with FastControl; the feed copies the block's jumps).  Feeders whose stream is over or ends within the block (`#plan_finished?(count)`) run that block unfused and become boundaries (check mode can't replay a stream's end); when the stream's content jumps back (restart, seek, rewind: `#plan_generation` changes), the first such node to be sampled re-includes every one of them at once, plus nodes found unsupported meanwhile (`Plan::RestartWatch`, `Installation#reinclude`; user: "do what makes most sense live", 2026-10-09).  Planning is opt-in per class (`plan_events!`); `Describable` prepends `Planned` to subclasses too (NoteEnvelope's own `#sample` must not run before a region it roots).  Envelope inputs outside the region are optional boundaries: an ending one replays the block unfused (`#plan_input_ended` returns `:replay`) and is a constant afterwards; Synth's skipped lanes advance fused nodes with `Notes::Node#advance`.
- Ops are Ruby objects (`Plan::Op::*`: a dst Value, operands, the describing node, `#run_ruby` mirror, `#exact?`); `Plan::Program` lists them (`to_s`), allocates registers (linear scan; a dst never shares its operands' slots; params own theirs), and lowers them to Int32 words for `FastPlan.run`.  `Plan.explain(graph)` lists regions, ops, and why other nodes stay unfused.
- Region finder (`Plan::Installation`): consumers first; a describable node joins its readers' region only if all of its readers, through every Tee branch, are fusable inputs of that one region, else it roots its own region (regions under `Plan.min_nodes`, 2, are dropped).  Regions read boundary inputs through their nodes' own Tee branches (lockstep kept); optional inputs (reset triggers) may end; a buffer of another type replays the block unfused (`Tee::Branch#replay`) and recompiles.  `Plan.changed(node)` after structural edits (Multiplier#add, a new Mixer summand, Tee branches, Tone configuration, spies) rebuilds the installation before its next block; `structure: false` (sample rates, constants, existing gains) recompiles the region.  Introspection never misses a buffer: spied nodes and `Plan.observe(node)` stay boundaries, and a fused node read from outside its plan replans (`Region#foreign_read`).
- `Plan.precision` is `:fast` by default (user decision 2026-10-09; `MB_SOUND_PLAN_PRECISION=exact` or `:exact` for bit-exact plans): naive real sines without noise run a vectorized float polynomial (`include/mb_vec_sine.h`: the naive kernel's exact phases, then a branch-free shape pass GCC vectorizes at baseline flags; Ruby mirror `Plan::VecSine`, bit-identical), within 6e-7 of libm (-124 dB); `Op::Tone::FAST_TOLERANCE` 4e-6 per block in check mode (a fast modulator's error moves the phases it modulates), node states compared within `Region::STATE_TOLERANCE` (1e-5, `Plan.states_close?`) for inexact programs, `plan_compare` within -100 dB of the peak.  Complex sines are exact (the old scalar fast path, `mb_fast_math.h`/`FastMath`, is gone).  `mb_wrap` floors without libm (`mb_floor` in `mb_ext_helpers.h`, bit-exact; naive sines ~10% and ramps ~27% cheaper).

### Feedback loops

`sig.feedback { |fb, input| input + fb.delay(5.ms) * 0.8 }` (alias `fb`; `GraphNode::FeedbackMethods`, `GraphNode::FeedbackLoop` in `lib/mb/sound/graph_node/feedback_loop.rb`) builds a loop: the block gets the loop variable (`fb`, the loop's own output) and the input (`input`; `in` is a Ruby keyword) and returns the body; `sig.delay(t, feedback: g, dry:, wet:) { |fb| insert }` is the tape-echo form (the loop output is `insert(delay(input + g * output))`, so the insert runs on every repeat, the first included; without a block `#delay` is unchanged); insert pipelines (user decision 2026-10-09) `sig.delay(t, feedback: g) { |d| d.fb { |fb| fb.filter(3000.hz.lowpass).softclip }; d.wet { |wet| wet.filter(5000.hz.lowpass) } }`: a block that calls the builders on its argument (`GraphNode::DelayMethods::InsertPipeline`; else the block's return value is the tape insert) is a pipeline, `d.fb` processes only the recirculated signal in the loop (first echo clean, each later repeat processed once more, on time) and `d.wet` every echo on its way out, outside the loop and not fed back (its latency not compensated); either may be left out; with `d.fb` the echoes come from a second delay line outside the loop (`(input + g * loop).delay(t)`, since loop taps don't exist yet), about one delay's extra cost.  The loop's nodes (those depending on `fb`) run one sample at a time as plan ops in C (`ext/mb/sound/fast_loop`, `FastLoop.run`; exact Ruby mirror `Plan::Loop::Program#run_ruby`, `MB_SOUND_PLAN=ruby`; `MB_SOUND_PLAN_CHECK=1` runs both and compares bit for bit), so the output is the same at every block size and loops may be as short as one sample; everything else (input, delay times, gains, cutoffs, LFOs, envelopes, MIDI) is computed by the graph per block and read per sample (`FeedbackLoop#plan_sources` shows the plan layer only these inputs, so regions upstream still fuse).  Ops on the loop: arithmetic (Mixer, Multiplier, Constant, `/`, `**`), shapers (antialiased or not), delays (`fb.delay(t)`: Filter::Delay through `SampleWrapper#loop_describe`, its own DelayLine buffer and time handling, any interpolation; no `feedback:`/`wet:`/`dry:` of its own inside a loop), SVF filters (any type; cutoff/Q/gain may move).  `fb` is the current output when every path from it to the output has a delay, else the output one sample earlier (`Op::LoopHistory`, gen~-style); delays read from the sample being computed (at least one sample back).  Latency compensation (default; `compensate: false`; user decision 2026-10-09): the longest delay on the loop reads earlier by the rest of the loop's latency, so loop periods and echo times are exact.  Default mode `:pitch` (`compensate: true`; user decision 2026-10-09, `Program#pitch_latency`): the latency is the rest of the loop's phase delay at the fundamental 1/T (T the delay's time), from each op's complex response (delays, gains, antialiased shapers' half sample, SVFs' exact response; the DC estimate unwraps the phase and gives the loop gain's sign, linear-phase loops keep the exact DC value), evaluated at every 16th sample of the stream (in C since 2026-10-10: `FastLoop.pitch_track`, `ext/mb/sound/fast_loop/loop_pitch.c`, bit for bit with the Ruby version `Program#pitch_track_ruby`, which `MB_SOUND_PLAN=ruby` runs and check mode compares; Ruby checks whether anything moved before calling it; `#sustain_stretch` takes the phase at w with the shelf once (until 2026-10-10 its lambda assigned the method's locals, so the phase came from w - h with the shelf applied twice; fixed in both by the user's decision): lowpass at the pitch T60 110 Hz 20.83 → 21.20 s, 440 Hz 4.70 → 4.78 (unfiltered 20.74 / 4.67), lowpass at 2x within 0.3%) and ramped linearly between points while inputs move (same output at any block size), held exactly while nothing moves; no fixed-point iteration is needed since the target pitch 1/T is known.  `compensate: :dc` is the earlier mode: group delay at DC from per-op moments (the history's sample, an antialiased shaper's half sample, a lowpass SVF's 1/(2gQ), an allpass's twice that, other delays; gains weight parallel paths; per block in Ruby, per sample when a gain or cutoff moves; `FeedbackLoop#latency`). ### Numeric Mixins

`lib/mb/sound/numeric_sound_mixins.rb` adds methods like `.hz`, `.db`, `.meters`, `.bits` to Numeric (e.g. `440.hz.sine`, `-20.db`).  `440.hz` is a `Pitch` (`lib/mb/sound/pitch.rb`): a light frequency source whose oscillator methods (`sine`, `ramp`, `at`, `fm`, `pm`, `lfo`, `tone`/`hz`, `phasor`) make a new `Tone` each call; it plays as a full-scale sine when used directly as a signal, and sequences can hold it as a fixed frequency (`seq(C4, 440.hz)`).  `Note < Pitch` (C4 = 60) gets its frequency from the session `Tuning` (`tuning b4: 480`, live; in a scheduled block it changes on the block's time, `Session#at_time`).

`Tone` (`lib/mb/sound/tone.rb`) is the one oscillator node (no separate Oscillator or Phasor classes; `pitch.phasor` is a Tone with wave type `:phasor` that outputs its phase in cycles, no `at`).  Its DSL methods configure it before it plays (afterwards they raise `FrozenError`, or warn and change nothing in live mode; values that change come from input nodes; `sample_rate=` works any time), and everything that changes per sample (phase in cycles, band-limiting history, queued jump step, random-phase seed and draws) is one `Tone::State` (`lib/mb/sound/tone/state.rb`; plain-value `to_h`, chosen with `bin/osc_state_benchmark.rb`).  The class comment maps each buffer's steps to plan-layer ops (inputs, SPLIT at resets/timeline jumps, PHASE, SHAPE, GAIN, JUMP, PORTS).

Phases: `MB::Sound::Phase` (`lib/mb/sound/phase.rb`): `0.25.cycles` (`.cyc`, `.cycle`; `to_radians`/`to_cycles`/`to_degrees`, arithmetic like Interval) and `node.cycles` (a node whose output is in cycles; `to_radians` is the node × 2π, made once).  Methods that take radians also take Phases via `Phase.radians` (`with_phase`, `reset(to:)`, `pm` source/index (a numeric Phase source is a fixed offset), `fm_feedback`, unison `phase:`, `ping(phase:)`); `pm_cycles` (alias `pm_cyc`) is `pm` with the modulation in cycles; plain numbers and nodes stay radians (2026-10-10 first step; moving every phase to cycles is a pending user decision).

Lengths: `Sequence::NumericDurations` adds musical lengths (`2.bars`, `3.beats`, `3.n16`, `3.sixteenths`, `1.n8.dotted`) returning `Sequence::Duration`s (see Tempo sync).  `MB::Sound::Length` (`lib/mb/sound/length.rb`) adds `Length::Seconds` (`4.seconds`, `250.ms`) and `Length::Samples` (`5.samples`, counted at the sample rate where used, so inside `oversample` too), sharing one protocol with Duration (`to_seconds`/`to_samples`/`to_whole_notes`); `node.samples` / `node.seconds` mark a node's unit.  Every method that takes a length accepts all of them plus plain numbers in its usual unit (seconds for delays, envelopes, `until`, `silence`, `render(seconds:)`; bars for fades and schedules; samples for `with_buffer`), via `Length.seconds`/`Length.samples` or `Duration.bars`/`Duration.whole_notes`.  Changing lengths (delay times) go through `Length::Source`, which keeps the unit and converts per buffer at the current rate.  `MB::Sound::Interval` (`lib/mb/sound/interval.rb`) is the pitch interval: `4.octaves` (`.oct`), `7.semitones` (`.st`, `.semi`), `50.cents` (whole cents exact; `1200.cents == 1.oct`), with `#to_semitones`/`#to_octaves`/`#to_cents`/`#ratio` and arithmetic; methods taking an interval also accept plain numbers in their usual unit via `Interval.semitones`/`Interval.octaves` (semitones for `transpose` on Notes, Pitches, clips, and seqs).  `MB::Sound::Scale` (`lib/mb/sound/scale.rb`; `scale(:minor, :a)`, `Scale[name, root]`, `Scale.new([0, 204.cents, 7.st], period:)`, `Scale.steps([2, 2, 1, ...])`) maps degrees to note numbers (`#note`, `#[]` → Notes, so Tuning applies; degree 0 is the root note, `:a` = A4, `root: A3` = A3), `#transpose(note, degrees)` (off-scale notes keep their distance above the scale note below), `#snap`, `#degree`, `#chord`, `#notes(range)`, `#mode(n)`; `Scale::CHROMATIC` is every transform's default, so degrees are semitones unless a scale is given (user decision 2026-10-09: `pitch:` is always in scale degrees).

### Oscillators and antialiasing

Tone waveforms are antialiased by default (`lib/mb/sound/band_limit.rb`, kernels in the `fast_synth` extension); every shape has a naive (aliased) `a*` twin for lo-fi sounds and control signals.  Measure any expression with `bin/aliasing.rb 'p.ramp' 'p.aramp'` (coherent-sampling aliasing table and cost; `--render DIR` writes 100 Hz-8 kHz sweeps with spectrograms).

- `ramp`/`saw`, `square`, `triangle` use PolyBLEP/PolyBLAMP (corrections on the samples either side of each edge, found on the phase plus phase modulation, so FM/PM and through-zero motion work); `aramp`/`asaw`, `asquare`, `atriangle` are naive (`Tone#band_limited?`).  `.lfo` fades band-limiting in from 15 to 30 Hz (`BandLimit::LFO_FADE`), so slow LFOs keep exact jumps (delay times, gates) and audio-rate "LFOs" are clean.  Free-running PolyBLEP shapes have exact means at every pitch (PolyBLEP's step correction sums to the ideal step's area, and PolyBLAMP's extra 1/12 per corner cancels over a cycle): measured 2026-10-08 at 2-12 kHz, means within 1e-5 at any start phase, and 50 ms window means over a 2-12 kHz sweep within 8e-5 of the ideal band-limited waveform's (low-frequency beats of aliases near 0 Hz, -70 dB at 4799.7 Hz); a band-limited tone's first sample is corrected as if it had always run (`state.blep[3]` 0 = never played, 2 = after a jump), so a square starting at phase 0 plays 0, the ideal, not +1 (fixed 2026-10-08).
- `pwm(width)` (alias `skew`; width a number or node) warps the phase of any shape: `square` → pulse (`pulse(w)`/`apulse(w)`), `triangle.skew(0.1)` → near-saw, `sine.pwm(w)` → CZ-style phase distortion; DC offset removed by default (`dc: true` keeps it); the warp's corners are band-limited too.
- `complex_ramp`/`complex_square`/`complex_triangle` are closed-form band-limited impulse trains, integrated (`BandLimit.blit_ruby`): no aliasing or negative frequencies (-153 dB), top octave lifted ~2.6 dB.  With phase modulation, `pwm`, or sync (or resets and timelines with `clean`) they play from complex wavetables of the exact series (`Tone.complex_table`, `Tone#complex_table?`, kernel `:wavetable`; also `complex_sine` with a warp or sync; 2026-10-08, before: the naive `acomplex_*` with PM, `pwm` ignored, sync refused); without `clean`, resets of plain complex tones restart the impulse trains as before.  With `clean` (and no PM), warps, resets, and timeline jumps run through the synced table kernel without sync events (`Tone#clean_table?`: exact corners, resets as hard sync events with `FastWavetable.sync`'s `reset_phase`).  Measured two-sided (`bin/aliasing.rb -c`, harmonics on both sides): PM 0.5 rad at 1 / 3 kHz -45 / -29 dB (naive -20 / -14; the rest are PM sidebands past Nyquist), `pwm(0.3)` -31 to -40 (naive -12 to -18; clean -113 to -118), sync 2.37 -101 to -112; clean resets against the ideal complex reset waveform -30 to -57 dB (restart -24 to -32; a minBLEP step on the table measured worse at edges, where the imaginary part has log peaks).  The impulse trains' phase leads the exact series by their integrators' leak (0.6 samples at 100 Hz, 0.006 at 1 kHz).
- `sync(ratio: r)` hard-syncs a tone to a hidden master at its own pitch (playing at pitch × r; r a number or node), `sync(master)` to a Pitch/Tone/phasor (its `wraps` port) or any trigger node; `softsync` reverses direction instead.  Synced tones use a causal minBLEP kernel whose output is exactly the naive waveform through the minBLEP's minimum-phase filter (`FastSynth.oscillate_sync`, `BandLimit.sync_tables`): polynomial segments are delayed by the filter's moments (about 2.78 samples) and events add residuals of their value, slope, and curvature jumps; sine segments use per-frequency residuals (`BandLimit.sync_sine_table`, 6 MB, built on first use).  So DC and harmonics match the ideal synced waveform (DC error < 1e-4; harmonics -56 to -106 dB; aliasing -88 to -135 dB); until 2026-10-07 every step left 2.78 samples times its height of DC behind (+0.82 on a ramp synced at 2.37x of 3 kHz) and soft-synced squares spiked on their edge at phase 0.  Synced sines cost 1.3-2.2% of realtime at 3-4 kHz masters; no phase modulation with sync.
- `fm_feedback(amount, gain: env, dc: false)` (aliases `fmfb`, `fm_fb`; `fm_feedback_cycles`/`fmfb_cycles`/`fm_fb_cycles` take cycles; sines only; renamed from `feedback`/`fb` 2026-10-09 so `feedback` is graph feedback, see Feedback loops) is FM operator self-feedback in the kernel (`FastSynth.feedback_sine`, mirror `Tone#feedback_ruby`, history `state.feedback` = [y1, y2, dc]): y = sin(phase + pm + amount × avg(y[n-1], y[n-2])) × gain, DX7-style two-sample average; `gain:` (an envelope) is inside the loop so brightness follows it, `at` is outside.  Radians for now (a later project moves phase units to cycles, `.pm` included).  Measured at 55-440 Hz: 1-1.5 rad saw-like, 2.0 the brightest clean setting; chaos starts ~2.2 rad but stays above 12 kHz (a hiss many playback chains drop) until ~3.5 rad, audible broadband noise from ~4 rad; `Tone::FEEDBACK_MAX` = 2π (DX7 FB 7 at full level) is the knob range (no clamping anywhere).  DC (mean -0.25 at 2 rad) is removed from the output by default (`dc: true` keeps it) by a pitch-tracking one-pole at f/20 outside the loop.  Resets (key sync) clear the history so every note starts identically (`reset(t, keep_feedback: true)` / `.keep_feedback` keep it; timeline jumps keep it).  Aliases like FM at high notes (1 kHz, 1.5 rad: worst alias -59 dB); ~28 ns/sample for any amount (sine 21).  Not with other shapes, pwm, sync, noise.  `Tone.dx7_feedback(0..7)` = 2π·2^(fb-7) (MSFA's arithmetic; the operator's level goes in `gain:`).  Demo: `bin/synths/fm_brass.rb` (`--feedback 0` to compare).
- `tone.gain(g)` (alias `amp`; number or node, e.g. an envelope) multiplies the output inside the Tone after `at` and jump steps, bit-identical to `tone * g` without a Multiplier (`FastArithmetic.scale`, Numo fallback/mirror); saves ~4 ns/sample at 128-sample buffers (~2 at 512) against `tone * env`.  On feedback sines it is the output gain; `fm_feedback(gain:)` is the in-loop one.
- Phase jumps (reset inputs, timeline jumps of tempo tones) are band-limited steps over the next 32 samples by default (minBLEP/minBLAMP from the old waveform to the new, queued in `state.jump_residual`; `Tone.jump_residual` adds a 4-tap raised cosine 1.5 samples after the jump so each step has the area of an ideal step on the sample, -dv/2 + ds/12: no DC drift at audio-rate resets; a reset on an edge in value starts from its left side; 2026-10-07; plain sines still jump naively).  Opt-in `clean` (`tone.clean`, `reset(trig, clean: true)`, `pwm(w, clean: true)`; user's choice 2026-10-08: the default keeps key-synced voices' cost predictable) plays a tone's jumps through the synced kernels: band-limited ramps, squares, triangles, and warped shapes without PM, noise, or an LFO fade (`Tone#reset_sync?`, kernel `:reset_sync`) make each jump a hard sync event on its sample to the target phase (`FastSynth.oscillate_sync`'s `reset_phase`), as clean as sync (harmonic error against the ideal reset waveform -72 to -86 dB instead of -19 to -38), at the cost of the naive waveform through the minimum-phase filter (about 2.8 samples of delay, minBLEP edge ringing with peaks up to ~1.4x PolyBLEP's) and about 2x the oscillator's CPU (bin/synths/fifth_pad.rb with `.clean` saws: 16% -> 19.5% of realtime at 512-sample buffers).  Resets happen on whole samples (sync pulses carry sub-sample times), so audio-rate resets jitter by up to a sample where sync doesn't.
- Reset inputs (top-down note flow): `tone.reset(trig, to: nil)` jumps the phase at every nonzero sample of `trig` (e.g. `clip.trigger`), at exactly that sample (step measured with that sample's FM/PM/width); `to:` is nil (the `with_phase` start), radians, a node, or `:random`; `reset(nil)` removes it; not with `sync`.  The Tone splits the buffer at reset samples in Ruby around the kernels (a scan costs ~3 us per 128-sample buffer, each reset ~35 us; tones without a reset input skip it).  `.free` (`free?`) = never reset (no key sync in synth voices; reset+free and rnd+fixed `to:` conflicts: last call wins with a warning; reset+sync raises; `lfo` tones aren't `free?` but may take a reset input); `.random_phase`/`.rnd(seed:)` = random start, new random phase per reset.  Randomness: `MB::Sound.seed(n)` / `random_seed` / `next_seed` (`RandomMethods`, default seed 0 or `RANDOM_SEED`, restored before every spec example); random-phase tones draw a sub-seed when `rnd` is called (creation order), `Tone#seed=` for derived seeds.  `smooth(t, reset: trig)` jumps instead of gliding on resets. `GraphNode::HarmonicTable`) is an additive oscillator whose spectrum (numbers, nodes, or a callable of time) changes while it plays (32 harmonics: ~100 us per rebuild, 1.4% of realtime at 512-sample buffers, 1.8% at 128, plus its amplitude sources; spectra and half means in C, `FastWavetable.harmonic_spectra`/`.half_means`).  Table sync redesign 2026-10-08 (the 2026-10-07 study on the never-merged branch `research-sync` (2f595c60, `research/sync/`) found the old residuals, normalized by H per harmonic while the reads weren't filtered, drifted the mean up to 0.21 from the ideal, which blocked the warp corners). - Still aliasing: FM/PM sidebands and operator feedback (use `oversample`), `gauss`, naive `a*` shapes, unmipped (`mips: false`) tables.  Demo and A/B snippets: `bin/songs/antialias_song.rb`.
- Unison: `pitch.unison(n, detune: 12.cents, layout: :random, phase: :random, spread: 0, normalize: :power, seed: nil) { |p, i| p.saw }` on any Pitch (`220.hz`, Notes, `v.hz`; `lib/mb/sound/unison.rb`): the block gets each copy's `pitch.transpose(offset)` (so `v.hz` keeps key sync, bend, glide, vibrato), and every oscillator made from it (or pitches derived from it) gets the phase through `Pitch#unison_phase` (`:random` = `rnd`, new random phases at each key-sync reset; radians; `:reset` = leave alone).  `detune` is the outermost copies' distance either side (Interval or semitones, or an Array of fixed offsets, or a node of semitones: copies keep fixed layout fractions -1..1 scaled by it, computed for all copies at once by `Unison::Detune` in the `fast_unison` extension; copies are `Unison::CopyPitch`es making the base pitch's kind of tone; `detune_mode: :exact` (default since 2026-10-07; every copy exp per sample, ~0.15% of realtime more for 7 copies) or `:interp` ramps the exact outermost ratio every 16 samples of the stream (buffer-size independent) and spaces copies linearly in Hz, middle copy sharp by 1200·log2(cosh(d·ln2/12)) cents (0.18 at 25 cents, 2.9 at 100), ~half the detune math of `:exact`; fixed detunes keep the plain `transpose` path); `:random` layout jitters by up to 1/3 step, recenters, rescales (seeded from the root RNG, or `seed:` for the layout only; per-lane in synths).  `GraphNode::ChannelMixer::Unison` mixes with 1/sqrt(n) (or `:peak` 1/n); `spread > 0` (or a node) returns stereo, equal-power pans × sqrt(2) with sides alternating by pair (`Unison.pan_slots`).  `mix:` (0..2 or a node, clamped; default 1 = bit-identical) sets the side copies' level to mix² (0.5 = -12 dB, 2 = +12 dB): center copies (`Unison.center_copies`: nearest the pitch for odd counts, two nearest for even; 2 copies are both centers) stay at 1, and the normalization follows the weights (power 1/sqrt(Σw²), so loudness stays put).  Per copy: the block gets `|p, i|`, `Pitch#unison_copy` (`Unison::Copy`: index, count, RNG from the unison's seed drawn after the layout), and pitch methods on copies take per-copy values: a Range (random), `spread(a..b)` (even, lowest copy first), `channels(...)` (cycled); Intervals → semitones, Lengths → seconds.  Node-detune copies of Notes pitches take `glide`/`bend_range`/`vibrato`/`transpose(node)` (`CopyPitch#notes_pitch`: a NotePitch transposed by the copy's offset node fraction × detune, so exact detune through `Notes::Frequency`; the `Detune` node is built lazily by `Unison::CopySet` only if plain copies use it).  Glides with the same settings share one `Notes::Glide` per Notes (memoized in `NotePitch#number_node`; before and inside the block alike).  `Pitch#transpose`/`NotePitch#transpose` take a node of semitones; a fixed transpose of a tempo pitch gives `TempoNode#scaled(ratio)` (exact ratio, freewheel follows the parent), so `1.beat.hz.unison(3)` stays timeline-locked.  `Notes::Glide` has `overshoot:` (0..1, smoothstep + k t³(1-t)²) and relative `from: -7.st`.  `pitch.swarm(12, chord:, detune:, glide: 0.08..0.9, overshoot:, scatter: 1.oct | from: G3..G4, drift: 10.cents, drift_rate:, spread: 1, ...)` (`lib/mb/sound/unison/swarm.rb`) is a unison of per-copy glides on Notes pitches, optional chord tones (`Unison.chord_offsets`), scattered or banded starts, and sine drift; cost ~0.8% of realtime per gliding copy at 512-sample buffers (Glide + Frequency + saw each; 24 copies ~20%, ~56% at 128), less once glides settle.  Demos: `bin/songs/unison_song.rb`, `bin/songs/swarm_song.rb`.

### Envelopes

`MB::Sound::Envelope` (`lib/mb/sound/envelope.rb`; kernel in `fast_envelope`, exact Ruby mirror `Envelope.process_ruby`) is a state machine (idle, attack, decay, sustain, release, choke, ended) over curved segments (a segment list with a release node, ready for multi-segment envelopes) that land exactly on their targets at their times (whole samples).  Curves are signed dB, SuperCollider's curvature (`c = -d ln 10 / 20`): +60 falls like a 60 dB exponential, 0 is linear, negative swells; presets `:linear`, `:analog` [12, 60, 60] (default), `:snappy`, `:gentle`, `:swell`, `:dx`; `curve: 60`, `{ release: 30 }`, `[a, d, r]`, or `.curve(...)`; +30 is about the old `adsr(...).db(30)` (`GraphNode#db` is gone: write `10 ** (node / 20)` to turn dB into gain; `Numeric#db` stays).

Segment shapes (`shape:` `:exp` default or `:s`, per stage `{ attack: :s }`/`[a, d, r]`, or `.shape(...)`): `:s` is smoothstep of the dB-warped phase (zero slope at both ends; 0 dB = the old smoothstep ADSREnvelope); a time change re-rates the phase so it still lands on time, target/curve changes re-anchor at the current level and phase, and after a re-plan, release, or retrigger a short Hermite slope carry (≤ 2 ms, `S_SLOPE_TIME`; ≤ 1% of the step, `S_OVERSHOOT`) avoids corners.  Presets `:smooth` (S, [0, 0, 0]: the old ADSREnvelope exactly) and `:pad` (S, [0, 12, 12]); a curve preset name also sets the shapes (`CURVE_SHAPES`), `shape:` applies after `curve:`.  S code is out of line in the kernel (`env_plan_s`/`env_sample_s`) so the exp loop stays fast (ns/sample: exp 17.5, S 22.5).  Runs (2026-10-10; user rule: specialize only on constants of the patch, never on inputs that merely hold still): while an exp segment's time, curve, and level (and the hold without a gate) are numbers, a sustain's level is, or the envelope is idle, the kernel makes the samples until the segment lands or the gate, trigger, or choke changes (still read every sample) without its per-sample parameter reads and re-plan checks, bit for bit (a spec compares numbers against the same values as signals); constant parameters 9.2 → 3.5-3.9 ns/sample, signal parameters unchanged (GM-scaled synth envelopes have signal times).

Multi-segment envelopes (every constructor and the Notes versions, `env([[level, time, curve, shape], ...], release_at: k, loop: j)`): segments `:t1..:tN` (2-16), levels relative to the velocity peak (bipolar fine), the level before `release_at` (default: the last segment) is the sustain; `loop:` (index, name, or true) makes the segment before the release jump back while held (kernel config's optional 10th value; a loop at the release index runs straight into the release, the SQ-80's CYC; at most 16 loop jumps per sample, so zero-length loops sustain).  Curves/shapes not given per segment come from the preset by role (`Envelope.segment_role`: first = attack, others before the release = decay, rest = release; Hash keys may be roles or names); `[[1, a], [s, d], [0, r]]` is sample-identical to ADSR (specs per preset).  `Envelope#set_time`/`set_level`/`segments`/`names`; NoteEnvelope GM scaling goes through `set_time` by role.  SQ-80 panel units: `MB::Sound::SQ80` (`lib/mb/sound/sq80.rb`: `.time` from the manual's chart, `.level`, `.env_options` with LV lin/exp, T1V, TK via `SQ80::TimeScale` nodes, second release, cycle, loop; UNVERIFIED values are constants), `sq80_env(**panel)` and `v.sq80_env(**panel)` (`restart: true` = `retrigger: :zero`: every note starts from 0, the SQ-80's ENV restart; kernel flag `FLAG_ZERO`, off by default).  Specs: `spec/lib/mb/sound/envelope_segments_spec.rb` (also in memcheck).

Times, sustain, and curves take numbers, Lengths (Durations follow the tempo), or nodes; a change mid-segment re-plans the rest from the current level.  Inputs are signals: `gate:` (edges), `trigger:` (rising edges to > 0; negative values reserved), `velocity:` (read at the note start, mapped by a `sensitivity:` Range, `velocity_scale: :linear`/`:db`), `choke:` (3 ms, linear), `lift:` (release velocity at the release start: release time × 2 ** ((0.5 - lift) × 2), off by default); `.legato`.  `retrigger: :add` (or `.retrigger(:add)`) makes a note that starts while sounding attack to the energy sum sqrt(level² + peak²) (capped by `ADD_LIMIT`, so rolls level off within +3 dB of one strike; never below the current level) instead of its own peak (`:restart`, default), so soft re-strikes of ringing notes don't drop (`#velocity_peak`/`#retrigger_peak` predict peaks).  Without a gate, notes release `hold:` seconds after they start (default 2 × (attack + decay), at least 0.1; `false` forever); without gate or trigger it's a one-shot (then `#sample` returns nil); gated and triggered ones never end (`#idle?`).  Constructors (`EnvelopeMethods`, defaults 5 ms / 0.2 s / 0.7 / 0.3 s): `adsr` (generic, sensitivity 0..1; `node.adsr` multiplies; old `auto_release:`/`log:` are `hold:`/`curve:`), `env` (0.5..1), `amp_env` (release +40, -18..0 dB velocity), `fm_env` (`:dx`, sustain 0), `filter_env`/`filt_env` (outputs the cutoff multiplier 2 ** (env × `depth:` octaves; a number, `#to_octaves`, or a node), default 2).  Plot with `bin/plot_envelope.rb` (`--compare`, `--print`, `--shape s,exp,exp`).

### Tweening curves

`MB::Sound::Curve` (`lib/mb/sound/curve.rb`, `curve/library.rb`) maps progress 0..1 to 0..1 (overshoot allowed), shared by glides, tweens, smoothing, shapers, and TimelineInterpolator blends: `Curve[:elastic, overshoot: 0.4, cycles: 4]`, names `linear smoothstep(:smooth,:s) smootherstep sine(_in/_out) quad..quint exp back anticipate elastic squiggle bounce steps ease(_in/_out/_in_out)`, any name with `_in/_out/_in_out/_out_in`, `Curve.db(d)`/`Curve.s(d)` (Envelope's signed-dB curve and :s shape, specs check they match), `Curve.power`, `Curve.bezier`, Procs; `reverse`, `in`/`out`/`in_out`, `>>`, `blend`, `steps`.  `#call` and `#map` (Numo) give identical values; `#lookup` evaluates a 2048-cell Hermite value table in C (`FastClip.curve_lookup`, ~4 us per 512 positions for any curve, within 1e-7 of `#map` except at bounce contacts (1e-4) and vertical end slopes), used by glides.  `bin/plot_curves.rb` plots or tabulates them.

- Glides: `v.hz.glide(t, shape: :squiggle, overshoot:, cycles:)` (`Notes::Glide`; no shape = the old smoothstep code, bit-identical, pinned by `spec/lib/mb/sound/tween_reference_spec.rb`); `swarm(..., shape:, cycles:)` takes per-copy values (`channels(:squiggle, :elastic)`, Ranges).  Shaped glides cost the same as plain ones.
- Tweens: `tween([300.hz, 3000.hz, 800.hz], 1.bar, curve: :elastic)` (`SequenceMethods#tween`, built on `Clip#tween`, a shaped Glide on a clip shifted to keyframes): values are keyframes (each value at its step start, tweening to the next during the step; the last holds or loops back over the last step; repeat a value to hold it); Pitches tween in octaves and give Hz (overshoots stay above 0 Hz), plain numbers linearly, `log:` overrides, mixing raises.  `smooth(t, curve:)` curves every step change (an elastic knob).
- Shaper: `sig.ease(curve, in:, out:, range:, edges: :clamp/:extend/:wrap/:mirror/:none, symmetric:)` (`GraphNode::CurveShaper`; "ease" since `curve`/`shape` are Envelope settings) is antialiased like softclip (ADAA on the excess over the in->out line plus the half-sample allpass; edge modes integrated too; closed forms for polynomial/cosine/exp curves, a Hermite antiderivative table otherwise; `FastClip.shape_curve`, mirror `CurveShaper.shape_ruby`); `aease` is exact for control signals.  Demo: `bin/songs/tween_song.rb`; renders in /app/tmp/listening/tweening/.

- Bounce rhythms: `bounce_hits(2.bars, count: 16, elasticity: 0.75, note: C2, reverse:)` (`SequenceMethods`) is a Clip of hits at length × (1 - e^i), converging on the bar line; velocities fall by `decay:` separately from the timing (`:gentle` e^(i/2), default since 2026-10-08 (user's listening pick); `:speed` e^i, the impact speed, the old default; `:none`; a factor per hit; a Curve or Curve name over the hits; a Proc of (i, position fraction)), and `pitch: -1` (semitones or Interval per hit, or a Proc) moves later hits; demo `bin/songs/bouncing_ball.rb` (per-section decays: 0.9 per hit for the drop and settle, the user's picks; `--decay` overrides all; balls loop with `align: :launch` so they drop where launched).
- Dynamic cookbook cutoffs (`filter(:lowpass, cutoff: node)`) clamp to `Cookbook::DYNAMIC_MIN_CUTOFF` (1 Hz, like FourPole; negative and NaN included).  Fast moves into very low cutoffs still make a direct-form biquad's output jump (a DC bump that decays once the cutoff rises; measured in the commit 8323e7d1 message), so tween cutoffs as Pitches.

### Filter System

`lib/mb/sound/filter/` contains 16+ filter types (Biquad, FIR, Butterworth, Hilbert, Delay, etc.). Filters implement `#process` / `#reset`. `Filter::Cookbook` provides standard designs (lowpass, highpass, bandpass, etc.).

Graph cookbook filters are state-variable filters (user decision, 2026-10-08): `node.filter(:lowpass, cutoff:, quality:, gain:)`, `filter(150.hz.highpass(quality: 4))`, `filter(800)`, `peq`, `peq_series`, and `bandpass_series` build `Filter::SVF` (`lib/mb/sound/filter/svf.rb`; Simper's linear trapezoidal SVF, kernel `FastFilter.svf` in `fast_filter` sharing `mb_tan_pade` with the four-pole, exact Ruby mirror `SVF.process_ruby`) with the cookbook's types and parameter meanings (plus `:bandpass_skirt`, peak gain Q, in both structures), so static responses match the biquad (analytic within ~1e-8, float32 renders usually bit-identical).  Its states are integrator states, so cutoff/Q/gain may move on any sample: a cutoff diving toward 0 Hz gives no DC bump (the biquad's 10 ms DC reached 4.8 at Q 3 in the old linear elastic tween), and audio-rate cutoff FM stays bounded (the biquad's output went to infinity at a 2 kHz wobble, Q 4).  `gain:` may be a node with the SVF.  `structure: :biquad` (the only switch; the user declined a global one) builds the old `Filter::Cookbook` through the same path as before (kept for its thumps, e.g. drums); raw `Filter::Biquad`/`Cookbook` objects used directly are unchanged.  ns/sample (kernels, 512-sample buffers): constant params SVF 14 vs `dynamic_biquad` 32 (it recomputes cos/sin every sample), modulated 25 vs 28, scalar static 14 vs `Biquad#process` 12.  Measurements and renders: `/app/tmp/listening/svf_default/`.

`sig.lp4(cutoff, resonance: 0..1)` (aliases `four_pole`, `lowpass4`; also `filter(:lp4, cutoff:, resonance:)`) is a CEM3379-style 4-pole lowpass (`GraphNode::FourPole` over `Filter::FourPole`; zero-delay-feedback OTA cascade in the `fast_filter` extension, exact Ruby mirror `FourPole.process_ruby`, own tan/tanh/2^x approximations): cutoff (Hz, a Pitch, or a node such as `v.cutoff(...)`) and resonance read per sample; -12 dB at the cutoff, 24 dB/octave; like the SQ-80 it never self-oscillates by default (resonance 1 = k 3.9, +37 dB peak) and keeps its bass (-6 dB at full resonance, `compensation: 0.375`; 0 gives -14 dB); `self_oscillate: true` (its own curve, `FourPole.self_oscillate_gain`, kernel curves 2/3: the chosen curve compressed into 0..0.9 reaching k 4 at 0.9, then k = 4 + 1 × x² up to `SELF_OSCILLATE_K` 5, so oscillation starts at 0.9 and its level grows about linearly to ~0.22 peak; starts from silence; was k 4.3 with onset 0.74 until 2026-10-07), `mode:` :lp2/:bp2/:bp4/:hp2/:hp4 taps.  `resonance_curve: :db` (default since 2026-10-07; `:linear` is the round-1 k = r × k_max) makes the gain at the cutoff linear in dB (-12 to +33.8 dB, closed form `FourPole.resonance_curve`; peak +14.5 dB at 0.5 vs +7.5 linear; user-approved 2026-10-07).  Retune values written for the linear curve with `FourPole.db_resonance(linear)` (same loop gain; 0.3 -> 0.21, 0.5 -> 0.33, 0.7 -> 0.47, 0.75 -> 0.51, 0.9 -> 0.68, 0.95 -> 0.79; inverse `linear_resonance`).  Resonant sweeps of a low saw step through single harmonics while the cutoff is low (the narrow peak, not a glitch; detuned pairs make it irregular).  `drive:` (level; saturates above ~1/drive) with `drive_mode:` `:input` (default, tanh on the cascade input), `:stages` (every OTA stage's current plus the input, Zavalishin's one-step secant method), or `:feedback` (`clip: :soft`/`:hard`; only the resonance feedback y4 - c x clips, the MS-20's diode-clipper idea on our 4-pole, passband clean); the last two default to drive 1.  `quality:` instead of `resonance:` (a number or node, e.g. `v.quality(4)`) maps a 2-pole Q to the same gain at the cutoff; in voices `v.reso(0.6)` (alias `resonance_amount`) follows CC 71 (base at 64, 0 at 0, 1 at 127; `v.resonance` is the raw CC 71 Q multiplier).  ns/sample: linear 20, :input 28, :feedback 34-37, :stages 61 (+22 with a per-sample resonance node on the dB curve); ~0.16% of realtime per mono filter at 128-sample buffers.  Renders and measurements: `/app/tmp/listening/four_pole/` (README rounds 1 and 2).

`sig.diode(cutoff, resonance:)` (alias `diode_ladder`; `lp4(mode: :diode)`, `filter(:diode, ...)`) is a TB-303-style diode ladder (`FastFilter.diode_ladder`, exact mirror `FourPole.diode_process_ruby`; from the `research-classic-synths` prototype): four coupled one-pole stages (tridiagonal, open loop 1/D(s), D = s⁴ + 7s³ + 15s² + 10s + 1), TPT solved per sample (Thomas algorithm, linear in the loop input, so cutoff and resonance move every sample), oscillating at k = 901/49 = 18.39 at the cutoff.  Same knobs as lp4 (user: consistency): lp4's curves scaled by K/4 (same distance from oscillation per knob position, same `self_oscillate` onset 0.9), its own `:db` curve (gain at the peak frequency -25.3 to +32.3 dB, linear in dB), compensation, drive `:input`/`:feedback` (`:stages` raises).  `normalize: true` (default; user decision 2026-10-09: easy switching between lp4 and diode, not hardware fidelity; kernel argument 12) matches it to lp4 at the same settings: the stages' frequency × `FourPole.diode_cutoff_scale(k)` (m = 1 + 1.8585 (1 - x)/(1 + 2.1x + 10.6x²), x = k/K: 2.86 at r 0, 2.58 at 0.1, 2.14 at 0.2, 1.65 at 0.3, 1.31 at 0.4, 1.06 at 0.6, 1 at the oscillation edge) keeps the -12 dB-below-DC point at lp4's at r 0 (-12 dB at the cutoff, -3 dB at 0.28 × it vs lp4's 0.43; slopes ~8/11/16/21 dB/oct vs 16/21/24, brighter above) and puts the resonant peak at lp4's frequency from r 0.3 up (within 30 cents; round 3, 2026-10-09: the user heard lp4 a bit brighter at r 0.1-0.4, where round 2 matched the -12 dB point (b 14.4, c 4.85) and the diode's broader peak sat up to 450 cents low; now its -12 dB point is 0.3-0.45 octaves above lp4's at r 0.1-0.3, and a drive-1.5 saw sweep's 0.5-2 kHz bands are 1-5.5 dB under lp4's instead of 3-8.5 at r 0.1-0.4); `diode_compensation(k, k4, c)` replaces the compensation c by c' = ((1 + k)(1 + c k4)/(1 + k4) - 1)/k (k4 = `lp4_loop_gain` at the same knob), so the DC gain equals lp4's at every resonance, compensation, and curve (round 3: the plain c left the diode 1-2 dB quieter from r 0.1 up, -7.8 dB of bass at full resonance vs lp4's -6; now fundamentals within 0.3 dB, RMS within 0.5, and the resonant harmonic under drive 1.5 is still 14 dB over lp4's at r 0.9: acid stays acidic); and `diode_headroom(k)` (1 + (K/4 - 1) x²) lifts the input saturator so self-oscillation matches lp4's level within 0.02 dB (it was 13.25 dB under: the ladder passes 1/K at the resonant frequency, lp4 1/4; `:feedback` drive matched already); `quality:` then gives lp4's knob.  DC through self-oscillation (round 3 check of a swell 0.8→1 that looked offset): running means over whole input periods stay under 5e-4 for both filters (sub-5 Hz power -63 dB re total vs lp4's -50); the waveform's peaks are asymmetric (max/min midpoint up to -0.1, lp4 alike), not offset.  All three are computed only on resonance changes (a per-sample resonance node: ~98 ns/sample vs 91 in round 2, 113 vs 93 with the cutoff moving too).  `normalize: false` is the round-1 ladder (peak at the cutoff at every resonance: -25.3 dB there at r 0, slopes ~14/18/22, self-oscillation ~0.048 peak, plain compensation: -7.8 dB of bass at full resonance).  ns/sample (lp4 vs diode): :input constant 29 vs 34, cutoff per sample 33 vs 48.  Renders and measurements: `/app/tmp/listening/acid/` (round 2 in `round2/`, round 3 in `round3/` with its measurement scripts).

### Delays

`Filter::Delay` (`#delay`) and `GraphNode::MultitapDelay` (`#multitap`) are front ends for one `MB::Sound::DelayLine` (`lib/mb/sound/delay_line.rb`): a circular buffer that grows without losing stored audio, read in C (`MB::Sound::FastDelay.read` / `.feedback`) with Ruby mirrors (`#read_ruby` / `#feedback_ruby`) that specs check for exactly equal values.  Interpolation (`interpolation:`) defaults to `:sinc` (`DelayLine::DEFAULT_INTERPOLATION`; Kaiser-windowed, cutoff lowered by the read speed when a moving delay raises the pitch, so no aliasing up to 4x); `:cubic` and `:linear` (the old lo-fi sound) are options.  Constant whole-sample delays read directly in every mode; a moving or fractional `:sinc` delay costs ~1.5-2% of realtime per mono delay.  No mode reads samples newer than the current input.  Delay times are any length (`0.01`, `250.ms`, `96.samples`, `3.n16`, nodes, `node.samples`) held as `Length::Source`, so they keep their unit when the sample rate changes and rate changes rebuild nothing; fractional constant delays are kept (snapped within 1e-9 of whole samples).  `feedback:`, `wet:`, and `dry:` may be numbers or graph nodes; `#delay` smooths delay changes by default (`smoothing:`), `#multitap` only with `smoothing:`.  With a block (`sig.delay(t, feedback: g) { |fb| insert }`) the feedback runs through the block one sample at a time (see Feedback loops).  Tools: `bin/delay_gallery.rb` (null-test cases), `bin/delay_benchmark.rb` (`--interpolation`), `bin/delay_quality.rb` (error and aliasing against an exact sine answer).

### Chorus

`sig.chorus(:juno1 | :juno2 | :juno12 | :lush, rate:, depth:, delay:, dry: 1, wet: 1, mix:, bbd: false, cutoff:, hiss:, seed:)` (alias `juno_chorus`; `GraphNode::Chorus`, self-contained in `lib/mb/sound/graph_node/chorus.rb` and `chorus_nodes.rb` so a later effects project can move it) is a Juno-60-style chorus: one MultitapDelay (sinc reads) with two taps swept by triangle Tone LFOs, the right inverted, each added to the dry signal; returns a stereo bundle.  Modes are Pendragon's Juno-60 measurements (I 0.513 Hz, II 0.863 Hz, both 1.66-5.35 ms; I+II 9.75 Hz over 3.3-3.7 ms, alias `:juno_i_ii`); `:lush` (`:juno3`, `:stacked`; not on the hardware) runs I and II at once, four taps, two per side at equal power (`rate:` an Array of two or a number for the first).  Mono in like the Juno: a stereo input is averaged for the delay line while the dry keeps its sides (not run per channel; >2 channels raise).  `rate:` takes Hz, Pitches, Durations (tempo sync), or nodes; `depth:` scales the sweep (number or node); `mix:` (0 dry .. 1 wet, number or node) multiplies `dry:` by 1 - mix and `wet:` by mix.  Clean by default (user's choice); `bbd: true` adds the Juno-60 board's fifth-order lowpasses before and after the delay (all-pole cascades from Holters and Parker, DAFx-18, table 1; wet path -3 dB at 5.42 kHz, `cutoff:` moves it, scaling every pole) and -72 dBFS hiss (UNVERIFIED: no measured noise floor found).  When the input ends the chorus plays the delay tail (+50 ms) and ends; the hiss fades out then, or once every Ringdown/Synth upstream ended, so script file renders stop on time.  % of realtime at 128/512-sample buffers: 2.7/2.5 (`bbd` 4.3/3.3, `:lush` 6.0/5.2, `interpolation: :cubic` 1.0/0.7).

### Reverbs

`GraphNode::Reverb` / `#reverb` (`lib/mb/sound/graph_node/reverb.rb`, from the reverb video; `[l, r].reverb(:hall)` / `mix.reverb` take one input per channel) is the one reverb (`FdnReverb`/`#fdn_reverb` were removed 2026-10-10; their room_size/decay/damping contract is `#reverb`'s friendly form).  Its network (inputs → diffusion stages → feedback delay network → output taps) runs in C (`ext/mb/sound/fast_reverb`, `Reverb::Network` over `FastReverb::Network`, exact Ruby mirror `Reverb::Network::RubyKernel`, `MB_SOUND_REVERB=ruby`): diffusion stages a block at a time (no feedback), the FDN one sample at a time, so loops are exactly the line delays at every buffer size and any buffer runs without splitting.  `show_internals: true` builds the same network as nodes for graphviz (same sound within float32 rounding; no modulation or loop processing).
- Classic presets `:room`, `:hall`, `:stadium`, `:space`, `:default` sound as in 2026-01 (impulse responses null against the old code to -122..-140 dB; renders -126 dB): they keep the old loop timing with `loop_extra: CLASSIC_LOOP_EXTRA` (1024 samples at 48 kHz; each line is read at its tap for the output and 21.3 ms later for the loop, what the old `FEEDBACK_BLOCK` read did) and the old level through `level: Reverb.classic_level(n, stages)` for stereo in and out; other channel counts get `Reverb.channel_trim` = 2 / sqrt(inputs × outputs) (user's decision 2026-10-10: mono in or out +3 dB each, the old levels; the reverb answers the inputs' mean power and spreads one total wet energy over its outputs, so 6 outputs are -4.8 dB each and 8 voice inputs -6 dB each).  `loop_extra: 0` gives compact loops, gains retuned from `tuned_loop_extra` so each line keeps its decay per second (RT60 room 0.271→0.276 s, hall 7.03→7.17, stadium 5.66→5.66, space 26.7→28.7, default 0.79→0.84; +0.2 to +3.3 dB energy, denser early sound).  Room-size presets: `:plate`, `:shimmer`, `:grit`, `:lofi`, `:gated`, `:drone`.
- Friendly form: without a preset, `room_size:` (0..1), `decay:` (RT60, any Length), `damping:` (0..1) build a room-size layout (`Reverb.room_params`: FdnReverb's stratified log-random delays rejecting near-integer ratios, diffusion 1-15 ms and feedback 15-120 ms scaled by 0.3 + 0.7 room_size; 8 lines, 4 stages, `loop_extra: 0`, subtle modulation, wet -6 dB; `ROOM_DEFAULTS`).  `decay:` works with any preset too (line gains 10^(-3 loop/decay)); `mix:` (0..1) like the chorus's.  Every input, a single node too (since 2026-10-10; before, a mono reverb ended with its input), is padded with `extra_time` of silence so the tail rings out.
- Gains (energy-normalized, 2026-10-10; were hand-tuned per preset): inputs on their lines at 1/sqrt(lines per input), Hadamard stages × 1/sqrt(N), Householder feedback, each output's group of lines × sqrt(N / group size); with stereo in and out, wet 1 gives each output within ~1.5 dB of the input energy (other counts × channel_trim; no feedback; 4-line networks with 1-2 stages up to ±3 dB, coherent input copies), whatever the lines, stages, inputs, and outputs (the old structure moved by tens of dB; e.g. hall at 4 vs 16 lines 6.7 LU apart, now 0.8).
- Modulation (research 2026-10-10, below): `modulation:` (alias `mod:`) moves each feedback line ±depth, `diffusion_modulation:` (`diffusion_mod:`) each diffusion line by 0..2 depth: true/`:subtle` (feedback 0.25 ms at 0.5 Hz smooth random, ~1.4 cents; diffusion 0.05 ms at 0.7 Hz sine), `:lush`, `:chorus`, `:seasick` (`MODULATION`, `DIFFUSION_MODULATION`), a depth, a node, or `{ depth:, rate:, shape: :sine/:triangle/:random/:smooth, spread:, max_depth: }` (rate a number, Pitch (tempo pitches follow the tempo), or node).  Per-line rates spread over 1 ± spread (0.3) and start phases spread, from the seed; LFO targets every 16 samples of the stream (`FastReverb::LFO_STEP`), ramps between, each LFO its own splitmix64 stream; fractional reads Catmull-Rom.  Off for classic presets (sound kept), on (subtle, feedback only) for the room-size form.  Modulation shortens RT60 a little (cubic interpolation loses highs in the loop: hall 7.03→6.53 s with :subtle).
- Inside the feedback loop (per line; numbers or nodes): `damping:` (Jot first-order absorption filters per line, highs' RT60 × (1 - damping); a number) or `lowpass:` (one-pole Hz/Pitch/node), `highpass:`, `drive:` with `drive_mode:` (`:soft` rational tanh, `:hard`, `:fold`; unity small-signal gain), `crush:` (bits, quantized toward zero so tails can't limit-cycle), `shimmer:` (0..1, two power-complementary 50 ms grains per line at `shimmer_pitch:`, default 12 st, mixed at equal power), `freeze:` (0..1: input muted, loop gains → 1, filters bypassed; lossless), `stretch:` (scales the feedback delays live; lines sized for `max_stretch:`).  After the network: `duck:` (dB while the input peak is above `threshold:`, default -30 dB; 10 ms fall, 300 ms rise) and `gate:` (seconds open after the input falls below the threshold, 20 ms close: gated reverb), from a 50 ms-release peak follower.  Not built: a general `reverb { |fb| ... }` insert block (the FDN is N lines through a matrix; the loop-program machinery has one loop variable and no matrix op yet), reverse reverb.
- Cost (% of realtime, mono in, stereo out, best of 3, 128/512-sample buffers, 2026-10-10; master-ai FusedStage → kernel): room 4.36/1.37 → 1.67/0.85, hall 3.83/1.28 → 1.60/0.85, stadium 2.21/0.58 → 1.17/0.51, space 7.61/2.54 → 2.89/1.60; hall + `mod: :lush` 2.65/1.86, + diffusion modulation 4.4/3.5 (32 modulated reads), space with both 8.4/7.0; plate 4.3/3.5, shimmer 4.0/3.1, grit 4.1/3.4, lofi 3.3/2.4, drone 4.3/3.6.  All fine for a live master chain except perhaps `:space` with full modulation on a slow machine.
- Research (2026-10-10; summary on branch `research-reverb-modulation` 5b7ee4c5, `research/reverb-modulation/README.md`): Dattorro's plate modulates only the two tank allpasses (EXCURSION 16 samples at 29.8 kHz, ~1 Hz, quadrature sine; 2.9-5.8 cents), not the input diffusers; Spin FV-1 (Barr) the loop allpasses ±20 samples at 0.5-2 Hz; Lexicon 480L "spin and wander" move delay taps randomly (WAN ~10 ms of early reflections); ValhallaRoom dozens of randomized LFOs (~0.5 Hz smooth, >1 Hz chorus); CloudSeed separate early-diffuser, late-diffuser, and line modulation (0-2.5 ms, 0-5 Hz; per-line scales 0.7-1.15); Schlecht's thesis: up to 4 Hz natural, ±50% rate spread, keep < 400 Hz static, or modulate the matrix; Freeverb/Zita/Faust Dattorro none; Costello: modulating short input diffusers sounds like "water sloshing around in a metal pan", piano is the hard case.  Peak pitch deviation 2π f A / fs.  Unverified: Lexicon 224 depths, Spin's depth mapping.
- Specs: `spec/ext/mb/sound/fast_reverb_spec.rb` (C vs mirror bit for bit with every feature, block sizes, lossless freeze), `spec/lib/mb/sound/graph_node/reverb_spec.rb` (graph mode, buffer sizes 1..12000, energy grid, RT60 vs `decay:`, damping, modulation seeds, shimmer octave, freeze, ducking/gate, presets), graph sweep entries.  Renders: `/app/tmp/listening/reverb/` (bench set reverb-2026-10-10, `tools/cases.rb`).

### Drum machines

`tr808(source, **knobs)` (`DrumMethods`, `Drums::TR808.kit`; `lib/mb/sound/drums.rb`, `drums/`) is a TR-808-flavored kit, not an exact emulation: a `Drums::Kit` mixing `Drums::Voice`s (kick, snare, rimshot, clap, closed/open hat, cymbal, cowbell, toms, congas, claves, maracas; `kit[:kick]`, `kit.voices`) built from `trigger.ping(freq, decay:)` resonators (`GraphNode::Resonator`, kernel `FastResonator.ping`: a complex one-pole whose frequency moves without changing the ring level), naive-square metal banks (shared by the hats and cymbal), and noise.  Sources: a grid `Sequence::Kit` (rows name voices, aliases, or GM drums), or any MIDI source (clip, `midi`, file, Stream) routed by `TR808::GM_MAP`; knobs per voice as Hashes (`kick: { tune: 45, decay: 1.2 }`; numbers, Lengths, or nodes); the open hat is choked by the closed hat; idle voices are skipped (`skip_idle:`).  Velocity (`Drums.accented`, power curves velocity ** e): `velocity_curve: :grid` (clips, grids, trigger signals) puts x (0.75) `accent:` dB (default 6, user-confirmed) below X; `:midi` (files, live MIDI; chosen from the source by `Drums.velocity_curve`) puts velocity 64 `accent:` dB below 127 (about linear at 6 dB; the grid curve gave -14 dB at 64).  `more_cowbell: true | dB` raises the cowbell's level and its decay × 2^(dB/12).  `outputs: :separate` (alias `:individual`) returns a `GraphNode::Channels` of the voices, named and in `VOICES` order (`outs[:snare]`, `outs.names`; channels may have names in general, kept through per-channel DSL calls), adding up bit for bit to the mix.  Defaults from listening (user, 2026-10-08): snare heads 0.25 s with snappy 0.3 (round 2's louder, longer noise at 0.6 was too noisy), cowbell 0.42 s.  Demo `bin/songs/drums_808.rb`, MIDI script `bin/synths/drums_808.rb`; renders `/app/tmp/listening/drums_808/` (`round2/`).  Not yet: a melodic kick voice, a 909, per-voice pan.

### Sequences

`lib/mb/sound/sequence/` (`MB::Sound::Sequence`) holds musical sequences: immutable `Clip`s of `Event`s timed in exact Rational whole notes, built with `seq` (e.g. `seq(C4, E4, G4.n4).n8`), `grid` (drum step strings like `'x...x...'`), and note length methods on `Note` (`n1`-`n8`, `n12`-`n128`, `.d`, `.t`, long names).  A clip is just a MIDI source: `clip.stream` is a `MIDI::Stream` of a new `MIDI::ClipSource` (a `TimelineNode`; a new source per call, since each follows its own graph's timeline), and its node methods are the mono (last-note) `Notes` nodes of `clip.notes`: `clip.env`/`amp_env`/`fm_env`/`filt_env` (NoteEnvelopes: `:analog` curves, default 5 ms/0.2/0.7/0.3, Envelope keywords such as `curve:`/`sensitivity:` (velocity range; `velocity:` is the input), GM2 time scaling off unless `gm: true`), `clip.tone`/`hz` (a key-synced NotePitch: `clip.tone.ramp`, `.transpose(7)`), `clip.freq` (Hz node), `clip.period`, `clip.gate`, `clip.trigger`, `clip.number`, `clip.velocity(range:)`; each call makes its own Notes, so share one with `n = clip.notes`.  Edges land on exact samples at the tempo of a shared `Transport` (`bpm 120`); `spec/test_data/clip_node_reference.json` (outputs of the removed `ClipNode` renderers) is the edge reference.  `clip.synth(voices: 2, **synth_options) { |v, i| }` is `Synth.new(clip, voices:, tail: 0)` (`v` is a lane's Notes; returns Channels for multichannel voices).  Non-looping clips end one buffer after their last note-off; NoteEnvelopes end once their stream ended and they are idle; an ended reset input (key sync trigger) only stops resets, so tones ring through releases.  `legato(0.85)` shortens notes without changing the rhythm.  `reverse` (alias `retrograde`) mirrors a clip or reverses a Seq's steps; `permute([2, 0, 1])` / `permute(seed: 3)` (alias `shuffle`) moves notes among the same rhythm, repeatably from the clip's seed.  In a `Session`, looping clips play in phase with the transport timeline (`seek`, `rewind`), so graphs started at different times stay in sync.  `clip.loop(align: :launch)` (`Clip#launch_aligned?`) instead counts cycles from the exact launch time (`Player#launch`, the bar line rather than the floored first sample; `TimelineNode#start_at(launch:)`), or from the swap that brings it in; seeks and rewinds keep that anchor (the loop plays as the timeline loop rotated by the launch time; before the anchor it plays the cycles leading up to it), only a new launch (`bg`, `resume`) moves it, and `:clip` launch points ignore such loops.  `rotate(amount)` moves a clip's events later by a Duration (or signed whole notes), wrapping within its length.  See `bin/songs/sequence_demo.rb`.  Launches, replacements, swaps, and master chain switches land on the sample whose window holds their time (floor, like Notes edges), so a clip launched on a bar line between samples (e.g. 112 BPM) keeps its first note. See `bin/songs/sequence_demo.rb`.

Note marks (`Sequence::NoteMarks` on Note, the same methods on `Seq::Step`, each returning a Step, chaining in any order: `~!A1`, `A1.!.~`, `(!A1).up.n8`): accent `!A1`/`.accent`/`.acc`/`.a!` (Step flag `accented`, velocity `Clip::ACCENT_VELOCITY` 1.0 vs default 0.75; grid `X` sets it too), slide `~A1`/`.slide(overlap)`/`.s!` (flag `slid`; the note sounds `Seq::SLIDE_LEGATO` 1.02 of its last step, overlapping the next so mono voices glide and legato envelopes hold; `legato` transforms leave slides alone), octaves `up(n)`/`dn(n)` (alias `down`)/`oct(n)` defined once on Pitch via `transpose` (also on Steps and Seqs).  `!` is overridden only on Note and Step (audit and guard: `spec/lib/mb/sound/note_negation_spec.rb`; test values that may be Notes with `nil?`, never `!x`); `!A1.n8` is `!(A1.n8)` (seq raises with a hint); `!~A1` is Ruby's not-match operator (write `~!A1`); `-A1`/`+A1` stay undefined (minus is for signal inversion).  `Rest`/`R` (a rest Step) and `Tie`/`T` (holds the previous note one more step, resolved when the Seq builds events; a rest after a rest or at the start; grid `-`).  `Seq#acid(accent: 1.0, normal: 0.6, gate: 0.5, slide: 1.02)` plays a Seq like the 303's sequencer (half-step gates, ties hold, slides overlap, accent/normal velocities; tracked for swaps); `acid(*items, step: 16)` is `seq(...).len(step).acid`.  `Seq#loop` returns a looping Seq, so step transforms (`acid`, `acc`, `len`, ...) work on loops.  Voice helpers: `v.accent(0.8)` (0/1 per note from velocity), `v.accent_sweep(env, resonance:)` (the 303's accent capacitor: lowpass at 2 - 0.8 r Hz, x1.6; three accented 16ths at 128 BPM peak 0.57, 0.78, 0.86), `v.acid_env(decay:)` (legato MEG, accents decay in 0.2 s; linear unless `curve:`, e.g. 30; the user picks the default by ear, A/B in /app/tmp/listening/omnibus2/).  Demo voice `bin/synths/acid.rb` (`acid_voice(clip_or_midi, ..., env_curve:)`, a one-voice Synth), song `bin/songs/acid_song.rb`.  Diode accuracy (2026-10-10, study on branch `research-acid-diode`): our equal-capacitor ladder is within 0.7 dB of Stinchcombe's TB-303 core (bottom capacitor halved) at the same knob; the 303's feedback coupling capacitors (~10 Hz) only change the subsonic band (< 0.5 dB at 55 Hz); per-stage diode saturation not built (~2x the diode's cost, a user decision).

`swap :bass, bass2` (`Session#swap`, `lib/mb/sound/session/clip_swaps.rb`) changes a player's clips on the next bar via `ClipSource#swap_clip` on every ClipSource in the graph (exact time; graph and effect state kept; sounding notes get note-offs, held values chase the new clip).  Transformed clips remember their `source` and transform (`Clip#lineage` / `#rederive`), so clips derived from the old one (`bass.transpose(12)`) are rebuilt from the new one, and a `clip.synth` follows through its one source; pass `old => new` pairs (or `kit => kit2` for `grid` rows) when a player has unrelated clips.  See `bin/songs/swap_song.rb`.

Clip feel, chance, and generators (`sequence/clip_feel.rb`, `sequence/generators.rb`; clips move notes both ways, live streams only delay): `humanize(1.n64, velocity: 0.2, seed: clip seed, vary:)`, `quantize(16, amount:, ends:)`, `swing(0.58, 16)` (a time warp per pair of steps), `chance(p)` (alias `maybe`) and `every(n, from: 1)` (Elektron-style cycle conditions, `Event#condition`; also step marks `E4.every(2, from: 2)`, `G4.maybe(0.5)`, and on Seqs; `Clip#plays?` decides both per cycle).  `Clip::Variation`s (`#variations`, `#events_for(cycle)`) change a loop every cycle repeatably from seed + cycle: `permute(vary: true)`, `humanize(vary: true)`, `melody(vary: true)`; mapping transforms keep them, `#repeat` unrolls them (and conditions) per copy, `|`/`&` take cycle 0.  `bake(fx or block, cycles: 1)` runs MIDI stream transforms offline into a Clip (loops bake their steady state, so echoes wrap; `cycles:` keeps several cycles of a varying loop; code note: may change with library/live work).  Generators: `euclid(hits, steps, note = kick, step: 16, rotate:, velocity:)` (Bjorklund, a Seq) and `melody(scale, count, step:, rhythm: clip, leap: 3, range:, weights:, rest:, seed: (drawn from MB::Sound), vary:)` (a weighted walk over scale degrees).

### Tempo sync

`Sequence::Duration` (`lib/mb/sound/sequence/duration.rb`) is an exact musical length in whole notes (comparable, `+`/`-`, scaled by numbers, friendly `to_s` like "3 × n16"), accepted wherever lengths are (`at:`, `fade:`, `every`, `after`, `render(bars:)`, `.len`, `until`).  `1.beat.hz` is a Pitch whose frequency comes from a `Sequence::TempoNode` following the tempo, and `4.bars.lfo` a Tone from it.  Tones made from the pitch lock their phase to the timeline on jumps (start, seeks, resume) plus `with_phase`, top-down through two TempoNode ports that are inputs of each tone (`Tone#follow_timeline`; `jumps` is 1 on the first sample after a jump, `jump_phase` the timeline position in cycles there, shared frozen zeros otherwise), split and band-limited like resets; they freeze while the timeline is paused unless `.freewheel` (per TempoNode; `Tone#timeline` is the TempoNode).  `sig.delay(1.n8.dotted)` (or `sig.filter(3.n16.delay(...))`, `multitap(1.n8.d, ...)`) follows the tempo; `2.bars.lfo.square.at(3.n16..5.n16)` gives an alternating delay time (`Tone#musical_time?`).  Tempo-following nodes include `Sequence::TimelineNode` (shared with `MIDI::ClipSource`, found through the Notes nodes' streams), which `Session` finds in every graph (`timeline_nodes`).  `Tone#lfo` means full range plus no MIDI retrigger.  `render(bars:)` counts bars on the timeline, so tempo changes during a render are followed; `tail: true` adds the master effects tail after the limit.  See `bin/songs/tempo_song.rb`.

### Multichannel

Every GraphNode has `outputs` (`[self]` for one channel) and `channel_count`; nodes with several outputs (stereo file inputs, multi-output reverbs, `MultiOutput`s) act as bundles.  `GraphNode::Channels` (`lib/mb/sound/graph_node/channels.rb`) is the bundle class: `stereo(l, r)`, `channels(a, b, c)`, `[l, r].channels`, `node.stereo`; it is Array-like (`[]`, `each`, `map`, `l, r = bundle`) but deliberately not Enumerable (`Enumerable#filter` is `select`).  `GraphNode::ChannelDispatch` (loaded last in `graph_node.rb`) generates a per-channel version of every `*Methods` module method, so DSL calls on a bundle run per channel and return a bundle.  Channel counts combine like NumPy broadcasting (1 is reused, N-N per channel, other mismatches raise); per-channel arguments are bundles, `channels(0.010, 0.013)` of plain values, or lazy `spread(a..b)`; filter objects are Marshal-copied per channel.  `reverb` is the deliberate exception: a bundle's channels all feed one reverb.

Conversions are `GraphNode::ChannelMixer` nodes (`lib/mb/sound/graph_node/channel_mixer/`): one N-in/M-out gain-matrix node per call, a subclass per mixing law declaring its channel counts, `param`s (numbers or nodes read every sample; numeric gains are computed once) and `option`s, with `#params`/`#gains`/class-level `.params` for introspection.  `pan(pos, law:)` (`ChannelMixer::Pan`; laws `:equal_power` default, `:minus_4_5db`, `:linear`; stereo bundles balance, the common DAW default, also `balance`), `width(w)`, `mono`/`mixdown`, `swap`, `mid_side`/`from_mid_side`, `matrix(rows)` (any N->M, entries numbers, complex, or nodes; replaced `MatrixMixer`), `place(x:, y:)` (alias `position`; phase-amplitude Lt/Rt positioning, replaced `ComplexPan`), plus `left`/`right`.  Complex gains send every input through the same Hilbert stage (`ChannelMixer::Analytic`) and output real parts unless an input was complex.  Mixer outputs advance to a new frame when an output is sampled again, so sample all outputs of a mixer in turn (as a Session does).  `master { |mix| ... }` gets the whole mix as a bundle.  `graphviz` collapses each per-channel call into one box listing per-channel arguments (`expand_channels: true` shows every node).  Deferred (local idea notes): surround layouts/matrix presets and encoder-aware `place` laws (with the user's private surround work), dual/stereo pan modes, `.widen`/`.haas`/ping-pong, `Mixer` accepting bundles, mixer fusion (graph optimizer), vectorized N-channel nodes.  See `bin/songs/stereo_song.rb`.

### Master effects

`Session#master` (`lib/mb/sound/session/master.rb`, console `master { |mix| mix.softclip }`) runs the whole mix through a chain built on `GraphNode::MixSource` channels (one param = the mix as a stereo bundle, N params = one per channel; `master nil` bypasses).  New chains start at `bg`-style launch points; by default the old chain "spills over" (fed silence from the switch sample so tails ring out, dropped after 1 s below -90 dB or 10 s), `fade:` crossfades, `fade: 0` cuts (also used when the render load is over 60%).  Clips in a chain follow the timeline like players' clips (non-looping and launch-aligned ones count from the chain's start, `Chain#launch`, through seeks and resumes).  Chains keep processing while idle, `panic` rebuilds the chain to clear tails, and `render` adds the tail after the last player (10 s cap).  Nodes that change the sample count (`resample`, `oversample`) can't be used in a master chain yet.  See Reverbs for which reverbs are light enough for a live master chain.

### Audio I/O

Device I/O goes through miniaudio (the old JackFFI, Jack/Alsa outputs and inputs, and the mb-sound-jackffi gem are gone; ffmpeg stays for files and ffmpeg outputs).  `OUTPUT_TYPE`/`INPUT_TYPE` are `device` (default), `ffmpeg` (output only), or `null`; unknown types raise.  `MB::Sound::DeviceOutput` (`lib/mb/sound/device_output.rb`) writes into a lock-free ring that a C callback on miniaudio's device thread drains (`FastAudio::Playback`); Ruby never runs on the audio thread.  `#write` keeps at most `AUDIO_LATENCY` seconds queued: a write that doesn't fit queues what fits and waits without the GVL until the rest fits, so the sound card's clock paces the Session one buffer at a time, with evenly spaced writes (and live MIDI reads) and the queue within about a period of full (2026-10-04, JACK dummy, period 128: `:default` write spacing 10.67 ms, sd 0.3 ms).  `MB::Sound::DeviceInput` (`lib/mb/sound/device_input.rb`, `INPUT_DEVICE`) records through `FastAudio::Capture`: `#read` waits without the GVL, skips the oldest audio beyond the queue limit so live input stays near real time, and resamples from the card's rate; `test_pattern: true` records a frame counter on the null device for specs.

Latency profiles (`DeviceOutput::PROFILES`, `AUDIO_PROFILE` or `profile:`; chosen with `bin/audio_load_check.rb` on the user's old Mac; rerun it after big performance changes): `:default` write 512 / period 128 / queue 50 ms (45-56 ms, clean with fm_bass and stereo_drone together), `:low` 256 / 128 / two writes (16-19 ms, light patches only), `:video` 400 / 128 / 50 ms (120 fps frames; 8-10 points more load, so 512 stays the default per the user), `:safe` 800 / 480 / 85 ms (about 110 ms; 60 fps frames).  `AUDIO_BUFFER`, `AUDIO_PERIOD`, and `AUDIO_LATENCY` override a profile; offline renders take `render(buffer_size:)`.  The queue is adaptive: it grows by half after dropouts, up to the `:safe` queue, and shrinks by a third back to the profile's after `DeviceOutput::SHRINK_AFTER` (10) seconds without dropouts (notes on stderr; `AUDIO_ADAPTIVE=0` disables).  `latency :low` (alias `lag`) restarts the background session on a device output with that profile.  Effect/synth/song scripts take `-L/--latency-profile` and a `profile:` keyword (`-L` wins, then `AUDIO_PROFILE`, then the script's default) and call `MB::Sound.warm_up` before live playback (synths: `warm_up(midi: true)`).  Live MIDI switches to `:low` (user decision, 2026-10-04): opening it (console `midi`, synth scripts, effect MIDI controls) calls `live_midi_latency`, which restarts the idle background session on a `:low` device output unless `AUDIO_PROFILE` is set or the user gave `latency`/`use_output` an output (`Session.output_chosen?`); not for ffmpeg/null outputs; with players or master effects it prints a `latency :low` hint instead.  Exact MIDI timing's latency follows the adaptive queue (console live sources follow output switches through `LiveSource#output=`).

Environment: `AUDIO_BACKEND` (e.g. `jack,pulseaudio`; on Linux JACK first only if a JACK server answers (including PipeWire's), then PulseAudio/PipeWire, then ALSA; CoreAudio on macOS; `null` is miniaudio's timer-driven fake sound card, used by the specs), `OUTPUT_DEVICE`/`DEVICE` (index or part of a name), `AUDIO_SAMPLE_RATE` (the rate written, 48000 by default), `JACK_CLIENT_NAME` (default: the script's name; also the PulseAudio/PipeWire application name).  Mono outputs open two channels.  Sample rates (user's choice): graphs and Sessions stay at 48 kHz, and when the card runs at another rate (e.g. 44.1 kHz on the Mac after jackd changed it) the writer resamples the mix with libsamplerate (`AUDIO_RESAMPLE`/`resample:` fastest sinc by default, ~0.8% CPU for stereo; medium, best, linear, zoh, or off to run at the card's rate); `#sample_rate` is the written rate, `#device_rate` the card's; `AUDIO_DEVICE_RATE` forces a card rate (specs use it with the null device); `AUDIO_SET_DEVICE_RATE=1` lets CoreAudio switch the card's system-wide rate.  `Session#sample_rate` is the output's; `Session#add` sets graphs at another rate to it, or resamples nodes that can't change rate (file inputs, raw Biquads); filenames open at it.  Most filters have `sample_rate=` (FirstOrder, Butterworth, HilbertIIR, FIR from a gain Hash, Gain, FilterBank, envelope followers; `spec/lib/mb/sound/filter/sample_rate_setters_spec.rb`), and DSL methods use the node's rate.

JACK has its own small backend instead of miniaudio's and RtMidi's (user requirement, 2026-10-04: every port of a script on one JACK/PipeWire node, added at any time, for their qpwgraph arrangement feature): `ext/mb/sound/fast_audio/mb_jack.c` loads libjack at run time and keeps one client per process; units (a port set plus a realtime process function) attach and detach at any time through an atomically swapped list, detaching after every cycle that might hold the old list has finished.  `Playback.new`/`Capture.new` take optional JACK port names (14th/11th argument) and reuse their rings, resampler, and adaptive queue on JACK's thread; `FastAudio::JackMIDIInput`/`JackMIDIOutput` are byte rings of [JACK frame time, bytes] records.  Ruby side: `MB::Sound::Jack` (`lib/mb/sound/jack.rb`; port names `out_N`, `in_N`, `midi_in`/`midi_in_2`, numbered after those in use; the user's old JackFFI is a reference for structure, not a spec); `DeviceOutput`/`DeviceInput`/`MIDI::Input`/`MIDI::Output` use it whenever JACK leads the backends and fall back to the next backend if it can't open.  JACK servers are never started; new audio ports are connected once (to the physical ports, to ports whose names contain `OUTPUT_DEVICE`/`INPUT_DEVICE`, or nowhere with `none`), and later rewiring by qjackctl/qpwgraph/session managers is left alone.  `FastAudio.jack_connect`/`jack_disconnect` wait (up to 200 ms) until JACK's graph shows the change (otherwise connections are listed late and first messages lost).  Specs: `spec/ext/mb/sound/fast_audio_jack_spec.rb`, `spec/lib/mb/sound/jack_spec.rb` (one-node acceptance test, sample-exact loopbacks).

Tools and threads: `bin/audio_check.rb` lists devices and measures latency, underruns, clock drift, write spacing, and queue range (`--busy` adds GVL contention).  A busy Ruby thread can starve the writer for a whole time slice (100 ms by default, longer than the queue; 131 underruns in 10 s on the user's Mac), so bin/ scripts set `RUBY_THREAD_TIMESLICE=10` in their shebang (user's choice; 0 underruns measured; read only when Ruby starts, so `ruby bin/x.rb`, irb, and `fork_script` don't get it); a priority of -3 on the busy thread also works.  The Session render thread calls `FastAudio.boost_thread_priority` (user-interactive QoS on macOS via `pthread_set_qos_class_self_np`, no privileges; a no-op elsewhere).  `vis` shows each buffer when it reaches the speakers (now + `output.latency`).  `use_output(obj_or_type)` gives the background session another output (refuses while players run); `render` accepts an output object; `OUTPUT_TYPE=ffmpeg` is any live ffmpeg output (`OUTPUT_FORMAT`, default audiotoolbox on macOS and pulse elsewhere; `OUTPUT_CODEC`; `OUTPUT_DEVICE` as the name or URL; about 0.4 s latency), wrapped in `BackgroundOutput` (feeds paced silence so ffmpeg never runs dry; kept separate from FFMPEGOutput by choice).

### Scripts

Every bin/ script except `bin/sound.rb` is built on one of four helpers in `ScriptingMethods`, backed by `ScriptRunner` (`lib/mb/sound/script_runner.rb`, OptionParser):

- `effect_script(input_channels:, live_channels:, **params) { |input, p| graph }` - the input is an audio file (first audio argument or `-i`, rung out with a `Ringdown` node until 1 s of quiet, 10 s cap) or live input (`-c/--input-channels`); `--repeat [COUNT]` loops the file.  `-m/--midi SOURCE` takes `p.midi_cc` controls from a MIDI port (part of its name) or a `.mid` file (played with the graph, also in `-o` renders; `p.midi` is that Notes); only the input's `Ringdown` decides when a file effect ends (live MIDI control nodes never end).
- `synth_script(**params) { |midi, p| graph }` - `midi` is a `MB::Sound::Notes` on the MIDI file or live port given (`-i` or a non-audio argument; by default the script's own port), like the console's `midi`: a mono voice applying the sustain pedals (`midi.hz.saw * midi.amp_env`; `Notes.new(midi.stream, sustain: false)` ignores them) and a source for synths (`midi.synth(voices: 6) { |v| ... }`, `Synth.new(midi)`, `MB::Sound.synth(midi, ...)`).  A MIDI file rings out: once it has ended and every voice is idle (`Synth#ended?` or the Notes nodes' `#ended?`), the runner stops after a second of quiet (10 s tail limit), like effect file inputs (`Ringdown#ended?`); a Synth itself returns nil only `tail:` (`MIDIFile::TAIL_SECONDS`) later, for players without tail detection.  Converting old patches (all of `bin/synths/` and `bin/wavetable_pr_example.rb` use Notes/Synth): `midi.env(...).db(N)` became `fm_env`/`amp_env` with curve -N rising, (1 - s) × N for the decay and s × N for the release (N with sustain 0), the sustain and the old 0.5..1 velocity range mapped through the same curve (see fm_bass.rb, fm_bell.rb); plain `midi.env` amplitude envelopes keep -6..0 dB velocity; fixed-ratio operators are `v.hz.transpose(Math.log2(r).oct)` (key-synced), node ratios `(v.freq * node).tone.reset(v.key_trigger)` (fm_bell.rb), `reset(v.trigger)` for tones and per-voice LFOs that restart at every note-on (drums); `named('portamento')` filters became `v.hz.glide(t)`.  `bin/synths/fm_chain.rb` (the 2021 chained fm_synth: each held note FM-modulates the previous one) is a script-local GraphNode reading `midi.note_stream` per buffer and splitting buffers at event samples.
- `song_script(bars:, **params) { |p| ... }` - the block arranges the song on the current session (`bg`, `at_bar`, `master`); `-b/--bars N` plays or renders N bars (live too), `--bpm` sets the starting tempo and scales the song's tempo changes (`Transport#override_bpm`), `--graphviz` draws the session at the start (`Session#graph_view`).
- `script(args:, **params) { |args, p| ... }` - general scripts (utilities, plots, file processors, benchmarks, MIDI tools): only `-h/--help` is common, positional arguments go to the block (`args:` Integer/Range checks their count; negative numbers stay positional).

Effects, synths, and songs share `-o/--output` (or a positional audio file) to render instead of playing, `-f/--force`, `-g/--graphviz`, `-P/--plot`, `-q/--quiet`, and play through the background `Session`.  Parameters are options only (no positional numbers): `name: default` or `name: [default, 'description', '-x', Type, allowed_range_or_array, :required]` in any order after the default; bad values print the option help.  `p.midi_cc(1, :hz, range: 0.0..6.0)` gives a Notes controller node (range relative to the value; its `MIDI::ControlSpec` has the parameter's name and description, listed by `p.midi.controls` and the script's control listing) when MIDI is open (live unless rendering, or `-m FILE`), else a constant; a value inside the range is the knob's center (raw 64, each half linear), else the nearest end, so it starts at the value.  Graph-building code belongs inside the block (`--graphviz` runs song blocks twice).  Guard scripts that can also be `load`ed with `if main_script?(__FILE__)`.  Every script starts with `#!/usr/bin/env -S RUBY_THREAD_TIMESLICE=10 RUBY_YJIT_ENABLE=1 ruby` (checked by `spec/bin/shebang_spec.rb`; see Audio I/O for the time slice).  YJIT roughly halves graph cost (fm_bass at 128-sample buffers under the profiler: ~190% of realtime without, ~85% with; +8 MB RSS) but compiles methods only after many calls, so live paths (`ScriptRunner` live play, `bin/sound.rb` startup) call `MB::Sound.warm_up` (`lib/mb/sound/warm_up_methods.rb`; nil without YJIT) before the first output write: a throwaway graph of common nodes (~0.2 s; first-buffer stall ~55 ms to ~14 ms), plus MIDI voices in synth scripts (`warm_up(midi: true)`; ~0.35 s; ~50 ms to ~14 ms).  `ruby bin/x.rb` and specs run without YJIT.

### MIDI

`lib/mb/sound/midi/` is a pull-based event layer, loaded from `midi/streams.rb` after Sequence: Sources make Events, Streams share them among readers, Notes turns them into signal nodes, and Synth allocates voices.  Nothing is pushed through callbacks, and nothing reads a clock except live input.

- `MIDI::Event` (`midi/event.rb`): the only MIDI message type (`Note#to_midi`/`Pitch#to_midi`/`Tone#to_midi` return note-on Events whose `bytes` `MIDI::Output#<<` sends), a Data value (normalized velocity/CC/pressure 0..1, bend -1..1, raw kept, 0-based channel, time in Rational seconds since the stream start; allocator types `:choke`/`:glide` and `legato`).
- Sources (`midi/source.rb`: `read(from, to)`, `seek`, `restart`, `ended?`, `music_end`, `chase`; note-ons/offs kept balanced across jumps): `FileSource` (one tempo via a tempo-map object, `loop:`; `#notes`/`#note_stats` list notes with key and pedal release times as played, via `MIDI::NoteList` in `midi/note_list.rb`, used by `bin/midi/midi_roll.rb`), `ClipSource` (see Sequences), `LiveSource` (below).  `MIDIFile` (`midi/midi_file.rb`) only parses and analyzes files (`events`, `tracks`; no clock).
- `MIDI::Stream` (`midi/stream.rb`) reads a source once for many `reader`s (cursors in seconds, so any sample rate; late readers start at the slowest), stamps bend ranges from RPN 0, and makes transform views (`midi/transform.rb`: `channel` 0-based, `transpose`, `sustain` (the only sustain handling), `velocity_curve`, `bend_range`).  Streams include `Nameable`/`Traversable` but aren't GraphNodes.  `Stream.for` takes a Stream, Source, Input, Clip, MIDIFile, filename, or anything with `#to_midi_stream` (a Notes).
- `MIDI::LiveSource` (`midi/live_source.rb`; `Stream.live(connect:, output:, timing:)`) reads `MIDI::Input#read_raw` (JACK frame times or RtMidi deltas).  `MIDI_TIMING=exact` (default) keeps timestamp spacing at a constant latency L (default: the output's queue limit + period + one buffer, ~63 ms with `:default`, ~18 ms with `:low`; `latency:` overrides); JACK input with a JACK `output:` is sample-exact through `DeviceOutput#jack_clock`, else the input clock is anchored at the first events and re-anchored when off by more than L (`#track_drift` is the hook for a DLL); `asap` puts events at the start of the read.  `MIDI::RealtimeReader` (`midi/realtime_reader.rb`) plays a file or live input against the wall clock for the bin/midi tools (no audio).
- `MB::Sound::Notes` (`lib/mb/sound/notes.rb`, `notes/`): the per-voice (or mono) signal DSL over a stream (`v` in synth code; `Notes.new(stream | source | clip | file, sustain: true)`).  Note nodes read `note_stream`, the input through the sustain pedal transform (lazy and held weakly, so a Notes used only for controllers or as a synth source never holds the input back), unless `sustain: false` (Synth lanes, already pedaled, and `Clip#notes`); `stream` stays the input (controllers, `to_midi_stream`, `.source`); `control_specs` adds the pedals while note nodes use them.  Every node has its own reader and puts events on exact samples at its own rate: `gate`, `trigger` (impulse = velocity), `number`, `velocity`, `lift`, `choke` (`:choke` events, CC 120), `freq` (Tuning + bend); last-note priority; held values chase `Source#chase` after jumps.  Channel-wide nodes (`bend`, `bend_semitones(range)`, `pressure`, `cc(n, range:)`, GM-named `mod`, `brightness`, `resonance`, `attack_time`, `vibrato_rate`, ... with `MIDI::ControlSpec`s, listed by `notes.controls`) are shared per control stream (`Notes.control_stream`).  `env`/`amp_env`/`fm_env`/`filt_env` are `NoteEnvelope`s wired to gate/trigger/velocity/choke (`lift: true` opt-in), GM2 time scaling (CC 73/75/72) unless `.gm(false)`, registered for `notes.idle?`/`notes.level`.  `v.hz` is a `NotePitch` whose tones key-sync (`Notes::KeyedTone`, `reset(v.key_trigger)`) unless `.free`/`.lfo`/`.sync`; `.bend_range(12.st)`, `.transpose`, `.vibrato`, `.glide(50.ms | :gm, legato:)`.  `v.key_trigger` (`Notes::KeyTrigger`, alias `key_sync_trigger`) is `v.trigger` without note-ons that add energy to a sounding voice (user rule, 2026-10-05: adding energy to an existing envelope doesn't reset oscillators), i.e. note-ons while a `retrigger: :add` envelope of the Notes is sounding, decided per buffer from the envelopes' state at the buffer start (`Notes#adding_at?`, `NoteEnvelope#sounding_at?`, so graph order doesn't matter); `v.trigger` fires at every note-on.  `v.cutoff(base, env:, keytrack: 0.5)` and `v.quality(q)` feed `filter(...)`; `v.reso(amount)` (CC 71 around the base) feeds `lp4(resonance:)`.  `v.poly_pressure` (alias `key_pressure`; per-key 0xA0 pressure of the newest held note, 0 at each note-on, held after release; the Allocator routes each key's pressure to its lane), `v.aftertouch` = max(poly, channel pressure) (it was an alias of `pressure`; `channel_pressure` is the new alias); ControlSpec type `:poly_pressure`, listed but left out of ACID XML.  Controller smoothing (2026-10-08; `Notes::Smoother`, kernel `FastControl.smooth`, mirror `Smoother.smooth_ruby`): CCs, GM-named controls, channel/poly pressure, aftertouch, and bend (so `v.hz`/`v.freq`) glide between MIDI steps through a triangle FIR (two moving averages; each step an S-shaped transition that lands exactly after the time, delay half of it): `Notes::CONTROL_SMOOTHING` 10 ms, `BEND_SMOOTHING` 5 ms (`Notes.control_smoothing`/`.bend_smoothing` apply live: nodes made with the default keep a smoother, a pass-through one while the default is false, and `Smoother#length=` re-plans it from the current output on its next buffer, also in plans (the plan op reads the smoother's arrays each block); nodes given `smooth:` keep theirs; spec_helper restores them); adaptive smoothing `smooth: :adaptive` (`Notes::ADAPTIVE_SMOOTHING` 5..200 ms) or a Range of times (also as the global defaults): each step glides linearly from the current output over the time since the previous step, clamped (the user's scroll-bar idea; a slow 7-bit wheel becomes a line, lag one step interval; kernel `FastControl.adaptive`/`mb_adaptive_run`, mirror `Smoother.adaptive_ruby`, plan `Op::Smooth` picks the kernel by the state's length, 8 = adaptive); per node `smooth:` (`v.cc(1, smooth: 20.ms)`, `v.mod(smooth: false)`, `v.bend(smooth: 0)`, `p.midi_cc(..., smooth:)`); switch CCs (curve `:switch`) step unless given a time; gate/trigger/number/velocity/lift/choke never smooth; poly pressure jumps at note-ons and content jumps. ## Working Notes (lessons learned)

### Verifying audio without speakers

The container has no audio device, so check sound-producing code by rendering it: `MB::Sound.render('file.flac', graph, bars: 4)` or loops of `node.sample(800)`, then look at peak levels, silent stretches, and exact sample offsets of note edges.  Use `NullOutput.new(..., sleep: false)` and `Session.new(realtime: false)` with `#process_buffer` for fast, deterministic tests.  To check that events happened (e.g. a swap landed on its bar), trace internal state from a scheduled block; spectral checks of the mix are easily fooled by other parts.  Leave listening to the user (on a Mac) with copy-pasteable snippets and expected results, and keep good snippets in demo script header comments.

### Gotchas

- `#sample` usually returns a reused buffer; `.dup` each buffer before collecting several of them (several false "bugs" came from forgetting this).  It may also be frozen (a Tee's shared buffer): copy before modifying a buffer you didn't create.
- A Tee branch that is never read keeps its Tee copying until the branch falls a whole CircularBuffer (1 s) behind, and raises `BranchBufferOverflow` if read later; benchmarks that reuse one node in two graphs sampled separately hit this.
- Oscillators (`Tone`, `noise`) are full scale (-1..1) by default, and the master bus (`Session#master_gain`, `master_gain -6.db`, `render(gain:)`) is -10 dB by default, live and in renders, so mixes of full-scale parts have headroom; effect scripts set it to 0 dB, since they process recordings with their own levels.  Check levels by rendering.
- Oscillators and constants play forever (there is no `.for`/`.forever`); sounds end through envelopes (one-shots without gate or trigger; gated or triggered ones, as in voices and clips, never end by themselves), clips, files, `x.until(seconds)` or `x.until(2.bars)` (`GraphNode::TimeLimit`, a hard cut; musical lengths follow the tempo, counted from the node's first sample), `and_then`, or `MB::Sound.silence(s)` (zeros, then the end; e.g. tails via `and_then(silence(s))`).  `play` of a graph says to press Ctrl-C, `write` caps graphs at `MAX_RENDER_SECONDS`, and `fft`/`plot`/`write` given a bare Tone or Pitch take one second of it.
- `40.hz` is a Pitch that plays as a sine when used as a signal, not a constant; use `40.constant` for fixed values in arithmetic, and `pitch.transpose(n)` or `(f * 2).hz` to change frequencies (`440.hz * 2` doubles the sine's amplitude).
- `Numeric#samples` is a `Length::Samples` (it used to return seconds at 48 kHz), and `#delay`/`#multitap` have no `samples:`/`sample_rate:` options: write `delay(96.samples)` or `delay(lfo.samples)` (counted at the running rate).  A plain node or number is seconds; `smooth(0.1)` and `smooth(4800.samples)` replace `smooth(seconds:/samples:)`.
- Use the `a*` names (`aramp`, `aclip`, ...) or `.lfo` for control signals that must keep exact edges (delay times, gates, phases), and remember that `softclip`/`clip`/`abs`/`quantize` add half a sample of delay (null tests against older renders show a -20 to -30 dB residual; align by half a sample to compare).  An edge landing exactly on a sample is a classic rounding trap in these kernels (phases snap within 1e-9 of an edge).
- The container compiles with GCC, which never warns about unused `static inline` functions; the user's Mac uses clang, which does for functions defined in a `.c` file (not in headers), and `-Werror` makes that a build failure.  After C changes, check that every static function in a `.c` file is still called.
- `Numo::Pocketfft.rfft` (and `ifft` of a complex view) read an NArray view like `x[100..]` from its parent's start; `MB::Sound.fft`/`ifft`/`real_fft`/`real_ifft` copy their input, but `.dup` views before calling Pocketfft directly.
- `node.filter(cookbook_filter)` copies the filter's cutoff and quality into constant inputs (and, by default, into a new `Filter::SVF`), so changing the Cookbook's `center_frequency` from outside (e.g. a MIDI callback) does nothing; pass `cutoff:` a node and change the node.
- `multitap` and other multi-output results are `Channels` bundles, which are deliberately not Enumerable (`.to_a` for `shuffle`, `reverse`, etc.).
- C4 = 60 (C3 = 48).  Derive expected values in specs from note constants or a quick script; hand-computed notes and offsets caused several wrong assertions.
- A realtime Session's render thread runs until `close`; close sessions in spec `after` blocks.  `kill -QUIT <pid>` prints every thread's backtrace (`MB::U.sigquit_backtrace`, set up in spec_helper).
- Before adding `bin/sound.rb` commands, check for collisions with `MB::Sound` methods and Pry commands (`Pry::Commands`; e.g. `reset` and `watch` are taken).

### Process

- In multi-step shell scripts, use `set -euo pipefail`, don't pipe away exit codes, and put commands on separate lines (a failure inside `a && b` doesn't stop the script; a batch loop that kept going after a failure once produced broken commits).
- Use the Edit tool for multi-line code changes; ad hoc Python/sed replacements often failed on indentation or escaping.  Never `sed -i` the Rakefile: on the Mac's case-insensitive `/app` mount it once left a stale lowercase `rakefile` entry that rake loads first (`LoadError ... rakefile`; `rake -f Rakefile` works around it).
- Memcheck (selective by default for branches): run `rake -f Rakefile memcheck:changed` before merging branches that touch `ext/` or code calling extensions; it selects specs from `spec/valgrind/memcheck_map.json` (changed extension dirs, users of changed shared headers, `lib/` files naming a `Fast*` module, changed memcheck specs; the full list for suppressions, `gc_stress_calls.rb`, `mb_ext_helpers.h`, the Rakefile memcheck section, a new extension, or over half the extensions; rules in `spec/valgrind/memcheck_selection.rb`).  Selections range from under a minute (one small extension: fast_resonator's 2 spec files took 0.7 min in Valgrind, 2026-10-09) to most of the full run (fast_sound and fast_arithmetic reach 37 and 31 of the 58 spec files; `lib/mb/sound/tone.rb` names four extensions).  Run the full `rake memcheck` when `memcheck:changed`/`memcheck:status` says it is due (every 3 merges that changed `ext/` since the last full run, or 7 days; `FULL=auto` escalates) and at checkpoint merges; it records `tmp/memcheck_full.stamp` in the main checkout (until one exists the policy counts from `MemcheckSelection::FULL_BASELINE`, the 2026-10-09 feedback-loops tip; per the user, the first full run waits until the policy says it is due) and rerecords the map (commit `memcheck_map.json` afterwards). - Measure before explaining a failure; the first theory for the macOS latency problem was wrong, and a small experiment found the real cause.
- The user often says "note for later": record those in local memory (themed idea files), not GitHub, and implement them only after an explicit go-ahead.
- Preserve research side quests (prototypes, measurements, studies by research agents) before their worktree is removed; a gitignored `tmp/` is lost with it.
