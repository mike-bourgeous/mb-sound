# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

mb-sound is a Ruby library for sound processing with a fluent DSL for building signal processing chains. It is a companion to an educational YouTube video series about sound. It uses Numo::NArray (via the `numo-narray-alt` fork) for numeric operations and includes C extensions for performance-critical paths.

### Folders

- `bin/` - user-facing scripts and experiments (`bin/effects/`, `bin/synths/`, `bin/midi/`, `bin/songs/`, plus general utilities at the top level); all but `bin/sound.rb` use the script helpers (see Scripts below)
- `ext/` - C extensions for performance-critical functions
- `lib/` - Ruby code (most functionality lives here)
- `spec/` - Test suite

## Build & Development Commands

```bash
bundle install                    # Install dependencies
bundle exec rake compile          # Compile C extensions (required before running; in parallel, -j N)
bundle exec rspec                 # Run the test suite (without the :slow tier; SLOW=1 for everything)
bundle exec rake spec:parallel    # the suite in parallel processes (PARALLEL=N; default half the CPUs, capped at 1.5 GB of available memory each), then its slowest files and examples
bundle exec rake spec:full        # spec:parallel with the :slow tier (SLOW=1): the suite before and after merges
bundle exec rake spec:quick       # everyday subset: the 95% covering set (spec/quick_map.json) + specs of units changed since master-ai (QUICK_DRY=1; Mac PARALLEL=8: 60 s vs 184 s)
bundle exec rake spec:quick:map   # rerecord the covering set (the suite once with per-file coverage, +50% time)
bundle exec rspec spec/some_spec.rb        # Run a single test file
bundle exec rspec spec/some_spec.rb:42     # Run a specific test line
bundle exec rake                  # Default task (runs spec)
bin/sound.rb                      # Launch interactive Pry console with MB::Sound context
bundle exec rake memcheck         # all C extension specs under Valgrind (~30 min on 2026-10-10, up to 1.3 GB; manual: pre-release or leak hunts; options in Rakefile)
bundle exec rake memcheck:changed # only the memcheck specs for extensions changed since master-ai (MEMCHECK_DRY=1, FULL=1)
bundle exec rake memcheck:status  # last full memcheck (a record; full runs are manual) and whether the map knows ext/
bundle exec rake depend:check     # ext depend files against the headers the sources include
bundle exec rake plan:full        # plan specs over the full 21 block sizes (MB_SOUND_PLAN_FULL=1; ~35 s)
bundle exec rake plan:changed     # plan:full if the branch changed the plan layer by 50+ lines since master-ai (PLAN_DRY=1)
bundle exec rake golden:check     # sound guards: render the golden set, compare fingerprints (golden:check[techno], golden:approve[name] RUN=dir, golden:list)
```

Testing: run affected specs while working, and the full suite, slow tier included (`SLOW=1`, `rake spec:full`), before and after each merge (on the Linux runner, `/claude/test-runner/run_test.sh <id> <sha> suite smoke` (a branch, not a detached commit), 2026-10-18: suite ~1 min at PARALLEL=12, smoke ~0.8 min, one process ~10 min; `rake spec:parallel` at PARALLEL=4 ~2.5 min; the Mac container with its 31 GB VM, 2026-10-24, default run without the slow tier: 8.4 min at PARALLEL=2, 4.9 at 4, 3.4 at 6, 2.9 at 8 using 3.4 GB at most, the slow tier adding ~1.6 min of PARALLEL=2 wall); run specs on local disk only (a `/claude/worktrees/` worktree or the runner: over sshfs every Ruby start takes ~5 s and every file read crosses the network), or more often for good reason (a merge that changes only one `bin/` script and its spec needs only that script's specs; `.claude/collaboration.md`).  Changes that touch DSP, presets, or the plan layer also run `rake golden:check` (Sound guards below; failures go to the maintainer as a Bench set, never re-approved by an agent).  Save suite output to a file and grep it instead of rerunning.  Concurrent spec processes work (per-process temp dirs and coverage files).  `rake spec:parallel` (`spec/parallel_specs.rb`; `PARALLEL=N`, else half the CPUs capped by available memory at 1.5 GB a process (maintainer, 2026-10-25: 8 in the Mac container, 16 on the 7950X), also for `spec:quick`/`spec:full`/`spec:quick:map`; `SPECS=` for a subset) splits files by their last measured times (`tmp/spec_file_times.json`) and ends with the slowest files and examples, marking files over 8 s and examples over 2 s, since slow or leaky specs are better fixed than hidden (the maintainer's preference; parallelism came last in the 2026-10-10 spec speed project).

Spec conventions (`spec/support/`):
- Selection and promotion (test-tiers-1, maintainer 2026-10-25): `rake spec:quick` runs the cheapest spec files reaching 95% of the suite's lib/ branches (`spec/quick_map.json`, `rake spec:quick:map` after big changes; files newer than the map always run), `QuickSelection::ALWAYS` (whole-library guards and property sweeps: buffer-size invariance, take replays, graph sweep, relation fuzz), and the spec files of units changed since master-ai (mirror path, file-name prefix, top-level describe; `spec/quick_selection.rb`): the maintainer accepts that regression specs outside it run only when their unit changes, or at merges (the full suite).  So **a fix adds its case to a sweep**, besides its regression spec: a graph sweep factory (`spec/support/graph_sweep.rb`), a `plan_compare` case, a script smoke row, a recipe round trip, or a relation fuzz step (`spec/support/relation_fuzz.rb`: seeded random graphs checked planned == unplanned at `:exact`, `:fast` within -60 dB RMS, plan check mode, `to_ruby` and graph document round trips, buffer sizes within -80 dB; failures shrink to a minimal graph printed as Ruby; `FUZZ=N` long mode, `FUZZ_SEED=n` repro; `RelationFuzz::KNOWN` lists open bugs with reasons).
- Slow tier (test-tiers-1, 2026-10-24): plain `rspec` and `spec:parallel` skip what guards rare regressions (exactness at other buffer sizes, long song renders); `SLOW=1` (`rake spec:full`, the post-merge script, CI; always under memcheck) runs it.  Inside sweeps, `slow_tier(list, keep: 1)` keeps the first entries by default (`[[800], *slow_tier([[367, 368], [64]])]`; `expect_invariant` applies it to its sizes); whole examples are tagged `:slow` only when a cheaper example in their area stays (a `file:line` or `-e` filter still runs one).  New exactness sweeps over many sizes use `slow_tier`; never move a check of what the maintainer hears (same settings, same buffer size) into the tier.  SLOW runs keep their file times in `tmp/spec_file_times_full.json`.
- Temp files: `tmp_path('name.flac')` gives a path in an empty directory per example, inside a random per-process `Dir.mktmpdir` removed at exit (`KEEP_SPEC_TMP=1` keeps it); never write fixed names under `tmp/`.
- Coverage is opt-in: `SIMPLECOV=1 bundle exec rspec` (CI sets it) reports to `coverage/` (+~20% suite time, +~30% smoke); bin/ scripts run by specs get `spec/subprocess_coverage_helper.rb` (via RUBYOPT), merged into the report after the suite.  If script specs are slow, check `coverage/.resultset.json` isn't huge; `rm -rf coverage` is safe.
- `fork_script(script, *args)` runs a bin/ script in a fork of the spec process (skips ~0.7 s of startup); a spec using it must also run its script once as a real process doing real work, so load-order problems still show.
- Before each example spec_helper calls `MB::Sound.close_outputs` and closes the default Session if a `play`/`bg` left its render thread running or it holds set state (tracks, scenes, players, names, scheduled blocks; `spec/support/session_guard.rb` fails the example that left it, `MB_SOUND_SESSION_CHECK=report|off`; close it in an `after` block, omnibus12), so cached outputs, NullOutput pacing, and a running Session (which pumps live MIDI instead of the graph reading it) don't leak between examples.  Specs that run a Session on the shared transport must `MB::Sound.rewind` afterwards.
- Sessions in specs (gc-leak-1, maintainer 2026-10-17): `Session.new(realtime: false)` + `#process_buffer` unless a render thread is under test; realtime cases use `NullOutput.new(..., sleep: :virtual)` (a virtual clock: `#write` blocks `ahead:` frames past what the waiter `#consume`s; `play`/`wait`/take replays consume through `Internal.wait_audio`), never `sleep: false` (a render thread spins, once 22 GB) and wall-clock pacing (the default `sleep: true`) only where wall-clock timing is what's tested.  Unpaced NullOutputs may render 60 s of audio per example (`spec/support/render_budget.rb`; `render_budget: { seconds:, reason: }` for longer renders, `MB_SOUND_RENDER_BUDGET=report` lists instead); `rake spec:parallel` lists examples growing RSS over 200 MB.
- For limits like `Session::MAX_TAIL_SECONDS`, `stub_const` the constant where it's defined (`Session::Master::MAX_TAIL_SECONDS`) instead of rendering 10 s of tail.
- No reruns (maintainer, 2026-10-15): investigate every spec failure right away (read it, reproduce or measure, then fix the cause, flake or bug, or record it with its failure text for a fix round); never rerun to see whether it passes.  Known load-sensitive examples, as context for that investigation: realtime timing examples can fail under heavy load (concurrent renders, other suites) or Valgrind, such as `spec/lib/mb/sound/device_output_spec.rb:244` and `live_source_spec.rb`'s JACK "frame plus the latency" example under `rake memcheck` (first note one 256-sample period early).  Under memcheck, Valgrind errors (not timing failures) are what count, but a timing failure still gets recorded for a fix.  A rare `fork_script` hang (first seen in `spec/bin/graph_profile_spec.rb`'s plans-off-and-on example) stays as is by the maintainer's choice (2026-10-15): forked scripts time out after `ForkScript::TIMEOUT` (300 s, `MB_SOUND_FORK_TIMEOUT`) and print diagnostics; keep the failure text if it happens.
- Warnings fail specs (`spec/support/warning_guard.rb`, 2026-10-14): any Ruby warning reaching the real stderr fails its example (the run, if outside examples), including Ruby subprocesses and `fork_script` children (via RUBYOPT `spec/subprocess_warning_helper.rb`) and the `:deprecated` category.  Expect deliberate ones with `expect { }.to output(/.../).to_stderr` (`to_stderr_from_any_process`), or for scripts check the output and call `expect_script_warnings(/.../)`; never allowlist our own (`WarningGuard::ALLOWED` is for gems, with reasons).  `:performance` warnings fail too (since warnings-2, 2026-10-15; never printed, recorded even under output matchers; `MB_SOUND_WARNINGS_PERFORMANCE=report` lists them after the run instead): a class "reached 8 shape variations" when its instances set instance variables in varying orders, so set every one in the constructor (nil until used), and declare a GraphNode module's lazily set ones with `GraphNode::IvarPreset.declare` (preset before every node class's constructor).  `rake spec:parallel` prints "Stray warnings" with the examples that printed each.  Once-per-process notices go off per example in spec_helper (`Plan.fold_warnings`).
- Spec speed (test-speed-2/3, 2026-10-18): `spec/time_budgets.yml` caps each file (20 s) and example (8 s) in `rake spec:parallel` (entries with reasons for more; in the runner's seconds, scaled per machine and PARALLEL by `spec/host_speed_bench.rb`, measured on the first run into `tmp/spec_host_speed.json`, `MB_SOUND_SPEC_CALIBRATE=1` again; the Mac i9 at PARALLEL=2 is x2.0); join buffers with `SpecBuffers.join` (`spec_hygiene_spec.rb`); wait for conditions (`wait_until`, `wait_mode`/`wait_settled`, sync marks, `Tiles#refresh` for a drawn frame), never fixed sleeps or quiet periods; one-sample buffers only over the edges they prove (shorter inputs, a shorter `stop:`); a slow spec is often a slow library path (a table file read per synth lane, a `stop` waiting out a thread's IO timeout, tables built for a whole 30 s file): fix those first.
- Short inputs: `spec/test_data/arp_a7.flac` is a 0.4 s stereo Am7/Amaj7 triangle arp (made by `spec/test_data/make_arp_a7.rb`) for effect and script specs; test MIDI files start within 0.2 s.

The bin/ script smoke tests (`spec/bin/script_smoke_spec.rb`, tagged `:smoke`, about 1.5 minutes; plain `rspec` skips them, CI runs them as a separate job) run every script with `--help` (in forks for scripts that also render) and a short render (real processes), with shared-buffer checks raising (see Core Abstraction).  Run them with `bundle exec rspec --tag smoke` before merging changes to bin/ scripts, the script runner, or nodes that touch input buffers, and add new scripts to their tables.

System dependencies (apt): `ffmpeg libsamplerate0-dev libasound2-dev libjack-jackd2-dev jackd2 graphviz` (ALSA headers build RtMidi's ALSA sequencer backend; the shared JACK client loads libjack at run time, so `libjack-jackd2-dev` only builds RtMidi's JACK API, which specs use as an outside JACK client; `jackd2` runs a dummy JACK server for the JACK specs, which skip without it).  In the container, the Dockerfile sets `OUTPUT_TYPE=null` so playback uses `NullOutput`.

## Architecture

Each subsystem below is a summary; the full notes (design decisions with dates, measurements, research, render locations) are in `design/notes/<topic>.md`.  Read the topic's note before changing a subsystem, and update both when behavior changes.

### Core Abstraction: GraphNode DSL (`design/notes/graph_nodes.md`)

`GraphNode` (`lib/mb/sound/graph_node.rb`) is mixed into any class with `#sample`, giving fluent chaining:

```ruby
play 123.hz.triangle.at(-20.db)   # oscillators play until Ctrl-C
play 123.hz.fm(369.hz.at(1000)).softclip.filter(150.hz.highpass(quality: 4))
```

DSL methods live in topic modules `lib/mb/sound/graph_node/*_methods.rb`; node types in `lib/mb/sound/graph_node/`, MIDI nodes in `lib/mb/sound/notes/`; traversal via `Traversable`.
- `node.at(x)` scales any node like Tone#at: numbers and nodes multiply, `a..b` maps -1..1 onto the range (Tones keep their own #at, applied inside the oscillator; a node becomes the tone's #gain, merged with a numeric gain; a node gain already set is a live_error plus a Multiplier).
- Node classes keep internals in instance variables or non-DSL names: a public or private method named like a DSL method must call super or be listed in `dsl_shadowing_spec.rb`'s ALLOWED (renamed 2026-10-13: `FourPole#kernel_filter`, `Tone#pwm_width`/`#soft_sync?`, `Tee::Branch#owner_tee`, `SQ80::TimeScale#time_seconds`).
- Every consumer must call `get_sampler` on nodes it stores in its constructor, so a node used in several places branches through a `Tee` instead of advancing twice.
- Tee branches reading in lockstep share one frozen buffer; otherwise the Tee copies through a CircularBuffer (made lazily).  A node processing its input in place copies it first only if `buf.frozen?` (user rule; `GraphNode::FrozenCopy`).  `MB_SOUND_CHECK_SHARED=1` / the `:check_shared` tag verify shared buffers aren't modified (multi-output nodes, Synth and ChannelMixer, alternate two sets of output buffers so a channel's buffer outlives the next frame); `MB_SOUND_SHARED_TEE=0` turns sharing off.
- `oversample(m)` raises upstream rates when the graph first plays or is planned; nodes also read outside the region keep their rate and the region's Tee branch resamples them (`Branch#resampled?`, `Tee.pin_rates`), so shared nodes are never read at two rates.
- Sums ring until all of their inputs have ended (since omnibus8: gong tails, dry + reverb; an ended input drops out, fused by the plan layer); `(a + b).ring(:first)` (also `Mixer.with_ring(:first) { }`, `Session#ring`, `render(ring: :first)`) ends a sum with its first input, the old default (`drone + hit` ended with the hit).  Products still end with their first input (`osc * env` ends with the envelope).
- Multiplier, Mixer, and Pan have allocation-free C fast paths (`fast_arithmetic`), bit-identical to the general path.
- Measure graph cost with `bin/graph_profile.rb [-n 32,128,800] [--profile] [--plan on|off|ruby|both] script.rb` (worst-case synth input: `spec/test_data/dense_modulated.mid`); compare branches in alternating runs against a master-ai worktree.

### Graph I/O: recipes, Ruby export, and graph documents (`design/notes/graph_io.md`)

Every graph remembers the DSL calls that built it (`GraphNode::Recipe`, `lib/mb/sound/graph_node/recipe.rb`, `recipe/`), so it prints itself back as Ruby: `node.to_ruby(inputs: { midi: notes }, seeds: true)` (seeds off by default; also bundles, Synths, Notes, clips), console `ruby node`; variables take block locals, `.named` names, or roles (`voice`, `osc`, `env`, `fx`, `sig`, `out`).  Per-copy randomness derives from one seed per parent (synth lanes, unison copies, chorus hiss, tr808 voices via `MB::Sound.with_seed`), so a single `seed:` rebuilds it.
- Recording is always on (`MB_SOUND_RECIPES=0` off): generated recorders prepended to the DSL surface (`Recipe::Surface`; a guard spec requires every public DSL method recorded or listed in `Surface::EXEMPT`/`Recipe::EXEMPT` with a reason) record outermost calls only; build blocks (`BUILD_BLOCKS`: synth lanes, feedback, delay inserts, unison/swarm, oversample, map_notes, bands, fill, sampler, rack constructors) record their invocations and locals; runtime blocks print as Prism source; seeds drawn are kept.  New DSL methods in `*Methods` modules or the surface classes are picked up automatically; a new method that takes a build block goes in `BUILD_BLOCKS`.
- The writer prints chains, shared variables, units, `per_voice(...)` for lanes that differ in values, and `nil # FIXME(graph-io): ...` for anything unrepresentable; no flow control.  Round trips (counted from the specs' exception lists, 2026-10-17): 210/220 graph sweep factories and 31/34 bin synth/effect scripts render bit-identically (wavetable_bass.rb also as a bundle) (`recipe_spec.rb`, `spec/bin/recipe_script_sweep_spec.rb` under `--tag smoke`).
- Graph documents (`.mbg.rb`, `lib/mb/sound/graph_io.rb` + `graph_io/`): to_ruby's text after a header (`graph 3, name:, kind:, saved:, mb_sound:, from:, description:, options:`, `inputs :midi`, `param :drive, 1.0, range:, description:, cc:`, `knob :cut, 800.0, range:, curve:, cc:` for GraphNode::Knobs, saved at their current value), loaded by walking the Prism tree (`GraphIO::Loader`; never eval/instance_eval/Marshal/YAML): calls only through `GraphIO::Registry` (the recorded surface plus value methods) with `public_send`, constants from a closed table, no flow control/def/class/globals/ivars/send/const_get (`GraphIO::LoadError` with file:line and did_you_mean), resource limits (`GraphIO::LIMITS`), file reads only relative to the document (`GraphIO::FileGuard`: strings from document text are marked, and the lowest readers, `Wavetable.from_file`, `FFMPEGInput`, `MIDI::MIDIFile`, refuse absolute paths, `..`, and links out of the directory, whatever DSL method passed them).  Runtime blocks load in a safe subset (arithmetic/math on their own parameters), else `&named_proc(:x)` (`MB::Sound.named_proc`), else `trust: :code` (`TrustedCode`, the one eval).
- API: `GraphIO.load(path_or_text, inputs:, params:, trust:)`, `.parse` (header), `.dump(graph, name:, inputs:, params:, options:)`, `.save`, `.document_of(graph)` (`doc[:drive] = 2` sets every knob Constant); console `save :dark_hall, g`, `preset :dark_hall, input: mic, mix: 0.6`, `presets`; documents' `knob`s join the Session that plays them (or `preset` loads them into; same name and range: one shared knob, which a `preset` override turns; `cc:` knobs listen to MIDI; collisions via `live_error`).  Param overrides may also be a graph node or a Session knob's name (`preset :dnb_reese, midi: riff, cutoff: :cut`): every use reads it, never from document text (knob names resolve only through `Session#knobs`).  Presets go to `$MB_SOUND_PRESETS`, else a project's `presets/` (nearest Gemfile naming mb-sound), else the user data dir; loading also searches mb-sound's own `presets/` last (the persona panel's patches, saved by `bin/save_presets.rb`; `--check` after library changes).  Script `--save NAME` saves a script's graph with its numeric parameters as params (knobs where the graph uses a Constant named after one; the rest baked into `options:`).  Each use of a param is its own Constant (a node shared into an oversample region reads at two rates).  When adding a DSL method that reads files or allocates by an argument, add it to `Registry::FILE_METHODS` or `Loader#check_limits` (a new low-level file reader needs a FileGuard hook).
- Phase 3 (`graph-io-3`): clips save as recipes (note marks `!A1`/`~C2`/`.chance`, kits, `|`/`&`, MIDI transform chains) or, without a recipe (captured, `Clip.new`, seed-drawing bakes), as `events([start, length, value, velocity, { marks }], ..., length:, loop:)` rows in exact Rationals; graphs that read files save as bundles `name.mbg/` (`name.mbg.rb` + `assets/`, `asset "assets/x.flac", sha256:` lines checked on read; `GraphIO::Assets`; `save(..., bundle: true/false)`); `save :gig, set` writes a `kind: :set` document (tempo, knobs, master, buses (`bus(:hall, to:) { |sig| ... }`), tracks with `to:`/`send:` routes (held gains or followed knob names) and patch blocks built once to print them, clips, scenes, mute groups, sections, flow; `GraphIO::SetWriter`) and `preset :gig` loads it into the current Session (`doc.form` to play; `seeds: :fresh` redraws the seeds the save drew, printed `seed: drawn_seed(N)` since format 2, and keeps seeds the code gave; format 1 documents redraw every seed; format 3 reads bare dynamics levels and gains as linear gains, older documents as dB).  Scene blocks save as source when they hold only `Loader::SCENE_COMMANDS` (`{ meter 2, 4 }`, `bg`, `turn`, mutes), else `live_error`.  Patches print through `Recipe.wrap_block` (no TracePoint, which would make YJIT drop its code).

### Sound guards (`design/notes/sound_guards.md`)

"Ears win" (maintainer, 2026-10-22): sound is the test, exactness only where it is heard or a workflow needs it (same settings reproduce seeds/takes/variants exactly; buffer sizes within -80 dB where cheap).  The golden set (`golden/set.rb`: song scripts with options and presets on phrases across his genres; no SQ-80 while banned) is re-rendered by `rake golden:check` and compared by perceptual fingerprints (`MB::Sound::SoundGuard`, `lib/mb/sound/sound_guard/`: loudness curve, mel spectrum, envelope, onsets, stereo width; committed in `golden/fingerprints/`) against thresholds calibrated on inaudible and audible changes (`golden/calibration/`); approved renders live in the main checkout's `tmp/golden/approved/` (`MB_SOUND_GOLDEN_DIR`), never in git.  A failing piece gets a Bench set (approved vs new) in its run directory; `rake golden:approve[name] RUN=dir` re-approves after the maintainer's verdict.

### Plan layer (`design/notes/plan_layer.md`)

`lib/mb/sound/plan.rb` + `plan/` (executor `ext/mb/sound/fast_plan`) runs connected regions of a graph as one op list per block in C, an as-if transformation: same samples (bit-exact except the default `:fast` sines and 2^x, within -124 dB), the user's graph untouched, node state kept in the nodes so a plan can drop at any block boundary.
- Installed automatically by `Synth` (per lane) and `Session#add`.  `MB_SOUND_PLAN=0` off, `=ruby` the Ruby mirror; `MB_SOUND_PLAN_CHECK=1` runs every block planned and unfused and compares samples and states.  `MB_SOUND_PLAN_PRECISION=exact` / `Plan.precision = :exact` for bit-exact programs (wiring specs and Tone null-test references set it).
- Node protocol (`Plan::Describable`): `plan_describe(p)` returns the node's output Value built with `Plan::Builder` (`p[handle]`, `p.const`, Value operators, `p.tone`, `p.param`, `p.boundary`), plus `plan_inputs`, `plan_unsupported_reason`, `plan_snapshot`/`plan_restore`.  Ops are `Plan::Op::*` objects with a `#run_ruby` mirror; `Plan::Program` allocates registers and lowers to Int32 words.
- Covered: constants and arithmetic, shapers, Tones (naive and PolyBLEP kernels with FM/PM/width/gain/resets), Notes event nodes and envelopes (event feeds recorded in Ruby, rendered in C), filters (SVF, biquad, four-pole, diode), SQ80 time scaling, cycle-mode wavetable tones and KeyMaps, SampleHold, TempoNode values, `UnaryFunction`s (MathFunction, ComplexNode), one-channel companders (compress/expand/gate/duck/compand; `Op::Dynamics`), ChannelMixers with real number gains (unison, numeric pan/balance/width/mid-side/swap/mono/matrix; `Plan::MultiDescribable`: the mixer roots a region computing every output, `Op::Mix` rows + `Op::Output` copies, so unison oscillators fuse with their pitch), moving pans/balances/unison spreads (`Op::PanGain`, plan-fusion-2; a moving unison mix and complex gains stay boundaries), decimators (`Op::Decimate`, kernel shared through `mb_decimate.h`).  Spied nodes stay fused (`Op::Tap` hands their spies each block; `Plan.observe` still unfuses).  Lane groups treat `x` and `x * c` as one shape (`Plan::ScaleMatch` pads `x * 1`).  Boundaries for now: limiters and crossover bands, multichannel dynamics, curve shapers, delays, synced tones, ports, timelines, BLIT, clean resets, sample-mode/complex wavetables, sampler voices/grains/loop players, reverb, chorus, resonators, dust/drift, formant, drum voices' triggers, sleeping synth sub-lanes (feedback loops run per sample in `fast_loop`).
- Lane groups (`Plan::LaneGroup`): regions with the same lowered words (`Program#signature`) run in one `FastPlan.run_lanes` call, with lane-major SVF/four-pole/diode/biquad recursions; a Synth groups across its lanes (only when no lane may be skipped while idle; lanes whose nodes plans could all fuse are never skipped, planned or not, `Synth#lane_fusable?`, so plans never change skipping and its samples; grouped lanes are computed every buffer, user decision 2026-10-10), `Plan.install` groups an installation's same-shape output regions; members alternate two output buffers (`Region#swap_out!`).  `MB_SOUND_PLAN_LANES=0` off.
- `0 * x` folds to 0 for constants of the patch (x's ops still run; warned once per kind).  `Plan.changed(node)` after structural edits; `Plan.explain(graph)` lists regions and why nodes stay unfused.  Plans have no steady-input shortcuts (predictable cost).
- Specs: `spec/lib/mb/sound/plan/` (`plan_compare` runs unplanned, C, and mirror over block sizes 1, 7, 128, 800, and one random size from RSpec's seed, repeated to reach every event; `rake plan:full` runs the 21-size sweep, for branches that substantially change `lib/mb/sound/plan*`, `ext/mb/sound/fast_plan`, or `fast_loop`: `rake plan:changed` decides, user decision 2026-10-10), `spec/ext/mb/sound/fast_plan_spec.rb`.  Unfused-block counts survive rebuilds (carried to the region on the same root); an ending envelope/four-pole parameter input runs 2 blocks unfused by design (1 on a block edge), a feeder's end 1; specs assert these exactly (`Result#unfused_blocks`).

### Feedback loops (`design/notes/feedback_loops.md`)

`sig.feedback { |fb, input| input + fb.delay(5.ms) * 0.8 }` (alias `fb`; `GraphNode::FeedbackLoop`) runs the loop's nodes one sample at a time as ops in C (`fast_loop`, exact Ruby mirror; same output at any block size); everything outside the loop runs per block.  `sig.delay(t, feedback: g) { |fb| insert }` is the tape-echo form; insert pipelines `{ |d| d.fb { ... }; d.wet { ... } }` process only the recirculated or only the output signal.
- Loop ops: arithmetic, shapers, delays (`fb.delay(t)`, no `feedback:` of their own inside a loop), SVF filters.  Not yet: oscillators, envelopes, four-pole/biquad, multitap, loop taps.  Other nodes on the loop go through `MB::Sound.live_error` (raise in scripts/specs; in live mode, block-delayed fallback).
- Latency compensation (default `compensate: true` = `:pitch`): the longest delay reads earlier by the rest of the loop's phase delay at the fundamental, so periods and echo times are exact; `:dc` is the older group-delay mode, `false` off.
- Sustain (default on for loops with gentle lowpass SVFs): a hidden high shelf keeps the loop gain at the pitch as if the filters were wires; `#delay` echo loops pass `sustain: false`.
- Karplus-Strong: write one period of noise into the delay line, output after damping (the snippet is in the note).  Demos: `pluck.rb`, `bin/effects/tape_delay.rb`, `bin/effects/flanger.rb`, `bin/songs/feedback_song.rb`.

### Numbers, lengths, intervals, phases (`design/notes/numbers_lengths_phases.md`)

`lib/mb/sound/numeric_sound_mixins.rb` adds `.hz`, `.db`, `.meters`, `.bits` to Numeric; `-6.db` is a `Decibels` (`lib/mb/sound/decibels.rb`: acts as the Float gain, keeps its dB, prints as `-6.db`); every dB-valued argument (dynamics, drum `accent:`, reverb `duck:`, chorus `hiss:`, filter gains, ...) reads it exactly and bare numbers as linear gains, bare negatives raising (live mode: read as dB with a warning); curve shapes and `db_gain:` keep bare dB (`Decibels.gain_of`/`.db_of`; the list is in the note).  `440.hz` is a `Pitch` (oscillator methods make a new `Tone` each call; plays as a sine when used as a signal); `Note < Pitch` (C4 = 60) follows the session `Tuning` (`tuning b4: 480`).
- `Tone` (`lib/mb/sound/tone.rb`) is the one oscillator node; DSL methods configure it before it plays (afterwards `FrozenError`, or a warning in live mode); per-sample state is one `Tone::State`.
- Phases are in cycles everywhere (0.25 = 90°): `with_phase`, `pm` index, `fm_feedback`, `reset(to:)`, unison `phase:`.  `MB::Sound::Phase`: `0.25.cycles`, `1.5.radians`, `90.degrees` (overrides mb-math's `Numeric#degrees` for reals; write `30.degrees.to_f` for radians), `node.radians`.
- Lengths: `2.bars`, `3.beats`, `3.n16`, `1.n8.dotted` (`Sequence::Duration`), `4.seconds`, `250.ms`, `5.samples` (`MB::Sound::Length`), `0.5.attack` (a track `lead:` in attack times); every length-taking method accepts them plus plain numbers in its usual unit (seconds for delays/envelopes, bars for fades/schedules, samples for `with_buffer`); `pitch.period` is a `Length::Seconds`.
- `138.75.bpm` is a `MB::Sound::Tempo` (clocks).  Type-dispatched parameters: `MB::Sound::ArgTypes` (`design/notes/arg_types.md`) classifies values (tempo, ratio, seconds, frequency incl. tagged `v.freq`, name, ...), with Signatures (keyword > type > position; canonical forms print keywords) and per-receiver Dispatch tables (errors and `help :at`/`:over` from them, a guard spec over every row); the toolkit methods will adopt it.
- `MB::Sound::Interval` (`4.octaves`, `7.semitones`, `50.cents`; plain numbers are semitones for `transpose`, octaves for `up`/`dn`/`oct`) and `MB::Sound::Scale` (`scale(:minor, :a)`; degrees to Notes; `Scale::CHROMATIC` is every transform's default, so `pitch:` is always in scale degrees).

### Params (`design/notes/params.md`)

`MB::Sound::Param` (`lib/mb/sound/param.rb`, param-1) is the one frozen declaration record: Knob specs, `MIDI::ControlSpec`, script options, graph-document `param`/`knob` lines, rack knobs, ChannelMixer's `param` DSL, and ArgTypes signatures (`ArgTypes::Param` is it) build and carry one.  Types and units come from the values (`2400.hz`, `-12.db`; `type:` types plain numbers, `unit:` only for plain numbers); Integer range + Integer default = stepped, Array = choices; curves `:linear`/`:exp`/`:switch` (aliases `:exponential`, `:log`, `:db`, `:enum`), defaulting by type (exp for frequencies and times, dB-linear for Decibels).  Names imply ranges (`Param.names`: cutoff, mix, pan, voices, attack, ...) when the default has the entry's type; explicit ranges win.  Ranged defaults: `(lo..hi).at(default)` (canonical, printed) or `default.in(lo..hi)`.  Checks at declaration (`Param::Error` with did-you-mean), load, build, and `turn` (`#check` through `live_error`: raise in scripts, limit live), never per sample; `clamp: false` lets a param or knob leave its range.  Graph documents (format 5) write params and knobs in that spelling, typed (`knob :cut, (150.hz..8000.hz).at(2400.hz)`).  Write continuous ranges as Floats or unit values; Integer ranges are steps.  A guard spec (`param_guard_spec.rb`, `spec/bin/param_declarations_spec.rb`) checks every declaration in lib/, presets/, and bin/ (script options and literal `knob` calls) builds a help line, a knob, and a document line.

### Oscillators and antialiasing (`design/notes/oscillators.md`)

Tone waveforms are antialiased by default (`lib/mb/sound/band_limit.rb`, `fast_synth`); each shape has a naive `a*` twin (`asaw`, `asquare`, ...) for lo-fi and control signals; `.lfo` fades band-limiting in from 15-30 Hz.  Measure with `bin/aliasing.rb 'p.saw' 'p.asaw'`.
- `ramp`/`saw`, `square`, `triangle`: PolyBLEP/PolyBLAMP.  `pwm(w, pivot:)` (alias `skew`) warps any shape around a per-shape pivot (triangle 0.75: `triangle.skew(w)` is a true skewed triangle rising for `w`; `pivot: 0` the old lobe warp).  `complex_*`: closed-form band-limited impulse trains (wavetables with PM/pwm/sync).
- `sync(ratio:)` / `sync(master)` / `softsync`: causal minBLEP kernel, exact naive waveform through a minimum-phase filter (~2.78 samples delay).  `fm_feedback(amount, gain:)` (aliases `fmfb`, `fm_fb`): DX7-style operator self-feedback in cycles, sines only.  `tone.gain(g)` multiplies inside the Tone.
- Phase jumps (resets, timeline jumps) are band-limited steps; `clean` (opt-in, ~2x CPU) makes jumps hard-sync events.  `tone.reset(trig, to:)` jumps at nonzero trigger samples; `.free` never resets; `.rnd` random phases.  Randomness from `MB::Sound.seed(n)`/`next_seed` (restored before every spec); noise has its own splitmix64 state per tone.  Tones with a frequency signal keep a running phase wrapped every sample (`mb_phase.h`, mirror `Tone.wrap_phase`), and constant frequencies count from an 800-sample grid of the tone's own time (`mb_grid_phase`), so both give the same samples at any block size.
- `softclip`, `clip`, `abs`, `quantize` use ADAA plus a half-sample allpass (half a sample of delay); `asoftclip` etc. are exact.  Ports (`tone.wraps`, `.increment`, TempoNode `jumps`): every reader must read each buffer.
- `sig.decimate(rate, jitter:, interpolation: :hold | :linear)` (`crush_rate`, `srr`; `GraphNode::Decimator`, `fast_lofi`): sample-rate reduction aliasing on purpose, the rate a number or a per-sample node (key-track with `v.freq * n`); vocal-lead demo `bin/synths/vocal_lead.rb` / `bin/songs/vocal_lead_song.rb` (formants + resonant filter + key-tracked crusher, ghost chords).
- Wavetables (`lib/mb/sound/wavetable.rb`, `fast_wavetable`): `Wavetable` cycle tables and samples, mipmapped (`:half_octave` default), `440.hz.wavetable(t, scan:)` with FM/PM/pwm/sync/resets, `wavetable_of(:sine, [1, 0.5], ->(p) { ... }, t)` scan tables from mixed frames (`Wavetable.of`; prints and saves as the call; `help :wavetables`), `KeyMap` zones, `phase_table`, `waveshape`, `Pitch#harmonics` additive.  Demo `bin/songs/wavetable_song.rb`.
- Unison (`lib/mb/sound/unison.rb`): `pitch.unison(n, detune:, spread:, mix:) { |p, i| p.saw }`, also `pitch.unison(n).saw` (a pending unison whose oscillator methods chain) and `pitch.saw.unison(n)` (`Tone#unison` from the tone's recipe), bit for bit the same; `pitch.swarm(...)` per-copy glides.  Demos `bin/songs/unison_song.rb`, `swarm_song.rb`.  Still aliasing: FM/PM sidebands (use `oversample`), `gauss`, naive shapes.

### Envelopes (`design/notes/envelopes.md`)

`MB::Sound::Envelope` (`fast_envelope`, mirror `Envelope.process_ruby`) is a state machine over curved segments landing exactly on target at whole samples.  Curves are signed dB (bare numbers, or Decibels read as their dB: `curve: 60.db`) (+60 falls like a 60 dB exponential, 0 linear, negative swells; presets `:analog` default, `:linear`, `:snappy`, `:gentle`, `:swell`, `:dx`, `:smooth`, `:pad`); shapes `:exp` or `:s`.  Multi-segment `env([[level, time, curve, shape], ...], release_at:, loop:)`; SQ-80 panel units via `sq80_env`.
- Times/levels/curves take numbers, Lengths, or nodes; inputs `gate:`, `trigger:`, `velocity:` (+ `sensitivity:`), `choke:`, `lift:`; `retrigger: :add` attacks to the energy sum.  Without a gate, notes release after `hold:`; without gate or trigger it's a one-shot.  `hold_last: true` holds the last level after the envelope ends (pitch dives) instead of 0; `.sensitivity(range | nil)` / `.no_velocity` change or clear velocity scaling in a chain.
- Constructors: `adsr`, `env`, `amp_env`, `fm_env`, `filter_env`/`filt_env`.  Kernel "runs" specialize only on constants of the patch (user rule).  `GraphNode#db` is gone: write `10 ** (node / 20)`.  Plot with `bin/plot_envelope.rb`.

### Filters (`design/notes/filters.md`)

`lib/mb/sound/filter/` has 16+ filter types (`#process`/`#reset`); `Filter::Cookbook` has standard designs.
- Graph cookbook filters (`node.filter(:lowpass, cutoff:, quality:, gain:)`, `filter(150.hz.highpass(quality: 4))`, `peq`) build `Filter::SVF` (user decision): cookbook responses, parameters may move every sample without DC bumps.  `structure: :biquad` builds the old Cookbook biquad.
- `sig.lp4(cutoff, resonance:)` (`four_pole`): CEM3379-style 4-pole, `tuning: :musical` by default (-6 dB at the cutoff without resonance, the resonant peak on the cutoff once 6 dB tall, every tap and the diode alike; `:hardware` the old mapping; `FourPole::Tuning`, generated tables), `:db` resonance curve, no self-oscillation unless `self_oscillate: true`, `drive:`/`drive_mode:`, `mode:` taps, `quality:`; `v.reso(...)` in voices.
- Musical vs hardware (maintainer convention, 2026-10-17): wherever mb-sound departs from the hardware or design that inspired it, the playable version is `:musical` (default) and the faithful one `:hardware` (opt-in); first use lp4/diode `tuning:`.
- `sig.diode(cutoff, resonance:)`: TB-303-style diode ladder with lp4's knobs and cutoff meaning, `normalize: true` (default) matches lp4's levels (and, with `tuning: :hardware`, its cutoff).
- SVF, four-pole, diode ladder, and formant states (and loop SVFs) flush below 1e-30 on an 800-sample grid of the filter's own time (`MB_FLUSH_GRID` in `mb_svf.h`, `Filter::SVF::FLUSH_GRID`; the count is kept after the states), so tails are the same at any buffer size.
- `sig.formant(:a, :o, morph:, voice:, shift:, width:)` (alias `vowel`; `GraphNode::Formant`, kernel `FastFilter.formant`): five parallel SVF bandpasses from the Csound formant tables, morphable and key-trackable, level-normalized.

### Dynamics (`design/notes/dynamics.md`)

One compander core (`GraphNode::Dynamics`, `fast_dynamics`, exact mirrors): a peak/RMS detector in dB (linked across channels by default; `sidechain:` any node or bundle), a transfer curve (`Dynamics::Transfer`: soft-knee corners, points joined linearly or by monotone cubics, Curve-shaped segments, blocks), a log-domain gain smoother (attack/release/hold, `upward_attack:` for boosts; times take Lengths, Durations, nodes), `lookahead:`, `makeup:` (dB or `:auto`), `mix:` (parallel); same output at any buffer size.
- Faces: `compress` (+ `upward_threshold:`/`upward_ratio:`), `expand`, `noise_gate`, `duck(kick)` (defaults -18 dB, 20 ms hold, 1/16 release; `amount: -12.db` or `12.db` both duck by 12 dB, never boosting: the maintainer's deep pump), `compand(-60.db => -80.db, -40.db => -40.db, 0.db => -12.db, interpolation: :cubic)` (or `[[in, out, shape], ...]`, or a block mapping dB numbers).  One rule for levels, gains (`makeup`, `min_gain`/`max_gain`, squeeze `gain`), and compand points: write `-12.db` (`MB::Sound::Decibels`, a gain that remembers its dB; read exactly as dB); bare numbers are linear gains (`makeup: 2` is +6 dB), negatives raise (live mode reads them as dB with a warning) and meaningless zeros go through `live_error` (db-1, 2026-10-14; graph documents before format 3 load with the old dB meaning and a warning).
- `limit(ceiling: -1.db, lookahead: 1.5.ms, release:, true_peak: true)`: lookahead brickwall, Annex 2 true peaks; latency lookahead + 6 samples; master-chain ready (`master { |mix| mix.limit }`).
- Trigger tracks (duck-keys, 2026-10-18): `sidechain :pump, grid(16, 'x...x...').loop` (aliases `pump`, `trigger_track`, `trigger_line`; `key` is the session key) is a track heard only by readers (`duck(:pump)`, `bus(:pump)`, `compress(sidechain: :pump)`): a trigger route (`Session::Buses#route(name, trigger: true)`, `track(..., trigger: true)`) never reaches the mix, buses, sends, stems, CUE, or meters, and works with scenes, `launch`, `swap`, undo, takes, and set documents (`sidechain(:pump) { |clip| ... }`); `shape: :gate` (default; one-sample impulses barely move a 1 ms attack), `:impulse` (with `attack: 0`), `env(0, 0.08)`, or a patch block (closed hats through `tr808`, unheard); `sidechains` lists them; `turn :"pump/level", 0` (its level knob, scenes `"pump/level": 0`) or `stop :pump` turns a pump off (mute doesn't: readers hear sources before their mute).  Kits: `voice :trigger, silent: true` plays for `duck(:drums, only: :trigger)` but is never mixed.  Templates: `sidechain :pump, clip` (dnb's `genre(:dnb) { sidechain :pump, :pump }` option).
- `bands(200.hz, 2000) { |lo, mid, hi| [...] }` (LR2/4/8 crossovers summing to an allpass; any node per band; bundles for stereo), `mono_below(120)` (lows averaged to one channel through `bands`; an option for club/vinyl masters) and `squeeze` (three-band upward + downward, `:default` gentle, `:eleven` extreme; not called ott: trademark).  ~0.2% of realtime per stereo 800-sample buffer for a compressor, 0.4% limiter, 0.7% squeeze.

### Sampler (`design/notes/sampler.md`)

`MB::Sound::Sample` (`lib/mb/sound/sample.rb`, `sample/`) is an immutable sound in memory (one SFloat per channel, root note, loop points and mode `:one_shot`/`:no_loop`/`:forward`/`:ping_pong`/`:release`, a region of the audio): `Sample['x.flac']` (files cached; tags keep settings), `Sample[narray]`, `bounce(graph, 2.bars, bpm:)` / `node.bounce(1.bar, root: F1)` (offline at a private tempo), `capture_audio(4.bars, from: :master | node)` (live, `Session#capture_audio`).  Views share audio and playback tables (`slices(16)`, `slices(:onsets)`, `.rev`, `.at(7.n16)`, `.looped`, `.fade`, `.gain`, `.transpose`); edits make new audio (`.bits`, `.lofi(:s950 | :sp1200 | :mpc60)`, `.stretch(r, cycle:)`, `.mono`).
- `Sample::Slices`: `brk.name(k: 0..1)`, `brk[:k]`, `brk.keymap(from: C2)`, `brk.chop(:k, T, [:s, 2], brk[:s].rev)` → a Clip of the keymap's keys (slices, named runs, then all reversed, from C2) with a pitch mark on every hit (`Seq::Step#pitch`, `MIDI::Event#pitch`, `Notes#pitch_mark`; MIDI 1.0 bytes: a bend at ±24 semitones before the note-on), so `clip.transpose` moves the marks, not the keys, and live keys play the same slices (pitch from bend); `brk.keymap(from: C1, split: C4)` plays the last slice chromatically above the split.  `Sampler::Instrument` regions (keys, velocities, `seq:`/`rand:` round robins per voice, keytrack, veltrack), `sfz(path, mips: :octave)` (`Sampler::SFZ`; samples inside a document's directory), `sf2(path, preset)` (`Sampler::SF2`, pure Ruby: `sf2(path).presets`, `[bank, program]`/name; zones layered per the spec into `Instrument.layered`, per-zone envelope/filter/modulation as `Sampler::ZoneMap`s read per note by `GraphNode::ZoneValue`; stereo pairs, pans, mod wheel vibrato; specs build fonts with `spec/support/sf2_writer.rb`), `inst.play(v)`, `clip.sampler(brk)` (one truncating voice), `sample.node`; `breakbeat(:jungle)` is a synthesized break that ships with mb-sound (prints as itself).
- `GraphNode::SamplerVoice` + `fast_sampler` (exact mirror `Sampler::KernelRuby`): region choice and starts on the exact note-on sample, sample-mode Wavetable levels (antialiased; `interpolation: :none, mips: false` for the old sound), a 64-sample declick tail; worst case two reads per sample; ~0.28%/0.14% of realtime per voice at 128/800-sample buffers (0.40/0.24% with constant retriggers, ~1.05-1.2% with `:sinc`).  A plan boundary.  Narrow layers of layered instruments (SF2) sleep in synth voices while they have no region for the note (`GraphNode::SubLane`, Synth sub-lanes: woken on the exact note-on sample, bit-identical to rendering them; `midi.md`); voices the synth steals fade over 3 ms (`steal_fade`, on by default since the maintainer's A/B, 2026-10-16; `steal_fade: false` lets them ring on).  Graph documents print samples through their lineage on bundle assets.  Help `help :sampler`, `lesson :chop`; demo `bin/songs/press_and_chop.rb`.

### Textures (`design/notes/textures.md`)

### Granular and spectral stretch (`design/notes/granular.md`)

`sample.grains(density:, size:, position:, scan:, spread:, pitch:, pitch_spread:, pan_spread:, reverse:, window:, jitter:, seed:, read:, max_grains:)` (aliases `granular`, `cloud`; `GraphNode::Grains`, a stereo MultiOutput) plays a cloud of windowed reads of a Sample's band-limited levels; every option a number, Length/Interval, knob, or node read per sample, each grain keeping its onset's values; `position:` 0..1 freezes or scrubs, `scan:` moves a playhead (1 when no position: plays through), `pitch: [0, 12, 19]` picks per grain, `jitter:` 0 regular to 1 Poisson onsets, `normalize: :power` (1/sqrt overlap, default) or `:amplitude` (for grains lined up at scan 1).  `v.grains(sample, ...)` key-tracks in synth voices.  Kernel `FastSampler.grains` (`fast_sampler/granular.c`, exact mirror `Granular::KernelRuby`): onsets on exact samples (snapped within 1e-9), six splitmix64 draws per onset, `max_grains` slots (32, 16 in `v.grains`; extra onsets skipped): ~18 ns per grain per channel (full 32-slot cloud 3% of realtime mono, 5.7% stereo, at 128 or 800-sample buffers).  A plan boundary.
- `Sample#stretch(r, mode:)`: `:cyclic` (default, the S950 stretch), `:spectral` (`Sample::Spectral.vocoder`: phase vocoder with Laroche-Dolson identity phase locking, one phase rotation from the channels' mix, onsets kept unstretched with a phase reset (`transients:`, on by default); ~25-50x realtime per output), `:paul` (Paulstretch, counter-based seeded random phases, `seed:` 0; `transients: true` opt-in); `randomize:` 0..1 moves either between vocoder and Paulstretch phases (granular-2); `:slice` stretches by slices (loops.md).  Offline edits; results over 30 s read with `mips: :octave`.  Help `help :granular`; demo `bin/songs/granular_song.rb`.

### Loop files and tempo-following loops (`design/notes/loops.md`)

### Sequences (`design/notes/sequences.md`)

`lib/mb/sound/sequence/`: immutable `Clip`s of `Event`s in exact Rational whole notes, built with `seq(C4, E4, G4.n4).n8`, chord steps `seq([C3, E3, G3], chord(:min7, root: :d))`, `grid('x...x...')` (division 16 unless given first), note length methods (`n4`, `.d`, `.t`).  A clip is a MIDI source: `clip.stream`, and node methods from `clip.notes` (`clip.env`, `clip.tone`, `clip.freq`, `clip.gate`, `clip.trigger`; each call makes its own Notes, so share `n = clip.notes`); `clip.synth(voices:) { |v, i| }`.
- Edges land on exact samples at a shared `Transport`'s tempo (reads no edge can reach compare integer frames against the next edge's frame: `ClipSource` quiet reads, midi.md); looping clips follow the timeline (`align: :launch` counts from the launch); launches and swaps land on the floor sample of their time.
- Transforms: `legato`, `note_length`, `reverse`, `permute`, `rotate`/`shift`, `transpose(step, scale:, root:)`, `ratchet(n, rate:)`, `halftime`/`doubletime` (clips, Seqs, Kits); feel and chance: `humanize`, `quantize`, `swing`, `chance`/`maybe`, `every`, `Clip::Variation`s (`vary: true`), `bake(fx)`; generators `euclid`, `melody`. Scale methods count degrees from 0, `ghost_chords` from 1.
- Note marks: accent `!A1`, slide `~A1`, flam `D2.flam` (drum kits), `up`/`dn`/`oct`; `Rest`/`R`, `Tie`/`T`; `Seq#acid` and `acid(...)` for 303 patterns; voice helpers `v.accent`, `v.accent_sweep`, `v.acid_env`; demo `bin/synths/acid.rb`, `bin/songs/acid_song.rb`.  `!` is overridden only on Note and Step (test with `nil?`, never `!x`).
- `clip.ghost_chords(1, 4, 7, 6, per: 1.bar, scale: scale(:minor, :a), harmonic:, tie: :contour)`: snaps a repeated melody to a silent chord progression (degrees from 1, note Arrays, nil), keeping rhythm and contour; looping clips repeat to fit; without `scale:` the chords are in the session key.
- Clips remember what plays them (`Sequence::PlayedBy`, play-1): `brk.chop(...)` clips are `played_by` their slices and `machine.grid` grids by their kit design, carried through every transform, so `bg :x, chop` / `play chop` play the slices (= `chop.sampler(brk)`); plain clips play a soft saw, grids a TR-909 (a TR-808 when they name 808-only voices; omnibus9), envelopes a triangle plus pink noise; `clip.played_by(sf2(...))` picks one.
- `swap :bass, bass2` changes a player's clips on the next bar, keeping graph state; derived clips are rederived.  Demos `bin/songs/sequence_demo.rb`, `swap_song.rb`.

### Generative music (`design/notes/generative.md`)

Phases G1 (2026-10-15) and G2 (phrase memory, 2026-10-16) of the `research-generative` proposal (G3 knob decision points, evolving rhythms, and G4 long form to come).  A generator is a looping Clip whose events per cycle are a pure function of (seed, cycle): every draw is counter-based (`Generative::Dice`: splitmix64 over the seed and a key path, in C `fast_generative` with an exact Ruby mirror, `Dice.mode = :ruby`), so cycles come out the same cold or in order (seeks, takes, documents, any buffer size).
- Probability scales are values with operators: `scale(:dorian, :d).weights.blur(0.1) + tones(D3, F3, A3) * 2` (or `chord(:min7, root: :d).weights`: `chord` with a quality and `root:` is a `Generative::Chord` value, anything else the MIDI transform), `.blend(other, t)`, `.over(A3..A5, around: E5)` (a `Field`), `harmony(0 => a, 12.bars => b, curve:, loop:)` (keys and loops are lengths, plain numbers raise; keyframes blended per moment, shapes normalized, totals moving between the keyframes'; ops may take other harmonies; Weights `+ - * blend` with a Harmony give a Harmony); they print back as the expression that made them.
- `generate(1.bar, values:) { |cycle, dice| rows }` (`Clip.generate`; lengths, not Integer divisions), `strikes(field, every:, chance:, gap:)`, `melody(weights_or_harmony, ...)` (Scale melodies keep their notes; `vary: true` is a generator).  `Clip#values` is what kits build voices for; `map_clip` transforms map generated events (`Generative::Producer`).
- `motifs(h, 8, step: 1.n8, form: %i[a a b a], answer: { b: :a }, vary:, mutate:, evolve:, range:, around:)` (`Generative::Motifs`): phrase memory, one phrase per cycle; motifs are rhythms plus contours in scale steps realized where each note starts (through key changes), answers mirror and land home, repeats vary, and every `evolve` passes each step mutates within 32 generations of the first form (bounded: a cold jump to cycle 10^6 costs one cycle, ~0.1-5 ms).  `bin/songs/generative_blur.rb` makes blur audible (dense lines, a granular cloud with one weighted pitch draw per grain; defaults from the maintainer's Bench picks: blur 0.03, an unblurred one-a-bar bass anchor (`--no-bass`), chord blends of 1/4 bar for the line and 1/2 bar for the thick three-octave cloud (120 grains a second, `-c dense` the earlier 40) with 1-bar key changes; `-c sparse`, `-t slow`, `-C 0`, `-O 2` for the earlier sound).
- Live, reading cycle N queues N+1 on the realtime scheduler thread (`Scheduler#background`, `Generative::Ahead`); renders compute where read.  Demo `bin/songs/generative_demo.rb`; `help :generative`.

### Arrangement and Session groundwork (`design/notes/arrangement.md`)

Phases 1-4 of the arrangement plan (`research-arrangement`), built to the interconnect contracts (`research-plan-interconnect`, K1-K3, K6 knobs, K7 mute stage).
- Session groundwork: `Session::Stamp` (session `frame` + Rational `pos`, shown `bar:beat`), `Session::Journal` (K3 entries: seq, kind, subject, issued/commits/lands, status queued/landed/cancelled/failed; the render thread only queues notes), and the change queue: every change (`bg`, `stop`, `resume`, `swap`, `master`, mute/solo, undo restores, scenes) goes through `Session#change`, applied now or at the start of the buffer holding its time on the exact sample, under a render lock; any number of changes can wait per player. - Undo (`session/undo.rb`): one step per command or scheduled block; `undo` restores snapshots at the next bar (`on: :now`), cancels changes not yet landed; `redo!`, `changes`; bounded at 64 steps and 8 retired graphs (~7.5 MB per 8-voice sq80 synth).
- Set layer (`MB::Sound::Arrangement`, `Session#arrangement`): `track :bass, q: 1 do |clip| ... end` (patches are built once when stored by `track`/`scene`/`arm`, `Arrangement::PatchCheck`: errors at the prompt with the track and patch line), `scene :drop, bass: b, drums: beat` (full states; `others: :keep` for partial), `go :drop` (each track at its own `q:`; only differences change), `quant`. - Scene builds (scene-build, 2026-10-12): scheduled blocks build scene graphs on the scheduler thread (priority -3; the render thread runs at 3) `Session#lookahead` ahead (`:auto`: half a bar, more after slow blocks, up to 2 bars; renders always half a bar); blocks still running at their time go through `live_error` (live: warn, changes land late; scripts/specs: `Session::LateChange` raised before landing, `Scheduler::LateBlock`; `Session#late_blocks`).  `play_form` in an idle realtime session with YJIT first runs `Arrangement#warm_up` (one printed line; `flow(warm_up: false)` skips it; console `warm_up(tracks: true)`): every patch built (twice, to find self-contained ones) and, with a form, a rehearsal (`Arrangement#rehearse`): a sandbox Session with the master chain, buses, routes, clocks, knobs, those tracks and scenes plays a short copy of the form (sections of 48 buffers, at most 2 passes, then the first section again) at the live buffer size, so YJIT has compiled transitions (landings, swaps, first buffers, scheduled blocks) before the set needs them (scene-jit-1: render-thread compile at transitions ~85-120 -> ~25-40 ms; ~1.5 s more warm-up; patches reaching outside nodes are only built; seeds restored; a `GC.start` after it). ### Master effects (`design/notes/master_effects.md`)

`Session#master` / console `master { |mix| mix.softclip }` runs the mix through a chain of `GraphNode::MixSource` channels; new chains start at launch points with the old one spilling over (`fade:` crossfades, `fade: 0` cuts); `master nil` bypasses; `render` adds the tail.  Without a chain, realtime Sessions' live output ends in a transparent zero-latency safety limiter at -1 dBFS (`Session::SafetyLimiter`, omnibus9; after a post-chain master gain, before CUE and the monitor trim; never in renders, stems, takes, `rec_audio`, taps; `master` reports it).  The master gain applies before the chain, so a limiter keeps its ceiling (`master_gain 2.db, post: true` / `Session#master_gain_post` after it).  `resample`/`oversample` can't be used in a master chain yet.
- Mastering presets (mastering-1/2; `lib/mb/sound/mastering.rb` + `mastering/`): `master :club` (two limiters after an 18 kHz `air:` lowpass; renders target its loudest 16 bars, `measure: :loudest` with `loudest_bars:` per genre, windows on bar lines, since omnibus9; `clip: true` a gentle clipper; `air: :dynamic`/`:band`/`false`) / `:streaming` (`platform: :apple`) / `:quiet` (`lufs: :ebu_r128`) / `:vinyl` end the chain (a block's effects come first: `master(:club) { |mix| fx }`), `mix.master(:club)` anywhere, `masters` lists them; frozen `Mastering::Preset` values (steps as data, `Loudness::Target`, ceiling, notes, sources; options `lufs: platform: ceiling: drive: ride: mono: glue: clip: de_ess:`), saved in set documents and genre master steps.  One trim stage before the level-dependent stages: renders reach the target exactly in two passes (`Mastering::Targeting`: pass 1 records the mix and each targeted chain's input/output, the chains are rebuilt offline with other trims, pass 2 renders with the found trim; bit-identical at any buffer size; the block must build its graphs; `render(master:, loudness:)`, `loudness: false` once; scripts `--master club`, `--lufs`); live uses the preset's drive (assumes a -20 LUFS mix) or `ride: true` (`GraphNode::Rider`: 3 s short-term loudness on a 100 ms grid of its own time, gated). Reports add pass/fail, LRA, PLR, side below 120 Hz, decoded MP3/AAC true peaks (`Mastering.codec_peaks`; AAC only with libfdk_aac or aac_at, since ffmpeg's built-in encoder adds noise bursts that overstate them by several dB, aac-peaks).

### CUE and MAIN (`design/notes/cue.md`)

### Audio I/O (`design/notes/audio_io.md`)

Device I/O through bundled miniaudio (`fast_audio`), plus a small JACK backend (one client per process, ports added any time; user requirement).  `OUTPUT_TYPE`/`INPUT_TYPE`: `device` (default), `ffmpeg` (output), `null`.  `DeviceOutput` writes a lock-free ring drained on the device thread (Ruby never on the audio thread); the card's clock paces the Session.
- Latency profiles `:default` (512/128/50 ms), `:low`, `:video`, `:safe` (`AUDIO_PROFILE`, `-L`, `latency :low`); adaptive queue; live MIDI switches to `:low`.  Graphs stay at 48 kHz and the writer resamples to the card's rate.  Env: `AUDIO_BACKEND`, `OUTPUT_DEVICE`, `AUDIO_SAMPLE_RATE`, `JACK_CLIENT_NAME`, ...
- Never `jack_port_unregister` on an active JACK client (races libjack's notification thread; segfault 2026-10-12): the shared client keeps closed ports as disconnected spares and unregisters them behind `jack_deactivate` once no port is in use.
- Things closed at exit register with `ExitClose` (one hook, held weakly), never their own `at_exit` block: a block given to `at_exit` is a GC root, and per-Session blocks once kept every closed Session's graphs alive (guard in `exit_close_spec.rb`).
- bin/ scripts set `RUBY_THREAD_TIMESLICE=10` in their shebang (busy threads starve the writer otherwise).  Tools: `bin/audio_check.rb`, `bin/audio_load_check.rb`.

### Latency probe (`design/notes/latency_probe.md`)

`bin/latency_probe.rb -t 1h` / `MB::Sound::LatencyProbe.start(dir:)` (latency-probe-1, 2026-10-25) separates system stalls from mb-sound's own: `FastLatency::Probe` is a pthread outside the GVL on an absolute-deadline loop (1 ms; `clock_nanosleep` TIMER_ABSTIME / `mach_wait_until`) timing a memory-touching walk (64 MiB buffer, 128 KiB a tick: the Mac Docker VM's top-of-minute stalls slow memory ~10x while CPU-only work runs normally) and a CPU loop, with per-second aggregates and log-bucket histograms in C (mirror `LatencyProbe::Histogram`), stall episodes, and a lock-free SPSC ring that drops and counts when full; a Ruby consumer thread waits in C without the GVL and drains it.  A Ruby ticker (2 ms) sees GVL/GC/YJIT stalls too; per-second GC/YJIT deltas, free memory, load, CPU busy/steal, PSI; `#watch(session)` logs slow buffers and underruns.  Reports: percentiles, counts over 1-80 ms, top stalls with wall times, periodicity (`Periodicity`, ":59.9 of each minute"), Ruby stalls by cause; plots (time with minute rules, histograms, by second of the minute) as SVG/PNG/text; CSV flushed every 10 s.  `MB_SOUND_LATENCY_PROBE=1` probes any live script.  Priority: macOS time constraint, Linux SCHED_FIFO/nice where allowed (the container has neither).

### Scripts (`design/notes/scripts.md`)

Every bin/ script except `bin/sound.rb` uses a `ScriptingMethods` helper (backed by `ScriptRunner`): `effect_script { |input, p| }` (file or live input, rung out with `Ringdown`; `-m` MIDI controls), `synth_script { |midi, p| }` (`midi` is a `Notes`; file renders ring out), `song_script(bars:) { |p| }` (`-b`, `--bpm`), `script(args:) { |args, p| }`.
- Shared options: `-o` render, `-f`, `-g` graphviz, `-P` plot, `-q`, `-L`, `--ui [LAYOUT]` (play in a console-less terminal screen; live synth/effect scripts also take Esc for all notes off, `MIDI_LOG=1`, `MIDI_STUCK=s`).  Parameters are options only: `name: [default, 'description', '-x', Type, range]`.  `p.midi_cc(1, :hz, range:)` is a controller when MIDI is open, else a constant.  Graph-building code goes inside the block; guard loadable scripts with `if main_script?(__FILE__)`.
- `bin/sound.rb` is the console: `Help.welcome`, `Help.install_pry!` (Pry's help, play, reset, hist become `pry-*`), the take hooks, and the did_you_mean workaround in its exception handler (until mb-util prints `detailed_message`).

### MIDI (`design/notes/midi.md`)

`lib/mb/sound/midi/` is pull-based (no callbacks; only live input reads a clock): Sources make Events, Streams share them among readers, `Notes` turns them into signal nodes, `Synth` allocates voices.
- `MIDI::Event` is the one message type (normalized values, 0-based channels, Rational seconds).  Sources: `FileSource`, `ClipSource`, `LiveSource` (`MIDI_TIMING=exact` keeps a constant latency; JACK input is sample-exact).  `MIDI::Stream` fans out with per-reader cursors and makes transform views.
- `MB::Sound::Notes` (`v` in synth code): `gate`, `trigger`, `number`, `velocity`, `freq`, channel-wide controllers (`bend`, `pressure`, `cc(n)`, GM-named `mod`, ...; smoothed by default), envelopes (`amp_env` etc. with GM2 scaling), `v.hz` key-synced NotePitch (`.glide`, `.vibrato`, `.bend_range`), `v.key_trigger` (no reset on energy-adding re-strikes, user rule), `v.cutoff`, `v.reso`, `v.lfo`, `v.mod_sum`/`mod_scale`, `poly_pressure`, `aftertouch`.
- `MIDI::Allocator` lanes with `steal:` chains and `retrigger:` modes; `Synth.new(source, voices:, spares:, retrigger:, skip_idle:, exact_lanes:) { |v, i| }` (`:string` and `:ring` presets); `ended?` once the source is over and lanes are quiet.  Sub-lanes (`GraphNode::SubLane`, `Synth#sub_lanes`, `MB_SOUND_SUB_LANES=0` off): parts of a lane that sleep on the skip grid after an exactly silent cell and wake on the exact sample of an event their `wake:` Proc accepts (sampler layers).  `exact_lanes: true` (also `Session#exact_lanes`, `render(exact_lanes: true)`, always on in take replays) frees lanes by whole 800-sample grid cells, splitting buffers that cross one, so allocation is the same at any buffer size; off by default (maintainer: exactness only when asked for; no extra CPU).  `same_key: :restrike` (default for real-time input, `MIDI::Source#realtime_input?`: live keyboards, the UI keyboard, Session MIDI inputs and their take replays) restarts the lane holding a re-pressed key, so a dropped note-off is fixed by pressing the key again; files and clips keep `:count`; `MIDI::Output` ends a held note before re-sending its key (`NoteBalancer`).
- MIDI transforms on Streams/Notes/Clips: `echo`, `arp`, `chord`, `strum`, `humanize` (4 ms, later only), `quantize`, `swing`, `chance`, `every`, `legato`, `ratchet`, `ghost_chords`, `snap`, `transpose`, `degrees`, `lock`, `select`/`reject`, `split`, `merge`, ...; unattached chains (`Transform::Spec`, carrying the clip operations too) via console `echo(...)` etc. with `stream.through(fx)` / `clip.bake(fx)`.  Demo `bin/songs/midi_transforms_song.rb`.
- Moving parameters (`MIDI::Param`, `value_at(pos, transport:, stream:)`, midi-consol-2): `cc(1, 0.5..0.7)` (the transform's own input, else the Session's MIDI input), knobs (`Knob#value_at`: exact inside the rendered span, else the known value or a queued turn, never extrapolating a follow; future answers are decisions logged for takes, `Session::Decisions`), `knob(:x).choose(...)` (hysteresis), tempo LFOs (`4.bars.lfo.at(0.5..0.66)`), clips (`transpose(seq(0, 5).n1.loop)`), arithmetic printing back as Ruby; read once per decision (note-on; arp/ratchet step; every/clip cycles; strikes cycles).  Plain values keep the old code paths.  Examples `bin/midi/moving_params.rb`.
- Session key and locks: `key :d, :dorian`, `mode :lydian` (launch points, scenes/sections `key:`/`mode:`, undoable; `MusicalKey` in the transport's key map), `scale(:dorian)` takes the key's root, bare `scale` is the key's scale, `mode knob(:dark)` / `modes(:lydian..:locrian, by:)` walk the modes one note at a time.  `MIDI::Lock` maps (`degrees(layout: :flow | :fit, black: :passing | :silent | :lower)`, `snap(:chord, from:, extend:, avoid:, bass:)`, styles `lock :mash | :play | :along | :chord | :off`) shared by streams (`stream.lock(:play)`), the Session input lock (console `lock :play`: live MIDI and the virtual keyboard), and `UI::Keyboard::ScaleLock` (:mash by default); cents scales give whole notes with pitch marks (`micro: :mark`, MIDI bends; `micro: :note` fractional notes).  Demo `bin/midi/key_lock.rb`; help `:key`, `:lock`, `:params`.
- Live MIDI uses JACK MIDI ports when a JACK server answers, else bundled RtMidi (CoreMIDI/ALSA); `MIDI_API`, `MIDI_DEVICE`; `bin/midi_check.rb` diagnoses.  JACK specs use a private dummy server (`spec/support/jack_dummy.rb`, one at a time via a lock file).  `MIDI::ControlMap` lists controllers and writes ACID DAW XML (`--acid-xml`).
- Console: `midi` (a Notes on live input through the session's `MidiInput`), `midi_file(path)`.

## Working Notes (lessons learned)

### Verifying audio without speakers

The container has no audio device, so check sound-producing code by rendering it: `MB::Sound.render('file.flac', graph, bars: 4)` or loops of `node.sample(800)`, then look at peak levels, silent stretches, and exact sample offsets of note edges.  Use `NullOutput.new(..., sleep: false)` and `Session.new(realtime: false)` with `#process_buffer` for fast, deterministic tests.  To check that events happened (e.g. a swap landed on its bar), trace internal state from a scheduled block; spectral checks of the mix are easily fooled by other parts.  Leave listening to the user (on a Mac) with copy-pasteable snippets and expected results, and keep good snippets in demo script header comments.

### Gotchas

- `#sample` usually returns a reused buffer; `.dup` each buffer before collecting several of them (several false "bugs" came from forgetting this).  It may also be frozen (a Tee's shared buffer): copy before modifying a buffer you didn't create.
- A Tee branch that is never read keeps its Tee copying until the branch falls a whole CircularBuffer (1 s) behind, and raises `BranchBufferOverflow` if read later; benchmarks that reuse one node in two graphs sampled separately hit this.
- Oscillators (`Tone`, `noise`) are full scale (-1..1) by default, and the master bus (`Session#master_gain`, `master_gain -6.db`, `render(gain:)`) is -10 dB by default, live and in renders, so mixes of full-scale parts have headroom; effect scripts set it to 0 dB, since they process recordings with their own levels.  Check levels by rendering (file renders warn when the mix goes over full scale, which integer formats clip even under `loudness:`; `RenderPeak`).
- Oscillators and constants play forever (there is no `.for`/`.forever`); sounds end through envelopes (one-shots without gate or trigger; gated or triggered ones, as in voices and clips, never end by themselves), clips, files, `x.until(seconds)` or `x.until(2.bars)` (alias `x.for(2.bars)`, printed and saved as `until`; `GraphNode::TimeLimit`, a hard cut; musical lengths follow the tempo, counted from the node's first sample), `and_then`, or `MB::Sound.silence(s)` (zeros, then the end; e.g. tails via `and_then(silence(s))`).  `play` of a graph says to press Ctrl-C, `write` and `render` without `bars:`/`seconds:` cap graphs at `MAX_RENDER_SECONDS` (`render(bars:)` has no cap: it runs to its end bar and tail, or stops early once every sound has ended and nothing is scheduled; `max_seconds:` caps explicitly; renders keep time while idle until scheduled blocks start something, live sessions pause), and `fft`/`plot`/`write` given a bare Tone or Pitch take one second of it.
- `40.hz` is a Pitch that plays as a sine when used as a signal, not a constant; use `40.constant` for fixed values in arithmetic, and `pitch.transpose(n)` or `(f * 2).hz` to change frequencies (`440.hz * 2` doubles the sine's amplitude).
- `Numeric#samples` is a `Length::Samples` (it used to return seconds at 48 kHz), and `#delay`/`#multitap` have no `samples:`/`sample_rate:` options (and `delay(seconds: t)` is deprecated): write `delay(96.samples)` or `delay(lfo.samples)` (counted at the running rate).  A plain node or number is seconds; `smooth(0.1)` and `smooth(4800.samples)` replace `smooth(seconds:/samples:)`.
- Use the `a*` names (`asaw`, `aclip`, ...) or `.lfo` for control signals that must keep exact edges (delay times, gates, phases), and remember that `softclip`/`clip`/`abs`/`quantize` add half a sample of delay (null tests against older renders show a -20 to -30 dB residual; align by half a sample to compare).  An edge landing exactly on a sample is a classic rounding trap in these kernels (phases snap within 1e-9 of an edge).
- The container compiles with GCC, which never warns about unused `static inline` functions; the user's Mac uses clang, which does for functions defined in a `.c` file (not in headers), and `-Werror` makes that a build failure.  After C changes, check that every static function in a `.c` file is still called.
- `Numo::Pocketfft.rfft` (and `ifft` of a complex view) read an NArray view like `x[100..]` from its parent's start; `MB::Sound.fft`/`ifft`/`real_fft`/`real_ifft` copy their input, but `.dup` views before calling Pocketfft directly.
- `node.filter(cookbook_filter)` copies the filter's cutoff and quality into constant inputs (and, by default, into a new `Filter::SVF`), so changing the Cookbook's `center_frequency` from outside (e.g. a MIDI callback) does nothing; pass `cutoff:` a node and change the node.
- `multitap` and other multi-output results are `Channels` bundles, which are deliberately not Enumerable (`.to_a` for `shuffle`, `reverse`, etc.).
- C4 = 60 (C3 = 48).  Derive expected values in specs from note constants or a quick script; hand-computed notes and offsets caused several wrong assertions.
- A realtime Session's render thread runs until `close`; close sessions in spec `after` blocks.  `kill -QUIT <pid>` prints every thread's backtrace (`MB::U.sigquit_backtrace`, set up in spec_helper).
- Before adding `bin/sound.rb` commands, check for collisions with `MB::Sound` methods and Pry commands (`Pry::Commands`; e.g. `reset` and `watch` are taken).

### Process

- `/app` is one tree on the maintainer's Mac (case-insensitive APFS) that the Linux desktop mounts over sshfs; both machines run Docker containers with `/app` as a volume of it (setup in `dock.sh` and `Dockerfile`: per-machine Claude config at `/claude`, with memory, skills, plans, agents, rules, commands, workflows, and output styles shared from the gitignored `.claude-shared/`), and both may run Claude sessions at once (2026-10-10).  At the start of each session, check which machine this is with `grep -m1 'model name' /proc/cpuinfo`: AMD Ryzen 9 7950X is the Linux desktop's container, Intel Core i9-9880H the Mac's container (the 2019 MacBook Pro, under Docker's Linux VM).  On the Linux desktop, also check that `/app` is `fuse.sshfs` in `/proc/self/mountinfo`; anything else is a stale local copy.  Re-read a file just before editing it (the other machine may have changed it, and sshfs caches attributes and listings for a few seconds); never create paths that differ only in case or rename by case alone; don't count on `flock` or stamp files to coordinate across machines.  Git writes (commit, merge, checkout, rebase, worktree add/remove) share one `.git`: check for `.git/index.lock` first and tell the other machine's session before switching branches or merging in `/app`.  Both containers are x86_64-linux and build into the same `tmp/x86_64-linux/` and `lib/**/*.so` (native macOS builds go in `tmp/x86_64-darwin*/`); `rake clobber` (also run by the memcheck -O0 task) deletes all of `tmp/`, so remove `tmp/<platform>/<extension>` instead.  The maintainer also works natively on the Mac, outside any Claude session (2026-10-11): files, branches, and builds can change with no heads-up, and the native builds (`lib/**/*.bundle`, `tmp/x86_64-darwin*/`) can't be rebuilt from a container, so leave them alone.
- In multi-step shell scripts, use `set -euo pipefail`, don't pipe away exit codes, and put commands on separate lines (a failure inside `a && b` doesn't stop the script; a batch loop that kept going after a failure once produced broken commits).
- Use the Edit tool for multi-line code changes; ad hoc Python/sed replacements often failed on indentation or escaping.  Never `sed -i` the Rakefile: on the Mac's case-insensitive `/app` mount it once left a stale lowercase `rakefile` entry that rake loads first (`LoadError ... rakefile`; `rake -f Rakefile` works around it).
- Memcheck (selective by default for branches): run `rake -f Rakefile memcheck:changed` before merging branches that touch `ext/` or code calling extensions; it selects specs from `spec/valgrind/memcheck_map.json` (changed extension dirs, users of changed shared headers, `lib/` files naming a `Fast*` module, changed memcheck specs; the full list for suppressions, `gc_stress_calls.rb`, `mb_ext_helpers.h`, the Rakefile memcheck section, a new extension, or over half the extensions; rules in `spec/valgrind/memcheck_selection.rb`).  Selections range from under a minute (one small extension: fast_resonator's 2 spec files took 0.7 min in Valgrind, 2026-10-09) to most of the full run (fast_sound and fast_arithmetic reach 37 and 31 of the 58 spec files; `lib/mb/sound/tone.rb` names four extensions).  The full `rake memcheck` is rare (maintainer decision 2026-10-18, after no full run since selective memcheck began found an error the selective runs missed): a pre-public-release step, or a deliberate choice when hunting a hard-to-find leak, never "due" by merge count or age; it records `tmp/memcheck_full.stamp` in the main checkout (`memcheck:status` reports it) and rerecords the map (commit `memcheck_map.json` afterwards).  Keeping the map current is part of changing `ext/`: the map records the ext/ structure it was made against (`MemcheckSelection.structure`: each extension's sources, `Fast*` modules, resolved includes, depend entries), and a branch that adds a source, header, extension, module, or include, or changes a `depend` file, runs `rake -f Rakefile memcheck:map` (~5 min natively) and commits the map in that branch; `memcheck_selection_spec.rb` (normal suite) fails and `memcheck:changed` refuses to run until then (`MEMCHECK_DRY=1` and full runs only warn), naming the command.  Every selection that runs anything also runs `spec/lib/mb/sound/graph_sweep_spec.rb` (`MemcheckSelection::ALWAYS`, "memcheck light": every GraphNode/multi-output/Filter class and every filter type from the filters' own type lists, in small graphs with modulated inputs, MIDI clips and Synths, stereo bundles, and feedback loops, planned and unplanned at 1/128/800-sample buffers, `:check_shared`; ~4 s natively, est. ~2 min under Valgrind; its guard fails for a new node class until the sweep builds it or `GraphSweep::EXEMPT` says why not).  New memcheck specs go in `MemcheckSelection::SPECS` and run in every selective run until the map is refreshed (`rake memcheck:map`, ~5 min natively).  Memcheck runs set `MB_SOUND_MEMCHECK=1` (`SPEC_MEMCHECK` in spec_helper; 2026-10-10): specs shrink inputs whose extra length only adds Ruby time under Valgrind (notes_ops one file pass and no check-mode pass, loop_spec 4000 samples, fast_wavetable 100-sample cases, graph sweep 20 one-sample buffers instead of 40), and examples tagged `memcheck_skip: 'reason'` (the reason names what still runs their C paths) are left out (loudness cases with 40-100 s of audio, wavetable file round trips); per-example times go to `tmp/memcheck_times.json` for the next trim.
- After merging (or rebasing onto) changes that touch `ext/`, run `bundle exec rake -f Rakefile clean compile` and check that it succeeds before trusting specs: a stale `.so` from before the merge loads fine and lets the suite pass while the merged C doesn't build (2026-10-06: gc-fixes changed `mb_read_signal_input`'s signature, and the four-pole and wavetable kernels from parallel branches still used the old one; git merged them cleanly).
